## Rules

The eight rules of `docs/wp/WP-057.md` "Rules" hold, with the settings of
§3 and §4 in place of rule 3:

- **Rows R** rename one entity in place: `declared.txt` is one
  `relocate <entity> => <its parent> :: <new name>` line (R03 and R08:
  one line per renamed entity). There is no `dep/` unless the row needs
  a dependency (R04).
- **Rows E** declare nothing: `declared.txt` is absent or empty, except
  E11's `good` tree, whose removed declarations are `removed` lines.

And for these tables in particular:

- **`good: none`** (R01, R04, R07, E10, E14): the hazard has no correct
  edit of the same shape. The row has `bad/` only, and its line in
  `expect.txt` says why in a few words.
- **Rows with two `good` shapes** (R05: a harmless local rename; E03:
  redundant parentheses; E06: four respellings; E07: four edits) have
  one `good-<k>/` per shape, all on `pre/`. Each must verify by itself;
  do not fold them into one tree.
- **Every wrong edit here is silent** unless the table says
  `not_parsed` (R06): the `bad` tree compiles, with clang and with
  Kiln. If yours does not, it is not the row.
- **R03, R07, E11** allow two findings ("on the derived class or its
  function", "`changed` the caller … or `derived_changed` on the
  template"): write the one your reading of `spec/digest.md` expects,
  and say in the landed file which fact decides it. WP-056 corrects the
  line if the run shows the other.
- **R11**: the expected line is `mismatch indeterminate <entity>` (a
  collision: two entities with one key), not a `changed`.
- **E13** pins today's behaviour (`__LINE__` is a value); its
  `expect.txt` carries a `#` line saying so and naming the open
  question of `spec/digest.md`.
- **E09** expects the order unit: the entity is `<order>`.

**Deviations from `spec/pitfalls.md` §3 and §4** (rule 8), and what I
would change in the table:

- R05: no `declared.txt` (a local is no unit). Say "nothing declared".
- R11: `pre-2/` and `pre-3/` for `__func__` (ruling 3): add them to the
  row.
- E02: `good` qualifies the other call, on `int`; "left unqualified" is
  no edit. Write the column so.
- E05: the cast form does not verify (`h(static_cast<long>(1))` and
  `h(1L)` are other expressions); `good` is a move that stays before
  `h(int)`. Drop the cast from the column.
- E10: the function, not the caller (ruling 2).
- E11: `removed` lines for every removed header's declarations, so that
  the `bad` trees are caught by the program's change; two `bad` trees.
- E12: an inner namespace and a `created` line: any statement inserted
  into a block changes its function. Write the row with a namespace
  scope.
- E14: the line names `changed later()`.
- E15 and E16: `good: none`. `T x = T(y)` selects the explicit
  constructor here and is a written cast elsewhere; `[&n]` for `[&]` is
  not equal by design (`LambdaData` `default`, `LambdaCapture`
  `implicit`). Change both columns to `—` and `good: none`.
- E04: the dependent-operator form is not built (one hazard per row).

**Names**: R04's expected `lib::store<app::Mine>::put(app::Mine &)` is
printed `lib::store<Mine>::…` today (WP-104). No other expected name
differs.

**Kiln**: no disagreement of verdict.
