# WP-164 — one function for real paths: the `canonicalize` left in the product crates, and clippy's coverage of `slip_cli`

- Status: review

- Track: D

## Scope

`spec/edits.md` §2.1 ("Every place a path enters Slip gives it that
spelling, through one function") and `spec/landed/edits/WP-151.md` make
`slip_spelling::real_path` (`crates/slip_spelling/src/lib.rs`) the one
way a path that enters Slip is made real. WP-151's handback (item 4 of
its supervisor's handback, `docs/wp/WP-151.md`) left `std::fs::canonicalize`
in places it did not own. This package settles every remaining call.

1. **Every `std::fs::canonicalize` (or `fs::canonicalize`) in non-test
   code of `crates/*/src`, except `crates/slip_spelling`**, is
   classified, and the handback has one row per call site (file, function,
   class, what changed). Today's sites (`git grep -n canonicalize -- 'crates/*/src'`):
   `slip_apply/src/fs.rs` (2), `slip_cli/src/negatives.rs` (4),
   `slip_cli/src/worker.rs` (1), `slip_cli/src/image.rs` (1),
   `slip_cli/src/verify_job.rs` (2: `as_recorded`, `still_there`),
   `slip_cli/src/transform/rename.rs` (1: `--relative-to`),
   `slip_kiln/src/{tree,session,parse}.rs` (3),
   `slip_script/src/driver.rs` (3). The classes:
   - **(a) a path entering Slip, or compared with a path that did**
     (a recorded real path, an ownership entry, `--relative-to`): it
     goes through `slip_spelling::real_path` (or `respelled`, where the
     record keeps a path as given). Known members:
     `transform/rename.rs` `--relative-to` (named in §2.1 itself);
     `verify_job.rs` `as_recorded` and `still_there`, which compare
     `canonicalize`'s answer byte for byte with a path recorded through
     `real_path`, so on a volume that folds case a correct file reads as
     moved. Decide `negatives.rs` (guard N1, `appeared`; `found`; `walk`)
     by the same test: is the result compared byte for byte with a
     spelled path, or only by identity (`Resolver::under_subject` is by
     identity)? Say which, per site.
   - **(b) kept on purpose**: the call is the first half of
     `real_path` itself, a fallback a spec names (`image.rs`
     `canonical`, `spec/landed/edits/WP-151.md` ruling 2), or a
     comparison by identity only. Each keeps `canonicalize` with a
     comment on the line above, `// canonicalize: <reason>`, citing the
     spec section or ruling.
   - **(c) test code** (inside `#[cfg(test)]`, or a test helper):
     unchanged, listed.
   `xtask/src` is out of scope (it does not take requests; its paths
   are the corpus layout's): list its sites in the handback, no change.
2. **A lint keeps it so**: `cargo xtask lint` rejects `canonicalize(`
   in non-test code of `crates/*/src` outside `crates/slip_spelling`
   unless the line above carries `// canonicalize: ` with a non-empty
   reason. Follow the shape of the existing rules in `xtask/src/lint/`
   (a rule, its message naming file and line, tests in `xtask/tests/`
   with one accepted and one rejected case, the rule listed where the
   other rules are documented, `spec/harness.md` if the lint rules are
   listed there). A call inside `#[cfg(test)] mod` is not flagged; if
   telling test code apart is not reliable with the lint's existing
   machinery, flag it too and give test sites the comment.
3. **Clippy's coverage of `slip_cli`.** WP-151's handback says the
   plain `clippy` step of `cargo xtask ci` does not cover `slip_cli`:
   true by design (it runs on the workspace's `default-members`, which
   leave out the Kiln-linking crates; `Cargo.toml`). The `kiln` step
   runs `cargo clippy -p <each of lint::KILN_LINKING> --all-targets --
   -D warnings`, and `KILN_LINKING` includes `slip_cli`. First check
   which is so: does every gate (`cargo xtask ci`, and `--quick` if it
   exists) run clippy over `slip_cli` with `--all-targets -D warnings`?
   - If yes: no code change; correct the comment above the `clippy`
     arm in `xtask/src/ci.rs` to say the `kiln` step covers the rest,
     and say so in the handback.
   - If a gate leaves it out (say which): make that gate cover it, by
     the smallest change, and give the test that shows it
     (`xtask/tests/`).

### Numbered choices

1. **`negatives.rs` split across (b) and (a).** `appeared` (`negatives.rs:78`, guard N1) is class (b): it passes `real` only to `Resolver::under_subject`, which checks directory identity (`Resolver::region`; its byte fallback at `image.rs:1305` runs only when a subject root's identity cannot be read, under which an existing file cannot lie), and keeping `canonicalize` avoids false refusals on an unlistable ancestor. `record` (`negatives.rs:143`) and both calls in `walk` (`negatives.rs:172, 178`) are class (a): each is compared byte-for-byte with recorded `FileRef.path` values.
2. **`slip_apply/src/fs.rs` both class (b).** `DiskTree::real_path` (`fs.rs:122`) is the first half of `slip_apply`'s own real-path check before `Spelling::entries` walks `on_disk`. `DiskTree::stat` (`fs.rs:41`) checks only that no directory on `dir` became a symbolic link after `write.rs`'s fresh `Spelling::check`; calling `slip_spelling::real_path` there would consult the process-wide cache (`spec/edits.md` §2.1 requires apply to walk afresh per call) and turn spelling/listing issues into `NotRegular` or `Io`.
3. **`slip_kiln/src/parse.rs:865` class (b).** It needs both `canonicalize`'s answer and `on_disk`'s answer to compute `respelled = on_disk != real` for `inputs.respelled`, without changing `slip_spelling`'s API (out of scope).
4. **`slip_kiln/src/tree.rs:78` class (c) with comment.** `Tree` is a test helper (`pub mod tree;` outside `#[cfg(test)]`). Rather than special-casing `tree.rs` in the lint, the call stays unchanged and carries a `// canonicalize:` comment.
5. **Lint `real-path` (`xtask/src/lint/real_path.rs`).** Lexes tracked `.rs` files under `crates/*/src/` outside `crates/slip_spelling/` with `rust_tokens::tokens` (skipping comments and string literals), skips items carrying an outer `#[cfg(test)]` attribute (including stacked attributes and balanced `{ ... }` or `;`), and rejects any remaining `canonicalize(` token pair unless the immediately preceding line starts (after whitespace) with `// canonicalize: ` followed by a non-empty reason. Registered in `xtask/src/lint.rs` (`LINTS` and `check`) and documented in `spec/harness.md` §3 / §3.2 and `spec/edits.md` §2.1.
6. **`xtask/src/lint/rust_tokens.rs:99` bug fix.** `skip_string` skipped `\` + next byte (`i += 2`) without incrementing `*line` when the escaped byte was `\n` (a string line continuation, such as `crates/slip_cli/src/image.rs:422`), causing token line numbers after line continuations to drift off by 1. Fixed and covered in `lint::rust_tokens::tests::lines`.
7. **Item 3 — clippy coverage of `slip_cli`.** Every full gate (`cargo xtask ci`) already covers `slip_cli` with `--all-targets -- -D warnings`, in the `kiln` step. Exact commands in `xtask/src/ci.rs` (also verified by `xtask/tests/ci.rs` `s2_full_gate_order`):
