## Interface

Signatures are fixed; `expr.rs` and `expr_core.rs` do not change.
Everything you call is on `main`: `expr::{node, expr_id, decl_id,
expr_list, child, child_opt, children, check_bits, check_aux}`,
`Walk::write_ref`, `write_type`, `value::value`. If a kind needs the
walk to do something `expr.rs` does not offer (a second list form, an
accessor), add nothing there: say what is missing in the handback and
write the conservative thing.

Things to settle by reading Kiln (`kiln_ast::expr`, `kiln_sema`), each
with its `file:line` in the landed file:

- **`CXXRewrittenBinaryOperator`** writes the semantic form and then
  the two operands as written. If the operands are the same nodes the
  semantic form holds, a nest of rewritten comparisons (`(a != b) !=
  c`, twenty deep, each level rewritten) is walked 2^n times. Measure
  it. If it is exponential the row cannot be written as the table says
  (properties: linear work): report it with a proposal (the operands
  written by their position in the semantic form; or numbered as
  opaque values are) and write the node indeterminate past a nesting
  you choose, with its test.
- **`CXXDefaultArgExpr.a`** is the parameter's position, "its function
  is the callee or constructor of the enclosing call": find every
  place Kiln builds the node and check that the enclosing node always
  names the function (a call through a function pointer has no default
  arguments; an inherited constructor; a `CXXParenListInitExpr`); a
  site where it does not is a missed difference to report.
  `default_arg_rewritten`: when Kiln rebuilds (immediate functions,
  source-location builtins) and whether the rebuilding depends on
  anything but the use.
- **`CXXDefaultInitExpr`** writes the field; `default_imm` is `demand`
  (§11.4): write nothing for it and give it its `demand` test.
- **`CXXConstructExpr` and `ConstructInfo`**: every field of the
  record against digest §6 ("the selected entity": the constructor; the
  bit for several candidates is `out`). An elided copy, list
  initialisation, a `std::initializer_list` constructor, zero
  initialisation before the call, a constructor inherited from a base
  (which `ref` Kiln stores: the base's constructor or the shadow).
- **`InitListExpr`**: which form Kiln stores (semantic, with fillers
  and brace elision resolved) and where the form as written is kept
  (`syntactic_list`, "in a template pattern": confirm no entry exists
  outside a pattern, else the row writes a written form §1 rule 2
  forbids: report). `InitListExtra` row by row; `union_field`.
- **`CXXNewExpr`/`NewExtra`, `CXXDeleteExpr`**: the allocation and
  deallocation functions are the fact (digest §6). `CXXDeleteExpr.b`
  for a class with a virtual destructor: what Kiln stores, and whether
  a later use (the destructor's definition, `ColdDeclData`
  `dtor_delete`, which is `demand`) can set or change it. If it can,
  the row is `demand`: report it and do not write it.
  `bits-array-as-written` against `bits-array-form` in a pattern.
- **`CompoundLiteralExpr.aux`** non-zero is `Cause::Unsupported`, with
  its `indeterminate` test (C++ at file scope; if Kiln rejects it in
  C++, say so and leave the test out).
- **Nesting.** Each kind function is entered by recursion (one
  `enter_node` level per nested kind of this file). Tests: an
  initialiser list of 100 000 elements is linear (LLVM's generated
  tables are of that size); 2 000 nested braces digest; if a shape of
  real code nests these kinds deeper than `NODE_LIMIT`, say which.

## Tests

Per row as the common rules say. Beyond the rows:

- `equal`: a constructor named with and without its qualifier
  (`ns::S(1)`, `::ns::S(1)`, `S(1)` inside `ns`); `S s = S(1)` written
  through an alias of `S`; `new ns::S` requalified.
- `differ`: the constructor chosen (an overload added that wins); a
  converting constructor against a conversion function for the same
  source text; `T x{1}` choosing the `initializer_list` constructor
  after one is added; `()` against `{}` where they mean different
  things; `new` choosing a class's `operator new` after one is added;
  `delete` choosing a sized deallocation function; `a == b` rewritten
  through `<=>` against a real `operator==`; reversed operands.
- `demand`: a use on side B that instantiates the class constructed
  (its members are units of their own: the constructing body holds
  still); a use that makes a defaulted constructor non-trivial is not
  one (that is a different program).
- With `origin/main` merged, un-pend the `# needs: expr` tests whose
  missing kind is one of yours (leave the others); see each pass and,
  for one in five, fail when the row is broken.
