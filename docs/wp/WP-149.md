# WP-149 — rename: the names the new pin records (stage-3 roles, declaration rows), each decided

- Status: todo

- Parallel with: the transform packages that do not edit `crates/slip_refactor`'s rename

## Scope

With the pin of `docs/wp/WP-066.md` Kiln records written names it did
not before (its WP-1932 stage 3, WP-2470, WP-2471): a
using-declarator's name as a reference to the base member as well as
the shadow's declaration, an elaborated or friend reference, a
specialisation's target, a redeclaration's name, a friend class, a
designator, `offsetof`'s designator, a namespace alias and a
using-directive's namespace, concept names. WP-066 kept the rename
reading only the old pin's roles (`crates/slip_refactor/src/rename/target.rs`
`rename_role`), because reading them all broke two merged tests
(`wp120_unhide_idiom_end_to_end`, `wp119_known_mismatch_f2_member_first_using`:
a `MixedSet` refusal, a missing shadow). Its second review (F6): the
filter is safe only while `spec/api.md` §9.1 allows Function and
Variable targets; a name of the target that the rename does not read
is a name left behind.

1. **Each role, decided against §9**: a table of role × target kind
   (function, variable, and the kinds §9.1 does not allow yet: say so
   per row) × what the rename does with a name of that role that
   denotes the target or a follower: edit, keep, refuse, or
   `unreachable` with its reason; with the source that shows it. For
   Function and Variable targets today: a using-declarator
   (`using B::f;` when `f` is renamed: the declarator's name is
   edited, the shadow follows; the unhide idiom of WP-120 keeps
   working), a friend function declaration and a friend's qualified
   name, an explicit specialisation's and an explicit instantiation's
   name (WP-066 says the name is now claimed and the follower of a
   member's explicit instantiation is still `unreachable`: serve it),
   a redeclaration's name, a designator naming a renamed field (a
   variable target that is a field), `offsetof(S, f)`.
2. **`rename_role`'s filter goes**: every role Kiln records is read,
   and a role the table does not serve is a refusal with its reason,
   never a silent skip. The two tests that failed pass by the table's
   rows, not by the filter.
3. **The `unreachable` rows that the new rows reach** (`written.rs`
   `recorded_*`, the `s9_5-unreachable-*` directories that "now
   describe a reachable seed and keep their names"): rename the
   directories to what they are, turn each into its `s9_*` row. The
   pending `s9_5-unreachable-explicit-instantiation-after-specialisation`
   (WP-066's F4: at this pin the rename claims all three tokens and
   the post-image compiles) loses its mark here, once its answer is
   verified end to end by the digest and not only blessed.
4. **When the kinds widen** (not this package): the table's rows for
   the kinds §9.1 does not allow are the specification that package
   starts from. Say what is missing in Kiln's records for them, if
   anything, as "For Kiln".

## Tests

One per row of item 1's table that applies to Function and Variable
targets, end to end (the edit, then verified by the digest); the two
merged tests; a name of the target in a role the table refuses is a
refusal that names the role and the place. Mutations: each role
skipped in turn fails a named test (a name left behind is `changed`
or a refusal, never `verified`).
