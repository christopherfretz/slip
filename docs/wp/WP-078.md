# WP-078 — the rename transform tests

- Status: done
- Milestone: M2
- Track: G
- Needs: WP-072, WP-076, WP-077
- Size: L
- Parallel with: WP-073

## Scope

`tests/transform/rename/`: the rename, end to end through the
executable, in the form of `spec/harness.md` §6.2 and under all five
oracles of §6.4. These are the tests that say a release candidate's
rename is right; the unit tests of `slip_refactor` say only what it
claimed.

**The author of these tests did not write the rename.** They are
written from `spec/edits.md` §2, §8, §9 and §10 and from
`spec/pitfalls.md`, not from the code. Expect to find defects, in the
rename, in reduce, in the report and in the spec. A defect is not fixed
here: the test is written as the spec says it should behave and marked
`xfail: <what is wrong>`, and the handback lists it with the directory
and the smallest reproduction. A one-line fix in a file no open package
owns may be made, each listed.

Files: `tests/transform/rename/` and nothing else, except
`spec/pitfalls.md`'s index of which hazards have a transform test.

## Interface

None. One directory per case; the name says the case
(`shared-header-two-tus`, `virtual-diamond`, `macro-body-refused`).
Every `test.txt` has a `spec:` line.

## Tests

At least the following, each a directory. Where a line says "refused"
or "not verified", the test has no `post/` and checks that the tree is
untouched.

**Shared headers and agreement (§5, `spec/verify.md` §9)**

- a function declared in a header included by three source files, one
  of which also declares it itself (a second declaration, as
  `TimePassesIsEnabled` in LLVM);
- the same header included twice by one file, and through two
  spellings; a header reached by a symbolic link;
- a name that is the subject in one observer and something else in
  another at the same bytes (a header whose meaning depends on a macro
  the two commands define differently): contested, refused;
- a file two observers read with different content is not possible on
  disk at one moment; instead: two commands that reach different files
  through one include line (two `-I` orders), one owned and one under
  `dep/`.

**References (§9.3)**: one directory per row, positive (verified, with
its `post/`), including a qualified definition, `&f`, a call through a
function pointer initialised from the name, a default argument, a
`decltype`, a `noexcept` operand, a template argument, a friend
declaration, a block-scope `extern`, an explicit specialisation.

**What must stay (§4.2)**: overloads of the same name in another
namespace reached by argument-dependent lookup; a local variable, a
parameter, a field, an enumerator, a label and a macro of the same
name; the name in a comment and a string (mentions in `expect.txt`).

**Hazards (`spec/pitfalls.md`)**: for each catalogued hazard a rename
can meet, the pair it asks for. In particular: the new name hides a
function of an enclosing namespace (not verified); the new name is
hidden by a local declaration at one use (not verified, by a
`spelling denotes_other` line: `spec/verify.md` §10.3); the new name
joins an overload set of an associated namespace and wins for one call
(not verified); a rename that makes a using-declaration ambiguous.

**Spelled entities (`spec/verify.md` §10)**: a reference whose
replacement, in the post-image, names another overload of the new name
than the one it named before (`denotes_other`, with what was found); a
reference only in a header that no selected observer reads after the
edit (`unseen`: the run does not verify); an overload set of which each
call selects a different member (each spelled piece carries its own
key, all hold); a token substituted twice into calls that select two
subjects (a literal piece, no obligation, the digests alone judge).

**Refusals (§9.5, §5.2)**: each flag; a declaration under `dep/`; an
override of a `dep/` virtual; `name_taken`; a seed of another kind; no
such entity (`no_subject`); every reference in a macro body (the shape
of `llvm::callDefaultCtor`, `docs/demos/demo-2.md` §2.3).

**Macros (§2.2)**: a use in a macro argument (verified; one edit, the
votes in `expect.txt` if the argument is substituted twice); an
argument that is also stringised (the shape of `EXPECT_EQ`: not
verified in M2, with the finding at the string literal); a name pasted
from two halves (residue or refused, as §2.2 gives); a name from `-D`.

**Residue (§8.4)**: a use under `#if 0`; under a macro no command
defines; in a source file no command compiles; with and without
`allow: residue`; a mention only.

**Families and followers** (`docs/wp/WP-072.md`): a virtual family
over three files that no single observer sees whole; an unrelated
family that keeps its name; using-declarations.

**Templates** (`docs/wp/WP-073.md`), each `xfail: pending <what it
waits for>` until its part lands (the names are that package's: `KR1
amendment 1 §2` for the dependent callee, `Kiln WP-1933` for the other
dependent names): the dependent callee, with its `exempt` line and the
spelled pieces inside the exempt unit still checked; a member of a
class template; the argument-dependent case that must not verify. An
explicit specialisation and an explicit instantiation of a function
template are not among these: they are §9.3's rows and verify.

**Commands (§10)**: an observer that does not parse, with and without
`allow: unparsed` (`incomplete`, status 4, without); `usage` and
`input` states; a database with two configurations of one file
(`cdb.json`), where the name is a function in one and absent from the
other.

## Done when

`cargo xtask transform` passes (every test `PASS` or `XFAIL`) and the
gate runs it; no test turns an oracle off without a reason that names a
spec section; the mutation oracle ran on every accepted test and its
count of mutations is in the handback; the handback lists every
`xfail` with its cause and the package or Kiln follow-up it waits for,
and every defect found, by directory.

## Out of scope

Fixing what the tests find. The corpus (`docs/wp/WP-079.md`). Tests of
transforms other than rename.

### Defects, by severity

1. **Rename / Kiln table, medium** — `stay-label` (xfail). A label named
   like the old name: `goto f` is not claimed `keep` (edits §4.2) and is
   listed as residue `not_compiled`, so a correct rename ends
   `verified_with_residue` and writes nothing without `allow: residue`.
   Reproduction (`stay-label/pre/a.cpp`): `namespace a { int f(int x)
   { return x; } int u(int n) { int r = 0; f: r += f(1); if (r < n) goto
   f; return r; } }`, `rename --from a::f --to g`.
   Waits for: the label use to be recorded as a non-reference (a Kiln
   occurrence for the label in `goto`, or rename treating it as `keep`).
2. **Report, low** — `refuse-mixed-follower`, `family-hidden-shadow-mixed`.
   The line `refusal mixed_follower: …` prints the follower's 64-hex key
   id (the runner normalises it to `<id>`) instead of a display: the
   follower is not in `set.subjects`, and
   `crates/slip_cli/src/transform/lines.rs` (about line 258) falls back to
   the key's text. Reproduction: `namespace n { struct B { int f() {
   return 0; } }; struct D : B { using B::f; int f() { return 1; } }; }`,
   `rename --from n::B::f --to g`. Not a one-line fix; written as the
   output is, the expectation records `<id>`.
3. **Unreproduced, to watch** — once, in a parallel batch run,
   `stay-macro-same-name` ended `not_verified` at bless ("cannot bless:
   state not_verified"); seven later runs (alone and in the full suite)
   ended `verified_with_residue`. The work directory was overwritten; no
   reproduction.

No `capped-run` kill and no status 137 was seen.

### Spec findings

- **edits §9.5 (unreachable rows)**: `hazard-attribute-argument` — the
  name in `__attribute__((cleanup(f)))` is now recorded and edited, and
  the run verifies; the row that calls it unreachable is out of date.
  The test is written to the behaviour (verified), which is what
  pitfalls R14's `good` asks for.
- **harness §6.4 (the back oracle)**: "the inverse ends in the same state"
  does not hold (a) when the residue is one-sided — the inverse of a run
  with residue of the old name has none, so it ends `verified`; the
  residue tests also hold a use of the new name in the same non-compiled
  place, so that the oracle stays on; (b) when `name_taken` is not
  symmetric (a derived or base class declares the old name): oracle off
  in two tests, see below. Suggest §6.4 say the back oracle compares
  states modulo residue, or that a test may turn it off citing §9.5.
- **harness §6.2**: a header reached by a symbolic link cannot be
  written (links are forbidden in a test), and there is no capability
  directive to skip a case-only spelling (`H.h`) on a case-sensitive
  volume. Neither is covered; `shared-header-two-spellings-two-tus` uses
  `sub/../h.h`, which is one real path on both kinds of volume.
- **edits §10.1 against the brief**: `--dependent` defaults to `leave`
  (spec and CLI agree); the package's text expected the offering form.
  Tests follow the spec.
- **edits §9.5 / §10.1 silent**: `--kind function` naming a variable
  gives `subject_unsupported`; the spec does not say which refusal a
  seed of a kind excluded by `--kind` gets (`refuse-kind-mismatch`
  records what the tool does).
- **verify §10 / edits §10.5**: votes are not in the output, so "the
  votes in `expect.txt`" (macro argument substituted twice) cannot be
  shown; `macro-argument` shows one edit.
- **verify §10.3 `unseen`**: not reachable from a rename with the
  observer still parsing (a rename changes no directive, so every
  observer that read the reference reads the edit); `spell-unseen-not-parsed`
  covers the nearest case (`not_parsed`).

### Mutations

The mutation oracle ran on all 56 accepted tests (`verified` or
`verified_with_residue`): 298 mutations (186 dropped edits, 22 added at
kept ranges, 90 flipped keys), every one caught. The runner does not
print the count; it is derived from each `expect.txt` as
`min(edits, 8) + min(kept, 4) + min(spellings, 4)`.

### Not covered, and why

- A header reached by a symbolic link, and a case-only spelling: harness
  §6.2 (above).
- Votes: not in the output (above).
- R05, R08, R09, R10, R16, R18, R21, R22: they rename locals, two names,
  enumerators, types or template parameters, which wait for edits §11.
- An `unseen` obligation with the observer parsing (above).
- A database the tool cannot read: the runner itself rejects malformed
  `cdb.json` as an error of the test, so `input` is reached through
  `owned:`/`readonly:` on one path instead.
