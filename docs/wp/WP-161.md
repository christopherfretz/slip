# WP-161 — the store without link-then-unlink, and reads by id that are checked

- Status: review
- Milestone: M1
- Track: C
- Needs: none
- Size: S

## Scope

Found by WP-159 (`spec/landed/harness/WP-159.md`, "A finding" and the
audit; the supervisor's rulings under `docs/wp/WP-159.md`).

1. **No promise of the store rests on reading a name just after it was
   linked and its source unlinked.** On the workspace mount (`cargo
   xtask fscheck`, row `unique-tmp-link`) such a name reads as absent
   for a while, about once in 1,000 to 6,000. The two sequences that do
   it are the lock (`slip_exec::store::Store::take_lock`) and the
   journal (`slip_cli::transform::store::StoreJournal::publish`).
   Ruled: both are made by **exclusive creation of the final name**
   (`create_new`), written and synced in place; no hard link is left in
   the product.
   - The lock: a reader that finds it empty or without its newline reads
     "being written" and retries as it retries a lost race today; the
     take-over of a stale lock keeps its check that what was moved aside
     is the stale lock. Say what a crash between creation and the write
     leaves (an empty lock whose owner cannot be read) and how the next
     opener gets past it without two openers taking it at once; if that
     cannot be made sound without a link, stop and say so with the
     sequence that breaks.
   - The journal: `slip_apply` touches no file of the tree before the
     journal is written and synced (check this in `slip_apply::write`
     and state where). A journal that does not decode whole (its length
     and digest are in it; if they are not, the format gains them by its
     version rule) is "the write was interrupted before any file was
     touched": `apply --recover` removes it and says so; `apply --write`
     refuses as it does for any journal.
   - The close of a store that reads its lock as absent, and a process
     that opens the same store again after such a close (today: its own
     live pid in the lock, `Busy`), are tests.
   - `cargo xtask fscheck` gains the row for the new sequence
     (`create-new-read`, relied on) and `unique-tmp-link` becomes "not
     relied on"; `spec/harness.md` §11 and `spec/exec.md` §2.1 follow.
2. **A read by id is checked against the id.** The plan read by `--plan
   <id>` and the declared changes read by `check --declared <id>` are
   decoded and not compared with the id they were asked by
   (`spec/exec.md` §2.1 "Which reads are checked"). Both are compared;
   a difference is the `Input` error a blob gives. The map shards `slip
   map` counts failed runs in, and run records, stay as they are: say in
   §2.1 why each cannot mislead (what is compared instead).

## Handback

### What changed

- **The lock** (`slip_exec::store`): created exclusively under `lock`,
  written `<pid>\n` and synced in place. Who may read and act on it is
  decided by **claims**, `tmp/<pid>.<t>.<n>.claim`: an opener creates
  its claim, lists `tmp/`, and goes on only if no other live process has
  one (else it removes its claim, backs off and retries, at most 8
  rounds, then `Busy`). Inside, an absent lock is created; a live other
  pid's is `Busy`; a dead pid's, an empty one, or digits without the
  newline are stale, removed and created again; anything else is `Io
  InvalidData`, left alone. A process-wide registry (under the mutex of
  the takes) says which locks this process holds: a second exclusive
  open in the process is `Busy`, and a lock of this process's pid that it
  no longer holds (a close that read it as absent) is taken by its next
  exclusive open. The close removes the lock only if it reads this
  process's line. The protocol is generic over `LockFs` so its tests run
  over a file system in memory. No hard link.
- **The journal**: `Store::publish_journal` creates `write.journal`
  exclusively, writes, syncs it and the store's directory;
  `read_journal`, `remove_journal`. `StoreJournal` (`slip_cli`)
  delegates to them. Its format is a `JRNL` container, version 1, the
  record in section 1 (`slip_apply::journal`; `model.md` §5.1 lists
  `JRNL`). `Journal::read` gives `Whole`, `Interrupted` or `Err`
  (malformed, kept). `recover` removes an interrupted journal
  (`Recovered.interrupted`); `discard_interrupted` does only that.
  `apply --recover` says `recovered: the write was interrupted before
  any file was touched; the journal is removed` and exits 0; `--write`
  refuses any journal as before. Journals without a container (earlier
  Slips) are still read.
- **Reads by id**: `load_plan` (every `--plan <id>`: parse, verify,
  declare, units, map, rename, reduce, check) and `check --declared
  <id>` compare the content id of what they read with the id: `Input`,
  `<path>: the file's content id is not its name`.
- **fscheck**: row `create-new-read` (relied on: `L` created
  exclusively, written, synced, read; a claim created, listed, removed,
  no longer listed; `L` read again); `unique-tmp-link` not relied on.
- **Specs**: `exec.md` §2 (Locking), §2.1 (`tmp/` names, which reads are
  checked, fsync, "The lock" with the argument, "The journal",
  Closing), §2.2 (the journal methods); `edits.md` §7.3 step 2 (the
  container, whole / interrupted / legacy / malformed), the recovery
  paragraph, §7.4, §10.4; `model.md` §5.1; `harness.md` §11.2, §11.4.
- **Soak**: `crates/slip_exec/examples/lock_soak.rs`.

### Where the soundness argument is

`spec/exec.md` §2.1 "The lock" (the steps, "Why two openers never both
hold the lock", "After a crash at any one step"), and in full, with the
breaking sequence of the old take-over without a link, the lemmas and
the table of what each observer sees, `spec/landed/exec/WP-161.md` §1
and §2. **The lock is sound without a link**, under three assumptions:
the file system is linearizable for create, unlink, read by name and
listing (row `create-new-read`), `/proc` tells a live pid from a dead
one, and every exclusive opener is a Slip following §2.1.

The journal: in `slip_apply::write`, `journal.publish` is
`crates/slip_apply/src/write.rs:552`; the first touch of the tree is
`tree.create` of the first staged name, `write.rs:577`. The journal is
synced at `crates/slip_exec/src/store.rs:1135` (`f.sync_all()`) and the
store's directory at `store.rs:1137`, inside `publish_journal`, before
it returns.

### Choices for the supervisor

1. **Claims as the mutex of the lock's readers** (a new mechanism, not a
   repair of the old take-over): relies on a listing of `tmp/` seeing a
   claim made before it (row `create-new-read`). Under heavy contention
   two openers can both end `Busy` after 8 rounds although neither held
   the lock (safety over liveness).
2. An empty lock, or digits without the newline, seen *inside* (claims
   checked) is taken over at once, not waited on as "being written": a
   writer of it would hold a live claim, so none is writing it.
3. A process-wide registry of held locks lets a process take back a lock
   of its own pid that it no longer holds (a close that read it as
   absent), and makes a second exclusive open in the process `Busy`.
4. The journal is a `JRNL` container (version 1, the record in section
   1), which carries its length and digest.
5. Journals of earlier Slips (no container) are still read: `Whole` if
   they decode and pass the rules, else interrupted.
6. A cut or corrupt container is interrupted (removed by `--recover`); an
   `UnsupportedVersion` or a whole one that breaks the rules is malformed
   and kept.
7. API: `Recovered.interrupted` and `discard_interrupted` in
   `slip_apply`.
8. The journal's create, read and remove moved into `slip_exec::Store`
   (`publish_journal`, `read_journal`, `remove_journal`); `StoreJournal`
   delegates.
9. The brief names an existing test of openers racing for a stale lock:
   none existed. `s2_openers_racing_for_a_stale_lock` is new.
10. Pid namespaces (two containers sharing a store) are out of scope, as
    before: assumption (P).
11. The racing test and the soak start their copies by `args_os[0]` with
    a retry on `NotFound`: on the mount `/proc/self/exe` can read
    `… (deleted)`.
12. The back-off between rounds is random (found by the soak: a function
    of the pid and the round kept two openers meeting every round;
    `spec/landed/exec/WP-161.md` §4).

### Fix round 1

The review (`.build/review-161/findings.md`) found two blockers; both are
fixed as ruled. Choices 1–4 and 7–12 above stand; choice 5 is gone;
choice 6 is replaced by finding 2 below; choice 3 by finding 1.

**Finding 1 — the lock names its take, not the path.**
- The lock line is `<pid> <nonce>\n`: pid u32 and nonce u64, both
  canonical decimal (no sign, no leading zero), one space, one newline,
  at most 32 bytes (`4294967295 18446744073709551615\n`). The nonce is
  drawn per take (`RandomState` keys and the clock), never one already in
  the registry.
- `HELD` is now the set of nonces this process holds, under its mutex.
  Step 3 reading `<Q> <N>\n`: `Q` is me and `N` is held → `Busy`; `Q` is
  me and `N` is not held → stale, removed; `Q` another pid alive →
  `Busy`; dead → stale. The old form `<Q>\n`: `Q` me → `Busy`, never
  taken back; `Q` dead → stale; `Q` alive → `Busy`.
- A partial lock is any proper prefix of a line: `\d{0,10}`, or
  `\d{1,10} \d{0,20}`, without the newline (`lock_texts` checks every
  prefix of the longest line is partial and lists what is not).
- The close removes the lock only if it reads exactly its own line.
- `VERSION` is `2\n`. `1\n` is refused: "store version 1: written by an
  earlier Slip, whose lock this Slip does not share (this Slip reads
  version 2); use a new store". The reading of an earlier Slip's journal
  is gone.
- Lemmas 2 and 3, the theorem and (S) are restated in `spec/exec.md` §2.1
  and `spec/landed/exec/WP-161.md` §2.
- Tests: `s2_two_spellings_of_one_store_in_one_process` (a symbolic link
  on the container's disk; both orders; another process `Busy`; then a
  leftover lock taken back through the other spelling); unit tests
  `a_take_held_by_this_process_is_busy`, `a_close_removes_only_its_own_take`,
  `locks_of_the_old_form`; the version refusal covers `1\n`.

**Finding 2 — the journal's length.** The head, byte by byte:

| Bytes | Content |
|---|---|
| 0..8 | magic |
| 8..12 | `JRNL` |
| 12..16 | version 1, u32le |
| 16..18 | `01 10` (section 1, 16 bytes) |
| 18..26 | total length of the file, u64le |
| 26..34 | first 8 bytes of `content_digest(bytes[0..26])` |

then section 2 (the record), the end byte, the 32-byte trailer. The
length's check is a header digest (not the length written twice): it
also covers magic, kind, version and framing. Classification, in order:
< 34 bytes interrupted; bad magic/kind malformed; framing or check bad
malformed; version ≠ 1 malformed; shorter than declared interrupted;
longer malformed; container rule 5, a missing record section, an unknown
critical section, a record that does not decode or breaks a rule
malformed; else whole. Interrupted: `--recover` removes it and says
`recovered: the write was interrupted before any file was touched
(<why>); the journal is removed`. Malformed: exit 3, `<path>: <reason>;
the journal is damaged, not cut short: it is kept and nothing was changed
(spec/edits.md §10.4)`. `spec/edits.md` §10.4 says a zeroed tail is
malformed and what the user does.
- Tests: `damaged()` in `crates/slip_apply/tests/write.rs`, 20 damages
  (the reviewer's five among them: a bit in the record, in the trailer,
  in the magic; bytes appended; the tail zeroed), each expected kept by
  `s7_3_recover_refuses_a_malformed_journal` and `Err` in
  `s7_3_journal_record`; `slip_cli` `s7_3_recover_removes_an_interrupted_journal`
  adds a flipped bit kept, exit 3.
- Old tests changed: `s7_3_recover_removes_an_interrupted_journal` no
  longer expects removal of a whole-length zeroed file or a flipped bit
  (now malformed, in `damaged()`), nor of an earlier Slip's cut record;
  it expects `interrupted: Some(why)` with the reason. The
  `s7_3_recover_refuses_a_malformed_journal` cases (newer version,
  unknown section) moved into `damaged()` in the new format.
  `s7_3_journal_record` no longer reads an earlier Slip's record as whole
  nor its prefixes as interrupted (choice 5 gone): it is malformed.
  `s7_3_a_torn_publish_leaves_an_interrupted_journal` checks
  `interrupted.is_some()`.
