## Interface

```rust
// slip_kiln::parse
impl<'r> Unit<'r> { pub fn stack_remaining(&self) -> Option<usize>; }

// slip_digest::map
pub fn with_input<R>(unit: &slip_kiln::Unit<'_>, subject: &dyn Fn(&[u8]) -> Vec<u8>,
                     f: impl FnOnce(&Input<'_>) -> R) -> Result<R, String>;

                   subject: &dyn Fn(&[u8]) -> Vec<u8>) -> Result<Output, String>;

```

What you build on, as it is today:

- `parse_observer_with` (`crates/slip_kiln/src/parse.rs:119`) calls its
  closure on the front end's own thread with the AST final
  (`parse.rs:166-178`); that
  thread has the command's `-fkiln-stack-size=` or Kiln's 1 GiB and
  Kiln's stack guard installed
  (`kiln/crates/kiln_driver/src/front_end.rs:221-248`,
  `kiln_sema/src/stack_guard.rs:33`). `StackGuard::current().remaining()`
  is `stack_guard.rs:100` and `:121`; `slip_kiln` already depends on
  `kiln_sema`.
- `slip_digest::digest(&Input, &Options) -> Output` and
  `slip_digest::STACK_SIZE` (`crates/slip_digest/src/lib.rs`,
  `walk.rs:44`). `Input.subject_path` takes a `FileId`; `with_input`
  builds it from `Unit::real_path`, `SourceManager::file_name`
  (`kiln/crates/kiln_source/src/manager.rs:1144`) and `subject`.
- A closure that must report an error from inside the walk (a buffer
  that is not an input, §8.5 "Subject paths") records the first one in a
  cell and `with_input` returns it after `f`; `f`'s result is then
  dropped. WP-052, WP-054 and WP-055 use `with_input` for the walk's
  other uses: its signature is fixed by the spec.
- `Output.causes` has one `(key, Cause)` per indeterminate key;
  `Cause::name()` and `Display` give the two halves of a cause counter.
  `groups.rs:83-107` already emits `digest.indeterminate.<cause>` and
  `digest.indeterminate.pending.<area>`; `counters` adds
  `digest.cause.<cause>.<word>` for `Unsupported` and `Unaccounted`.
- The closure's result type is your choice (`R: Send`); the task turns
  `Some(Err(text))` into `Err(text)`.
