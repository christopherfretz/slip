## Scope

Three modules of `slip_kiln`:

1. **`slip_kiln::sites`**: `spec/edits.md` §2.2 and §2.3. The file range
   and tier of a name are `slip_kiln::ranges::name_range`'s
   (`docs/wp/WP-084.md`), one function for both producers, which
   stands on Kiln's `token_end` and `editable_file_range` (Kiln
   WP-2150). `sites` adds what a native producer needs beside it: when
   there is no range, *why* (tiers 2, 3 and X), and where a person must
   look (§4.2); when there is one, whether it may be edited
   (`not_a_file`, `not_owned`, `file_recoded`, `not_plain`); the
   `MacroSite`; and the `FileRef` of a file. It computes no range and
   no end of a token: every range it gives out is `name_range`'s, or
   the range of an invocation's name token, which is `name_range` of
   that token. What it reads of Kiln's source manager beside that is
   facts, not rules: `expansion_info`, `immediate_spelling_loc`,
   `is_written_in_scratch_space`, `file_origin`, `load_report`,
   `original_bytes`, and `expansion_loc` for the outermost invocation.
2. **`slip_kiln::scan`**: the lexical half of `spec/edits.md` §8.4: the
   identifier tokens of a file that spell a name, and the mentions in
   comments and literals. It uses Kiln's lexer in raw mode over bytes,
   with no preprocessing and no source manager state kept. It needs
   nothing of the other two: write it first.
3. **`slip_kiln::tree`**: a front end over a few files written to a
   fresh directory, for tests. `slip_kiln::snippet` cannot serve here:
   its buffer is not a file, so every token in it is `not_a_file`.

Files: new `crates/slip_kiln/src/sites.rs`, `src/scan.rs`, `src/tree.rs`,
`crates/slip_kiln/tests/sites.rs`, `tests/scan.rs`; `src/lib.rs` for the
three `pub mod` lines and `pub use kiln_lex as lex;` in the module `kiln`
(with the manifest's dependency).

**Which part waits for what.** `sites` needs WP-084, and through it the
pin move after WP-044 (Slip's Kiln revision at or after `913a490bb`,
where Kiln WP-2150 is): it cannot be written before. `scan` needs
nothing but Kiln's lexer, which the present pin has, and `tree` needs
`docs/wp/WP-067.md`'s `ParseOptions`: both can be written, tested and
merged before that pin move, as a first part of this package.

## Interface

```rust
// slip_kiln::sites
pub struct Sites<'u, 'r> { /* the unit, the ownership, a cache of FileRefs */ }

/// Where a name token is written.
pub enum Located {
    /// Tier 0 or 1: the token's bytes in a file, editable.
    At { file: FileId, lo: u64, hi: u64, tier: u64 /* tiers::T0 or T1 */, macro_site: Option<MacroSite> },
    /// It cannot be edited. `at` is the range a `refuse` claim carries
    /// (§4.2); `None` is `[0, 0)` of the main file.
    Refused { reason: Reason, tier: u64, at: Option<(FileId, u64, u64)>, macro_site: Option<MacroSite> },
}

impl<'u, 'r> Sites<'u, 'r> {
    pub fn new(unit: &'u Unit<'r>, ownership: &'u Ownership) -> Sites<'u, 'r>;
    /// `name` is the span of a name token as `slip_kiln::written` gives
    /// it; `spelling` is the identifier the caller expects there.
    pub fn name_token(&self, name: Span, spelling: &[u8]) -> Located;
    /// The `FileRef` (real path, size, content digest of the original
    /// bytes) of a file a claim names; `None` for a buffer that is not a
    /// file. The same values the shard's `inputs` hold.
    pub fn file_ref(&self, file: FileId) -> Option<FileRef>;
    pub fn is_owned(&self, file: FileId) -> bool;
}

// slip_kiln::scan
pub struct Hit { pub lo: u64, pub hi: u64, pub line: u64, pub column: u64, pub mention: bool }
/// Every identifier token of `bytes` spelled `name` (`mention` false) and
/// every comment, string literal or character literal that contains
/// `name` as a whole word (`mention` true; the range is the word's), in
/// ascending order of `lo`. Lines and columns are 1-based, columns in
/// bytes. The lexer runs with the options of the latest C++ standard
/// Kiln has: one file is read by observers of several standards, and the
/// scan is a report, not a parse.
pub fn scan(bytes: &[u8], name: &[u8]) -> Vec<Hit>;

// slip_kiln::tree
pub struct Tree { /* a directory this value owns; removed on drop, file by file */ }
impl Tree {
    /// Writes `files` (relative path, bytes) under a new directory of
    /// `base` (a test passes `env!("CARGO_TARGET_TMPDIR")`).
    pub fn new(base: &Path, name: &str, files: &[(&str, &[u8])]) -> std::io::Result<Tree>;
    pub fn root(&self) -> &Path;
    /// The observer of `kiln -std=<std> <args> -I<root> -I<root>/dep -c <main>`
    /// with directory `<root>`: the default command of `spec/harness.md` §6.2.
    pub fn observer(&self, main: &str, std: &str, args: &[&str]) -> Observer;
    /// `parse_observer_opts` on it. Parses of all trees in one process are
    /// serialised by a lock here: the parse changes the working directory
    /// (`crates/slip_kiln/src/parse.rs`, "This changes the process's
    /// current directory").
    pub fn parse<R: Send>(&self, observer: &Observer, options: &ParseOptions<'_>,
                          f: impl FnOnce(&Unit<'_>) -> R + Send) -> Result<(Shard, Option<R>), String>;
}
```

Rules of `name_token`, in the order of the table of §2.3:

1. `ranges::name_range(name)` gives a range: the tier is its tier (0
   or 1). It gives none: the tier is why. The token's location, moved
   to its immediate spelling while it is in a macro-argument entry (the
   walk of `name_range`), is in an entry whose spelling is in scratch
   space: tier 3 (`pasted`); in an entry whose spelling is in a file,
   a macro's replacement list: tier 2 (`macro_body`); a spelling in a
   buffer that is not a file is X (`not_a_file`); anything else for
   which `name_range` gave none (the name's span is not one token of
   one entry, Kiln's `token_end` has no end for it) is X (`crossing`).
   `sites` must never call a token editable that `ranges` did not: the
   two agree by construction, since the `At` case is `name_range`'s
   answer and nothing else.
2. The range's buffer is not a file read from disk or through an
   overlay (`file_origin`; for Kiln every location that is not a macro
   location is a file location, the predefines' and the command
   line's included): `not_a_file`.
3. The file is read-only: `not_owned`.
4. The file's load report is not clean (`SourceManager::load_report`,
   Kiln `kiln_source/src/manager.rs:1225` at `913a490bb`: invalid UTF-8
   was replaced): `file_recoded`. Kiln's offsets are offsets in its
   text of the file, and only then are they the file's. A byte-order
   mark is part of the text (`original_bytes`, `:1253`) and shifts
   nothing.
5. The file's bytes in the range are not `spelling`: `not_plain`.

`macro_site` is the name token of the outermost invocation the bytes are
an argument of or were produced by, mapped to its file, and its
spelling; absent for tier 0. Its name token is at Kiln's
`expansion_loc` of the token's location as the parser saw it (the
start of the outermost expansion, `kiln_source/src/manager.rs:1610`),
and its range is `name_range` of that token. If the invocation's own
name is not in a file, the refusal has `at: None`.

The refusal's `at`: for `macro_body`, the token's bytes where they are
written in the definition (the spelling location; if that file is
read-only the range is still given: it is where a person must look); for
every other reason, the invocation's name token, or `None`.

Rules of `scan`: identifiers are compared after the lexer's own
canonical spelling (a universal-character-name and the character it
names are one identifier; a line splice inside an identifier does not
split it), and such a hit's range is the bytes as written. Raw strings,
`'` as a digit separator and a `#include <…>` header name are the
lexer's business: no hit inside a header name. The text of an excluded
conditional group is scanned like any other text (raw mode sees no
directives): that is what residue `not_compiled` is for.

## Tests

- `crates/slip_kiln/tests/sites.rs`, over `slip_kiln::tree`: each tier
  (plain text; an argument; an argument passed through two macros; an
  argument that names an object-like macro whose body holds the token:
  tier 2; a body; `__VA_ARGS__` tokens: tier 1, and tokens written
  inside `__VA_OPT__(…)`: tier 2; a pasted name; a stringised argument;
  a name from `-D`; a name whose qualifier and last component come from
  different expansions); each reason; two reasons at once for each
  adjacent pair of the order above; the range of each kind of refusal;
  the same bytes at tier 0 in one command and tier 1 in another (a name
  before `(` that is a macro under `-D`); an argument substituted twice
  gives two calls with equal results (the votes are the transform's to
  count); a file with a byte-order mark (editable, offsets as in the
  file) and one with an invalid byte before the token (`file_recoded`);
  `é` written as a universal-character-name (`not_plain`); a name that
  is a whole expansion (`ID(foo)`: tier 1, the argument's bytes;
  `NAME` defined as `foo`, and `#define foo foo`: `macro_body`);
  `file_ref` equals the shard's `inputs` entry. For every `At`, the
  answer equals `ranges::name_range`'s.
- `crates/slip_kiln/tests/scan.rs`: `spec/edits.md` "Tests", plus: the
  name as a prefix and a suffix of a longer identifier (no hit); in a
  comment as a word and as part of a word; in a raw string with a
  delimiter; a file that ends inside a comment; an empty file; invalid
  UTF-8 around a hit.

the handback lists, for each rule above, the Kiln function it stands on
with `file:line` at the pin, and every case where the tier could not be
told from the source manager alone (each is a candidate for
[KF3](../requests/KF3-location-utilities.md) §3, which Kiln has not
been sent). `sites` and `scan` hold no rule for the end of a token or
for a range of file characters: `scan` runs Kiln's lexer over a file
and takes each token's extent from it.
