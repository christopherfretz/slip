# WP-068 — slip_kiln: sites (from a Kiln location to a claim's range) and the residue scan

## Scope

Three modules of `slip_kiln` that every transform, native or scripted,
and their tests will share:

1. **`slip_kiln::sites`**: `spec/edits.md` §2.2 (tiers) and §2.3 (file
   ranges and the reasons a range is refused), on Kiln's location
   utilities (KF3, `docs/wp/WP-067.md`). A transform gives a location of
   a name token and gets a claim's `(file, start, end, tiers, macro)`, or
   the refusal's reason and range (§4.2: where a person must look).
2. **`slip_kiln::scan`**: the lexical half of `spec/edits.md` §8.4: the
   identifier tokens of a file that spell a name, and the mentions in
   comments and literals. It uses Kiln's lexer in raw mode over bytes,
   with no preprocessing and no source manager state kept. It needs
   nothing of KF3: write it first.
3. **`slip_kiln::tree`**: a front end over a few files written to a
   fresh directory, for tests. `slip_kiln::snippet` cannot serve here:
   its buffer is not a file, so every token in it is `not_a_file`.

Files: new `crates/slip_kiln/src/sites.rs`, `src/scan.rs`, `src/tree.rs`,
`crates/slip_kiln/tests/sites.rs`, `tests/scan.rs`; `src/lib.rs` for the
three `pub mod` lines and `pub use kiln_lex as lex;` in the module `kiln`
(with the manifest's dependency); `src/parse.rs` only to add
`Unit::lex_options` (the unit's `LexOptions`, which `token_at` takes)
and `ParseOptions::written_refs` (follow-up K-b: the parse asks the
front-end entry for the written-reference table; default `false`).
Both files are WP-066's before this package, which is why it needs it:
the pin it starts from has KF2 and KF3.

## Interface

```rust
// slip_kiln::sites
pub struct Sites<'u, 'r> { /* the unit, the ownership, a cache of FileRefs */ }

/// Where a name token is written.
pub enum Located {
    /// Tier 0 or 1: the token's bytes in a file, editable.
    At { file: FileId, start: u64, end: u64, tier: u64 /* tiers::T0 or T1 */, macro_site: Option<MacroSite> },
    /// It cannot be edited. `at` is the range a `refuse` claim carries
    /// (§4.2); `None` is `[0, 0)` of the main file.
    Refused { reason: Reason, tier: u64, at: Option<(FileId, u64, u64)>, macro_site: Option<MacroSite> },
}

impl<'u, 'r> Sites<'u, 'r> {
    pub fn new(unit: &'u Unit<'r>, ownership: &'u Ownership) -> Sites<'u, 'r>;
    /// `at` is the location of the first character of a name token as
    /// Kiln gives it (`WrittenRef.range`'s start, `DeclNode.loc`);
    /// `spelling` is the identifier the caller expects there.
    pub fn name_token(&self, at: Loc, spelling: &[u8]) -> Located;
    /// The `FileRef` (real path, size, content digest of the original
    /// bytes) of a file a claim names; `None` for a buffer that is not a
    /// file. The same values the shard's `inputs` hold.
    pub fn file_ref(&self, file: FileId) -> Option<FileRef>;
    pub fn is_owned(&self, file: FileId) -> bool;
}

// slip_kiln::scan
pub struct Hit { pub start: u64, pub end: u64, pub line: u64, pub column: u64, pub mention: bool }
/// Every identifier token of `bytes` spelled `name` (`mention` false) and
/// every comment, string literal or character literal that contains
/// `name` as a whole word (`mention` true; the range is the word's), in
/// ascending order of `start`. Lines and columns are 1-based, columns in
/// bytes. The lexer runs with the options of the latest C++ standard
/// Kiln has: one file is read by observers of several standards, and the
/// scan is a report, not a parse.
pub fn scan(bytes: &[u8], name: &[u8]) -> Vec<Hit>;

// slip_kiln::tree
pub struct Tree { /* a directory this value owns; removed on drop, file by file */ }
impl Tree {
    /// Writes `files` (relative path, bytes) under a new directory of
    /// `base` (a test passes `env!("CARGO_TARGET_TMPDIR")`).
    pub fn new(base: &Path, name: &str, files: &[(&str, &[u8])]) -> std::io::Result<Tree>;
    pub fn root(&self) -> &Path;
    /// The observer of `kiln -std=<std> <args> -I<root> -I<root>/dep -c <main>`
    /// with directory `<root>`: the default command of `spec/harness.md` §6.2.
    pub fn observer(&self, main: &str, std: &str, args: &[&str]) -> Observer;
    /// `parse_observer_opts` on it. Parses of all trees in one process are
    /// serialised by a lock here: the parse changes the working directory
    /// (`crates/slip_kiln/src/parse.rs`, "This changes the process's
    /// current directory").
    pub fn parse<R: Send>(&self, observer: &Observer, options: &ParseOptions<'_>,
                          f: impl FnOnce(&Unit<'_>) -> R + Send) -> Result<(Shard, Option<R>), String>;
}
```

Rules of `name_token`, in this order (the order of the table of §2.3):

1. `Origin` (KF3 U3) gives the tier: `File` 0; `Argument` 1; `Body` 2
   (`macro_body`); `Scratch` 3 (`pasted`); `NotAFile` X (`not_a_file`).
   The token's extent is `token_at` (U1). If the extent does not map to
   one contiguous piece of one file (`file_char_range`, U2, is `None`),
   or the token's text there is not one token, the tier is X
   (`crossing`).
2. The file is read-only: `not_owned`.
3. `original_offset` (U4) is `None` for the start or the end:
   `file_recoded`.
4. The file's bytes in the range are not `spelling`: `not_plain`.

`macro_site` is the name token of the outermost invocation
(`Origin`'s `invocation`, mapped to the file by the same functions) and
its spelling; absent for tier 0. If the invocation's own name is not in
a file, the refusal has `at: None`.

The refusal's `at`: for `macro_body`, the token's bytes where they are
written in the definition (the spelling location, mapped as above; if
that file is read-only the range is still given: it is where a person
must look); for every other reason, the invocation's name token, or
`None`.

Rules of `scan`: identifiers are compared after the lexer's own
canonical spelling (a universal-character-name and the character it
names are one identifier; a line splice inside an identifier does not
split it), and such a hit's range is the bytes as written. Raw strings,
`'` as a digit separator and a `#include <…>` header name are the
lexer's business: no hit inside a header name. The text of an excluded
conditional group is scanned like any other text (raw mode sees no
directives): that is what residue `not_compiled` is for.

## Tests

- `crates/slip_kiln/tests/sites.rs`, over `slip_kiln::tree`: each tier (one test per row of KF3's table §3.3 and per
  settled edge row, seen through `name_token`); each reason; two reasons
  at once for each adjacent pair of the order above; the range of each
  kind of refusal; the same bytes at tier 0 in one command and tier 1 in
  another (a name before `(` that is a macro under `-D`); an argument
  substituted twice gives two calls with equal results (the votes are
  the transform's to count); a file with a byte-order mark and one with
  an invalid byte before the token (`file_recoded`); `é` written as
  `é` (`not_plain`); `file_ref` equals the shard's `inputs` entry.
- `crates/slip_kiln/tests/scan.rs`: `spec/edits.md` "Tests", plus: the
  name as a prefix and a suffix of a longer identifier (no hit); in a
  comment as a word and as part of a word; in a raw string with a
  delimiter; a file that ends inside a comment; an empty file; invalid
  UTF-8 around a hit.
