# WP-156 — the digest: operand units (a name in an operand that only a type or a value holds)

- Status: review
- Milestone: M1
- Track: C
- Needs: WP-155
- Size: L
- Parallel with: every non-digest package; one digest branch merges at a time

## Scope

Stage O of `docs/wp/WP-153.md`. The design is
`spec/landed/digest/WP-153.md` §3.7 and §3.8 **as ruled in its §13.2**:
where §13.2 differs from the sections before it, §13.2 holds, and this
package lands the ruled text in `spec/digest.md` and
`spec/digest-kinds.md`. It needs nothing of Kiln beyond the pin.

The digest writes a type by its canonical form and a constant by its
value. A name inside an expression that only such a type or value
holds is then written nowhere:

```cpp
namespace lib { struct X {}; int make(X); }   // a migration leaves make behind
template <class T> int make(T);
lib::X x;
decltype(make(x)) y;                           // lib::make, or ::make<lib::X>: `int` both times
template <class T, unsigned long N> struct array {};
array<char, sizeof(make(x))> a;
```

1. **The operand unit.** `KeyKind` 35 `operands`, `Name` 17, parent
   the unit's key, no discriminator; derived, in the derived group of
   the parent's file. Stream: per declaration of the entity that has a
   written operand, in declaration order, a count and then the
   operands (§13.2 B2); per operand its site and the ordinary
   expression walk, or for site 8 the canonical form of each argument.
   The parent may be any unit: a declared entity, a specialisation, a
   `definition`, a resolved `exception_spec`, a default argument's
   unit.
2. **The sites are the holders of a written type** (§13.2 B4), each a
   row of the completeness test of `spec/digest.md` §13 and a class of
   its own in `spec/digest-kinds.md` (S1): a declaration's written
   type (return, each parameter before adjustment, variable, field,
   typedef and alias, base specifier, friend); a default template
   argument; the argument list of an explicit or partial
   specialisation and of an explicit instantiation; in an expression,
   the template arguments and qualifier of a reference to a
   declaration, of a member expression and of a concept-id, and the
   written type of a cast, `sizeof`, `alignof`, `typeid`, a type
   trait, `new`, a compound literal; a nested-name-specifier that
   names a type. Inside a written type the operands are: `decltype(e)`
   (1), `typeof(e)` (2), an expression template argument (4),
   `noexcept(e)` (6), and the written argument list of an alias
   specialisation (8). Sites 3 (array bound), 5 (pack index) and 7
   (`explicit(e)`) are not built: 3 and 5 are not in the AST at the
   pin (B1, B7), 7 is walked today (S1). Their numbers stay reserved.
3. **What is written and what is not** (S5, B5): an operand of sites
   1, 2, 4, 6 is written only if its walk writes a reference to a
   declared entity or a selection; a site-8 operand always. An operand
   that is instantiation-dependent is not written (a pattern's own
   spellings have it). The walk stops at a substituted parameter's
   replacement (type or non-type), at an alias's underlying type, at a
   typedef's, at a specialisation's own argument list. Never read: the
   type of an expression; a deduced type (S3). Kiln has no fact for
   "declared with a placeholder" at the pin (its WP-3583 adds one;
   `docs/requests/KR9-substitution-bindings.md` §5.12 D), and its own
   walk of written expressions follows a deduced type, so do not use
   that walk for this. Tell a placeholder from what the pin does give
   (the declaration's type specifier in the source); where that cannot
   be told, read the stored type, count it, and state the duplicates.
4. **State and nesting** (S6, S7): an operand is walked in its
   parent's state (the numbers of the parent's parameters and locals,
   its `this`); a parameter of a function type without a function
   declaration by depth and index; a nested operand is its own entry
   right after the one that holds it; each written operand once (from
   the parameter declarations where a function has them); a lambda in
   an operand by `spec/digest.md` §4.3. For a specialisation the
   `noexcept` operand belongs to the resolved `exception_spec` unit's
   operand unit only (S4). An operand unit inherits its parent's
   cause.
5. **Member templates of an instantiated class** (B3): the
   `definition` unit of a class made by instantiation writes the
   sorted keys of its member templates. Prove with a pair that a
   correct relocation of a namespace such a signature refers to leaves
   the class's unit equal through the map. If the key cannot be
   mapped, stop and report: that is a ruling.
6. **The pair runner and the existing pairs** (S2): `equal` stays
   strict; a class for "every unit both sides have is equal, the
   one-sided units are operand units, no finding". Move
   `equal/_/decltype-non-dependent` and `equal/TypeView/Decltype`
   there. **List any other existing pair, pitfall tree or golden whose
   verdict or digest changes before changing it**; each is a ruling.
7. **`scheme`** by `spec/digest.md` §11: the next number, or the
   number in force if no baseline of it is recorded when this lands
   (ask the supervisor at the final merge of `main`).
8. **The specs**: `spec/digest.md` §2.3 (the limit rewritten: what is
   closed; what stays by name: an array bound, an adjusted parameter
   of an instantiated function, a pack index, `explicit(bool)` of a
   function template specialisation, a template candidate the front
   end did not instantiate), §2 and §3 (the unit and its key), §13;
   `spec/digest-kinds.md` (the operand class, `KeyKind` 35, `Name`
   17, the instantiated class's member-template list);
   `spec/verify.md` §4 step 3 (S8: why a one-sided operand unit is no
   finding) and the report's detail for an operand unit (the operands
   of each side, so a person sees which is gone or moved);
   `spec/model.md`; `spec/pitfalls.md` rows for the cases below.
9. **Counters and the corpus command** for the supervisor: operand
   units, operands per site, site-8 operands, operands skipped by item
   3's test, deduced types read; on `llvm` `lib/Support`: the count of
   each, digest bytes and time against `main`, and that Demo 1's
   control and `01-relocate` stay clean.

### The rewrite under X3, M-1 and M-2: unlinked held types

Round 1's sets were read from every type of the arena that holds an
operand, so any spelling anywhere (`decltype(obj) other;`, an alias
template, a `decltype(k)`) triggered a refusal. Now `operands::linked`
collects the types the declarations hold as written (each
declaration's type, a parameter's before adjustment, a typedef's, a
friend's and its row's qualifier and arguments, an enumeration's
underlying type, the bases, the template parameters' defaults, a
using-declaration's qualifier, the arguments as written) with the
types written inside them; the sets (`Tu`) are read from the types
that are **not** linked, hold an operand that is no literal, are not
instantiation-dependent and hold no substituted parameter. Kiln
interns a type holding an operand by its expressions, so one spelling
is one type: a spelling Kiln does not link (a placeholder's
constraint, a qualifier's template-id, a directive's declarator) is
unlinked, one a declaration holds is not. A type written in an
expression is not linked either, so the sets are wider than what is
unkept, never narrower (a refusal, not a wrong answer).

Two location windows narrow what has no type to compare
(`bounds_of`, `window`): the bounds are the names of the declarations
outside functions, lambdas and requires-expressions (not a class or
enumeration that is no definition, which an elaborated-type-specifier
inside an operand declares), and the ends of their bodies and
initialisers; all are expansion locations.

## Design for fix round 3 (2026-11-28)

### Diagnosis

Three rounds gave three lists of new wrong answers because the method
has three leaks, and only the first was ever worked on.

1. **Exhaustive over kinds is not exhaustive over what a kind stores.**
   Fix round 1 made `scan`, `holders_of` and `signature_of` list every
   kind. A listed kind can still read one field and pass another: the
   `Function` arm reads `NoexceptExpr` and passes `ExcSpec::Dynamic`
   (A5); the `Vector` arm reads `elem` and passes `count`, a number
   Kiln folded from an expression (A4); `DependentVector`,
   `DependentAddrSpace`, `DependentSizedArray` and `PackIndexing` read
   the element and pass the expression beside it. And the recursion
   over `TypeView` exists five times (`scan`, `holds`, `link`,
   `substituted`, `type_exprs`), three of them with `_ =>`, which must
   agree and do not.
2. **What Kiln stores on no node cannot be found by reading nodes.**
   A directive's declarator, a friend specialisation's declarator, a
   declarator's qualifier, a destructor's name, a deduced placeholder's
   constraint, and every expression Kiln folds to a number (`_BitInt`
   width, vector size, address space) leave no slot. Rounds 1 and 2
   infer them from residue: types of the arena no declaration "links",
   and expressions located in a window of source. Each inference is a
   **join that answers "nothing was written" when it finds no match**:
   `function_key` compares the specialisation's deduced `int` with the
   declarator's `auto` and finds none (A1); the friend's function type
   is tested only up to its exception specification (A2); the window
   is a pair of expansion locations, which are one point inside a
   macro (A3). The default is `equal`, so every miss is a wrong
   `verified`. A1 to A3 are not new holders: X3, X7 and X8 found the
   holders, and the narrowing let them through.
3. **`linked` is a second, hand-written copy of the holder list.** It
   reads declarations only, so a type written in an expression is
   "unlinked" and widens every set (B1). Its misses fall on the safe
   side, but they fall on ordinary code.

So the set of places read is "what somebody listed", and nothing
compares it with what was written. What makes it provable is a ledger
Kiln already keeps and tests for totality: the **written-reference
table** (Kiln `spec/ast.md` §18). It has one entry per name written in
the source, with the declaration the name denotes after resolution
(`entity`: the overload chosen, the specialisation), the declaration
whose text holds it (`enclosing`, stored, not derived from locations),
and token locations with macro provenance. Kiln's identifier accounting
test (§18.8) shows that every identifier token is an entry, a declared
name or a listed non-name; §18.11.1 shows that every `DeclRefExpr` and
`MemberExpr` built from a written name joins exactly one entry by
`name_lo(id) == loc()`. `docs/requests/KT1-written-placeholder-and-qualifier.md`
§3 set the table aside because "it holds references, not the operands'
trees". For reading an operand that is right. For **closing** the set
it is what is needed: the wrong answer of N47 is a written name that
binds otherwise, and the table has every written name.

### The mechanism

Two layers. Layer S makes the reading of what Kiln stores total by
construction (leak 1). Layer L replaces every residue inference by a
conservation rule over written names (leaks 2 and 3): **a name written
in the source is walked by a stream, or written into an operand unit by
its entity, or the translation unit is indeterminate.** No rule of this
round reads a source location to decide what a declaration wrote, so
there is no window, and a macro changes nothing.

#### Layer S: one traversal, exhaustive over fields

1. `operands::slots(types, t, f)`: the one place that destructures
   `TypeView`. Every variant is matched with **every field bound to a
   name** (no `..`, no `field: _`), under `#[deny(unused_variables)]`,
   and each bound field is passed to exactly one of:

   | Slot | Meaning | Fields (all of them; a new field does not compile) |
   |---|---|---|
   | `Type(q)` | written inside: descend | pointee, referee, element, `Paren`, `Complex`, `Atomic`, `ExtQual.base`, `Attributed.modified`, `Decayed.original`, `PackExpansion.pattern`, `PackIndexing.pattern`, `UnaryTransform.base`, `MemberPointer.{pointee, class}`, `QualifiedArray.base`, `Elaborated.named`, a function type's result and parameters, `TypeOf(Type)`, **each type of `ExcSpec::Dynamic`** |
   | `Operand(site, e)` | an operand | `Decltype.expr` (1), `TypeOf(Expr)` (2), `ArgView::Expr.expr` (4), `ExcSpec::NoexceptExpr.expr` (6) |
   | `Bound(o)` | an expression beside a type that is no site of §2.4 | `ConstArray.size_expr`, `VariableArray.size`, `DependentSizedArray.size`, `DependentVector.size`, `DependentAddrSpace.space`, `PackIndexing.index` |
   | `Args(l)`, `AliasArgs(l)`, `Nns(n)` | a written list or qualifier | `TemplateSpecialization.args` (alias: site 8), `Auto.args`, `DependentTemplateSpecialization.{nns, args}`, `DependentName.nns`, `Elaborated.nns` |
   | `Folded(what)` | a value Kiln computed from an expression it does not keep | `BitInt.width`, `Vector.count`, the address space of `ExtQual.word`, each `TypeAttrKind` that takes an argument (an exhaustive match over `TypeAttrKind`) |
   | `Splice` | `Splice.operand`, `Nns::Splice` | |
   | `Denotes(x)` | what a name denotes or Kiln computed: never descended | `Typedef.underlying`, `Using.underlying`, `TemplateSpecialization.underlying`, `Decltype.underlying`, `TypeOf.underlying`, `Auto.deduced`, `DeducedTemplateSpecialization.deduced`, `SubstTemplateTypeParm.replacement`, `InjectedClassName.injected`, `Attributed.equivalent`, `Decayed.adjusted`, `UnaryTransform.result`, `PackIndexing.selected`, `Splice.designated`, `NoexceptExpr.value`, every `ProfileId`, `ExcSpec::Deferred` |
   | `Plain(x)` | a declaration, keyword, flag or index that is no written syntax | the rest, each named |

   `ExcSpec`, `ArgView`, `Nns` and `TypeOfOperand` are matched the
   same way inside it. `scan`, `args` and `scan_nns` become the one
   consumer of `slots`. `holds`, `link`, `link_args`, `link_nns`,
   `substituted`, `arg_types`, `args_exprs` and `type_exprs` are
   deleted with their users (Layer L), so no second recursion is left
   to disagree.
2. What the consumer does with a slot: `Type`, `Args`, `Nns`: recurse.
   `Operand`: `push`, as today. `AliasArgs`: as today. `Bound(Expr(e))`:
   `dependent(w, e, out)` when `e` is instantiation-dependent (its
   holders are read, as for any dependent operand); otherwise nothing
   here: the names in it are Layer L's (rule L3), and sites 3 and 5
   stay reserved. `Bound(Profile)`: nothing (canonical). `Folded`: sets
   `State::folded` (rule L4, T3). `Splice`: `Op::Unkept(SPLICE)`.
   `DependentBitInt`: `Op::Unkept(BIT_INT)`, as today.
3. `holders_of` keeps its exhaustive match over `ExprKind`. Two
   changes: the `_BitInt`, destructor and `new` placeholder checks go
   (Layer L), and a **census test** is added (below), since an
   expression's operands are untyped words that a match cannot see.

**The census** (a unit test in `operands.rs`, read from Kiln's public
role tables, `kiln_ast::roles`): for every `ExprKind`, every word of
`expr_roles(k)` (`a`, `b`, `aux`, through `Opt`, `List` and `Side`)
whose role is `Type`, `TypeId`, `ArgList` or `Nns`, and every row of
`COLD_MAPS` keyed by an expression or a declaration whose value has
such a role or is a `Record`, must have a row in a table
`operands::SLOTS: &[(owner, word, Disposition)]`, with `Disposition`
one of `Read(by)` (the function that scans it), `NodeType` (the node's
own type is the written one), `Computed(why)` (a type Kiln derived,
never written), `Stream(why)` (the unit's own stream walks it). A role
table entry with no row fails the test and names the word; a row that
names no word fails too. For declarations the same test reads
`tables.rs`' field rows (the test of `spec/digest.md` §13 item 4
already ties them to Kiln's schema): every stored field of a
declaration payload or side record whose Kiln type is `QualType`,
`TypeId`, `ArgListId`, `NnsId`, `TemplateParamListId` or `TypeList`
has a row. The test is the totality proof of Layer S: every place Kiln
**stores** a written type or list is read or carries a stated reason.
`spec/digest.md` §13 gets it as item 9.

#### Layer L: the ledger of written names

L0. **The table is always recorded.** Every parse whose result is
digested sets `ParseOptions::written` (`slip_cli` `worker.rs`,
`image.rs`, `worker/post.rs`; the digest test harness). When
`Ast::written_refs` is not on, or `unrecorded()` is not empty (a
snapshot or module image made without it), the operand unit of the
translation unit's `<order>` unit gets `Op::Unkept` with cause
`kiln/written-refs-not-recorded`. Fails closed.

L1. **Which entries take part.** An entry with an `entity`, not
`DEPENDENT`, not `UNRESOLVED`, whose entity is no namespace and no
namespace alias. A dependent name is the pattern's spelling and its
specialisations' business, as an instantiation-dependent operand is
today. A namespace name decides nothing by itself: what the name after
it denotes is that name's entry. So a transform that adds or drops a
namespace qualifier (`make(0)` to `legacy::make(0)`) changes no entry
that takes part.

L2. **The unit of an entry** is the unit of the entity that
`units::enclosing_entity` gives for the entry's `enclosing` (a
`REF_GROUP` entry: for each declaration of its group). An entry held
by the translation unit belongs to `<order>`. *(Fix round 3, commit 4,
accepted by the coordinator:)* so does an entry held by a parameter of a
function type, which no unit holds (`using FT = void (int a)
noexcept(noexcept(f(a)))`, a function pointer's parameter); the
holder's own stream walks the same name, so `<order>`'s site-9 entry is
a duplicate, not a second meaning (pinned by
`differ/_/operands-function-type-parameter-order` and
`differ/_/operands-scan-arms`). An index
`(unit entity, entry id)`, sorted, is built once per translation unit
(8 bytes an entry); so is `(name_lo, entry id)` for the join.

L3. **Met, deferred, unmet** (the rule that needs no list of holders).
While a unit's kept stream is written (its own stream and its operand
entries; `UnitState`, so a dropped or numbering walk leaves nothing),
`expr::write_node` records `loc()` and the declaration of each
`DeclRefExpr` and `MemberExpr` it writes, of the callee of an operator
call and of a literal operator's callee (Kiln §18.11.1 and §18.13.7:
the join rules). Marks made while an operand entry is walked are kept
only if the entry is written (S5). At `operands::finish`, after the
groups, for each entry of the unit with role `Expr`, `Member`,
`Operator` or `UdSuffix`:
- **met**: a recorded node has `loc == name_lo(id)` and the entry's
  entity. Nothing is written.
- **deferred**: its `name_lo` is that of a name expression under a
  root that a part of this unit walks (a parameter's default argument
  that is a `default_argument` unit; the `noexcept` operand of a
  function whose specification is `deferrable`), found with
  `ExprArena::children` from the root. The part checks it at its own
  `finish` (met by the part's stream, else written in the part's
  operand unit).
- **unmet**: an entry of site 9 is written (L5).

A name is unmet when no stream of its unit walked its expression:
that is exactly "a name inside an expression that only a type or a
value holds, or that nothing holds". Where the holder is known and
read (a `decltype` in a declaration's type), the operand entry walks
the expression, the name is met, and the streams of today do not
change. Where it is not (a directive's `noexcept`, a `_BitInt` width
in a macro, `vector_size(e)`, a friend's declarator, a qualifier's
argument, a constraint's argument, a destructor's template-id, and
whatever the next review would have found), the name is written. A
missing holder is now a duplicate-free extra entry, not a wrong
answer.

L4. **Names that join no expression** (a type name, a template name,
a concept name) cannot be met one by one: types are interned and have
no location. They are written, with every other entry of the range,
where the unit has one of these **triggers**. Each replaces a refusal
of rounds 1 and 2, and none is narrowed by a location or a type join:

| | Trigger (from the AST, no location) | Range of entries written |
|---|---|---|
| T1 | the unit is a namespace's or `<order>` | every entry of the unit that is not met. What a namespace or the translation unit holds directly is what declares nothing: an explicit instantiation of a function or variable (Kiln §18.3 "Not holders") |
| T1b | a class one of whose members is `own_explicit_instantiation` | every entry the class itself holds |
| T2 | a declaration written outside its class whose `Redecl` entry has a qualifier chain with a component that is not a namespace, a class that is no specialisation, or an enumeration, named directly (so: a template-id, an alias, a typedef, `SPECIFIER`) | from the declaration's first entry through the last entry of its qualifier chain (its decl-specifiers and qualifier) |
| T3 | `State::folded`: the unit read a `Folded` slot | every entry of the unit |
| T4 | a declaration whose type a placeholder deduced (`VarPlaceholder` not `None`, `return_deduced`), or a unit with a `CXXNewExpr`, that holds a `Concept` entry | the declaration's entries up to its last `Concept` entry (for `new`: every entry of the unit). **Until the pin move** to Kiln WP-3640, after which the constraint is read from `written_decl_type` and T4 goes |
| T5 | a friend whose form is `Specialization` | every entry of the friend's holder |

*Amendment (coordinator, 2026-11-28, on fix round 3's fact (d)):* T2's
range ends at the last entry of the `Redecl` entry's qualifier chain,
since Kiln records a function definition's `Redecl` entry after its
parameters' and body's entries; parameter types, a trailing return
type and the body are read by Layer S and L3, as for any declaration.

L5. **A site-9 entry**: `uv 9`, then `Walk::write_ref` of the entry's
entity, in the unit's state (a parameter or local has the unit's
number). An entity `write_ref` cannot write makes the entry
indeterminate. The entries of a unit are written after its groups, in
table order, as one more group (`count`, entries); the own-spelling
list stays last. A site-9 entry is always "written" in the sense of
S5. No role, no spelling and no location is written.

L6. **Conservation, checked.** Every entry that takes part is
*claimed* when the `finish` of its unit (or of the part it was
deferred to) has decided it. After the queue is drained, an entry
that is not claimed (its unit was never written) is counted,
`digest.operands.names.unclaimed`, and makes `<order>`'s operand unit
indeterminate, cause `operands/unclaimed-name`. An entry deferred to a
part that was never demanded is counted apart
(`digest.operands.names.undemanded`) and is no cause: its expression
is in no unit by §2.2's own rule. `unclaimed` is 0 on both sides of
every fixture of the digest's tests, asserted in `tests/common` beside
`digest.instantiated.unheld` (`spec/digest.md` §13 item 7's pattern).

**Why a name's entity is enough for the backstop.** A site-9 entry
does not walk the expression, so a selection with no token in it (an
implicit conversion, a constructor chosen) is not written. Such a
selection is found by member lookup in classes whose units are
compared, never by namespace lookup: ordinary and argument-dependent
lookup start from a name or an operator token, and both are entries
(Kiln §18.13). So if every written name has the same entity under the
map and every unit is equal, the selection is the same.

### The STOP: T2's range on a function definition

The design gives T2's range as "the declaration's entries recorded
before its `Redecl` entry (its decl-specifiers and qualifier)". By
fact (d), for a function definition the entries recorded before
`Redecl` are the whole definition: decl-specifiers, qualifier,
parameters and body. T2 fires on a qualifier with a template-id, and
the probe `template <class T> void QP<T>::f(X1 a) { make(x); }` shows
that the qualifier's `Nns` entry of a class template's out-of-line
member is not dependent. So T2, built as written, writes every
non-dependent name of every out-of-line member definition of a class
template (libc++'s `vector<_Tp, _Alloc>::__append`, LLVM's
`SmallVectorTemplateBase<T, true>::grow`) as site 9, and the design's
own control for mutation 8 (a body that spells a typedef otherwise
stays `equal`) would turn `differ`. That is no wrong `verified`, but a
false `differ` on common real code, and mutation 8's "T2 with the whole
unit as the range" would be equivalent for a function subject.

What the coordinator may choose (the implementer did not):
1. a range that needs no location: the entries recorded up to and
   including the last entry of the `Redecl` entry's qualifier chain
   (its link, `RefQualifier`): in every probe (w7, w7f, w7r, w7p,
   t2, q3) exactly the qualifier's entries and what precedes them (no
   probe has a decl-specifier naming a type before such a qualifier);
2. ask Kiln to record `Redecl` once the declarator is parsed (KT1 2.9
   promise 5 as a correction), T2 unchanged;
3. accept the wider range for function definitions.

### The STOP of commit 4: a local class declared in an unwalked bound

*Ruled (coordinator, 2026-11-28): option 1.* The pair expects
`indeterminate f()::<operands>`; the shape is the named over-refusal
**`operands/unwalked-local`** (`Cause::Unsupported`, written by L5 when
`write_ref` of a site-9 entry's local finds it in no numbering of the
unit; no second write path), counted by the corpus run under that
cause, and a note in KT1 2.9. The new/delete join and the
function-type parameter duplicate (L2's sentence) are accepted.

`differ/_/rev112b-b04-local-class-array-bound`:
`void f() { int a[([] { struct L { static constexpr unsigned m() { ... } }; return L::m(); }())]; ... }`.
The bound is a value only, so no stream walks it; `L::m`'s entry is
`f`'s and unmet, and L5 writes it at site 9. `L` is declared inside the
unwalked lambda, so `f`'s numbering never met it and `write_ref` fails
(`undeclared_local`): by L5 the entry is indeterminate, and the pair
turns `differ` to `indeterminate` on both sides. That is a change of
verdict item 3 does not cover (it is an array bound, but it goes to
`indeterminate`, not `differ`), so the pair is unchanged and fails.
Probes (untracked) show the common shapes stay determinate: a body's
local in a bound (`char b[sizeof(x) / sizeof(x[0])]`), a body's local
class's enumerator or static member function in a bound, a local of a
function template's body, a local lambda called in a bound. What the
coordinator may choose:
1. accept it: a local class (or other local entity) declared inside
   an expression no stream walks fails closed, as L5 says; the pair's
   expectation adds `indeterminate f()::<operands>`;
2. have L5 write such a local by something other than its number
   (its holder's entry and kind), which the design does not give.
