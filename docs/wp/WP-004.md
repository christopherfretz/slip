## Scope

`crates/slip_exec/src/jobserver.rs`, `process.rs`, `signals.rs`,
implementing `spec/exec.md` §3, §4 and the parts of §7 that concern children
and tokens (kill the groups, wait, return the tokens, always exit; the store
lock and the run record are the caller's and reach you as a callback). The
module files exist as stubs; `lib.rs` already declares them.

This is a port. Kiln solved exactly this in safe Rust, including the hard
cases (signal cleanup that always exits, tokens returned exactly once, a
dead stderr pipe): read `kiln/spec/harness.md` sections "Jobserver" and the
memory-cap/timeout mechanism, then `kiln/xtask/src/jobs.rs` and
`kiln/xtask/src/util/process.rs`, and carry the design and the tests over.
Both projects are MIT OR Apache-2.0 with the same owner; say in each file's
header which Kiln file it derives from. Leave out what is specific to Kiln's
test runner (GNU `time`, stack-reservation helpers, compiler probes).
Environment variable names use the `SLIP_` prefix.

## Interface

```rust
// jobserver.rs
pub struct Pool;         // from_env() -> Pool (fallback when there is no fifo), from_fifo(path), jobs limit
pub struct Token;        // released on Drop
//   Pool::acquire(&self) -> Token                      blocking
//   Pool::try_acquire / a channel-based request the scheduler can abandon   (§3, last paragraph)
pub fn status(fifo: &Path) -> io::Result<usize>;
pub fn refill(fifo: &Path, jobs: usize) -> io::Result<RefillReport>;

// process.rs
pub struct Limits { pub address_space: Option<u64>, pub timeout: Option<Duration>, pub rss_cap: Option<u64> }
pub enum Killed { Memory, Time, Signal }                  // why the supervisor killed it, if it did
pub struct Sample { pub rss: u64, pub hwm: u64 }
pub trait Sampler { fn sample(&self, pid: u32) -> Sample; }          // real: /proc; tests: fake
pub struct Child;        // spawn(Command, &Limits) in its own process group and in the table;
                         // pid, kill(Killed), try_wait, wait, sample
// signals.rs
pub fn install(on_cleanup: Box<dyn FnOnce() + Send>);     // §7; idempotent
```

Adjust shapes where Kiln's code shows a better one, and record the final
interface in `spec/landed/exec/WP-004.md`.

**Dependency approved for this WP:** `signal-hook = { version = "0.3",
default-features = false, features = ["iterator"] }`, as in Kiln, added to
`[workspace.dependencies]` and to `slip_exec`.

## Tests

`crates/slip_exec/tests/jobserver.rs` and `tests/process.rs` as listed in
`spec/exec.md` "Tests", using fifos and child programs the tests create
(`sh`, `sleep`, a small helper binary of this crate if needed). Signal
behaviour is tested by starting a helper process that holds tokens and
children, signalling it, and checking the fifo is whole again and the
children are gone. Port Kiln's tests for the same behaviour.
