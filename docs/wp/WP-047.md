# WP-047 — slip_digest's pair runners: derived units named exactly, and the suite back under its time

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-024, WP-038
- Size: M
- Parallel with: WP-034..040, WP-044, WP-045, WP-046, WP-048

**Can start now.** Test support only: nothing under
`crates/slip_digest/src/` changes, and no digest changes.

## Scope

Two things the reviews of the digest's area packages asked of the pair
runners (`crates/slip_digest/tests/common/mod.rs`, `differ.rs`,
`equal.rs`, `demand.rs`, `indeterminate.rs`), and their description in
`spec/digest.md` §14 and `spec/digest-kinds.md` §1.5.

1. **A derived unit that appears, disappears or changes can be named,
   and a test can ask that nothing else derived moves.** Today a
   `differ` test leaves derived units free unless a `derived-changed`
   line names one, and that line is satisfied by any difference,
   presence included (`differ.rs`). A wrong edit that changes an
   instantiation nobody named passes, and a test cannot say "this
   instantiation appears and that one is untouched".
2. **The suite's time.** The pair tests take about 70 s of the gate
   against the 60 s the framework package set
   (`docs/wp/WP-024.md`, `docs/wp/WP-038.md` Handback); every area
   package adds directories (about 1,400 now), four runners and the
   determinism and tables tests each parse all of them, one directory
   after another.

Files you own: `crates/slip_digest/tests/common/mod.rs` (the parts named
below), `differ.rs`, `equal.rs`, `demand.rs`, `indeterminate.rs`,
`crates/slip_digest/tests/runner.rs` (new: the runner's own tests),
`crates/slip_digest/tests/runner/` (its fixture directories),
`spec/landed/harness/WP-047.md`. `tests/determinism.rs`, `tables.rs`,
`expr_chains.rs` only where they call something whose signature you
change. Open packages add directories under `tests/differ/` and the
others, and `docs/wp/WP-045.md` adds `tests/resolved.rs` on top of
`common`; `docs/wp/WP-055.md` adds `tests/records.rs`. **Keep every
public function of `common` callable as it is** (a new parameter is a
new function beside the old one), so that their branches merge without
an edit.

## What is decided

### Lines of `expect.txt`

| Line | Holds when |
|---|---|
| `changed`, `added`, `removed` `<name>` | as now: over declared and `tu` units |
| `derived-added <name>` | side B has a derived unit under the key and side A has none |
| `derived-removed <name>` | side A has one and side B has none |
| `derived-changed <name>` | as now: the derived units under the key differ in any way, presence included. **Unchanged in this package**, so that no open branch's test changes meaning; the closing package of the digest narrows it to "both have it and it differs" and rewrites the lines that mean an appearance |
| `exact derived` | a directive, at most once: the derived keys that differ between the sides are exactly the keys the `derived-*` lines name, each in the way its line says (`derived-changed` here means both sides have it and it differs). Without the directive derived units are free unless named, as now |

- A `derived-added` or `derived-removed` line that does not hold fails
  the test whether or not `exact derived` is written.
- `demand` tests accept `derived-added` lines (the instantiation a use
  forces) and, with `exact derived`, fail on a derived unit only B has
  that no line names. `equal` and `indeterminate` tests accept neither
  (every unit both sides have is equal already; say in `spec/digest.md`
  §14 what `equal` does about a derived unit only one side has: read
  `equal.rs`, and if it is free today, make it an error unless the
  directory has an `expect.txt` naming it, and list the directories
  that needed one).
- A name is what it is in the other lines (`common::Digested::name`);
  two derived units of one name under different keys are told apart as
  the existing lines tell declared ones apart (read how `expect`
  resolves names to keys today; if it compares names only, keep that
  and record the limit).
- **A report, not a gate, of what is unnamed.** With
  `SLIP_DIGEST_DERIVED=report` in the environment the `differ` runner
  prints, per directory, the derived units that differ and no line
  names, as the lines that would name them, and still passes. The
  handback has the count by kind over the suite at your base. The
  closing package decides from that list whether `exact derived`
  becomes the default; this package does not rewrite other packages'
  `expect.txt` files.

### The runner in parallel

- `common::run_all` runs its directories on a bounded pool of threads
  and reports exactly what it reports now, in directory order (the
  `skipped (pending)` lines, the count line, the failures joined in
  order). Each directory's work is what it is now; nothing is shared
  between directories but the support files, which are read once.
- The pool's size: `SLIP_TEST_THREADS` if set (a positive number, else
  an error naming it), otherwise the smaller of 4 and
  `std::thread::available_parallelism()`. The host is shared and a
  `cargo test` holds one jobserver token whatever its threads do: do
  not take tokens from the jobserver in a test (a test that dies
  holding one starves every build on the host), and do not raise the
  default past 4 without the supervisor.
- `run_all`'s closure must then be callable from several threads. If
  adding `Sync` to its bound breaks a caller on main, fix the caller;
  callers on open branches (`tests/resolved.rs`, `tests/records.rs`)
  pass plain functions and closures over nothing, which stay valid.
- A panic in one directory's work is that directory's failure, with the
  panic's text, and the others still run.
- `determinism.rs` and `tables.rs` walk every directory too: give them
  the same pool where their loop is over directories and its order does
  not matter to what they assert; where it matters, leave the loop
  alone and say so.
- `SLIP_DIGEST_TIMES=1` prints the twenty slowest directories of a
  runner with their milliseconds. Use it to find anything pathological
  (a directory that takes seconds is a finding about the walk or about
  Kiln: list it; do not fix the walk here).
- The target: the tests of `slip_digest` (`cargo test -p slip_digest`,
  built, on this host with the default pool) under 40 s. If the pool
  alone does not get there, say where the time goes; a cache of parses
  between runners is out of scope.

## Interface

`common` gains (names are yours to adjust, the shape is not):

```rust
pub enum Expect { /* … */ DerivedAdded(String), DerivedRemoved(String) }
/// Whether `expect.txt` has the directive `exact derived`.
pub fn exact_derived(dir: &Path) -> Result<bool, String>;
/// The derived keys that differ between the sides, each as the line
/// that names it under `exact derived`.
pub fn derived_differences(a: &Digested, b: &Digested) -> BTreeSet<Expect>;
```

`expect` returns the new lines; `exact derived` is not one of them.
`docs/wp/WP-045.md`'s `resolved` runner asserts appearance its own way;
when both are on main the closing package makes it call
`derived_differences`.

## Tests

`tests/runner.rs`, over small fixture directories under
`tests/runner/` that the four runners do not walk:

- each new line holding and not holding (an instantiation that appears;
  one that disappears; one both sides have that changes; one both have
  that is equal), with and without `exact derived`, for `differ` and
  `demand`;
- `exact derived` with one unnamed derived difference fails and names
  it;
- `derived-changed` behaves as before with no directive (a fixture for
  presence and one for content);
- the pool: the report of a run over a fixed set of directories, some
  failing, some pending, one panicking, is byte for byte the same with
  1, 2 and 8 threads; `SLIP_TEST_THREADS=0` and `=x` are errors;
- the report mode prints the lines and passes.

The existing suites pass unchanged, and `tests/tables/untested.txt` does
not move.

## Done when

time of `cargo test -p slip_digest` before and after (three runs each,
built, with what else the host was doing), the pool size used; the
twenty slowest directories; the report's counts of unnamed derived
differences by kind and the directories with the most; what `equal`
did about one-sided derived units and what it does now; every caller
changed.

## Out of scope

Anything under `crates/slip_digest/src/`; other packages' `expect.txt`
files, except a directory this package's stricter `equal` rule makes
fail; module sources (`docs/wp/WP-048.md`); the `resolved` runner
(`docs/wp/WP-045.md`); making `exact derived` the default.

Not trusted base by its code, but every digest test stands on it:
second review, asking whether any test that failed before can pass now
(a failure lost by the pool, a line that holds vacuously) and whether
the report can differ between runs.
