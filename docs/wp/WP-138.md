# WP-138 — a fold's operator: what the definition context found, read in place of the indeterminate

- Status: review
- Milestone: M1
- Track: C
- Needs: WP-066
- Size: S
- Parallel with: the digest's area packages (one digest branch merges at a time)

## Scope

`crates/slip_digest/src/expr_dep.rs` `cxx_fold_expr` marks a unit
indeterminate (`spelling/fold-operator`) when a fold's operator is
overloadable and some non-member declaration in the translation unit
is named for it (`expr_profile.rs` `fold_left_out`): the old pin
recorded nothing of what unqualified lookup found for the operator at
the fold's definition. That is 163 indeterminate units of Demo 1, one
of them (`__gnu_cxx::__promoted_t`) in 132 of 151 observers.

Kiln WP-2625 (in the pin since `docs/wp/WP-066.md`) records the fold's
definition-context operator set in `templates.oper_lookups`, as it
does for a dependent binary operator. WP-066 left the walk as it was
("fail closed until WP-138").

1. **Read the set.** A fold's operator is written as a dependent
   binary operator's is (`templ.rs` near 482: the candidates of
   `oper_lookups.of(e)`, by entity, in the set's order rule), and the
   indeterminate goes. Say what Kiln records for each form (unary left
   and right, binary, an operator with no candidate in the definition
   context, `,` `&&` `||` whose built-in forms have their own
   evaluation rules, a comparison, which C++20 rewrites: is the set the
   rewritten candidates' too, as for the binary operator?), read from
   Kiln's `spec/ast.md` §8.5 and its tests, and what the digest writes
   for each. Where Kiln's record falls short of the binary operator's,
   that form stays indeterminate with its own cause and goes into "For
   Kiln" with a source.
2. **What an instantiation of the fold is**: the instantiated
   expression (nested binary operators, each resolved) is walked by
   the rows that exist. Confirm with a pair that a change of what an
   instantiation's operator resolves to (an overload added that ADL
   finds for one argument type) moves the instantiation's unit and not
   the pattern's, and that a change of the definition-context set (an
   operator declared before the template) moves the pattern's.
3. **`fold_left_out` goes** with its cache (`Walk::declared_operators`)
   unless something else reads it; `own_spelling.rs` near 1064 (the
   operator's candidates left out of every profile, digest-kinds §9.5)
   is looked at for the fold: say whether a fold's candidates need the
   same treatment.
4. **`spec/digest-kinds.md`** §4.4 "Spellings" rule 9 and the row of
   `CXXFoldExpr`; `scheme` moves only if a unit that was determinate
   changes its digest: say whether it does (a fold with no non-member
   operator declared in the unit was determinate and wrote nothing for
   the set: if it now writes an empty set, every such unit's digest
   moves; choose the encoding that moves none, or move `scheme` and
   say so before building).

### Item 2 — Instantiated folds

Confirmed with `exact derived` pair tests:
- `differ/_/fold-operator-before-template-instantiated`: an overload
  declared before the fold template moves both the pattern
  (`template <class...> auto f(...)`) and the affected instantiation's
  resolved unit (`f<A::X, A::X>(A::X, A::X)::<definition>`), while an
  unrelated instantiation (`f<int, int>`) stays equal.
- `differ/_/fold-operator-adl-instantiation`: an overload declared after
  the fold template in an operand's namespace moves only that
  instantiation (`f<A::X, A::X>(A::X, A::X)::<definition>`) and neither
  the pattern nor `f<C::Y, C::Y>`.

### Item 3 — `fold_left_out`, `Walk::declared_operators`, and `own_spelling.rs`

- Removed `expr_profile::fold_left_out` and `Walk::declared_operators`
  (no other readers in the workspace).
- `own_spelling::node` (`crates/slip_digest/src/own_spelling.rs:1321-1325`)
  already inspects `ast.templates.oper_lookups.of(e)` before dispatching
  on `ExprKind`, so folds already receive the same `Fact::Oper`
  treatment as dependent binary operators. Folds need this treatment
  because Kiln's profiler (`kiln_ast/src/types/profile_expr.rs:581-584`)
  excludes `oper_lookups` from `CXXFoldExpr`'s profile (verified by
  Mutation 4: skipping `CXXFoldExpr` there fails all 9 trailing-return-type
  fold `differ` pairs).

### Item 4 — `scheme` analysis

**`scheme` does NOT move (stays `3`).**
- Full walk: `templ::expr_maps` has run at the end of every `CXXFoldExpr`
  since WP-066 (when Kiln WP-2625 entered the pin) and already wrote
  `oper_lookups.of(e)` (`opt(true)` + count `0` for empty sets,
  `opt(false)` for `.*`/`=`). Removing `fold_left_out` in
  `expr_dep::cxx_fold_expr` changes zero bytes of any previously-determinate
  unit; only previously-indeterminate `spelling/fold-operator` units change
  (from indeterminate to determinate).
- Profile mode and `own_spelling`: `expr_profile::node` already called
  `oper_left_out(w, e)` for `K::CXXFoldExpr` and `own_spelling::node`
  already read `oper_lookups.of(e)` (`Fact::Oper([])` has `due == false`,
  writing nothing when no other fact is due). Removing `fold_left_out` in
  `expr_profile::node` changes zero bytes, marks, or lists of any
  previously-determinate unit.

### For Kiln

None. Kiln WP-2625 covers every fold form identically to dependent binary
operators.

### Choices

1. Keep the existing `templ::expr_maps` (`opt` + `write_refs_sorted`) and
   `own_spelling` (`Fact::Oper`) encoding without special-casing
   `CXXFoldExpr`: zero previously-determinate units move (`scheme` stays
   `3`) and `CXXFoldExpr` stays uniform with dependent `UnaryOperator`,
   `BinaryOperator`, and `CompoundAssignOperator`.
2. Turn all four `indeterminate/_/spelling-fold-operator-*` directories
   into `differ/_/` pairs (adding a global `#ifdef B` `operator==` to
   `spelling-fold-operator-comparison` so it tests C++20 `!=` → `==`
   rewriting) and remove `spelling/fold-operator` from
   `expr_profile_tests::PAIR_CEILINGS` and `own_spelling_tests::REACHED`.
3. Update `own_spelling_tests::an_alias_whose_spelling_is_indeterminate_is_listed`
   to use a dependent `_BitInt` (`spelling/bit-int`) to keep testing Rule 4
   with a cause inside rule 7's profile, and add
   `a_fold_in_an_alias_holds_its_oper_set_and_is_determinate` for the
   original fold-in-alias source.
