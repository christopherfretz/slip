## Scope

The four containers a transform's run publishes:

- `spec/edits.md` §6 and §6.1 (`EDTS`), §7.1 (`OVLY`, with its spelling
  obligations), §8.4 (`Residue`), §8.5 (`RSLT`), §10.6 (`RUNT`);
- `spec/model.md` §3 (the tag `slip.basis.v1`) and §5.1 (the four kinds).

Files. New: `crates/slip_model/src/{editset.rs, overlay.rs, result.rs,
transform_run.rs}`, the same four names under `src/formats/`,
`crates/slip_model/tests/editset.rs`. Changed: `src/lib.rs`,
`src/formats/mod.rs`, `src/hash.rs` (the tag).

Starts when WP-060's types are on `main`. Needs nothing of M1 or Kiln.

## Interface

As WP-060: a production is a Rust type of the same name, field for field
(`macro` is `macro_site`; `Result` is `TransformResult`, the name being
taken in Rust). `Piece`, `Place`, `Subject`, `MacroSite`, `Reason`,
`Report`, `Failure` and `KeyId` are `slip_model::edits`'.

```rust
// slip_model::editset                                          spec/edits.md §6
pub struct Basis { pub observer: Digest, pub shard: Option<Digest> }
/// H("slip.basis.v1", list<Basis>).
pub fn basis_id(basis: &[Basis]) -> Digest;
pub enum SetState { Accepted = 0, Refused = 1 }
pub struct Edit { pub file: u64, pub lo: u64, pub hi: u64, pub pieces: Vec<Piece>, pub subjects: Vec<KeyId>,
                  pub tiers: u64, pub macro_site: Option<MacroSite>, pub notes: Vec<Vec<u8>>,
                  pub observers: u64, pub votes: u64, pub first: Vec<Digest> }

                    pub observers: u64, pub first: Vec<Digest> }

                 SubjectUnreachable = 4, NameTaken = 5, MixedFollower = 6, MixedSet = 7, SiteRefused = 8,
                 Contested = 9, Divergent = 10, Overlap = 11, FileDiffers = 12, Cyclic = 13, Buried = 14,
                 RuleConflict = 15, NoEdit = 16 }

                     pub changed: Vec<Exempt>, pub kept: Vec<Place>, pub unresolved: Vec<Place>,
                     pub refusals: Vec<Refusal>, pub reports: Vec<Reported>, pub failures: Vec<Failed>,
                     pub unparsed: Vec<Digest>, pub counters: Vec<Counter> }

/// The geometry of spec/edits.md §5.4 for two ranges `(lo, hi)` of one
/// file. Used by `validate` here, by reduce and by apply: one definition.

```

`slip_model::result::Spellings` (of a result) and
`slip_model::spellings::Spellings` (of a shard, WP-060) are two records;
neither is re-exported at the crate root from this package.
`slip_model::result::RunVerdict` is the type `slip_verify` uses if M1's
`slip_verify::run` has one of the same three values by then
(`docs/wp/WP-055.md`): keep one, in the crate the other can depend on,
and say which in the handback.

Kinds `EDTS`, `OVLY`, `RSLT`, `RUNT`, version 1, through `format_impl!`.
`RUNT` is the one that is not deterministic; it is marked as the run
record is (`formats/run.rs`).

Validation: §6.1's table in its order (the `basis` row is not checked by
the format; nor is that copies are well-founded and every edit
effective, which apply checks); the overlay's invariants of §7.1; for
`RSLT`, the invariants §8.5 lists and nothing more. Which state a result
has is the trusted base's to decide (`docs/wp/WP-070.md`), not the
format's.

## Tests

`crates/slip_model/tests/editset.rs`: binary and JSON round trips of the
four kinds, each with every record at least once; every invariant broken
alone, with offset and path; the four geometry functions over: disjoint,
touching at one end, equal, nested at the start, at the end and strictly
inside, crossing; an edit set whose edits are nested (valid), cross
(invalid), cross a copied range (invalid); `basis_id` changes with the
order, with an absent shard and with a shard's id; `Overlay::find` and
`obligations_of` (a file with none, the first and the last file); an
overlay file with `post` equal to `pre` is valid.
