# WP-169 — `corpus rename` passes a run whose observers did not parse

- Status: review
- Milestone: M1
- Track: H
- Needs: none
- Size: S
- Parallel with: every package that does not edit `xtask/src/corpus/` (after WP-166: both touch `xtask/src/corpus/rename.rs`; take `main` with WP-166 merged before the PR, or say which lines collide)

## Scope

Demo 2's run 3b (`.build/demo2/run3b.log` on the supervisor's side,
2026-11-25) ended `corpus rename: ok` with `map: selected 4061, ok 619,
not ok 3442`: 3,441 observers failed with `cannot enter <build>/lib/…: No
such file or directory`, because the corpus copy lacked the build
directories the database's entries `cd` into (the supervisor's copy
script; fixed). `corpus rename` passes `--allow-unparsed` (the two units
of `spec/harness.md` §8.7 are `diagnosed`), so nothing failed. A run that
parsed 15% of the corpus is not a run of the corpus; the harness must say
so.

1. **Before `slip` runs** (with the tool checks of §6.5 item 4, for every
   run, not only `--build`): every database entry's `directory` exists
   and is a directory, and its `file` exists. Otherwise stop with
   status 2 (an error of the command), naming the count and the first 10
   (`corpus rename: <n> database entries cannot run: <dir>: <reason>`).
2. **A new first check, `coverage`**, before `state`: every observer of
   the plan has map outcome `ok`, except the corpus's **expected
   unparsed observers**, a list kept with the corpus's definition
   (`xtask/src/corpus/…`, wherever the corpus rows live) with an outcome
   and a one-line reason each. For `llvm` it is the two `diagnosed`
   units of §8.7 (`clang/tools/clang-fuzzer/ClangFuzzer.cpp` and
   `ClangObjectiveCFuzzer.cpp`). `ok` when the not-ok set is exactly that
   list with those outcomes; `FAIL` otherwise, with the detail
   `<k> observers not ok beyond the expected <e>` (or `expected unparsed
   observer <path> is <outcome>` when a listed one parsed or changed
   outcome), and up to 10 such observers printed with their outcome and
   their first error line. Read the outcomes from the store (the map
   phase record, or whatever record names each observer's outcome; say
   which). The order of checks becomes `coverage`, `state`,
   `determinism`, `accept`, `build`, `back`; the first failure stops them
   as today.
3. Update `spec/harness.md` §6.5 (the list of checks, "Checks", item 4's
   "before `slip` runs") and §8.7 (the expected list is the two units
   named there), and the JSON of `bench/results/` (the new check appears
   in `checks` and `measured.checks`).

## Tests

- Unit or `xtask/tests` cases on a small corpus fixture (the existing
  fixture corpora of `xtask/tests`): (a) all observers `ok` → `coverage`
  ok; (b) one observer not ok beyond the list → `FAIL`, later checks `not
  run`, exit as a failed check; (c) a listed observer that parsed →
  `FAIL`; (d) a database entry whose `directory` is missing → status 2
  before `slip` runs, no store written.
- Mutations (one at a time, report killed or survived): `coverage`
  always ok; the comparison by count instead of by set; item 1's check
  removed.

## Done when

The four cases hold; §6.5 and §8.7 say what the code does; the full
`cargo xtask ci` passes on the branch with `main` merged in (with
`clang++-19` installed).

## Out of scope

Changing `slip`'s own `--allow-unparsed` semantics or the state of a
result with unparsed observers (`spec/edits.md`). The census of WP-166.

### Store record read for `coverage`

`read_records` locates the `StepName::Map` phase `RunRecord` (`<store>/runs/<plan>/map.<round>.<started>.run`, matched by content id from `TransformRun.steps`) and stores its path on `Records::map_run`. `Rename::coverage` loads that run record, its content-id-verified `Plan`, and all map shards (`<store>/shards/<plan>/map.<round>/<observer>.shrd`) via `perf::load`, and resolves each plan observer's map outcome and first diagnostic line via `invariants::side` and `Shard::outcome.message`.

### Choices

1. **Where `expected_unparsed` lives:** Stored as an optional array key `expected_unparsed` in `bench/corpora.toml` (`<outcome>:<path>:<reason>`) parsed into `Corpus::expected_unparsed` in `xtask/src/corpus/rows.rs`. Keeping it optional preserves backward compatibility with existing fixture `corpora.toml` files across `xtask/tests/`, lets `xtask/tests/corpus_rename.rs` test custom expected lists end-to-end on the `tiny` fixture, and keeps corpus metadata together with the corpus row.

3. **Plan content-id tamper test:** `s6_5_accept_refuses_a_plan_under_another_id` now triggers `coverage` first (because `coverage` reads the plan through `perf::load`, which verifies the plan's content id); `accept`'s own content-id check remains intact.
