## Scope

[KF2](../requests/KF2-overlay-and-file-identity.md), stage 1.

**Kiln implements the overlay itself** (its WP-2390; decided by Kiln on
2026-11-22, with §3.2 and §3.4 of the request accepted as proposed; the
answers are in the request file). There is no prototype and no branch
`slip/kf2`. **Starts when Kiln's WP-2390 is on Kiln's `main`**: the
supervisor's brief names the commit.

In this package:

1. The pin moves to that commit, by the rules of `docs/wp/WP-101.md`
   (its work items 1, 3 and 4 and its decisions 2 to 4: nothing is
   turned on for an existing caller, and a digest that changed for a
   source that did not is a finding).
2. In `crates/slip_kiln/`: the parse task takes an overlay. It adds one
   field to the `ParseOptions` that `docs/wp/WP-067.md` made, which is
   why that package is in `Needs`. Read what Kiln landed (the names in
   the request are placeholders) and write the Interface below against
   it; a point of the request's §1 that Kiln's form does not give is a
   finding for the handback, with the test that shows it.

Files: the submodule `kiln`; `crates/slip_kiln/src/parse.rs`, new
`crates/slip_kiln/tests/overlay.rs`; the places that state the pin.

## Interface

```rust
// slip_kiln::ParseOptions (docs/wp/WP-067.md) gains
/// Replacement contents, by real path (spec/edits.md §7.1). The paths
/// must exist. Sorted by path, no two equal.
pub overlay: &'a [(&'a [u8], std::sync::Arc<[u8]>)],
```

`parse_observer_opts` with an empty overlay behaves as before this
package.

- The shard's `inputs` give, for an overlaid file, the size and content
  digest of the overlay's bytes (they come from `original_bytes`, Kiln
  `kiln_source/src/manager.rs:1177` at the pin, which KF2 point 3 makes
  the overlay's); for every other file, what they give today.
- An overlay path that does not exist, or two entries of one file
  identity, is an `Err` before the parse.
- The check `parse.rs` makes today that no file changed during the parse
  (`collect_inputs`) compares an overlaid file with the overlay's bytes,
  never with the disk.
- `Unit` gains `pub fn overlaid(&self, file: FileId) -> bool` (from
  `FileOrigin::Overlay`).
- Guard O2 of `spec/verify.md` §5.3 stands on the first point: a verify
  job compares the `inputs` entry of each overlay file it read with the
  overlay's `post`. A route that read the disk instead shows there as a
  digest that is not the overlay's.

## Tests

- The request's §4 is Kiln's acceptance, in Kiln; not repeated here.
- `crates/slip_kiln/tests/overlay.rs` (`spec/edits.md` "Tests"): through
  `parse_observer_opts` over a tree in a temporary directory under the
  target directory: the main file overlaid; a header overlaid and
  reached by two spellings and by a symbolic link; an overlay that adds
  an `#include` of an existing file and one that removes an include (the
  `inputs` change accordingly); `inputs` shows the post-image digest for
  the overlaid file and the disk's for the others; an empty overlay gives
  a shard byte-identical to `parse_observer`'s; the overlaid file changed
  on disk during the parse is not an error (it was not read), another
  file changed is; the two `Err` cases; an overlay together with
  `written` on (the table's ranges are offsets in the overlay's bytes).
- Reference check, in the same file: for each case, the shard equals the
  one obtained without an overlay from a copy of the tree in which the
  files were replaced, after the two roots are made the same string.
