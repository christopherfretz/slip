# WP-015 — slip_model: the digests and verdict sections

- Status: in-progress
- Milestone: M1
- Track: A
- Needs: WP-006
- Size: M

## Scope

The binary and JSON forms of two shard sections, over the plain types that
are already in `crates/slip_model/src/digests.rs` and `verdict.rs`:

- section 19 `digests` (`spec/digest.md` §11),
- section 21 `verdict` (`spec/verify.md` §6),

in `crates/slip_model/src/formats/` (new files `digests.rs`, `verdict.rs`;
`shard.rs` reads and writes them), following exactly the conventions
WP-006 landed (`spec/landed/model/WP-006.md`: order of checks, offsets,
JSON paths, unknown sections). `Shard` gains

```rust
pub digests: Option<Digests>,
pub verdict: Option<Verdict>,
```

and every construction of a `Shard` in the workspace is updated (`slip_exec`,
`slip_kiln`, `xtask` tests, …) with `None`. Ids 16, 17, 18 and 20 stay
reserved and rejected.

Not in scope: the `DECL` container of `spec/verify.md` §2 (it needs key
encodings that `spec/digest-kinds.md` will define), anything that computes
a digest or a verdict.

## Interface

No new public function beyond the two fields: `Shard::to_bytes`,
`from_bytes`, `to_json`, `from_json`, `validate`, `formats::dump` and
`undump` cover the sections. Field order in both forms is the order of the
spec's records. In JSON the members are named as the spec names the fields
(`Finding::location` is `where`), enumerations by the spec's names
(`declared`, `derived`, `tu`; `verified`, `mismatch`, `unverifiable`;
`changed`, `removed`, `added`, `indeterminate`, `derived_changed`,
`derived_indeterminate`).

Invariants (`validate`, and every reader), in this order after WP-006's:

`digests`
1. present only if the outcome's status is `ok`;
2. `scheme` is `digests::SCHEME`;
3. `groups` strictly ascending by `(class, file)`;
4. a `tu` group has an empty `file` (so there is at most one); a
   `declared` group has a non-empty `file`;
5. `count` is at least 1;
6. where `units` is present: strictly ascending (`Unit`'s order), its
   length is `count`, every `flags` is 0 or 1, and `digest` is
   `digests::group_digest(units)`;
7. `tu` is `digests::tu_digest(groups)`.

`verdict`
1. present only if the phase is `verify`, the status is `ok` and `digests`
   is present;
2. `reason`, and every `name`, `node` and `what`, is at most 4096 bytes;
3. `verified`: `total` 0, no finding, empty `reason`; `mismatch`: `total`
   at least 1, empty `reason`; `unverifiable`: non-empty `reason`, `total`
   0, no finding;
4. `findings` is no longer than `total`, at most one finding per `(kind,
   key)` among those with a key, ascending by `(kind, file, key)` with an
   absent key first;
5. a finding's `key` is absent only for `indeterminate`; `changed` and
   `derived_changed` have `key`; `removed` has no `post`; `added` has no
   `pre`;
6. `used` strictly ascending;
7. in a `Site`, `line` is 0 exactly when `column` is 0.

Record what you had to decide (offsets and JSON paths of each violation,
anything the two specs leave open) in `spec/landed/model/WP-015.md`.

## Tests

`crates/slip_model/tests/formats.rs` (or a new `tests/sections.rs` in the
same style), each test naming its section:

- round trip, binary and JSON, of shards with: digests without unit lists,
  with some, with all; each verdict kind; findings of every kind with and
  without `where`; a non-UTF-8 `file`.
- golden files under `tests/golden/` for one map shard with digests and
  one verify shard with a `mismatch` verdict (binary bytes written out by
  hand in the test as WP-006's are, and the JSON).
- every invariant above violated in turn, rejected by `from_bytes` with
  the offset and by `from_json` with the path the landed file states; a
  truncated section; leftover bytes; an unknown enumeration value.
- a shard of WP-006's golden set still reads and writes the same bytes
  (the sections are optional and absent).
- ids 16, 17, 18, 20 still `UnknownSection`.
