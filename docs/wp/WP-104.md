# WP-104 — slip_digest: values that come from names (digest §9), and qualified template arguments in a unit's name

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-039, WP-057
- Size: M
- Parallel with: WP-040, WP-041, WP-045, WP-049, WP-103, WP-105

## Scope

Two defects that the pitfall rows of WP-057 showed, both in the way of
verifying a relocated namespace on real code.

### Part 1: the type and the constant of a name-derived builtin are symbolic

`spec/digest.md` §9, as amended with this package: the value of
`__func__`, `__PRETTY_FUNCTION__` and their kin is symbolic, **and so
are the expression's own type and the constant it stands for**; whatever
consumes the value is written by value. Today:

- `__PRETTY_FUNCTION__` in `legacy::where()` has the type `const
  char[28]`, in `acme::where()` `const char[26]`, and the walk writes
  the type by value: row N18 `good` gives `changed legacy::where()`
  (`crates/slip_verify/tests/pitfalls/n18-*`,
  `spec/landed/pitfalls/WP-057.md` "What the walk gives today").
  `assert` expands to `__PRETTY_FUNCTION__`, so every function that
  asserts fails to verify under a rule that changes the length of its
  name.
- `std::source_location::current()` in a default argument: the
  immediate invocation's result (`default_immediates`) holds the
  function name's value, so N18 `good-3` differs even for a name of the
  same length, and `std::source_location::current` itself is
  indeterminate. `SourceLocValues` `location` is `symbolic` in
  `spec/digest-kinds.md` §7.3; the walk does not follow its own table.

Find every place a name-derived value reaches a stream, by reading Kiln
at the pin, not by the two reports: `PredefinedExpr` (each
`PredefinedKind`: `__func__`, `__FUNCTION__`, `__PRETTY_FUNCTION__`,
`__FUNCSIG__` and the rest; in a function, a lambda, a block-scope
initialiser, a template and its instantiations, a dependent context
where `a` is absent), `SourceLocExpr` (each `SourceLocKind`:
`__builtin_FILE`, `__builtin_FUNCTION`, `__builtin_LINE`,
`__builtin_COLUMN`, `__builtin_source_location`), the constants that
evaluation makes from them (`ConstantExpr` results, the evaluated
initialiser of a `constexpr` variable, `default_immediates`, an
instantiated default argument's unit), and the string literals that
come from `__FILE__`, `__LINE__`, `__DATE__` and their relatives (§9's
second list: are their types and constants treated as §9 now says? a
`__FILE__` of another length is `const char[M]`). The landed file has a
table: construct, Kiln `file:line` where the value is made, what the
walk wrote before, what it writes now.

What must hold, and the tests that show it (pair tests under
`tests/equal/` and `tests/differ/`, in the forms of digest §14.1; the
rows of `spec/digest-kinds.md` they belong to named in each
`expect.txt`):

1. **Equal under a rule**: a function holding each builtin, relocated
   to a namespace whose name has another length, digested under the
   rule that undoes it (`tests/common` `digest_side_with`), equals the
   original. With `assert`-like use (the value passed as `const char
   *`), with the value bound to a `const char *` variable, returned,
   passed to a function template that takes `const char *`. The same
   for a member function, a lambda, a function template's
   instantiation (the name holds the arguments), and for
   `source_location::current()` as a default argument, called from a
   relocated function.
2. **Equal when moved**: the construct on another line, in a function
   of another name with no rule, is a `symbolic` row's test (digest-kinds
   §1.5): these exist; keep them passing.
3. **Different when consumed**, each its own test, each under the same
   rule as 1: `sizeof(__func__)` as an array bound, as a template
   argument, in a `static_assert`, as the initialiser of a `constexpr`
   variable; `auto &r = __func__;` (the variable's type holds the
   bound); a function template deducing the bound (`template <unsigned
   long N> void f(const char (&)[N]); f(__func__);`: another
   specialisation is called); `decltype(__func__)` as a type; a
   `constexpr` function over the characters whose result is used as a
   constant (`__func__[0]`, a hash); `source_location::current().line()`
   as a template argument; the `function_name()` of a `constexpr
   source_location` compared in a `static_assert`. Never equal: if the
   walk cannot tell a consumer from a pass-through somewhere, that unit
   is indeterminate, with a cause of its own, and the landed file says
   where.
4. **No new wrong equal**: the symbolic type must not hide a real
   difference. `__func__` against `__PRETTY_FUNCTION__` (another
   builtin) differ; the builtin against a string literal of the same
   text differ; two functions that differ only in which of them holds
   the builtin differ.

The array type's symbolic form is yours to define (a row of
`spec/digest-kinds.md` §4.3 or a note on `PredefinedExpr`; the tables
test and `untested.txt` must stay consistent): say what is written, and
why two different programs cannot share it.

Then the three shapes of row N18 verify as the row says: run them
through `slip declare` and `slip verify` by hand, as
`spec/landed/pitfalls/WP-057.md` describes, and record the result.

### Part 2: template arguments in a unit's name are qualified

`spec/verify.md` §6.1, as amended with this package: a specialisation's
arguments are printed with every entity they name written by its
qualified name. Today `names.rs` `spec_args` prints
`legacy::store<Mine>`; two classes `Mine` of two namespaces give two
units with one name, against §6.1's "two units of one image with
different keys have different names". Fix it in `names.rs` (Kiln's
printer takes a naming policy: read `write_arg_list` and `PrintOptions`
at the pin; if the policy cannot qualify, report it for Kiln and wrap,
as `TypedNull` does). Arguments of every kind: a type, a template, a
declaration (a function, a variable, an enumerator, a member pointer),
a pack, a nested specialisation, a lambda's closure type, a local
class.

Tests: unit tests in `names.rs` for each kind of argument; a pair in
`tests/determinism/` `keys_and_names_are_unique`'s sources that has two
specialisations differing only in the namespace of an argument (it
fails today); the expectation lines that move, moved (names only; if a
verdict moves, stop and report). Row N06's line
(`legacy::store<legacy::Mine>::put(legacy::Mine &)`) then matches what
the walk prints.

## Handback

What landed is in `spec/landed/digest/WP-104.md` (the tables of Part 1,
the mutations, N18, Part 2). This handback is after the review's fix
round (`F1`..`F7`).

- **Part 1.** A `PredefinedExpr`'s type is `const char[]` only as the
  operand of an implicit array-to-pointer decay; everywhere else it is
  written by value. A symbolic value has the identity of its object: a
  `PredefinedExpr` string is its kind and the function whose name it
  holds, a source-location function name the pretty-or-plain flag and
  its context, both only where the bytes are Kiln's name of that kind
  for that entity (else the bytes); a file name is its bytes; an
  `__impl` object is its function and an ordinal; the offset is by
  value. Keys, types, `static_assert` conditions and a `ConstantExpr`
  with no stored value are written by value (`Walk::by_value`); a
  block-scope variable's value is written in the function's mode, and
  by value where a use is read by value.
- **F2.** Pretty-string content beyond entity names (alias, elaborated
  keyword, qualifier as written, template parameter names) is left out
  of the unit digest where the string is passed on, by §9; six pairs
  pending with `# needs: WP-112` for the names digest. No known wrong
  equal is claimed, and WP-041 is no longer cited for it.
- **Tests.** Differ: the five md-pick pairs, a default-argument chooser,
  the swapped `__func__` pair, the by-value local pointer in a
  `static_assert`, the source-location name and role choosers, a moved
  `std::source_location` template argument (keys by value). Equal: the swapped `__func__` pair under a swapping
  rule, the two block-scope pass-through values, the reviewer's F7
  source. Pending: the lambda test (WP-040), the implicit `g<long>` half
  (demand).
- **Indeterminate:** nothing new.
- **Mutations:** 26 after the fix round: 22 killed; 6 survive, each with its reason in the landed file (M1d, M2a equivalent; M2h, M3g, M3h, M3l no reachable case).
- **N18:** the three shapes equal under `relocate legacy => :: acme`, in
  process (no `slip declare`/`verify` on this branch).
- **Part 2:** Kiln's `write_arg_list_scoped` with a `TypeNames` wrapper
  that writes every entity in an argument as the walk names it (inline
  namespaces, unnamed classes and enums by key); no expectation line
  moved, no verdict moved.
- **For the next batch to Kiln** (observations, no defect): a literal
