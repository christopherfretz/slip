# WP-153 — the digest: what a name bound in a substitution whose expression is not kept

- Status: done
- Milestone: M1
- Track: C
- Needs: WP-139
- Size: L
- Parallel with: stage 0 with everything; the build with no other digest branch (one digest branch merges at a time)

## Scope

`docs/wp/WP-139.md` found it (`spec/landed/edits/WP-139.md`, finding 3)
and the supervisor ruled it a limit of the digest, not of the rename:

```cpp
struct Base { static int s(); };
namespace n { struct S : Base { static int s(); }; }
template <class T, int = sizeof(T::s())> int call() { return 0; }
int u() { return call<n::S>(); }
```

Rename `n::S::s`. `T::s` at `call<n::S>` now finds `Base::s`. Every
digest is equal: the default argument's value is in the
specialisation's key, and the substituted expression is nowhere.

The class: **a substitution whose expression is not kept is seen by its
outcome** (the argument's value or type, the alias's type, whether a
constraint is satisfied, which partial specialisation or candidate was
chosen), **never by what its names bound**. The shapes:

| Shape | Outcome that is compared today |
|---|---|
| a default template argument at a use that takes it | the argument, in the specialisation's key |
| an alias template's pattern at `A<X>` | the type the alias names |
| a requires-clause, a type-constraint or a concept-id at a satisfaction check | the stored result; the candidate chosen |
| a partial specialisation matched (`void_t<decltype(swap(…))>`) | the pattern the specialisation was made from |
| a signature substituted during deduction (`-> decltype(T::s())`, a parameter type) | the specialisation's type |
| a `noexcept` or `explicit` operand substituted at instantiation | the stored value |

No evaluated call changes while the outcome is equal. What is not
proven is the statement Slip makes, "every name resolves as it did":
in a namespace migration, the argument-dependent lookup inside a
trait can find another `swap` and the trait still say yes.

Kiln's answer (2026-11-24, to be copied into the request file): its
per-specialisation table (`WrittenRefs::specs()`) has rows for some of
these shapes, keyed by a declaration that does not name the
substitution (an alias template's rows do not say which `A<X>`; a
satisfaction's not which arguments), none for a function template's
default template argument (Kiln WP-3520), for a partial
specialisation's matching, or for an unqualified call in a function
template's own requires-clause. It proposes a substitution key
(`SubstKey { kind, outcome, template, canonical interned args, extra }`,
an `inst` field per row) and measures the cost as small (on
`<bits/stdc++.h>`: 17,933 rows today, 10.6 MB; about 5k to 18k rows
more). Slip has told it: successes only, the order of need
(partial-specialisation match, satisfaction, default template
argument, alias, the out-of-line `noexcept` operand), and four
properties (one row set per distinct key whether computed or answered
from a cache and whatever the order of instantiation; every dependent
entry of the pattern has a row under the key; keys enumerable and
named by template and canonical arguments; a key's rows independent of
which other keys exist).

### Stage 0: design (a design agent; no code)

1. **The request to Kiln**, `docs/requests/KR9-substitution-bindings.md`:
   what the table must hold per shape, in the terms of Kiln's sketch;
   the properties above made exact (what "the same row set" means for a
   substitution memoised by Kiln: the atomic-constraint cache, the
   alias and default-argument caches; nested substitutions each under
   their own key); which entries need the found set and `adl` and which
   the entity; what a row says for an entry that stays dependent; what
   is NOT asked (failed substitutions: say why a failure needs no row,
   and find the case, if there is one, where a name bound, the
   substitution failed later, and the binding still reached the
   program). Read Kiln's `spec/ast.md` §18.9 and its substituter
   (`kiln/` is read-only) so that the request is about what exists.
2. **Where the digest writes it.** Decide and justify, against
   `spec/digest.md` §3 to §8 and `spec/verify.md` §2 to §4:
   - the unit: a derived unit per substitution key, or a part of an
     existing unit (the specialisation's `resolved` unit for a default
     argument and a deduced signature; the using unit for an alias
     template-id, which has no declaration of its own); what its key is
     when the substitution has no declaration (an alias template-id, a
     satisfaction with its arguments) and how that key is mapped by a
     namespace rule (`spec/verify.md` §2) and exempted or mapped by a
     rename's declared changes;
   - how a row names its entry without a position (the digest is
     position-free): by the entry's ordinal in the pattern's stream, by
     its profile, or otherwise; what happens when a transform edits the
     pattern (the ordinals of the pre- and post-image must still join);
   - what is written for an entity (a `Ref`, as §6), for a found set
     (the set's order rule, as `oper_lookups`), for argument-dependent
     lookup;
   - which unit differs, and what the report says, for the example
     above; for a trait whose `swap` moved; for an alias template whose
     argument's member moved;
   - inertness: under the empty rules table and with no such
     substitution, no existing digest moves; say whether `scheme` moves
     (it does if a unit that exists today gains bytes) and choose the
     form that moves none, or state the move;
   - cost: units and bytes per observer on the figures Kiln measured,
     and what the supervisor should measure on `llvm` `lib/Support`.
3. **Until Kiln's rows exist**: the limit as a paragraph of
   `spec/digest.md` (the section that lists what is not digested) and of
   `spec/digest-kinds.md` "Hazards accepted for now", in the words of
   this package's Scope; and whether anything can be counted today so
   that a result can say "n substitutions of this kind were made and
   not looked into" (the table's rows that exist; `Ast` facts): a
   counter that changes no verdict, or nothing, with the reason.
4. **The build's stages**, each a package the supervisor can launch
   when its Kiln rows are in the pin: tests per shape (pairs: bound
   another entity, equal outcome: `differ`; nothing moved: `equal`),
   mutations, the corpus measurement.

The design is handed back as `spec/landed/digest/WP-153.md` (the
proposal, with every decision's alternative and why it lost), the
request file, and the two paragraphs of item 3 as a diff. It gets an
independent design review before anything is built or sent to Kiln.

**What the design is now** (the proposal's §2 and §3)

- A derived unit per completed substitution: `KeyKind` 34
  `substitution`, `Name` 16 `substitution(k)`, parent the unit of the
  declaration Kiln's key names, discriminator the digest of the
  canonical arguments. Its stream has the kind, the form, Kiln's
  outcome (completed or unsatisfied) and the content.
- Two forms of the content, designed to the same depth. **Form R**:
  the walk of the root Kiln keeps per key, slot by slot. **Form T**:
  Kiln's rows as a sorted set, each entry named by (owner, region,
  ordinal within the region). A decision table per kind (§3.13).
  Recommended: roots for all four kinds; never both forms for one key.
- An **operand unit** (`KeyKind` 35 `operands`, `Name` 17) under any
  unit whose walk meets an operand that is not instantiation-dependent
  and that only a type or a value holds. It covers ordinary code
  (`decltype(n::S::s()) v;`) and instantiated declarations from the
  AST, so the digest does not read `specs()`.
- A rule that names a `substitution` or `operands` key is refused; the
  unit inherits the cause and the collision of its parent's key and of
  its argument keys.
- A key that Kiln reports as left out, an image without the table, and
  (after the last stage) a key of an unknown kind each make an
  indeterminate unit. Keys of a local declaration are counted and left
  out, a named limit.
- `scheme` moves, unconditionally, at the first stage that writes a
  substitution unit, and a digest of that scheme or a later one is
  always made with Kiln's key table on. Open question 1 asks what
  stage O does, which writes operand units and needs no table.

**What changed against the first version**

- The behaviour cases are WP-155's, a package of its own that lands
  first. The proposal's §1 adds the review's two forms and says what
  closes each.
- A key exists for every completed substitution (Kiln amended WP-3540),
  so a unit both images have is compared; the outcome is in the stream.
- An entry is no longer named by (owner, ordinal): the owner cannot be
  found from `enclosing` at the pin, and the set of dependent entries
  of an owner is not a function of its text. No Form T stage is built
  before the pin has Kiln's WP-3143, the alias residual and a region.
- Operators, constructors and conversions are in the promise; a root
  holds them, rows do not.
- The second report of §4 is corrected (one unit, one finding).

**Stages** (the proposal's §10)

3. The table stages a (`PartialMatch`), b (`Satisfaction`), c

**What could not be decided** (the proposal's §13; new with the

3. A written type argument of a transparent alias in a root
