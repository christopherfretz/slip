### The interface

A new public module `kiln_driver::front_end`. The names and shapes below
are fixed; where Kiln's types make a detail impossible, do the nearest
thing and say so in the handback.

```rust
/// How one run behaves. `Default` is: diagnostics discarded, no lookup
/// log, a thread of its own.
#[non_exhaustive]
pub struct FrontEndOptions {
    /// Diagnostics are also rendered here, as text or JSON as the command
    /// line says, followed by the summary line as `kiln` prints it.
    /// `None` renders nothing.
    pub stderr: Option<SharedWriter>,
    /// Record the header lookups (`kiln_pp::LookupLog`).
    pub record_lookups: bool,
    /// Run on a new thread whose stack is the command line's
    /// `-fkiln-stack-size=` (else Kiln's default), with the stack guard
    /// installed, as the `kiln` executable does. `false`: run on the
    /// calling thread, which has done both.
    pub own_thread: bool,
}

/// What the closure sees: the state of one translation unit when its AST
/// is final. References only, valid inside the call.
#[non_exhaustive]
pub struct FrontEnd<'r, 'sm> {
    pub sm: &'sm SourceManager,
    pub interner: &'r Arc<Interner>,
    pub diags: &'r DiagEngine<'sm>,
    pub ast: &'r Ast,
    pub oven: &'r Oven,
    pub pp: &'r Preprocessor<'sm, 'r>,
    pub target: &'r Target,
    pub lang: &'r LangStd,
    pub parse_options: &'r ParseOptions,
    pub main_file: Option<FileId>,
    /// Tokens the preprocessor delivered to the parser, the end of file
    /// not counted.
    pub tokens: u64,
    /// Paths the result depends on that are not buffers of `sm`, in the
    /// order first met, each once.
    pub consulted: &'r [Consulted],
    /// The lookup log, when `record_lookups` was set.
    pub lookups: Option<&'r LookupLog>,
}

pub struct Consulted { pub kind: ConsultedKind, pub path: String }
pub enum ConsultedKind {
    /// Found by `__has_include` or `__has_embed` and not otherwise read.
    Probe,
    /// The resource of an `#embed`.
    Embed,
}

pub struct FrontEndReport<R> {
    /// The closure's result. `None`: no parse happened (the driver
    /// refused the command line, or the job stopped before parsing).
    pub value: Option<R>,
    /// Errors and warnings of the driver and of the job together.
    pub errors: u32,
    pub warnings: u32,
    pub fatal: bool,
    /// The part of `errors` reported before any job ran.
    pub driver_errors: u32,
    /// The first diagnostic of level error or fatal, in the order emitted.
    pub first_error: Option<FirstError>,
}

pub struct FirstError {
    pub id: Option<DiagId>,
    /// The message as the text sink prints it after `error: `.
    pub message: String,
    /// Presumed position as the text sink prints it; `None` for a
    /// diagnostic without a location.
    pub at: Option<Position>,
}
pub struct Position { pub file: String, pub line: u32, pub column: u32 }

pub enum FrontEndError {
    /// The front end or the closure panicked; the payload as text.
    Panicked(String),
    /// The thread could not be started.
    Thread(std::io::Error),
    /// The command line does not name exactly one source input.
    NotOneInput,
    /// The command line's action is not `-fsyntax-only`.
    NotSyntaxOnly,
}

/// Parses the one input of `command_line` as `kiln -fsyntax-only` would
/// and calls `f` when the AST is final.
pub fn run_front_end<R: Send>(
    argv0: &str,
    command_line: &[String],
    options: FrontEndOptions,
    f: impl FnOnce(&FrontEnd<'_, '_>) -> R + Send,
) -> Result<FrontEndReport<R>, FrontEndError>;
```

Rules the code must keep:

1. **Same parse as a compile.** The command line goes through the same
   argument parser, toolchain, search list, predefines, target and
   `SyntaxJob::parse_options` as `kiln -fsyntax-only`; nothing is
   assembled a second time by hand. `SyntaxJob::parse` is split or gains
   an observer; the `kiln` executable's behaviour does not change and
   the existing tests show it.
2. **When `f` runs.** Whenever a parse happened, with errors or without,
   after everything `SyntaxJob::after_parse` does to the AST and before
   anything is dropped. Not when the job stopped before parsing.
3. **No side outputs.** The entry writes no file: no dependency file, no
   `-o`, no statistics log (it does not go through `run_jobs`). A module
   interface's module file and `-fconstexpr-report=` are written by
   `after_parse` today; the entry skips both. `-verify` and the
   `-include-pch` snapshot paths are not reachable: a command line with
   either is refused with a driver error of an existing or new `drv_` id
   (say which in the handback).
4. **Panics.** A panic of the front end or of `f` comes back as
   `Panicked` with the payload's text, on both settings of `own_thread`;
   the process's panic hook is not replaced and `crash::contained` /
   `crash::catching` are not used (their state is process-global). A
   later call in the same process works.
5. **Diagnostics.** One sink serves the driver's engine and the job's:
   it forwards to the text or JSON sink over `options.stderr` when there
   is one and keeps the first error. Totals come from the engines.
6. **Concurrency.** Two calls on two threads, with absolute paths, do
   not affect each other. The current directory and the environment are
   still the process's (research §6): both stay out of this package.
7. `FrontEnd` and `FrontEndOptions` are `#[non_exhaustive]` so that
   `sema` (Kiln's KS2), a working directory, an overlay and an
   environment can be added without breaking callers.

### Additions below the driver

- `kiln_parse`: the token count leaves `finish_tu` (`ParsedTu.tokens`).
  It must be the same number on every run of the same input; say in the
  handback what it counts after a fatal error.
- `kiln_source`, on `SourceManager`: `file_ids()` (every buffer, in
  `FileId` order), `file_origin(FileId)` (a public enum: disk, virtual,
  lazy), and `original_bytes(FileId) -> Option<Cow<'_, [u8]>>`: the
  bytes as read from disk, rebuilt from the decoded text and the load
  report's replacements (borrowed when the buffer was valid UTF-8);
  `None` for a lazy buffer never read.
- `consulted`: from the search events the dependency list already
  listens to (`deps.rs`, `on_search_event`); a path that is also a
  buffer of `sm` is not listed. If the command line has `-M*` options
  the entry still writes nothing.
- `lookups`: `search.record_lookups()` when asked,
  `pp.take_lookup_log()` before `f`. `ParseOptions.prefix` is not set by
  it. If this turns out to be more than the few lines the study expects,
  leave `lookups` always `None` and say why.

## Tests

In Kiln's `crates/kiln_driver/tests/` (and unit tests where the
additions live), each on files written to a temporary directory and
named by absolute path:

1. A unit with two headers: `f` sees the declarations (find one by
   name); `file_ids` gives the main file and both headers and
   `original_bytes` equals the bytes on disk, for a header holding
   invalid UTF-8 and one starting with a byte-order mark too; `tokens`
   equals a number counted by hand and is the same on a second run.
2. `__has_include` of a file not included, and an `#embed`: both in
   `consulted` with their kinds, once each; an included file is not.
3. A unit with one error: `f` is called, `value` is `Some`, `errors` is
   1, `first_error` has the id, the message and the position that
   `kiln -fsyntax-only` prints for the same file (compare with the text
   sink's output through `options.stderr`).
4. No parse: an unknown `-std=`, and a missing input file: `f` is not
   called, `value` is `None`, `driver_errors` and `first_error` as
   reported. `NotSyntaxOnly` and `NotOneInput`. A `-verify` command line
   refused.
5. A closure that panics: `Panicked` with its message, on both settings
   of `own_thread`; the next call succeeds.
6. A module interface unit and a command line with
   `-fconstexpr-report=<path>`, `-MD -MF <path>` and `-o <path>`:
   nothing is written.
7. Eight calls on eight threads over different units, twice: every
   report equals the one of the same unit run alone.
8. Deep nesting that the stack guard turns into a fatal diagnostic under
   `kiln`: the same through the entry with `own_thread` set (an existing
   Kiln test shows the input).
9. `record_lookups`: a missing `__has_include` key is in the log.

Besides the usual: every item whose visibility changed and every public

specification text until Kiln places it in its `spec/`; whether `Ast`

environment or an overlay as parameters; the bytes of an `#embed`
