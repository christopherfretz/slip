# WP-014 — M0 exit: the first LLVM baseline

- Status: in-progress
- Milestone: M0
- Track: G
- Needs: WP-011, WP-012, WP-013
- Size: M

## Scope

Not an implementation package: the supervisor runs it. `slip plan` and
`slip parse` over the `llvm` corpus (`cargo xtask corpus path llvm --db`)
within the memory budget of this host, then:

- every excluded entry and every shard that is not `ok` classified as a
  Slip defect (fixed, or filed as a work package), a Kiln defect (reduced
  and reported to the Kiln agent), or a property of the corpus (recorded in
  `bench/corpora.toml` or the spec that should say so);
- `cargo xtask perf record llvm <run record>` committed as
  `bench/baselines/llvm.json`, with `perf summarize`'s output in the
  handback;
- a second run compared with `perf check` (counters exact) and its shards
  compared byte for byte with the first run's (`spec/model.md` §8: a shard
  is deterministic);
- runs at `-j` 1, 4 and 8 on a slice (`--limit`) to see how wall time and
  `peak_rss_sum` scale, and one full run: reported to the operator with
  the measured per-observer and summed peaks and what a 32 GiB limit would
  change;
- every `spec/landed/` file folded into its spec, and `round` added to
  `Run`, as the close of M0.

## Done when

The baseline is committed, a repeated run passes `perf check` with
identical shards, and nothing is unclassified.

## Out of scope

libc++'s test suite as a corpus (a later package). Digests (M1).
