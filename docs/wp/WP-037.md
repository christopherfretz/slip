## Interface

Signatures are fixed; `expr.rs` and `expr_core.rs` do not change.
Everything you call is on `main`: the `expr::` accessors and `child*`,
`Walk::write_ref`, `write_type`, `write_types`, `write_sym`,
`value::value`, `stmt::child` (`StmtExpr.a`; pending `Area::Stmt`
until WP-034 lands: its tests are marked `# needs: stmt`).

Things to settle by reading Kiln, each with its `file:line` in the
landed file:

- **`TypeTrait`** (about a hundred rows): hold the mapping from Kiln's
  enumeration to the generated tags by one exhaustive `match`, and
  give every row its pair test (a namespace-scope `constexpr bool` or
  `static_assert` operand naming the builtin; generate the directories
  with a script kept under `research/` or the scratchpad, not in the
  crate). A builtin Kiln does not parse in the runner's mode stays in
  `untested.txt`, listed with the reason.
- **Stored results** (`TypeTraitExpr.b`, `ExpressionTraitExpr.b`,
  `CXXNoexceptExpr.b`, `OffsetOfExpr.b`, `ChooseExpr.aux`,
  `GenericSelectionExpr.b`, `array_trait`): each is written as stored.
  For each, when Kiln computes it: at the expression's analysis (a
  function of the program before that point: written) or later, or
  from a cache another use fills (`demand`: report, do not write). A
  trait over an incomplete class that a later definition completes is
  a function of the expression's position, which is fine; a trait
  whose answer needs an instantiation (`__is_constructible` over a
  class template specialisation) triggers it itself: give a `demand`
  test in which side B triggers the same instantiation earlier, and
  see the unit holding the trait unchanged.
- **`UnaryExprOrTypeTraitExpr`**: the value of `sizeof` and `alignof`
  is not stored (digest §6): confirm, and confirm that
  `alignof(T)` against `__alignof__(T)` differ by `TraitKind` and
  `sizeof(ns::T)` against `sizeof(::ns::T)` are `equal`.
- **Symbolic rows** (`PredefinedExpr.a`, `SourceLocExpr.a`,
  `source_loc`/`SourceLocValues`): §1.2 and digest §9 say what is
  written. `PredefinedExpr.a` "absent in a dependent context".
  `equal`: the enclosing function renamed consistently on both
  sides is not a pair test (the key moves); show instead that moving
  the expression down a line changes nothing, and that
  `__func__` against `__PRETTY_FUNCTION__` differ (`PredefinedKind`).
- **Coroutines**: the runner has no standard library: declare
  `std::coroutine_traits`, `std::coroutine_handle` and a promise type
  in the test source (see how Kiln's own tests do, and reuse one
  header `side.h` across the tests). `CoawaitParts`: five elements
  written, "the sixth, the placeholder for the awaiter, is reached
  from the calls" as an opaque value (WP-031's numbering): confirm
  with the Kiln site; `CoyieldExpr.a` "in a template pattern the
  operand alone"; `DependentCoawaitExpr`. The body of a coroutine is
  WP-034's (`CoroutineBodyData`): tests that need it are marked
  `# needs: stmt`.
- **`AddrLabelExpr.a`**: a label referred to before its declaration
  gets its ordinal here (digest §4.3).
- **`AtomicExpr.aux`** "which atomic builtin, in Kiln's numbering
  (Open questions)": hold the numbers you write equal to Kiln's by a
  unit test over Kiln's own constants or enumeration, as `attrs.rs`
  holds `KINDS`; if Kiln has an enumeration, match it exhaustively and
  report that the row could be an `enum` row.
- **GNU and C kinds**: `ChooseExpr` (`__builtin_choose_expr`),
  `VAArgExpr`, `ShuffleVectorExpr` (`b` only when the mask is known),
  `ConvertVectorExpr`, `ExtVectorElementExpr` (`ExtVectorAccess`),
  `GenericSelectionExpr` (`_Generic`), `PseudoObjectExpr`: which of
  them Kiln builds in the runner's C++ mode. One that needs a flag or
  target the runner cannot give (`-fms-extensions`, a vector
  extension off by default) gets its rows written, a unit test over a
  hand-built node if the arena lets a test build one, no pair test,
  and a line in the handback: a later package gives the runner flags.
- **`OffsetOfExpr`**: `aux`, the index expressions, the stored
  result; in a pattern `offsetof_pattern-*`; `offsetof_layout` (the
  steps: `OffsetofStep` row by row). `offsetof(S, a.b[2])`.

## Tests

Per row as the common rules say. Beyond the rows:

- `equal`: every type operand requalified or named through an alias
  (`__is_same(ns::A, B)` with `using B = ns::A;`); `typeid(ns::S)`
  requalified;
- `differ`: `typeid(T)` against `typeid(e)` of the same type;
  `noexcept(f())` after `f` gains `noexcept` (the stored result and
  the callee's unit both move: name both); `co_await` choosing a
  member `operator co_await` after one is added;
- With `origin/main` merged, un-pend the `# needs: expr` tests whose
  missing kind is one of yours; see each pass and, for one in five,
  fail when the row is broken.
