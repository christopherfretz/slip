## Interface

Signatures are fixed; `expr.rs` and `expr_core.rs` do not change.
Everything you call is on `main`: the `expr::` accessors and `child*`,
`Walk::write_ref`, `write_refs_sorted`, `write_name`, `write_nns`,
`write_args`, `write_type`, `local::write_decl`, `local::ordinal`,
`Walk::take_unit`, `take_expr_state`.

Things to settle by reading Kiln, each with its `file:line` in the
landed file:

- **Profiles.** §4.4's three rules. "Entities declared inside the
  walked expression are numbered from 0 within the stream being
  written": a profile is walked inside a type digest or a key, which
  are memoised across units, so its numbering must not read the
  unit's ordinals for what it declares itself, and must for a local
  entity declared outside (then `UnitState::local_uses` makes the type
  digest memoised for the unit only; inside a key `write_ref` already
  makes it `Unaccounted("key/local-ref")`). Say how the state is put
  aside and restored, and show: one key from two units that name
  `template<int N> void f(char(*)[N + 1]);` (the test WP-024 left,
  marked `# needs: expr` on `main`: un-pend it); two functions
  overloaded on `decltype` of different dependent expressions have
  different keys; the same expression requalified gives the same key;
  `decltype(x)` against `decltype((x))` differ (`child_keep_paren`).
  `first_expr` absent is indeterminate: find whether Kiln can leave it
  absent and give the cause a name.
- **The stored results** `RequiresExpr.aux` and
  `ConceptSpecializationExpr.aux`: "0 for a dependent expression and
  after a substitution error, never for want of asking". Prove it:
  find where Kiln fills them (at the expression's own analysis, or
  lazily from a satisfaction cache that another use fills); a `demand`
  test each, in which side B adds a use that checks the same concept
  with the same arguments elsewhere. If a use elsewhere can change the
  stored word, the row is `demand`: report, do not write.
- **`UnresolvedLookupExpr`**: `b` is the declarations found at the
  definition, sorted; `aux` whether argument-dependent lookup applies
  at instantiation. These are what makes a pattern's digest move when a
  migration changes what a dependent call can find, so: requalifying
  the name (`ns::f(t)` to `::ns::f(t)`) is `equal`; adding an overload
  to the set is `differ`; `f(t)` against `ns::f(t)` for the same set
  is `differ` (the `aux` bit); the same set found through a
  using-declaration against directly is `equal` or reported (the row
  says "the declarations found": what Kiln stores for a
  using-shadow decides; a shadow written as its target is the rule of
  `DeclRefExpr.a`, apply the same). Where the qualifier and the
  explicit template arguments of the node are kept (`TemplateTables`,
  WP-029's `templ::expr_maps`, on `main`): check the pair of tests
  covers them or add it.
- **`DependentScopeDeclRefExpr`, `CXXDependentScopeMemberExpr`**: the
  `Nns` canonical (`Walk::write_nns`); `aux-template-keyword` is `out`
  "the explicit arguments are the fact": show that `t.template
  f<int>()` and `t.f<int>()` (which without the keyword is a
  comparison) differ through the other rows.
- **Packs**: `SizeOfPackExpr` has one row, the pack, and digest §6
  says the stored result of `sizeof...` is written: find what an
  instantiation holds (a literal, a node with the count somewhere) and
  whether a partially substituted pack keeps arguments the row does
  not write; a fact Kiln stores that no row writes is reported with
  the unit made indeterminate (common rule 2).
  `SubstNonTypeTemplateParmPackExpr.b`, `FunctionParmPackExpr.b`,
  `PackIndexingExpr`, `CXXFoldExpr` (operator, which side the pack is
  on: both `child?` present or absent decide; check an init-less fold
  against one with an init).
- **Requires-expressions** (§9.3): the parameters by `decl` with
  ordinals; each `Requirement` variant; a nested requires-expression;
  the result word in an instantiation. Renaming a parameter is
  `equal`.
- **`CXXExpansionSelectExpr`, `IntegerPackExpr`**: what builds them
  (`template for`, `__integer_pack` through `std::make_index_sequence`
  or the builtin spelled directly); if the runner's language mode
  cannot, write the rows, leave the pair tests out and list the rows.

## Tests

Per row as the common rules say; these kinds live in template
patterns (a function template's body or signature, a variable
template's initialiser, a default template argument) and, for the
`Subst…` kinds and the stored results, in instantiations (a
`derived-changed` line names the instantiation). Beyond the rows:

- the profile tests above; a profile inside a class template's member
  signature; a profile naming a parameter of the function
  (`decltype(a + b)` in a trailing return type) and one naming a
  template parameter;
- `equal`: every dependent name requalified; template parameters
  renamed; a requires-clause's atomic constraints requalified;
- `differ`: `T::x` against `T::y`; `t.f()` against `t->f()`;
  `sizeof...(Ts)` against `sizeof...(Us)`; `(... + ts)` against
  `(ts + ...)`; a `noexcept` added to a compound requirement;
- With `origin/main` merged, un-pend the `# needs: expr` tests whose
  missing kind or profile is yours; see each pass and, for one in
  five, fail when the row is broken.
