# WP-171 — a compiler crash is never a rejection: the clang oracles and their tests

- Status: todo
- Milestone: M1
- Track: H
- Needs: none
- Size: S
- Parallel with: every package that does not edit `xtask/src/corpus/rename.rs`, `crates/slip_cli/tests/pitfalls.rs` or `crates/slip_script/tests/{subject_calls,header}.rs` (WP-166 edits `rename.rs`: take `main` with WP-166 merged before the PR, or say which lines collide)

## Scope

WP-167's independent review (2026-11-28) found that two clang oracles
take a compiler crash for clang rejecting the code. Both are older than
WP-167. With `-fno-crash-diagnostics` (WP-167), a crash of
`clang++-19` exits with status 139, not a signal. Before WP-167 a crash
exited 1, like a rejection.

1. **`corpus rename --accept`** (`xtask/src/corpus/rename.rs`, about
   line 1416). A unit is "rejected on both images" when clang exits
   non-zero on both, so a crash on both images passes the check.
   Shown with a stand-in clang exiting 139 on both images:
   `s6_5_accept` passes with "1 rejected on both images". When every
   command fails the same way, the check prints `check accept: ok (3
   commands; 3 rejected on both images, none otherwise)`. Fix: only
   exit status 1 is a rejection. Any other status, a signal, or
   clang's crash text on standard error ("PLEASE submit a bug report",
   "frontend command failed due to signal") FAILS the check, naming the
   command. Update `spec/harness.md` (about line 611, "exits as it does
   on the pre-image") to say so.
2. **The pitfalls' clang check** (`crates/slip_cli/tests/pitfalls.rs`,
   about line 868, `code() == Some(0)`, used about line 1180). A crash
   on a tree expected `not parsed` counts as clang rejecting it, so it
   "agrees" with Slip. The shape exists: the transform case
   `spelling-prefix-pack-indexing` crashes clang 19 even with plain
   `-fsyntax-only`. Fix as item 1: a crash fails the test, naming the
   tree.
3. **The parent test of `crates/slip_script/tests/subject_calls.rs`**
   (about lines 2805-2822) spawns its child test and never checks that
   the child ran. With the child renamed, the filter matches nothing and
   the parent passes. Assert the child's `1 passed` (or its exact
   count).
4. **Item 7's differential** (`subject_calls.rs` about line 2293) files
   a clang crash under `clang_errors`, with standard error discarded
   (about line 2238) and no bound. 8 sides are uncompared on every run
   without notice. Add a separate `crashed` result, and an allowlist of
   the sides known to crash clang 19, with a one-line reason each. A
   crash not on the list fails. A listed side that no longer crashes
   also fails, so the list cannot go stale.
5. **`accept-tmp`** (`rename.rs` about line 1409): add a test that the
   directory is removed after the check, on success and on failure.
6. **`crates/slip_script/tests/header.rs`** (about line 32) makes its
   per-case TMPDIR under `std::env::temp_dir()`. Use the crate's work
   root (`tests/common`, `spec/harness.md` §11.5) as the other tests do.
   Add a test that would fail if it went back to the system temp.

## Tests

- Item 1: with a stand-in clang exiting 139 on both images, the check
  FAILS. With exit 1 on both images, it passes as today. With 139 on
  one image and 1 on the other, it fails.
- Item 2: a pitfall tree whose stand-in or real compiler crashes FAILS
  the run.
- Items 3 to 6 each have a test that fails on today's code.
- Mutations, one at a time, reported as killed or survived:
  - "any non-zero exit is a rejection" (item 1)
  - the pitfalls' check back to `code() == Some(0)` (item 2)
  - the child assert removed (item 3)
  - a crash filed under `clang_errors` again (item 4)
  - the `accept-tmp` removal dropped (item 5)
  - `header.rs` back to `temp_dir()` (item 6)

## Done when

Every item holds with its test. `spec/harness.md` says what item 1
does. The full `cargo xtask ci` passes on the branch with `main`
merged in, with `clang++-19` installed.

## Out of scope

The compiler runs of `corpus rename --build` and of the corpus build
steps (`xtask/src/corpus.rs`): those are corpus runs, not gate steps.
The transform oracle (`xtask/src/transform/oracles.rs`) already reports
a crash as `exit 139` or `killed`.
