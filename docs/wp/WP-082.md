# WP-082 — the resource headers: where they live, how they are checked

- Status: in-progress
- Milestone: M3

## Scope

Rules 1 to 3 can start now. Rule 4 launches after WP-080.

`spec/api.md` §2.1 rules 1 and 6, §2.2 (the header check), §8.2. The
files `resource/include/slip/meta.h` and `__intrinsics.h` exist and are
normative; this package does not redesign them. A defect found in them is
a spec change: fix both, say so in the hand-back.

1. **Embedding.** `slip_script` embeds the two headers
   (`include_bytes!`) and exposes their digests.
2. **The resource directory.** `$SLIP_RESOURCE_DIR` if set, else
   `<directory of the executable>/../share/slip/resource`, else (a
   development build) the repository's `resource/`. `slip resource
   --write <dir>` writes the embedded files there.
3. **The header check** (`transform-header`): given the files a transform
   unit read (WP-080's `ReadFile`), the two under
   `<resource>/include/slip/` must be present and have the embedded
   digests.
4. **Header conformance.**

## Interface

```rust
// crates/slip_script/src/resource.rs
pub const META_H: &[u8]; pub const INTRINSICS_H: &[u8];
pub fn resource_dir(exe: &Path, env: Option<&OsStr>) -> PathBuf;
pub fn write_to(dir: &Path) -> io::Result<()>;
pub enum HeaderError { NotRead(&'static str), Differs(&'static str) }
pub fn check_headers(read: &[(Vec<u8>, slip_model::Digest)], resource: &Path) -> Result<(), HeaderError>;
pub const API_LEVEL: u64 = 202611;
```

## Tests

`crates/slip_script/tests/header.rs`:

1. The embedded bytes equal the files under `resource/`.
2. `check_headers`: accepted; a header not read; a header with one byte
   changed; a header of the right content read from another directory
   (refused: the rule is about `<resource>`).
3. With `g++` or `clang++` on `PATH` (skip otherwise, visibly): both
   examples under `resource/examples/` pass `-std=c++26 -fsyntax-only`
   with only the "used but never defined" warning for `__call`.
4. After WP-080: a transform unit that includes `<slip/meta.h>` and
   declares, for every function of `spec/api.md` §4 to §7, a pointer or
   a `requires` expression with the exact signature the specification
   gives, compiles in the transform universe; each feature-test macro has
   its value; `__SLIP_HOSTED` is 1.
5. After WP-080: both examples compile in the transform universe.
