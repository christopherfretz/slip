# WP-124 — what a pattern keeps outside the AST: a template constructor's mem-initializers, and the audit of its siblings

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-041
- Size: M
- Parallel with: WP-106, WP-122, WP-123 (one digest branch merges at a time; this one first: it closes a wrong `equal`)

## Scope

`docs/wp/WP-041.md`'s fifth round found a wrong `equal` that is not a
spelling:

```cpp
template <class T> struct S {
  int m;
#ifdef B
  S() : m(2) {}
#else
  S() : m(1) {}
#endif
};
```

No mem-initializer of a constructor defined in a template reaches the
digest. Kiln's parser hands the list to `Sema`, which keeps it as
parsed in a table of its own (`pattern_mem_inits` in
`kiln_sema/src/templ/mod.rs`) for the instantiation to substitute into;
the constructor's declaration in the `Ast` has no initializer, and the
expressions, though they are in the expression arena, hang from
nothing. An instantiation's constructor has its own list, so the two
sides differ in a translation unit that instantiates the definition,
and are `equal` in one that does not. The pending pairs are
`crates/slip_digest/tests/differ/_/mem-initializer-in-template`,
`-operand-in-template` and `-base-in-template`.

Kiln has the request (KB6 9.7, sent 2026-11-23: the list on the `Ast`).
Until the record is in the pin Slip must not answer `equal` here.

1. **The facts first** (a table in the landed file, each row a pair):
   for the three pending pairs and for the same sources with one
   instantiation (`S<int> s;`), with a use that needs the constructor's
   definition and with one that does not: which units exist, which
   differ. Also a constructor template of a class that is not a
   template; a constructor of a member class of a class template; a
   constructor defined outside the class; a delegating constructor; a
   base initialised by a pack expansion; a default member initialiser
   used because the mem-initializer was removed.
2. **Fail closed.** A constructor definition whose mem-initializers the
   `Ast` does not hold is indeterminate, cause
   `Unsupported("kiln/pattern-mem-initializers")`. The condition must
   be the one under which Kiln takes that path (read
   `Sema::act_on_mem_initializers`: `check_mem_inits_of`), stated from
   what the `Ast` gives: say what you test and why it cannot be
   narrower with the `Ast` alone (Kiln keeps no mark of "has a
   ctor-initializer" on the declaration; if you find one, use it, with
   the pair that shows a constructor without a ctor-initializer stays
   determinate). No reading of the source text between `)` and `{`.
3. **The cost, measured before the rule is final.** What becomes
   indeterminate: only the constructor's own unit, or more (does a
   unit that refers to an instantiated constructor, or a class whose
   member it is, take the cause)? Numbers: pair directories whose
   verdict moves (list them; each gets `# needs: kiln` or an adjusted
   source, never a silent re-bless), indeterminate units added over the
   standard-library translation units the harness parses, by header.
   If the cost is the constructor's unit alone, the rule lands as
   written. If units that merely use `std::vector` become
   indeterminate, stop and tell the supervisor with the numbers and the
   path by which the cause spreads: the decision between this rule and
   a named hole is the supervisor's, and a hole in the trusted base is
   not taken lightly.
4. **The siblings.** The same shape may exist for other syntax of a
   pattern that `Sema` holds until instantiation. For each of the
   following, a pair that changes it in a class template or function
   template that no translation unit instantiates, and what the digest
   answers today: a default member initialiser; a default argument of
   a member function and of a function template; a `noexcept`
   operand (`ExcSpec/Deferred` is counted today: say what it covers);
   a trailing `requires`-clause and a constraint in the template head;
   an `explicit(…)` condition; the branches of `if constexpr`; a
   member function's body; a lambda's body and its captures inside a
   template; a friend function's body; an attribute's argument; an
   in-class static member initialiser; an enumerator's value in a
   member enumeration; a base-specifier list with a pack expansion;
   a deduction guide; a variable template's initialiser. Read Kiln's
   `InstState` (and what else in `kiln_sema` stores parsed syntax
   keyed by a declaration) and list every table of this kind with the
   construct it holds: that list is the one the supervisor asked Kiln
   for; yours is from the code and checks theirs. Each sibling that is
   `equal` today is a finding: the same fail-closed rule with its own
   cause, its pair, and a For Kiln item.
5. **When Kiln's record lands** (not this package unless it is in the
   pin before you finish): the rule of item 2 becomes "read the list"
   and the pending pairs become `differ`. Leave the note of what to
   change and where.
