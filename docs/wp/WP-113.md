# WP-113 — what an entity takes from its enclosing namespaces besides its name: linkage and visibility in its unit

- Status: todo
- Milestone: M1
- Track: C
- Needs: WP-040, WP-103, WP-104
- Size: M
- Parallel with: WP-110, WP-112 (not with another package that moves every unit digest)

## Scope

The independent review of `docs/wp/WP-103.md` found two programs that
differ in meaning and compare equal under rule tables `slip declare`
makes:

```cpp
// pre                                         // post
namespace { struct Impl { int f() { return 1; } }; }    namespace { }
                                                        struct Impl { int f() { return 1; } };
int u() { return Impl().f(); }                 int u() { return Impl().f(); }
```

with `relocate (anonymous namespace)::Impl => :: =`. `Impl::f` is a
local symbol before and a weak external one after; two translation
units that each had their own `Impl` now violate the one-definition
rule, each verifies, and the linker keeps one definition. The same for
an inline function, for the unnamed namespace renamed to a named one,
the reverse, and a named namespace merged onto the unnamed one; and for
a function moved between namespaces that differ in
`__attribute__((visibility("hidden")))`.

The cause is in the design. `spec/digest-kinds.md` (the `aux-braceless`
row, `spec/landed/digest-kinds/WP-033.md`) says an entity's linkage "is
what its key holds": the key's parent chain says whether an unnamed
namespace encloses it. Rules rewrite keys. So under a rule the one
record of that fact is rewritten with the name, and `spec/verify.md`
§2.1's sentence "no generated code depends on which namespace an entity
is in except through names" is false.

The fix: **an entity's unit holds what the entity takes from its
enclosing namespaces other than its name.** Then a rule can move the
name and nothing else.

1. **Find everything a member takes from its namespace.** From the
   standard and from Kiln's code, not from this list: linkage from an
   unnamed namespace ([basic.link]); a namespace's `visibility`
   attribute and `#pragma GCC visibility push` (how does Kiln apply
   each: an attribute on the member, or a lookup of the enclosing
   namespaces when code is generated? `kiln_sema/src/visibility.rs`,
   the linkage and visibility caches of `DeclMisc`); `abi_tag` on a
   namespace (changes mangled names only: a name, but not the one the
   rule declares: decide); `deprecated` and `unavailable` on a
   namespace (do uses of a member differ?); an `inline` namespace
   (lookup only, or more?); module attachment and `export` of a
   namespace; `extern "C"` blocks (already `c_linkage` in the key:
   confirm nothing else is taken); anything Kiln's mangler, visibility
   computation or code generator reads from a namespace
   (`spec/digest-kinds.md` row `lexical_ctx` names the readers). Record
   the audit as a table in the landed file: the property, where Kiln
   holds it, whether a member's unit holds it today, the pair that
   shows it.
2. **Write it** (`crates/slip_digest`): for every entity whose
   semantic context is a namespace or the translation unit, a row of
   its unit with what item 1 found, computed from the chain of
   enclosing namespaces. Proposed form: the entity's effective linkage
   as Kiln computes it (`kiln_ast/src/linkage.rs` `Ast::linkage`) where
   the namespace decides it, and the effective visibility where a
   namespace gives it; say why not simply "inside an unnamed
   namespace: yes or no" (or why that is enough). An entity inside a
   class or a function takes these from its parent, whose key it
   holds and whose unit holds the row: show that this chain has no gap
   (a class with no unit; a local class; a closure; a friend defined
   in a class; a specialisation whose template is in an unnamed
   namespace; a template argument with internal linkage).
3. **The spec.** `spec/digest-kinds.md`: the new row, and the
   `aux-braceless` row's sentence corrected; `spec/digest.md` §3 and §5
   where they say the key carries linkage; `spec/verify.md` §2.1: the
   namespaces paragraph and the soundness argument as they then are
   (what WP-103's fix round wrote as a known gap becomes the rule).
4. **The digest scheme.** Every namespace-scope unit's digest changes:
   the scheme number of `spec/model.md` §8.2 moves, every golden of the
   map phase is re-blessed once, the corpus baseline is re-recorded (or
   left to the supervisor: say which). Show that nothing else moved: a
   run with the new row left out reproduces the old goldens.
5. **Tests.** The pending cases of WP-103 (`# needs: WP-113`) pass;
   beside them, for each row of item 1's table, a pair that differs
   and the rule table under which it would otherwise be equal; the
   controls (an entity moved between two named namespaces with nothing
   to take: equal; from an unnamed namespace to an unnamed namespace
   nested elsewhere: equal); the pitfall row for it
   (`crates/slip_verify/tests/pitfalls/`, the next free N number, with
   the `nm` evidence in its comment) and its line in `spec/pitfalls.md`
   §2.
6. **If WP-103's fix round did not build it**: refuse, where the rule
   table or the container is validated, a rule of kind `namespace`
   whose two names differ in being the unnamed namespace's. With item
   2 built this is no longer needed for soundness (the members' units
   differ); keep it or remove it, and say which and why.

## Interface

No public type changes. The unit stream gains a row; the scheme number
moves.

Files you may edit: `crates/slip_digest/src/` where a declaration's
rows are written and the files item 2 needs; the tests and goldens of
`crates/slip_digest`; `crates/slip_model` for the scheme number; the
specs of item 3; the pitfall row; `spec/landed/digest/WP-113.md`.

## Tests

Item 5; mutations: the row not written; written for class members too
(nothing may change: say what does); the linkage taken from the first
declaration only; visibility left out; the chain stopped at the first
enclosing namespace (an unnamed namespace two levels up missed); an
`inline` namespace treated as unnamed.
