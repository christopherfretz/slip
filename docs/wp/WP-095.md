# WP-095 — slip_script: the subject over Kiln: keys for declarations and spelled entities

- Status: in-progress
- Milestone: M3
- Track: E
- Needs: WP-083, WP-086, WP-087
- Size: S
- Parallel with: WP-085, WP-089, WP-090

## Scope

`spec/api.md` §7.5 rules 1 to 3. In `KilnSubject`: `unit_keys`,
`rename_rule`, `entity_key`, over `slip_digest::query::Keys` (WP-087).
Nothing here computes a key; it finds the declaration and asks.

1. `unit_keys(v)`, for a reference or an expression only (the host
   refuses the other sorts, §7.5 rule 2; answer `unsupported` if asked):
   for a reference, the holder of the reference (the
   declaration whose body, initialiser or declarator holds its name: the
   calls index of WP-086 extended to record the holder of each written
   reference it passes, or, for a reference outside every body, the
   declaration whose range the table attributes it to); for an
   expression, `KilnSubject::holder`. Then the unit's key and
   `Keys::derived`. `NoKey::ContentKeyed` and `Indeterminate` are
   `unsupported`; no holder is `unsupported`.
2. `rename_rule(e, n)`: `Keys::rename_rule`; `NotAUnit` and
   `ContentKeyed` are `unsupported`.
3. `entity_key(e)`: `Keys::key_id` or none.
4. `Keys` is built on first use and lives as long as the `KilnSubject`.

## Interface

`impl Subject for KilnSubject` in
`crates/slip_script/src/kiln_subject/keys.rs`.

## Tests

`crates/slip_script/tests/subject_keys.rs`, on snippets:

1. A call in a function, in a lambda in a function, in a variable's
   initialiser, in a default member initialiser, in a member function of
   a class template with two instantiations: the keys are those the
   digest lists for the unit (joined through `Output::names`).
2. A reference in a parameter's type and in a base specifier: the
   function, the class.
3. Each `unsupported`.
4. End to end, with the fake edits of the test: digest a snippet;
   run `expect_changed(call)`; change the call by hand; digest; the only
   keys that differ are among those declared.
5. `KilnSubject`'s entity and `Keys::entity` agree on every declaration
   of the snippets (WP-083's rule).

## Handback

Branch `wp/095-subject-keys`. Landed: `entity_key`, `rename_rule` and
`unit_keys` of `KilnSubject` (`kiln_subject/keys.rs`), over
`slip_digest::query::Keys`, which runs on a key server thread started
by `KilnSubject::with_keys`. Also, the holder of each written reference
is recorded by WP-086's walk (`calls.rs`), and every table entry of a
reference is kept (`references.rs`). Tests 1 to 5 are in
`crates/slip_script/tests/subject_keys.rs`. The holder rules per place,
every `unsupported`, the decisions, the measurement, the mutation table
and the For Kiln items are in `spec/landed/api/WP-095.md`.
`spec/api.md` §7.5 rule 2 now states that a unit the host cannot
establish is `unsupported`.

Results:

- **Test 5.** No declaration of any snippet has a `KilnSubject` entity
  that disagrees with `Keys::entity`.
- **Cost of recording holders.** On 2,000 functions (20,000 recorded
  entries, debug build), the index takes about 1.0 s with or without
  recording. The memory is about 250 KiB, one hash map.
- **Mutations.** 12 mutants, 9 killed; the 3 survivors are argued in
  the landed file. The review round adds 9 more (table in the landed
  file).

Review round (F1 to F9):

- An expression in decl-specifiers shared by a declarator group is
  `unsupported`, by the same `shared_specifiers` as the reference path.
- A block-scope declaration is held by the outermost function whose
  body holds it; a block-scope `extern` gives two units (`unsupported`)
  except in its default arguments.
- `slip_digest`'s `Keys::derived` lists explicit instantiations of a
  function (its only other caller is `slip_digest`'s `api_keys` test).
- `with_keys` returns `Keyed { value, server_panicked }`; a panicked
  server makes every later key question `unsupported`.
- One-shot key servers are counted and printed as
  `api.one_shot_key_servers` when not 0.
- The landed file lists the open question on base specifiers of class
  templates and the known wrong `unsupported`s.

For other packages:

- **WP-092** must run `Loaded::run` inside `subject.with_keys`, as
  `script_test::run_one` now does. Outside it, every key question
  builds a new `Keys`: the answers are correct but not memoised, and
  the run's counters show `api.one_shot_key_servers`. When
  `Keyed::server_panicked` is true, the run is an internal error: no
  result, the edits discarded.
- **WP-085 (finding):** building `KilnSubject::from_snippet` on a
  snippet of 2,000 small functions takes about 5.1 s in debug, and
  20,000 did not finish in 7 minutes. That growth is superlinear and
  predates this package.

Not done:

- Type names in enumerator values and template head defaults are not
  recorded by the walk, so they stay `unsupported`.
- Created and removed units (out of scope).

For Kiln (with reproducers in the landed file): the names of aliases,
enumerators, template heads and `static_assert`s are enclosed by the
lexical context, not by the declaration. A shared decl-specifier
(`S a, b;`) is enclosed by the first declarator only.
