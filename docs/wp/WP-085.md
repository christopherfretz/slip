# WP-085 — slip_script: the subject over Kiln: references, ranges and text

- Status: in-progress
- Milestone: M3
- Track: E
- Needs: WP-067, WP-081, WP-083, WP-084
- Size: L
- Parallel with: WP-086..089

## Scope

It reads Kiln's written-reference table (Kiln WP-1930 and WP-1931;
`docs/design/notes/kiln-landed-2026-11.md` §5 gives the interface with
places and the eight things that differ from what Slip asked for)
through `slip_kiln::written` (`docs/wp/WP-067.md`, milestone M2), the
one module that reads it for the native rename, for the check of
spelled entities and for this subject. This package defines no reading
of the table of its own.

`spec/api.md` §5.4, §6.5, §6.6, §7.4 rule 3. In `KilnSubject`:
`references_to`, `referent`, `name_range`, `extent` of a reference,
`references_at`, `found_directly`, `tier`, `place` of a reference, a
declaration and an entity, and the counter of §6.5 rule 6.

What is decided:

1. A **reference** is one entry of `slip_kiln::written::written_refs`
   in one of the roles of §6.5 rule 3. Entries in other roles, should
   Kiln add them (stages 3 to 5), are skipped here until the
   feature-test macro of rule 4 is defined: the set must not grow
   silently under one API level.
2. Kiln's table repeats an entry when a default member initialiser or a
   default argument is parsed again
   (`kiln-landed-2026-11.md` §5, difference 3). One written name is one
   reference: entries equal in role, range and referent are one. The
   joining is `written_refs`' (`docs/wp/WP-067.md`, item 2); test 3
   below holds it from this side.
3. `references_to(e)` uses an index from origin to references, built on
   the first call in the unit and kept for the life of the `KilnSubject`
   (which is one run or many; the index does not depend on the run).
4. `name_range` and `extent` go through `slip_kiln::ranges`
   (WP-084), which calls Kiln's `editable_file_range`, and are null
   when it returns none. `name_range` is also null when the range is
   not the identifier token itself (`spec/api.md` §6.6 rule 1): for a
   name that is a whole macro expansion (`ID(foo)` with `#define ID(x)
   x`) Kiln's range is the invocation (`docs/wp/WP-084.md`, item 1).
   The host tells by asking Kiln: `token_end` at the start of the range
   must be its end, and the token there must spell the name.
   `spec/api.md` §5.4 does not say which of its two rows such a name
   is in; null is the reading that never returns an approximation, and
   the hand-back says how many names of the test corpus it concerns.
5. **A leading `::`.** The table says a qualifier is global and does not
   say where the `::` is (`docs/requests/KR1-amendment-1.md` §3). Until
   Kiln records it: lex backwards is not possible, so lex the file text
   from the start of the line that holds the first named component, and
   accept the `::` only if it is the token immediately before that
   component and is file text of tier 0 or 1 at the same tier. Otherwise
   the extent is null. Never return an extent that starts after a `::`
   that was written.
6. The counter `api.unresolved_spelling_matches`: for each entity asked
   about, the number of identifier tokens of the unit's dependent-name
   records spelled like its identifier. If the pin has no such record,
   the counter is absent, not zero, and the hand-back says so.
   The trait method is `Subject::unresolved_named(identifier) ->
   Option<u64>` (WP-081): the host counts each identifier once and
   makes the counter absent when any answer is `None`
   (`spec/api.md` §6.5 rule 6).
7. **`tiers(r) -> Option<[bool; 2]>`** (`spec/landed/api/WP-088.md`
   decisions 6 and 10, `spec/landed/api/WP-102.md` decision 3; it was
   `tier(r) -> Option<u8>` before) answers the tiers at which the unit
   reaches `r`, `reached[t]` for tier `t`, never both false, only when
   `r` is exactly a range that `name_range` or `extent` gives for some value of the unit, and `None` for any other
   range, even one inside such a range: `replace` refuses `None` as
   forged. Keep the ranges given out (or an index from range to tiers)
   rather than classifying an arbitrary range. **`place(v)`** answers
   `PlaceOf::Own`, `Nearest` (the macro invocation), `Unnamed` (a place
   exists and neither it nor a nearer one is nameable) or `Nowhere` (an
   entity with no written declaration).

The record must be switched on: a subject is parsed with
`ParseOptions::written` (`docs/wp/WP-067.md`, item 1), which until
Kiln's WP-2320 (`docs/requests/KR1-amendment-1.md` §1) adds Kiln's dump
flag to the command line and discards the output. A worker reaches the
table that way (`docs/wp/WP-074.md`, `docs/wp/WP-092.md`); the snippet
front end of this package's tests sets the same option. A unit parsed
without it (`slip_kiln::written::recorded` is false) has no reference
and no dependent-name record: `unresolved_named` then answers `None`
(item 6), so the counter is absent and not zero.

## Decided since the package was written (the review of WP-083)

**Which declarations are written is read from Kiln's declaration-extent
table**, not inferred from member lists. `KilnSubject`'s `written(d)`
(WP-083, one function) had three defects found by review, all of the
same kind: a declaration reachable through a member list that the parser
never parsed (an explicit instantiation's members, the declaration Kiln
makes by deduction for an explicit specialisation of a member template,
the fields of an implicit builtin record). Kiln's table has one row per
declaration the parser parsed and none for an implicit declaration, an
instantiation or its members (Kiln `spec/ast.md` §19.1), and
`slip_kiln::written` (`docs/wp/WP-067.md`) switches it on with the
written-reference table. So in this package:

- a `KilnSubject` is made only over a unit for which
  `slip_kiln::written::recorded` is true; over any other, making it
  fails;
- the body of `written(d)` becomes: `d` has a row, and the row is not
  that of an explicit instantiation (an explicit instantiation is not a
  declaration of the entity: WP-083's decision 2 stands). A block-scope
  declaration and a template parameter have rows; check both and say so;
- WP-083's tests of written-ness stay and must pass unchanged; a test
  over every pair-test snippet of `slip_digest` states where the old
  structural rule and the table disagree, each disagreement explained,
  before the structural rule is deleted;
- the row is read through `slip_kiln::written::row(unit, d)` (WP-067's
  fix round: `Some` for every row, with its kind, those `decl_names`
  leaves out included), not from Kiln's table directly. Three holes of
  the table at this pin are in `spec/landed/edits/WP-067.md` with their
  `kiln_hole_*` tests (no row for some explicit instantiations; a later
  friend or repeated explicit-specialisation declaration overwrites an
  earlier row; an init-capture has no row): `written(d)` is wrong for
  those until Kiln fixes them, and each gets a test here that states
  what is seen today.

## Interface

`impl Subject for KilnSubject` in
`crates/slip_script/src/kiln_subject/references.rs`. Nothing public is
added, and `slip_kiln` gains nothing: `written_refs`, `WrittenRef`,
`dependent_names` (the records item 6 counts) and `origin` are
`slip_kiln::written`'s (`docs/wp/WP-067.md`, "Interface"), which this
package uses as they are. If the subject needs of that module something
it does not give, the hand-back says what; this package does not add
it.

## Tests

`crates/slip_script/tests/subject_references.rs`, on snippets, calling the
trait:

1. One test per role of §6.5 rule 3, with the name's range checked byte
   for byte.
2. One per row of rule 4: the name is not returned.
3. Rule 2 above: a default member initialiser used by two constructors
   gives each name once.
4. Extents: unqualified; `a::b::c`; `::a::b`; `:: a::b` with a comment
   between; `a::template b<int>`; `typename T::x` (not returned:
   dependent); an operator name (extent non-null, name range null).
5. Tier 1: a reference inside a macro argument; the argument used twice
   gives one reference with one range. Tier 2: a reference in a
   replacement list has null ranges and a place that is the invocation,
   marked not its own.
6. `references_to` of a template returns references to its
   specialisations (origin); of an overload returns only that overload's.
7. `found_directly` is false through a using-declaration and true
   through a using-directive and an inline namespace.
8. Unit order across two headers and the main file.
9. The property: for every reference of every digest pair-test snippet,
   `text(name_range)` is the referent's identifier.

## Handback

Branch `wp/085-subject-refs`, last code commit `912e5ee6`. Landed:
`kiln_subject/references.rs`. It gives `references_to`, `referent`,
`name_range` (of a reference and of a declaration), `extent`,
`references_at`, `found_directly`, `tiers`, `place` (of a reference, a
declaration and an entity) and `unresolved_named` for `KilnSubject`.
`written(d)` is now the declaration-extent table's answer, and WP-083's
structural rule is deleted. Making a subject now returns `Result`, and
fails over a unit parsed without the tables. Tests are in
`tests/subject_references.rs`; tests 1 to 9 are there, each named after
its spec section, together with the tests the mutants asked for. The
decisions, the comparison of the structural rule with the table, the
costs and the Kiln defects are in `spec/landed/api/WP-085.md`.

`RangeSetTest.cpp` (206 674 references), `SemaDecl.cpp` (249 188) and
`Instructions.cpp` (110 803). Release build, LLVM 19.1.7, single thread:

Proposed spec sentences:

- §6.5 rule 4, after "an elaborated or friend reference": "An elaborated
  reference is an elaborated type specifier that declares (`class X;`,
  `friend struct S;`). One that only names a type (`struct S *p;`) is a
  type name of rule 3."
- §5.5: "An explicit specialisation is its own origin;
  `references_to` of a template does not return the names of its
  explicit specialisations."
- §6.3: "The identifier of a reference is its referent's identifier."
- §6.6: "A name that is written as a whole macro expansion has no name
  range. Its extent is the invocation's range, at tier 0."
- §7.4 rule 3: the order of fallbacks for the nearest place of a
  reference and of a declaration (landed decision 8).
