# WP-016 — slip_verify: the comparison

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-006
- Size: M

## Scope

`crates/slip_verify/src/compare.rs`: `spec/verify.md` §3, §4 and §4.1 as
pure functions over the plain types of `slip_model::digests` and
`slip_model::verdict` (already on `main`). No front end, no file, no
clock. This crate is part of the trusted base: it is small on purpose,
has no dependency but `slip_model`, and every sentence of §4 has a test
that fails if the sentence is not implemented.

Not in scope: rules and the `DECL` container (§2), the verify job (§5),
localisation (§6.1), names of entities (`Finding::name` stays empty and
`location` stays `None` here).

## Interface

```rust
/// §2.2. Each slice sorted, no two equal (checked by `Exemptions::new`).
pub struct Exemptions { changed: Vec<Digest>, created: Vec<Digest>, removed: Vec<Digest> }
impl Exemptions {
    pub fn none() -> Exemptions;
    pub fn new(changed: Vec<Digest>, created: Vec<Digest>, removed: Vec<Digest>) -> Result<Exemptions, String>;
}

/// §3 "Shards": why two `Digests` cannot be compared, if they cannot.
pub fn comparable(pre: &Digests, post: &Digests) -> Result<(), String>;

/// §4.1 step 1 and the definition of G.
pub enum AtSums {
    /// Equal `tu` digests.
    Equal,
    /// The groups, by (class, file), whose sum is not the same in both; sorted.
    Differing(Vec<(GroupClass, Vec<u8>)>),
}
pub fn at_sums(pre: &Digests, post: &Digests) -> AtSums;

/// §4 over the unit lists of the groups given (the groups of G from each image).
pub struct Comparison {
    pub findings: Vec<Finding>,       // every finding, in the order of §6
    pub only_pre: u64, pub only_post: u64,
    pub used: Vec<Digest>,            // sorted, no two equal
}
pub enum CompareError { MissingUnits { class: GroupClass, file: Vec<u8>, post: bool } }
pub fn compare_groups(pre: &[&Group], post: &[&Group], exemptions: &Exemptions) -> Result<Comparison, CompareError>;

/// §6: the section, with `findings` cut to `limit`.
pub fn verdict(comparison: Comparison, pre_shard: Digest, rules: Digest, limit: usize) -> Verdict;
pub fn verdict_at_sums(indeterminate: u64, pre_shard: Digest, rules: Digest, limit: usize) -> Verdict;   // §4.1 step 1
pub fn unverifiable(reason: &str, pre_shard: Digest, rules: Digest) -> Verdict;
```

`verdict_at_sums` with `indeterminate` 0 is `verified`; otherwise
`mismatch` with `total = indeterminate` and that many unnamed
`indeterminate` findings (cut to `limit`). `reason` longer than 4096 bytes
is cut at a character boundary. Adjust shapes where the code shows a better
one and record the final interface, and every rule §4 leaves open, in
`spec/landed/verify/WP-016.md`.

A finding's `file` is the file of the pre-image group that holds a unit of
its key, else of the post-image group; if several groups of one image hold
it, the smallest. `pre` and `post` are as §6 says.

The comparison must be linear, up to sorting, in the number of units
given; a translation unit can have several hundred thousand.

## Tests

`crates/slip_verify/tests/compare.rs` (§4), over unit lists written by
hand, each test naming the step it covers: equal images; `changed`,
`removed`, `added`, each also prevented by its own exemption and by no
other, with `used` holding exactly the exemptions that prevented a
finding; an indeterminate unit in the pre-image only, the post-image only
and both, with and without an exemption for its key (never prevented);
a content-keyed unit in two groups (multiplicity 2 against 2, 2 against
1); two different units of one key on one side; a declared unit that
moved between groups; the `tu` group compared with the declared ones;
derived keys: both and equal, both and different, both with one
indeterminate, one side only (counted, no finding); a key that is declared
in one image and derived in the other; the order of findings; `verdict`
with `limit` below, at and above the number of findings; the three
verdict kinds valid under `slip_model`'s invariants once WP-015 lands
(until then, checked field by field).

`crates/slip_verify/tests/groups.rs` (§4.1): a deterministic generator
(a small xorshift in the test, no dependency) makes pairs of images:
random units over random files and classes, then a random mix of edits
(change a digest, remove, add, move a unit to another file, duplicate a
content-keyed unit in another file, flag indeterminate), building
`Digests` with `slip_model::digests::{group_digest, tu_digest}`. For each
pair, `at_sums` + `compare_groups` over the differing groups gives the
same findings, counts and `used` as `compare_groups` over all groups; and
`AtSums::Equal` exactly when the comparison over all groups has no finding
and no one-sided derived key. At least ten thousand pairs, in well under a
second each hundred.

`comparable`: equal schemes; different schemes; a scheme this crate does
not implement.

## Done when

`cargo xtask ci --quick` passes; no dependency was added; the crate has no
`unsafe`, no panic reachable from its inputs (lists that are not sorted or
hold duplicates are `Err` or handled, never a wrong answer: say which in
the landed file), and no wildcard arm over `FindingKind`, `GroupClass` or
`VerdictKind`.
