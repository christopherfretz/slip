# WP-137 — `spell` is made where it lands: an entity with no qualified name at a name range

- Status: in-progress
- Milestone: M3
- Track: G
- Needs: WP-132
- Size: S
- Parallel with: WP-129 and WP-133 (all three edit `spec/api.md`: this one owns §7.1 rule 4 and §7.2 rule 1 only)

## Scope

`docs/wp/WP-132.md` left one thing open (`spec/landed/api/WP-132.md`,
"Open"): the idiom

```cpp
auto g = lookup(parent_of(referent_of(r)), "g");
replace(name_range_of(r), spell(g));
```

at `w.f()` with `W<int> w` finds the template's own `W::g`, and then
`spell(W::g)` throws `unsupported` when the code value is made
(`spec/api.md` §7.1 rule 4: a member of a class template has no
qualified name without template arguments), before `replace` knows that
the range is a name range, where the spelling is the identifier alone.
The transform's only other way to write the name is `identifier("g")`
built from text the transform holds, which is what version 0 exists to
avoid when the entity is in hand.

The ruling (the supervisor's; the first of the two resolutions the
landed file offers):

1. `spell(e)` of an entity that has an identifier is always made; the
   piece holds the entity. What §7.1 rule 4 refuses today for the lack
   of a qualified name (a specialisation or a member of one, a member of
   a class template, an entity declared in an unnamed class, an entity
   whose only declarations are friend declarations) is refused where
   the piece is turned into text (§7.2) and only if the place takes the
   fully qualified spelling. At a place that takes the sibling spelling
   or is a name range (§7.2 rule 1 and WP-132's rule for a declaration's
   name) the text is the entity's identifier, with the key WP-132's
   rule 6 gives or withholds.
2. Still refused when the code is made: `wrong_kind` for what is no
   entity; `unsupported` for a parameter, for an entity with no
   identifier, and for an entity the digest has no key for (§7.2 rule 5:
   a spelling that could not be checked is not given).
3. The error of a refusal at `replace` names the piece's entity and the
   place, and is the error `spell` gave before (`unsupported`), so a
   transform that caught it at `spell` and one that catches it at
   `replace` read one kind.
4. `tests/api/lookup/r8-the-idiom-in-an-instantiation` loses its
   `xfail`; its expected key names were the implementer's guess: make
   them what the host gives and check them against `slip units`.

## Handback


Built as ruled except one point that needs the supervisor's decision; the
record is `spec/landed/api/WP-137.md`.

- **Items 1 to 3**: `spell` of an entity with an identifier and no
  qualified name is made (`Subject::unqualified`, new, says why; the held
  piece carries it); `replace` refuses it with `unsupported` where the
  place takes the fully qualified spelling, alone or inside `cat`, the
  message naming the entity and the refusal's place the range replaced.
  Still refused at `spell`: what is no entity, a parameter, no
  identifier, no key, and the other cases `qualified` refused that the
  ruling does not list (landed decision 4).
- **Item 4**: the idiom's directory passes with no `xfail`; its keys
  `W::g()`, `O::I::g()`, `X::g()` are the `declared` units `slip units`
  prints for the file.
- **The sibling condition** compares the pattern's parent (the parent of
  the referent's origin), as §7.2 rule 1 already said.
- **Open, for the supervisor (STOP)**: a specialisation passes the sibling
  conditions at a reference to itself, and its key could never hold
  (verification takes the origin's key). Built: refused there with
  `unsupported` (landed decision 2). Alternatives: record the origin's key
  (a change of how a key is given: second review), or record the
  specialisation's key (always fails verification).
