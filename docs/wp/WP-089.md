## Scope

`spec/api.md` §2 (all) and §12. The one place that joins a transform
session (WP-080), the host (WP-081) and a subject: given a transform's
command line, compile it once; given a subject, run `transform()` against
it and return the run output or the failure.

What is decided:

1. **Order of checks** when a transform is loaded: options
   (`transform-option`), compile (`transform-compile`), headers
   (`transform-header`), reserved names (`entry-reserved`), the entry
   (`entry-*`). The first that fails is the error.
2. **The transform id** is computed here (§2.2) from the API level, the
   command line as given to Kiln and the files read with their digests.
3. **A run** makes a new `Host`, runs the entry with the budgets, and
   classifies: completed (the host's `finish`); or one of §2.8. For
   `uncaught` of type `slip::v0::error`, the message and place come from
   the host's failure list. Kiln reports the type of an uncaught
   exception and not its value, so the driver cannot read the ordinal
   the exception carries: it reports the most recent failure of the run
   and words it as that ("the most recent refusal was"). It is the right
   one unless the transform stored an error and threw it later. For any
   other type, Kiln's rendering.
4. **A failed run has no output** (§2.8). The host is dropped.
5. A host error (`Err` from `Host::call`) is `host-failure` and is a Slip
   bug: the driver also returns it as an error of the worker.
6. Nested evaluations (`kiln-landed-2026-11.md` §3.4 item 3): the driver
   sets a flag for the duration of `Session::run` and the handler it
   gives Kiln refuses any call while the flag is clear. Until Kiln rules
   (`docs/requests/KS2-amendment-1.md` §4), that is the whole defence;
   test it.

## Decided since the package was written (the review of WP-080)

1. **The handler is `Send` at this pin, so the subject is `Sync`.**
   `slip_kiln::session::Handler: Send` stays until Kiln lifts it (its
   WP-2321, not waited for). `Host` holds `&(dyn Subject + Sync)`, and
   `Loaded::run` takes `subject: &(dyn Subject + Sync)`: this package
   makes that change in `slip_script` (`host.rs`, the fake subject, the
   tests), with a compile-time test that `Host` over a `Sync` subject
   is `Send`. `KilnSubject` is `Sync` (`docs/wp/WP-083.md`: it holds the
   AST and the source manager, never the unit's `Oven`).
2. **The target is an input of the transform id** (§2.1 rule 3) and
   §2.2's formula has no term for it: the session's files leave out the
   predefines (virtual buffers). Read the Handback of `docs/wp/WP-080.md`
   "for WP-089" for what a session hands out at the pin, add the term to
   §2.2 and hash it; a test that two targets give two ids.
3. **A run away from the compiling thread can fail "stack exhausted"**
   at this pin and stay failed
   (`docs/requests/KS2-amendment-2.md` §2, Kiln WP-2410). The driver
   classifies it as what it is (a failure of the host, not of the
   transform: `host-failure`, with Kiln's text), and a session that
   reported it is not run again; say in the Handback whether a run of
   the demo transforms reaches it.
4. **A session whose handler panicked is unusable**
   (`slip_kiln::session` returns a defined failure for the next run):
   the driver ends the worker's use of the transform with an internal
   error.
5. `#embed` in a transform, a word beginning with `@`, and a relative
   path are refused by `slip_kiln::session` (`transform-option`,
   `transform-compile`): the driver passes the refusals on; §12 names
   them if it does not.

## Interface

```rust
// crates/slip_script/src/driver.rs
pub struct Loaded<'s> { /* the session, the entry, the id */ }
pub enum LoadError { Option(String), Compile { rendered: String }, Header(resource::HeaderError), Entry(&'static str /* the name of §12 */), Internal(String) }
pub struct Budgets { pub steps: u64, pub bytes: u64, pub depth: u32 }   // Default: §2.5
pub enum Outcome { Completed(output::RunOutput), Failed { kind: &'static str /* §2.8 */, message: String, place: Option<subject::Range>, rendered: String } }
pub struct RunStats { pub steps: u64, pub host_calls: u64, pub peak_bytes: u64, pub wall_ns: u64 }

/// Compiles on the calling thread (which needs `stack` bytes) and calls `f`.
pub fn with_transform<R>(resource: &Path, author: &[String], file: &Path, stack: usize,
                         f: impl FnOnce(Result<Loaded<'_>, LoadError>) -> R) -> R;

impl Loaded<'_> {
    pub fn id(&self) -> slip_model::Digest;
    pub fn files(&self) -> &[slip_kiln::session::ReadFile];
    pub fn run(&mut self, subject: &dyn Subject, budgets: Budgets, cancel: &slip_kiln::session::Cancel) -> Result<(Outcome, RunStats), String>;
}
```

## Tests

- `crates/slip_script/tests/entry.rs`: each error of §12 from a
  transform a few lines long; a transform with two errors gets the first
  of rule 1.
- `crates/slip_script/tests/contexts.rs`: §2.6, each forbidden context,
  in a plain function and in a template; the same failure in each of
  three runs; a call from a nested evaluation (rule 6).
- `crates/slip_script/tests/budgets.rs`: each failure kind of §2.8 with
  the smallest transform that causes it; `slip::error` uncaught gives the
  host's message and the place of the failed call; a caught one does not
  fail the run; after each failure a normal run completes.
- The transform id: equal for equal inputs; differs when one byte of an
  included file changes, when an option changes, when the header's digest
  changes.

All against the fake subject; none needs `KilnSubject`.
