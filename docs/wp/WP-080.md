## Scope

Launch after Slip's Kiln revision is on Kiln main (Kiln WP-2120 with
WP-1990 and WP-1995). `docs/design/notes/kiln-landed-2026-11.md` §3 and
§4 give the Kiln interface with places; read them against the pin first.

`spec/api.md` §2.1 (the command line), §2.2 (the files read), §2.4 rule 5,
§2.5. A facade in `slip_kiln` over Kiln's `with_eval_session`,
`EvalSession`, `RunBudget`, `CancelToken` and `HostCalls`, so that
`slip_script` names no Kiln crate (lint `kiln-boundary`). This package
knows nothing of the API's operations: a handler here is any
`FnMut(op, ints, bytes, out)`.

The first task is a finding, not code: does a handler that borrows
`&kiln::ast::Ast` satisfy `HostCalls: Send`
(`kiln-landed-2026-11.md` §3.4 item 1)? Write the compile test. If it
fails, stop and hand back: `docs/requests/KS1-amendment-1.md` is then on
the critical path and is sent.

## Interface

```rust
// crates/slip_kiln/src/session.rs

/// The command line of spec/api.md §2.1, already checked (rule 2).
pub struct TransformCommand { pub resource_include: PathBuf, pub author: Vec<String>, pub file: PathBuf }

pub enum CompileError {
    /// spec/api.md `transform-compile`; the diagnostics as Kiln renders them.
    Diagnosed { rendered: String, errors: u32 },
    /// Kiln refused the command line Slip built: a Slip bug.
    CommandLine(String),
    Panicked(String),
}

/// One file the transform unit read: path as given, content digest.
pub struct ReadFile { pub path: Vec<u8>, pub digest: slip_model::Digest }

pub struct Budget { pub steps: u64, pub bytes: u64, pub depth: u32 }

/// What a handler writes into (Kiln's `HostOut`, without its type).
pub trait Out {
    fn int_capacity(&self) -> usize;
    fn byte_capacity(&self) -> usize;
    fn write_ints(&mut self, v: &[u64]);
    fn write_bytes(&mut self, v: &[u8]);
}

/// `Err(text)` is Kiln's uncatchable handler error (spec/api.md §3.5 rule 4).
pub trait Handler { fn call(&mut self, op: u32, ints: &[u64], bytes: &[u8], out: &mut dyn Out) -> Result<u64, String>; }

pub enum EntryError { Missing, Overloaded, NotFunction, NotConsteval, Parameters, Type, Undefined }
pub enum RunFailure { NotConstant, StepBudget, MemoryBudget, DepthLimit, Cancelled, Host(String), Uncaught { type_name: String } }
pub struct RunReport { pub result: Result<(), RunFailure>, pub steps: u64, pub host_calls: u64, pub peak_bytes: u64, pub rendered: String }

pub struct Session<'a> { /* yours */ }
impl Session<'_> {
    pub fn files(&self) -> &[ReadFile];
    /// `Ok(true)`: a function of that name exists in the global namespace.
    pub fn declares(&mut self, name: &str) -> bool;
    pub fn entry(&mut self, name: &str) -> Result<Entry, EntryError>;   // `Type` unless it returns void
    pub fn run(&mut self, entry: Entry, handler: &mut dyn Handler, budget: Budget, cancel: &Cancel) -> RunReport;
}

/// Compiles the transform on the calling thread and calls `f` with the
/// session. The caller's thread must have the stack it wants; this
/// installs Kiln's stack guard for it.
pub fn with_transform<R>(cmd: &TransformCommand, stack: usize, f: impl FnOnce(Result<Session<'_>, CompileError>) -> R) -> R;
```

`Session::run` may be called from the thread of a subject unit's front end
(`parse_observer_with`'s closure) while `with_transform`'s thread waits:
`Session` is `Send`. Show it in a test.

## Tests

`crates/slip_kiln/tests/session.rs`:

1. A handler holding `&Ast` of a snippet compiles and runs (or the
   hand-back above).
2. Compile once, run 1000 times with a counting handler: results, steps
   and host-call counts are equal on every run.
3. A session and a subject front end alive at once, on one thread and on
   two: both give the results they give alone.
4. Each `EntryError`; `declares` for a reserved name.
5. Each `RunFailure`, with `rendered` holding the call-stack notes; the
   session runs normally afterwards.
6. `files()` lists `<slip/meta.h>`, `<slip/__intrinsics.h>` and every
   standard header read, each with the digest of the bytes on disk.
7. `__DATE__` and `__TIME__` are the epoch's.
8. An author option outside §2.1 rule 2 never reaches Kiln (it is
   refused when `TransformCommand` is built).

**Item 4, the reproducer.** Not reproduced through an entry. The stack
checks are reached only by an instantiation or a nested evaluation during
the run (`kiln_sema/src/templ/stack.rs:496`, `oven_bridge.rs:635`,
`:739`, `:776`). What was tried: an entry calling a static member of a
class template, the same with a `static_assert` in the member, a virtual
`consteval` override of a class template called through the base, and a
variable template. Each was compiled under a 4 MiB guard on a 64 MiB
thread, then run on a second thread (far outside the guard) and then at
home. Every run completed with no diagnostic, because each template the
entry's body uses is instantiated when the unit is compiled. Kiln's own
test `instantiation_diagnostics_are_reported_by_every_run`
(`kiln_parse/tests/eval_session.rs:399`) instantiates at a run only
because its entry is itself an uninstantiated member (`X::run`), which
§2.3 does not allow a transform. Through Kiln's API directly, with that
entry, it reproduces: test
`k2_known_hole_a_kiln_run_instantiating_away_from_the_compiling_thread`
asserts the hole today (both runs fail with "stack exhausted") and is to
be turned when K2 lands. The hazard stays in the landed file. When
a later operation instantiates during a run (reflection over the
transform's templates), it becomes reachable.

Round 2 mutations, each seen to fail its test: the poison flag not set
(s2), the session check dropped (f7), `@` accepted (b1), relative paths
accepted (t8), NUL accepted (t8), using-shadows not skipped (both t4
tests), every namespace transparent (both t4 tests), the `#embed` hit

**Measured.** The `#embed` scan costs 19 ms on an unoptimised build over
the 164 files (2 MB) of a transform that includes `<vector>` and
`<string>`. The unit's compile takes about 2 s on the same build. A
release build was not made (host rule). Test `session::tests::embed_scan_cost`,
`--ignored --nocapture`.

**Words inside a string or comment.** They are refused: `__has_embed`
anywhere, and `embed` after `#`, `%:` or `*/` on its logical line, so
`// # embed` and `"__has_embed"` are refused (`f1`, `embed_scan`). This
errs towards refusing: a missed directive would put an unlisted resource
in the identity. The scan cannot see `__has_embed` or `embed` built by
`##` or spelled with universal character names (the hazard K3 lifts).

**For Kiln** (requests to send; none is on the critical path):

- **K1. No response-file expansion of a client's argv.**
  `with_eval_session` expands every word beginning with `@`
  (`kiln_driver/src/session.rs:81`, `rsp.rs:15-41`). Slip refuses such
  words; Kiln should let a library client turn expansion off.
  Reproducer: `b1_a_response_file_never_reaches_kiln`, which gives Kiln
  `-std=c++26 -fsyntax-only -fkiln-reproducible-time -I <r> @<dir>/opts.rsp
  <dir>/b1.cpp`, with `opts.rsp` holding `-DSMUGGLED=1 -std=c++20`, and
  sees `#error smuggled` fire.
- **K2. A run uses the stack guard of the thread that compiled the
  unit.** `Sema.inst.guard` is copied when the state is created
  (`kiln_sema/src/templ/mod.rs:613-617`, `stack_guard.rs:71-75`), and
  `stack_exhausted` is sticky (`templ/mod.rs:620`,
  `stack_guard.rs:172-190`). `EvalSession::run` should check against the
  calling thread's guard, installed or given per run, and not leave the
  flag set across runs. Reproducer, at the Kiln level:
  `k2_known_hole_a_kiln_run_instantiating_away_from_the_compiling_thread`.
  It compiles Kiln's pattern (`template <class T> struct W { static
  consteval int run() { return sizeof(T); } }; static_assert(sizeof(W<int>)
  > 0); using X = W<int>;`) through `with_eval_session` under a 4 MiB
  guard, takes `entry_named("X::run")`, runs it on a spawned thread
  ("stack exhausted"), then on the compiling thread (fails again, as the
  flag is sticky). As a control, a first run at home completes, and a run
  away after it then completes too: the template is already instantiated.
- **K3. The consulted resources of a session.** `SessionFrontEnd` lists
  no `#embed` resource and no `__has_embed` probe, so Slip refuses both.
  Wanted: the list of resources read and probed, as for headers, so that
  they can enter `TransformId`.
- **K4. The call stack of an uncaught exception.** The diagnostic has only
  the throw's location. The frames are still intact where the fault is
  raised (`kiln_oven/src/vm/exc.rs:218-220`), so the "in call to" notes
  could be added there (§2.8 rule 3).
- **A public diagnostics renderer** for a run's diagnostics
  (`docs/requests/KS2-amendment-1.md` §3). Today `rendered` goes through
  `TextSink` with default options.
- **`Ast: Sync` asserted in Kiln** (KS1 amendment 1, sent): it holds by
  auto traits only.
