## Scope

`crates/slip_digest/src/decl_func.rs` and, in `local.rs`, the function
`write_decl`. Tables: `spec/digest-kinds.md` §5.4 (`FunctionData`,
`FnSpec`, `FnStorage`, `ConstexprKind`, `Defaulted`, `ParamData`,
`VarData`, `VarSpec`, `VarStorage`, `TlsKind`, `InitStyle`, `VarEval`,
`VarEvalState`, `LetData`), with §2.3 (what is merged over the
declarations of an entity), §2.4 (declarations walked in place) and the
parts of §11.3, §11.4 and §11.9 that say what a unit's own stream
writes for a `demand` row.

The four functions of `decl_func.rs` are *reach stubs* today (the
placeholder, then the children): replace each whole.

`local::write_decl` (the encoding `decl`, §2.4) is written here for
every kind except local types: a variable, parameter, binding or label
writes its ordinal (`local::ordinal`) and then its declaration stream
(`Walk::decl_stream`); a local typedef, alias, using-declaration,
using-directive and empty declaration write nothing; a block-scope
function or variable with linkage writes a `ref`; a local
`static_assert` writes its rows. A local class, enumeration or closure
type stays `s.pending(Area::Local)`: the package for local entities
writes it. A template parameter met by `decl` has no ordinal (§9); see
how `templ::head` writes parameters today and keep that.

The language linkage a function's and a variable's stream holds
("A function's stream also holds its language linkage", `ScopeData`
`aux-lang`) is written here; `keys.rs` already reads it for
`c_linkage` (reuse its reading, do not write a second one).

## Interface

The signatures in `decl_func.rs` and `local.rs` are fixed. Calls into
other areas, all existing: `expr::child_opt` (initialisers, default
arguments), `stmt::child` (bodies), `templ::templ_link` (the `templ`
rows), `value::value` (nothing of §5.4 is written by value in the
unit's own stream if the tables say `demand`: check), `local::ordinal`.

§11.4: in an implicit instantiation `ParamData` `default_arg` writes an
absent child whatever Kiln holds. Whether a function is an implicit
instantiation is what `units.rs` already decides for the unit's class:
find and reuse that reading (make it `pub(crate)` if it is private;
that one-word change in `units.rs` is allowed).

## Tests

Per row, as the common rules say. In particular: each `FnSpec` and
`VarSpec` fact, with the merged ones (`inline`, `constexpr`,
`constinit`) shown both by a `differ` test and by an `equal` test in
which the specifier moves from one declaration of the chain to another;
a function defined on one side and only declared on the other; a
default argument given on a later declaration (equal to giving it on
the first); `ParamData` `original_ty` (array against pointer parameter:
the function's key is the same, its unit differs only if the table says
so); the three `demand` rows of §5.4 with `tests/demand/` pairs
(`VarData` `eval`, `ParamData` `flags-default-arg-pending`, …); a
parameter's name not mattering (`equal`); a block-scope `extern`
declaration (`equal` against the same declaration at namespace scope
where digest §4.3 says so, else `differ`).

Body and initialiser differences are visible only through `stmt` and
`expr`, which are pending: a test whose only difference is inside a
body or an initialiser is marked `# pending` (common rule 5); presence
against absence of a body or initialiser is visible today.

## Rules common to the digest's area packages

Read first, in this order: `docs/AGENTS.md`; `spec/digest.md` (whole);
`spec/digest-kinds.md` §1 and §2, then the sections in Scope; the
documentation at the top of `crates/slip_digest/src/lib.rs` (the
functions every area calls, "How to fill an area");
`spec/landed/digest/WP-024.md`; the Handback of `docs/wp/WP-024.md`.
Look at how `types.rs` and `decl.rs` write their tables before writing
yours.

1. **Files.** You own the files named in Scope and your tests. In
   `crates/slip_digest/src` touch nothing else, with two exceptions: a
   function another area must provide and that has no signature yet is
   added to that area's file as a pending function (final signature,
   body `s.pending(Area::X)`, one line in the handback), never
   implemented; and `lib.rs` gets one line per function you add for
   others, in its table. Do not touch the `Area` enumeration,
   `tables.rs` (generated), `tests/tables/pins.txt`, or the tables of
   `spec/digest-kinds.md`. Several packages run at the same time in
   other files of this crate: a change outside your files conflicts
   with theirs.
2. **The tables decide.** Rows are written in table order as §2.1 says;
   tags and decisions come from `crate::tables`, never from a number
   written by hand; `bit` rows go through `FlagWord`. A set bit or a
   value no row accounts for is `Cause::Unaccounted("<short name>/<row>")`,
   an `unsupported` row `Cause::Unsupported("<short name>/<row>")`; the
   stream stays well formed either way. A row that is wrong about Kiln
   (the field is not stored as the note says, a fact is missing) is not
   corrected in code: write the conservative thing (indeterminate),
   leave the row's test out, and report it with the Kiln `file:line`.
3. **No wildcard** (digest §13 obligation 2): every `match` over a Kiln
   enumeration lists every variant, no `_`, no `..` over variants, no
   `matches!`; a Kiln record or view is destructured without a rest
   pattern, so that a field Kiln adds does not compile.
4. **Properties** (WP-024 "Properties that are not negotiable"):
   determinism (no hash-map order, id, address or interning order in a
   stream); linear work; no panic on any AST Kiln can build (an
   unexpected shape is `Unaccounted`, not `unwrap`, not indexing);
   recursion bounded as `lib.rs` "What bounds the stack" says.
5. **Tests.** Every row of your tables gets the directory §1.5 names
   (`differ`, `equal`, `demand` or `indeterminate`), in the form
   `docs/wp/WP-024.md` "The pair tests" describes; the names leave
   `tests/tables/untested.txt` with `SLIP_BLESS=1 cargo test -p
   slip_digest --test tables`. A `differ` test changes one fact and
   names the unit that must change; choose sources in which the fact is
   visible while the other areas are pending. Where it cannot be (the
   difference is inside what another area still writes as its
   placeholder), write the test anyway and mark it: `expect.txt` gets
   the lines `# pending` and `# needs: <area>` (for an `equal` test, an
   `expect.txt` holding only those two lines); the runner skips it and
   the last area package runs them all. Keep these few and list their
   count by area in the handback. A row marked `unbuilt` needs no test.
   Rows that C++ source cannot reach through Kiln (say why, with the
   Kiln site) stay in `untested.txt` and are listed in the handback.
6. **Tests that can fail.** For every table, break at least one row in
   five on purpose (skip it, swap two, write a constant) and see its
   test fail, and do so for every row whose rule is in prose under a
   table. The handback lists the rows checked this way. Do not leave
   the breakage in.
7. **What the spec left open** goes to
   `spec/landed/digest-kinds/WP-026.md` (a decision per paragraph, the
   conservative one). Unit tests of helpers go in a `#[cfg(test)] mod
   tests` inside your own file, not in `src/tests.rs`.
8. **Gate.** `cargo xtask ci` (the full gate: this crate links Kiln)
   passes with `origin/main` merged in; `cargo test -p slip_digest`
   stays under a minute once built. Expect conflicts in
   `tests/tables/untested.txt` when merging `main`: resolve by taking
   `main`'s file and blessing again.

## Done when

The gate passes; every row of the tables in Scope has its test or is
listed in the handback with the reason; no function of your files
writes `pending` for your own area any more (say which pending calls
into other areas remain); the handback has what `docs/AGENTS.md` rule
12 asks, plus: rows implemented and rows left by table, the mutation
checks of rule 6, tests marked `# pending` by area, the functions added
for other areas, every row reported wrong, and the counters of
`digest.indeterminate` by cause over your own test sources.
