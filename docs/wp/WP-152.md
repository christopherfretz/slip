# WP-152 — rename: what the new name finds at each instance a dependent name was edited on

- Status: done
- Milestone: M2
- Track: C
- Needs: WP-139
- Size: M
- Parallel with: the transform packages that do not edit `crates/slip_refactor`'s rename

## Scope

`docs/wp/WP-139.md` edits a dependent name when every instantiation an
observer made binds it to the renamed entity. It does not ask what the
**new** name finds there (`spec/landed/edits/WP-139.md`, finding 1):

```cpp
template <class T> struct D : T { int g() { return this->f(); } };
int u() { return D<n::S<int>>().g(); }
```

Renaming `n::S::f` to `g` writes `this->g()`, which finds `D::g`. The
run is accepted and then not verified: loud, and late (after the
verify phase), with a reason that names a unit and not the cause.

1. **The check, per instance.** For every instance of a row-2
   `replace` (`spec/edits.md` §9.4), the lookup the instantiation made
   for the old name is made for `new_name` in the same context: the
   class of a member access (`t.f`, `this->f`), the nominated class of
   a qualified name (`T::f`), and for a call found by
   argument-dependent lookup the associated set. If it finds a
   declaration that is not a subject of the rename, the claim is
   `refuse` with a reason of its own (`captured_at_instance`), naming
   the specialisation and the declaration found. Say which of these
   lookups Kiln lets Slip make at this pin (`member_lookup` and its
   successor `using_named`; the per-specialisation table has the
   entity found, not the lookup's context), and which need a request
   to Kiln: those shapes stay accepted and not verified, each with a
   test, and go to "For Kiln" with the Slip need and a source.
2. **The other direction**: a declaration named `new_name` that an
   instantiation would find *instead of* the renamed entity only
   because of the rename is the same check. A declaration named
   `new_name` hidden by the renamed one before and after is not a
   capture: say how the two are told apart.
3. **The non-dependent rule it mirrors.** `spec/edits.md` §9 has the
   capture checks of a written reference (the spelling obligations of
   `spec/verify.md` §10). State in §9.4 which of them an instance
   inherits and which this package adds, so that there is one list.

### Item 2 — Hiding vs capture

- **Class hierarchies (`member_lookup_post`)**: Simulates `[class.member.lookup]` for `new_name` in the **post-image** where every renamed subject in a class `c` carries `new_name`:
  1. If `c`'s own name is `new_name` (injected-class-name, `[class.pre]/2`), or `c` directly declares or introduces (via a non-hidden `UsingShadow`, `ast.shadow_hider(d).is_none()`) any non-subject named `new_name`, lookup stops in `c`'s subobject and records a capture (naming the class or declaration found).
  2. Else if `c` directly declares or introduces any subject named `old_name`, lookup stops in `c`'s subobject without recursing into `c`'s bases (`[class.member.lookup]/2`). A `new_name` declared only in a proper base of `c` is hidden by the renamed entity and is **not** a capture.
  3. Otherwise, recurse into every base of `c` (virtual and non-virtual alike). Virtual-base dominance was removed in fix round 1: any non-subject provider reached through any base counts as a capture and refuses.
- **ADL (`check_adl`)**: Non-functions and `ADL_ONLY` hidden friends of non-associated classes are ignored before and after (`[basic.lookup.argdep]/4`) and are not captures. Non-viable overloads in associated namespaces are deliberately refused (pending Kiln's overload facts).

### Fix round 1

Overall rule: **when the check cannot decide, the rename refuses** (never accept on "found nothing").

1. **Removed virtual-base dominance (`dependent.rs`).** Deleted `is_virtual_base_of` and `via_virtual`. Any non-subject provider reached through any base (virtual or non-virtual) counts as a capture and refuses `captured_at_instance`. Non-virtual direct hiding (`S::f -> g` hiding `Base::g`) stays accepted; virtual diamonds (`wp152_hidden_new_name_is_not_a_capture`) and probes `d1`, `d5`, and direct virtual-base providers (`wp152_virtual_base_providers_refused`) all refuse.
2. **Injected-class-name (`[class.pre]/2`).** `member_lookup_post` checks `ast.decls.get(c).name() == new_dn` for every class on the lookup path and refuses with note `in <spec>: new name '<new>' finds injected-class-name <class>` (`wp152_injected_class_name_refused`, probe `a2`, plus non-matching control).
3. **Unrecovered context and limits fail closed (with one exception).** When `lookup_classes_in_spec` recovers no lookup class (default argument `int x = T::s()` probe `a3`, `using R = decltype(T::s());` in a body probe `a4`, alias templates, requires-clauses, substituted signatures) or when `WALK_LIMIT` or `BASE_DEPTH_LIMIT` is hit, the rename refuses `captured_at_instance` with a note naming the specialisation and cause. **One exception**: if no class in the TU declares/introduces a member named `new_name` and no class in the TU is itself named `new_name` (`tu_has_class_new_name`), no member/qualified lookup can capture `new_name` and the check accepts (`wp152_unrecovered_context_and_limits_refuse`, `rename::dependent::tests::wp152_walk_limit_hit_refuses`).
4. **Both Kiln gaps now fail closed.** Gap 1 (`Member`/`Qualified` unrecovered) is covered by item 3; Gap 2 (`Unqualified`, and the ordinary half of `Adl`/`Both`) walks enclosing scopes from `DependentName::enclosing` (`check_unqualified_enclosing`, checking enclosing classes via `member_lookup_post`, functions via `lookup_local` + `ctx.named.new`, and namespaces/TU via `lookup_local` + `using_directives`, stopping at a scope declaring a subject `old_name` and no non-subject `new_name`). Updated `wp152_kiln_gaps_fail_closed` to assert refusals; kept both "For Kiln" items and updated `spec/edits.md` §9.4 and `spec/landed/edits/WP-152.md`.
5. **Non-viable ADL candidate (`b1`).** Kept the refusal (Slip performs no overload resolution, pending Kiln's overload facts), documented in `spec/edits.md` §9.4, pinned in `wp152_adl_non_viable_candidate_refused` (note names `o::g(int)`).
