## Scope

The two stage commands that need no parse, and the glue between the
Kiln-free crates and the store (`spec/edits.md` §10.2, §10.4, §10.5 for
the lines these commands print, and the exit statuses of their
columns):

```
slip reduce --plan <id or file> --round <n> [--store <dir>] [-j <n>]
slip apply  --result <id> (--write | --patch <file>) [--relative-to <dir>]
            [--allow-residue] [--allow-partial] [--store <dir>]
slip apply  --recover [--store <dir>]
```

Files: new `crates/slip_cli/src/transform/{mod.rs, store.rs, reduce.rs,
apply.rs, lines.rs}`, new `crates/slip_cli/tests/stages.rs`;
`crates/slip_cli/src/args.rs` (the two commands, and the options
`rename` and `check` will share, parsed here once: `--owned`,
`--readonly`, `--allow-*`, `--relative-to`, `--residue-ext`, `--round`,
`--edits`, `--declared`, `--result`), `src/commands.rs` (dispatch),
`src/lib.rs` (the usage text). `args.rs` and `commands.rs` are also
M1's while its commands are open: this package starts when the
supervisor says they are free.

It can be finished before any package that needs Kiln's changes: its
tests publish shards and results written by hand.

## Interface

```rust
// slip_cli::args
pub struct ReduceArgs { pub plan: PlanSource, pub round: u64, pub store: Option<PathBuf>, pub jobs: Option<usize> }
pub enum ApplyAction { Write, Patch(PathBuf), Recover }
pub struct ApplyArgs { pub result: Option<String>, pub action: ApplyAction, pub relative_to: Option<PathBuf>,
                       pub allow_residue: bool, pub allow_partial: bool, pub store: Option<PathBuf> }
pub struct TransformOptions { /* the shared options above, for WP-076 */ }
// Invocation gains Reduce(ReduceArgs), Apply(ApplyArgs)

// slip_cli::transform::store: the Kiln-free crates' traits over a Store
pub struct StoreShards<'a> { /* plan, phase map, round, the selected observers */ }
impl slip_reduce::Shards for StoreShards<'_> { /* … */ }
pub struct StoreBlobs<'a>(pub &'a Store);
impl slip_apply::Blobs for StoreBlobs<'_> { /* … */ }
pub struct StoreJournal<'a>(pub &'a Store);
impl slip_apply::JournalStore for StoreJournal<'_> { /* … */ }
pub struct DiskFiles;
impl slip_apply::Files for DiskFiles { /* … */ }

// slip_cli::transform::reduce
/// Runs reduce over a round and publishes `EDTS` and, if accepted, `DECL`.
pub fn reduce_round(store: &Store, plan_id: Digest, plan: &Plan, round: u64, selected: &[usize], threads: usize)
    -> Result<(Digest, EditSet, Option<(Digest, Declared)>), CommandError>;

// slip_cli::transform::apply
/// §7.2 or §7.3 for a published result; checks `slip_verify::conclude::permits` first.
pub fn apply_result(store: &Store, result_id: Digest, action: &ApplyAction, relative_to: Option<&Path>,
                    allow: Allow, out: &mut dyn Write) -> Result<Applied, CommandError>;
pub enum Applied { Written(u64), Patch(PathBuf), NotPermitted(State), Refused(slip_apply::Refused) }

// slip_cli::transform::lines: the lines of §10.5 that describe an edit set
pub fn edit_set_summary(set_id: Digest, set: &EditSet, declared: Option<(Digest, &Declared)>, out: &mut dyn Write);
pub fn refusal_lines(set: &EditSet, relative_to: Option<&[u8]>, files: &dyn slip_apply::Files, out: &mut dyn Write);
```

`Allow` and `permits` are `slip_verify::conclude`'s
(`docs/wp/WP-070.md`): the command asks, it does not decide.

- `reduce` uses `<store>/tmp` (`Store::scratch_dir`,
  `crates/slip_exec/src/store.rs:389`) for its runs, and `-j` for
  `Options::threads`; the edit set does not depend on either.
- The ownership `apply --write` checks is the transform's (`TRFM`,
  found through the result), never the command line's.
- Lines and columns of refusals are computed from the pre-image file as
  it is on disk if its bytes still have the `FileRef`'s digest; if not,
  the line is printed with the byte range instead (`<path>:@<start>`).
- Status 3 and the message of `spec/edits.md` §10.5 for a store with a
  journal, on every command of this package but `apply --recover`.

## Tests

`crates/slip_cli/tests/stages.rs` (`spec/edits.md` "Tests"), through
the executable over a store the test fills with a plan and shards made
with `slip_model`:

- `reduce`: two observers that agree (the three output lines, status
  0); a contested site (status 1, `state refused`, the refusal line);
  a shard of another transform (status 3); run twice, with `-j 1` and
  `-j 4`: the same ids and the same bytes on standard output;
- `apply --result`: a result of each state against `--write` and
  `--patch`, with and without each `--allow` option (the table of
  `permits`, seen from outside); a written tree equals the post-image;
  the patch applies with `patch -p0`; `--relative-to`; a file changed
  since the result (status 1, tree untouched); a file outside the owned
  set in a result made by hand (refused);
- the journal: a store with one is refused by `reduce` and
  `apply --result` with status 3; `apply --recover` restores a tree
  that a test left half written (using the journal format of
  `slip_apply::journal`) and exits 0; with a file it has to report,
  exits 3 and keeps the journal;
- usage errors: each option without its value, `--write` with
  `--patch`, `--recover` with `--result`.
