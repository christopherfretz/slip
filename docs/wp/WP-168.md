# WP-168 — tests whose assertions are swallowed: a snippet callback's panic discarded

- Status: review
- Milestone: M1
- Track: H
- Needs: none
- Size: M
- Parallel with: every package; tell the supervisor at once which digest tests start failing (see item 3)

## Scope

`slip_kiln::snippet::parse_with` and `preprocess_only`
(`crates/slip_kiln/src/snippet.rs`, about lines 357 and 439) run the
caller's callback under `catch_unwind` and return a panic as
`Err("the callback panicked: …")`. That is right for a library: it is
the caller's to propagate. But
`crates/slip_digest/src/expr_profile_tests.rs` `each_input` (about line
95) does `let _ = slip_kiln::snippet::parse_with(…, |p| { … f(&input) })`:
the `Result` is dropped, so **every assertion made inside an
`each_input` or `each_side` callback can fail without failing its
test**. WP-156's implementer found one on `main`:
`own_spelling::tests::a_list_changes_only_the_units_that_write_one`
passes although the friend content key it checks differs
(`a78b…` against `1d4c…`).

1. **Find every such site**, not only this one: every call in the
   workspace (product code and tests, `crates/*/src` and
   `crates/*/tests`, `xtask`) of a function that returns a callback's
   panic, or any other failure, as a value, where the value is
   discarded (`let _ =`, `.ok()`, an ignored `Result`, `if let Ok` with
   no `else`, a `catch_unwind` whose `Err` is not resumed or asserted).
   At least: `snippet::parse_with`, `snippet::preprocess_only`, the
   other `snippet` entry points, `crates/slip_digest/tests/common/mod.rs`
   (about line 961), `crates/slip_digest/tests/spelling.rs` (about line
   928), `crates/slip_digest/src/trace.rs` (about line 152),
   `crates/slip_kiln/tests/session.rs` (about line 857). For each, say
   whether a failure there is propagated today, and change the ones that
   are not so that it is (`expect`/`unwrap` with the message, or
   `resume_unwind`). A deliberate catch (a test that a panic is caught)
   stays, with a comment saying so.
2. **Keep it so**: a test per helper you change that a failing
   assertion inside its callback fails the test (a `#[should_panic]`
   test, or a run of a tiny case that asserts false). If a lint is
   cheap and reliable (e.g. `let _ = …parse_with(`), add it to
   `cargo xtask lint` in the shape of the existing rules; otherwise say
   why not.
3. **What it exposes — STOP AND REPORT, do not fix the code under
   test.** After item 1, run the affected test binaries. Every test that
   now fails is listed in the handback with: the test, the assertion,
   the two values, and your reading of whether the **test** is wrong
   (an expectation that was never checked and is simply wrong) or the
   **code** is (a defect in `slip_digest`, `slip_kiln` or another crate
   under test). Then:
   - a test that is wrong: fix the test, and say why it is the test;
   - a code defect: **do not change the code under test** (it is the
     trusted base: the digest decides `verified`). Mark the test
     `#[ignore = "WP-168: <one line>"]` so the gate passes, list it, and
     message the supervisor as soon as you have the list (before the
     PR), with the reproductions. The supervisor rules and opens the
     packages.
   Start with `own_spelling::tests::a_list_changes_only_the_units_that_write_one`.
4. Count and report: how many test functions run assertions inside a
   swallowed callback today (before your change), by file.

2. **Token-based `swallowed-result` lint in `xtask` with block-scoped binding tracking.** Uses `xtask/src/lint/rust_tokens.rs` (skipping comments and string literals), tracks unpropagated `let <var> = <call>(...);` bindings within their `{ … }` block, adds `common::digest_side_with` and `common::skip_unparsed` to the target helpers, accepts `if let Ok(…) = … { … } else { non-empty }` (eliminating the false positive while still flagging `else {}` and missing `else`), and catches `.unwrap_or_default()`, `.unwrap_or()`, `.is_ok()`, discarding `.unwrap_or_else()`, `let _name =`, and unguarded discarding `match` arms. `Tree::parse` (`.parse(`) is intentionally not added as a bare method target because `.parse(` is ubiquitous on `&str` and would false-positive; its single swallowing caller (`subject_references.rs:1841`) is fixed and guarded by `wp168_tree_side_propagates_callback_panic`.
3. **`common::skip_unparsed` returns `Result<Option<T>, String>` where `Err` is a panic.** Consequently `if let Ok(r) = common::skip_unparsed(…)` without an `else` WOULD swallow panics; in Fix round 1 we added `common::skip_unparsed` to `swallowed-result`'s target helpers and replaced the misleading accepted case in `xtask/tests/lint.rs` with `if let Some(r) = common::skip_unparsed(common::with_side(…))?` (while pinning `if let Ok(r) = common::skip_unparsed(…)` as rejected).
