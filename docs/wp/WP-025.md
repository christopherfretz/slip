# WP-025 — slip_kiln: the parse task on Kiln's front-end entry

- Status: done
- Milestone: M1
- Track: B
- Needs: WP-020, WP-021
- Size: M
- Parallel with: WP-024

## Scope

Until now the parse task ran `kiln_driver::run_as` as a black box and
read what it wrote: a dependency file for the inputs, JSON on standard
error for the diagnostics, and then every input a second time for its
digest (`spec/model.md` §8.4, `docs/requests/KF1-front-end-entry.md`).
Kiln's `kiln_driver::front_end::run_front_end` (WP-020; read
`kiln/crates/kiln_driver/src/front_end.rs` and the section "Front-end
library entry" of `kiln/spec/driver.md`) calls a closure over the
finished front end instead. This package moves the parse task onto it:

1. no dependency file, no scratch file, no JSON, no second read of a
   file the front end read;
2. the counter `pp.tokens`;
3. a second entry, `parse_observer_with`, whose closure sees the
   finished unit: the production entry of the semantic digest (the
   worker composes it with `slip_digest` in a later package; here only
   a test uses it);
4. `KilnCheck` checks the command line the parse now gives Kiln.

It changes `spec/model.md` §8.4 and `spec/cdb.md` §6.1 and §6.2: the
rules below replace the text there. **Rewrite those sections in this
package** to say exactly what the code does (the supervisor reviews the
text with the diff); everything else the spec left open goes to
`spec/landed/model/WP-025.md` as usual.

## Interface

```rust
// slip_kiln
/// The finished front end of one observer. Its methods name Kiln's
/// types: only the crates that may name `slip_kiln::kiln` call them
/// (`slip_digest`, `slip_script`); any crate may pass a `&Unit` on.
pub struct Unit<'r> { /* … */ }
impl<'r> Unit<'r> {
    pub fn ast(&self) -> &'r kiln::ast::Ast;
    pub fn sm(&self) -> &'r kiln::source::SourceManager;
    pub fn oven(&self) -> &'r kiln::oven::Oven;
    pub fn main_file(&self) -> Option<kiln::source::FileId>;
    /// For a buffer that is one of the shard's `inputs`: that entry's
    /// `path` (the real path). `None` for any other buffer.
    pub fn real_path(&self, file: kiln::source::FileId) -> Option<&'r [u8]>;
    /// Errors reported so far (the job's engine).
    pub fn errors(&self) -> u32;
}

/// Parses `observer`'s command with Kiln's front end in this process;
/// when a parse happened, calls `f` on the finished unit (with errors
/// or without) before anything is dropped. Returns the shard for
/// `phase` and `round` and `f`'s result (`None`: no parse happened).
pub fn parse_observer_with<R: Send>(
    observer: &Observer, phase: Phase, round: u64,
    f: impl FnOnce(&Unit<'_>) -> R + Send,
) -> Result<(Shard, Option<R>), String>;

/// `parse_observer_with` with a closure that does nothing.
pub fn parse_observer(observer: &Observer, phase: Phase, round: u64) -> Result<Shard, String>;
```

`ParseOptions` and its `scratch` go (the worker in `slip_cli` no longer
asks the store for a scratch directory for this; `Store::scratch_dir`
stays). If `Unit` needs the engine's lifetime as a second parameter,
add it and say so. `kiln::…` in these signatures is this crate's own
module.

## Rules

**The run.** The command line given to `run_front_end` is `argv[0]
-fsyntax-only argv[1..]` (`argv[0]` replaced by `kiln` for a scanner
name, as today), `FrontEndOptions::default()` with `own_thread` true
and no `stderr`. The current directory is still set to the command's
`directory` first and not restored (Kiln has no working-directory
parameter yet). `Command.env` is still not applied.

**Outcome**, from the `FrontEndReport`:

- `errors`, `warnings`: the report's.
- `ok`: `errors` is 0 and a parse happened. No parse and no error is
  `Err` ("the front end did not parse and reported no error").
- Otherwise `rejected` if the first error's id is a driver diagnostic
  (`DiagId::name()` starts with `drv_`), else `diagnosed`. `message` is
  the first error as `<file>:<line>:<col>: <message>` from
  `FirstError.at` and `.message`, `<message>` alone without a position;
  clipped as today.
- `FrontEndError::NotSyntaxOnly` and `NotOneInput`: `rejected`, one
  error, the message the error displays. A command that is not UTF-8:
  as today.
- `FrontEndError::Panicked(text)`: `Err("the front end panicked:
  <text>")`, as today (the worker answers `Failed`; the coordinator
  retries once). `Thread`: `Err`.

**Inputs.** Present exactly when a parse happened (so also for a
`diagnosed` unit whose `#include` was not found: this is new). The
list is:

- every buffer of the source manager whose origin is `Disk`
  (`SourceManager::file_ids`, `file_origin`): size and content digest
  from `original_bytes`, never from a second read;
- every `consulted` path that is not such a buffer (an `#embed`
  resource, a `__has_embed` hit): read here, once, for size and digest;
  failing that is `Err`;
- a `Lazy` buffer: listed from `original_bytes` when it has them, left
  out when it has none (it can only come from a module image or a PCH;
  say in the landed file what Kiln's `-MD` listed for it).

Each name is resolved against `Command.directory` and to its real path
(failing that is `Err`); the list is sorted by path bytes and unique.
Two buffers with one real path and different bytes is `Err` (it means
the file changed during the parse). The content of this list for a
unit that the old code gave inputs for must be **the same list**: see
the parity test.

**Counters.** `inputs.bytes`, `inputs.files`, and `pp.tokens`
(`FrontEnd.tokens`), when a parse happened; none otherwise. After a
fatal error `pp.tokens` is what Kiln counts (the tokens before it and
the one returned with it).

**`KilnCheck`** parses `argv[0] -fsyntax-only argv[1..]`. Rejection 3
of `spec/cdb.md` §6.2 becomes: what `run_front_end` refuses without
running (its `structural_checks`: an action other than
`-fsyntax-only`, `--help`, the print and dump probes, `-M`/`-MM`, an
unbuilt header unit) and what it refuses with
`drv_front_end_unsupported` when written on the command line
(`-verify`, `-include-pch`): `UnsupportedFlag` with the argument, as
the existing rule words it. Decide from Kiln's public `Args` fields;
do not call a private function of Kiln and do not copy one's body
beyond the conditions themselves. The command's own `-MD`, `-MF`,
`-MT`, `-o` and `-fdiagnostics-format=` no longer matter: the entry
writes nothing and renders nothing. The other rejections stand.
A check and a parse must agree: a command `KilnCheck` accepts is never
`rejected` by the parse for a reason of rejection 3 (test).

**Removed**: `diags.rs` (the JSON reader), the dependency-file
arguments and `DEP_TARGET`. `depfile.rs` and the old flow
(`run_as` with `-MD` and JSON) move, as small as they can be made, to
`crates/slip_kiln/tests/support/` as the oracle of the parity test.

## Tests

`crates/slip_kiln/tests/parse.rs`, rewritten against the rules above
(each test names its paragraph of §8.4), keeping every case the file
has today that still applies, plus:

- **parity**: for each fixture, the shard of `parse_observer` equals
  the one the oracle computes the old way, field for field except the
  counter `pp.tokens` and the documented differences (inputs of a
  `diagnosed` unit with a missing include). Fixtures: two headers, one
  guarded and one `#pragma once`, each included twice; a header reached
  through a symbolic link and through `..`; `__has_include` of a file
  not included and of a missing one; `#embed` and `__has_embed`;
  `-include` of a file; a header holding invalid UTF-8 and one with a
  byte-order mark; warnings (`-Wall` on an unused variable) and
  `-Werror`; an error in a header (position in `message`); a fatal
  missing include; `-ferror-limit=1` with three errors; an unknown
  `-std=` (`rejected`); a missing main file (`rejected`: two driver
  errors, as `kiln` prints);
- `pp.tokens` equal to a count made by hand, and equal on a second
  run;
- `parse_observer_with`: the closure finds a function by name in
  `unit.ast()`; `real_path` of the main file and of a header are their
  entries in `inputs`, and of the predefines buffer is `None`; the
  closure runs for a `diagnosed` unit and not for a `rejected` one; a
  closure that panics is `Err` and the next call works;
- an `#embed` resource deleted before the parse ends cannot be shown
  simply: instead, a resource that is a directory or unreadable is
  `Err`;
- no file is created anywhere: the fixture directory holds the same
  entries after the parse as before (with `-MD -MF x.d -o x.o` in the
  command);
- `tests/check.rs`: rejection 3 as rewritten, each case; and the
  agreement of check and parse over every fixture command of both
  files.

`crates/slip_cli`: the worker's tests and the end-to-end tests pass
unchanged except where they named the scratch directory or expected no
`inputs` for a missing include.

## Out of scope

Calling `slip_digest` from the worker and writing the `digests`
section (after WP-024). A front-end panic without a retry and without
a fresh worker process (it needs a field in the worker protocol:
`spec/exec.md` "Open questions"; add the question there). A working
directory or an environment passed to Kiln instead of the process's.
The snippet front end (`slip_kiln::snippet`), except what the new pin
breaks in it. Modules and PCH as inputs.

Decided at handback:

- **Standard input in rejection 3**: accepted (the entry refuses it as
  `NotOneInput`; the check must agree with the parse).
- **`-S`, `--precompile` and `-c` are accepted by the check**: correct,
  `-fsyntax-only` first wins in Kiln as in clang, and a database of
  `-c` commands is the normal case.
- **The message under `-Werror` ends in ` [<option>]`**: accepted. The
  message is for people; nothing compares it across tools. The LLVM
  baseline is recorded again anyway.
- **Inputs of a `diagnosed` unit with a missing include**: wanted (a
  repaired include path must invalidate that shard).
- **The PCH probe** (`-include h` with `h.pch` beside it: accepted by
  the check, `rejected` by the parse): left. The unit is reported, not
  lost; it goes away when PCH is in scope or when Kiln's entry takes
  "no PCH probe" as an option. Added to the KF1 list below.
- **Lazy buffers have no test**: until modules or PCH are in scope
  (their package writes it).
- **`refusing_argument` parses the command once per argument**: left;
  it runs only for a rejected command, once per entry.
- **A panic costs a retry and no fresh worker**: the open question is
  in `spec/exec.md`; it is a protocol package of track A, not urgent
  while Kiln panics on no unit of the corpus.
- **Asked of Kiln next, on the entry** (appended to
  `docs/requests/KF1-front-end-entry.md`): the bytes or the digest of
  each consulted file (removes `read_consulted`, the second read and
  its race), a working directory and an environment as parameters
  (removes `set_current_dir`, which is what forces one parse at a time
