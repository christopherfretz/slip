# WP-010 — slip_kiln: front-end check and the parse task

- Status: in-progress
- Milestone: M0
- Track: B
- Needs: WP-003
- Size: M

## Scope

`crates/slip_kiln`: the Kiln-backed `FrontEndCheck` (`spec/cdb.md` §6) and
the function that parses one observer and returns its shard
(`spec/model.md` §8), which `slip_cli` wraps as the parse `Task`
(`spec/exec.md` §5.1). M0 reaches Kiln only through `kiln_driver`'s public
API (`args::Args::parse_as`, `run_as`, `Io`); nothing in the `kiln`
submodule is edited. Where that API is not enough, say exactly what is
missing in the handback: it becomes part of request KF1
(`docs/design/05-kiln-interface.md`).

`slip_kiln` gains the dependency `slip_cdb` (for the trait). It does not
depend on `slip_exec`.

## Interface

```rust
pub fn kiln_version() -> &'static str;                         // exists

pub struct KilnCheck;
impl slip_cdb::check::FrontEndCheck for KilnCheck { … }        // spec/cdb.md §6

pub struct ParseOptions { pub scratch: PathBuf }               // a directory for temporary files, unique to the caller
pub fn parse_observer(observer: &Observer, phase: Phase, round: u64, options: &ParseOptions) -> Result<Shard, String>;
```

**`KilnCheck`.** Kiln's own command-line parser decides. Parse
`command.argv[1..]` plus the action `-fsyntax-only` as the program
`command.argv[0]`. An argument Kiln reports as an error is
`UnsupportedFlag` with that argument as detail (the first one). The
language is the one Kiln will compile the input as (`-x`, driver mode,
extension: Kiln's rules, not `ByExtension`'s); a language Kiln does not
compile is `UnsupportedLanguage`. The check reads no file and runs no
compilation.

**`parse_observer`.** Runs the front end in this process on the observer's
command with `-fsyntax-only`, in the command's `directory`, with output
captured, and returns:

- `header`: the observer's id, `phase`, `round`.
- `outcome`: `ok` if the front end finished with no error; `diagnosed` with
  the error and warning counts and the first error's text otherwise;
  `rejected` if the driver refused the command line. Captured output is
  bounded: count while streaming, keep only what `message` needs.
- `inputs`: every file the front end read, the main file included, as
  `FileRef`s (real path, size, content digest), sorted by path, no
  duplicates. Use Kiln's dependency output (`-MD -MF <scratch>/…`), which
  includes system headers; remove the file afterwards.
- `counters`, sorted by name: `inputs.files`, `inputs.bytes`, and
  `pp.tokens` if Kiln's public API can report it deterministically (if it
  cannot, leave it out and say so).

`Err` is only for a failure of the worker itself (the scratch directory
cannot be written, the directory cannot be entered). The same observer and
the same files give the same `Shard`, byte for byte once encoded.

Kiln has no `-working-directory`, so entering the directory changes the
process's current directory. That is correct in a worker (one job at a
time) and a hazard in a test binary: document it on the function, restore
nothing, and make the tests that call it serialise on one lock.

## Tests

`crates/slip_kiln/tests/check.rs`: C and C++ by extension and by driver name
(`cc`, `c++`, `gcc`, `g++`, `clang`, `clang++`, versioned names); `-x`;
a real LLVM-shaped command accepted; an unknown flag refused with the flag
as detail; an Objective-C input refused; agreement with `ByExtension` on a
table of ordinary commands.

`crates/slip_kiln/tests/parse.rs`, with fixtures written to a temporary
directory: a clean translation unit (`ok`, zero errors); one with an error
(`diagnosed`, the count, the message); warnings counted; a relative include
found through `-I` relative to the command's directory; `inputs` holds the
main file and each header once, by real path, with the right sizes and
digests; a header reached through a symbolic link appears under its real
path; determinism (two runs, equal shards); a C translation unit; a command
Kiln refuses (`rejected`). Fixtures are self-contained (no system headers),
except one test that includes `<cstddef>` and reports itself skipped, with
the reason, when no standard library is found.

## Done when

`cargo xtask ci` (the full gate: this crate links Kiln) passes. The first
build of Kiln takes several minutes and goes through the jobserver: start
it in the background and do not set `-j`. No third-party dependency added.

Handback additionally reports: what Kiln does with each compiler name in
`argv[0]`; how diagnostics were counted (structured, or by reading text);
which counters were available; peak memory and time of parsing one
ordinary translation unit.

## Out of scope

`slip_cli` (WP-012). Any use of Kiln's AST. Changes to Kiln.
