# WP-172 — the owned code already in the target namespace, enumerated at scale

## Scope

WP-144's ruling (`docs/wp/WP-144.md`, "Design ruling on item 1") lets a
`DECL` list the owned entities that were in the target namespace before
the edit (`Declared.existing`, `existing_local`), and leaves the making
of that list at scale to a package of its own (its limit 7). This is
the package. The list is made from the pre-image map shards, by the map
phase that already runs, with no second parse:

- each map job that is given the run's files writes, per owned file,
  **the owned list** of that file: the namespaces opened in it and the
  entities keyed under them, with their pre-image keys. A list is a
  content-addressed blob, written once however many observers include
  the file; the shard names its lists (a new section, 35);
- **the enumeration**, a pure function of the union of the lists and a
  rule table, gives the two lists of the ruling's format, unchanged;
- `slip declare` runs the enumeration for a new line, `enumerate`, and
  a person amends its answer with two more lines, by entity, never by
  text pattern.

Nothing here is in the comparison: the list stays a declared change,
and a wrong entry in either direction is a finding (Design notes, "What
a wrong list does"). The walk's part must be inert.

Two stages; each merges alone; **stop after stage 1** for the
supervisor's corpus figures (item 6).

**Probes, before anything is built. Each is a STOP if it fails: report
and wait.**

- P1. Under the empty table, `Options::read_only` given as the run's
  files (`ReadOnly` of a `ReadOnlyFiles`) and not `EVERY_FILE` changes
  no byte of `Output` (`records::facts` relies on this today, by
  reading). Run `tests/inert.rs` and the map-task tests both ways.
- P2. Under the empty table the walk can say, of every entity it keyed,
  the namespace declaration its key is keyed under, by the same
  function WP-144 2a's `existing(e)` uses for "its key's parent is a
  namespace" (`OwnedState::ns_parents` is filled only under rules, by
  reading). If 2a did not leave one function for both, make it one in
  this package and say so; do not write a second.
- P3. For each fixture of `crates/slip_digest/tests/rules/existing/`
  whose `existing.txt` is right (item 9 says which), the key the
  pre-image's walk memoised for a listed entity is the key
  `existing.txt` resolves to. The ruling says so (amendment 2, last
  bullet); this is the run that confirms it.
- P4. Whether a shard's one section can be read without reading the
  file (`Store::read_shard` reads it whole, by reading). Report the
  answer and the time to read section 35 of every shard of the corpus
  run of item 6; nothing is built for it here.

If a probe shows a fact Kiln does not keep, it goes under "For Kiln"
in the handback with the Slip need, and the package stops there. No
Slip-side substitute.

### Stage 1: the lists (inert; `slip_model`, `slip_digest`, the map task)

1. **The owned lists of one observer** (`crates/slip_digest/src/
   owned_lists.rs`, formed last in `walk::run_kept`, after `own_lists`,
   with `Walk::bytes` and every counter put back, as `own_lists.rs`
   does). Asked for by a new `Options::owned_lists: bool`; the table is
   empty and `read_only` is the run's files. With it false nothing is
   read and no byte changes.

   A **candidate** is an entity `e` with a memoised key
   (`KeyRes::Key`) such that
   - its key's parent is a namespace (P2's function: what WP-144's
     `existing(e)` is asked of): not a class member, not a
     specialisation, not a member of an instantiation, not a part, not
     an entity with C language linkage, not a member of the global
     namespace;
   - it is not a namespace;
   - it is owned: `Walk::owned(e)` under the run's files, asked as
     `records::facts` asks it (`owned_state.query`).

   A candidate is **program-wide** or **local** by WP-144's one
   predicate (2a exports it from `own_lists.rs`; it is not written a
   third time). An entity whose key cannot be formed has no entry and
   is counted.

   - A program-wide candidate has one entry, in the list of the file of
     its first declaration that lies in a file (`Walk::located` of
     `Walk::representative`, as a `made` entry's place).
   - A local candidate has one entry **in the list of each file a
     declaration of it lies in** (the file of the declaration's
     expansion location, the function 2a's `existing(e)` reads for
     `file(d)`: one function). If a declaration of it lies in no file
     it has no entry at all (2a: such an entity is never existing).
   - A **space** is a namespace, written by its `Key` under no rule. A
     file's list has a space for each namespace with an owned opening
     in the file (a declaration of the namespace's chain that lies in
     the file and of which `Walk::in_owned_file` holds), for each
     namespace an entry of the file is keyed under, and for every
     namespace around one of those (the list is closed under parents).
     `opened` says which of the three it is: an owned opening lies in
     this file. A space with no entry is written: the enumeration needs
     the tree.

   ```
   OwnedList := format: uv            1
                scheme: uv            `digests::SCHEME`: the key space the keys are in
                file:   bytes         subject path
                spaces: list<Space>   strictly ascending by the id of `space`
   Space     := space:  Key           kind `namespace`; its parent is `root` or a space of this list
                opened: bool
                wide:   list<Entry>   program-wide candidates; strictly ascending by key
                local:  list<Entry>   local candidates with a declaration in this file; strictly ascending by key
   Entry     := key: KeyId, line: uv, column: uv, name: str
   ```

   `line`, `column` are the declaration's (for a local entry, its first
   declaration in this file); `name` is `names::entity_name`. Two
   candidates of one key in one list are one entry, the least `(line,
   column, name)`. A list with no space is not written.

2. **The record** (`crates/slip_model/src/owned_lists.rs`,
   `spec/model.md` §8). The list's encoding above with its reader rows
   (each strictly-ascending rule; `format` 1; a space whose kind is not
   `namespace`; a parent that is neither `root` nor a space of the

   path), golden bytes, and decode(encode(x)) as a property test. And
   **section 35, `owned_lists`**, of a shard of phase `map`, status
   `ok`:

   ```
   OwnedLists := files: digest         content id of the encoded `Ownership` the lists were formed under (item 3)
                 lists: list<digest>   strictly ascending; each the content id of an `OwnedList` blob
   ```

   A critical id, added as 28 to 34 were (no change of the shard's
   version). In a shard of phase `verify`, or one whose status is not
   `ok`: `Malformed` at the payload's first byte. Present **exactly
   when the job carried the run's files**; an observer with no
   candidate has the section with `lists` empty, so that an absent
   section never reads as "nothing owned here". (34 is WP-144's
   `existing_use`. `docs/wp/WP-150.md` still says "section 32", which
   WP-139 took for `edits`; that package needs an id of its own.)

   - `Job` gains `files: opt<digest>` after `post`: the content id of a

     With `--owned` the command publishes the blob and every job
     carries its id. Without it nothing changes: no section, no blob,
     the shard's bytes as today.
   - The map task with `files`: reads the blob (missing, not hashing to

     it. No collector is built.

### Stage 2: the enumeration and `slip declare`

7. **The enumeration** (`crates/slip_reduce/src/existing.rs`; pure: it
   is given decoded lists and a `RuleTable`, and does no I/O). Let `T`
   be the union of the spaces of the lists it is given, by the id of
   `space`, `opened` the disjunction. For `n` in `T`:

   - `m(n)`: `n`'s key with its parent replaced by `m` of its parent
     (`root` is itself), then `RuleTable::map`: the key `n` has in the
     owned view when nothing is listed.
   - `moved(n)`: the id of `m(n)` is not `n`'s. `matched(n)`:
     `RuleTable::map` changed that level.
   - `under(n)`: `n` and every space of `T` whose chain of parents
     passes through `n`.

   The **state** of `n`, parents first:

   | State | When, the first that holds |
   |---|---|
   | `plain` | not `moved(n)` |
   | `unlisted` | `n`, or a space around it, is named by an `unlisted` line (item 8) |
   | `covered` | its parent is `whole` or `covered` |
   | `whole` | all of W1 to W6 below |
   | `members` | otherwise |

   - W1. `n` is named (not the unnamed namespace) and `opened`.
   - W2. Not `matched(n)`: a namespace a rule matches is the target
     itself, and listing it whole says nothing moves (2b refuses the
     line; so does this).
   - W3. **No space of `T` has the id of `m(n)`.** This is "a
     namespace that both roots had" (amendment 4): with `relocate
     legacy => :: acme`, `acme::detail` is whole only if no selected
     observer's owned code opens, or keys an entity under,
     `legacy::detail`. A `legacy::detail` that only dependencies open
     is in no list and does not prevent it: nothing owned moves from
     it.
   - W4. No rule of the table has a `parent` or a `to_parent` that is
     `unit(x)` with `x` the id of `d` or of `m(d)`, for `d` in
     `under(n)`: nothing is declared to arrive in, or to leave, the
     namespace or one below it.
   - W5. `n` is not named by a `members` line (item 8).
   - W6. The caller did not ask for members only.

   **What it gives.** For a `whole` space: its key's id, in `existing`.
   For a `members` space: each `wide` entry's key, in `existing`; each
   `local` entry's key with the list's `file`, in `existing_local`;
   except a key that a rule of the table produces (the id of
   `(to_parent, kind, to_name, disc)`: the ruling's limit 1; such an
   entity verifies only when it is not listed) and a key named by an
   `unlisted` line. For every other state, nothing. Then the union
   with the entries the text's `existing` lines gave (2b), in the
   **normal form**: a key or `(key, file)` entry whose space is under a
   whole entry of the result is dropped (2a would report it as never
   matched), and a namespace an `existing` line lists whole is `whole`
   before the states are computed. Both lists strictly ascending, as
   the `DECL` requires.

   Errors, each naming a list's id and, where there is one, the space:
   a list whose `scheme` is not `digests::SCHEME`; a space whose parent
   is in no list (cannot be, by the reader's row; checked again on the
   union); two spaces of one id with different keys.

   Two passes, for memory: the first folds the spaces of every list
   into `T` (order-free: a union); the states are computed; the second
   reads the lists again and keeps what the states select. The caller
   does the I/O and may run either pass on threads; the answer is a
   function of the **set** of lists and the table. What is held is
   counted and returned beside the answer, as `Reduced::peak` is
   (`spec/edits.md` §5.6): `lists` (distinct ids), `spaces`, `entries`
   kept.

8. **`slip declare`** (`crates/slip_cli/src/declare.rs`,
   `spec/verify.md` §2.3, `spec/exec.md` §8.8). Three lines:

   ```
   enumerate                 every owned entity of the map shards that a rule of this file would rename is existing
   members  <entity>         a namespace: it is not listed whole by `enumerate`; its members are
   unlisted <entity>         an entity, or a namespace with all it holds: `enumerate` does not list it
   ```

   - `enumerate` takes nothing after the keyword and is given at most
     once (`Duplicate`). `members` and `unlisted` are resolved in the
     pre-images with no rules, as `changed` is; without an `enumerate`
     line they are `Syntax` (`members without enumerate`). `members`
     of an entity that is not a namespace is `Refused`. A text with
     `enumerate` and no `relocate` line that gives a namespace rule is
     `Refused` (`enumerate without a namespace rule`).
   - With `enumerate`, the command reads, for **every observer of the
     plan** (not the selection: `--only` and `--limit` choose what is
     parsed here to resolve names, and the list is the run's), the map
     shard of round 0 from the store. An observer with no shard, or
     one that is not `ok`, contributes nothing and is counted. An `ok`
     shard with no section 35 is an input error: `slip: declare: the
     map shard of <main file> has no owned lists; run slip parse with
     --owned`. A section whose `files` is not the id of this command's
     `--owned`, `--readonly` and `--rebuilt` is an input error naming
     both ids. A list that is missing, does not hash to its id or does
     not decode is an input error naming the list and the first
     observer, in plan order, that names it. **In every one of these
     nothing is written**: a shorter list is never the answer to
     missing data.
   - Shards are read on as many threads as CPU tokens can be had
     without waiting, as `plan` takes them (`spec/exec.md` §8.1); the
     distinct list ids are collected; item 7's two passes read each
     distinct list once per pass.
   - Standard output gains, after `kept <n>`: `existing <n>`,
     `existing_local <n>` (2b may already print them; then unchanged)
     and, with `enumerate`, `enumerated <whole> <keys> <local> from
     <lists> lists of <observers> observers, <skipped> without an ok
     map shard`.
   - **`--existing-list <file>`**: what a person reviews. One line per
     entry of the result, sorted by `(name, key)`, written beside the
     file and renamed: `whole <key, 16 hex> <name> <spaces under it>
     <entries under it>`, `entity <key> <name> <file>:<line>:<column>`,
     `local <key> <name> @ <file>:<line>:<column>`, and for each
     amendment that changed the answer `unlisted <key> <name>`; first
     a line `source <map run> files <files id> observers <n> lists
     <n>`. The names are the lists' (a namespace's is made from its
     key's chain). An entry an `existing` line gave and no list holds
     is `given <key> <name>`.
   - **Staleness.** The list is right for the map shards it was read
     from, and `slip verify` compares against the map shards the store
     has when it runs. With `enumerate` the command publishes
     `<store>/existing/<declared id>` (the store is opened shared; a
     publish like any other): the content id of the plan's latest map
     run record, the `files` id, and the counts. `slip verify`, after
     it has read the declared file and asked for the latest map run:
     if the record of this `DECL`'s id exists and names another map
     run, an input error (status 3) before any job starts: `slip:
     verify: the existing entries of <file> were enumerated from map
     run <a>; the plan's latest map run is <b>; run slip declare
     again`. A `DECL` with existing entries and no record is run as it
     is (a list written by hand is a declaration like any other). A
     stale list that does run fails closed (Design notes).
   - `spec/exec.md` §8.8's "no shard is read or written" becomes "no
     shard is written, and none is read without an `enumerate` line".

## Interface

What this package needs of WP-144, exactly:

- **2a, for stage 1:** the one predicate "program-wide or local"
  shared with `own_lists.rs`, callable from another module of
  `slip_digest`; the one function for "the namespace an entity's key
  is keyed under" and the one for a declaration's file (`file(d)`).
- **2a, for stage 2:** `Declared.existing`, `existing_local`,
  `ExistingLocal`, `DECL` version 4 and its reader, `rules_id` version
  4; the harness's `existing.txt` and the fixtures of
  `tests/rules/existing/`; the verify job's passing of the lists;
  section 34.
- **2b, for stage 2:** the `existing` line and its resolution (the
  enumeration's union takes its entries).

The ruling's format is written as it stands: no field of `Declared`,
of the `DECL` or of `rules_id` changes.

```rust
// slip_digest
pub struct Options<'a> { /* … */ pub owned_lists: bool }
pub struct Output { /* … */ pub owned_lists: Vec<slip_model::owned_lists::OwnedList> }   // sorted by file

// slip_model::owned_lists
pub struct OwnedList { pub scheme: u64, pub file: Vec<u8>, pub spaces: Vec<Space> }
pub struct Space { pub space: Key, pub opened: bool, pub wide: Vec<Entry>, pub local: Vec<Entry> }
pub struct Entry { pub key: Digest, pub line: u64, pub column: u64, pub name: String }
pub fn encode(list: &OwnedList) -> Vec<u8>;
pub fn decode(bytes: &[u8]) -> Result<OwnedList, Error>;

// slip_reduce::existing
pub struct Amend<'a> {
    pub given: &'a [Digest], pub given_local: &'a [ExistingLocal],   // the `existing` lines
    pub members: &'a [Digest], pub unlisted: &'a [Digest],
    pub members_only: bool,
}
pub struct Spaces { /* T */ }
impl Spaces {
    pub fn add(&mut self, id: &Digest, list: &OwnedList) -> Result<(), Error>;   // pass 1; any order
    pub fn merge(&mut self, other: Spaces) -> Result<(), Error>;
    pub fn decide(self, rules: &RuleTable, amend: &Amend<'_>) -> Result<Decided, Error>;
}
impl Decided {
    pub fn select(&self, list: &OwnedList, out: &mut Selected);                  // pass 2; any order
    pub fn finish(self, parts: Vec<Selected>) -> Enumerated;                     // sorted, normal form
}
pub struct Enumerated {
    pub existing: Vec<Digest>, pub existing_local: Vec<ExistingLocal>,
    pub review: Vec<ReviewLine>, pub peak: Peak,
}
```

## Design notes

### Who makes the list: the three ways compared

`N` = 10^5 observers; `E` = the owned entities keyed under a namespace,
10^6 to 10^7 at the operator's scale; an observer reads about 10^3
owned files with a candidate; `v` = distinct contents of one file's
list over the run (conditional compilation), 1.2 to 2 by WP-146's
guess, measured in item 6. A key is 32 bytes.

| | (a) lists from the map phase, united (chosen) | (b) `slip declare` parses the database | (c) the verifier finds it, no list |
|---|---|---|---|
| parses | none beyond the map phase | `N` more, every time the text changes: the map phase's cost again (hours on the large machine) | none, if per observer; else as (a) |
| bytes | section 35: 32 B per owned file, about 32 KB per observer, 3.2 GB over the run (`inputs` is about 20 GB). Blobs: `E` x (40 B + the name, about 45 B) x `v`: 0.1 to 2.5 GB, 10^5 to 10^6 objects | none stored; the same lists in memory or in `tmp/` | per observer: none. Run-wide: the pre-image's keys must reach every job, which is (a)'s list unwritten, or unit lists in the shards (WP-144 measured about 160 GB) |
| peak per worker | the observer's lists, under 10 MB beside a parse of gigabytes; milliseconds | a parse | unchanged |
| the uniting step | one process: the distinct ids (about 80 B each: 80 MB at 10^6), the spaces (about 150 B each: 15 MB at 10^5), the result twice (below); 300 MB at the largest. Reads 3.2 GB of sections (20 GB of shards until one section can be read alone, P4) and the blobs twice | the same | none, or the same |
| parallelism | emission: the map phase's own. Uniting: both passes over threads, a union, order-free | needs the pool (`slip declare` parses at most 64 observers, in turn, in its own process) | the verify phase's own |
| fails closed | a shard without the section, a section of other files, a missing or damaged list, another key scheme: nothing is written. A stale list: refused before the run by the store's record, and a finding without it | an observer that does not parse contributes nothing and the list is short: a finding in that observer's includers | per observer it does **not**: it is the ruling's option B, attack B1a (a wrong `verified`) |
| the same pre-image | by construction: the lists are in the shards the verify job compares against | not tied: the files may have changed since `slip parse` (the drift guard O2 exists for) | by construction |

(c) per observer is rejected by the ruling. (c) run-wide is (a) with
the list kept out of the `DECL`: the verify shard's `binding` and
`rules_id` would then not cover what the keys were formed with, and
nobody could review or amend it. (b) pays the map phase twice, more
than once (the text is iterated on), and is the only one whose list is
not tied to the shards. (a).

**Why every owned candidate, and not only those of the target
namespace.** The worker cannot know the target. Under `slip parse`
there is no rule yet. Under a transform the rules of the run are the
union over observers, and the observer that most needs to speak has
none of its own: a translation unit wholly in `acme` gives no rule,
and its `acme::y`, defined in its main file and seen by nobody else,
is listed by it or by no one. A namespace named on the command line
would be a text pattern in all but name, and a wrong one costs the map
phase again. So the lists say what is owned and keyed under a
namespace, whatever the rules; the table is applied when they are
united. This also keeps a map shard a function of its inputs and the
run's files: the text of `slip declare` can change (another rule, an
amendment) and nothing is parsed again.

**Why per file, in blobs.** As WP-146's carrier (`spec/landed/verify/
WP-146.md` §3.5): inline, an observer's candidates are about 5 x 10^4
x 80 B = 4 MB, 400 GB over the run, for a union four orders smaller.
A header's list is the same in every observer that reads the header
the same way.

### What a wrong list does

The ruling's claim holds for a list a machine made, because the claim
does not depend on who made it: 2a keys the post-image as a function
of the post-image and the `DECL`, identically in every observer.

- **An entity left out** (a missed candidate, a stale list, `unlisted`
  in error, a shard that contributed nothing): owned and not existing,
  so mapped: `removed acme::x`, `added legacy::x`, and every reference
  to it differs. A finding.
- **An entity listed wrongly.** Every key the enumeration writes is
  the pre-image key of an entity some observer owned under that
  namespace. If the post-image's entity of that key is that entity
  untouched: right. If it is a moved entity that landed on the key
  (the ruling's b, two observers): keyed unmapped, `removed
  legacy::x`, `added acme::x`: a finding, rightly. If no post-image
  entity has the key: an unused entry in the report.
- **A namespace listed whole wrongly** (moved entities arrive in it):
  they are keyed unmapped: a finding (`whole-namespace-receives-
  moved`). W3 and W4 exist to avoid the false refusal, not for
  soundness; `members` is the remedy where they cannot see (a rule
  whose parent is a namespace only the post-image has).
- **A list of other files, another key scheme or another run**: the
  first two are refused; the third is refused where the store's record
  is, and is otherwise entries that match nothing plus entities left
  out.
- **Program-wide and local confused** by the generator: 2a honours a
  key entry for a program-wide entity only and a file entry for a
  local one only; the entry matches nothing and the entity is left
  out. A finding.

So the generator is outside the comparison's trusted base, as `slip
declare` and `reduce`'s derivation are. What is trusted in this
package is only that forming the lists does not disturb the walk.

### Candidates against the ruling's predicate

- *Owned* is `Walk::owned` (policy 1: per inclusion). An entity one
  observer owns and another reads through a read-only includer is
  listed by the first; in the second no entry is read of it. Listed if
  any observer owns it.
- *The key* is the pre-image's under no rule, which the ruling states
  is the probe key `U(e)` of the untouched entity (P3 confirms on the
  fixtures; the null move confirms on the corpus).
- *Program-wide or local* is 2a's predicate, called, not copied. Two
  observers may class one key differently (an `inline` function here,
  a `static` one of the same signature there): both entries are
  written and each is honoured for its own class.
- *A namespace both roots had* gets per-member entries, recursively:
  each nested namespace is decided on its own, so under a shared
  `acme::detail` a nested `acme::detail::impl` with no `legacy::
  detail::impl` is one whole entry. *Whole is sound anywhere* (above);
  it is chosen where no declared change can make it a false refusal
  (W2 to W4), and it is worth choosing: one entry for a component born
  in the new root, its local entities and its C-linkage declarations
  covered (limit 5), and no probe to miss (limit 2).
- *An unnamed namespace* is never whole; its members are local entries
  unless a named namespace around it is whole.
- *A key a rule produces* is not listed: the entity is relocated by
  its own rule in this run, and by limit 1 it verifies only when it is
  keyed as owned.

### Cost at 10^6 entries

`existing`: 32 B a key, **32 MB at 10^6** (the ruling's "3 to 16 MB"
is 10^5 to 5 x 10^5 keys). `existing_local`: 32 B and the path, about
130 B an entry; a codebase with 3 x 10^5 listed `static` and
unnamed-namespace entities adds 40 MB. Whole entries remove most of
both wherever the code already in the new root is in namespaces the
old root does not have; item 11 measures LLVM both ways. Every verify
worker decodes the `DECL`: tens of milliseconds a job and the lists'
size in each worker's memory (32 to 80 MB at that scale, times the
workers). Memory admission does not count it today (`spec/exec.md`
§6): a follow-up for the supervisor, with item 11's figure.

### Review and amendment

The declaration is the person's: the text has the `enumerate` line
(without it nothing is generated), `--existing-list` shows every entry
by name and place with its source, and three lines change the answer
by entity: `existing` (add; 2b), `unlisted` (remove, an entity or a
namespace with all it holds), `members` (a namespace's members and
not the namespace). Each is resolved in parsed pre-images as every
other line is; none is a pattern. At 10^6 entries nobody reads the
list; they read the `whole` lines, the counts, and the report's unused
entries and findings after a run.

### Found on the way

1. `docs/wp/WP-150.md` item 1 says "section 32 of a verify shard"; 32
   is `edits` since WP-139. This package takes 35 (34 is WP-144's).
2. **A rule on a member of an existing entity cannot match** (by
   reading). `slip declare` and a transform write a rule's `parent` in
   mapped terms under the table alone (`m(P')`, `spec/verify.md`
   §2.3): for a member of `acme::C`, `legacy::C`. If `acme::C` is
   existing, 2a keys it `acme::C` and the rule matches nothing: a
   finding, fails closed, whoever wrote the list. It widens the
   ruling's limit 1 from the entity to what is keyed under it, and
   `m` needs the lists to close it. W4 keeps the enumeration from
   making it worse (a namespace with such a rule below it is not
   whole); it does not make it better.
3. The ruling's size estimate (above).

## Coordinator's acceptance of the design (2026-11-28)

The design above is the package. It stays one package, in two stages,
with the stop after stage 1. The designer left eight decisions to the
coordinator:

1. **Where the staleness record lives.** In the store, as
   `existing/<declared id>`. The ruled `DECL` v4 format does not
   change.
2. **Names in the list entries.** Kept for now. The stage 1 corpus
   figures decide; the package stops there for that question.
3. **`reduce` deriving the list in a transform's run.** Out of scope.
   It opens with WP-092.
4. **Section id.** This package takes 35. WP-150 must take a free id
   of its own, not 32, which `edits` holds; its scope is corrected
   when it is next touched.
5. **Protocol 3 (`Job.files`) and the ownership options on `slip
   parse`.** Accepted.
6. **Memory admission does not count the `DECL`.** A follow-up package
   opens once stage 1's corpus figure is known.
7. **A rule on a member of an existing entity cannot match.** This is
   a widening of WP-144's limit 1, and it fails closed. It goes to
   WP-144's implementer as a limit, to be written into its §2.1.
8. **Size L.** Accepted.

The probes P1 to P4 are STOPs, as written.
