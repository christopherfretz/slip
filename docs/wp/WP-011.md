# WP-011 — xtask corpus: fetch and configure LLVM 19.1.7

- Status: in-progress
- Milestone: M0
- Track: G
- Needs: WP-005
- Size: M

## Scope

`cargo xtask corpus` (`spec/harness.md` §8): fetch a pinned corpus,
configure it so that it has a compilation database, and generate the
sources its translation units include, so that every entry of the database
can be parsed. Code in `xtask/src/corpus.rs` (and submodules); corpora are
described in a new committed file `bench/corpora.toml`.

The first corpus is `llvm`: llvm-project 19.1.7, `llvm/` with
`LLVM_ENABLE_PROJECTS=clang`, targets `X86;AArch64`, C++17, Release,
configured with `clang-19`/`clang++-19` as the build's compilers. URL and
tag are not repeated: the row names a table of
`kiln/scripts/oss/projects.toml` (`llvm_project`) and takes them from
there, so Slip and Kiln measure the same code.

## Interface

```
cargo xtask corpus list
cargo xtask corpus fetch <name>          shallow clone at the pinned tag; verifies the tag; no-op when present
cargo xtask corpus configure <name>      cmake (CMAKE_EXPORT_COMPILE_COMMANDS=ON), then the generate step
cargo xtask corpus status <name>         what is present: source, build tree, database (entries), generated step done
cargo xtask corpus path <name> [--db]    prints the corpus directory or its compile_commands.json
```

The corpus root is `$SLIP_CORPUS_DIR` if set, else `.corpus/` in the
repository (git-ignored): `<root>/<name>/src`, `<root>/<name>/build`.
Each step is idempotent and records completion in a stamp file that names
the pin and the configuration, so a changed row reconfigures.

**Generated sources.** LLVM's translation units include files made by
TableGen at build time; without them most of the database cannot be
parsed. `bench/corpora.toml` lists, per corpus, the build targets that
produce generated sources (for LLVM: the TableGen and `*_gen` targets, the
target-specific `…CommonTableGen` ones, clang's `clang-tablegen-targets`,
the revision headers), found by inspecting the configured build. The
generate step builds exactly those. Use the "Unix Makefiles" generator and
`make`, which takes its parallelism from the shared jobserver through
`MAKEFLAGS`; never pass `-j`. This compiles the TableGen tools with
clang-19 and takes several minutes: run it in the background.

`configure` ends by checking that every `#include "….inc"`-style generated
file the listed targets promise exists, and prints the number of database
entries. A step that needs a missing tool (`git`, `cmake`, `make`,
`clang-19`) fails with one line naming the tool and
`scripts/provision.sh --full`; nothing is installed by xtask.

The host for this package needs `scripts/provision.sh --full` (in the
workspace above the repository); run it first. Disk: about 2 GB of source
and 2 GB of build tree; say what it came to.

## Tests

`xtask/tests/corpus.rs`: parsing `bench/corpora.toml` and the Kiln row it
names (fixtures); the directory layout and `$SLIP_CORPUS_DIR`; stamps
(unchanged row is a no-op, changed row reconfigures); the missing-tool
message; `fetch`/`configure` against a tiny local git repository holding a
three-file CMake project with one generated header, when `git`, `cmake` and
a C++ compiler are present (reported skipped, with the reason, otherwise).
No test uses the network.

`spec/harness.md` §8 is an outline; write what you land in
`spec/landed/harness/WP-011.md` in the form the section should take.

## Done when

`cargo xtask ci --quick` passes; on this host `cargo xtask corpus configure
llvm` has run to completion and `status llvm` shows the database and the
generated step; the handback gives the entry count, the list of generate
targets, sizes on disk and wall time. xtask stays std only.

## Out of scope

Running `slip` over the corpus and baselines (WP-013). The libc++ test
suite as a corpus (a later package). Building LLVM itself.
