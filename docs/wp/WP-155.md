# WP-155 — verify: an instantiation that is emitted without a reference, in one image only, is a finding

- Status: done
- Milestone: M1
- Track: C
- Needs: WP-114
- Size: M
- Parallel with: every non-digest package; one digest branch merges at a time

## Scope

`spec/verify.md` §4 step 3 says that a derived unit present in one
image only is no finding, and argues it ("Why a derived unit on one
side only is not a difference"): whatever demanded the unit is written
in the unit that made it, so a declared unit differs too. The design
of `docs/wp/WP-153.md` found the demand that is written nowhere, and
its design review ran it (2026-11-24; the cases are listed under
"Tests"): **a substitution whose result is not kept can instantiate a
definition, and that definition can emit code by itself.**

```cpp
#include <cstdio>
inline int note() { std::puts("registered"); return 0; }
template <class U> struct Reg { static int r; };
template <class U> int Reg<U>::r = note();
struct Base { template <class U = int> static int s(); };
namespace n {
struct S : Base {
  template <class U = int> static auto s() { return &Reg<U>::r; }
};
}
template <class T, int = sizeof(T::s())> int call() { return 0; }
int main() { return call<n::S>(); }
```

Rename the member template `n::S::s` to `h`. `T::s` in the default
argument now finds `Base::s`; the default argument's value is the same;
`n::S::s<int>` is no longer instantiated, its deduced return type no
longer forces its body, the body no longer odr-uses `Reg<int>::r`, and
the program no longer prints. Every unit both images have is equal; six
derived units are in the pre-image only; the run is `verified`. The
same with no name binding anything else: a call requalified in a
namespace migration (`f(lib::X(), 0)` to `::f(lib::X(), 0)`, same
callee) loses a template candidate that argument-dependent lookup
supplied, and with it what that candidate's substitution instantiated.

The supervisor's ruling (2026-11-24): **a derived unit of an entity
that is emitted whether or not anything refers to it, present in one
image only, is a finding.** It closes the behaviour of every demand no
unit records, whatever the cause, and needs nothing of the front end
that the pin does not have.

1. **The mark.** The walk marks the `definition` unit of an entity
   that the translation unit emits by itself once it is defined:
   - a variable of static or thread storage duration that is not
     constant-initialised, or whose type has a non-trivial destructor,
     or that has the attribute `used`;
   - a function with the attribute `constructor`, `destructor` or
     `used`.
   Kiln's own rule is `var_must_emit`
   (`kiln/crates/kiln_codegen/src/global_init.rs`) with `USED` and
   `is_ctor_dtor_fn` (`kiln/crates/kiln_codegen/src/module.rs`); Slip
   does not link Kiln's code generator, so the walk decides from the
   AST (storage, the constant-initialisation fact that gives a
   `<value>` unit, the destructor, the attributes). Where the walk
   cannot tell, it marks: a mark too many is a finding too many, a mark
   too few is a wrong `verified`. Not marked, because they are emitted
   only through a function that is: a virtual table, type information,
   a static local, a lambda's statics, a constant inline variable. A
   thread-local is marked (lazy in fact; conservative). State as limits:
   `dllexport` on an instantiated class; `asm` labels (find out).
   The mark is bit 1 of `slip_model::digests::Unit::flags` ("emitted
   unreferenced"). It is set on derived and on declared units alike
   (the rule reads it only on derived ones); it is not part of any
   digest. A shard made before this package has no marks and must not
   be compared with one made after: `scheme` moves to 3
   (`spec/digest.md` §8; say what else the move obliges: the goldens,
   `bench/baselines`, the corpus invariants are the supervisor's to
   re-record).
2. **The rule** (`spec/verify.md` §4 step 3; `slip_verify`): a derived
   key that only one image has and whose unit is marked gives the
   finding `derived_only_pre` or `derived_only_post` (new kinds, their
   numbers and the report's words by `spec/verify.md` §8 and the
   `slip.verify.v1` report), once per key. Unmarked, as today: counted,
   no finding. No exemption applies (as for `derived_changed`). An
   indeterminate one-sided unit stays `derived_indeterminate`. Through
   groups (§4.1): a group that holds such a unit is opened as one that
   differs is.
3. **The text a person reads**: "`Reg<int>::r` is no longer
   instantiated in this translation unit (its initialiser ran before
   `main`)", or "is now instantiated …"; it says "in this translation
   unit": another may still instantiate it. With the place of the
   pattern.
4. **`spec/verify.md`**: step 3; the argument corrected (a demand made
   by a substitution that is not kept, or by a candidate that is no
   longer considered, is written in no unit; what the rule covers and
   what stays: a one-sided unmarked derived unit changes no behaviour
   by itself); §8's limits: the rule is as good as the match between
   the front end's compatibility level and the compiler of the
   compilation database (Kiln defers template candidates as clang 22
   does: with a perfect non-template match the candidate is not
   instantiated in Slip's parse and is in clang 19's); the finding is
   per translation unit. `spec/digest.md` §2.3 where the limit of
   substitutions is stated (after `docs/wp/WP-153.md` lands its
   paragraphs; if they are not on `main` yet, leave a sentence for the
   merge). `spec/pitfalls.md`: rows for the two programs above.
5. **Counters** `verify.derived.only_pre.emitted`,
   `verify.derived.only_post.emitted`; the corpus command for the
   supervisor (how many marked derived units an observer of `llvm`
   `lib/Support` has, and whether Demo 1's control and `01-relocate`
   stay clean: they must).

### Supervisor's handback (merge, 2026-11-24)

Merged after two reviews and two fix rounds; the second fix round on the
supervisor's read (the third review's failing shapes are R24 pre-15 to
pre-17 as the reviewer wrote them, and give `derived_only_pre`), with no
third review.

- Rule 1 holds by construction where it is built: the record is unit
  state, taken when the unit is written (`units::write`,
  `demand::write_part`, `Walk::content_hash`), and a templated entity's
  unit is never marked.
- One residue of the read, kept loud rather than closed: a
  content-keyed entity's stream is memoised, and a first computation
  made while an owner is being numbered records nothing. No shape that
  reaches it is known (the content-keyed kinds write no local class in
  place but through a lambda in a `static_assert` or a consteval
  block). Such a function is then placed by neither way, and
  `digest.emitted.unplaced` counts it: the counter is required 0 by
  every `slip_digest` fixture and is read on every corpus run. A
  non-zero value on a corpus is a finding.
- The Kiln gap found (no closure for the initialiser of a class
  template's `static constexpr` member or of a variable template's
  specialisation: the specialisation's `init` is the pattern's
  expression) goes on the held list for Kiln; nothing here rests on it.
- Owed by the supervisor after Demo 2's runs (which hold the release
  binary of the commit before this merge): `slip parse` over
  `lib/Support` before and after, the first two cases of Demo 1, and the
  baseline re-recorded at scheme 3.
