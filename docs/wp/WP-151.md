## Scope

`docs/wp/WP-147.md` gives every path its spelling on disk where it
enters (`slip_spelling::real_path`), and `slip apply` checks it. Two
rows of its inventory (`spec/landed/edits/WP-147.md` §1, L3 and T1)
were left out of its build because the files they change were being
changed by `docs/wp/WP-074.md` and `docs/wp/WP-076.md`. This package
builds them.

1. **T1: the ownership entries a run reads.** A `TRFM`'s `ownership`
   and a `DECL`'s `files` are compared with real paths as bytes. The
   command line makes them through `slip_spelling` since WP-147, but a
   record is also a file anyone can write, and nothing checks an entry
   read from the store: `readonly /r/SRC/VENDOR` for `/r/src/vendor`
   carves nothing out, the walk and reduce take the dependency's files
   for owned, and only `slip apply`'s check of the written path stops
   it, at the end of the run.

   The rule (the supervisor's ruling on WP-147, Q4): **where a
   `TRFM`'s ownership or a `DECL`'s files are read for a run, every
   entry must exist and be spelled on disk** (`Spelling::on_disk` gives
   the entry back). An entry that is spelled otherwise, and an entry
   that is `Missing`, is an `Input` error, status 3, naming the entry
   and, when there is one, its spelling on disk. `Missing` is refused
   and not passed: on a volume that answers lookups inconsistently,
   "missing" is the answer that would let the entry carve nothing.

   Where: the worker's `read_transform`
   (`crates/slip_cli/src/worker/transform.rs`) and the verify job's
   read of the declared changes (the job fails: a failed run, never a
   shard); `slip map`, `slip check`, `slip rename`, `slip reduce`,
   `slip apply` and `slip verify --declared` where they read a request
   or a `DECL` from the store or a file (once per command, before the
   first job). One function, called from each; not one copy per caller.

   If a merged test or a specified flow hands a run an entry that does
   not exist (an owned root made later by the transform, a read-only
   directory of another machine), do not loosen the rule: stop and say
   which.
2. **L3: the image's roots.** `crates/slip_cli/src/image.rs`
   `real_dir` (`--root`, `--post`) and `Image::canonical` go through
   `slip_spelling::real_path`. WP-147 found no defect there (the
   regions are by directory identity); this is the one rule applied
   everywhere, and `slip_cli/tests/verify.rs` `s5_1_roots_in_another_case`
   keeps passing. `Image::from_post` (a job's roots: "each must be the
   real path of a directory") compares with the spelled path, so that
   a job whose roots are in another case is refused as one that is not
   a real path is.
3. **An overlay names a file once.** The second review of
   `docs/wp/WP-074.md` (F1): two entries of an overlay that are one
   file (hard links; before WP-147, two spellings on a volume that
   folds case) give that file two post-images. The verify job refuses
   such an overlay since WP-074. The same refusal where an overlay is
   **made** (`slip_apply`'s overlay builder, and reduce's edit set when
   two of its files have one (device, inode)): an `Input` error naming
   both paths, before anything is written to the store. `slip apply`
   already refuses a file with more than one hard link when it writes
   (`write.rs`); say whether the builder's refusal makes that one
   unreachable, and keep both.
4. **Text.** `spec/edits.md` §2.1 (the sentence that says where a
   record's entries are checked), `spec/exec.md` §8.4 and §8.6,
   `spec/verify.md` §5.1 where the roots are defined.

### Choices

1. `real_path(entry) == entry`, stricter than `on_disk`: it also refuses an entry through a symbolic link. Apply's own check stays `on_disk`, and the CLI's runs first.
2. `Image::canonical`: an error other than not-found falls back to `canonicalize`'s answer (regions are by identity).
3. map/rename check the request they built, before the store opens.
4. Reduce checks one-name-per-file after `slip_reduce::reduce` (its scratch is its own) and before publishing. In `check`, the DECL is published before the builder runs.
5. `Files::identity` is a required method; the in-memory fakes answer `None` (skipped), and so is a path that finds nothing.
6. The verify job checks in `make_params`; direct `verify()` callers in tests are not checked.
7. In `--recover`, a T1 error keeps the journal and says so.
8. In apply, T1 runs after `permits`.
9. `folding_root()` (ruling 1): with `SLIP_TEST_ROOT` set, `<CARGO_TARGET_TMPDIR>/folding/<pkg>/<same name as the work dir>`, swept when its twin's lock (on the container disk; `flock` does not exclude on the mount) is free. Without the variable it has its own lock and the sweep.
10. The guard's "the gate runs on the workspace mount" is "the source tree's volume folds" (`source_folds`).
11. Ruled: stages `s2_1_another_case_of_a_readonly_directory_refused` handed `reduce` a read-only entry that did not exist yet. Its two lines that make `src/vendor/x.h` moved before `fx.reduced(...)`; nothing else changed. Its meaning is kept, since apply sees the same tree and bytes. The old order's refusal is `stages.rs` `s2_1_a_request_entry_that_does_not_exist` (reduce, check, apply: status 3 naming the entry).
