## Scope

`spec/harness.md` §9 (new): `cargo xtask invariants a|b <corpus>`.

1. `xtask::slip_run` (new file `xtask/src/slip_run.rs`): finding and
   running the `slip` executable, reading its output lines, removing a
   tree under the corpus directory.
2. `xtask::invariants` (new file `xtask/src/invariants.rs`): §9.1 and
   §9.2, the pure parts `compare_runs` and `check_identity`, and the
   command.
3. Dispatch and usage text (`xtask/src/main.rs`, `xtask/src/lib.rs`).
4. Tests (below).
5. The run of invariant (a) on the `llvm` corpus, recorded.

Files you own: `xtask/src/slip_run.rs`, `xtask/src/invariants.rs`,
`xtask/tests/invariants.rs`, fixtures under `xtask/tests/invariants/`,
`spec/landed/harness/WP-051.md`. You edit `xtask/src/main.rs` and
`xtask/src/lib.rs` (a module line each, the usage text, one match arm);
no other open package does until WP-059, which comes after you.

## Interface

`spec/harness.md` §9.4. `xtask` depends only on `slip_model` and
`slip_exec` and reaches `slip` only as an executable: the run records
and shards are read with what `xtask::perf` already has (`perf::load`,
`Loaded`, `spec/harness.md` §7.4), the report with
`slip_model::json::parse`.

Reading a run for (a): `Loaded.record.jobs` is in completion order; an
observer's shard id is the `shard` of its **last** entry
(`spec/model.md` §9); its status comes from `Loaded.shards`. An observer
of the selection with no entry in a record is `different`
(`no job | …`).

## Tests

`xtask/tests/invariants.rs`, the list of `spec/harness.md` "Tests". The
fake `slip` is a shell script the test writes (as `xtask/tests/ci.rs`
fakes `cargo`); the stores it "produces" are written by the test with
`slip_model` and `slip_exec::store`, as `xtask/tests/perf.rs` does.

## Done when

- `cargo xtask ci --quick` passes with `origin/main` merged in.
- `cargo xtask invariants a llvm` has been run with a release `slip`
  built from `origin/main` after WP-050. In
  `spec/landed/harness/WP-051.md`: its full output; for each `different`
  observer (if any) the first difference between the two shards
  (`slip dump` of each, `diff`), reduced to its cause; the wall time of
  the two runs. A difference is a defect of the walk or of the parse
  task, not of this package: hand it back as a finding with the
  observer, do not relax the comparison.
- `cargo xtask invariants b llvm` is not run here (it needs WP-053; it
  is WP-059's); `check_identity` is covered by the tests.
