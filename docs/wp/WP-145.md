# WP-145 — a default's consumed name: found by its field, and the depth limit not memoised

- Status: review
- Milestone: M1
- Track: C
- Needs: none
- Size: S
- Parallel with: the digest's area packages (one digest branch merges at a time)

## Scope

The review of WP-112's two second-round mechanisms (the memoised reach
of a default, the reset of `in_constant` in `local_type`) ran 55 pairs
(`crates/slip_digest/tests/{differ,equal}/_/rev112b-*`, already on this
package's branch, commit `14bc73cd`). Neither mechanism gave a wrong
equal. Two defects beside them did, and are this package.

1. **A wrong equal (on `main`).** `differ/_/rev112b-c38-line-file-collides-pretty`:

   ```cpp
   #line 10 "void f()"        // side B: #line 10 "void start()"
   void log(unsigned = len(std::source_location::current().function_name()));
   void f() { log(); }        // rename start() => f
   ```

   The consumed length is 8 on one side and 12 on the other; `f()`
   compares equal. Kiln keeps one string object per content, so the
   file name and the function name of the `__impl` are one object;
   `value.rs` (near 513) takes as the pretty name "the first relocation
   whose origin is not the file's", finds none, and
   `default_use_names` (`expr_misc.rs` near 497 and 518) then writes
   that there is no name and no bytes. Fix: the name is the object the
   `_M_function_name` field points to, found by the field (its offset
   or its member, whichever `value.rs` has), never by comparing
   origins; and where a source location is present and no name can be
   found, the unit is **indeterminate** with a cause of its own, not
   silently nameless. Say whether the same "origin differs" test is
   used anywhere else to tell two strings apart (the file name itself,
   `__builtin_FILE`, `__func__` against `__PRETTY_FUNCTION__`) and fix
   each the same way, with a pair.
2. **The depth limit depends on where the walk began.**
   `expr_misc.rs` near 343: `if walking.len() >= REACH_LIMIT { return
   (Err(REACH_LIMIT_CAUSE), true); }`. The `true` lets every default on
   the stack memoise the error, so a default is indeterminate or not by
   the order of its first use (`equal/_/rev112b-z01-reach-depth-order`
   shows it with the check lowered to 3), against `spec/digest.md` §9.
   Fix: a depth error is not memoised below the root that met it (or
   the memo keeps the depth it was computed at; propose the smaller);
   the check reads the same `limit` the unit test lowers, and that
   test covers depth: a chain past the limit is indeterminate from
   every starting point, a chain under it is determinate from every
   starting point.
3. **The 55 pairs stay** as tests, the failing one passing after
   item 1. Trim nothing; if two are the same shape say so in the
   handback and keep both.

## Handback

Branch `wp/145-default-name-by-field` (worktree `.worktrees/rev-112`).

**What changed, where.**

- Item 1, `crates/slip_digest/src/value.rs`: the `__impl` object's
  function name is the pointer at the offset of the field
  `_M_function_name`, found by its member of the record's definition
  and its offset in Kiln's `RecordLayout::fields` (`impl_field_offset`,
  as `kiln_sema/src/builtins.rs` `source_location_object` places it);
  the file the pointer at `_M_file_name`. No new fact from Kiln was
  needed. The role of each pointer (`Role::Pretty`/`Role::File`) is
  given by the same fields; a pointer at both or at no known field
  counts as the file's. Where an object's function name is not found
  so, the unit is indeterminate, `IMPL_NAME_CAUSE` =
  `Unaccounted("value/source-location.function-name")`: in
  `write_location` (a pointer to the object), in `expr_misc.rs`
  `feed_source_loc_values` (a `__builtin_source_location()` node, which
  now takes the stream) and in `default_use_names` (a use of a default,
  passed on or consumed). After the fix that is unreachable from C++
  (Kiln always builds both fields), so it is a guard and has no pair.
- Item 2, `crates/slip_digest/src/expr_misc.rs` `reach_default`: the
  memo holds each default's nesting with its answer (`Reached`'s `Ok`
  is now `(found, nesting)`); a memo hit with `n` defaults on the stack
  is a depth error where `n + nesting > limit`; a depth error is
  memoised only at the root that met it (stack empty on entry, no
  cycle), never below (`Taint { cycle, depth }` replaces the `own`
  bool); the depth check reads `limit`, not `REACH_LIMIT`. Of the two
  fixes the brief offered, "not memoised below the root" alone is not
  enough: a shallower default memoised first would let a deeper chain
  through it pass the limit (the ascending order of the unit test), so
  the memo also keeps the nesting. Cost: a chain past the limit is
  walked again from each use below its root (only past 65,536 nested
  defaults).
- Item 3: the 55 `rev112b-*` pairs are unchanged; `rev112b-c38` passes
  without `# pending`. No two are the same shape: `c08` and `c40` share
  a source but differ in the order of first use, which is their point.

**Item 1's question: the "origin differs" test elsewhere.** It was used
twice, both in `value.rs` `name_values`, both on the relocations of an
`__impl` object: to pick the pretty name (the defect), and to give each
relocation its role. Both now go by field. The second never gave a
wrong equal: a string object that is both file and name was given only
the file's role, so its bytes were written; now it has both roles and
its bytes are written for the same reason (two kinds of use). Nowhere
else are two strings told apart by object: `SourceLocValues`' `file`,
`file_name` and `function` (so `__builtin_FILE` against
`__builtin_FUNCTION`) are separate fields Kiln records; a
`PredefinedExpr`'s string (`__func__` against `__PRETTY_FUNCTION__`) is
its own literal, found by the `PredefinedExpr` that names it
(`name_string`), not by comparing with another string.

**Tests added.**

- `differ/_/wp145-two-callers-each-file-named-as-it`: the nearest
  reachable collision besides `c38`. A real file cannot be named as a
  pretty name through the harness (a `#line` name is the only way to
  give a file the bytes `void f()`), so two callers in one unit, each
  under a `#line` naming the file as that caller; renaming one moves
  only its unit (`g()` stays equal).
- `differ/_/wp145-pretty-pointer-file-collides`: the role by field: a
  `constexpr` pointer to `function_name()` passed on, its object also
  the file's: bytes written, the rename seen.
- `differ/_/wp145-builtin-function-file-collides`: `__builtin_FILE`
  against `__builtin_FUNCTION`: `#line` naming the file as `f`, a
  pointer to `__builtin_FUNCTION()` passed on: bytes written, the
  rename seen.
- `expr_misc.rs` `reach_tests::the_nesting_limit_does_not_depend_on_the_order`
  (digest §9): a chain `c7 -> ... -> c0` at limit 4, every use walked in
  ascending, descending and mixed order of nesting, and each use first
  then the rest, each order on a fresh memo: nesting past 4
  indeterminate, at or under 4 determinate, every order.
