# WP-145 — a default's consumed name: found by its field, and the depth limit not memoised

## Scope

The review of WP-112's two second-round mechanisms (the memoised reach
of a default, the reset of `in_constant` in `local_type`) ran 55 pairs
(`crates/slip_digest/tests/{differ,equal}/_/rev112b-*`, already on this
package's branch, commit `14bc73cd`). Neither mechanism gave a wrong
equal. Two defects beside them did, and are this package.

1. **A wrong equal (on `main`).** `differ/_/rev112b-c38-line-file-collides-pretty`:

   ```cpp
   #line 10 "void f()"        // side B: #line 10 "void start()"
   void log(unsigned = len(std::source_location::current().function_name()));
   void f() { log(); }        // rename start() => f
   ```

   The consumed length is 8 on one side and 12 on the other; `f()`
   compares equal. Kiln keeps one string object per content, so the
   file name and the function name of the `__impl` are one object;
   `value.rs` (near 513) takes as the pretty name "the first relocation
   whose origin is not the file's", finds none, and
   `default_use_names` (`expr_misc.rs` near 497 and 518) then writes
   that there is no name and no bytes. Fix: the name is the object the
   `_M_function_name` field points to, found by the field (its offset
   or its member, whichever `value.rs` has), never by comparing
   origins; and where a source location is present and no name can be
   found, the unit is **indeterminate** with a cause of its own, not
   silently nameless. Say whether the same "origin differs" test is
   used anywhere else to tell two strings apart (the file name itself,
   `__builtin_FILE`, `__func__` against `__PRETTY_FUNCTION__`) and fix
   each the same way, with a pair.
2. **The depth limit depends on where the walk began.**
   `expr_misc.rs` near 343: `if walking.len() >= REACH_LIMIT { return
   (Err(REACH_LIMIT_CAUSE), true); }`. The `true` lets every default on
   the stack memoise the error, so a default is indeterminate or not by
   the order of its first use (`equal/_/rev112b-z01-reach-depth-order`
   shows it with the check lowered to 3), against `spec/digest.md` §9.
   Fix: a depth error is not memoised below the root that met it (or
   the memo keeps the depth it was computed at; propose the smaller);
   the check reads the same `limit` the unit test lowers, and that
   test covers depth: a chain past the limit is indeterminate from
   every starting point, a chain under it is determinate from every
   starting point.
3. **The 55 pairs stay** as tests, the failing one passing after
   item 1. Trim nothing; if two are the same shape say so in the
   handback and keep both.
