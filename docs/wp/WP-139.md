# WP-139 — rename: a dependent name every observed instantiation binds to the renamed entity is edited

- Status: in-progress
- Milestone: M2
- Track: C
- Needs: WP-127, WP-066
- Size: M
- Parallel with: the transform packages that do not edit `crates/slip_refactor`'s rename

## Scope

`docs/wp/WP-127.md` built the refusing form for a dependent name that
an instantiation binds to a renamed entity, and wrote the proposal for
the offering form (`spec/landed/edits/WP-127.md`, "The offering form").
The supervisor's ruling (2026-11-23):

**The offering form is built, and it is the default.** It is row 2 of
the table of `spec/edits.md` §9.4 as that section has stated it since
`docs/wp/WP-073.md`, read from what the observer's instantiations give
(WP-127's join) in place of the front end's per-specialisation entries:

```cpp
template <class T> int call(T t) { return t.f(); }
int u() { return call(n::S<int>()); }
```

Renaming `n::S::f` to `g` edits the `f` of `t.f()` when every
instantiation of the pattern that every observer made binds that name
to a renamed entity. The reasons, to be written into §9.4:

- The guarantee of a run is over its observers, for every reference:
  a translation unit outside the run that calls `S::f` directly breaks
  as one that instantiates `call` with another class does. A dependent
  name is not a different promise, it is a place where the limit shows.
- Verification proves it for what the run saw: every specialisation an
  observer made before is made again and binds the renamed entity, or
  the run is not verified (`derived_changed`, a unit added or removed,
  an instantiation that no longer parses).
- Refusing instead makes the rename of any member that a template
  calls through its parameter impossible, where the evidence to do it
  correctly is in hand.

1. **The claims, per observer** (§9.4 row 2, exactly): every
   instantiation the observer made binds the name to a subject:
   `replace` (with the `changed` entry and the holder's exemption as
   §9.4 writes them); none binds it to a subject and at least one
   binds it to a declaration named like the old name: **`keep`** (this
   is what makes two observers that instantiate differently disagree
   at reduce, in either order: test both orders, and three observers
   of which one does not instantiate); some do and some do not:
   `refuse(mixed_instances)`; no instantiation binds it: `unresolved`,
   as now. Say what "binds" is when an instantiation's expression at
   the place is not a reference to a declaration (an expression that
   stayed dependent in a partially substituted pattern, a member of an
   unknown specialisation): it is not evidence, and the name is
   `unresolved` unless another instantiation decides it.
2. **The piece** is built as the rename builds every replacement
   (WP-132's identifier piece once it is on `main`; no text), and the
   obligation the piece carries is the ordinary one.
3. **What the report says** (`spec/edits.md` §10.5 and the report's
   format): a section listing each dependent name edited on the
   evidence of instantiations: the pattern's place, the subject, the
   specialisations seen and the number of observers that made each,
   under a heading that says a specialisation made only outside the
   run is not checked. It is residue of its own kind, distinct from
   `dependent` (a name no instantiation decided). The result's
   conclusion does not change for it; say so and why.
4. **`--dependent=refuse`** on the rename (and the field of its
   options the command line sets): the refusing form of WP-127, for a
   run whose observers are known not to be the program (a library's
   own tests). The default is `offer`.
5. **A refusal names the specialisation.** `slip_model`'s `Refusal`
   (or `Reason`) gains what is needed to say which instantiation bound
   the name elsewhere or to a subject (WP-127's open point): the
   specialisation's key and the observer. A format change: its
   version rule and goldens by `spec/model.md`.
6. **What the join misses** (WP-127's landed file and its review): for
   each shape of a dependent name where the instantiation's expression
   does not carry the pattern's place (a type name, a
   nested-name-specifier's component, a template name, a
   mem-initializer), the name is `unresolved` and a test shows that
   the run then fails verification loudly when an instantiation needed
   the edit, never `verified`.
7. **Correspondence told exactly, and three shapes where it may not
   be** (the supervisor's read of WP-127's fix round).
   `followers.rs` `hiding_signature` tells that a member does not hide
   a function a using-declarator names when their parameter types,
   variadic-ness, cv-qualifiers or ref-qualifiers differ. Test first,
   then make each "cannot be told" (`None`) if the front end hides
   where the comparison says it does not: a member without a
   ref-qualifier against a named function with one
   ([basic.scope.scope]/3); an explicit object parameter on either
   side; a trailing requires-clause on either side (a member of a
   class template's instantiation). Each test: the rename in both
   member orders is refused, or is accepted and verifies.
8. **The refusal's reason** for one instance and one subject is
   `mixed_instances` today, a misnomer (WP-127 F6): with item 5, give
   it its own reason or word the existing one so that it is true.
9. **The join is replaced by the front end's table.** Kiln's
   per-specialisation entries (its WP-1933: `WrittenRefs::specs()`,
   rows `SpecRef` keyed by pattern entry and specialisation, with
   `entity`, `found`, `adl`, `udir`, `how`; `Ast::spec_origin`;
   `kiln/spec/ast.md` §18.9) are in the pin since `docs/wp/WP-066.md`
   (not before it: the old pin has no `SpecRef`). Items 1 and 6 are
   built on them, and WP-127's join by token location goes, with a
   test for each shape the join missed that the table has (item 6's
   list) and a list, for Kiln, of each shape where the table has no
   row or a row that does not say what bound the name. Where the table
   falls short the name stays `unresolved`; the join is not kept as a
   second source.

## Tests

Items 1 to 6 as written; every accepted rename of the tests is run
through verification and verifies. The three forms (`t.f()`, `T::f()`,
`&T::f`), an unqualified dependent call found by argument-dependent
lookup at instantiation, `this->f()` with a dependent base, a pattern
that is a member of a class template. Mutations: `keep` not claimed
when no instantiation binds a subject (the two-observer test fails in
one order); the specialisations of the first observer only; the flag
ignored.

## Rules

`docs/AGENTS.md`. No string edit of the source. The gate is the full
`cargo xtask ci`. Second review; the reviewer's question: a rename
that is accepted and does not verify, or one that verifies and changed
what a name means in an instantiation an observer made.

## Done when

package's cases fails verification; the report section is in a golden.
