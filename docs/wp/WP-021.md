# WP-021 — slip_kiln: a snippet front end for tests, and who may name Kiln's types

- Status: done
- Milestone: M1
- Track: B
- Needs: WP-010
- Size: S
- Parallel with: WP-022, WP-023

## Scope

`slip_digest` walks Kiln's AST, so it has to name Kiln's types, and its
tests have to parse small sources and look at the AST. Neither is possible
through `slip_kiln` as M0 left it (no Kiln type in its interface; the
parse task returns a shard). This package gives both, inside the
boundary rule (`spec/harness.md` §3, `kiln-boundary`): `slip_kiln` stays
the only crate whose manifest names a `kiln_*` crate.

1. **`slip_kiln::kiln`** is on `main` already (re-exports of `kiln_ast`,
   `kiln_snap` and `kiln_source` as `ast`, `snap`, `source`). Add what
   the snippet front end's interface needs (`oven`; others only if a type
   in a public signature below needs them) and nothing else.
2. **`slip_kiln::snippet`**: a front end over files held in memory, for
   tests. It is not the production parse (that is `parse_observer`, and
   after WP-020 Kiln's `run_front_end`): no command line, no predefined
   macros, no system headers, no file system. It exists so that a test
   of the walk is a few lines and can run on many threads at once.
3. **The lint.** `kiln-boundary` gains a third rule: outside
   `crates/slip_kiln/`, the paths `slip_kiln::kiln` and
   `slip_kiln::snippet` are named only in files under
   `crates/slip_digest/` and `crates/slip_script/` (`snippet` also under
   any crate's `tests/`, for crates that may depend on `slip_kiln`).
   A textual check of `.rs` files is enough (the tokens `slip_kiln`, `::`,
   `kiln` or `snippet` in sequence, comments and strings excluded as the
   existing lints do it, and a `use slip_kiln::{…}` group that names
   either). Message and line as the other rules give them.

## Interface

```rust
// slip_kiln::snippet
/// A translation unit in memory.
#[derive(Clone, Debug)]
pub struct Snippet<'a> {
    /// `(path, text)`. Paths are `/`-separated and relative to an
    /// imaginary root; no two equal. `#include "x"` looks beside the
    /// including file, then in each directory of `include`, in order;
    /// `#include <x>` only in `include`.
    pub files: &'a [(&'a str, &'a str)],
    /// The path of the main file; one of `files`.
    pub main: &'a str,
    /// Directories (paths as above; `""` is the root) searched in order.
    pub include: &'a [&'a str],
    /// `c++17`, `c++20`, `c++23`, `c++26` (what Kiln's `-std=` accepts).
    pub std: &'a str,
}

/// The state of the translation unit when its AST is final. References
/// only, valid inside the call.
#[non_exhaustive]
pub struct Parsed<'r> {
    pub sm: &'r kiln::source::SourceManager,
    pub ast: &'r kiln::ast::Ast,
    pub oven: &'r kiln::oven::Oven,
    pub main_file: kiln::source::FileId,
    pub errors: u32,
    pub warnings: u32,
    /// Every diagnostic as Kiln's text sink renders it, in order.
    pub diagnostics: String,
}
impl Parsed<'_> {
    /// The snippet path a buffer was added under; `None` for a buffer the
    /// front end made itself.
    pub fn path(&self, file: kiln::source::FileId) -> Option<&str>;
}

/// Parses `snippet` for x86-64 Linux and calls `f` when the AST is final
/// (after everything `kiln -fsyntax-only` does to it before it would drop
/// it), with errors or without.
///
/// Err: the snippet itself is wrong (a path twice, `main` not among the
/// files, an unknown `std`), or the front end panicked (the payload's
/// text). The process's panic hook is not replaced.
pub fn parse<R>(snippet: &Snippet<'_>, f: impl FnOnce(&Parsed<'_>) -> R) -> Result<R, String>;
```

Built on Kiln's public pipeline: `SourceManager::add_virtual`, a
`Preprocessor` with an `IncludeResolver` of this module's own over the
snippet's files, `kiln_parse::parse_preprocessed`. See
`research/kiln-front-end-entry.md` §9 item 1 and §3 of the context
repository (the supervisor's brief gives its path) for what
`kiln -fsyntax-only` does after the parse (`SyntaxJob::after_parse`):
whatever of it changes the AST must happen here too, by calling Kiln's
public functions, never by copying their bodies. If a step is not public
at the pin, leave it out, say so in the module's documentation and in
the handback (it becomes a line of KF1). The language options are those
`kiln -std=<std> -fsyntax-only` would use with no other flag, as far as
`kiln_parse::ParseOptions` and `PpOptions` can be built from public
functions; say what differs.

The call runs on the calling thread, guarded as `parse_observer` guards
Kiln's recursion (`crate::parse`: the stack guard), on a thread of
sufficient stack if that is how `parse_observer` does it. Two calls on
two threads do not affect each other: no current directory, no
environment, no file.

## Tests

`crates/slip_kiln/tests/snippet.rs`, each naming this file's section:

- one file: `f` sees a declaration (find a function by name in
  `parsed.ast`); `errors` 0;
- quote and angle includes: beside the includer, through `include` in
  order (two directories holding the same name: the first wins), an
  angle include that only the includer's directory could satisfy is not
  found; `path` of each buffer; `#pragma once` and an include guard;
- a missing include: `errors` ≥ 1, `diagnostics` holds Kiln's message,
  `f` is still called;
- a semantic error: `f` called, `errors` 1, the rendered diagnostic has
  the file's snippet path, the line and the column;
- each `std`; an unknown one is `Err`; a duplicate path and a missing
  `main` are `Err`;
- a panic inside `f` is `Err` with its message and the next call works;
- sixteen threads, each parsing a different snippet a hundred times: every
  result equals that of the snippet parsed alone (compare a dump of the
  AST, `kiln::ast::dump`, or the count and names of declarations);
- a deeply nested expression that Kiln's stack guard turns into a
  diagnostic under `kiln` does the same here.

`xtask` lint tests (beside the existing `kiln-boundary` tests): the two
paths named in `slip_digest` (allowed), in `slip_cli/src` (refused, both
the path form and the `use` group form), in a comment and in a string
(ignored), `snippet` in `slip_cli/tests` (allowed).

## Out of scope

The production parse and its move to `run_front_end` (the package after
WP-020). A file-system snippet (pitfall rows are read from disk by their
harness and handed over as `Snippet`s). Predefined macros and a target
other than x86-64 Linux.

`SyntaxJob::after_parse` changes the AST without a flag.

Decided at handback:

- The closure runs on the calling thread after the front end's thread
  has finished (the signature has no `Send` bound); recursion inside the
  closure is therefore not under Kiln's stack guard: accepted; the walk
  bounds its own stack (WP-024).
- The stack guard is shown by a unit test at an 8 MiB stack through a
  private `parse_on`, not at the default 1 GiB: accepted.
- `__DATE__`, `__TIME__` and `__TIMESTAMP__` were the wall clock: fixed
  at the merge to the epoch's (`kiln_driver::time::spellings(0)`), with
  a test; a test's input is its files.
- The language options mirror the private `SyntaxJob::parse_options`,
  `Job::pp_options` and `configure_preprocessor` field by field and can
  drift (`wp021_same_diagnostics_as_kiln` compares twelve sources with
  the driver): deferred to KF1's review by Kiln, with the two
  visibility lines (`StagedFeatures`, an `Args` accessor for
  `complex_promoted`); added to `docs/requests/KF1-front-end-entry.md`.
- The lint does not see a renamed crate (`use slip_kiln as k`) or a
  glob import: accepted and said in the landed file; review catches it.
