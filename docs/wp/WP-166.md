# WP-166 — the census: the causes of indeterminate units over a corpus, before a run that needs none

- Status: review
- Milestone: M2
- Track: G
- Needs: none
- Size: M
- Parallel with: every package that does not edit `xtask/src/corpus/rename.rs` or `xtask/src/invariants.rs`

## Scope

`docs/demos/demo-2.md` §1 makes it a precondition of a `verified`
corpus rename that "every `ok` unit has digests with no indeterminate
unit, or each remaining cause is listed". Nothing checks it before a
run: Demo 2's run 1 (attempt a, 5.6 hours) was started without the check and
ended `not_verified` because 3,996 observers mismatched on
`indeterminate` findings only (`docs/demos/demo-2-record.md`). The
counts exist: every `ok` map shard carries `digest.indeterminate.<cause>`
and `digest.cause.<cause>.<word>` (`spec/model.md` §8.5; `spec/harness.md`
§9.3), and `perf summarize` sums them over a run. What is missing is a
command that says, per cause, how many keys and **which observers**,
and that answers "may a `verified` run start" with an exit status.

1. **`cargo xtask census <corpus>`** with the options of `invariants`
   (`--slip`, `--only`, `--limit`, `-j`; `spec/harness.md` §9, same
   rules for locating `slip`, a configured corpus, a selection said in
   the last line) and `--store <dir>`:
   - It runs `slip parse` over the corpus's plan into a store of its own
     (`stores/census` under the corpus directory, beside `invariants`'
     stores, `spec/harness.md` §8.2), or reads the newest map run
     already in that store when its plan, Kiln pin and `slip` binary
     are the same (say how "the same" is decided; when in doubt,
     parse again).
   - It reads every `ok` shard's counters (through `slip` itself: find
     the command that prints a shard's counters, e.g. `slip dump`, or
     the run summary; do **not** parse the store's binary format in
     xtask unless `xtask` already does so elsewhere — then reuse that).
   - Output, standard output:
     - per cause (`digest.indeterminate.<cause>`, including
       `pending.<area>`): keys, observers with at least one, and the
       first five such observers by path;
     - per cause text (`digest.cause.<cause>.<word>`): keys and
       observers;
     - shards not `ok` (`failed`, `incomplete`, ...) by status, with
       their count (they are not clean either: a run that needs
       `verified` needs them `ok`);
     - a JSON file `census.json` in the store's directory with the same
       numbers (schema in the spec section you write), for the supervisor's
       records;
     - last line `census: clean (<n> observers)` or
       `census: <k> indeterminate keys in <m> of <n> observers, <c> causes; <f> not ok`
       (with `(selection)` as `invariants` does).
   - Exit status: 0 clean, 1 not clean, 2 for an error of the command
     (as `invariants`).
2. **`cargo xtask corpus rename` checks it first**
   (`spec/harness.md` §6.5): with `--expect verified` or `--accept`
   (the runs that need `verified`), it runs the census over the same
   selection before the rename's map phase, prints the census's last
   line, and refuses to start (status 1, one line naming
   `cargo xtask census`) when it is not clean, unless
   `--skip-census` is given (then it says so in its own last line).
   `--expect refused` and `--expect not_verified` runs do not check.
   If the census's store can serve as the rename's map run, say so
   and whether you reuse it; do not change the rename's own store
   layout in this package.
3. **The spec**: a section in `spec/harness.md` (beside §9 and §6.5)
   with the command, options, output, JSON schema, exit statuses and
   the reuse rule; `docs/demos/demo-2.md` §1 and §3 name the census as
   the check of the precondition.

## Tests

`xtask/tests/` in the way `invariants.rs` and `corpus_rename.rs` test
their commands (a small configured fixture corpus or a fake `slip`, as
those do; read them first and reuse their helpers):

- a clean fixture: `census: clean`, status 0;
- a fixture with an indeterminate unit (any construct a digest test
  already uses for a known cause: find one under
  `crates/slip_digest/tests/indeterminate/`): the cause, its count, the
  observer named, status 1;
- a shard not `ok`: counted, status 1;
- `--only`: `(selection)` in the last line;
- the reuse rule: a second census over an unchanged store does not
  parse again; a changed `slip` binary (or what your rule keys on) does;
- `corpus rename --expect verified` refused before its map phase on an
  unclean fixture; `--skip-census` starts it and says so;
  `--expect refused` does not run the census.

Mutations (at least four, each with the test that kills it; run them
one at a time and report killed or survived): a cause dropped from the
sum; shards not `ok` ignored; the exit status inverted; the rename's
check skipped for `--accept`.

## Done when

The command and the rename's check exist as specified; the tests and
mutations pass; the full `cargo xtask ci` passes on the branch with
`main` merged in. **No corpus run** is part of this package: the
supervisor runs the census on LLVM after the merge. If your container
has a configured corpus, you may run `cargo xtask census llvm --only
/llvm/lib/Support/` once and quote the last line, but say so; it is
not required.

## Out of scope

Removing any cause (that is the digest packages' work). Changing what
`slip` records. Per-unit locations of indeterminate keys (the
observers are enough for planning; a later package may add the units).

### Numbered choices

1. **Reading shards through `perf::load` and `invariants::side`.** `xtask`
   already reads `Store`, `Plan`, `RunRecord`, and `Shard` via `slip_exec` and
   `slip_model` in `perf.rs`, `invariants.rs`, and `demo.rs`; `census.rs`
   reuses `perf::load` and `invariants::side` rather than shelling out to
   `slip dump` per shard.
2. **Store-reuse key in `<store>/census.json`.** A store is reused without
   running `slip parse` only when `census.json` parses as `slip.census.v1` and
   matches all of: `slip_digest` (`slip_model::hash::content_digest` of the
   `slip` binary bytes, catching rebuilds with the same `--version` string),
   `tool_slip`/`tool_kiln` (`slip --version` and run record), `kiln_pin`
   (`git -C kiln rev-parse HEAD`, or the corpus tag when no `kiln` checkout
   exists), `selection` (`only`, `limit`), `plan` (from `slip plan`), round 0,
   zero missing shards, and exact selected observer set. Otherwise `slip parse`
   runs afresh (removing `<store>` first via `slip_run::remove_tree` when
   strictly under `<corpus dir>`, and refusing without deleting if `--store`
   points to an existing non-reusable directory outside `<corpus dir>`).
3. **Avoiding double-counting `pending` + `pending.<area>`.** `slip_digest`
   (`crates/slip_digest/src/groups.rs:106-112`) emits both
   `digest.indeterminate.pending` and `digest.indeterminate.pending.<area>`
   for each pending key. Both appear as rows in `causes`, while total
   `indeterminate_keys` sums top-level `digest.indeterminate.<cause>` counters
   (falling back to `pending.<area>` only if `pending` is absent, and taking
   `max` with `digest.indeterminate`) so keys are counted once.
4. **Exit status 2 for all command errors in `census::main`.** Exit `0` is
   clean, `1` is not clean, and `2` is any usage or runtime error (missing
   corpus, missing `slip`, bad store), so scripts can distinguish unclean
   census (1) from command error (2).
5. **Non-`ok` status grouping.** `Side::Shard(Diagnosed|Rejected|Failed, _)`
   are counted under `diagnosed`, `rejected`, `failed`; `NoJob`, `NoShard`,
   `Absent`, and `Other` are grouped under `incomplete`.
6. **When `corpus rename` checks the census (`needs_census`).** Checks every
   run whose expected state is `verified` or `verified_with_residue` —
   including runs with no `--expect`, since `check_state` defaults to
   `verified` or `verified_with_residue`. Only runs whose `--expect`
   explicitly names a non-verified state (`refused`, `not_verified`, or
   `incomplete`) skip the census. (Updated in Fix round 1; see below.)
7. **Census store vs rename store.** `census` runs transform-free `slip parse`
   at round 0 into `<corpus dir>/stores/census`, whereas `slip rename` needs
   round-1+ map shards with transform-specific `edits` claims in
   `<corpus dir>/slip-store`. Because round-0 shards cannot serve as
   round-`r` transform map shards, the rename's store layout is unchanged.
