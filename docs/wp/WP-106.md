## What to look for, beyond one test per row

1. **§4.2 "Adjustments to Kiln's canonical form"**, rule by rule: each
   rule gets a pair that shows the adjustment is made (equal) and a pair
   that shows it is not made too widely (two types the rule must keep
   apart differ). Sugar is `out`: a typedef chain, a using-declared
   type, an elaborated specifier, parentheses, an alias template that
   names a type directly. But what sugar can hide is not: an alias
   template whose argument is not used (`template <class T> using
   void_t = void;`: `void_t<A>` against `void_t<B>` in a signature of a
   template are functionally different declarations, [temp.alias]), an
   attribute that changes the type (`Attributed` `kind`: which kinds
   are part of the type and which are not, row by row of
   `TypeAttrKind`), a `decltype` of an id-expression against the
   parenthesised one.
2. **Dependent types are compared by structure** (digest §8): two
   templates whose signatures differ only in the name of a template
   parameter are equal; in depth, index or pack-ness differ; `typename
   T::x` against `typename T::y`, against `typename T::template x<int>`;
   the keyword (`typename`, `class`, `struct`, none) where it is a fact
   and where it is not; `T<int>` on a template template parameter;
   pack expansions with and without a known number of expansions; pack
   indexing with a dependent and with a constant index.
3. **Substituted forms**: `SubstTemplateTypeParm` records from which
   parameter of which template a type came. Which of its rows are `in`
   and which `out` decides whether `S<int>::f(int)` written through `T`
   and written as `int` are one function type: read the table, then
   show both directions with instantiations (a member of a class
   template instantiated twice; an alias template; a default template
   argument; a pack).
4. **Qualifiers and template names** (§4.6): a nested-name-specifier is
   written where it is a fact (a dependent name's qualifier) and not
   where it is spelling (`Elaborated`); each `Nns` kind in both
   positions; a namespace alias in a qualifier against the namespace;
   `Qualified`, `Using`, `Subst…` template names against the plain
   template; an overloaded template name; a dependent template name
   with and without the `template` keyword.
5. **Template arguments** (`ArgView`): each kind, in a specialisation's
   key and in a type; an expression argument against its value where
   Kiln has evaluated it and where it is dependent (`profile`); a pack
   of one against the element; an empty pack; `TemplateExpansion` with
   a number of expansions; a null pointer of two types; a declaration
   argument against another declaration of the same value.
6. **What the type digest memoises**: a type digest is cached
   (`types.rs`, the memo and `UnitState::local_uses`). Show that no
   type's digest depends on which unit asked first: the determinism
   sweep over your sources, and a test that digests the units of one
   source in two orders.
7. **Rows that source cannot reach** through Kiln at the pin
   (`Invalid`, `VariableArray` in C++, `Splice` without reflection,
   `0-sme`, `0-regparm` on this target, the placeholder builtin types
   outside an expression): say why with the Kiln site; an `unsupported`
   row gets its `indeterminate` test where a flag of
   `spec/harness.md` §6.1 reaches it (`// args:`), else it stays in
   `untested.txt`, listed.

## Interface

No signature changes. Files you may edit: `types.rs`, test directories,
`tests/gen/` if you generate pairs (`UnaryTransformKind`'s sixteen rows
are one shape), `spec/landed/digest/WP-106.md`. A defect in `types.rs`
is fixed with the pair that shows it; a defect elsewhere is reported
with a pending test (`# needs: <area>`), not fixed, unless it is one
line in a file no open package owns. A row of `spec/digest-kinds.md`
that is wrong about Kiln is not corrected in code (rule 2 of the common
rules): conservative, indeterminate, reported.

## Tests

Per row as the common rules say (`docs/wp/WP-029.md`, rules 5 and 6,
and the second of the three further rules of `docs/wp/WP-034.md`: every
enumeration, flag and optional row fails its test when skipped and when
written as a constant). Mutations beyond those: each adjustment of §4.2
removed; each sugar kind written instead of skipped; the memo keyed
without the unit where `local_uses` says it must be.
