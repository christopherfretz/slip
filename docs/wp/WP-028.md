## Scope

`crates/slip_digest/src/value.rs`. Tables: `spec/digest-kinds.md` §8
(`ValueKind`, `ConstValue`, `Scalar`, `FloatKind`, `NullKind`,
`MemberKind`, `PtrBase`, `ByteImage`, `ByteRange`, `Reloc`,
`UnionMember`, `ShadowKind`, `ShadowRun`), §8.1 (the store: all `out`,
check) and §10.3 (`Entry`, `StringEncoding`, `StringPool`), with digest
§7. Also the tests of the rows of §4.6 that a constant makes visible
and that are still in `untested.txt`: `ArgView/Value`, `ArgView/Value.ty`,
`ArgView/Value.value`.

`value::value` and `value::string` are pending today: replace both. A
constant is read only through `ConstStore::get` (§8); nothing written
depends on a `ConstValueId` or on interning order. A constant that
holds a pointer to a constant writes that one in place; say what bounds
the recursion (the store is append-only: a value names only earlier
values) and bound the depth as `lib.rs` says.

This package also shows what WP-024 could not: two specialisations
that differ only in a non-type template argument have different keys
(`A<1>` and `A<2>`, and the same for a pointer, a pointer to member, a
floating-point and a class-type argument), each with a `differ` test
under `_/` beside the row tests.

## Interface

The signatures in `value.rs` are fixed. A pointer whose base is an
entity writes `Walk::write_ref`; a label its local ordinal
(`local::ordinal`); a lifetime-extended temporary the `Ref` of the
declaration that extends it and the index digest §7 names; a `typeid`
the type digest; a string literal `value::string`. A base that is an
expression or needs a statement calls `expr::child` (pending).
`PtrBase` rows that name a `TemplateParamObject` write its `ref`
(the object is a unit keyed by content: `templ::param_object` writes
its stream and is not yours).

Aggregates (digest §7 last rule): the target-layout image with padding
zeroed, the ranges that hold no value, each relocation as the pointer
it holds, each active union member as a `Ref`. Read how Kiln builds
`ByteImage` (`kiln_ast::consts`) before deciding what "padding zeroed"
needs from you: if Kiln's image already has it, say where; if a
shadow run decides it, write by the rows.

## Tests

Per row, as the common rules say. A constant is reachable today through
a non-type template argument in a type or a key (`template<auto V>
struct A; A<…> x;`): integers of every width and signedness, `bool`,
`char` kinds, enumerators, null pointers of each `NullKind`, pointers
to objects, subobjects (offset and designated type), functions,
string literals' addresses where the language allows, pointers to
member (data and function, with a base path), floating-point values of
each `FloatKind` (C++20), class-type values (aggregates with padding,
a union's active member, an array member, a nested pointer). `equal`
tests: the same value written differently (`1+1` against `2`, `'a'`
against `(char)97`), and two aggregates equal except in padding.
`value::string`: each `StringEncoding` and the bytes, through a
pointer base or, where only an expression reaches it, marked
`# pending`, `# needs: expr`.

Rows reachable only through a variable's evaluated value (`VarData`
`eval`, a resolved unit that does not exist yet) or an enumerator's
value (WP-027 writes that call): cover them with unit tests in
`value.rs` that call `value::value` on a constant taken from a parsed
snippet's AST and compare stream bytes, and mark the directory test
`# pending` with the area it needs.

## Rules common to the digest's area packages

Read first, in this order: `docs/AGENTS.md`; `spec/digest.md` (whole);
`spec/digest-kinds.md` §1 and §2, then the sections in Scope; the
documentation at the top of `crates/slip_digest/src/lib.rs` (the
functions every area calls, "How to fill an area");
`spec/landed/digest/WP-024.md`; the Handback of `docs/wp/WP-024.md`.
Look at how `types.rs` and `decl.rs` write their tables before writing
yours.

1. **Files.** You own the files named in Scope and your tests. In
   `crates/slip_digest/src` touch nothing else, with two exceptions: a
   function another area must provide and that has no signature yet is
   added to that area's file as a pending function (final signature,
   body `s.pending(Area::X)`, one line in the handback), never
   implemented; and `lib.rs` gets one line per function you add for
   others, in its table. Do not touch the `Area` enumeration,
   `tables.rs` (generated), `tests/tables/pins.txt`, or the tables of
   `spec/digest-kinds.md`. Several packages run at the same time in
   other files of this crate: a change outside your files conflicts
   with theirs.
2. **The tables decide.** Rows are written in table order as §2.1 says;
   tags and decisions come from `crate::tables`, never from a number
   written by hand; `bit` rows go through `FlagWord`. A set bit or a
   value no row accounts for is `Cause::Unaccounted("<short name>/<row>")`,
   an `unsupported` row `Cause::Unsupported("<short name>/<row>")`; the
   stream stays well formed either way. A row that is wrong about Kiln
   (the field is not stored as the note says, a fact is missing) is not
   corrected in code: write the conservative thing (indeterminate),
   leave the row's test out, and report it with the Kiln `file:line`.
3. **No wildcard** (digest §13 obligation 2): every `match` over a Kiln
   enumeration lists every variant, no `_`, no `..` over variants, no
   `matches!`; a Kiln record or view is destructured without a rest
   pattern, so that a field Kiln adds does not compile.
4. **Properties** (WP-024 "Properties that are not negotiable"):
   determinism (no hash-map order, id, address or interning order in a
   stream); linear work; no panic on any AST Kiln can build (an
   unexpected shape is `Unaccounted`, not `unwrap`, not indexing);
   recursion bounded as `lib.rs` "What bounds the stack" says.
5. **Tests.** Every row of your tables gets the directory §1.5 names
   (`differ`, `equal`, `demand` or `indeterminate`), in the form
   `docs/wp/WP-024.md` "The pair tests" describes; the names leave
   `tests/tables/untested.txt` with `SLIP_BLESS=1 cargo test -p
   slip_digest --test tables`. A `differ` test changes one fact and
   names the unit that must change; choose sources in which the fact is
   visible while the other areas are pending. Where it cannot be (the
   difference is inside what another area still writes as its
   placeholder), write the test anyway and mark it: `expect.txt` gets
   the lines `# pending` and `# needs: <area>` (for an `equal` test, an
   `expect.txt` holding only those two lines); the runner skips it and
   the last area package runs them all. Keep these few and list their
   count by area in the handback. A row marked `unbuilt` needs no test.
   Rows that C++ source cannot reach through Kiln (say why, with the
   Kiln site) stay in `untested.txt` and are listed in the handback.
6. **Tests that can fail.** For every table, break at least one row in
   five on purpose (skip it, swap two, write a constant) and see its
   test fail, and do so for every row whose rule is in prose under a
   table. The handback lists the rows checked this way. Do not leave
   the breakage in.
7. **What the spec left open** goes to
   `spec/landed/digest-kinds/WP-028.md` (a decision per paragraph, the
   conservative one). Unit tests of helpers go in a `#[cfg(test)] mod
   tests` inside your own file, not in `src/tests.rs`.
8. **Gate.** `cargo xtask ci` (the full gate: this crate links Kiln)
   passes with `origin/main` merged in; `cargo test -p slip_digest`
   stays under a minute once built. Expect conflicts in
   `tests/tables/untested.txt` when merging `main`: resolve by taking
   `main`'s file and blessing again.

## Handback

Merged 2026-11-22 (branch head `298c111`). `value.rs` writes a constant
by structure (`value::value`) and a string literal by content
(`value::string`); the landed decisions are in
`spec/landed/digest-kinds/WP-028.md`.

The independent review found that a constant reached through
`PtrBase::Const` was written in place once per path (a chain of twenty
shared pairs took 34 s), that several pair tests changed more than
their row, and that two specialisations of a variable template with
value arguments collided while the area was pending. Fixed before the
merge: a pointer to a constant writes that constant's content digest
`H("slip.value.v1", stream)`, computed apart from the unit and
memoised per walk, children first by store order so that a chain nests
one level (digest §7 and the tag table of `spec/model.md` say so now);
rows named in causes; isolating unit tests where a pair cannot isolate
(`FloatKind`, encodings, `Int.ty`, `Pointer.ty`); key tests for
variable-template and function-template specialisations.

At the merge the nine tests marked `# needs: value` (attribute string
operands, `Annotation` `value`, `TemplateTables`
`param_object_values`) lost their marks and pass.

Follow-ups, each decided:

- **`TemplateTables` `param_object_values` has no isolating test**: its
  pair expected `derived-changed` for the object, which cannot happen
  (the object's key is its content). Expectation corrected; a unit test
  of `templ::param_object` is scheduled with the tests-only package for
  the header and name rows.
- **A local entity below a pointed-to constant** makes the unit
  indeterminate (`key/local-ref`): kept, conservative; measured with
  the other causes on LLVM when the worker runs the walk (deferred to
  that measurement).
- **The top-level value is written in place at every occurrence** (not
  memoised): deferred to the performance phase with `digest.bytes`.
- **`Reloc/at`, `UnionMember/at`, `ByteRange/*`, `MemberPtr.derived`**
  cannot be isolated by a pair (Kiln's store moves another row with
  them): their `expect.txt` says what else changes and names the unit
  test. Dropped as follow-ups.
- **Pointers to two members of one union are one constant in Kiln**
  (KD3, Kiln WP-2200): `differ/_/value-pointer-to-union-members` is
  marked `# needs: kiln` and is un-pended when the pin has the fix.
- **`PtrBase` `Absolute` and `LabelDiff`** are not reachable through the
  snippet runner (`kiln_oven/src/lib.rs:1882`); they stay in
  `untested.txt` until the runner has target and flag variants (wave 3
  harness work).
- **Reflection values** are `unsupported` and have their
  `indeterminate` test.
