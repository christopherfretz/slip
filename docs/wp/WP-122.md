# WP-122 — the reach audit: every dependent-lookup node the front end made is read or accounted for

- Status: todo
- Milestone: M1
- Track: C
- Needs: WP-041, WP-054
- Size: M
- Parallel with: nothing in `slip_digest` while it is in its re-bless (one digest branch merges at a time)

## Scope

`docs/wp/WP-041.md` went through five review rounds. Each re-check found
new wrong `equal`s of one family, by hand: a construct in a templated
context whose written form Kiln drops or replaces by a canonical one (a
qualifier, a template-id, an array bound, the qualifier of `using enum`,
of a pseudo-destructor, of a friend), where the only trace of a change
of meaning is a dependent call inside it:

```cpp
int f(int);
#ifdef B
long f(long);
#endif
template <class T> struct S { friend void Bq<sizeof(sizeof(f(T())))>::g(); };
```

Side B makes `f(T())` find two functions; nothing the digest writes for
`S` holds the found set, because nothing the digest walks reaches the
expression. Listing constructs one at a time does not converge: the
reviewer probes ten shapes and finds three. This package replaces the
hand search by a mechanical one, and proposes the net that makes a
construct nobody listed indeterminate rather than `equal`.

The observation it rests on: Kiln's expressions live in one arena
(`Ast::exprs`). An expression the parser built for a construct whose
written form Kiln then dropped is still in the arena; it is only
unreachable from what the digest walks. So "what did the walk not
read" can be asked of the arena.

1. **The reach record** (`crates/slip_digest`). The walk can record
   every expression node it writes, first writing or back-reference
   (`spec/digest.md` §4.3), over all units of a translation unit: one
   bit per node of the arena. Off unless asked for, as
   `docs/wp/WP-054.md`'s recorder is: the ordinary walk's bytes, time
   and memory do not move, and a test shows the bytes do not.
2. **The audit.** After a walk with the record on: every node of the
   arena that carries a lookup the instantiation will redo, or a name
   it will resolve, and that the walk did not reach. Start from the
   kinds for which the digest writes a found set or a dependent name
   (unresolved lookup, unresolved member, dependent-scope declaration
   reference, dependent-scope member, and what else Kiln has: list the
   kinds and say why each is in or out). For each such node say, from
   what Kiln records:
   - where it is: its location, the unit (`spec/digest.md` §2) whose
     extent holds it, and the construct around it as far as Kiln's
     records give it;
   - how it came to be: built by the parser for source text, or built
     by substitution (an instantiation's copy), or rebuilt by sema in
     place of another node. If Kiln does not record which, say what it
     would take (a For Kiln item) and what the audit does without it.
3. **Classes.** Every unreached node falls in a class, and every class
   has a verdict with its evidence:
   - *read elsewhere*: the digest writes what the node holds by another
     path (name the path and the pair that differs);
   - *not part of the program*: a node the parser built and discarded
     (a tentative parse, a default argument parsed twice), with the
     argument why no meaning depends on it;
   - *an instantiation's copy*: covered by its pattern's node, with the
     argument (`spec/digest.md` §3.4) and one pair;
   - *a hole*: a pair under the prelude above that is `equal` and should
     not be. Each hole gets a cause (`spelling/…`, indeterminate) or a
     rule that reads the written form, as `docs/wp/WP-041.md`'s rules
     do, and a For Kiln item where Kiln keeps nothing to read.
4. **Run it over everything we have**: both sides of every pair
   directory under `crates/slip_digest/tests/`, the standard-library
   translation units the harness already parses, and, on the
   supervisor's word only, a sample of the corpus. The result is a
   table (class, construct, count, one location each) in the landed
   file. The pair directories' result is also a test: a blessed list
   `crates/slip_digest/tests/reach/expected.txt` of the unreached
   nodes by class and construct, so that a pair added by a later
   package with a node in no class fails the gate with the node's
   place. That is the part that keeps finding holes after this package.
5. **The net (decide with numbers, then build behind an option).**
   In the product's walk: a templated unit (`docs/wp/WP-041.md`'s one
   predicate) whose extent holds a parser-built node of the audited
   kinds that the walk did not reach and that is in none of item 3's
   accounted classes is indeterminate, cause `spelling/unreached`.
   Measure before proposing it as the default: the walk's time and
   peak memory with the record on, over the pair directories and the
   standard-library units; the number of units it makes indeterminate
   there; and what must be true of Kiln (item 2's "how it came to be")
   for the net to have no false refusals. Build it behind an
   `Options` field that is off; the supervisor turns it on after the
   corpus numbers.
6. **What an expression audit cannot see.** A difference in a dependent
   name with no expression in it (`typename T::template X<U>` against
   another spelling that names another member) is in no expression
   node. Say which of `docs/wp/WP-041.md`'s rules are of that kind,
   whether Kiln's written-reference table (`docs/requests/KR1-written-reference-table.md`)
   holds an entry for each such name inside a templated extent, and
   what a second audit over that table would need. Do not build it.

## Interface

`slip_digest`: the record and the audit behind a function the tests and
`xtask` can call (name it; not part of `digest`'s result); `Options`
gains the net's field (item 5), off by default, and with it off the
output is byte for byte what it was. Files: `crates/slip_digest/src/`
(a new module; the hook where a node is written, beside WP-054's),
`crates/slip_digest/tests/reach/`, `spec/digest.md` (a section for the
audit and the net; "Tests"), `spec/digest-kinds.md` rule 11 where a
hole becomes a rule or a cause, `spec/landed/digest/WP-122.md`.

## Tests

- The record off: every pair directory's digest unchanged (the
  existing suites are that test: say so and how many directories).
- The record on: the output is the same bytes as with it off.
- Each class of item 3: one source that lands in it.
- Each hole: its pair, `equal` before and indeterminate or `differ`
  after.
- The blessed list, and one test that adds a node in no class and
  expects the failure message with its place.
- The net: on, the hole pairs with their fixes removed are
  indeterminate `spelling/unreached`; off, nothing moves.
- Mutations: the record skips back-references (reached nodes reported
  unreached); the audit skips one kind; a hole's class turned into
  *read elsewhere*; the net asks the declaration's chain and not the
  stream (WP-041's G1).

## Rules

`docs/AGENTS.md`; the "Rules common to the digest's area packages" of
`docs/wp/WP-029.md`. The gate is the full `cargo xtask ci`. No corpus
run without the supervisor's word. Trusted base: second review. The
reviewer's question: a templated construct that changes meaning between
two sides, with no unreached node of the audited kinds and an `equal`
digest.

## Done when

The gate passes with `main` merged in; the table of item 4 is in the
landed file with no class left without a verdict; every hole found has
a pair that is no longer `equal`; the blessed list is a gate test; the
net exists behind its option with its measured cost and its count of
refusals over the pair directories and the standard-library units.

## Out of scope

The second audit over the written-reference table (item 6 proposes).
Name-derived strings (`docs/wp/WP-112.md`). Turning the net on by
default (the supervisor's decision after the corpus numbers).
