## Scope

The parts of a transform's run that decide whether its post-image may be
written, as pure functions over model types in `slip_verify` (which
links `slip_model` only). Trusted base: second, independent review.

1. `spec/verify.md` §9: stale observers, unused rules, and which post
   shards count ("What the run needs").
2. `spec/verify.md` §5 "Inputs under an overlay".
3. `spec/edits.md` §8.5: the state of a result from the facts of the
   run, and what each state permits.

Files: new `crates/slip_verify/src/{agreement.rs, inputs.rs, conclude.rs}`
and `crates/slip_verify/tests/{agreement.rs, conclude.rs}`;
`crates/slip_verify/src/lib.rs` for the `mod` lines. `compare.rs` is not
touched. Starts when WP-061 is on `main`; needs nothing of Kiln, and of
M1 only that no open package owns `crates/slip_verify/src/lib.rs`.

## Interface

```rust
// slip_verify::agreement
/// One selected observer, as the run sees it.
pub struct Observed<'a> {
    pub observer: Digest,
    /// Its map shard is `ok`.
    pub pre_ok: bool,
    /// The verify shard of this round, if there is one.
    pub post: Option<&'a Shard>,
}
pub struct Agreement {
    /// Sorted by (rule, observer).
    pub stale: Vec<Stale>,
    /// Rule indices with `via` and `direct` 0 in every observer; ascending.
    pub unused: Vec<u64>,
    /// Observers whose pre shard is `ok` and whose post shard is missing,
    /// has no `binding`, is bound to another overlay or other declared
    /// changes, or (status `ok`) has no `rule_use` or one for another
    /// rules id. In the order given.
    pub unbound: Vec<Digest>,
}
/// `rules_id` is the id the verdicts carry (`Verdict::rules`).
pub fn agreement<'a>(declared: &Declared, declared_id: Digest, rules_id: Digest, overlay: Option<Digest>,
                     observers: &mut dyn Iterator<Item = Observed<'a>>) -> Agreement;

// slip_verify::inputs
/// spec/verify.md §5 "Inputs under an overlay". `Err`: the first path,
/// in path order, that fails, and which of the two rules it failed.
pub enum InputsError { NotThePostImage(Vec<u8>), SubjectChanged(Vec<u8>) }
pub fn inputs_under_overlay(pre: &[FileRef], post: &[FileRef], overlay: &Overlay) -> Result<(), InputsError>;

// slip_verify::conclude
pub struct Facts<'a> {
    pub set_state: SetState,
    pub tally: &'a Tally,
    pub agreement: &'a Agreement,
    pub cancelled: bool,
    pub allow_unparsed: bool,
    pub residue: &'a [Residue],
}
/// spec/edits.md §8.5: the first state that applies.
pub fn state(facts: &Facts<'_>) -> State;
pub struct Allow { pub residue: bool, pub partial: bool }
/// Whether `--write` or `--patch` may act on a result.
pub fn permits(result: &TransformResult, allow: Allow) -> bool;
/// One observer's line of the tally from its two shards. `scheduled`:
/// the run gave the observer a verify job (spec/edits.md §8.2).
pub enum Counted { Unparsed, Verified, Unchanged, Mismatch, NotParsed, Unverifiable, Failed }
pub fn count(pre_ok: bool, scheduled: bool, post: Option<&Shard>) -> Counted;
```

- With an empty rule table `agreement` returns three empty lists
  whatever the shards are (an unchanged observer has no post shard and
  that is not `unbound`).
- A rule of kind `namespace` is never stale (`spec/verify.md` §9); its
  uses still count against `unused`.
- An observer's post shard with a status other than `ok` contributes no
  `rule_use` and is not `unbound` if its `binding` is right: it is
  `not_parsed` in the tally, which already prevents `verified`.
- `state`: `unbound` not empty is `incomplete` (row 3), unless row 1 or
  2 applies first. `permits` is false for every state but `verified`
  and, with `allow.residue`, `verified_with_residue`; and false for a
  `partial` result without `allow.partial`.
- `count`: a pre shard that is not `ok` is `Unparsed`; an observer that
  was not scheduled is `Unchanged`; a scheduled one with no post shard
  is `Failed` (the run was cancelled before the coordinator wrote one,
  `spec/exec.md` §5.4); otherwise the post shard's status and verdict as
  `spec/verify.md` §6 names the outcomes.

## Tests

- `crates/slip_verify/tests/agreement.rs`, over sections written by
  hand: `spec/verify.md` "Tests" for it; and: two observers stale for
  one rule, one observer stale for two; a namespace rule with `direct`;
  a rule used by `via` in one observer only (not unused); the iterator
  given in two orders gives the same `stale` and `unused`.
- `crates/slip_verify/tests/conclude.rs`: every row of §8.5 alone, and
  each adjacent pair of rows together (the earlier wins); residue made
  of mentions only is `verified`; `permits` over the five states and the
  four combinations of `Allow`, with `partial` on and off; `count` for
  each outcome.
- `inputs_under_overlay`, in `agreement.rs` or a file of its own: both
  failures; both at once (the least path is reported); a file in only
  one list (not an error); an overlay file the post-image did not read
  (not an error: an edit removed its `#include`).
