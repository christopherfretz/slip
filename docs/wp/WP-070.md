## Scope

The parts of a transform's run that decide whether its post-image may be
written, as pure functions over model types in `slip_verify` (which
links `slip_model` only). Trusted base: second, independent review.

It **extends M1's run report** (`slip_verify::run`, `docs/wp/WP-055.md`,
`spec/verify.md` §7.3) and replaces nothing of it: the states, their
order, `state`, `run_verdict` and the order of findings stay M1's. A run
with a tree image and no rule produces, after this package, the report
it produced before, byte for byte.

1. `spec/verify.md` §9.2 to §9.5: stale observers, unused rules, "this
   run's shard" as far as a shard decides it, `combine`, and the
   additions to the report (§9.4).
2. `spec/verify.md` §10.3, §10.5 and the run's half of §10.6: the fold
   of the `spellings` sections over the run.
3. `spec/verify.md` §5.3, guards O1 and O2, as one pure function the
   verify job calls.
4. `spec/edits.md` §8.5: the state of a result from the facts of the
   run, the tally, and what each state permits.

Files: `crates/slip_verify/src/run.rs` (the additions to `Report`); new
`crates/slip_verify/src/{spelling.rs, guards.rs, conclude.rs}` and
`crates/slip_verify/tests/{agreement.rs, spelling.rs, conclude.rs}`;
`crates/slip_verify/src/lib.rs` for the `mod` lines. `compare.rs` is not
touched. Starts when WP-055 and WP-061 are on `main`; needs nothing of
Kiln.

**From WP-061's merge**: the reader of `RSLT` (`slip_model`
`formats/result.rs`) checks §8.5's list and not yet three facts the file
alone decides: the tally adds up, `first` is absent for `unseen`, line
and column are 1-based. Add them here with their tests (the rule of
`spec/landed/edits/WP-061.md`: whatever the file alone decides, the
reader checks), in `spec/edits.md` §8.5 too.

```rust
// slip_verify::guards                                          spec/verify.md §5.3
pub enum OverlayGuard { O1(Vec<u8>), O2(Vec<u8>) }              // the path the reason names
/// O1 over every entry of `post`, then O2: the first failure in that
/// order, each in path order. `pre` and `post` are `inputs` lists.
pub fn overlay_inputs(pre: &[FileRef], post: &[FileRef], overlay: &Overlay) -> Result<(), OverlayGuard>;
impl OverlayGuard { pub fn reason(&self) -> String; }           // the text of §5.3's table

// slip_verify::conclude                                        spec/edits.md §8.5
pub struct Facts<'a> {
    pub set: &'a EditSet,                  // its state, its refusals, its failures and reports
    pub selected: u64,                     // observers the run selected
    pub report: Option<&'a run::Report>,   // None: the verify phase did not run or did not finish
    pub allow_unparsed: bool,
    pub residue: &'a [Residue],
}
pub fn tally(facts: &Facts<'_>) -> Tally;
/// The first state of §8.5 that applies.
pub fn state(facts: &Facts<'_>) -> State;
/// The `verdict`, `tally`, `agreement`, `unused`, `spellings` and `state`
/// of a result, copied from the report and decided by `state`: the
/// caller fills the ids, `partial`, `residue` and `exempt`.
pub fn conclude(facts: &Facts<'_>, overlay: Option<&Overlay>) -> Concluded;
pub struct Concluded { pub state: State, pub verdict: Option<RunVerdict>, pub tally: Tally,
                       pub agreement: Vec<slip_model::result::Stale>, pub unused: Vec<u64>,
                       pub spellings: slip_model::result::Spellings }
#[derive(Clone, Copy, Default)]
pub struct Allow { pub residue: bool, pub errors: bool, pub partial: bool }
/// Whether `--write` or `--patch` may act on a result. `set` is the
/// result's edit set: which reasons a `verified_with_residue` has is
/// read from it and from the result.
pub fn permits(result: &TransformResult, set: &EditSet, allow: Allow) -> bool;
```

- **`Report::add`** (M1's) reads `binding`, `rule_use` and `spellings`
  from the shard it is given. A shard a worker wrote whose `binding` is
  not the run's (`declared`, `overlay` or its absence, `pre`), or that
  is `ok` under rules that are not empty and has no `rule_use` for the
  run's `rules_id`, or whose `spellings` the fold refuses, is treated as
  no shard: the observer is `failed` (`spec/verify.md` §9.3, §10.4). The
  run's `declared` and `rules` are the header's; `overlay` and
  `pre_round` are set before the first `add`, and calling either after
  it is a panic of the caller's (documented).
- **Stale**: `direct(r)` not 0 for a rule whose kind is not `namespace`,
  from this run's `ok` shards only. A namespace rule's uses still count
  against `unused`.
- **`Report::verdict`** is `combine(run_verdict(states), stale pairs,
  obligations not passed)`. `combine`: `NotVerified` if `states` is, or
  `stale` or `obligations_not_passed` is not 0; else `states`.
- **The fold** keeps one slot per obligation and no shard:
  `DenotesOther` wins over everything and keeps the first observer in
  plan order with what it found; `Passed` counts the observers whose
  `inputs` list the obligation's file and that neither held nor failed
  it; an obligation no `ok` shard held or failed is `Unseen`. `add`
  returns `Err` for an index past the overlay's obligations and for an
  index whose file the shard's `inputs` do not list. Memory is one slot
  per obligation whatever the number of observers.
- **The report's additions** (§9.4, §10.5) are present only when they
  apply; the order of JSON members and of text lines is the spec's.
- **`tally`**: the seven states from the report (`Report::states`),
  `unparsed` as `spec/edits.md` §8.2 counts it, `failed_runs` and
  `error_reports` from the edit set (`failures` by `observers`, reports
  of severity `error`). For a refused set, 0 in every field but
  `selected`, `unparsed`, `failed_runs` and `error_reports`.
- **`state`** follows §8.5's five rows in order and decides nothing the
  report did not: row 2 is `Report::verdict() == NotVerified`, row 3 is
  `Incomplete`, no report, or `unparsed` not 0 without `allow_unparsed`.
- **`permits`**: `Verified`: yes. `VerifiedWithResidue`: every reason
  present must be allowed: a residue entry that is not a mention, or a
  refusal in the set, needs `allow.residue`; `failed_runs` or
  `error_reports` not 0 needs `allow.errors`. Every other state: no. A
  `partial` result: only with `allow.partial`.

**Differences from the Interface.**
- `run::Stale` is `pub use slip_model::result::Stale`, not a new struct:
  the result stores it, and `slip_model` cannot depend on this crate.
  This is the same as `RunVerdict`.
- Added: `Outcome::passed()`, `Fold::len()`, `Fold::is_empty()`.
  `OverlayGuard` derives `Clone, Debug, PartialEq, Eq, Hash`, and
  `Allow` derives `Debug, PartialEq, Eq, Hash` besides `Clone, Copy,
  Default`. `Concluded` derives `Clone, Debug, PartialEq, Eq`.
- `Fold::add` refuses more than the two cases the Interface names: it
  also refuses the section's own invariants and a `seen` that the
  shard's `inputs` do not give (landed §3).
- `Report::add` also refuses an `ok` shard that has a `rule_use` in a
