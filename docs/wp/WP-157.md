# WP-157 — reduce: a round whose map phase did not finish gives no edit set

- Status: done
- Milestone: M2
- Track: G
- Needs: WP-076
- Size: S
- Parallel with: WP-078

## Scope

Found by `docs/wp/WP-076.md`'s fix round (should-fix 4, "For the
coordinator"): after an interrupted `slip map`, `slip reduce` builds
an `accepted` edit set from the map shards that exist. A selected
observer whose job was cancelled or never started has no shard; its
edits are left out and nothing says so. `slip check` refuses such a
round since WP-076 (`check::map_pass`: a selected observer with no map
shard, or with bytes that are not its shard, is an input error naming
its main file, whatever `--allow-unparsed` says). But the set exists,
has an id, and `slip apply` can be given it.

1. **`reduce` refuses the round**: before it folds anything, every
   selected observer has a map shard of the round, `ok` or not
   (`spec/edits.md` §8.2); one with none, or with an unusable one, is
   the same input error as `check`'s, from the same function (move it
   where both commands reach it; no second wording). No edit set is
   written, no record names one.
2. **The same in `rename`** if its reduce step can be reached after a
   map step that did not finish (find out; say in the handback which
   it is, with the test that shows it).
3. **`apply`** is not changed: it cannot know the round. Say in
   `spec/edits.md` (§8.2 or §10.3) that an accepted set is always of a
   finished map phase, and that this is `reduce`'s promise.
4. Anything else that reads "the round's map shards" and takes a
   missing one for an observer with nothing to say: list it; fix it if
   it is in `crates/slip_cli`, report it otherwise.

## Handback

Branch `wp/157-reduce-unfinished-map`; only `crates/slip_cli` and the
documents changed. The choices are `spec/landed/edits/WP-157.md`.

- **What moved where.** WP-076's check left `check::map_pass` for
  `transform::store::map_shard_of_round` (one observer, one wording,
  unchanged). `map_pass` calls it per observer. The new
  `transform::store::map_phase_finished` calls it for every observer the
  round's map phase selected (`selected_of_round`), on `reduce`'s
  threads, and gives the error of the least selected position, so the
  message does not depend on `-j`.
- **`reduce`** runs it after `selected_of_round` and before
  `request_of_round` and `reduce_round`: status 3, the message names the
  observer's main file, no edit set is published, and `reduce` publishes
  no record (as before), so none names one.
- **`rename` cannot reach reduce after an unfinished map.** Its reduce
  step runs only when `pool::run_with` returned a summary, which the
  pool builds only when every observer has its shard (an `unreachable!`
  otherwise); an interrupted map returns `PoolError::Cancelled` and
  `rename` stops. `rename::s10_6_rename_interrupted_in_map` now also
  checks that the store has no edit set and that the record names none.
  No second check in `rename`: it would decode every shard once more on
  every rename.
- **`apply`** is unchanged. `spec/edits.md` §10.2 now says that an edit
  set is always of a finished map phase, and that this is `reduce`'s
  promise.
- **Item 4, other readers of a round's map shards:**
  - `check` given a **refused** set: fixed. `map_pass` runs only after
    the apply step, which a refused set does not have, so such a set of
    an unfinished round was concluded as a `refused` result that counted
    the missing observers as unparsed. `check`'s `prepare` now runs
    `map_phase_finished` for a refused set (status 3, the record with no
    step, decision 1 of WP-076).
  - `slip_reduce::reduce` (`Shards::open` returning `None` is unparsed,
    its documented contract): outside `slip_cli`, reported, not changed.
    Both callers now guarantee it does not happen.
  - `store::request_of_round` skips a missing shard while looking for
    the request: harmless, and it runs after the check in `reduce`.
  - `map::map`'s `failed runs` count: reads only after a finished phase.
  - `check`'s verify step (`map_shard`, `verify_cmd::map_status`) and
    the verify job's `read_pre`: they read again after `map_pass`; a
    shard gone by then goes to the trusted base as no map shard, which
    never gives `unchanged` or `verified`.
- **Tests** (`crates/slip_cli/tests/rename.rs`): the fixture of
  WP-076's should-fix 4 is now `interrupted_map`. New:
  `s10_2_reduce_refuses_an_interrupted_map` (`-j 1` and `-j 4`: status
  3, the third observer's main file, no edit set, no record names one),
  `s10_2_reduce_of_a_round_with_a_shard_not_ok` (accepted, one
  unparsed), `s10_2_reduce_refuses_an_unusable_map_shard` (the first
  observer's shard replaced by other bytes),
  `s10_2_reduce_of_a_partial_round_reads_the_selected` (`map --only
  b.cpp`), `s8_1_check_of_a_refused_set_of_an_interrupted_map`.
  `s8_5_an_interrupted_map_is_not_unparsed` now gives `check` the set
  the old `reduce` made (`slip_reduce` called directly with missing
  shards as `None`), since `reduce` no longer makes one.

### Supervisor's handback (merge, 2026-11-24)

Size S: read by the supervisor and merged on that read (the gate
passed on the branch with `main` merged in; seven mutants, all killed).
`reduce` refuses a round with a selected observer that has no usable
map shard, before it reads the request, by `store::map_phase_finished`
over `store::map_shard_of_round`, the one wording `check` uses too;
`check` of a refused set of such a round gives the same error. Ruled:
`reduce --allow-unparsed` stays a usage error (the option is not
`reduce`'s; the package's test line was wrong). Open after it:
`slip_reduce`'s `Shards::open` still reads a missing shard as an
unparsed observer by its contract; both callers now check first, and
the distinction belongs in that interface when it is next changed
(`docs/wp/WP-150.md` touches it).
