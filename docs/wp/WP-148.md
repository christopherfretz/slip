## Scope

`spec/landed/digest-kinds/WP-066.md` "For WP-138" lists what the pin
of `docs/wp/WP-066.md` makes possible and that package did not turn
on. The rows that are the front end's seam, in the order of what they
buy:

1. **A working directory per run (Kiln WP-2121).**
   `crates/slip_kiln/src/parse.rs` near 543 changes the process's
   working directory (`std::env::set_current_dir`) for each parse, and
   the tests hold a lock for it. A process can therefore parse one
   observer at a time wherever a relative path matters, and every
   in-process command (`slip units`, `slip declare`, the worker's
   `--worker-jobs`) inherits that. Pass the directory to Kiln; remove
   the process-wide change and the tests' lock; then show two parses
   with different directories running at once in one process (a test
   that fails with the old code) and say what `--worker-jobs` above 1
   now permits and what still forbids it, if anything.
2. **Inputs read once (second review of WP-066, F9; predates it).**
   `collect_inputs` reads a consulted file that is not a buffer again
   at collect time: a file changed between the parse and the
   collection gets the digest of bytes the parse did not see, and the
   store then says the observer is current for content it never
   parsed. The digest of an input is of the bytes the front end read
   (ask Kiln's source manager for them or for their digest; if it
   keeps neither for a file it only stat'ed or consulted without
   reading, say which inputs those are and what a change of them can
   do). A test that changes a file between the two points (a hook or
   a file system the test controls), and the same through the overlay.
3. **The written-refs option (Kiln WP-2320)**:
   `FrontEndOptions::written_refs` in place of the dump flag
   (`parse.rs` `written_words`). No behaviour changes; the cost of a
   parse with and without it on three corpus files is in the handback
   (debug build, relative numbers only).
4. **A split `>` located (Kiln WP-2542)**: `Ast::split_greaters` in
   `slip_kiln::ranges` in place of the refusal; `spec/api.md` and
   `spec/edits.md` where they state the refusal; a test per form
   (`>>`, `>>=`, `>=` split by a template argument list's close).
5. **Exact expression extents (Kiln WP-2327,
   `kiln_parse::ExprExtents`)**: where edit placement
   (`slip_kiln::ranges`, the rename's and the script's edits) computes
   an expression's range by other means, use the exact one; list the
   cases where the two differ at this pin (each is a test), and say
   whether any merged test's edit moves.
6. **A guard on any thread (Kiln WP-2410)**: `spec/api.md` §2.5 rule 5
   keeps runs on the compiling thread. State what the rule protects
   after WP-2410, and lift it or keep it with the reason; drop the
   hazard `docs/wp/WP-080.md` recorded if it is gone. A proposal in
   the handback is enough if lifting it changes `slip_script`'s
   threading: do not build that without the supervisor's word.
7. **The thrown object (Kiln WP-2480)**: `RunError::Uncaught`'s type
   as an entity and its value: `slip_script::driver` reports the
   thrown `slip::error`'s own refusal, and a class derived from it,
   by the entity and not by the type's spelling (`ERROR_TYPE`);
   `spec/api.md` §2.8 rule 3; the two `m1_*` tests of `budgets.rs`
   that wait on this.

Items 1 and 2 are the package; 3 to 7 are small and may be handed back
separately (say which were done). An item that turns out to need a

### Summary by item

1. **Working directory per run (Kiln WP-2121).**
   - `crates/slip_kiln/src/parse.rs` checks that `Command.directory` exists
     and is a directory, resolves it with `WorkDir::at`, and passes it via
     `FrontEndOptions::working_directory`. Response-file expansion uses
     `kiln_driver::rsp::expand_in`, `lookups.rs` uses `fe.sm.work_dir()`
     with `RealFs::in_dir`, and `collect_inputs` resolves relative names
     against `fe.sm.work_dir().dir().unwrap_or(dir)`.
   - All `std::env::set_current_dir` calls (including
     `crates/slip_kiln/tests/support/oracle.rs`) and all test
     serialization mutexes (`PARSE` / `LOCK`) were removed.
     `git grep -n set_current_dir -- 'crates/*/src'` returns empty.
   - `s8_4_two_directories_concurrently` (`crates/slip_kiln/tests/parse.rs`)
     runs two parses with different directories (relative main file, `-I`,
     `@flags.rsp`) concurrently across a barrier and verifies the process
     cwd never changes; passed **20/20** times in a row.
   - **`--worker-jobs > 1` (`spec/exec.md` §5.2):** Per-run cwd now permits
     reusing a worker across observers with different directories (and
     concurrent in-process parses in commands like `slip units` /
     `slip declare`) without cwd interference. What still limits raising
     `--worker-jobs` above 1: synchronous one-job-at-a-time worker
     protocol; `peak_rss` attribution depending on `/proc/self/clear_refs`
     and allocator retention remaining in RSS/caps; stderr log splitting by
     coordinator assignment (and interleaving if concurrent);
     `slip_spelling`'s process-wide directory cache persisting across jobs
     on case-folding volumes; `Loaded::run` pinned to the compiling thread
     (`&mut self`); and per-observer crash/cap isolation.

2. **Inputs read once (WP-066 second review F9).**
   - Buffers (`FileOrigin::Disk`, `FileOrigin::Overlay`, loaded
     `FileOrigin::Lazy`) are hashed directly from
     `SourceManager::original_bytes(file)` in `collect_inputs` — never
     re-read from disk.
   - Consulted paths (`fe.consulted`): `__has_include` hits are already
     in `SourceManager`; if a consulted path matches a buffer in
     `found[..buffers_end]` (e.g., `#include` + `#embed` of one file),
     `collect_inputs` cross-checks `c.content` against that buffer's
     `original_bytes`. For `#embed` / `__has_embed` not in buffers,
     overlaid paths resolve from `overlaid_real` (canonical paths captured
     before the parse, with `Overlay::resolve` fallback for hard links)
     and disk paths are read once for BLAKE3; both are verified against
     Kiln's `Consulted::content` (size + 128-bit FNV-1a), failing closed
     (`Err("<path> changed during the parse: ...")`) on mismatch.
   - **Inputs without Kiln bytes or digest:** only a `__has_include` probe
     whose buffer was never loaded (`Lazy` without `original_bytes`,
     `Consulted::content == None`). Because `__has_include` only tests
     existence and the parse never read the file's bytes, a content edit
     between parse and collect can at most cause a conservative mismatch /
     re-parse, never mark an observer current for unparsed bytes (and
     deletion fails closed with `cannot read`). A symlink retargeted
     between open and `collect_inputs`'s `canonicalize` remains an
     unchanged limitation because `SourceManager` stores opened paths.
   - Tests (`crates/slip_kiln/src/parse.rs`):
     `s8_4_inputs_buffer_mutated_before_collect_records_parsed_bytes`,
     `s8_4_inputs_consulted_embed_mutated_before_collect_fails_closed`,
     `s8_4_inputs_overlaid_files_mutated_before_collect_record_overlaid_bytes`
     (both in-place write and atomic rename replacing the inode).

### For Kiln

1. **`FrontEndOptions::decl_extents`** (`kiln/crates/kiln_driver/src/front_end.rs:81`):
   Slip still appends `-fkiln-decl-extents` to the command line when
   `ParseOptions::written` is set because `FrontEndOptions` exposes
   `written_refs` but not `decl_extents`.
2. **Explicit-object-parameter member call extent**
   (`kiln/crates/kiln_ast/src/expr_extent.rs:238`): for
   `struct S { int f(this S, int); }; int g(S s) { return s.f(2); }`,
   `WrittenExtents::written_first` takes `CallExpr`'s `first_child` (`f`)
   instead of `call_args[0]` (`s`), returning `f(2)` instead of `s.f(2)`.
   Slip adjusts `first` in `calls.rs:1038-1049`.
3. **Consulted `#embed` / `__has_embed` raw bytes or BLAKE3**
   (`kiln/crates/kiln_driver/src/front_end.rs:234-261`): `Consulted::content`
   stores a 128-bit FNV-1a digest (non-cryptographic) rather than the
   bytes or a caller-provided hash, requiring Slip to re-read
   non-overlaid `#embed` files to compute BLAKE3 (cross-checked against
   `Consulted::content`).

### Numbered choices

1. **Cross-checking consulted paths that also match a buffer (`parse.rs:874`).**
   When a file is both `#include`d and `#embed`ded in one parse, checking
   `c.content` against the buffer's `original_bytes` closes the window
   where the file changed between the two reads.
2. **Pre-parse canonical overlay table (`parse.rs:782-789`).** Resolving
   overlaid entries' canonical on-disk real paths when building the
   overlay ensures atomic renames on disk (even reusing an inode) still
   map consulted paths back to their overlaid bytes, with `Overlay::resolve`
   as fallback for hard links.
3. **Keeping `-fkiln-decl-extents` in `written_words`.** Only
   `-fkiln-dump-written-refs` was replaced by `FrontEndOptions::written_refs`
   because Kiln has no `FrontEndOptions::decl_extents` yet.
4. **Explicit-object workaround in `calls.rs:1038-1049`.** Kept minimal
   and localized to `Object::Before`, with a "For Kiln" entry so it can
   be deleted once Kiln fixes `WrittenExtents::written_first`.
5. **Keeping `spec/api.md` §2.5 rule 5 compiling-thread guard.** Per item
   6, `slip_script` threading is left unchanged pending supervisor word.
