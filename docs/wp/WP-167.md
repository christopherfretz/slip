# WP-167 — empty `/tmp/main-XXXXXX.cpp` files left by the gate

- Status: review
- Milestone: M1
- Track: H
- Needs: none
- Size: S
- Parallel with: every package that does not edit `xtask/src/transform/`

## Scope

A gate (`cargo xtask ci`) leaves empty files `/tmp/main-<6 hex>.cpp` in
the system temporary directory: 723 were seen on this project's host
before a restart, and 12 appeared within two minutes of one gate's
`transform` step (the first gate on the host with `clang++-19`
installed). The test work directories are under `$SLIP_TEST_ROOT`
(`spec/harness.md` §11.5); nothing of Slip's should write to the system
temporary directory without removing it.

The supervisor's hypothesis, to be confirmed or refuted first: these are
**clang's crash-diagnostic reproducer files** (clang names them
`<input stem>-<6 hex>.<ext>` in `$TMPDIR` or `/tmp` and writes a `.sh`
beside them), started when the transform runner's clang oracle
(`xtask/src/transform/oracles.rs`, the clang oracle of
`spec/harness.md` §2/§6) compiles a case's `main.cpp` and clang crashes or is
killed while writing the reproducer. If so, **a clang crash during the
gate is itself a finding**: say which case and which clang invocation,
with clang's standard error.

1. **Find the writer.** Run `cargo xtask transform` with clang present
   (and, separately, the test steps that might invoke a compiler) and
   see which step creates the files (e.g. `TMPDIR` set to a fresh
   directory per step, or `inotifywait`/`strace -f -e trace=openat` on
   the step if available). Name the process, the command line and the
   case.
2. **Fix it at the source.**
   - If clang's reproducer: give every compiler invocation of the
     harness a `TMPDIR` under the case's work directory (it is removed
     with the case), and pass `-fno-crash-diagnostics` so that a crash
     is reported through the oracle's own failure (status and
     standard error), never as a file in a shared directory. If clang
     actually crashes on a case, the oracle reports that case as failed
     or `off` by the rules of `spec/harness.md` (read which), and the
     handback quotes the crash.
   - If it is something else (a test, a crate, Kiln), fix it where it
     is created, the same way: inside a directory that is removed.
3. **Keep it fixed**: a test (or a check at the end of `cargo xtask
   transform`) that the step leaves no new entry in the temporary
   directory it was given. Choose the cheapest reliable form and say
   why; a check over the system `/tmp` is not reliable on a shared
   host (other processes write there), so point the step at a
   directory of its own and check that.

## Tests

- The check of item 3, with a mutation that removes the `TMPDIR`
  setting (or the fix of item 2) and is killed by it.
- If a clang crash is found: the case and a test that the oracle
  reports it (not a silent pass, not a leaked file).

## Done when

The writer is named with evidence; no gate step leaves files in the
system temporary directory; the full `cargo xtask ci` passes on the
branch with `main` merged in (with `clang++-19` installed: the gate's
`transform` step needs it; without it the step fails with `clang oracle
skipped`).

## Out of scope

Deleting the files already in `/tmp` (the host's, not this package's).
Changing which cases the clang oracle runs.

## Handback

### Root cause and evidence

- **Hypothesis partly confirmed, writer location refuted.**
  - **Confirmed**: The zero-byte `/tmp/main-<6 hex>.cpp` files are `clang++-19` crash-diagnostic reproducer files. When `cc1` hits a `SIGSEGV` (exit 139), the clang driver creates an empty `$TMPDIR/main-<6 hex>.cpp` and tries to preprocess `main.cpp` into it; because the invocation passes `-Xclang -ast-dump=json`, the reproducer sub-command also hits `SIGSEGV` (`unable to execute command: Segmentation fault` / `Error generating preprocessed source(s).`), leaving the zero-byte `main-<6 hex>.cpp` behind with no `.sh` script.
  - **Refuted (writer)**: They are **not** written by `xtask/src/transform/oracles.rs` (`tests/transform/` has zero `main.cpp` files; scanning every `tests/transform/*/*` `pre/` and `post/` command and running `cargo xtask transform` with an isolated `TMPDIR` produced 0 crashes and 0 leaked files).
  - **Actual writer**: `crates/slip_script/tests/subject_calls.rs` (`clang_dump`, called by `item7_differential_against_clang` during the gate's `kiln` step: `cargo test -p slip_script --test subject_calls`). `clang_dump` writes every test snippet as `main.cpp`, runs `clang++-19` with `stderr(Stdio::null())`, no `TMPDIR` isolation, and no `-fno-crash-diagnostics`, and maps any non-zero exit (including ICEs) to `Dumped::Error`.
- **Exact crashing cases** (scanning all 6,424 sides of `crates/slip_digest/tests/{differ,equal,demand,indeterminate}` and all `kiln/tests/codegen` tests with `Debian clang version 19.1.7 (3+b1)`):
  - Exactly **6 sides** (3 test directories × 2 sides) trigger a `SIGSEGV` inside `CrashRecoveryContext` and each leaves one zero-byte `$TMPDIR/main-<6 hex>.cpp` (matching the 6 files observed per `cargo xtask ci` run):
    1. `crates/slip_digest/tests/differ/_/name-value-source-location-key-moved` (`a.cpp`)
    2. `crates/slip_digest/tests/differ/_/name-value-source-location-key-moved` (`b.cpp`)
    3. `crates/slip_digest/tests/equal/_/name-value-source-location-template-arguments` (`a.cpp`)
    4. `crates/slip_digest/tests/equal/_/name-value-source-location-template-arguments` (`b.cpp`)
    5. `crates/slip_digest/tests/differ/_/spelling-prefix-pack-indexing` (`t.cpp`, side `a`)
    6. `crates/slip_digest/tests/differ/_/spelling-prefix-pack-indexing` (`t.cpp`, side `b`)
  - Exact command line for all 6:
    `clang++-19 -std=c++20 --target=x86_64-unknown-linux-gnu -nostdinc -nostdinc++ -I. -w -fsyntax-only -Xclang -ast-dump=json main.cpp`

### Fix

Every external C/C++ compiler invocation in the harness and test suites now isolates `TMPDIR` inside a directory cleaned up with the run and disables clang crash reproducers (`-fno-crash-diagnostics`):

- `crates/slip_script/tests/subject_calls.rs`: extracted `clang_dump_command`, setting `.env("TMPDIR", tmp)` to `<dir>/.clang-tmp` (removed by `remove_scratch(dir)`) and passing `-fno-crash-diagnostics`; `clang_dump` also asserts `<dir>/.clang-tmp` is empty after normal (`!too_large`) completion.
- `xtask/src/transform/oracles.rs`: `oracles::clang` sets `.env("TMPDIR", &tmp)` to `<work>/clang/tmp` (already allowed by `WORK_ENTRIES` and removed with `<work>`) and passes `-fno-crash-diagnostics`. A clang crash continues to fail with `Outcome::Error` (pre-image) or `Outcome::Fail` (post-image) quoting exit status and stderr per `spec/harness.md` §6.4.
- `xtask/src/corpus/rename.rs`: `accept` creates `<corpus>/rename/accept-tmp`, passes it as `TMPDIR` (after `u.command.env`) together with `-fno-crash-diagnostics` in `clang_run`, and removes `accept-tmp` when `run_units` returns.
- `crates/slip_cli/tests/pitfalls.rs`: `compile` isolates `TMPDIR` inside `<work>/clang-tmp` (removed when `work` is cleaned on pass) and passes `-fno-crash-diagnostics`.
- `crates/slip_script/tests/header.rs`: `suitable_compilers` and `s2_1_6_examples_under_another_compiler` isolate `TMPDIR` inside `<scratch>/tmp` (removed on `Scratch::drop`) and pass `-fno-crash-diagnostics` when the compiler name starts with `clang` (omitted for `g++`, which rejects that flag).

### Choices

1. **Test-based `TMPDIR` leak verification rather than a runtime `/tmp` check inside `cargo xtask transform`.** A subprocess test that points `TMPDIR` at a fresh private directory (`s6_4_clang_tmp_isolated_and_crash_reported` in `xtask/tests/transform.rs`, plus `wp167_clang_dump_crash_leaves_no_tmp_files` in `crates/slip_script/tests/subject_calls.rs`) is deterministic, immune to concurrent writers in system `/tmp`, requires no `unsafe` `env::set_var`, and exercises both the actual crashing `clang++-19` inputs and a stand-in compiler that unconditionally writes to `$TMPDIR`.
2. **Harden all five compiler-invoking sites, not only `subject_calls.rs`.** Although only `subject_calls.rs` currently triggers clang-19 ICEs, setting per-case `TMPDIR` and `-fno-crash-diagnostics` in `oracles::clang`, `corpus/rename.rs`, `pitfalls.rs`, and `header.rs` prevents any future test or corpus compiler crash from leaking into `/tmp`.
3. **Keep `oracles::clang`'s temp dir at `<work>/clang/tmp`.** `clang` is already in `WORK_ENTRIES` (`xtask/src/transform/run.rs`), so no change to `WORK_ENTRIES` or `check_surroundings` is needed and `tree::remove(&w)` deletes it with the case.
4. **Keep `clang_dump`'s `Dumped::Error` behavior on clang-19 ICEs.** The 6 crashing sides are valid C++20/C++26 digest tests that clang 19 itself crashes on during `-ast-dump=json`; `item7_differential_against_clang` already counts them under `clang_errors` and does not need to skip or remove them from `slip_digest/tests`.

### Mutations

1. **M1 — `crates/slip_script/tests/subject_calls.rs` (`clang_dump_command`)**: removed `.env("TMPDIR", tmp)` and `.arg("-fno-crash-diagnostics")`. **KILLED** by `wp167_clang_dump_command_isolates_tmp_and_disables_crash_diagnostics` and `wp167_clang_dump_crash_leaves_no_tmp_files` (`clang_dump leaked files into inherited TMPDIR: ["main-47774a.cpp", "main-363c55.cpp"]`).
