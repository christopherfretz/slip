# WP-167 — empty `/tmp/main-XXXXXX.cpp` files left by the gate

- Status: in-progress
- Milestone: M1
- Track: H
- Needs: none
- Size: S
- Parallel with: every package that does not edit `xtask/src/transform/`

## Scope

A gate (`cargo xtask ci`) leaves empty files `/tmp/main-<6 hex>.cpp` in
the system temporary directory: 723 were seen on this project's host
before a restart, and 12 appeared within two minutes of one gate's
`transform` step (the first gate on the host with `clang++-19`
installed). The test work directories are under `$SLIP_TEST_ROOT`
(`spec/harness.md` §11.5); nothing of Slip's should write to the system
temporary directory without removing it.

The supervisor's hypothesis, to be confirmed or refuted first: these are
**clang's crash-diagnostic reproducer files** (clang names them
`<input stem>-<6 hex>.<ext>` in `$TMPDIR` or `/tmp` and writes a `.sh`
beside them), started when the transform runner's clang oracle
(`xtask/src/transform/oracles.rs`, the clang oracle of
`spec/harness.md` §2/§6) compiles a case's `main.cpp` and clang crashes or is
killed while writing the reproducer. If so, **a clang crash during the
gate is itself a finding**: say which case and which clang invocation,
with clang's standard error.

1. **Find the writer.** Run `cargo xtask transform` with clang present
   (and, separately, the test steps that might invoke a compiler) and
   see which step creates the files (e.g. `TMPDIR` set to a fresh
   directory per step, or `inotifywait`/`strace -f -e trace=openat` on
   the step if available). Name the process, the command line and the
   case.
2. **Fix it at the source.**
   - If clang's reproducer: give every compiler invocation of the
     harness a `TMPDIR` under the case's work directory (it is removed
     with the case), and pass `-fno-crash-diagnostics` so that a crash
     is reported through the oracle's own failure (status and
     standard error), never as a file in a shared directory. If clang
     actually crashes on a case, the oracle reports that case as failed
     or `off` by the rules of `spec/harness.md` (read which), and the
     handback quotes the crash.
   - If it is something else (a test, a crate, Kiln), fix it where it
     is created, the same way: inside a directory that is removed.
3. **Keep it fixed**: a test (or a check at the end of `cargo xtask
   transform`) that the step leaves no new entry in the temporary
   directory it was given. Choose the cheapest reliable form and say
   why; a check over the system `/tmp` is not reliable on a shared
   host (other processes write there), so point the step at a
   directory of its own and check that.

## Tests

- The check of item 3, with a mutation that removes the `TMPDIR`
  setting (or the fix of item 2) and is killed by it.
- If a clang crash is found: the case and a test that the oracle
  reports it (not a silent pass, not a leaked file).

## Done when

The writer is named with evidence; no gate step leaves files in the
system temporary directory; the full `cargo xtask ci` passes on the
branch with `main` merged in (with `clang++-19` installed: the gate's
`transform` step needs it; without it the step fails with `clang oracle
skipped`).

## Out of scope

Deleting the files already in `/tmp` (the host's, not this package's).
Changing which cases the clang oracle runs.
