# WP-013 — xtask: jobserver and perf

- Status: done
- Milestone: M0
- Track: G
- Needs: WP-006, WP-008, WP-011
- Size: M

## Scope

`cargo xtask jobserver status|refill` (`spec/harness.md` §5) and
`cargo xtask perf summarize|record|check` (`spec/harness.md` §7): new
modules `xtask/src/jobserver.rs` and `xtask/src/perf.rs` (split `perf` into
a directory if it grows), dispatched from `xtask/src/main.rs` with their
lines added to its usage text.

`xtask` gains two dependencies, both workspace crates: `slip_model` (the
container forms, JSON) and `slip_exec` (`jobserver::{resolve_fifo,
resolve_pool_size, status, refill}`; `store::Store` opened `Shared` for the
plan and the shards). No third-party crate. Read
`spec/landed/exec/WP-004.md`, `spec/landed/exec/WP-008.md` and
`spec/landed/harness/WP-011.md` for the interfaces as they landed; the
corpus row and its pin come from `xtask::corpus::rows`.

## Interface

The pure parts are functions of the `xtask` library, so the tests need no
process:

```rust
// perf.rs
pub struct RunPath { pub store: PathBuf, pub plan: Digest, pub phase: Phase, pub round: u64, pub started_unix_ns: u64 }
pub fn parse_run_path(path: &Path) -> Result<RunPath, String>;                    // §7, first paragraph
pub struct Loaded { /* the record, its plan, the shard of each observer that has one */ }
pub fn load(path: &Path) -> Result<Loaded, String>;
pub fn counters(loaded: &Loaded) -> Result<BTreeMap<String, u64>, String>;        // §7.1; Err if a shard is missing
pub struct Measured { /* the fields of §7.1 */ }
pub fn measured(run: &RunRecord) -> Measured;
pub fn percentile(sorted: &[u64], p: u64) -> u64;                                 // nearest rank; 0 for an empty list
pub fn render_summary(given: &str, loaded: &Loaded) -> String;                    // §7.2
pub fn render_baseline(corpus: &Corpus, loaded: &Loaded) -> Result<String, String>;   // §7.3
pub fn check(baseline_json: &str, corpus: &Corpus, loaded: &Loaded) -> Result<(String /* report */, bool /* ok */), String>;
pub fn main(repo: &Path, args: &[String]) -> ExitCode;

// jobserver.rs
pub fn main(args: &[String], env: &dyn Fn(&str) -> Option<OsString>) -> ExitCode;
```

Adjust shapes where the code shows a better one and record the final
interface, and everything the spec left open, in
`spec/landed/harness/WP-013.md`.

Numbers: sums are `u64` and an overflow is an error, not a wrap. Seconds
are rendered from nanoseconds with integer arithmetic (three decimals,
rounded half up), not through `f64`; ratios in `perf check` may use `f64`.
A baseline is read with `slip_model`'s JSON reader; an unknown member or a
wrong type is an error naming it.

## Tests

`xtask/tests/jobserver.rs` (§5): `status` on a fifo the test made with a
known number of tokens (and the tokens are still there afterwards);
`refill` of a short pool, of a full pool and of one above `<n>`; the fifo
taken from `--fifo`, from `MAKEFLAGS` and from `SLIP_JOBSERVER_FIFO` in
that precedence; `<n>` from `--jobs` and `SLIP_JOBS`; a missing path, a
regular file, a bad `<n>`, an unknown option. The test never touches the
host's own fifo: it clears `MAKEFLAGS` for what it starts.

`xtask/tests/perf.rs` (§7), over a store written by the test in a
temporary directory with `slip_exec::store` and `slip_model` (a plan with
exclusions of several reasons, shards of every status, a run record with
retried, crashed and killed jobs):

- `parse_run_path`: a good path, each malformed shape, a record whose plan
  or phase disagrees with its path.
- `counters`: every row of the §7.1 table, zeros included; a missing
  shard, a shard of another observer and an invalid shard are errors;
  overflow is an error.
- `measured` and `percentile`: 0, 1, 2, 100 and 101 jobs; jobs that did not
  complete or have `peak_rss` 0 are left out.
- `summarize`: golden text (`xtask/tests/golden/perf/`), including a
  cancelled run with `missing shards`; ties broken by observer id; two
  records in one invocation.
- `record`: golden JSON; refused for a record that does not cover the
  plan; the file has no absolute path; `record` then `check` is `ok`.
- `check`: a changed counter, a missing one, an extra one, a different pin
  (each exit 1 with its line); a different tool version and different
  measured values (exit 0, printed).
- Through the built executable (`CARGO_BIN_EXE_xtask`): usage errors exit
  2; an unknown corpus and an unreadable record exit 1.

Each test names its section. Golden files contain no temporary path: the
test passes the record by a relative path or replaces the root, and says
which.

## Done when

`cargo xtask ci --quick` passes; no third-party dependency was added;
`cargo xtask jobserver status` run by hand against the host's fifo prints
the pool (report the line in the handback; do **not** run `refill` against
the host's fifo).

## Out of scope

Running Slip over a corpus and recording the first baseline (WP-014). A
gate on `measured`. Adding `round` to the run record.
