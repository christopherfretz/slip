## Scope

**This package was the prototype of KF3 stage 1 on a Kiln branch. It is
not any more.** After Kiln WP-1930, WP-1931 and WP-2090 landed, the
names a rename edits come from two of Kiln's tables with both ends
exact, and the file range of a token is Kiln's own function (Kiln
WP-2150, which delivered [KF3](../requests/KF3-location-utilities.md)
stage 1), called by `slip_kiln::ranges` (`docs/wp/WP-084.md`). What is
needed here is one module that reads those two tables for every
consumer. It needs the pin of `docs/wp/WP-044.md` and nothing of the
pin move after it (`docs/wp/WP-101.md`): the tables are on Kiln `main` at `83566cc47`.

`slip_kiln::written`: the names of a unit as the programmer wrote them,
from Kiln's written-reference table (Kiln `spec/ast.md` §18) and its
declaration-extent table (§19), in the form `spec/edits.md` §9.7 and
`spec/verify.md` §10.2 read them. Three consumers, one reading:

- the native rename (`docs/wp/WP-071.md`);
- the spelled-entity check of the trusted base (`docs/wp/WP-096.md`);
- the subject of a programmable transform (`docs/wp/WP-085.md`, which
  proposed `written_refs` with the signature below "if the pin needs
  it": it does, and this package owns it).

In scope:

1. **Switching the tables on.** `slip_kiln::ParseOptions` (WP-101)
   gains `written`. Declaration extents have a recording-only word
   (`-fkiln-decl-extents`, Kiln `kiln_driver/src/args.rs:2050`); the
   written-reference table has only the dump flag
   (`-fkiln-dump-written-refs`, `args.rs:2049`), which also formats a
   dump the entry discards. Until Kiln's WP-2320
   (`docs/requests/KR1-amendment-1.md` §1) gives the entry a recording
   switch, `written` adds both words to the command line the front end
   is given (never to the plan: the observer's id does not change) and
   pays for the dump. Measure that cost on three LLVM units and put it
   in the handback. It does not decide whether a corpus run can precede
   WP-2320: that is decided, Demo 2 runs before it
   (`docs/demos/demo-2.md` §1), and the measurement is what its record
   is read with. The switch is in one function, so WP-2320 changes one
   place; that function's documentation says which of the two it does
   at this pin, and the handback repeats it, because the demonstration's
   record must state it.
2. **Written references**, deduplicated: Kiln repeats an entry when a
   default member initialiser or a default argument is parsed again
   (`docs/design/notes/kiln-landed-2026-11.md` §5.3); entries equal in
   role, range and referent are one. In unit order
   (`slip_kiln::ranges::unit_order`, WP-084; until that package is on
   `main`, by the order of the table, and the handback says which).
3. **Dependent and unresolved names**: the entries with `REF_DEPENDENT`
   or `REF_UNRESOLVED` (Kiln `kiln_ast/src/written_refs.rs:138`, `:140`),
   which have no referent.
4. **Declaration names**: for every declaration with an extent, the span
   of its name (`DeclExtent.name`, Kiln `kiln_ast/src/decl_extents.rs:68`),
   with what kind of declaration it is as far as a rename must tell:
   an ordinary declaration or definition, a using-declaration, an
   explicit specialisation, an explicit instantiation.
5. **Origins**: the origin of a referent (`spec/api.md` §5.5: for a
   specialisation or a member of an instantiated class, the template or
   the member of the template), as one function, so that the rename, the
   host and the check cannot disagree about it.

Files: new `crates/slip_kiln/src/written.rs`, `crates/slip_kiln/tests/written.rs`;
`crates/slip_kiln/src/parse.rs` (the field `written` of `ParseOptions`,
and the one function that turns it into words of the command line),
`src/lib.rs`. WP-050 and WP-084 are changing `parse.rs` at the same
time: keep the change there to that field and that function.

## Interface

```rust
// slip_kiln: `ParseOptions` and `parse_observer_with(observer, phase,
// round, options, f)` exist since WP-101 (`spec/model.md` §8.4). This
// package adds one field; there is no `parse_observer_opts`.
#[non_exhaustive]
#[derive(Clone, Copy, Debug, Default)]
pub struct ParseOptions {
    pub pp_record: bool,                                   // WP-101
    /// Record the written-reference table and the declaration extents.
    pub written: bool,
}                                                          // WP-066 adds `overlay`

// slip_kiln::written
pub use kiln::ast::RefRole as Role;       // Kiln kiln_ast/src/written_refs.rs:44, by whatever path it is exported
pub struct WrittenRef { pub role: Role, pub name: Span, pub first: Loc, pub referent: DeclId,
                        pub global: bool, pub via_using: bool }
/// The written references of a unit that have a referent, deduplicated, in unit order.
/// Empty when the unit was parsed without `written`.
pub fn written_refs<'r>(unit: &Unit<'r>) -> Vec<WrittenRef>;

pub struct DependentName { pub role: Role, pub name: Span, pub enclosing: Option<DeclId>, pub unresolved: bool }
/// The entries without a referent, deduplicated, in unit order.
pub fn dependent_names<'r>(unit: &Unit<'r>) -> Vec<DependentName>;

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum DeclNameKind { Declaration, UsingDeclaration, ExplicitSpecialisation, ExplicitInstantiation }
pub struct DeclName { pub decl: DeclId, pub name: Span, pub kind: DeclNameKind }
/// The name of every declaration that has an extent and a name written
/// as one identifier token, in unit order. A declaration without one
/// (unnamed, an operator, a conversion function, a destructor) is absent.
pub fn decl_names<'r>(unit: &Unit<'r>) -> Vec<DeclName>;

/// spec/api.md §5.5.
pub fn origin<'r>(unit: &Unit<'r>, referent: DeclId) -> DeclId;
pub fn recorded<'r>(unit: &Unit<'r>) -> bool;     // both tables are on
```

`name` is the span of the name alone (for a qualified name its last
component; `first` is the location of the first token of the whole
written name, qualifiers included, and `global` says it starts with
`::`); `referent` is the table's `entity`, and `via_using` says `found`
differed from it by a using-shadow. Spans are Kiln's: a consumer maps
one to bytes of a file with `slip_kiln::ranges` (WP-084), and this module
does not.

What is not in either table is not invented here. For each row of
`spec/edits.md` §9.3 the handback says which function gives it, and for
a row neither table serves (a name in an attribute argument, a
designator) it says so: the rename's `unreachable` stands on that list.

## Tests

`crates/slip_kiln/tests/written.rs`, over snippets and, where a range
must be a file's, over a tree written to a temporary directory under the
target directory:

- one test per role of the table, with the name's span checked byte for
  byte against the source;
- the repeated entry of a default member initialiser used by two
  constructors, and of a default argument used by two calls: once;
- an overloaded call (the referent is the overload selected); a call
  found through a using-declaration (`via_using`); `::f`, `a::f`,
  `::a::f` (`global`, `first`);
- a dependent callee, `T::f`, `x.f` with `x` dependent: in
  `dependent_names` with their enclosing declaration, not in
  `written_refs`;
- `decl_names`: a function declared twice and defined; an out-of-line
  member definition (`void N::C::f() {}`: the span is `f`); a friend
  declaration; a block-scope `extern`; a using-declaration; an explicit
  specialisation and an explicit instantiation of a function template
  and of a variable template; a declarator group (`int a, b;`: two
  names); an operator and a destructor (absent);
- `origin`: a specialisation of a function template, a member of an
  instantiated class, a member of a member template, an ordinary
  function (itself);
- with `written` off: every function returns nothing and `recorded` is
  false; the shard of a parse with `written` on is byte-identical to the
  shard with it off (recording changes no digest and no `inputs`);
- the property of `docs/wp/WP-085.md` test 9: for every reference of
  every digest pair-test snippet, the text of `name` is the referent's
  identifier.
