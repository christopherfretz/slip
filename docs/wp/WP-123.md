# WP-123 — the two `unaccounted` causes LLVM reaches: a written expression as a template argument, a numbering asked for late

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-041
- Size: M
- Parallel with: WP-106 (both edit `crates/slip_digest/src/types.rs`; this package owns the `ArgView::Expr` arm of `write_arg`, WP-106 the tests of the other rows; whichever merges second merges `main`)

## Scope

`Unaccounted` is the cause of a place the walk reached and nobody
decided (`spec/digest.md` §10). M1's exit lists none. The preview of
Demo 1 on the corpus (2026-11-23, `docs/wp/WP-059.md`, the control over
`llvm/lib/Support`, 151 observers, 3,811,859 units) has 2,796:

| counter | units |
|---|---|
| `digest.cause.unaccounted.argview.expr` | 2,792 |
| `digest.cause.unaccounted.local.late_numbering` | 4 |

and the whole-corpus run of `docs/wp/WP-050.md` had 115,559 keys of the
first (its smallest observer then: `clang/lib/Basic/OperatorPrecedence.cpp`,
2 keys). Both are costs, not wrong answers: the units are
indeterminate. But the second is a cause the code calls "never", and
the first is a row somebody was always going to write later. This
package gives each its decision.

1. **`ArgView/Expr`** (`crates/slip_digest/src/types.rs`, `write_arg`):
   a template argument Kiln keeps as its written expression, met in a
   type's sugar, is written as a tag and the cause. `docs/wp/WP-036.md`'s
   follow-up names one source (`t->m<1>`: the argument of a canonical
   `expr_targs` list). First find out what LLVM's are: reduce two or
   three of the corpus's cases to sources of a few lines (the forms
   differ: say whether the argument is dependent, whether it is a
   constant Kiln also holds as a value, and where the type stands: a
   declaration's type, an expression's, a base, a template argument of
   another type). Then decide per form, with pairs:
   - What the row must hold. The expression names entities
     (`A<sizeof(f(0))>`: which `f`; `A<N>`: which `N`), and a
     transformation that requalifies them must be compared under the
     rules, as an expression of the unit is (`spec/digest.md` §7). The
     canonical argument's value, where Kiln has one, is written by the
     canonical side already: say so with the pair, and say what the
     sugar adds.
   - How it is written. The expression walk exists; the question is
     whether the type writer can call it here. Types are written once
     and referred back to (`spec/digest.md` §4.3): an expression inside
     a type's stream must not depend on the unit it was first met in.
     Answer: does the walk of this expression read anything of its
     context (local numbering, a lambda: `local/lambda-in-type`, the
     holder, the own-spelling predicate of `docs/wp/WP-041.md`)? If it
     does, say what is cut and under which cause; an `Unsupported`
     with a named reason is a decision, `Unaccounted` is not.
   - A dependent argument: the profile path (`ArgView::Profile`,
     `crates/slip_digest/src/expr_dep.rs`) writes dependent
     expressions. Say why Kiln gives `Expr` and not `Profile` in the
     cases found, and whether the same writer serves.
2. **`local/late-numbering`** (`crates/slip_digest/src/local.rs`,
   `LATE`): a numbering asked for after `number_all` sealed the memo.
   `spec/landed/digest/WP-040.md` says every owner of a local type and
   every closure's call operator is numbered before the first unit, and
   a lib test asserts no late numbering over every pair-test source.
   LLVM has four. Find the owner that `number_all` does not find (the
   last one found this way was a specialisation whose `definition`
   names its pattern's variable, `spec/landed/digest-kinds/WP-045.md`),
   reduce it, make the collection find it, and add the source to what
   the lib test walks. If the four are more than one form, each gets
   its source.
3. **The record.** `spec/digest.md` and `spec/digest-kinds.md` say what
   the `ArgView` `Expr` row is after item 1; `spec/landed/digest/WP-123.md`
   has the reduced sources, the count of units each form had in the
   preview, and what each is now.

## How to find the cases

No corpus run (`cargo xtask corpus`, `demo`, `invariants`) without the
supervisor's word. Single translation units of the corpus may be
digested one at a time under the host's rules, by the narrowest means
the tree has (say which you used; a test or example that takes one
entry of the compilation database and prints the indeterminate units
with their causes and places, kept if it is useful to the next
package). Start from `llvm/lib/Support` (the preview's observers) and
the file WP-050 names. The supervisor has the preview's reports and
gives file names on request.

## Interface

No new public item. Files: `crates/slip_digest/src/types.rs` (the one
arm and what it calls), `local.rs` (the collection), their tests and
pair directories, `spec/digest.md`, `spec/digest-kinds.md`,
`spec/landed/digest/WP-123.md`.

## Tests

- Per form of item 1: a `differ` pair (the argument's expression names
  another entity on side B, the canonical argument equal where that is
  possible), an `equal` pair (the same entity spelled another way, where
  rule 11 does not make it differ: say which), and one under a rule (a
  rename of the named entity: `equal` under the rule, `differ` without).
- The type met first in one unit and again in another: both units'
  digests are what they are with the order swapped
  (`the_order_of_units_does_not_matter`'s pattern).
- Item 2: the reduced source in the lib test's set; a pair in which the
  late owner's local type differs.
- Mutations: the arm writes the tag only (today's bytes without the
  cause: the wrong `equal`); the expression written without its
  references; the collection's new case removed.

## Rules

`docs/AGENTS.md`; the "Rules common to the digest's area packages" of

indeterminate under a named `Unsupported`); the supervisor's next

## Handback

The record is `spec/landed/digest/WP-123.md`. Cases were found with
`crates/slip_digest/examples/digest_one.rs` (kept), run one observer at a
time over the 132 preview observers that held either cause. They gave
exactly the preview's counts.

**Item 1, `ArgView/Expr` (2,792 units).** Two forms. Both are
non-dependent and unconverted, so Kiln gives them no profile and no
value:

- **A, 2,496 units:** a dependent name's explicit arguments
  (`expr_targs`: `std::get<0>(t)`, `__copy_move_a<true>`,
  `atomic_is_lock_free<_Tp, __default_lock_policy>`), written in the
  unit's stream. Now the unit's own expression, walked in full
  (`expr::child`).
- **B, 296 units:** a befriended specialisation in a class template
  (`friend struct _Local_iterator_base<…, false>`, `DenseMap.h:1238`),
  which Kiln does not profile (For Kiln 1), written inside a type. Now
  written by its canonical operand (`profile_expr`), with the unit's
  local state put aside (`local::detached`), so it is order-independent.

Inside a profile, the argument is walked in that profile's frame. The
row is `in`, `tag 6`, `child`.

**Item 2, late numbering (4 units).** One form: a range-`for` over a
non-dependent prvalue in a template, whose shared temporary's
`LetData.extending` is the pattern's `__range` (For Kiln 2). The units
are `format_provider<iterator_range<…>>::consumeOneOption` and three
`cl::sub::apply<Opt>`. `number_all` now numbers that owner.
