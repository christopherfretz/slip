**Waits for** WP-043 (the cases under `bench/demo1/`), WP-051
(`xtask::slip_run`, the `invariants` command and `xtask/src/main.rs`)

## Interface

`spec/harness.md` §10.5, with `xtask::slip_run` of §9.4 for every `slip`
run. `xtask` reads the reports with `slip_model::json` and the runs with
`xtask::perf` (`spec/harness.md` §7.4); it links neither `slip_cli` nor
`slip_verify`.

## The cases

They are WP-043's: the sites, the edits, the declared lines, the
expected findings, and the production compiler's acceptance of every
tree. This package runs them and does not rewrite them. What it may
change under `bench/demo1/`, each change named in the landed file:

- **the spelling of a name** in `declared.txt` or `expect.txt`, to the
  one `slip units` prints for **the same entity** (run it on the
  pristine tree, and with `--post-image` for a `created` line). The
  `README.md` of the case says which entity is meant; a name is not
  changed to another entity's because that one is found;
- **a slip of the `edit.txt` grammar** that the reader refuses, if the
  tree it then gives is byte for byte the tree WP-043 checked (its
  landed file records the edited files);
- **the `observers` file**, when the names are not all declared in the
  observers it lists.

It may not change a site, a line number, the kind of an expected
finding, or drop a line. A case that cannot be run as written is handed
back with what `slip` printed.

## Tests

## Done when

- `cargo xtask ci --quick` passes with `origin/main` merged in.
- **Demo 1 has been run** with a release `slip` built from `origin/main`:
  its whole output, `demo1.json`, and the versions are in
  `spec/landed/harness/WP-059.md`. What must hold for the package to be
  done:
  - no case is `DIFFERENT`, `MISSED` or `ERROR`. A `DIFFERENT` or a
    `MISSED` is first checked against the case (is the edit what its
    `README.md` says; is the expected line number that of the
    post-image); if the case is right, it is a defect of the trusted
    base: **stop and hand back** with the report's finding groups. If
    the case is wrong, that is handed back too. Neither is papered over
    by weakening `expect.txt`;
  - every `blocked` line names its cause, and the landed file lists, per
    cause, the digest package that removes it;
  - the last line is `demo 1: ok` or `demo 1: PARTIAL (…)`; for
    `PARTIAL` the landed file says in one paragraph what the run may be
    said to show, in the words of `spec/harness.md` §10.4.
- **Invariant (b) has been run** on the whole corpus: its output is in
  the landed file. While the walk leaves units indeterminate it prints
  `FAILED` with every `map_ok` observer under `indeterminate_only`; what
  must hold is `different 0`, `unverifiable 0`, `not_parsed 0` and
  `failed 0`. Any observer counted there is listed with its message and
  handed back as a finding (two parses of one tree disagree, or a guard
  fired on an unchanged tree). The wall time, `cpu_s` and `peak_rss_max`
  of the verify run are recorded beside the map run's. M1's exit needs
  `invariant b: holds` on the whole corpus with no excepted observer or
  cause (`spec/harness.md` §9.2); this run is the first measurement of
  the distance, and the landed file gives it as the count of
  `indeterminate_only` observers and the causes behind them.
- A second run of `cargo xtask demo 1` prints the same table up to the
  times.
