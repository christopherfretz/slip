## The cases

The table of `spec/harness.md` §10.2 fixes the hazards; you find the
sites. On the pinned corpus (`bench/corpora.toml`, row `llvm`):

- `llvm::hashing::detail` is declared in two blocks of
  `llvm/include/llvm/ADT/Hashing.h` and named in `StableHashing.h`,
  `llvm/lib/IR/StructuralHash.cpp` and
  `llvm/unittests/ADT/HashingTest.cpp`; `01-relocate` edits all of them,
  so that the tree is a consistent program and not only one that the
  selection happens to accept. `Hashing.h` has `using ::llvm::hash_value;
  return hash_value(value);` inside the namespace: read what the rename
  does to each lookup before calling the edit correct, and say it in the
  case's `README.md`.
- `StringRef::find(char C, size_t From = 0) const` is in
  `llvm/include/llvm/ADT/StringRef.h`; `02-default-argument` names, as
  its second finding, one function of `llvm/lib/Support/` that calls
  `find` with one argument.
- For `03-overload`, `04-adl` and `05-shadow` the site is yours to
  choose in `llvm/lib/Support/`, under these conditions: the tree
  compiles for **every** selected observer (the edit is silent); the
  call that changes meaning is in a function that is not a template (a
  declared unit, so the finding is `changed`, and the place is one
  line); the `README.md` shows the overload resolution or lookup, before
  and after, in two or three lines of reasoning.
- `06-relocate-and-change` and `07-relocate-undeclared` have `base`
  `01-relocate`.
- **Tier T2.** Each tree's affected translation units are compiled with
  the compiler the corpus's database names, with the command of the
  database and the root replaced by the tree, `-fsyntax-only` added:
  all of the selection for `01`, the files that hold the named callers
  for the others. The commands and their result go in `README.md`. A
  wrong edit that the production compiler rejects is not a case.
- `expect.txt` names units as `slip units` prints them; run it on the
  pristine tree to get the spelling.

## Done when

- `cargo xtask ci --quick` passes with `origin/main` merged in.
- **Demo 1 has been run** with a release `slip` built from `origin/main`:
  its whole output, `demo1.json`, and the versions are in
  `spec/landed/harness/WP-059.md`. What must hold for the package to be
  done:
  - no case is `DIFFERENT`, `MISSED` or `ERROR`. A `DIFFERENT` or a
    `MISSED` is first checked against the case (is the edit what its
    `README.md` says; is the site silent); if the case is right, it is a
    defect of the trusted base: **stop and hand back** with the report's
    finding groups. It is not papered over by weakening `expect.txt`;
  - every `blocked` line names its cause, and the landed file lists, per
    cause, the digest package that removes it;
  - the last line is `demo 1: ok` or `demo 1: PARTIAL (…)`; for
    `PARTIAL` the landed file says in one paragraph what the run may be
    said to show, in the words of `spec/harness.md` §10.4.
- **Invariant (b) has been run** on the whole corpus: its output is in
  the landed file. While the walk leaves units indeterminate it prints
  `FAILED` with every `map_ok` observer under `indeterminate_only`; what
  must hold is `different 0`, `unverifiable 0`, `not_parsed 0` and
  `failed 0`. Any observer counted there is listed with its message and
  handed back as a finding (two parses of one tree disagree, or a guard
  fired on an unchanged tree). The wall time, `cpu_s` and `peak_rss_max`
  of the verify run are recorded beside the map run's.
- A second run of `cargo xtask demo 1` prints the same table up to the
  times.
