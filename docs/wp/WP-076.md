# WP-076 — slip_cli: `map`, `check` and `rename`, the result and its report

- Status: review
- Milestone: M2
- Track: D
- Needs: WP-068, WP-070, WP-074, WP-075
- Size: L
- Parallel with: WP-072, WP-073, WP-077

## Scope

The verify loop as commands (`spec/exec.md` §8.11, §8.13;
`spec/edits.md` §8, §10.1, §10.2 `check`, §10.5, §10.6):

```
slip map    (--from <qualified name> --to <identifier> [--kind function|variable] | --transform <file.cpp> …) …
slip check  --plan <id or file> --round <n> --edits <id or file> [--declared <id or file>] …
slip rename --from <qualified name> --to <identifier> [--kind function|variable] …
```

1. **`map`**: the request built and published (§10.1 step 2); a new
   round (`Store::next_round`, `docs/wp/WP-064.md`); the map phase
   (`slip_exec::pool::run_with` with `JobExtra.transform`); the
   transform run record; the first three lines of §10.5. Only the
   rename form is built here: `--transform` is parsed, and the command
   answers `slip: map: --transform needs a slip built with slip_script`
   with status 2 until `docs/wp/WP-092.md` fills in step 2's second
   bullet (the `load` step).
2. **`check`**: from an edit set to a result. Apply
   (`slip_apply::build`; the overlay and its blobs published); the
   verify phase (`pool::run_with` with `JobExtra.post` =
   `Post { pre: round, declared, image: Overlay(id) }`), over the
   observers §8.2 says; the run report (`slip_verify::run::Report`,
   with `overlay` and `pre_round` set before the first `add`,
   `docs/wp/WP-070.md`), read from the shards as `spec/exec.md` §8.7
   "The report" says; the residue (§8.4, on `slip_kiln::scan`,
   `docs/wp/WP-068.md`), for a rename request only; the result
   (`slip_verify::conclude::conclude`); the result published; the
   report printed and, with `--report`, written; the transform run
   record.
3. **`rename`**: `map`'s steps with a rename request; `reduce_round`
   (`docs/wp/WP-075.md`); then `check`'s steps; then `apply_result` if
   `--write` or `--patch` was given. One transform run record for all
   of it.
4. The lines and the exit statuses of §10.5.

Files: new `crates/slip_cli/src/transform/{map.rs, check.rs, rename.rs,
residue.rs, report.rs, run_record.rs}`, new
`crates/slip_cli/tests/{rename.rs, verify_overlay.rs}`;
`crates/slip_cli/src/args.rs` and `src/commands.rs` for the three
commands (the shared options are parsed already).

If the package grows past two thousand lines, hand back `map` and
`check` with their tests first (`rename` is then one function over
them) and say so.

## Interface

```rust
// slip_cli::transform::map
pub struct MapInput<'a> {
    pub store: &'a Store, pub plan_id: Digest, pub plan: &'a Plan, pub selected: &'a [usize],
    pub transform_id: Digest, pub transform: &'a Transform,
    pub pool: &'a slip_exec::pool::Options,   // -j, memory, timeouts: what `parse` passes
}
/// Takes a round and runs the map phase. Returns the round and the counts of §10.5's `map:` line.
pub fn map(input: &MapInput<'_>, record: &mut Vec<Step>, out: &mut dyn Write, err: &mut dyn Write)
    -> Result<(u64, MapCounts), CommandError>;
pub struct MapCounts { pub selected: u64, pub ok: u64, pub not_ok: u64, pub failed_runs: u64 }
/// §3: the request of a rename from the command line; usage errors for a bad `--from` or `--to`.
pub fn rename_request(from: &str, to: &str, kind: Option<TargetKind>, options: &TransformOptions)
    -> Result<Transform, CommandError>;

// slip_cli::transform::check
pub struct CheckInput<'a> {
    pub store: &'a Store, pub plan_id: Digest, pub plan: &'a Plan, pub round: u64,
    pub selected: &'a [usize], pub partial: bool,
    pub transform_id: Digest, pub transform: &'a Transform,
    pub set_id: Digest, pub set: &'a EditSet,
    pub declared: Option<(Digest, Declared)>,
    pub options: &'a TransformOptions,        // --allow-unparsed, --residue-ext, --report, --findings, --locate
    pub pool: &'a slip_exec::pool::Options,
}
/// Steps apply, verify, scan, conclude. Publishes the overlay, its blobs
/// and the result. `record` gets one `Step` per step run.
pub fn check(input: &CheckInput<'_>, record: &mut Vec<Step>, out: &mut dyn Write, err: &mut dyn Write)
    -> Result<(Digest, TransformResult), CommandError>;

// slip_cli::transform::residue
/// §8.4. `read_by_some` yields, sorted, the owned real paths in the
/// `inputs` of any `ok` map shard of the round.
pub fn residue(transform: &Transform, set: &EditSet, read_by_some: &[Vec<u8>], unparsed_mains: &[Vec<u8>],
               extensions: &[Vec<u8>], threads: usize) -> std::io::Result<Vec<Residue>>;

// slip_cli::transform::report
pub fn result_summary(result_id: Digest, result: &TransformResult, out: &mut dyn Write);
/// The `finding`, `stale`, `spelling` and `residue` lines (the edit set's are WP-075's `edit_set_details`).
pub fn details(/* the result, the overlay, the plan, the run report */ out: &mut dyn Write);
```

Rules fixed here:

- **Who gets a verify job** (§8.2): every selected observer whose map
  shard is `ok`, when the declared rules are not empty; with no rules,
  those that read an overlay file. The others are `unchanged`
  (`spec/verify.md` §5.5), which the report is told without a shard.
- **The worker command** is `parse`'s followed by `--findings <n>` and
  `--locate <n>`, as `verify`'s is (`spec/exec.md` §8.7); everything
  else a worker needs is in the job.
- **A refused edit set** ends after reduce: no overlay, no verify
  phase, a result with state `refused`, status 1.
- **Cancellation** (a signal during a phase, `spec/exec.md` §7): the
  result is still concluded (`incomplete`, no `verdict`) and published
  with the run record, as §10.6 says; nothing is written whatever was
  asked. Status 4.
- **Residue** reads each file once, in parallel over files with at most
  `-j` threads, and its result is sorted, so it does not depend on the
  threads. The set of files some observer read is made in one pass over
  the map shards and holds owned paths only. A file that cannot be read
  is an `Input` error naming it. A script request has no residue scan
  (§8.4): the step is not run and not in the record.
- **`check` on an edit set that is not reduce's** (§10.2): the set's
  `plan`, `round` and `transform` must be the round's
  (`request_of_round`, `docs/wp/WP-075.md`); its `basis` is not checked
  (a mutated set has the original's). The overlay is built from the set
  given; `--declared` given is used as it is, and without it the
  declared changes are derived from the set (`slip_reduce::declared`).
  An `ApplyError` of `build` is an `Input` error (`StaleFile`, `Io`) or,
  for a set reduce would not have made (`Invalid`, `TooLarge`,
  `NotAccepted`), a result of state `refused` is **not** invented: the
  command stops with status 3 and the error.
- **Counting memory** for the run record: the coordinator's own peak at
  the end of each step from `/proc/self/status` (0 where there is
  none), as the phase records read theirs.
- **The report's details** are bounded as §10.5 says (64 `finding`
  groups, 200 lines of each other kind, each cut announced); the
  records hold everything. A `spelling` line's line and column are
  computed from the post-image blob.
- `--from` and `--to` are checked against §3 before the store is
  opened: usage errors, status 2.

## Tests

- `crates/slip_cli/tests/rename.rs` (`spec/edits.md` "Tests"), through
  the executable over small trees written by the test:
  a function in a header and two source files (`verified`, `--write`
  leaves the post-image, status 0); the same with `--patch`; without
  either (tree and working directory untouched, only the store grew);
  a refused run (a use in a macro body): status 1, the refusal line,
  no `overlay` line; a contested name; `--only` (a partial result that
  is not written without `--allow-partial`); an observer that does not
  parse, with and without `--allow-unparsed` (status 4, then the
  state the rest gives); residue in a file no observer compiles, with
  and without `--allow-residue` (status 1 both times, written the
  second); a mention; the usage errors; the output compared line by
  line with §10.5's forms.
- The stages: `map`, `reduce`, `check`, `apply` one after another give
  the ids and the tree `rename --write` gives in a fresh store; `map`'s
  three lines and its status with an observer that does not parse;
  `map --transform` (status 2, the message above); `slip verify` on the
  round of a `map` is refused (`spec/exec.md` §8.7).
- `check` as a stage: the edit set of a run given back to `check` gives
  the same result id; the same set with one edit removed (a new `EDTS`
  made with `slip_model`) is `not_verified` with a `stale` line or a
  mismatch, or `verified_with_residue` naming the range; with one edit
  added at a `kept` range: `not_verified`; with one spelled piece's key
  replaced by another entity's: `not_verified` with a `spelling
  denotes_other` line.
- A second declaration of a variable in another source file that the
  rename is made to miss (by `check` with a set lacking that edit): the
  `stale` line names the observer.
- `crates/slip_cli/tests/verify_overlay.rs` (`spec/verify.md` "Tests").
- Determinism: one run with `-j 1` and one with `-j 4` in fresh stores
  give the same five ids and the same standard output after the store's
  path is replaced.
- The run record: one `RUNT` per invocation of `map`, `rename` and
  `check`, its steps in order, the phase records it names exist;
  `Store::next_round` after a `map` alone gives the next number.
