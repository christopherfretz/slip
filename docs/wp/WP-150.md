# WP-150 — ownership agreed between observers: the record, the run's fold and the verdict

- Status: in-progress
- Milestone: M2
- Track: C
- Needs: WP-146, WP-114
- Size: L
- Parallel with: the transform packages; one digest branch merges at a time

## Scope

`docs/wp/WP-146.md` (design, ruling, stages 0 and 1) pinned the shapes
where two observers disagree about who owns an entity and each alone
says `verified`, and made the walk form two lists per observer of the
post-image, inert. This package is its stages 2 and 3
(`spec/landed/verify/WP-146.md` §3.1, §3.4, §3.5, §6, as amended by
that package's two rulings): the lists reach the store, the run joins
them, and a conflict is a finding that forbids `verified` and a write.

The rule, as ruled: **the run says of an edit what one observer that
saw every declaration would say.** Two joins, not one:

- **A split** (one entity of the pre-image, two of the post-image; the
  pair): some observer **made** an entity whose mapped key `K` is the
  own key of an entity some observer holds as a dependency's
  (`fixed`, T). Joined on the pre-image key: `made.key == fixed.key`.
- **A merge** (two entities of the pre-image, one of the post-image;
  the mirror, and an owned header that is read-only in one observer):
  some observer **made** an entity whose key as the post-image spells
  it, `post`, is the own key of an entity some observer holds as a
  dependency's and a rule would move were it owned (`fixed`, M).
  Joined on the post-image key: `made.post == fixed.key`.

An M entry alone is nothing (a dependency's entity in the target
namespace is the normal case); a T entry alone is nothing.

### Stage 2: the record (inert for the verdict; stop after it)

1. **Section 35 of a verify shard** (the next free id: 32 is `edits`, 33 `rebuilt_use`, 34 `existing_use` from WP-144; if another package took 35 first, the next free one; `spec/model.md` §8; phase
   `verify`, status `ok`, rules not empty): the content ids of the
   observer's ownership lists, strictly ascending. A list is a blob
   (`Store::publish_blob`), one per file with an entry, as the landed
   proposal's "The carrier" writes it, with `Made := key, post, rule,
   line, column` and `Fixed := key, as, line, column, name`; made
   strictly ascending by `(key, post)`, fixed by `(key, as)`. The
   format's version rule, reader rows, goldens and a fuzz or
   property test of decode(encode(x)) by `spec/model.md`. A worker
   remembers the ids it has published.
2. **The agreement** (`slip_verify::run`, on WP-114's `ours`): an `ok`
   shard of a run with rules has the section exactly when its lists are
   not empty, or always (choose, say why; an absent section must not
   be readable as "no entries" for a shard that had some). A shard
   whose section fails this is not this run's.
3. **Counters** `verify.ownership.made`, `.fixed`, `.lists`, `.bytes`
   per shard.
4. **The supervisor's corpus run** (not the implementer's): hand back
   with the command to run. The figures (`llvm` `lib/Support`: entries,

   the carrier is ruled on again (a main file's list inline in the
   section; the T test narrowed) **before stage 3 is built**.

### Stage 3: the fold and the verdict

5. **The fold** in `slip_verify`, pure: a function over sorted entry
   streams (made by `key`, made by `post`, fixed T, fixed M) giving
   the conflicts; the caller (`slip_cli`) does the I/O: the distinct
   list ids of this run's `ok` shards with, per id, the least plan
   position and the number of observers; each list read once;
   partitioned by the key's leading bits into files under the store's
   `tmp/`; per part sorted and intersected. Memory bounded by one part
   and the distinct ids (`reduce`'s discipline: what is held is
   counted, `docs/wp/WP-142.md`). A list that is missing, does not
   hash to its id or does not decode makes every observer that names
   it `failed`. Over a selection of observers the fold is of the
   selection, and the report says over how many observers it ran.
6. **The verdict**: `combine` gains the count of conflicts; a run with
   one is `not verified` (status 1) and `slip apply --write` refuses
   it, as it refuses a stale pair. The observers' states do not
   change.
7. **The report** (`slip.verify.v1`, extended as §9.4 was): `ownership`:
   each conflict with its kind (split, merge), the key's name as a
   person writes it, the made entity's file, line and rule, the
   dependency's file and line, the least plan position of an observer
   on each side and the number of observers on each side; sorted by
   key, listed up to the findings' limit, with the total. The text a
   person reads (provisional, `spec/verify.md` §8.6's notes) says what
   to do: for a split, the dependency still declares the old name
   (`kept`, or the declaration is the dependency's to change); for a
   merge, the moved entity lands on one a dependency already declares
   (a rule that renames as it moves, or `kept`).
8. **The shapes**: WP-146's pending `*_stage3` tests pass unignored
   (each asserts the `ownership` finding, its kind, its key and the two
   files); the shape that must stay verified (a rule that renames as it
   moves beside a dependency's entity of the old target name) stays
   verified; S15, S16, S17 (direct first) stay as their stated limit;
   WP-140's pending test that names WP-146 passes; the pitfall rows
   (`spec/pitfalls.md`): the pair `bad`, the pair with `kept` `good`,
   the mirror `bad`, the rename-as-you-move `good`.
9. **What stage 1 left for this package** (`docs/wp/WP-146.md`,
   "Supervisor's handback"):
   - a `fixed` entity whose as-if-owned key cannot be formed is today
     left out of the list. It is listed with no key and **reported**
     (a counter and a line of the report; the same for a `made` entity
     with no `post`): an entry the fold cannot join is not an entry
     that joined nothing. Decide whether one forbids `verified` (the
     ruling's rule says what one observer that saw every declaration
     would say; an entity nobody can key cannot be shown to agree) and
     say why.
   - a class member's `post` keeps its class's **mapped** key. The
     supervisor accepted it without a case. The reviewer builds the
     case: a member of a class a rule moves, the same member held as a
     dependency's by another observer, both orders; the join must find
     it or the landed file says why there is nothing to find.
   - the mutation "the anonymous-namespace check dropped" was
     equivalent **at this pin**. Re-run it after any move of the Kiln
     pin and record the answer.
10. **`spec/verify.md`**: §2.1's three holes (which this closes, which
   stay), a new §9.6 (the lists, the two joins, the fold, fail closed),
   §8's limits, "Open questions"; `spec/model.md` §8; `spec/exec.md`
   where the run's folds are listed.

## Tests

The fold from constructed lists: each join alone, both together, an
entry on one side only, the same conflict from many observers counted
once with the right least position, both orders of observers, a
selection. The record: round trip, a corrupt blob, a missing blob, a
blob of another id. End to end through `slip verify`: every shape of
WP-146. Mutations: the join on T only, on M only; M joined on `key`
instead of `post` (the rename-as-you-move shape turns to a finding);
a missing list read as empty; a list of a shard that is not `ok`, or
not this run's, folded; "first" by arrival and not by plan position;
the conflict not counted in `combine`; `apply --write` not refusing.

## Rules

`docs/AGENTS.md`. The gate is the full `cargo xtask ci`, once per
stage. Second review after stage 3 (trusted base). The reviewer's
questions: a run with a conflict that says `verified` or writes; a run
without one that is refused; a fold whose answer depends on the order
or number of workers.

## Done when

Stage 2: the gate passes, the section is written and checked, the
verdict of every existing test is unchanged, the corpus command is
handed over. Stage 3: the gate passes with `main` merged in; every
shape gives its answer; the report's section is in a golden.

### Summary of Stage 2 changes

1. **Section 35 (`ownership`) and `OwnershipList` blob format (`crates/slip_model`):**
   - Added `Shard::ownership: Option<Vec<Digest>>` (section id 35, critical,
     phase `verify`, status `ok`, strictly ascending blob ids; `SHRD`
     version stays 2).
   - Added `crates/slip_model/src/ownership.rs` and
     `crates/slip_model/src/formats/ownership.rs` implementing
     `OwnershipList` (versioned raw wire blob, `OwnershipList::VERSION = 1`,
     `Store::publish_blob`, `file`, `through`, `made: list<Made>` sorted by
     `(key, post)`, `fixed: list<Fixed>` sorted by `(key, as)`), binary +
     JSON codecs, 8 reader rows with exact offsets and JSON paths.
   - Added goldens (`ownership-list.bin`, `ownership-list.json`,
     `shard-ownership.json`), 2000-case property round-trip test, and
     truncation/byte-corruption/random-input fuzz test in
     `crates/slip_model/tests/ownership.rs`.
   - Updated all `Shard { ... }` struct literals across `crates/` and `xtask/`.
2. **Additive `Fixed.through` in `crates/slip_digest/src/own_lists.rs`:**
   - Added `pub through: Vec<u8>` to `slip_digest::own_lists::Fixed` so
     `OwnershipList.through` records the first read-only includer when an
     owned header is read-only by the include-chain rule alone (S9),
     leaving it empty otherwise. Inert for all digests, rule use, and verdicts.
3. **Fail-closed presence agreement (`crates/slip_verify/src/run.rs`):**
   - `Report::ours` requires section 35 on every `ok` verify shard of a run
     with non-empty rules (empty `[]` when the observer has no entries) and
     forbids it when rules are empty. Missing or unexpected section 35
     rejects the shard as not this run's (`Failed`).
   - Every existing test's verdict is unchanged; `combine`, report output,
     and all `*_stage3` tests remain untouched.
4. **Writer, worker dedup cache, and counters (`crates/slip_cli`):**
   - `verify_job::verify_caching` (called by `VerifyTask::run`, with
     `verify_job::verify` delegating with a fresh cache) groups `output.made`
     by `(file, b"")` and `output.fixed` by `(file, through)`, publishes
     each encoded `OwnershipList` blob via `Store::publish_blob` unless its
     id is already in `VerifyTask::published`, attaches sorted ids as
     section 35, and emits deterministic per-shard counters
     `verify.ownership.made`, `verify.ownership.fixed`,
     `verify.ownership.lists`, and `verify.ownership.bytes` (only when rules
     are non-empty).
