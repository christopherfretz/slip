## Scope

`spec/api.md` §9 (the cost table) and §7.6 rule 4; `spec/harness.md` §7.
The cost table of the specification is from Kiln's microbenchmarks. This
package replaces each row by a measurement of Slip's own and makes the
transform path visible in the performance records, so that a regression
in the host or in Kiln's session shows on the commit that causes it.

1. **Counters**, deterministic, in the run output and so in a map
   shard's counters, where `cargo xtask perf record` sums them into the
   baseline with no change to the harness (`spec/harness.md` §7.1):
   `api.runs`, `api.runs.failed`, `api.host_calls`, `api.steps`,
   `api.edits`, `api.reports`, `api.op.<name>` per operation,
   `api.unresolved_spelling_matches`.
2. **Times**, not deterministic, so not counters: the worker reports per
   job the nanoseconds spent compiling the transform (zero after the
   first job of a process), in the run, and building each index. They go
   where `spec/exec.md` puts a job's `cpu_ns` and `peak_rss`; this
   package proposes the two fields and the supervisor decides whether
   `spec/model.md` §9 gains them (hand back before coding if not).
3. **A microbenchmark as a test that prints**:
   `crates/slip_script/tests/cost.rs`, ignored by default, run by hand
   and at release candidates: an empty run; one host call of each
   convention; `lookup` of an absent and of a present name;
   `references_to` and `calls_to` cold and warm on a large snippet;
   `swap_arguments.cpp` per call site; compiling each example. It prints
   one line per row in the form of §9's table.

## Interface

The counters' names. The two fields of rule 2, if accepted.

## Tests

A unit test checks that every operation of `spec/api.md` §3.2 has a
counter name and that a run's counters are equal across two runs.

## Done when

The first measurements are in `spec/landed/api/WP-093.md` (numbers,
machine, commit), beside the table of `spec/api.md` §9 they replace.

## Out of scope

The corpus run (WP-094). A gate on measured time: the host is shared
(`spec/harness.md` "Open questions").
