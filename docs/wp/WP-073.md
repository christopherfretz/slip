# WP-073 — rename: dependent names and members of class templates

- Status: done

- Track: F
- Needs: WP-071

## Scope

`spec/edits.md` §9.4 and the follower "a member of a class template
specialisation" of §9.2, in two files of `slip_refactor` that this
package owns: `src/rename/dependent.rs` and `src/rename/spec_members.rs`.

Each part waits for something of Kiln's
([KF3](../requests/KF3-location-utilities.md) §5 says where each
follow-up stands), and each can land without the others. A part whose
follow-up is not in the pin stays as the core wrote it, with its tests
present and marked pending with the follow-up's name:

| Part | Needs from Kiln | Without it |
|---|---|---|
| A. The unqualified callee of a dependent call (§9.4 row 1): the declarations found at the definition give `replace` with a literal piece and a `changed` entry (key: `Keys::unit_of` the enclosing declaration, then `Keys::key_id`; place: the name token; reason `dependent name <old name>`; no entry if the holder has no key), or `keep`, or `refuse(mixed_set)` | K-a: from a dependent entry to its expression, by location ([KR1 amendment 1](../requests/KR1-amendment-1.md) §2, sent) | `unresolved` |
| B. A member of a class template referred to in an explicit instantiation or specialisation of the class | Kiln's stage 3 `SpecTarget` (WP-1932), where the declaration extents do not already give the name | the subject is `unreachable` |
| C. Members of class templates: a member of a class template is a seed; each member of an instantiated specialisation whose key has the old name is a follower with `of` the template's member | nothing for the followers themselves; K-e (stage 4) for the references inside patterns that are dependent | the core's `unsupported` |
| D. Any other dependent name (§9.4 row 2): per instantiated specialisation, the entity the name resolved to; a `replace` is written as in A | K-e: stage 4 (Kiln WP-1933) | `unresolved` |

Part A is the one Demo 2's fourth exhibit waits for (`llvm::PowerOf2Ceil`
in `llvm/ADT/DenseSet.h`, `docs/demos/demo-2.md` §2.4); none is on the
path of the two accepted targets.

**A decision this package does not make.** Part A exempts the pattern's
unit: its `changed` entry is in force when the edit is accepted
(`spec/edits.md` §6.2). "Open questions" there proposes a spelling rule
that would exempt nothing and needs a change to `spec/digest.md`. If the
supervisor has settled that before this package starts, part A follows
what was settled; if not, it implements §9.4 as written and the report's
`exempt` lines are its honesty. What an exemption does not withdraw:
every spelled piece inside the exempt unit is still checked
(`spec/verify.md` §10).

## Interface

The hooks `docs/wp/WP-071.md` fixed:

```rust
pub(crate) fn dependent::claim(ctx: &mut Ctx<'_, '_, '_>, name: &slip_kiln::written::DependentName);
pub(crate) fn spec_members::collect(ctx: &mut Ctx<'_, '_, '_>);
```

and nothing public. `dependent::claim` is called for every entry of
`slip_kiln::written::dependent_names` (`docs/wp/WP-067.md`); it must
locate no token whose entry it can dismiss by its role or its spelling.

## Tests

Directories under `crates/slip_refactor/tests/rename/`, as the core's,
one per row of each part's table cell, and:

- A: a dependent call whose definition-context set is all subjects, none,
  and mixed; the same call instantiated with a type whose
  argument-dependent lookup finds a non-subject of the old name (the
  claim is `replace`: the test's `expect.txt` says so, and the transform
  test of `docs/wp/WP-078.md` shows the run not verifying); the
  `changed` entry of each `replace`, and its absence for a holder
  without a key;
- C: a member function, a static data member and a member template of a
  class template; an explicit and a partial specialisation of the class
  with its own member of that name (a different entity, linked to
  nothing: `keep`, stated); two instantiations in one observer (two
  followers, one `of`);
- D: `T::f()`, `x.f()` and `x->f()` with `x` dependent: instantiated
  with subjects only, with none, with both (`mixed_instances`), and not
  instantiated (`unresolved`).
