# WP-017 — the comparison on differences; `GroupSum.indeterminate`

- Status: todo
- Milestone: M1
- Track: C
- Needs: WP-015, WP-016
- Size: M

## Scope

`spec/verify.md` §4, §4.1 and §6 and `spec/digest.md` §11 were amended
after WP-016 showed that restricting the comparison to the groups whose
sums differ was not exact (`docs/wp/WP-016.md` "Handback"). This package
brings `slip_model` and `slip_verify` to the amended text. Read both specs
as they are now, then `spec/landed/model/WP-015.md` and
`spec/landed/verify/WP-016.md` (what the code does today).

Trusted base: no dependency added, no wildcard arm over an enumeration of
the model, every sentence of §4 and §4.1 with a test that fails without it.

## Part 1 — `slip_model`

- `digests::Group` gains `pub indeterminate: u64` (after `count`): the
  number of the group's units with the indeterminate flag.
- `tu_digest` covers it: per group `uv(class)`, `bytes(file)`, `uv(count)`,
  `uv(indeterminate)`, `digest`. `SCHEME` stays 1 (nothing is released).
- `formats/digests.rs`: the field in the binary form (after `count`) and in
  JSON (`"indeterminate"`, after `"count"`). Two invariants, placed after
  rule 5 and after rule 6c in the order of checks, each with its offset
  (the `indeterminate` field) and path
  (`sections.digests.groups[i].indeterminate`):
  `indeterminate ≤ count`; and, for a group with a unit list,
  `indeterminate` is the number of units with the flag.
- Update the hand-written files, goldens and the table of
  `spec/landed/model/WP-015.md` (edit that file in place: it is the
  section's landed description; say at its top that WP-017 added the
  field).

## Part 2 — `slip_verify::compare`

- **§4 step 2 on differences.** Per key not set aside by step 1:
  `R = P − Q`, `A = Q − P` as multisets of digests. Both empty: nothing.
  Both non-empty: `changed` (exemption list `changed`). Only `R`:
  `removed` (`removed`). Only `A`: `added` (`created`).
- **§4 step 3.** A derived key with an indeterminate unit in either image
  is `derived_indeterminate`, also when the other image does not have the
  key. Else both `R` and `A` non-empty: `derived_changed`; only `R`:
  counted in `only_pre`; only `A`: counted in `only_post`.
- **§6 `pre`, `post`, `file`** as now defined there: `pre`/`post` from
  `R`/`A` when it has exactly one element (for the two indeterminate
  kinds: the key's one indeterminate unit in that image); `file` from the
  first group, in `(class, file)` order, among the groups whose unit lists
  are not the same in both images, that holds a unit of the key (pre-image
  first); for the indeterminate kinds, the first group holding an
  indeterminate unit of the key (pre-image first). `compare_groups`
  therefore has to know which of the groups it was given differ between
  the images: pair them by `(class, file)`.
- **§4.1.** `at_sums` returns `Equal` only when the `tu` digests are equal
  and every `indeterminate` of both images is 0. Otherwise `Differing`
  lists `G`: every `(class, file)` whose sum (`count`, `indeterminate`,
  `digest`) is not the same in both, and every group of either image with
  `indeterminate > 0`. So `Differing` can be returned with equal `tu`
  digests.
- **`verdict_at_sums` is removed**, with its unnamed findings: `Equal` is
  `verified` (a function `verified(pre_shard, rules) -> Verdict` replaces
  it), and everything else goes through `compare_groups`.
  `Finding::key` is always `Some` from this crate.
- `compare_groups` additionally rejects a group whose `indeterminate` is
  not the number of its flagged units (`CompareError::IndeterminateMismatch`).

## Tests

- `tests/compare.rs`: update to the amended rules; add, each named for its
  sentence: two equal copies against one is `removed` and the `removed`
  exemption prevents it, the `changed` one does not; one against two is
  `added`; `{d1, d2}` against `{d1}` is `removed` with `pre = d2`;
  `{d1}` against `{d2, d3}` is `changed` with `pre = d1`, `post` absent;
  a derived indeterminate key on one side only is a finding and is not
  counted in `only_pre`/`only_post`; the three `file` cases (a key with a
  unit in a group that differs and one in a group that does not; a moved
  unit beside a real difference; an indeterminate key); `at_sums` with
  equal `tu` and an indeterminate unit is `Differing` naming that group.
- `tests/groups.rs`: **the property the WP-016 brief asked for now holds
  and is asserted on every generated pair, with no pair set aside**:
  `compare_groups` over all groups of both images equals (the whole
  `Comparison`: findings with every field, counts, `used`)
  `compare_groups` over the groups of `at_sums`'s `Differing` list; and
  `Equal` exactly when every group has the same sum in both images and no
  group has an indeterminate unit, in which case the full comparison has
  no finding, no count and nothing used. Keep the
  generator's coverage assertions; it must go on producing keys with
  units inside and outside `G`, indeterminate units in unchanged groups,
  and one-sided derived keys of both sorts. At least 10,000 pairs.
  Remove the three tests that pinned the divergence.

  mutations that still apply, plus one for each new sentence above) and
  report it as WP-016 did.
- `crates/slip_model/tests/sections.rs`: the two new invariants violated
