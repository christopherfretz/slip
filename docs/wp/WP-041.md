# WP-041 — slip_digest: what a unit's own spellings hold beyond their profiles

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-036
- Size: M
- Parallel with: WP-040, WP-045, WP-046, WP-049

## Scope

`spec/digest-kinds.md` §4.2 rule 1 and §4.4 "The mark". A dependent type
is canonical by **profile**, and Kiln's profile of an unresolved name
does not hold the declarations lookup found for it where the template
was written. Those declarations are meaning: they are what overload
resolution starts from when the template is instantiated. The digest
writes the profile as the type's bytes (so that which of two equivalent
spellings Kiln met first changes nothing) and, since `docs/wp/WP-036.md`,
marks every type whose profile left such a fact out; a unit that writes
a marked type, or such a profile directly, is indeterminate with
`Pending(Spelling)`.

This package closes that area: **the unit writes, from its own spelling,
what the profile left out**, and `Area::Spelling` is removed.

The fact is the unit's and not the type's because two declarations can
write one canonical type through two spellings that found two sets:

```cpp
void f(int);
template <class T> auto g(T t) -> decltype(f(t));   // found { f(int) }
void f(long);
template <class T> auto h(T t) -> decltype(f(t));   // found { f(int), f(long) }
```

`g` and `h` have one return type by profile. Kiln keeps the first
spelling's expression for the canonical type (`TypeContext::expr_origins`,
`arg_origins`; `kiln_ast/src/types/context.rs:1450-1495`) and each
declaration's own written type keeps its own expression: a `Decltype`,
a dependent-sized array or vector, and a `TemplateSpecialization` are
interned by their expression or written argument list
(`kiln_ast/src/types/canon.rs`, `decltype_type`, `dependent_sized_array`,
`template_specialization`), so two spellings are two written types with
one canonical type.

In scope:

1. **The left-out facts of an expression**: one function that, for an
   expression walked in profile mode, yields in the order of the walk
   every fact `expr_profile.rs` leaves out (today one kind: the found
   set of an `UnresolvedLookupExpr`, `expr_profile.rs` where it raises
   `Walk::left_out`). If the survey of rule 6 finds another kind, it is
   a second variant of the same list, not a second mechanism.
2. **The spellings of a written type**: one function that walks a type
   **as written** (through sugar, not its canonical type) and yields the
   left-out facts of every expression in it, in the order of the type's
   structure: a `decltype`'s operand, a dependent array or vector bound,
   an expression argument of a `TemplateSpecialization` or of a
   dependent name's argument list, the expressions of a function type's
   exception specification and of its parameters' and return types,
   recursively through pointers, references, qualifiers, packs and
   elaborations.
3. **Where a unit writes them.** At each of the three places that raise
   `Pending(Spelling)` today, the unit stream gets, after what it writes
   now, the list of rule 1 or 2 read from the unit's own spelling:
   - `Walk::absorb_type` in a unit stream (`in_key == 0`,
     `type_nesting == 0`) for a marked type: the spellings of the
     written type the caller holds. Every caller that can reach it with
     a marked type must pass the declaration's written type; a caller
     that has only a canonical type (a type Kiln computed, not one the
     unit wrote) keeps a cause (rule 5);
   - `expr_dep::profile_expr` written straight into a unit stream (a
     template argument, a table row): the left-out facts of that very
     expression, which is the unit's own;
   - `templ::partial_spec_info`: the left-out facts of the partial
     specialisation's arguments as written
     (`TemplateTables::args_as_written`, `kiln_ast/src/templates.rs:412`),
     not of the canonical list.
4. **Sugar that names another unit stops the walk.** A typedef, an alias
   or an alias template specialisation in a written type is a reference
   to its unit, which writes its own spellings: the walk writes the
   `Ref` of that entity in the list and does not descend. (The type's
   bytes do not change: the canonical type is digested as today. The
   `Ref` in the list says where the left-out fact is written.) Without
   this a use through `using R = decltype(f(T()));` would either hide
   the alias's found set or copy it into every user.
5. **What stays indeterminate, with its own cause.** A marked type for
   which the unit has no spelling of its own (a deduced type, a type
   Kiln built by substitution whose expressions it did not keep per
   declaration, a canonical-only argument list) is
   `Unaccounted("spelling/<site>")`, one word per site, counted, and
   listed in the landed file with a source that reaches it. There is no
   `Pending(Spelling)` after this package. If more than a handful of
   pair tests end up there, stop and report before going on: the design
   then needs another look.
6. **The survey.** `expr_profile.rs` is read row by row against the full
   walk (`expr.rs`, `expr_dep.rs`): every field the full walk writes and
   profile mode does not is either (a) not meaning (say why), (b) in the
   profile's words in another form, or (c) a left-out fact, which then
   raises the mark and is in rule 1's list. The table is in the landed
   file. `Walk::left_out` is raised in exactly the places the list has
   an entry for; a test compares the two counts on every pair-test
   snippet.

Out of the mark's reach and not changed: a key ignores the mark and the
list (two declarations are one entity by [temp.over.link] whatever their
found sets, and a difference in the sets is a difference of the units).

Files: `crates/slip_digest/src/expr_profile.rs`, `expr_dep.rs`,
`types.rs`, `templ.rs`, the callers of `absorb_type` in `decl*.rs`; new
`crates/slip_digest/src/spelling.rs` if the two functions want a home;
`lib.rs` (`Area::Spelling` removed); `spec/digest-kinds.md` §4.2 rule 1,
§4.4 "The mark", "Hazards accepted for now"; `spec/digest.md` where it
lists the areas.

## What is decided

1. **Encoding of a found set**: a count and the `Ref` of each
   declaration found, as a **set** (sorted by the bytes of the `Ref`,
   duplicates removed): the order in which lookup listed them is not
   meaning. A declaration found through a using-declaration is written
   as the full walk writes it for an `UnresolvedLookupExpr` outside a
   type (one reading: use that function, do not write a second). An
   empty set is written as a count of 0 and is not a left-out fact (it
   does not raise the mark today).
2. **Encoding of a unit's list**: a count, then per left-out fact its
   kind tag and its payload, in walk order. A unit that writes no marked
   type and no marking profile writes nothing more than today, so no
   digest of such a unit changes and no golden moves; a test pins that
   on the whole pair-test corpus (the bytes of every unit that was not
   `Pending(Spelling)` are unchanged by this package).
3. **The walk order is the type's structure, not Kiln's first
   spelling.** Two spellings with one profile have their unresolved
   names in the same positions (the profile holds the names), so the
   lists of two equivalent spellings line up entry for entry and differ
   only in the sets.
4. **Instantiated declarations.** A member of an implicit instantiation
   whose type is still dependent (a member template of `A<int>`) has a
   written type Kiln made by substitution. If its expressions are the
   declaration's own (a fresh `ExprId` per substitution), rule 2 applies
   as it stands; if Kiln reuses the pattern's or the first spelling's,
   say which, with the place in Kiln, and apply rule 5. Decide by
   reading `kiln_sema/src/templ/subst/`, and pin with a test either way.

## Interface

No public interface changes. Internally:

```rust
// one reading of "what the profile left out", used by all three sites
pub(crate) fn left_out_of_expr(w: &mut Walk<'_>, s: &mut Stream, e: ExprId);
pub(crate) fn left_out_of_type(w: &mut Walk<'_>, s: &mut Stream, written: QualType);
```

## Tests

- Un-pend every `# needs: spelling` pair test
  (`differ/_/dependent-decltype-own-lookup-set`,
  `differ/_/dependent-decltype-earlier-spelling-added`,
  `differ/TemplateTables/size_of_pack_partial`, and whatever
  `docs/wp/WP-036.md`'s second round added): each passes with the
  expectation written in it. If one cannot, it is rule 5's and the
  landed file says why.
- New pair tests, one per site and per shape of rule 2: the example of
  the Scope (`g` and `h`: adding `f(long)` between them changes `h`
  only, and adding it before both changes both); the found set in an
  array bound, in a `noexcept(…)` of a function type, in a non-type
  template argument of a `TemplateSpecialization` used as a parameter
  type, in a default template argument, in a base specifier, in a
  partial specialisation's arguments, in a variable template's type, in
  an alias (`using R = decltype(f(T()))`: the alias's unit changes and a
  user of `R` does not), in a requires-clause.
- **Order independence** (the reason the mark exists): for each new
  test, the same two declarations in the other order give the same
  digests for both units (a unit test over the walk, since a pair test
  cannot reorder).
- `equal`: two spellings of one profile with the same found set
  (`decltype(f(t))` and `decltype((f)(t))` if the profile makes them
  one; otherwise the nearest pair that it does) are equal.
- Rule 6's count test; decision 2's "no other unit changed" test.
- The ratchet `tests/tables/untested.txt` shrinks or stays; `Area`
  has no `Spelling`.
- Mutations: at least ten, among them: the set written in lookup order;
  the list read from the canonical type (`expr_origin`) and not the
  written one; an alias descended into; the `Ref` of rule 4 dropped;
  one of the three sites left without its list; a shape of rule 2 not
  walked. Each must fail a test.

pair test is `# needs: spelling`; the landed file
`spec/landed/digest-kinds/WP-041.md` has the survey table of rule 6 and
the list of rule 5's sites; the spec sections named above say what the
code does. The package is in the trusted base: it gets the second,
independent review (`docs/AGENTS.md` "Review gates").

## Out of scope

Local entities in profiles (`docs/wp/WP-040.md`). The remaining rows of
dependent expressions and the expanded statement (`docs/wp/WP-049.md`).
Anything in Kiln: if a spelling is not kept per declaration, that is a
finding for Kiln and rule 5 here.
