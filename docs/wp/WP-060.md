# WP-060 — slip_model: the transform request and the shard sections of a transform

- Status: todo
- Milestone: M2
- Track: A

- Parallel with: WP-064, WP-065

## Scope

The formats a transform's map and verify shards carry, and the request
that starts a transform:

- `spec/edits.md` §2.1 (`Ownership` and "covers"), §3 (`TRFM`), §4 (the
  `edits` section, with every invariant of §4.4);
- `spec/verify.md` §9, the records only: `RuleUse`, `Use`, `Binding`;
- `spec/model.md` §5.1 (the kind `TRFM`) and §8 (sections 17 `edits`,
  24 `binding`, 25 `rule_use`, each with its phase).

Files. New: `crates/slip_model/src/{transform.rs, edits.rs, agreement.rs}`,
`crates/slip_model/src/formats/{transform.rs, edits.rs, agreement.rs}`,
`crates/slip_model/tests/edits.rs`. Changed: `src/lib.rs`, `src/shard.rs`,
`src/formats/mod.rs`, `src/formats/shard.rs`, `tests/sections.rs`. `Shard`
gains three fields, so every place in the workspace that builds a `Shard`
gains three `None`s: that one mechanical line per place is in scope, in
whatever crate it is; nothing else outside `slip_model` is.

This package starts now. It needs nothing of M1 and nothing of Kiln.

## Interface

Field for field as the spec; a record's fields in the spec's order, lists
as `Vec`, `bytes` and `path` as `Vec<u8>`, `uv` as `u64`.

```rust
// slip_model::transform
pub struct Ownership { pub owned: Vec<Vec<u8>>, pub readonly: Vec<Vec<u8>> }
impl Ownership {
    /// spec/edits.md §2.1: the longest covering entry is in `owned`.
    pub fn is_owned(&self, real_path: &[u8]) -> bool;
}
pub enum TransformKind { Rename = 1 }
pub enum TargetKind { Any = 0, Function = 1, Variable = 2 }
pub struct Rename { pub target: Vec<Vec<u8>>, pub kind: TargetKind, pub new_name: Vec<u8> }
pub struct Transform { pub kind: TransformKind, pub ownership: Ownership, pub rename: Option<Rename> }
// KIND b"TRFM", VERSION 1; to_bytes, from_bytes, to_json, from_json, validate
// as every container of `formats` (`format_impl!`, formats/mod.rs:334).

// slip_model::edits
pub type KeyId = Digest;
pub enum Role { Seed = 0, Candidate = 1, Follower = 2 }
pub mod subject_flags { pub const READ_ONLY: u64 = 1; pub const UNSUPPORTED: u64 = 2;
                        pub const NAME_TAKEN: u64 = 4; pub const UNREACHABLE: u64 = 8; }
pub struct Subject { pub id: KeyId, pub key: Key, pub renamed: Name, pub role: Role,
                     pub of: Vec<KeyId>, pub flags: u64, pub display: String }
pub struct Link { pub a: KeyId, pub b: KeyId }
pub enum Stance { Replace = 0, Keep = 1, Refuse = 2, Unresolved = 3 }
/// Not re-exported at the crate root: `slip_model::Reason` is the plan's.
pub enum Reason { None = 0, MacroBody = 1, Pasted = 2, Crossing = 3, NotAFile = 4, NotOwned = 5,
                  FileRecoded = 6, NotPlain = 7, MixedSet = 8, MixedInstances = 9 }
pub mod claim_flags { pub const DEPENDENT: u64 = 1; }
pub mod tiers { pub const T0: u64 = 1; pub const T1: u64 = 2; pub const T2: u64 = 4;
                pub const T3: u64 = 8; pub const X: u64 = 16; }
pub struct MacroSite { pub name_start: u64, pub name: Vec<u8> }
pub struct Claim { pub file: u64, pub start: u64, pub end: u64, pub rule: u64, pub slot: u64,
                   pub stance: Stance, pub text: Vec<u8>, pub subjects: Vec<KeyId>, pub reason: Reason,
                   pub group: u64, pub flags: u64, pub holders: Vec<KeyId>, pub tiers: u64,
                   pub macro_site: Option<MacroSite>, pub votes: u64 }
pub struct Edits { pub scheme: u64, pub transform: Digest, pub files: Vec<FileRef>,
                   pub subjects: Vec<Subject>, pub links: Vec<Link>, pub claims: Vec<Claim> }
impl Claim {
    /// The sort key of §4.2 as an `Ordering`.
    pub fn cmp_key(&self, other: &Claim) -> std::cmp::Ordering;
}
impl Edits {
    /// Sorts `claims`, joins derivations equal in the sort key (§4.3: votes
    /// summed, tiers or-ed, the least `MacroSite`), sorts the other lists.
    /// What a transform calls before it hands its claims over.
    pub fn normalise(&mut self);
}

// slip_model::agreement
pub struct Use { pub rule: u64, pub via: u64, pub direct: u64 }
pub struct RuleUse { pub rules: Digest, pub uses: Vec<Use> }
pub struct Binding { pub overlay: Option<Digest>, pub declared: Digest }

// slip_model::Shard gains, after `verdict`:
pub edits: Option<Edits>,        // section 17; phase map only
pub binding: Option<Binding>,    // section 24; phase verify only
pub rule_use: Option<RuleUse>,   // section 25; phase verify only, status ok
```

Validation follows the existing sections (`formats/shard.rs`,
`formats/digests.rs`): the invariants of `spec/edits.md` §4.4 in the
table's order, each error with the byte offset and the JSON path the
table gives. A section in a shard of the wrong phase is rejected as
`spec/model.md` §8 says. `TRFM` validation: §3's rules on `target` and
`new_name` (the list of keywords is every keyword of C++98 to C++26, in
one table in `transform.rs` with the standard's clause as a comment), and
§2.1's on `Ownership`.

## Tests

- `crates/slip_model/tests/edits.rs`: binary and JSON round trips of
  `TRFM` and of a shard with an `edits` section; each invariant of §4.4
  broken alone gives its offset and path; the order in which two broken
  invariants are reported; `normalise` (derivations that agree, that
  differ in each field of the key in turn; `macro` least by `name_start`
  then `name`); `is_owned` (an entry equal to the path, a prefix that
  ends inside a component, `readonly` inside `owned` inside `readonly`).
- `crates/slip_model/tests/sections.rs`: the three sections in the
  registry; each in a shard of the wrong phase; `binding` and `rule_use`
  round trips and their invariants (`uses` ascending, no `Use` with both
  counts 0).
- The existing golden and round-trip tests of shards still pass with the
  three fields absent: a shard written before this package is byte for
  byte what it was.
