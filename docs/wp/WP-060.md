# WP-060 — slip_model: the transform request and the shard sections of a transform

## Scope

The formats a transform's map and verify shards carry, and the request
that starts a transform:

- `spec/edits.md` §2.1 (`Ownership` and "covers"), §3 (`TRFM`, both
  kinds: `rename` and `script`), §4 (the `edits` section: subjects,
  claims with pieces, groups, reports, `changed`, `renamed`, the record
  of a failed run), with every invariant of §4.7;
- `spec/verify.md` §9.1, the records only: `RuleUse`, `Use`, `Binding`;
  §10.4, the record only: `Spellings`;
- `spec/model.md` §5.1 (the kind `TRFM`) and §8 (sections 17 `edits`,
  24 `binding`, 25 `rule_use`, 26 `spellings`, each with its phase and
  the statuses it is allowed in).

Files. New: `crates/slip_model/src/{transform.rs, edits.rs, agreement.rs,
spellings.rs}`, the same four names under `crates/slip_model/src/formats/`,
`crates/slip_model/tests/edits.rs`. Changed: `src/lib.rs`, `src/shard.rs`,
`src/formats/mod.rs`, `src/formats/shard.rs`, `tests/sections.rs`. `Shard`
gains four fields, so every place in the workspace that builds a `Shard`
gains four `None`s: that one mechanical line per place is in scope, in
whatever crate it is; nothing else outside `slip_model` is.

**Starts now.** It needs nothing of Kiln. M1's packages that are being
implemented (`docs/wp/WP-050.md`, `docs/wp/WP-055.md`) build `Shard`
literals too: merge `origin/main` before handing back and give every
literal that is new there its four lines.

What an `edits` section holds is what a run of a programmable transform
hands over (`spec/api.md` §7.6; `spec/edits.md` §4.8 is the mapping) and
what the native rename produces. `slip_script::shard::encode`
(`docs/wp/WP-092.md`) and `slip_refactor` (`docs/wp/WP-071.md`) both
write the types of this package.

## Interface

Field for field as the spec: a production is a Rust type of the same
name, its fields in the spec's order and with the spec's names (`macro`
is `macro_site`); `list` is `Vec`, `opt` is `Option`, `bytes` and `path`
are `Vec<u8>`, `str` is `String`, `uv` is `u64`.

```rust
// slip_model::transform                                        spec/edits.md §2.1, §3
pub struct Ownership { pub owned: Vec<Vec<u8>>, pub readonly: Vec<Vec<u8>> }
impl Ownership {
    /// §2.1: the longest covering entry is in `owned`.
    pub fn is_owned(&self, real_path: &[u8]) -> bool;
}
pub enum TransformKind { Rename = 1, Script = 2 }
pub enum TargetKind { Any = 0, Function = 1, Variable = 2 }
pub struct Rename { pub target: Vec<Vec<u8>>, pub kind: TargetKind, pub new_name: Vec<u8> }
pub struct Script { pub id: Digest, pub file: Vec<u8>, pub options: Vec<Vec<u8>>,
                    pub steps: u64, pub bytes: u64, pub depth: u64 }
pub struct Transform { pub kind: TransformKind, pub ownership: Ownership, pub indivisible: bool,
                       pub rename: Option<Rename>, pub script: Option<Script> }
// KIND b"TRFM", VERSION 1; to_bytes, from_bytes, to_json, from_json, validate
// as every container of `formats` (`format_impl!`).

// slip_model::edits                                            spec/edits.md §4
pub type KeyId = Digest;
pub struct Place { pub file: u64, pub lo: u64, pub hi: u64 }
pub enum Role { Seed = 0, Candidate = 1, Follower = 2 }
pub mod subject_flags { pub const READ_ONLY: u64 = 1; pub const UNSUPPORTED: u64 = 2;
                        pub const NAME_TAKEN: u64 = 4; pub const UNREACHABLE: u64 = 8; }
pub struct Subject { pub id: KeyId, pub rule: Option<Rule>, pub role: Role,
                     pub of: Vec<KeyId>, pub flags: u64, pub display: String }
pub struct Link { pub a: KeyId, pub b: KeyId }
pub enum Stance { Replace = 0, Keep = 1, Refuse = 2, Unresolved = 3 }
pub enum Piece { Literal(Vec<u8>), Copy(Place), Spelled { key: KeyId, text: Vec<u8> } }   // tags 0, 1, 2
pub enum Reason { None = 0, MacroBody = 1, Pasted = 2, Crossing = 3, NotAFile = 4, NotOwned = 5,
                  FileRecoded = 6, NotPlain = 7, MixedSet = 8, MixedInstances = 9 }
pub mod tiers { pub const T0: u64 = 1; pub const T1: u64 = 2; pub const T2: u64 = 4;
                pub const T3: u64 = 8; pub const X: u64 = 16; }
pub struct MacroSite { pub name_start: u64, pub name: Vec<u8> }
pub struct Claim { pub file: u64, pub lo: u64, pub hi: u64, pub stance: Stance, pub pieces: Vec<Piece>,
                   pub subjects: Vec<KeyId>, pub reason: Reason, pub tiers: u64,
                   pub macro_site: Option<MacroSite>, pub votes: u64, pub notes: Vec<Vec<u8>> }
pub enum Severity { Note = 0, Review = 1, Error = 2 }
pub struct Report { pub place: Option<Place>, pub severity: Severity, pub message: Vec<u8>, pub attached: bool }
pub struct Changed { pub key: KeyId, pub place: Place, pub reason: Vec<u8> }
pub enum FailureKind { Uncaught = 0, NotConstant = 1, StepBudget = 2, MemoryBudget = 3,
                       DepthLimit = 4, HostFailure = 5 }
pub struct SourcePlace { pub file: Vec<u8>, pub line: u64, pub column: u64 }
pub struct HostRefusal { pub function: String, pub errc: String, pub message: String, pub subject: Option<Place> }
pub struct Failure { pub kind: FailureKind, pub message: String, pub place: Option<SourcePlace>,
                     pub rendered: String, pub refusal: Option<HostRefusal> }
pub struct Edits { pub scheme: u64, pub transform: Digest, pub failure: Option<Failure>,
                   pub files: Vec<FileRef>, pub subjects: Vec<Subject>, pub links: Vec<Link>,
                   pub claims: Vec<Claim>, pub groups: Vec<Vec<u64>>, pub reports: Vec<Report>,
                   pub changed: Vec<Changed>, pub renamed: Vec<Rule> }
impl Piece {
    /// The order of §4.2: by tag, then by fields; bytes and ids by their bytes.
    pub fn cmp_key(&self, other: &Piece) -> std::cmp::Ordering;
}
impl Claim {
    /// The sort key of §4.2, `(file, lo, hi, stance, pieces)`, as an `Ordering`.
    pub fn cmp_key(&self, other: &Claim) -> std::cmp::Ordering;
}
impl Edits {
    /// What a producer calls before it hands the section over. Sorts
    /// every list in its order; joins claims equal in the sort key as
    /// §4.3 says (votes summed, tiers or-ed, the least `MacroSite`, the
    /// least reason other than `none`, `subjects` and `notes` united);
    /// carries `groups` through the new indices, joins groups that share
    /// a member and drops groups of one (§4.4); removes equal reports,
    /// `changed` entries and rules. The result satisfies §4.7 if the
    /// records did one by one.
    pub fn normalise(&mut self);
}

// slip_model::agreement                                        spec/verify.md §9.1
pub struct Use { pub rule: u64, pub via: u64, pub direct: u64 }
pub struct RuleUse { pub rules: Digest, pub uses: Vec<Use> }
pub struct Binding { pub overlay: Option<Digest>, pub declared: Digest, pub pre: u64 }

// slip_model::spellings                                        spec/verify.md §10.4
pub struct Span { pub first: u64, pub count: u64 }
pub struct Failed { pub index: u64, pub found: Option<KeyId>, pub name: String }
pub struct Spellings { pub seen: u64, pub held: Vec<Span>, pub failed: Vec<Failed> }

// slip_model::Shard gains, after `verdict`:
pub edits: Option<Edits>,            // section 17; phase map, status ok
pub binding: Option<Binding>,        // section 24; phase verify, any status but failed
pub rule_use: Option<RuleUse>,       // section 25; phase verify, status ok
pub spellings: Option<Spellings>,    // section 26; phase verify, status ok
```

`Rule` is `slip_model::keys::Rule` (`crates/slip_model/src/keys.rs:489`),
in the encoding `DECL` gives it; a rule table's order is that of
`spec/verify.md` §2. At the crate root only `Transform`, `Edits`,
`Claim`, `Piece`, `Place`, `Binding`, `RuleUse` and `Spellings` are
re-exported: `Reason`, `Report`, `Failed` and `Failure` are names other
modules of the workspace have too.

Validation follows the existing sections (`formats/shard.rs`,
`formats/digests.rs`): the invariants of `spec/edits.md` §4.7 in the
table's order, each error with the byte offset and the JSON path the
table gives; those of `spec/verify.md` §9.1 and §10.4. A section in a
shard of the wrong phase or status is rejected as `spec/model.md` §8
says. `TRFM` validation: §3's rules (for a rename, on `target` and
`new_name`, with `indivisible` true and no `script`; for a script, no
`rename`; the list of keywords is every keyword of C++98 to C++26, in
one table in `transform.rs` with the standard's clause as a comment),
and §2.1's on `Ownership`.

## Tests

- `crates/slip_model/tests/edits.rs`: binary and JSON round trips of
  `TRFM` of each kind and of a shard with an `edits` section that has
  every record at least once (a claim with each piece, a group, a report
  with and without a place, a `changed` entry, a rule) and of one with a
  `failure`; each invariant of §4.7 broken alone gives its offset and
  path; the order in which two broken invariants are reported;
  `normalise` (derivations that agree; that differ in each field of the
  key in turn, a spelled piece's key included; `macro` least by
  `name_start` then `name`; `notes` united; a group whose members are
  moved by the sort, two groups joined by a shared member, a group
  reduced to one member by a join of two claims); `is_owned` (an entry
  equal to the path, a prefix that ends inside a component, `readonly`
  inside `owned` inside `readonly`).
- `crates/slip_model/tests/sections.rs`: the four sections in the
  registry; each in a shard of the wrong phase and of a status it is not
  allowed in; `binding`, `rule_use` and `spellings` round trips and
  their invariants (`uses` ascending, no `Use` with both counts 0; an
  index twice in `held`, in both lists, more indices than `seen`, two
  spans that touch, a span of count 0).
- The existing golden and round-trip tests of shards still pass with the
  four fields absent: a shard written before this package is byte for
  byte what it was.
