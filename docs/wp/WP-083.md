# WP-083 — slip_script: the subject over Kiln: entities, lookup, structure

- Status: review
- Milestone: M3
- Track: E

## Scope

Can start at Slip's present Kiln revision: it reads only the declaration
arena. Rebase onto WP-081 when that lands (it defines the trait this
implements; until then code against the trait as printed in WP-081).

`spec/api.md` §1 (unit order), §5.1, §5.5 (origin), §6.1 to §6.4.
`KilnSubject<'u>`: the implementation of `Subject` over
`slip_kiln::Unit`, for the methods `is_live`, `kind_bits`, `lookup`,
`identifier`, `display`, `parent`, `parameters`, `declarations`,
`entity_of`, `origin`, `qualified`, `file_len`, `text`, `owned`,
`file_ref`. The rest return "nothing" until WP-085, WP-086 and WP-095.

Decisions already taken in the specification, to implement and not to
revisit:

- An **entity** is the declaration `slip_digest` treats as the entity
  (`Walk::entity`, `crates/slip_digest/src/keys.rs`): the first
  declaration, and for the pattern of a template the template. Implement
  the same two lines here; WP-095 adds the test that the two agree on
  every declaration of the test snippets.
- `lookup` walks declared members with the transparent scopes of §6.1
  rule 3. It builds a per-scope name index on first use, not a global one.
- **Unit order** is the order of first tokens after preprocessing. Use
  WP-084's comparator; until it lands, order by the expansion location's
  (include chain, offset), which is the same thing computed slowly.
- `display` reuses the names `slip_digest` renders (`names.rs`).

## Tests

`crates/slip_script/tests/subject_entities.rs`, on snippets
(`slip_kiln::snippet`), calling the trait directly:

1. §6.1 rule by rule: each transparent scope; each thing not followed;
   each thing not found; overloads in unit order; a name declared in two
   headers and the main file (order follows inclusion); `::`.
2. §6.2: each predicate true and false; an entity that satisfies none.
3. §6.3, §6.4: redeclarations are one entity with several declarations; a
   namespace's bodies; a parameter's parent; a friend declaration; an

4. §5.5: the origin of a function template specialisation, of a member of
   a class template instantiation, of a member specialisation of a member

1. `KilnSubject::new(unit: &slip_kiln::Unit<'u>, owned: &'u (dyn
   Fn(&[u8]) -> bool + Sync))`: `owned` is `Sync`, and the subject keeps
   the unit's parts, not the unit (coordinator's decision after the

3. `KilnSubject::entity_number(DeclId) -> Entity` and
   `kiln_subject::unit_order(sm, a, b)` (WP-084's signature) are public,
   for tests and for WP-085.

**Seen to fail.** Each feature was replaced by a constant answer, one at
a time, and the tests run: transparency off (6 tests fail), friend
targets not followed (1), unit order by raw location (1), every
declaration written (8), origin the entity itself (3), never a
definition (1), no parent (8), no qualified name (1), specialisations
findable (6), written set reduced to "not implicit" (4), template
parameter owners absent (1); `owned` without `Sync` does not compile
`subject_is_sync`. One mutant survives: sorting lookup's answer by
declaration number instead of `entity_order`. Kiln numbers declarations
in parse order, so the two agree on every snippet I could write; the
sort stays because nothing in Kiln promises that order.

**Measurement.** On the corpus's largest unit,
`clang/unittests/StaticAnalyzer/RangeSetTest.cpp` (550 589 declarations;
release build, the `Sync` subject; `measure_lookup_absent`, run with
`SLIP_WP083_DIR`/`SLIP_WP083_ARGV` from the compilation database), the
absent name `llvm::absent_name_wp083` costs 2.28 ms on the first call
(it builds the global namespace's index) and **67 ns per call after**
(1000 calls). `absent_name_wp083`: 26 ns; `std::absent_name_wp083`:
65 ns; `llvm::SmallVector::absent_name_wp083`: 235 µs first (that
class's index), 148 ns after. Under the 1 ms target by four orders of
magnitude. Note: the absent component is a name the unit never interned,
so the walk stops at the symbol table without probing the last index;
an interned name costs one more hash probe per scope (the present
`llvm::errs` costs 1.1 µs on its first call, with the indexes built).

**What is wrong or ambiguous in the spec** (each chosen by intent;
details in the landed file):

1. "Written" (§6.1 r5, §6.4 r3, §5.5) has no definition Kiln answers by a
   flag: Kiln's declaration of an explicit specialisation made by
   deduction before the specialisation is read is neither implicit nor
   an instantiation (`kiln_ast/src/decl.rs:2161`). Chosen: reachable
   through member lists (decision 1).
2. §6.1 r5 says using-declarations and aliases are not *followed*, not
   whether they are *found*. Chosen: found as themselves (decision 4).
3. §6.4 r1 lists no parent for a template parameter, and Kiln's `ctx` of
   one is the enclosing scope. Chosen: its template (decision 11).
4. §6.4 r3 for the global namespace: no body is written. Chosen: empty.
5. §6.2 r3 for a using-declaration, a namespace alias, a partial
   specialisation and an alias template (decision 8).
6. §1 unit order needs a declaration's first token; snippets have no
   extents, so the name is used when Kiln records none (decision 14).

**Needed from `slip_kiln` or Kiln.**

1. `slip_kiln`: a public way to make a `Unit` from a snippet (or the same
   accessors on `snippet::Parsed`), so that `from_parts` can go.
2. WP-084: `unit_order` and the first token of a declaration when extents
   are off. Here only the name location is used then; no range or tier
   code was written.
3. Kiln: a documented order of `DeclId` allocation (parse order), which
   would let lookup drop its sort; and the owner of a template parameter
   as a field, not a scan.
