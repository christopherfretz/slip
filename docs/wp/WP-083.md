## Scope

Can start at Slip's present Kiln revision: it reads only the declaration
arena. Rebase onto WP-081 when that lands (it defines the trait this
implements; until then code against the trait as printed in WP-081).

`spec/api.md` §1 (unit order), §5.1, §5.5 (origin), §6.1 to §6.4.
`KilnSubject<'u>`: the implementation of `Subject` over
`slip_kiln::Unit`, for the methods `is_live`, `kind_bits`, `lookup`,
`identifier`, `display`, `parent`, `parameters`, `declarations`,
`entity_of`, `origin`, `qualified`, `file_len`, `text`, `owned`,
`file_ref`. The rest return "nothing" until WP-085, WP-086 and WP-095.

Decisions already taken in the specification, to implement and not to
revisit:

- An **entity** is the declaration `slip_digest` treats as the entity
  (`Walk::entity`, `crates/slip_digest/src/keys.rs`): the first
  declaration, and for the pattern of a template the template. Implement
  the same two lines here; WP-095 adds the test that the two agree on
  every declaration of the test snippets.
- `lookup` walks declared members with the transparent scopes of §6.1
  rule 3. It builds a per-scope name index on first use, not a global one.
- **Unit order** is the order of first tokens after preprocessing. Use
  WP-084's comparator; until it lands, order by the expansion location's
  (include chain, offset), which is the same thing computed slowly.
- `display` reuses the names `slip_digest` renders (`names.rs`).

## Tests

`crates/slip_script/tests/subject_entities.rs`, on snippets
(`slip_kiln::snippet`), calling the trait directly:

1. §6.1 rule by rule: each transparent scope; each thing not followed;
   each thing not found; overloads in unit order; a name declared in two
   headers and the main file (order follows inclusion); `::`.
2. §6.2: each predicate true and false; an entity that satisfies none.
3. §6.3, §6.4: redeclarations are one entity with several declarations; a
   namespace's bodies; a parameter's parent; a friend declaration; an
   implicit member has no declaration.
4. §5.5: the origin of a function template specialisation, of a member of
   a class template instantiation, of a member specialisation of a member
   template.
5. Determinism: the same snippet parsed twice gives the same sequences.

## Done when

The tests pass. On the LLVM corpus's largest unit, `lookup` of a name that
is absent costs under a millisecond after the first call (record the
number in the hand-back; no gate yet).
