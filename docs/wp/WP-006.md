# WP-006 — slip_model: binary and JSON forms of plan, shard, run record

- Status: done
- Milestone: M0
- Track: A
- Needs: WP-001, WP-002

## Scope

`crates/slip_model/src/formats.rs` (split into `formats/` submodules if it
grows past about 600 lines), implementing `spec/model.md` §6–§10 over the
plain types in `plan.rs`, `shard.rs` and `run.rs`, using `wire`, `hash`,
`container` and `json`.

## Interface

```rust
impl Command  { pub fn observer_id(&self) -> Digest; }        // H("slip.observer.v1", Command), §7

// For each of Plan (kind PLAN), Shard (SHRD), RunRecord (RUNR):
impl Plan {
    pub const KIND: [u8; 4];  pub const VERSION: u32;
    pub fn to_bytes(&self) -> Vec<u8>;                         // debug-asserts the invariants a writer must uphold
    pub fn from_bytes(bytes: &[u8]) -> Result<Plan, wire::Error>;   // checks EVERY rule and invariant of the spec
    pub fn to_json(&self) -> json::Value;                      // §10
    pub fn from_json(value: &json::Value) -> Result<Plan, JsonFormError>;   // error names the JSON path
    pub fn validate(&self) -> Result<(), String>;              // the invariants, for values built in memory
}
pub fn dump(bytes: &[u8]) -> Result<String, wire::Error>;      // any kind → pretty JSON, for `slip dump`
pub fn content_id(bytes: &[u8]) -> Result<Digest, wire::Error>;
```

Invariants checked on read and by `validate`: sorted lists are strictly
ascending (§2); plan order; observer ids unique and equal to
`ObserverId(command)`; the accounting invariant as far as the plan alone can
show it (no (configuration, entry) pair twice; configuration indices in
range; every observer has at least one origin); configuration names unique;
a `failed` shard has no `inputs` and no counters; counter names match
`[a-z0-9_]+(\.[a-z0-9_]+)*`; `Outcome.message` is empty for `ok` and at most
4096 bytes.

## Tests

`crates/slip_model/tests/formats.rs`, each test naming its spec section:

- a hand-computed byte-for-byte encoding of one small plan, one shard and
  one run record (the expected bytes written out in the test, trailer
  included), so the format is pinned independently of the encoder;
- round trips binary → value → binary and binary → JSON → binary for
  representative values, including non-UTF-8 paths, values at and above
  2^53, absent and present `opt`, an unknown ignorable section;
- golden pretty JSON for each kind under `crates/slip_model/tests/golden/`;
- one test per invariant above: a file violating it is rejected with
  `Malformed`, and `validate` rejects the same value;
- `observer_id` of a fixed command equals a digest written in the test, and
  changes when any field changes (directory, an argument, argument order,
  an environment variable);
- JSON reading: unknown member, missing member, wrong type, each with the
  expected path in the error.
