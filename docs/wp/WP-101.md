## What is decided

1. **Slip calls Kiln's functions and does not restate them.** No
   function of Slip computes whether a range is editable, where a macro
   expansion begins, or where a token ends, from the source manager's
   tables: it calls the functions above. A package that needs more than
   they answer says so in its handback and the supervisor asks Kiln.
2. **Nothing is turned on.** `pp_record`, `written_refs`,
   `decl_extents`, sessions and host handlers stay off for every
   existing caller; the map task's output and every digest are byte for
   byte what they were. Show it: the goldens do not move, and the
   pristine `slip parse` of the `llvm` corpus's `lib/Support` selection
   (151 observers) gives the same counts and the same shard digests as
   before the move (`cargo xtask corpus` has the tree; the release
   `slip` of each revision, the same store options).
3. **If the commit changes `kiln_ast`.** Each changed type gets its row
   by the rules at the head of `spec/digest-kinds.md` and
   `spec/digest.md` §1, with Kiln's `file:line` and a pair test seen to
   fail without its code. For `offsetof`: the operand type is `in` as a
   type, each component of the designator is `in` (the field as `ref`,
   the base stepped through as `ref`, an index as its position), after
   the node's existing rows; the entry under "Hazards accepted for now"
   goes, and `tests/differ/_/offsetof-other-class-same-layout` loses its
   `# pending`. For anything else the request asked for, the request
   text says what Slip wanted the field for: write the row that reads it
   and un-pend the test that waits on `# needs: kiln`. A decision you
   are not sure of is a question in the handback with the row written
   `unsupported` meanwhile.
4. **A digest that changed for a source that did not** is a finding, as
   in WP-044: find the Kiln change, decide by `spec/digest.md` §1
   whether the new value is right, list it. Do not bless a golden
   without that.
