## What is decided

1. **Nothing is turned on.** The substitution keys, the root table,
   the token table and every other new option stay off for every
   caller. A new option that is on by default at the new pin is a
   finding to list, with what it changes.
2. **Slip calls Kiln's functions and does not restate them**
   (`docs/wp/WP-101.md` decision 1).
3. **A changed `kiln_ast` type gets its row** by the rules at the head
   of `spec/digest-kinds.md` and `spec/digest.md` §1, with Kiln's
   `file:line` and a pair test seen to fail without its code; where the
   request that asked for the field says what Slip wanted it for, the
   row reads it that way. A field whose reader is one of the packages
   in the table's last column is written `unsupported` with that
   package named, not built here. A decision you are not sure of is a
   question in the handback with the row `unsupported` meanwhile.
4. **A digest that changed for a source that did not is a finding**:
   find the Kiln change, decide by `spec/digest.md` §1 whether the new
   value is right, list it. No golden, pair or pitfall expectation is
   blessed without its line in that list. The same for a verdict of
   `tests/transform/` and of `crates/slip_verify/tests/pitfalls/`:
   **list every verdict that changes before changing it**; each is a
   ruling of the supervisor.
5. **A test that fails at the new pin because Kiln is wrong** is not
   worked around: it becomes `xfail` (or `# pending`) naming the Kiln
   behaviour, with a minimal reproduction and the request text in the
   handback. If more than a handful of tests end so, or one of them is
   on the rename's path, stop and hand back: the supervisor decides
   whether the move waits for Kiln.
