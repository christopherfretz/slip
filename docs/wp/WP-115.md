# WP-115 — name-derived values: the two known costs (a shared `__builtin_FUNCTION()` string, the unit-wide ordinal)

## Scope

`spec/landed/digest/WP-104.md` "Known costs (spurious differences)"
records two places where the symbolic form of a name-derived value
depends on something outside the unit that holds it. Each errs to a
difference, never to an equal; each makes an edit to one function
report another as changed, which in a namespace migration means noise
on every unit that logs. Their pairs are in the suite in pending form
(`# needs: known-cost`). This package repairs both.

1. **G2: a shared `__builtin_FUNCTION()` string is attributed to its
   first use.** Kiln makes one string object per content, so the
   `"get"` of `a::get()` and of `b::get()` is one object, and the walk
   writes it as `(plain, ref)` of the context of the first use. Repair:
   attribute the string to the **holder's own use** when the holder's
   plain name is the string's bytes, and only then; say what is written
   when it is not (the string reached a unit that is not the function
   it names: through a default argument evaluated at a call, through a
   `constexpr` variable of another function, through a template
   argument), and show that case is still never a wrong equal: two
   holders that pass on different functions' names must differ.
   Pairs: `equal/_/name-value-cost-plain-added-earlier`,
   `equal/_/name-value-cost-overload-plain-rename`.
2. **G3: one ordinal counter for every non-function context of the
   unit.** A `std::source_location` `__impl` object built outside a
   function is numbered among all such uses of the translation unit.
   Repair: number the objects **per holder** (the unit that holds the
   use), in the holder's own walk order. Say what the holder is for a
   use in a default member initializer, a default argument, a variable
   template's initializer, a non-static data member's initializer used
   by an aggregate initialization elsewhere, and a lambda at namespace
   scope; for each, a pair where a use is added to **another** holder
   (equal for this one) and a pair where two uses of **one** holder are
   swapped (differ).
   Pair: `differ/_/name-value-cost-global-loc-added-before`.
3. **Nothing else moves.** The scheme number of `spec/model.md` §8.2
   moves only if a digest of the existing goldens moves; list every
   golden that moved and why it holds a shared string or a non-function
   `__impl` object. If none moves, say so and leave the number.
4. **An `__impl` object whose file member is not a pointer to a string
   literal.** WP-104's second fix round writes the file by value when
   the member is such a pointer and `opt(false)` otherwise
   (`value.rs` `write_location`). Show from Kiln's code that the other
   case cannot occur for an object `__builtin_source_location()` made,
   or write the member's value whatever it is; a test either way.
5. **The spec**: `spec/digest.md` §9 as WP-104 left it, the two
   paragraphs; the "Known costs" section of the landed file becomes a
   pointer to `spec/landed/digest/WP-115.md`.
