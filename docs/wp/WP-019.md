# WP-019 — the run record carries its round

- Status: todo
- Milestone: M0
- Track: A
- Needs: WP-013, WP-018
- Size: S

## Scope

A run record (`spec/model.md` §9) names its plan and phase and not its
round, which every reader takes from the file name
(`spec/harness.md` §7). A record copied or renamed then describes
another round without anything noticing. `Run` gains `round: uv` after
`phase`, in the binary form and in the JSON rendering (§10). `RUNR`
stays at version 1: the format is `draft` and no store is kept.

- `slip_model`: the field, its encoding, validation and JSON.
- `slip_exec`: the pool writes the round it ran; `Store::publish_run`
  refuses a record whose round is not the one it is published under
  (`Invalid`, as for plan and phase); `latest_run` and the estimates of
  §6 are unchanged.
- `xtask perf`: the round is the record's; a record whose plan, phase
  or round disagrees with its path is an error (`spec/harness.md` §7).
  `summarize` prints the same lines as before.
- `spec/model.md` §9 and §10, `spec/exec.md` §2, `spec/harness.md` §7
  and its open question say so.

## Tests

`crates/slip_model/tests/formats.rs`: the round trips and the JSON form
with a non-zero round; a `Run` cut short before `round` is rejected.
`crates/slip_exec/tests/store.rs`: `publish_run` under another round is
`Invalid`. `crates/slip_exec/tests/pool.rs`: a run at round 3 records
3. `xtask/tests/perf.rs`: a record renamed to another round is an
error; the goldens change only where a rendering shows the record.

## Done when

`cargo xtask ci` passes and nothing reads a run's round from a file
name except to find the file.

## Out of scope

Rounds greater than 0 in `slip parse`. Cache keys (M5).
