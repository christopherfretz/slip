## Scope

Slip's pin `kiln` is `62d190007`, the head of Kiln's branch `slip/kf1`.
Kiln's `main` at `83566cc47172ea2e18c194b9611d291fc8994a34` has that
branch squashed (Kiln WP-2120, with the parameters the entry lacked and
`pp_record` on `FrontEndOptions`) and everything Slip asked for since:
the fixes for the 19 units of the `llvm` corpus that fail at the pin
(KD1, KD2), the written-reference table (WP-1930, WP-1931),
declaration extents (WP-2090), retained evaluation sessions (WP-1995),
the host-call builtin (WP-1990), `Ast::closure_owner` (WP-2023), the
names of an overloaded member access and the definition-context lookup
sets of operators (WP-2020, WP-2021), using-declaration shadows and one
linkage module (WP-2025, WP-2026), the `CHECKED` bit of an attribute
(WP-2022), the `adl` flag of an ordinary call that only
argument-dependent lookup resolved (WP-1928). This package moves the
pin to that commit and absorbs what changed: `slip_kiln` compiles and
behaves as before, and `spec/digest-kinds.md` has a decided row, with
its test, for every field, variant and type the new AST has.

The transform API's critical path (`docs/wp/WP-080.md`, then 089, 092,
094), local types (`docs/wp/WP-040.md`) and the corpus's clean baseline
all wait for it.

revisions. Each decision below is to be checked against Kiln's source
at the new pin (cite `file:line` in the landed file); if the source
contradicts one, stop and report it instead of following it.

## Interface

`slip_kiln`'s public interface stays what it is. If Kiln changed a type
that `slip_kiln::Unit` returns or a function `slip_digest` calls, say so
first in the handback. Nothing new is exported for the tables Slip does
not read yet.

## Tests

- Every existing test, green at the new pin.
- `crates/slip_kiln/tests/parse.rs`: one source that failed at the old
  pin for each of KD1 and KD2 (the smallest reproducers are in
  `docs/requests/`) parses `ok`; a source with uses parses with the
  written-reference table off and the unit's table is empty.
- One pair test for every row added as `in` (the directories
  `spec/digest-kinds.md` §1.5 derives), each seen to fail without its
  code; `equal` tests that show `written_refs`/`decl_extents` cannot
  matter are not needed (the tables are off).
- The ratchet `tests/tables/untested.txt` gains only rows marked
  `# pending` for another area.
