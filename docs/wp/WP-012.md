## Scope

`crates/slip_cli`: the commands, options, output and exit statuses of
`spec/exec.md` §8 (all of it: §8.1–§8.5 are the specification of this
package), wiring what the packages before it landed:

- `slip_cdb::plan::build` with `slip_kiln::KilnCheck` (WP-007, WP-010),
- `slip_exec::store`, `signals`, `jobserver` (WP-004, WP-008),
- `slip_exec::pool::run` with the worker command `slip __worker` (WP-009;
  `spec/landed/exec/WP-009.md` is the interface),
- `slip_exec::worker::serve` with a `Task` around
  `slip_kiln::parse_observer` (WP-008, WP-010),
- `slip_model::formats::dump` (WP-006).

Read the `spec/landed/` file of each before starting: they hold the final
interfaces, which may differ in shape from the briefs.

No dependency is added; option parsing is by hand.

## Interface

The crate becomes a library with a thin binary, so the pure parts are
tested without starting a process:

```rust
// lib.rs: #![forbid(unsafe_code)]
pub mod args;      // the command line -> Invocation; pure
pub mod commands;  // plan, parse, dump: each takes its parsed options and writers
pub mod worker;    // the hidden __worker command and the parse Task

// args.rs
pub enum Invocation { Version, Plan(PlanArgs), Parse(ParseArgs), Dump { file: PathBuf }, Worker(WorkerArgs) }
pub struct Db { pub name: Option<String>, pub path: PathBuf }
pub struct UsageError(pub String);
pub fn parse(args: &[OsString]) -> Result<Invocation, UsageError>;     // args after argv[0]
pub fn parse_size(text: &str) -> Option<u64>;                          // §8 <size>; None on overflow or malformed
pub const USAGE: &str;

// the entry main.rs calls; returns the exit status (§8.5)
pub fn run(args: &[OsString], out: &mut dyn Write, err: &mut dyn Write) -> ExitCode;
```

`main.rs` is `fn main() -> ExitCode` calling `run` with the process's
arguments and locked standard streams, through `signals::finish`.

Rules the specification leaves to this package:

- **Exit 70.** `run` installs a panic hook (coordinator commands only, not
  `__worker`) that prints the one line of §8.5, and wraps the command in
  `catch_unwind`; on a panic it kills live children
  (`process::kill_live_children_now`), returns tokens
  (`jobserver::release_all`) and returns 70. A hidden command `slip
  __panic` panics on purpose so the test can observe this.
- **Signals.** `parse` calls `signals::install` with
  `pool::cleanup_on_signal(&store)` (not the store's own: the pool's
  cancels the run, waits for its run record, then does the store's) before
  the pool starts. `pool::run` returning `PoolError::Cancelled` means the
  signal path is ending the process: return through `signals::finish`
  without printing a summary.
- **The pool.** `pool::Options::new(jobs, config)` with `tool_slip`,
  `tool_kiln`, `observer_timeout` (`--observer-timeout 0` is `None`) and
  `worker_jobs` set from the options; `admission::Config::with_budget`
  with `observer_memory`, `worker_stack` and the two estimate parameters
  set from theirs. `--worker-jobs <n>` goes to both `Options::worker_jobs`
  and the worker's own arguments in `WorkerCommand::args`, always the same
  number (a worker that stops before the pool expects it to costs a crash
  and a retry). The sampler is `process::ProcSampler`.
- **Stack guard.** `slip_kiln::parse_observer` runs Kiln on the worker's
  large-stack thread (`worker::serve`). Kiln's `StackGuard::install` is
  public (`kiln_sema::stack_guard`; `docs/requests/KF1-front-end-entry.md`); if
  installing it in `slip_kiln` before the parse is a few lines, do it and
  add a test with deeply nested input that ends `diagnosed` or `failed`
  and not by a signal; if it is more than that, say so in the handback.
- **Worker environment.** `WorkerCommand::env_remove` is every variable of
  the coordinator's environment whose name starts with `KILN_`
  (`docs/requests/KF1-front-end-entry.md` f).
- **The parse task** makes the job's scratch directory
  (`spec/exec.md` §2) with `Store::scratch_dir` on a store it opens shared
  at `job.store_path()` and keeps for its lifetime, and passes it as
  `ParseOptions::scratch`.
  The worker changes its current directory during a parse: every path it
  uses is absolute. Its standard output carries only protocol messages;
  nothing in the worker prints there.
- **Plan threads.** `plan` holds the tokens it hashes with for as long as
  the build runs: `Pool::from_env().with_jobs(n)`, the implicit token, then
  `try_acquire` until it returns none or `-j` is reached.
- **Budget.** `parse` without `--memory` uses `budget_from_system` on the
  two values of `admission::read_system()`. 0 (memory unknown) means no
  admission, as `--memory 0` does; say so in one warning line.
- **Tool versions.** `Tool { slip: CARGO_PKG_VERSION, kiln:
  slip_kiln::kiln_version() }` for the plan, the run record and `Ready`.
- **Output errors.** A failed write to standard output or standard error
  is ignored (`let _ = writeln!(…)`, never `println!`): a closed pipe must
  not become a panic and status 70.

## Tests

`crates/slip_cli/tests/args.rs` (§8, pure): every option in each of its
spellings (`--store x`, `--store=x`, `-j 4`, `-j4`); `--`; repeated
`--db` and `--only`; a repeated single option, an unknown option, a missing
value, a malformed number or size, `--plan` with `--db`, neither, several
unnamed databases: each a `UsageError`; the `--db name=path` split rule
including a path that contains `=`; `parse_size` over the suffixes, zero,
overflow and junk.

`crates/slip_cli/tests/cli.rs` (§8, through the built executable,
`CARGO_BIN_EXE_slip`), over fixture projects written to a temporary
directory (self-contained sources: no system headers), each test with its
own store and a time bound:

- `plan`: the output lines; the plan is in the store and `slip dump` of it
  is JSON that reads back; status 0, and 1 with an excluded entry that is
  not `not_a_compile`; the same plan id for `-j1` and `-j4`.
- `parse --db`: all `ok` gives status 0 and the summary lines (every
  `shard` and `job` line present, `selected`, `wall`, `run`); one
  translation unit with an error gives status 1, `shard diagnosed 1` and
  the `slip: diagnosed: <file>: …` line; every selected observer has a
  shard in the store that `slip dump` renders; the run record validates.
- `parse --plan` by id prefix and by file; an unknown and an ambiguous
  prefix (status 3).
- `--only` and `--limit`; a selection that keeps nothing (warning, status
  0).
- Status 2: unknown command, unknown option (usage text follows the one
  line). Status 3: a missing database, a database that is not JSON, a
  directory that is not a store, a store whose lock names a live process
  (the test's own pid), `dump` of a file that is not a container.
- Status 70: `slip __panic` prints exactly one line and exits 70.
- The worker: `slip __worker` with its input closed at once prints one
  `Ready` frame and exits 0.
- An interrupted `parse`: one translation unit includes a named pipe
  (`mkfifo`, made with the `mkfifo` program), so its worker blocks until
  the test writes to the pipe; when the worker is running, `SIGINT` (sent
  with the `kill` program) ends `slip` by that signal, no worker is left,
  the store has no lock and an empty `tmp/`, and a run record with a
  `cancelled` job exists. If Kiln does not block on a pipe, say so in the
  handback and leave this case out: WP-009's tests cover the signal path.

Tests wait on conditions with a bound, never on a fixed sleep.
