## Interface

```rust
// database.rs  (§2)
pub struct Entry  { pub directory: String, pub file: String, pub arguments: Vec<String> }
pub struct Defect { pub file: String /* as spelled; empty if absent or not a string */, pub detail: String }
pub struct DatabaseError { pub detail: String }            // not JSON, or the top level is not an array
/// One element per entry, in order; an entry's number is its index.
pub fn read_json(bytes: &[u8]) -> Result<Vec<Result<Entry, Defect>>, DatabaseError>;

// plan.rs  (§7)
pub struct Source { pub name: String, pub path: std::path::PathBuf }   // configuration name, database path
pub struct Tool   { pub slip: String, pub kiln: String }
pub enum PlanError { Usage(String), Database { path: std::path::PathBuf, detail: String } }
pub fn build(sources: &[Source], check: &dyn FrontEndCheck, tool: &Tool, threads: usize) -> Result<Plan, PlanError>;
```

`build` returns a plan for which `Plan::validate` succeeds (debug-assert
it). `Rejection::UnsupportedLanguage` and `UnsupportedFlag` become the
reasons of the same names, with the rejection's text as `detail`. A database
that cannot be read at all is `PlanError::Database`; so is one that is not a
JSON array. A main file that normalisation found but that cannot be read
when it is hashed is excluded as `missing_file`.

`threads` bounds the threads used to read and hash main files
(`std::thread::scope`; 0 and 1 both mean the calling thread). Each real path
is read once however many observers name it. The plan must be identical for
every value of `threads`. Files are hashed in pieces through
`hash::Hasher`; a main file is never held in memory whole.

## Tests

`crates/slip_cdb/tests/database.rs` and `tests/plan.rs`, as listed in
`spec/cdb.md` "Tests", each test naming its section:

- §2: `arguments` and `command` forms, both present (`arguments` wins),
  other keys ignored, and every defect (not an object; missing or non-string
  `directory`/`file`; relative `directory`; neither `arguments` nor
  `command`; empty `arguments`; a non-string argument; an unsplittable
  `command`), each with the entry still numbered and the others unaffected;
  the three `DatabaseError` cases.
- §7: the accounting invariant on a database mixing observers and every
  exclusion reason; two entries with the same normalised command (in one
  database, and across two configurations) are one observer with two
  origins; the same file compiled with different flags is two observers;
  plan order; `cost_hint`; duplicate and empty configuration names are
  `Usage`; the same plan bytes for `threads` 1, 2 and 8.
- Golden JSON plans under `crates/slip_cdb/tests/golden/`. Observer ids and
  paths depend on where the fixture tree is, so the test replaces the
  fixture root by `$ROOT` in paths and each digest that depends on it by a
  placeholder before comparing, and checks the ids separately against
  `Command::observer_id`. Say exactly what is replaced in a comment.

Fixture trees are built in a temporary directory and removed
(`tests/common/mod.rs` from WP-003 has the helper).
