## Scope

**This package is in the trusted base** and is reviewed as WP-087 is.

Launch after milestone M2's verify loop and overlay exist. Those
packages have no files yet, so they are not in `Needs`; add their ids
when they do. By name, this package needs: the verify job that parses an
observer against the overlay and digests it (`spec/edits.md` §8.3), the
edit set reduce accepts (§6), and apply's map from an accepted edit to
its bytes in the post-image (§7.1).

`spec/api.md` §7.2 rule 5 and §7.6 rule 4. A transform that writes
`spell(E)` says which entity it means and lets Slip choose the text.
Digests cannot check the choice where the unit is declared changed, and
that is exactly where a respelled callee sits. This package checks it
directly: in the post-image, the name where the piece landed must denote
`E`. Demo 3 may not be called verified without it. (WP-095 is needed
for one thing: its test that the host's notion of an entity and the
digest's agree, so that the key recorded at `spell` is the key this
check computes.)

**The normative text is not yet in `spec/verify.md`.** It goes there
when the supervisor reconciles `spec/api.md` §7.6 with `spec/edits.md`
and `spec/verify.md`. Until then the rules below are the specification,
and what this package lands is recorded in `spec/landed/api/WP-096.md`.

Rules:

1. **An obligation** is `(file, lo, hi, key)`: the bytes `[lo, hi)` of a
   post-image file that are the text of one spelled piece of one accepted
   edit, and the `KeyId` the piece records. Apply derives the range
   (`spec/api.md` §7.6 rule 4); the obligations of a Slip run travel with
   its declared changes to every verify job.
2. **In one observer**, for one obligation whose file the observer reads:
   find the written references (WP-085's deduplicated table, roles of
   `spec/api.md` §6.5 rule 3) whose name range ends at `hi` and starts at
   or after `lo`, mapped through `slip_kiln::ranges`. For each, take the
   origin of its referent (`spec/api.md` §5.5) and its key under the Slip
   run's rules (`Keys::with_rules`).
   - every such reference has the obligation's key: **holds**;
   - some reference has another key, or no key: **fails**, and the
     observer's verification fails, whether or not the unit that holds
     the name is declared changed;
   - there is no such reference: **not seen** in this observer.
3. **Over the Slip run**: an obligation that fails anywhere fails. An
   obligation that holds in at least one observer and is not seen in
   others passes, and the others are counted. An obligation that no
   observer holds is a failure of the Slip run's verification, reported
   once with its place (`spec/api.md` "Open questions" 4).
4. The check reads the post-image only. It takes nothing from the map
   shards but the obligations; a transform cannot influence it except by
   having said `spell`.
5. A name written in a macro argument that is substituted twice gives
   two references at one range: rule 2 requires each to hold.
6. Counters: `verify.spelling.obligations`, `.holds`, `.fails`,
   `.not_seen` (per observer); the result of the Slip run lists each
   failed obligation with the entity meant (its name as `spec/verify.md`
   §6 gives it) and the entity found.

## Interface

```rust
// crates/slip_digest/src/spelling.rs
pub struct Obligation { pub file: Vec<u8> /* subject path */, pub lo: u32, pub hi: u32, pub key: Digest }

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Spelling { Holds, NotSeen, Fails { found: Option<Digest>, found_name: String } }

/// One observer of the post-image. `obligations` are those whose file
/// the unit read; the result is parallel to it.
pub fn check_spellings(input: &Input<'_>, rules: &slip_model::keys::RuleTable,
                       obligations: &[Obligation]) -> Vec<Spelling>;
```

The verify job calls it after the digest walk and puts the verdicts in
its shard in the form the reconciled `spec/edits.md` gives. Folding over
observers (rule 3) is one function beside the existing verdict fold in
`slip_verify`, which names no Kiln type (its argument and result types
are those the reconciled specifications give the verify shard and the
result; the shape is):

```rust
// crates/slip_verify/src/spelling.rs
pub fn fold(per_observer: impl Iterator<Item = (ObserverIndex, Vec<(ObligationId, Verdict)>)>) -> SpellingResult;
```

## Tests

`crates/slip_digest/tests/spelling.rs`, on snippet pairs (a post-image
text with marked obligations):

1. Holds: a sibling spelling behind a written qualifier; a fully
   qualified spelling; a function template (the referent is a
   specialisation, the key is the template's); an overload (the key
   tells the overloads apart).
2. Fails: the name resolves to another overload; to a function of the
   same name in a nearer scope (the hazard a fully qualified name
   avoids and a sibling spelling can meet); to a variable; the name does
   not resolve to a reference at all in a unit that is declared changed
   (still fails).
3. Under a rename rule: the post-image names the entity by its new
   identifier and the obligation's key is the pre-image's.
4. Not seen: the bytes are in a skipped conditional group; in a macro
   argument the macro does not use.
5. Twice substituted: one use denotes the entity and one does not: fails.
6. `fold`: holds and not seen passes with the count; not seen
   everywhere fails once; one failing observer fails.

`crates/slip_cli/tests/demo3_small.rs` (WP-094) gains the end-to-end
case: the small corpus, with one caller where the sibling spelling is
captured by a nearer declaration; the run's verification fails there and
names both entities.
