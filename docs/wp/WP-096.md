# WP-096 — verification: every spelled entity denotes what the transform named

## Scope

**This package is in the trusted base** and is reviewed as WP-087 is.

**It is on milestone M2's path.** The native rename writes a spelled
piece at every resolved reference it renames (`spec/edits.md` §9.3), and
`docs/wp/WP-074.md` needs this package for the verify job of a
transform's run. M2's exit runs through it: there is no second, smaller
check for M2 (`docs/demos/demo-2.md` §1).

`spec/verify.md` §10 is the normative text: §10.1 (obligations), §10.2
(in one observer) and §10.6 (the interface) are this package's.
`spec/api.md` §7.2 rule 5 and §7.6 rule 4 say what a transform's author
relies on. A transform that writes `spell(E)`, and a rename that
replaces a resolved reference, say which entity a name means and leave
the text to Slip. Digests cannot check the choice where the unit is
declared changed, and that is exactly where a respelled callee sits.
This package checks it directly, in one observer: in the post-image, the
name where the piece landed must denote `E`. Neither Demo 2 nor Demo 3
may be called verified without it.

What is this package's is the check in one observer,
`slip_digest::spelling::check_spellings`. What is another package's:

- **The obligations.** Apply derives them and they travel in the
  overlay (`OVLY.spellings`, `spec/edits.md` §7.1; the record is
  `docs/wp/WP-061.md`'s), which a verify job reaches through
  `post.image` (`spec/exec.md` §5.2). They do not travel with the
  declared changes.
- **The verify job** that parses an observer through the overlay, hands
  the check the obligations of the files the observer read, and writes
  the `spellings` section (section 26, §10.4) and its counters:
  `docs/wp/WP-074.md`.
- **The fold over the run** (§10.3) and the report (§10.5):
  `slip_verify::spelling::Fold`, `docs/wp/WP-070.md`. This package has
  no fold.

The test of `docs/wp/WP-095.md` that the script host's notion of an
entity and the digest's agree (so that the key recorded at `spell` is
the key this check computes) stays in M3 and is not a need of the
check: the native rename takes its keys from `Keys` itself.

Rules this package fixes beyond §10 (recorded, with whatever else it
decides, in `spec/landed/verify/WP-096.md`):

1. **An obligation** as the check takes it is `(file, lo, hi, key)` of
   §10.1 with the file given by its subject path; the caller passes
   those whose file the observer read, in the overlay's order, and the
   result is parallel to them.
2. **The written references** of §10.2 rule 1 are
   `slip_kiln::written::written_refs` (`docs/wp/WP-067.md`: the entries
   with a referent, deduplicated, in unit order); the roles are checked
   here against the list of §10.2 rule 1, and an entry in a role outside
   it takes no part. A name range (rule 2) is
   `slip_kiln::ranges`' (`docs/wp/WP-084.md`, which calls Kiln's
   function: this package waits with it for the pin move after WP-044,
   `docs/wp/WP-101.md`); the origin (rule 4) is
   `slip_kiln::written::origin`; the key under the run's rules is
   `Keys::with_rules` (`docs/wp/WP-087.md`). Nothing of the three is
   computed a second way here.
3. **A unit parsed without the tables** (`slip_kiln::written::recorded`
   is false) answers `NotSeen` for every obligation, which over the run
   is `unseen` and fails it: safe, and the wrong message. The verify
   job of a transform's run always parses with `ParseOptions::written`
   (`docs/wp/WP-074.md`); the function's documentation says so.
4. The check reads the post-image only. It takes nothing from the map
   shards but the obligations; a transform cannot influence it except by
   having said `spell`, and the rename except by having written the
   piece.
5. A name written in a macro argument that is substituted twice gives
   two references at one range: each must have the key (§10.2).
6. `Fails.found` and `found_name` are those of the first answering
   reference in unit order that does not have the obligation's key
   (§10.4): its origin's key under the rules, absent if it has none, and
   its name as `spec/verify.md` §6.1 gives it.

## Interface

The types and the function are `spec/verify.md` §10.6's, unchanged:

```rust
// crates/slip_digest/src/spelling.rs
pub struct Obligation { pub file: Vec<u8> /* subject path */, pub lo: u32, pub hi: u32, pub key: Digest }

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Spelling { Holds, NotSeen, Fails { found: Option<Digest>, found_name: String } }

/// One observer of the post-image. `obligations` are those whose file
/// the unit read; the result is parallel to it.
pub fn check_spellings(input: &Input<'_>, rules: &slip_model::keys::RuleTable,
                       obligations: &[Obligation]) -> Vec<Spelling>;
```

The verify job calls it after the digest walk, on the same input, and
encodes the result as the `spellings` section (`docs/wp/WP-074.md`).
`slip_verify::spelling::{Outcome, Fold}` are `docs/wp/WP-070.md`'s.

## Tests

`crates/slip_digest/tests/spelling.rs`, on snippet pairs (a post-image
text with marked obligations):

1. Holds: a sibling spelling behind a written qualifier; a fully
   qualified spelling (`::a::b::f` is answered by `f` alone, §10.2 rule
   3); a function template (the referent is a specialisation, the key
   is the template's); an overload (the key tells the overloads apart).
2. Fails: the name resolves to another overload; to a function of the
   same name in a nearer scope (the hazard a fully qualified name
   avoids and a sibling spelling can meet); to a namespace-scope
   variable; to an entity without a key (a local variable of that
   name: `found` is absent); the name resolves to another entity in a
   unit that is declared changed (still fails).
3. Under a rename rule: the post-image names the entity by its new
   identifier and the obligation's key is the pre-image's. This is the
   native rename's case, and it is tested for a function, a variable, a
   member function named through an object and a qualified name.
4. Not seen: the bytes are in a skipped conditional group; in a macro
   argument the macro does not use; in a dependent name; in a unit
   parsed without the tables (rule 3).
5. Twice substituted: one use denotes the entity and one does not: fails.
6. Two obligations in one file and one in a file the unit did not read
   (the caller's error: the function is given only files the unit read,
   and answers `NotSeen` for a path it does not know).

The end-to-end cases are other packages': `crates/slip_cli/tests/tasks.rs`
(`docs/wp/WP-074.md`: a rename whose replacement resolves to another
function), `crates/slip_verify/tests/spelling.rs` (`docs/wp/WP-070.md`:
each row of §10.3), and `crates/slip_cli/tests/demo3_small.rs`
(`docs/wp/WP-094.md`), which gains the small corpus with one caller
where the sibling spelling is captured by a nearer declaration; the
run's verification fails there and names both entities.
