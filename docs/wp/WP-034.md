## Interface

`stmt::child(w, s, st)` and `fp::fp_override(s, o)` keep their
signatures (`fp_override` is also called by `decl_scope.rs` for
`ColdDeclData` `init_fp`). Calls into other areas, by encoding:

| Encoding in a row | Calls | On `main` |
|---|---|---|
| `child`, `child?`, `child*` naming an expression | `expr::child`, `child_opt`, `children` | there (WP-031); a kind of `expr_init.rs`, `expr_dep.rs`, `expr_misc.rs` is pending (`Area::Expr`) until its package lands |
| `decl`, `decl?`, `decl*` | `local::write_decl` | there for variables, parameters, bindings, labels, block-scope functions and `extern` variables; a local class, enumeration or closure type is pending (`Area::Local`) |
| `ref`, `ref*` (`GotoStmt.a`, `ReturnStmt.b`, `AsmData` `labels`) | `Walk::write_ref` | there |
| `attrs` (`AttributedStmt.a`) | `attrs::stmt_attrs` | there |
| `string`, `string*` | `value::string` | there |
| `sym?` | `Walk::write_sym` | there |

Whether a row's `child` is a statement or an expression is what Kiln
stores (`kiln_ast::stmt`): read it there, row by row; do not guess from
the name.

**The stack** (`lib.rs` "What bounds the stack"). Each statement the
walk recurses into enters one level with `Walk::enter_node`; past
`walk::NODE_LIMIT` the stream gets a placeholder and
`Unaccounted("walk/depth")`, never a stack overflow. Real code nests
statements deeply in two shapes that must not use a level, nor Rust
stack, per element, as WP-031 did for operator and call chains:

- the right spine of `if … else if … else if …` (`IfData` `els`);
- a run of labels: `case 1: case 2: … case n: stmt` (`CaseData` `sub`,
  `DefaultStmt.a`, `LabelStmt.b`; generated lexers and tables have
  thousands), and a chain of `AttributedStmt`.

Write those as a loop over the spine (the rows of each element in table
order, the tail last where the table has it last; where the table has
rows after the tail, an explicit heap stack as `expr.rs` "The walk"
has). Tests: an `else if` chain of 20 000 and a run of 20 000 `case`
labels digest without being indeterminate, in time linear in the
length (the form of `tests/expr_chains.rs`); a compound statement of
100 000 statements is linear. Add the statement walk's own recursive
path (a `CompoundStmt` in a `ForStmt` in a `CompoundStmt` …) to
`expr::tests::frames_fit_the_stack` or a test of the same form in
`stmt.rs`, so that `STACK_SIZE` is shown to hold `NODE_LIMIT` levels of
your frames; if it does not, report the measured frame and do not
change `STACK_SIZE` or `NODE_LIMIT` yourself (that one line is the
supervisor's).

Things to settle by reading Kiln, each with its `file:line` in the
landed file:

- `CompoundStmt.aux` "index into `StmtArena` `fp_overrides`": what the
  value is for a block with no pragma in effect, and whether a block
  inherits the override of the enclosing block or function (then a
  pragma at file scope reaches every body: show it with a test, and
  show that a body after `#pragma STDC FP_CONTRACT` popped back is
  equal to one that never saw it).
- `FpOverride` `mask`: "the bits are Kiln's `fp_bit` constants (Open
  questions)". Hold the constants you rely on equal to Kiln's by a unit
  test, as `attrs.rs` holds `KINDS`; a bit of `mask` no row of
  `FpOptions` accounts for is `Unaccounted`. Whether a field of `vals`
  whose `mask` bit is clear can differ between two parses that mean the
  same (then it must not be written as stored: report it, common rule
  2).
- Whether one `StmtId` can be reached twice in one unit's walk
  (`SwitchData` `cases` and `CoroutineBodyData` `promise_stmt` are
  `out` for that reason: confirm that everything they hold is written
  through the other row, with the Kiln site; look for others, e.g. the
  parts of a range-for or of an expansion statement that an
  instantiation shares with its pattern).
- `IfData`: "`then` absent when discarded in an instantiation"; the
  same for `els`. Show with an instantiation (a `derived-changed` line
  names it) that the discarded branch's content does not reach the
  instantiation's digest and the taken branch's does; and for
  `if consteval` what Kiln stores.
- `ReturnStmt.b`, "the variable the return may elide the copy of":
  when Kiln sets it (at the parse of the return, or later when the
  function's end is reached; in a pattern and in its instantiation).
  It must be a function of the body alone: if a use elsewhere can set
  or clear it, the row is `demand` and you report it instead of
  writing it.
- Labels: a `goto` before its label gives the label its ordinal at the
  reference (digest §4.3); `__label__` declarations; a label that
  nothing jumps to; `AsmData` `labels`. Renaming a label, or a local
  variable, is `equal`.
- `DeclStmt.a`: a declaration statement holding only a typedef or an
  alias writes its tag and its count (§2.4 gives the typedef nothing);
  say what a requalified local alias (`using T = ns::S;` against
  `using T = ::ns::S;`) gives: it must be `equal`.
- `RangeForData`, `CoroutineBodyData`, `ExpansionData`: the implicit
  variables and expressions Kiln builds (digest §6 "the selected
  entity"). For each implicit `decl` row check that `local::write_decl`
  writes its initialiser (the `begin`/`end` calls are the fact), and
  that a pattern whose range is type-dependent has the rows the table
  expects (absent `begin`, `end`, `cond`, `inc`).
- `CXXExpansionStmt` and `ContractAssertStmt`: which language mode or
  flag Kiln needs to build them. The pair runner has no per-test flags
  (a later package adds them): if the runner's mode cannot build one,

  Kiln's arena lets a test build one, leave the pair tests out, and
  list the rows in the handback. `ContractAssertStmt.aux-semantic` is
  "the evaluation-semantic slot": find what fills it and whether it is
  the command line's default (`ContractSemantic` is `out` for that
  reason, §10.9); if the slot can hold the default, report it.
- `GCCAsmStmt`: the four `aux` bits through `FlagWord`; `operands`

  as "the rest"): confirm the count of `operands` is their sum, else
  `Unaccounted`.
- `StmtNode` `flags` is `unbuilt`: a non-zero value is
  `Cause::Unsupported("StmtNode/flags")`, with a unit test if a node
  can be built by hand.

## Tests

Per row as the common rules say; a statement is reached through a
function body (`decl_func.rs` calls `stmt::child` for it). Beyond the
rows:

- `equal`: local names renamed (variables, parameters, labels,
  structured bindings); a name in a body requalified (`ns::f()` against
  `::ns::f()` against `f()` for the same entity); comments and layout;
  a local typedef respelled.
- `differ`: two statements swapped; `break` against `continue`; `while`
  against `do`; a `case` value; an `if` with and without an init
  statement; braces added around a single statement (a `CompoundStmt`
  is a node: record in the landed file that this is a difference and
  why it is not promised equal by digest §1); `catch (...)` against
  `catch (int)`; the order of two handlers; `[[likely]]` on a branch.
- `demand` (a use added on side B elsewhere in the file must not move
  the unit of a function whose body is the same): a body declaring a
  local `const` variable that a later constant expression of the body
  reads or not (the `VarEval` rows are WP-026's and `demand`: see that
  the body's unit holds still); a body with a range-for over a class
  template specialisation that side B also completes elsewhere; a body
  whose `if constexpr` condition names a variable template that side B
  instantiates elsewhere; a returned local variable whose class side B
  gives a use that defines an implicit copy constructor.
- With `origin/main` merged, un-pend every `# needs: stmt` test of the
  crate (54 on `main` when this was written, more with each merge) and
  see each pass; one that fails for another area's reason gets that
  area's mark back, with a line saying which fact is missing; one that
  fails for a reason of this package is a defect to fix. For one in
  five, break the row and see it fail.
- unit tests in each file for helpers.

## Rules

The "Rules common to the digest's area packages" of `docs/wp/WP-029.md`
apply (files, tables decide, no wildcard, properties, tests, tests that
can fail, gate), with the files named in Scope in place of rule 1's and
`spec/landed/digest-kinds/WP-034.md` in place of rule 7's. Three more,
from the reviews of wave 1:

- Wait for a long run by its exit notification and send no interim
  reply; never kill processes by pattern (`pkill -f`): other packages
  run the same commands; keep scratch files in a directory of your own
  under the worktree's `target` directory or a subdirectory of the
  scratchpad named after this package.
- Every `in` row that is an enumeration, a flag or an optional gets a
  test that fails when the row is skipped *and* when it is written as a
  constant: the independent reviews mutate every such row. A table of
  rows held by one table-driven unit test (as WP-031's last commit did
  for the expression enumerations) is accepted for enumerations whose
  every row has a pair test already.
- The gate's result is the log's own last lines (`ci: ok`), not the
  exit status of a pipeline that ends in `tail`.
