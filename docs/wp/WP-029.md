## Interface

The signatures in `templ.rs` are fixed, `expr_maps` as given above.
Calls into other areas: `expr::child_opt`, `expr::profile_expr`,
`expr::requires_clause`, `value::value`, `Walk::write_args`,
`write_nns`, `write_ref`, `write_type`, `decl_stream`.

`TemplLink` is read through `ast.templ_link(d).get()` as `keys.rs` and
`units.rs` do; its payload rows are written in the *unit's* stream and
are not the key (the key's use of the same records is in `keys.rs` and
stays). `Pattern.0-index` is `out`. A specialisation records what it
was instantiated from as a `Ref` (digest §8); "a `ref` to a pattern
that has no key … is `Ref::none`" (§9) must not make the unit
indeterminate: check what `write_ref` does for such a pattern and say
so in the landed file.

The `demand` rows of `TemplateTables` (`end_of_tu_defs`,
`ref_var_insts`, `specializations`, `spec_order`, `member_map`) are not
written; each gets its `tests/demand/` pair.

## Rules common to the digest's area packages

Read first, in this order: `docs/AGENTS.md`; `spec/digest.md` (whole);
`spec/digest-kinds.md` §1 and §2, then the sections in Scope; the
documentation at the top of `crates/slip_digest/src/lib.rs` (the
functions every area calls, "How to fill an area");
`spec/landed/digest/WP-024.md`; the Handback of `docs/wp/WP-024.md`.
Look at how `types.rs` and `decl.rs` write their tables before writing
yours.

1. **Files.** You own the files named in Scope and your tests. In
   `crates/slip_digest/src` touch nothing else, with two exceptions: a
   function another area must provide and that has no signature yet is
   added to that area's file as a pending function (final signature,
   body `s.pending(Area::X)`, one line in the handback), never
   implemented; and `lib.rs` gets one line per function you add for
   others, in its table. Do not touch the `Area` enumeration,
   `tables.rs` (generated), `tests/tables/pins.txt`, or the tables of
   `spec/digest-kinds.md`. Several packages run at the same time in
   other files of this crate: a change outside your files conflicts
   with theirs.
2. **The tables decide.** Rows are written in table order as §2.1 says;
   tags and decisions come from `crate::tables`, never from a number
   written by hand; `bit` rows go through `FlagWord`. A set bit or a
   value no row accounts for is `Cause::Unaccounted("<short name>/<row>")`,
   an `unsupported` row `Cause::Unsupported("<short name>/<row>")`; the
   stream stays well formed either way. A row that is wrong about Kiln
   (the field is not stored as the note says, a fact is missing) is not
   corrected in code: write the conservative thing (indeterminate),
   leave the row's test out, and report it with the Kiln `file:line`.
3. **No wildcard** (digest §13 obligation 2): every `match` over a Kiln
   enumeration lists every variant, no `_`, no `..` over variants, no
   `matches!`; a Kiln record or view is destructured without a rest
   pattern, so that a field Kiln adds does not compile.
4. **Properties** (WP-024 "Properties that are not negotiable"):
   determinism (no hash-map order, id, address or interning order in a
   stream); linear work; no panic on any AST Kiln can build (an
   unexpected shape is `Unaccounted`, not `unwrap`, not indexing);
   recursion bounded as `lib.rs` "What bounds the stack" says.
5. **Tests.** Every row of your tables gets the directory §1.5 names
   (`differ`, `equal`, `demand` or `indeterminate`), in the form
   `docs/wp/WP-024.md` "The pair tests" describes; the names leave
   `tests/tables/untested.txt` with `SLIP_BLESS=1 cargo test -p
   slip_digest --test tables`. A `differ` test changes one fact and
   names the unit that must change; choose sources in which the fact is
   visible while the other areas are pending. Where it cannot be (the
   difference is inside what another area still writes as its
   placeholder), write the test anyway and mark it: `expect.txt` gets
   the lines `# pending` and `# needs: <area>` (for an `equal` test, an
   `expect.txt` holding only those two lines); the runner skips it and
   the last area package runs them all. Keep these few and list their
   count by area in the handback. A row marked `unbuilt` needs no test.
   Rows that C++ source cannot reach through Kiln (say why, with the
   Kiln site) stay in `untested.txt` and are listed in the handback.
6. **Tests that can fail.** For every table, break at least one row in
   five on purpose (skip it, swap two, write a constant) and see its
   test fail, and do so for every row whose rule is in prose under a
   table. The handback lists the rows checked this way. Do not leave
   the breakage in.
7. **What the spec left open** goes to
   `spec/landed/digest-kinds/WP-029.md` (a decision per paragraph, the
   conservative one). Unit tests of helpers go in a `#[cfg(test)] mod
   tests` inside your own file, not in `src/tests.rs`.
8. **Gate.** `cargo xtask ci` (the full gate: this crate links Kiln)
   passes with `origin/main` merged in; `cargo test -p slip_digest`
   stays under a minute once built. Expect conflicts in
   `tests/tables/untested.txt` when merging `main`: resolve by taking
   `main`'s file and blessing again.

## Handback

Merged 2026-11-22 (branch head `921d401`). `templ.rs` writes `TemplLink`
and the specialisation records, template heads in key and unit form
with defaults taken from the declaration that gives them, every `in`
row of `TemplateTables` by declaration and by expression, and the
template parameter object. Decisions: `spec/landed/digest-kinds/WP-029.md`.
33 of its tests are marked `# pending` (decl_data 20, expr 9, units 3,
value 1).

Reviewed twice. The independent review found no row skipped or out of
order; it found tests that could not fail for what they named (fixed on
the branch: isolated where an edit can isolate the row, documented in
the landed file where the key carries the fact), and by running, two
leaks of instantiation into declared units that are not this
package's:

- a friend function template *defined* in a class template: Kiln sets
  `instantiated_from` on the first declaration of the namespace-scope
  template when the class is instantiated
  (`kiln_sema/src/templ/member.rs:316-329`), and the instantiated
  definition joins the declared entity's chain;
- a member-like constrained friend is a *declared* unit that exists
  only when the class is instantiated, and two instantiations give
  two entities one key (marked a collision, so not silent).

Decided at handback:

- **The two leaks**: scheduled, WP-032 (unit classification of
  declarations that an instantiation adds to a namespace-scope
  entity). Tests are in place, `# needs: units`:
  `demand/_/friend-defined-in-class-template`,
  `demand/_/member-like-friend-declared-by-instantiation`,
  `differ/TemplateTables/member_like_friend`.
- **`from`/`from_args` of an implicit instantiation** are withheld
  from the unit with `Pending(Demand)` (§9.4's prose); §11.9's table
  names them for a class only. The demand package writes them into
  `definition` for functions and variables too and corrects §11.9.
  Scheduled with that package.
- **`param_object_values`** stays at the `data` position of a
  `TemplateParamObject` and is not a closing row of every stream:
  landed file; folded into §9.5 at the next fold.
- **A default inside a template template parameter's own head given by
  another declaration is not merged** (`templ.rs`, `template_parm_info`):
  deferred, `spec/digest-kinds.md` "Open questions" (a false
  difference at worst, never a missed one).
- **The `differ` runner does not report unexpected changes of derived
  units**: dropped. Derived units are free by design (WP-024); what a
  use must not change is the `demand` runner's to show.
- `Area::Templ` is written by nothing any more; the variant goes when
  `Area` does (the last area package), so that the packages in flight
  do not meet a changed `lib.rs`.
