# WP-049 — slip_digest: a node reached twice in one stream is written once

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-034, WP-035, WP-036
- Size: M
- Parallel with: WP-040, WP-041, WP-045, WP-046

**Starts when WP-034, WP-035 and WP-036 are on main** (it edits the
expression and statement walks they own). A cost problem of the digest,
not a correctness one: the streams are right and too large.

## Scope

Kiln's AST is a graph in places: one expression or statement node is
the child of two parents, or is reached once through the semantic form
and again through the form as written. The walk writes the node's whole
subtree at each visit, so some shapes cost bytes and time quadratic or
worse in the size of the source:

| Shape | Measured | Recorded in |
|---|---|---|
| a designator range `[0 ... N-1] = e` in an initialiser list: the initialiser is written once per slot | 132 589 bytes for N = 10, 13 253 060 for N = 1000; O(n·\|E\|) | `spec/landed/digest-kinds/WP-035.md` "InitListExpr.a: runs" |
| nested designated lists in a template: each level's written form (`ColdExprData` `syntactic_list`) holds the semantic form's initialisers again | 654, 1130, 1725, 2439, 6485, 12 435 bytes for 1, 2, 3, 4, 8, 12 levels | the same file, "Nesting" |
| `return s;` in a constexpr function: two constructions share one argument node (`kiln_sema` `stmt.rs:1954`) | twice the argument | the same file; `spec/landed/digest-kinds/WP-034.md` |
| an expanded statement (`template for`): `range_init` is written twice, and each expansion carries its inner pattern, so nesting compounds | 21 934 / 35 478 bytes and on, quadratic in the nesting; figures in the landed file | `spec/landed/digest-kinds/WP-034.md` "A shape for WP-049" |
| the statements and expressions the review of WP-034 measured as reached twice | its figures | `spec/landed/digest-kinds/WP-034.md` and the Handback of `docs/wp/WP-034.md` |

`spec/digest.md` §4.4 already names "back-references to a node already
written in the same stream" among the numberings a stream may use. This
package specifies them and implements them: within one unit's stream, an
expression or statement node met again is written as a reference to its
first writing.

Files: `crates/slip_digest/src/expr.rs` (the driver that pushes a child:
one place), `stmt.rs` (the same for a statement), `walk.rs`
(`UnitState`: the memo, saved and restored as the opaque-value numbering
is), `spec/digest.md` §4.3/§4.4, `spec/digest-kinds.md` (the head of §7
and of the statement section: the encoding), `spec/landed/digest-kinds/WP-049.md`.
No per-kind file changes: a kind's rows do not know whether the node is
a first writing.

## What is decided

1. **The rule** (`spec/digest.md` §4.3, beside opaque values). In one
   stream, nodes are counted in the order they are first written, in one
   sequence for expressions and statements together, from 0 at the head
   of the stream. A node that the walk reaches again **in the same
   state** (decision 3) is written as `tag BACKREF`, `uv` its count, and
   its rows and children are not written. A first writing carries no
   number: the stream of a unit in which no node is reached twice is
   byte for byte what it is today, and no golden of such a unit moves.
   `BACKREF` is a tag no expression or statement kind uses (the next
   free value of the tag space the driver writes a node's kind with;
   say which, and add its row to the tables as a row of the walk, not of
   a Kiln type).
2. **Why it cannot hide a difference.** Two streams are equal only if
   every first writing is equal and every back-reference names the same
   count, that is, the same sharing. Sharing is a fact of the AST that
   Kiln builds deterministically from the translation unit; a
   transformation that turns a shared node into two equal nodes (or the
   reverse) changes the stream, which is a difference reported where the
   code generated is the same: allowed (a false difference), and to be
   shown not to happen for the shapes of the table above when only names
   change. State this argument in §4.3 in two sentences.
3. **The state is part of what is remembered.** A node's rows are not a
   function of the node alone: `w.unit.expr.dependent` (rows written
   only inside an instantiation-dependent expression, such as
   `CXXThisExpr.aux-implicit` and `CXXPseudoDestructorExpr.aux-qualified`),
   the profile mode of WP-036, `in_key`, and whatever else a row reads
   from the walk. The memo's key is the node **and** every such piece of
   state: reached again in another state, the node is written again in
   full and counted again. **Find every piece of walk state that any
   row of any kind reads** (grep `w.unit`, `w.in_key`, the profile flag,
   and the arguments the drivers pass down) and list them in the landed
   file with the rows that read each; a state you leave out of the key
   is a wrong equal. If the list is long or open-ended, the conservative
   form is: the memo is cleared whenever any of them changes (entering
   and leaving a dependent expression, a profile, a key), and that is
   acceptable if the shapes of the table still become linear.
4. **Scope of the memo**: one unit's stream. It starts empty at the head
   of every stream (a unit, a type digest, a key, a resolved unit) and
   is saved and restored around a stream written inside another, exactly
   as `UnitState::opaques` is (`spec/digest.md` §4.4). A memo is never
   shared between units: a back-reference into another unit's stream
   would make a digest depend on the order units are written in.
5. **Opaque values keep their own numbering.** An `OpaqueValueExpr` and
   its source are numbered as today; a source reached as an ordinary
   child and again through the opaque value is the existing rule's case,
   not this one. Say in §4.3 which rule applies when both could (the
   opaque rule first), and test it.
6. **`syntactic_list`.** With the rule above the written form's
   initialisers are back-references to the semantic form's, and the
   nested case is linear. If it is not (because Kiln builds fresh copies
   at each level, `kiln_sema` `templ/actions.rs:2162`, so nothing is
   shared to refer back to), do not special-case it here: measure, say
   so, and give the reproducer for a request to Kiln (instantiation
   reads only the outermost written form, `templ/subst/exprs.rs:2935`).
7. **Cost of the memo itself.** One map insertion per node written is on
   the hot path of every unit. Measure the digest of the LLVM
   `lib/Support` units (the map task of WP-050 reports digest time and
   bytes per observer; `cargo xtask corpus` has the tree) before and
   after: wall-clock and peak memory within 3 % of before on the units
   that have no shared node, or say what it costs and why it cannot be
   less. A map keyed by the node id with a cheap hasher, cleared per
   stream, is the expected form; a memo of only the kinds that can be
   shared is acceptable only with the list of kinds proven from Kiln's
   builders (cite `file:line` for each site that stores one node under
   two parents), because a kind left out is only a cost, but a list
   that is believed and wrong hides the next quadratic shape.

## Interface

None outside the crate. `Cause` gains nothing.

## Tests

- Unit tests of growth, each asserting bytes linear in N (N and 4N, at
  most 4.5 times the bytes): the designator range, the nested designated
  lists in a template (or the measurement and the Kiln reproducer,
  decision 6), `return s;` in a constexpr function, each shape of
  `spec/landed/digest-kinds/WP-034.md`. Un-ignore the measure
  `nested_designated_lists`.
- `tests/differ/`: for each shape, a pair that differs only inside the
  shared node (so the first writing differs), and a pair that differs
  only in a node after the shared one (so the count of the
  back-reference is not what makes them differ).
- `tests/differ/_/shared-node-in-two-states`: a node reached once
  outside and once inside an instantiation-dependent context (or, if no
  source gives that, a unit test on the walk that enters the state by
  hand as `expr.rs`'s `put back` test does), changed in a row that only
  the second state writes: the units differ.
- `tests/equal/`: a pair whose sides differ only in names under a
  relocation rule, with a shared node on both sides: equal (the sharing
  does not move with a name).
- `crates/slip_digest/tests/determinism.rs` still passes: a unit's
  stream is the same written first or written again (§4.4); add a case
  with a shared node in a unit that is written inside another's stream.
- Mutations, each caught by a named test: the memo not restored after an
  inner stream; the state left out of the key; the count taken per kind
  instead of in one sequence; a back-reference written for an opaque
  value's source.
- Goldens: list every golden that moves and show for each the shared
  node that explains it; a golden that moves without one is a bug.

## Done when

The full gate passes with `main` merged in. The handback gives the rule
as written in §4.3, the list of decision 3, the before/after bytes of
each shape, the measurement of decision 7, the goldens that moved, and
any shape that stays superlinear with its reproducer.

## Out of scope

Kiln's building of shared or copied nodes (reported, not changed);
sharing between units; types (a type is digested once per translation
unit already, `spec/digest.md` §5).

Trusted base: second review, asking whether any row reads state that
the memo's key does not hold, and whether a back-reference can make two
units equal that differ.
