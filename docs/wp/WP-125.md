# WP-125 — a consumed `__PRETTY_FUNCTION__` in a function template whose signature is respelled

- Status: done
- Milestone: M1
- Track: C
- Needs: WP-041
- Size: S
- Parallel with: WP-106, WP-122, WP-123, WP-124 (one digest branch merges at a time)

## Scope

The fourth review round of `docs/wp/WP-041.md` found (its "G3"):

```cpp
namespace ns { struct S { static int value; }; }
template <class T> unsigned long h(T, decltype(ns::S::value)) {
  return sizeof(__PRETTY_FUNCTION__);
}
unsigned long u = h(1, 1);
```

against the same with `decltype(::ns::S::value)`. clang 19 gives 53 and
55. The digest says nothing changed. `spec/digest.md` §9 writes a
consumed name-derived value by value (`sizeof(__func__)` is its first
example), so the instantiation's definition should differ. The same
respelling in a function that is not a template (`h(ns::S)` against
`h(::ns::S)`, an alias, a `decltype` of a variable) differs, rightly.
WP-041 left the source as a pending pair naming this package.

1. **Which of two defects it is.** Either Kiln's string for the
   instantiation does not print the parameter as written (then Kiln's
   own `sizeof` is the same on both sides, the digest is faithful to
   the parse, and the defect is Kiln's against clang: a For Kiln item
   with the two strings; Slip's truth is Kiln's parse and the pair
   waits `# needs: kiln`), or Kiln's values differ and the digest does
   not write them (a hole in the trusted base: find where the
   instantiation's `sizeof` operand is written symbolically though it
   is consumed, and fix it). A `static_assert` on each side settles
   which. Say what Kiln's `pretty_function`
   (`kiln_ast/src/dump/pretty.rs`) prints for an instantiation's
   parameter of a non-dependent written type, a dependent one, a
   return type, and a template argument list, each against clang 19.
2. **The same question for the string only passed on**: by §9 it is
   equal in the unit digest, and the names digest of
   `docs/wp/WP-112.md` reports it. If WP-112 is on `main`, a test that
   the report lists the instantiation for this pair; if Kiln's string
   does not change, the report cannot, and that is part of the For Kiln
   item.
3. **The neighbours**, a pair each, in a function template with one
   instantiation: `std::source_location::current().function_name()`
   consumed (its length as an array bound); `__func__` (unchanged by a
   respelling: `equal`); a member function of a class template whose
   class is named through an alias in the out-of-line definition; a
   lambda's `__PRETTY_FUNCTION__` inside the template.
