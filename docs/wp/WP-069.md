## Interface

```rust
// slip_digest (spec/verify.md §9.5)
pub struct Options<'a> { /* … */ pub rule_use: bool }
pub struct Output { /* … */ pub rule_use: Vec<slip_model::agreement::Use> }

// slip_model::keys::RuleTable gains
/// `map`, and the index of the rule that gave the entity's own
/// `(parent, kind, name, disc)` its key, if one did. A rule applied to
/// an ancestor or inside a discriminator is not reported here.
pub fn map_traced(&self, key: Key) -> (Key, Option<usize>);
/// The index of the rule that produces `key`:
/// `(r.to_parent, r.kind, r.to_name, r.disc) == key`'s four fields.
pub fn produces(&self, key: &Key) -> Option<usize>;
```

- An entity is counted once, declared or derived, however many
  declarations it has and however many times its key is written.
  `via(r)` when `map_traced` reports `r` for the entity's own key;
  `direct(r)` when it reports no rule and `produces` reports `r` for the
  mapped key. `Output::rule_use` is sorted by rule and holds only rules
  with a count that is not 0. With `rule_use` false, or an empty table,
  it is empty and the walk does no extra work (the counter
  `digest.units` and the time of the determinism test do not move).
- The index of a rule is its index in `Declared.rules`, which is the
  table's order (`spec/verify.md` §2).
- Nothing else of `Output` changes: the digests of every existing test
  are what they were.
- `map::with_input` (`docs/wp/WP-050.md`) passes `Options` through: a
  caller that asks for `rule_use` gets it. If that function fixes the
  options itself when this package starts, it gains the parameter here
  and the handback says so.

## Added after the review of WP-103 (2026-11-23)

The rules suite of `docs/wp/WP-103.md` counts `via` and `direct` for its
own cases, and its review found two places where that test-only count
departs from `spec/verify.md` §9.1. This package builds the real
counts and must get both right, each with a test:

- `via(r)` counts **entities**, including those that have no unit of
  their own (a specialisation that is only named, a block-scope
  `extern` declaration); the suite counts records.
- `direct(r)` counts entities whose **own, unmapped** key is the key
  `r` produces; an entity that another rule maps onto that key is not
  counted (the suite counts it: two rules onto one name gave 2 for 1).

  counted by its own key only, an entity with no key for no rule, one
