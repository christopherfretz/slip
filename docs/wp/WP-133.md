# WP-133 — declarative references: the names version 0 does not return, as far as the pin gives them

- Status: todo
- Milestone: M3
- Track: G
- Needs: WP-091, WP-095
- Size: L
- Parallel with: WP-129 and WP-132 (all three edit `spec/api.md`; ask the supervisor which merges first)

## Scope

`spec/api.md` §6.5 rule 4 leaves out of `references_to` the names
written in declarative contexts, under the feature test
`__slip_lib_meta_declarative_references`. The conformance suite showed
what that costs (`spec/landed/api/WP-091-effects.md`, "Disagreements",
third): the rename example edits the call through `using
lib::old_name;` and neither edits nor reports the using-declaration
itself, though §10.2 promises a report for every place the rename
cannot reach. A rename and a relocation are the transforms Slip exists
for; they cannot be written without these names.

1. **The inventory first** (in the landed file, before any host code):
   for each context of rule 4's first row (a using-declaration, a
   using-enum-declaration, a using-directive, a namespace alias's
   target, the qualifier of a declarator, an elaborated reference that
   declares, a friend declaration's name, an explicit specialisation's
   and an explicit instantiation's target, a concept name, a
   designator), what the Kiln pin's written-reference table and `Ast`
   give: an entry with the entity, an entry without, nothing. Use
   `spec/landed/api/WP-095.md` and `docs/requests/KB5*`, `KB6*` (several
   are asked of Kiln already: do not ask twice; name the item). Each
   context the pin does not give is a "For Kiln" item with a reproducer
   and stays in rule 4 under a feature test of its own.
2. **The references.** Each context the pin gives becomes a reference
   in the sense of §6.5 rule 3, with a role of its own in the table.
   Rules to write and test:
   - a using-declaration that names an overload set is one reference
     per entity it names, all with one extent and one name range (§5.4
     rule 3 already has several references with one extent); its
     `referent_of` is the named entity, not the using-shadow;
   - a qualifier component in any of these contexts is a qualifier
     component as elsewhere;
   - `extent_of`, `name_range_of`, `is_editable` hold as for every
     reference; the sibling spelling of §7.2 rule 1 applies (a
     using-declaration's name respelled to a sibling keeps its written
     qualifier);
   - `enclosing` (which declaration holds the reference: KB6 amendment
     1, item 10.1, is open for some of these; say what the host answers
     until the pin has it).
3. **What is still not returned is reported.** Where a context stays
   out, the host counts the names in that context that are spelled
   like an entity given to `references_to` (as rule 6 counts unresolved
   names), under a counter of its own, so that the rename example can
   say "N names in declarative contexts were not examined" instead of
   nothing. Propose the counter's name and precise definition in the
   landed file.
4. **The examples.** `resource/examples/rename_function.cpp` and its
   conformance directories: `use-through-a-using-declaration` now
   expects the using-declaration edited; new directories for a
   namespace alias, an out-of-line definition's qualifier (a rename of
   a namespace: write the minimal example if none exists), a friend
   declaration, an explicit specialisation. Where the pin gives nothing,
   the directory expects the report of item 3.
5. **`slip_refactor`** (the built-in rename and relocation) reads the
   table itself (`docs/wp/WP-127.md` has its own list of names a rename
   leaves behind): do not change it here; list in the landed file which
   of WP-127's cases this package's references would let a transform
   written in C++ handle.

## Tests

A conformance directory per context and rule; the isolation test
unchanged; `cargo xtask api-table` regenerated.

## Rules

`docs/AGENTS.md`. No string manipulation of code in any example or test
transform. The gate is the full `cargo xtask ci`. Second review (the
host's reference table is what every rename rests on); the reviewer's
question: a name in one of these contexts that denotes the entity and
is not returned, with no counter saying so; a reference returned whose
referent is not what the name denotes.

## Done when

The gate passes with `main` merged in; every context of rule 4's first
row is a reference, or is counted and has a "For Kiln" item.

## Out of scope

Dependent and imported references (rule 4's second and third rows).
