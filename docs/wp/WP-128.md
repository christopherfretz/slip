## Scope

The first run of the pitfall catalogue's runner (`docs/wp/WP-056.md`,
places mandatory) found a finding whose place disagrees with
`spec/verify.md` §6.1: E11 `bad-3`, `changed pick<int>()`, placed on
the pre side at `pick.h:1` (the pattern) where §6.1 says
`pick_int.h:1` (the site WP-056's handback names with the report's
lines). The tree is marked `xfail` naming this package; E22 `bad-7` may
be a second case (see the same handback).

1. State from §6.1 what the place of a derived unit is on each side (an
   instantiation: its point of instantiation, its pattern, the
   declaration that caused it?) and say whether the text or the code is
   wrong for E11 `bad-3`. If the text is ambiguous, propose the rule
   that helps a user most (the site in owned code whose edit changed
   the unit) and stop for the supervisor before changing §6.1.
2. Make the code and the text agree; remove the `xfail` lines.
3. A table in the landed file: for an implicit instantiation, an
   explicit instantiation, an explicit specialisation, a member of an
   instantiated class, a defaulted special member, a lambda's call
   operator: the place on each side, with a test each.
