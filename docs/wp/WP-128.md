# WP-128 — the place of a finding for a derived unit on the pre side

- Status: done
- Milestone: M1
- Track: C
- Needs: WP-056
- Size: S
- Parallel with: anything that does not edit the verify job's localisation

## Scope

The first run of the pitfall catalogue's runner (`docs/wp/WP-056.md`,
places mandatory) found a finding whose place disagrees with
`spec/verify.md` §6.1: E11 `bad-3`, `changed pick<int>()`, placed on
the pre side at `pick.h:1` (the pattern) where §6.1 says
`pick_int.h:1` (the site WP-056's handback names with the report's
lines). The tree is marked `xfail` naming this package; E22 `bad-7` may
be a second case (see the same handback).

1. State from §6.1 what the place of a derived unit is on each side (an
   instantiation: its point of instantiation, its pattern, the
   declaration that caused it?) and say whether the text or the code is
   wrong for E11 `bad-3`. If the text is ambiguous, propose the rule
   that helps a user most (the site in owned code whose edit changed
   the unit) and stop for the supervisor before changing §6.1.
2. Make the code and the text agree; remove the `xfail` lines.
3. A table in the landed file: for an implicit instantiation, an
   explicit instantiation, an explicit specialisation, a member of an
   instantiated class, a defaulted special member, a lambda's call
   operator: the place on each side, with a test each.

## Handback

**Item 1.** `spec/verify.md` §6.1 is clear and names this case: an
explicit specialisation is placed at the declaration the source wrote
(`pick_int.h:1`), a derived unit at its pattern. The code was wrong: the
declaration Kiln makes of `pick<int>` at the pattern before the source
specialises it shares the `SpecInfo` that then says
`ExplicitSpecialization`, so `templ::made_by_instantiation` called it
written. `crates/slip_digest/src/trace.rs` `entity_place` now skips it
(`made_before_explicit_specialisation`, Kiln's `Ast::contract_first`
reading). §6.1 is unchanged. E22 `bad-7` is no second case (a declared
unit, placed by the site of its difference; it passes).

**Item 2.** E11 `bad-3`'s `xfail` line removed; it passes with places
mandatory. Only places move: the walk's digests, verdicts and counts are
not read from the chain's places.

**Item 3.** The table with a test for each row, the mutation "the place
taken from the pattern" and the three tests it fails:
`spec/landed/verify/WP-128.md`.

**Open point.** §6.1's gloss "which for an instantiation is where its
pattern is" is not true of a class template's explicit instantiation
that is the first to name the specialisation (placed at the directive,
where Kiln makes its declaration; the rule itself gives that). Not
changed; the supervisor may narrow the gloss to an implicit
instantiation.
