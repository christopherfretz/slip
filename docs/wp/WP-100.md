# WP-100 — slip_digest: a parameter's attributes over the function's chain

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-026, WP-031
- Size: S
- Parallel with: WP-034..040, WP-044, WP-045, WP-046, WP-047

**Can start now.** A gap of the digest found by the audit against
Kiln's ODR hash (`spec/landed/digest-kinds/WP-042.md`, finding S1): two
programs that differ in meaning digest equal.

## Scope

`spec/digest-kinds.md` §10.1 says a declaration's attributes are those
of "every declaration of the entity's chain". A parameter has no chain
of its own: parameter *i* of another declaration of the function is
another `DeclId`, and `decl_func::alias_params` maps it only to an
ordinal. So `attrs::decl_attrs`, called for the parameters of the
declaration read, writes the attributes written on that declaration's
parameters and loses those written on the others'.

```cpp
// A
void f([[indeterminate]] int x);
void f(int x) { int y = x; }   // reading x is not erroneous
// B
void f(int x);
void f(int x) { int y = x; }   // erroneous behaviour (C++26 [basic.indet])
```

C++26 [dcl.attr.indet]/2 wants `[[indeterminate]]` on the first
declaration, which is the one the digest does not read when a later one
is the definition. `nonnull`, `noescape`, `pass_object_size`,
`annotate`, the lifetime and Swift parameter attributes have the same
gap. Kiln's ODR hash reads `INDETERMINATE` on parameter *i* of every
declaration (`kiln_abi` `odr_def/attrs.rs:104-112`).

Files: `crates/slip_digest/src/attrs.rs` (`decl_attrs` and a variant
for a parameter), `decl_func.rs` or `local.rs` only at the call that
writes a parameter's attributes, `spec/digest-kinds.md` §10.1 and §5.4,
`spec/landed/digest-kinds/WP-100.md`. `docs/wp/WP-045.md` and
`docs/wp/WP-046.md` are open in `decl_func.rs` at other sites (the body,
`default_arg` of an instantiated declaration): touch the parameter loop
only, and as little of it as the rule needs.

## What is decided

1. **The rule** (§10.1, after the declaration rule; the same sentence
   in the introduction of `ParamData`, §5.4): for a parameter, the
   chain is parameter *i* of every declaration of the function's chain
   that `ParamData` `default_arg` reads
   (`spec/landed/digest-kinds/WP-026.md` "Default arguments": block-scope
   declarations are left out), in chain order; within one parameter in
   stored order; `inherited` copies left out as for any declaration.
   Annotations (`AnnotArena`, §10.5) follow the same chain.
2. **One set of declarations, not two.** The declarations whose
   parameters are read are found by the function WP-026 uses for
   default arguments; if that is not one function today, make it one
   and call it from both. A declaration with fewer parameters than *i*
   (a declaration that is erroneous, or a C-style redeclaration)
   contributes nothing for *i*.
3. **What else is a parameter's alone.** Find, from Kiln's source, every
   fact Kiln keeps per parameter declaration that a later declaration
   can state and the declaration read does not repeat: attributes and
   annotations are two; check `ParamData`'s own fields (`flags`, the
   `this`-parameter mark, `KNR`) and the parameter's `VarData`/`LetData`
   words that sema merges or does not merge across redeclarations
   (`kiln_sema`'s redeclaration merge for functions: cite `file:line`).
   A fact Kiln merges into every declaration needs nothing. A fact it
   does not merge and that changes meaning gets the same chain rule and
   a test; one that is spelling only (the parameter's name) stays out.
   List what you found either way.
4. **Templates.** For a function template the chain is the template's
   declarations' patterns; for an instantiated declaration the
   attributes are "written as found" (§10.1 last paragraph): check what
   Kiln instantiates for a parameter's attributes when the pattern's
   first declaration has the attribute and the definition does not, and
   test it (an explicit instantiation's unit differs between A and B).
   If Kiln instantiates from the definition's parameters only, the
   instantiation loses the attribute in Kiln itself: that is a finding
   for Kiln, with the reproducer, and the unit is written as found.
5. **No digest of a function without parameter attributes on other
   declarations changes** except by this rule's count: if the encoding
   of the list is unchanged (one count, then the nodes), the goldens of
   functions with one declaration do not move. Say which goldens moved
   and why.

## Tests

- `tests/differ/_/param-attr-on-first-declaration` (the pair above,
  `-std=c++26`, `changed f(int)`), and the same for `nonnull`
  (`__attribute__((nonnull))` on a pointer parameter), `noescape`,
  `annotate`, on: the first of two declarations, the second of three, a
  friend declaration inside a class, a member function declared in the
  class and defined outside.
- `tests/equal/`: the attribute moved from the first declaration's
  parameter to the definition's digests **as §10.1 says a moved
  attribute of a declaration does** (chain order is kept: read the rule
  and assert what it gives; do not invent a normalisation).
- `tests/differ/`: an attribute on a parameter of a block-scope
  redeclaration does not reach the function's unit (the local
  declaration's own unit or stream changes instead: say which).
- The template cases of decision 4.
- Mutations, each caught by a named test: the chain read from the
  declaration read only (today's behaviour); the chain in reverse
  order; block-scope declarations included; annotations left on the old
  chain.
- Re-bless `tests/tables/untested.txt` only if rows are now tested.
