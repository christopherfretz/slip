## Interface

```rust
// store.rs  (§2)
pub enum Access { Exclusive, Shared }
pub enum StoreError { Unrecognised(PathBuf), Version(String), Busy { pid: u32 }, Io { path: PathBuf, error: std::io::Error } }
pub struct Store;        // removes its own tmp files and, if it holds it, the lock, on Drop
impl Store {
    pub fn open(dir: &Path, access: Access) -> Result<Store, StoreError>;
    pub fn root(&self) -> &Path;
    pub fn publish_plan(&self, bytes: &[u8]) -> Result<Digest, StoreError>;              // name = content id
    pub fn read_plan(&self, id: &Digest) -> Result<Option<Vec<u8>>, StoreError>;
    pub fn find_plan(&self, hex_prefix: &str) -> Result<Vec<Digest>, StoreError>;        // for `--plan <id>`; all matches
    pub fn publish_shard(&self, plan: &Digest, phase: Phase, round: u64, observer: &Digest, bytes: &[u8]) -> Result<Digest, StoreError>;
    pub fn read_shard(&self, plan: &Digest, phase: Phase, round: u64, observer: &Digest) -> Result<Option<Vec<u8>>, StoreError>;
    pub fn publish_run(&self, plan: &Digest, phase: Phase, round: u64, started_unix_ns: u64, bytes: &[u8]) -> Result<PathBuf, StoreError>;
    pub fn latest_run(&self, plan: &Digest, phase: Phase) -> Result<Option<Vec<u8>>, StoreError>;   // greatest started_unix_ns, any round
    pub fn log_path(&self, plan: &Digest, phase: Phase, round: u64, observer: &Digest, attempt: u64) -> PathBuf;   // parent directories created
    pub fn remove_log(&self, …) -> Result<(), StoreError>;                                // logs are kept only for failed attempts
}
pub fn cleanup_on_signal(store: &Store) -> impl FnOnce() + Send + 'static;   // what `signals::install` needs to remove tmp files and the lock

// worker.rs  (§5.1, §5.2)
pub const PROTOCOL: u64 = 1;
pub struct Job { pub store: Vec<u8>, pub plan: Digest, pub phase: Phase, pub round: u64, pub observer: Observer }
pub trait Task { fn run(&mut self, job: &Job) -> Result<Shard, String>; }
pub enum ToWorker      { Job(Box<Job>), Exit }
pub enum ToCoordinator { Ready { protocol: u64, tool: String },
                         Done { observer: Digest, shard: Digest, cpu_ns: u64, peak_rss: u64 },
                         Failed { observer: Digest, message: String } }
impl ToWorker      { pub fn encode(&self) -> Vec<u8>; pub fn decode(bytes: &[u8]) -> Result<Self, wire::Error>; }
impl ToCoordinator { pub fn encode(&self) -> Vec<u8>; pub fn decode(bytes: &[u8]) -> Result<Self, wire::Error>; }
pub fn write_frame(w: &mut impl Write, payload: &[u8]) -> io::Result<()>;      // u32le length, payload, flush
pub fn read_frame(r: &mut impl Read, max: usize) -> io::Result<Option<Vec<u8>>>;   // None at a clean end of input
pub struct ServeOptions { pub tool: String, pub stack_bytes: usize, pub max_jobs: u64 }
pub fn serve(task: impl Task + Send, options: &ServeOptions, input: impl Read, output: impl Write) -> io::Result<()>;
```

Adjust shapes where the code shows a better one and record the final
interface in `spec/landed/exec/WP-008.md`; WP-009 builds on it.

`Observer` and `Phase` inside a message use the plan's own encodings:
`slip_model::formats::{encode_observer, decode_observer, encode_phase,
decode_phase}` (WP-006). A message that has bytes left after its last field
is malformed. `read_frame` refuses a length above `max` without allocating
it (the coordinator and the worker use 64 MiB).

`serve` implements §5.2 exactly: `Ready` first; each job on a thread with
`stack_bytes` of stack; a panic of that thread is caught and becomes
`Failed` with the panic's message; the shard is validated (`Shard::validate`,
and its header must name the job's observer, phase and round), published to
the store named by the job (opened `Shared`), then `Done` with CPU time and
peak resident size read from `/proc/self` (0 where unavailable); after
`max_jobs` jobs, or on `Exit` or end of input, it returns. Peak reset
between jobs as §5.2 says.

**The fake worker** runs `serve` with a task whose behaviour for a job is
chosen by the job's observer: `observer.command.argv[1]` is one of
`ok`, `diagnosed`, `fail:<message>` (`Err` from the task), `panic`,
`exit:<status>` (the process exits without answering), `abort` (dies by a
signal), `hang` (sleeps for ever), `alloc:<MiB>` (allocates and touches that
much, holds it for `argv[2]` milliseconds if present, then `ok`),
`sleep:<ms>` (then `ok`), `garbage` (writes bytes that are not a frame),
`wrong-observer` (answers `Done` naming another observer), `no-shard`
(answers `Done` without publishing), `late-output` (writes after `Exit`).
Document the list at the top of the file; WP-009's tests rely on it.

## Tests

`crates/slip_exec/tests/store.rs` (§2): initialising an absent and an empty
directory; refusing a non-empty directory with no `VERSION` and a `VERSION`
other than `1`; every path of the layout; publish is atomic (a reader in
another thread never sees a partial file; nothing is left in `tmp/`) and
replaces an existing file; `Busy` when a live process holds the lock (hold
it from a child process); a lock naming a dead pid is taken over and stale
`tmp/` entries are removed; `Shared` neither locks nor cleans; `Drop`
removes the lock and the store's own `tmp/` files; `find_plan` and
`latest_run`.

`crates/slip_exec/tests/worker.rs` (§5.2): encode/decode round trip and
hand-written bytes of each message; rejection of an unknown tag, a truncated
message, trailing bytes, an oversized frame; and, against the fake worker
started as a child process: `Ready`, a job answered `Done` with the shard in
the store, `fail:` and `panic` answered `Failed`, `max_jobs`, `Exit`, end of
input.
