## Interface

`spec/exec.md` §8.6: `args.rs` (`ImageArgs` and `WorkerArgs` are
WP-052's and do not change), `declare::main`, `units::main`,
`verify_cmd::main`. `commands::dispatch` calls the three.

What you build on, as it is today:

- `commands.rs`: `parse` (`crates/slip_cli/src/commands.rs:161`) is the
  model for `verify`: the exclusive store, the signal handling, the
  selection, `pool_options` (`:208`), `worker_command` (`:354`), the
  summary lines. Share the code; do not copy it. Amended by M2: `verify`
  runs the phase with `pool::run_with` (`Phase::Verify`, the round) and
  a `JobExtra` whose `post` is `Post { pre: 0, declared: <the id
  publish_declared returned>, image: Image::to_post() }`, the same for
  every job; it appends `--findings <n>` and `--locate <n>` to the
  worker command and nothing else (§8.7).
- `pool::Summary` (`spec/exec.md` §5.7): `run` (the record), `run_path`,
  `outcomes`. "This run's shard" is decided from `Summary.run.jobs`
  alone: the `shard` of the observer's last entry against the content id
  of what `Store::read_shard` returns.
- `Store::latest_run(plan, Phase::Map)`
  (`crates/slip_exec/src/store.rs:588`) for the refusal of §8.7, and
  `Store::is_transform_round(plan, round)` for the last row of its
  table of input errors (amended by M2).
- `slip_verify::run`: `Header`, `Report::{new, add, verdict, to_json,
  to_text, verdict_line}`, `state` (WP-055). The command reads a map
  shard only for an observer whose verify shard is `diagnosed` or
  `rejected`.
- `Image::from_args`, `Image::parse`, `Side` (WP-052);
  `slip_digest::records::records`, `declare::{read, needs, resolve,
  finish}` (WP-055).

Rules a quick reading may miss:

- **A shard that is not this run's is no shard** for the report
  (`Report::add` with `None`): the observer is `failed`.
- **The `--report` file** is written through a temporary file in the
  same directory and renamed; an interrupted run writes none.
- **`declare` parses in this process**, one observer after another, and a
  parse changes the current directory: `--from`, `--out` and the store
  are made absolute first. `declare` and `units` need no pool and take
  no token beyond the implicit one.
- **`declare` writes nothing on an error**, and its warnings (an image
  that does not parse) do not change its status.
- **Status 4** only for `verify`'s incomplete run; an empty selection is
  one.
