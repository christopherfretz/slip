## Scope

The independent reviews of rows R, E (`docs/wp/WP-058.md`) and N25 to
N38 (`docs/wp/WP-105.md`) and their implementers listed hazards that no
row of `spec/pitfalls.md` covers. This package builds a row for each
that survives your own check, and writes its line in the tables of
`spec/pitfalls.md` §2 (N39 up), §3 (R13 up) and §4 (E18 up). Unlike
WP-105, **you write the table lines**: the lists below are sketches of
hazards, not subjects, and the earlier packages showed that a line
written before its row is built is wrong about one time in two.

For each sketch: derive it from the standard; decide whether it is a
hazard of its own or a second shape of an existing row (then it is a
numbered subject there, not a new row: say which, and build it there);
build the subject, the correct edit where one exists, the wrong edit,
preferably in its **silent** form; write the line. A sketch that turns
out not to be a hazard (any check catches it, or no edit a tool would
make produces it) is dropped with one sentence of why in the landed
file.

### Rename (rows R)

1. **A rename creates an override**: `B::f` renamed to `g` where `D`
   already has a non-virtual `g()`; `D::g` silently starts overriding.
   The opposite of R03.
2. **`using Base::f;` in a derived class**: renaming one `Base::f`
   overload drops it from the using-declaration's set; `d.f(1)`
   silently picks `Derived::f(long)`.
3. **A friend left behind**: `friend void helper(X &);` left after
   renaming `::helper` declares a new function; silent with an inline
   friend definition found by argument-dependent lookup.
4. **Names in strings**: `asm("label")`, `#pragma weak`,
   `[[gnu::alias("_Z1fv")]]`, `ifunc`, `weakref`. The attribute's unit
   is unchanged, so nothing differs in the translation unit: is there
   anything the verifier can show, or is this `verify.md` §8 ("What
   this does not show") with a row that pins the limit (`good` only,
   with the reason)? `__attribute__((cleanup(fn)))` names `fn` through
   lookup and must be caught.
5. **Stringising and registration macros**: `REGISTER(x)` expanding to
   `reg(#x, &x)`: the registered string changes with the rename. The
   rename counterpart of N17; no correct edit.
6. **Literal operators**: renaming the suffix `_km(unsigned long long)`
   to `_m` where `_m(const char *)` or a literal operator template
   exists changes what `5_m` selects.
7. **Deduction guides**: a class template renamed and used through an
   alias template with class template argument deduction; a user
   deduction guide left with the old name.
8. **A detection that turns silently false**: renaming the probed
   member makes `if constexpr (requires { t.size(); })`, a `void_t`
   trait or a constrained overload take the other branch. The opposite
   of R07.
9. **Names the language looks up**: a member `begin` renamed makes a
   range-based `for` fall back to a free `begin`; `get` and
   `tuple_size` for structured bindings (the member `get` renamed: the
   binding falls back to a free `get` found by argument-dependent
   lookup); `promise_type`, `await_ready`; a class-specific `operator
   new`; `std::hash` or `formatter` specialisations keyed on the
   renamed type.
10. **A template parameter renamed to the name of a member of a
    non-dependent base**: the base member hides the template parameter
    ([temp.local]).
11. **Renaming to the name of a library builtin**: `my_strlen` to
    `strlen` at global scope; the front end recognises a builtin.
12. **A rename that collides with a macro name**: `f` to `LOG` where
    `LOG(x)` is a function-like macro: usually `not_parsed`; silent
    when the expansion is valid.

### Other edits (rows E)

13. **Reordering class members**: data members (the order of
    initialisation in a constructor's mem-initializer list, layout,
    positional aggregate initialisation); virtual functions (the
    vtable). Reordering non-virtual member functions is a `good`.
14. **Removing `inline` or `constexpr`** from a header variable or
    function: linkage and one-definition changes; constant
    initialisation turned dynamic; `if consteval` and constant
    evaluation flipped.
15. **Overloaded address-of**: `&x` respelled as `addressof(x)` (a
    row-local declaration, no system header) where `operator&` is
    overloaded, and the reverse.
16. **Include order and the preprocessor**: a `#define` that a later
    header tests; `#pragma pack` push and pop across a moved include;
    `#pragma once` against include guards. Distinct from E04's lookup.
17. **Spelling edits that change meaning**, one subject each or one
    row with numbered subjects, your call: `S() {}` to `S() = default;`
    (value-initialisation zero-initialises, triviality); `NULL` or `0`
    to `nullptr` (overload selection); `push_back` to `emplace_back`
    shapes (explicit constructors considered: build it with a row-local
    class); `for (auto x : v)` to `for (auto &x : v)`; adding or
    removing `std::move`-like casts on a return; `enum` to `enum
    class`.
18. **An include replaced by a forward declaration**: `delete p` on an
    incomplete type skips the destructor.
19. **A block-scope insertion**, as a `good: none` subject (row E12
    moved to namespace scope because any declaration statement changes
    the function's digest): pins "never silent" for the table's
    original wording.

### Relocating a namespace (rows N)

20. An owned namespace-scope `using namespace legacy;` that dependency
    headers included later rely on.
21. A moved class-specific `operator new` or `operator delete`.
22. `extern` or `thread_local` variables declared by the dependency and
    defined by owned code.
23. A deduction guide for a dependency template written in an owned
    `legacy` block.
24. `friend struct X;` naming a dependency class, which inside `acme`
    silently declares a new `acme::X`.
25. A header that two translation units include before and after the
    compatibility declarations (two observers: the row needs two
    commands; if `spec/pitfalls.md` §1 cannot express it, say what it
    would need and do not build it).
26. `__PRETTY_FUNCTION__` prints parameter types as written: an
    E06-style respelling of a parameter type through an alias changes a
    string the program holds (`docs/wp/WP-104.md` was told to write the
    written types with the builtin). A row E, or a subject of R12.

What other languages and build files hold (a renamed `extern "C"`
symbol used from `.c` files, linker scripts, `.def` exports,
`dlsym("f")`) is not a row: add the paragraph to `spec/verify.md` §8.

## Rules

The eight rules of `docs/wp/WP-057.md` "Rules" and the further rules of
`docs/wp/WP-105.md` "Rules" hold (every row discriminates: name the
blind verifier; prove every silent change by a method you record; names
as `spec/verify.md` §6.1 gives them; no system header; `dep/`
unchanged). The format is `spec/pitfalls.md` §1 as amended
(`declared-<k>.txt`, `good-<k>: none`). Read
`spec/landed/pitfalls/WP-057.md`, `WP-058.md` and `WP-105.md` first.

Files you own: the new row directories under
`crates/slip_verify/tests/pitfalls/`, added subjects and lines in the
rows a sketch turns out to belong to, the new lines of
`spec/pitfalls.md` §2 to §4, the paragraph of `spec/verify.md` §8,
`spec/landed/pitfalls/WP-109.md`.
