# WP-162 — test work directories off a mount that changes inode numbers

- Status: todo
- Milestone: M1
- Track: H
- Needs: none
- Size: S
- Parallel with: every package

## Scope

Found on 2026-11-24 (the supervisor's handback of `docs/wp/WP-159.md`):
the workspace mount changes the inode numbers of freshly created files
in bursts, and the front end matches an overlay entry to a file by
device and inode. A test that writes a tree and then parses it with an
overlay fails at random there (`cargo xtask transform`: 1 and then 3 of
108 on the mount, 0 in four runs with the work directories on the
container's disk). The guards make it loud; it still costs a gate.

The build stays where it is (the operator's rule: nothing is built
outside the workspace). Only **work directories**, the trees a test
writes and then reads, move.

1. One rule, in `spec/harness.md` §11: a test's work directory is under
   `$SLIP_TEST_ROOT` when that variable is set and not empty (a
   directory, made if missing), else where it is today. `scripts/env.sh`
   of the supervisor's workspace sets it; nothing in the repository
   depends on its value.
2. `cargo xtask transform` (`xtask/src/transform.rs`, `target_dir`): the
   work directories go under `$SLIP_TEST_ROOT/transform/<checkout
   name>/` when set; the `slip` binary is still the target directory's.
   The line that names a kept directory prints the path it is at.
3. Every test that takes its directory from `CARGO_TARGET_TMPDIR` or
   `CARGO_TARGET_DIR` and writes files that a front end then reads (list
   them all in the handback, with the ones left alone and why): through
   one helper per crate's `tests/common`, same rule, a directory per
   test binary and process so that two checkouts and two runs never
   share one. `cargo xtask demo`, `corpus` and `fscheck` are not
   touched: they take their directories from the corpus or the command
   line.
4. `cargo xtask fscheck` gains the row `inode-stable` (relied on):
   create files, read their inode numbers, wait, read again, over
   `--rounds`; on the workspace mount it is expected to fail now and
   then, and the row's text says what fails when it does. Seed: the
   supervisor's probes (their paths are in the brief).

## Tests

`xtask/tests/transform.rs`: with the variable set, the work directory
is under it and the run passes; unset, it is under the target
directory; a kept directory's line names the right path. A unit test of
each crate's helper. The mutation "the variable is read but the work
directory is still made under the target directory" is killed.

## Done when

`cargo xtask ci` passes with `main` merged in **and
`SLIP_TEST_ROOT=/tmp/slip-helper` set**, its `transform` step included,
on the workspace mount.
