# WP-102 — slip_script: an edit's tiers are a set; a copy of an empty range

- Status: in-progress
- Milestone: M3
- Track: B
- Needs: WP-088
- Size: S
- Parallel with: WP-080, WP-083, WP-084, WP-085, WP-086

## Scope

Two differences between the run output as `docs/wp/WP-081.md` and
`docs/wp/WP-088.md` landed it and what `spec/api.md` §7.6 and
`spec/edits.md` §4.2, §4.7 and §4.8 ask of it since the M2 design
merged. Both are in `crates/slip_script`; nothing else changes.

1. **`tiers`.** `output::Edit` has `tier: u8`, and two requests that are
   one edit keep the higher. §7.6 makes it `tiers`, a non-empty set of
   0 and 1, joined by union: one range can be reached at both tiers in
   one unit (a header included twice, where a name is a macro in one
   inclusion and a function in the other), and reduce needs to know
   both.
2. **A copy of an empty range.** `Host::range_arg` accepts an empty
   range, so `code_copy` can hand over a copy piece whose place is
   empty; the claims of `spec/edits.md` §4.2 require a copy piece's
   place to be non-empty.

Files: `crates/slip_script/src/{output.rs,effects.rs,subject.rs,fake.rs}`,
`crates/slip_script/tests/{effects.rs,wire.rs}`, `spec/api.md` §7.1 (one
sentence) and §5.4 if decision 2 needs it, `spec/landed/api/WP-102.md`,
and the sentence of landed decision 13 in `spec/landed/api/WP-081.md`
("keeps the higher tier") with a pointer to this package.

## What is decided

1. `output::Edit::tiers` is a type of its own (a set of the two tiers:
   a private byte with bit 0 for tier 0 and bit 1 for tier 1, never
   zero, with `contains`, `union` and an iterator in ascending order),
   not a bare `u8`. `RunOutput::render` writes `tiers 0`, `tiers 1` or
   `tiers 0,1`.
2. `Subject::tier(r)` becomes `Subject::tiers(r)`, returning `None` as
   today (not exactly a range a query returns: `replace` refuses with
   `invalid_handle`) or the set of tiers at which the unit reaches `r`.
   An empty set is a host failure, as a number above 1 is today. The
   fake subject answers the set (give it the means to say "both" for a
   range). The Kiln-backed subject is `docs/wp/WP-085.md`'s: add the
   changed signature to its decision 7 and nothing more.
3. Joining: requests that are one edit join `tiers` by union and notes
   by union (as today); `tiers` is no part of an edit's identity or of
   the order of edits.
4. **`code_copy` of an empty range is the empty code**: no piece, the
   value `code()` gives. A copy is the bytes of a range, and the bytes
   of an empty range are none; a transform that copies what a query
   gave it must not need a special case. It counts as one operation and
   holds nothing. State it in `spec/api.md` §7.1 in one sentence. No
   other operation changes: `replace` of an empty range stays refused
   (§7.3), `report` at an empty range stays as it is.

## Interface

`output::Tiers`; `Subject::tiers`. `Edit.tier` is gone.

## Tests

- `tests/effects.rs`: two requests with one file, range and pieces at
  tiers 0 and 1 (the fake answering each in turn, or both at once) are
  one edit with `tiers 0,1`, in either order; an edit whose requests
  were all at tier 1 has `tiers 1`; an empty set from the subject is a
  host failure.
- `tests/effects.rs`: `code_copy` of an empty range gives a code equal
  to `code()` (`cat` with it adds no piece; `replace` with it is a
  deletion, §7.3 rule 1); the output of a run that copies an empty
  range holds no copy piece with `lo == hi`. A property test over
  random requests: no copy piece of any output is empty.
- `tests/wire.rs`: the test that reads "keeps the higher tier" now
  reads the union.
- Mutations, each caught: union replaced by `max`; `tiers` made part of
  the edit's identity; the empty copy handed over as a piece.
