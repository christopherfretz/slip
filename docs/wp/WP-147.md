# WP-147 — one spelling per file: a case-insensitive volume from the front end's inputs on

- Status: review
- Milestone: M2
- Track: D
- Needs: WP-066, WP-075
- Size: M
- Parallel with: the digest's area packages, WP-074

## Scope

Slip names a file by the bytes of its real path, and decides ownership
(`slip_model::transform::Ownership::is_owned`), equality of two files
(reduce's first pass), and the overlay's entries by comparing those
bytes. On a volume that folds case and keeps the spelling it was given
(the default on macOS; a bind mount of one under Linux, which is what
this project's own workspace is), `std::fs::canonicalize` returns the
case it was **asked** with, so one file has as many real paths as the
sources and the command line have spellings of it:

```cpp
// request: owns <root>/src; readonly <root>/src/vendor
#include "Vendor/x.h"      // opens <root>/src/vendor/x.h
```

The file's real path is `<root>/src/Vendor/x.h`, no `readonly` entry
is a prefix of it, and it is owned. The review of WP-075 wrote through
this (`--write` rewrote a read-only file, status 0). WP-075's fix round
closed the last line: `slip apply` refuses a path whose components are
not spelled as their directory entries are (`not_canonical`). That
makes the result safe and late: a run over 10^5 observers ends in a
refusal at apply, and everything before apply still holds the wrong
answer (a digest walk that calls a dependency's file owned maps its
entities by rule; reduce takes two spellings of one header for two
files and merges nothing; an overlay holds one file twice). The review
of WP-066 (F8) asked the same of the overlay's consumers.

The rule: **a file has one name in a run, the spelling its directory
entries have, from the first place a path enters.** Everything
downstream compares bytes, as now.

1. **Design; propose and stop for the supervisor before building.**
   - Inventory: every place a path becomes a real path or is compared
     as one (`crates/slip_cdb/src/{normalise.rs,plan.rs}`,
     `crates/slip_kiln/src/{parse.rs,tree.rs,session.rs}` and what Kiln
     itself hands back for an included file, `crates/slip_cli/src/{image.rs,commands.rs,negatives.rs,verify_job.rs,worker.rs}`,
     `crates/slip_apply/src/fs.rs`, the request's ownership entries,
     the overlay's entries, `--only`/`--match` filters), and for each
     whether a second spelling can reach it, with a test that shows it
     on this volume.
   - What Kiln does with `#include "Foo.h"` for a file `foo.h`: one
     file or two (a `#pragma once` header entered twice is a wrong
     parse, not only a wrong name), and which spelling it reports.
     Clang has `-Wnonportable-include-path` for it. If Kiln has two
     files there, that is a request to Kiln with the Slip need stated
     (one file per run; the spelling on disk), written as
     `docs/requests/KR7-…md`; say what Slip does until it lands.
   - The choice: **normalise** (one function gives the on-disk
     spelling, component by component from `read_dir`, cached per
     directory; every entry point calls it; WP-075's check in
     `slip_apply` becomes a call to the same function, moved to the
     crate both can use) or **refuse** (a path whose spelling is not
     the disk's is an error at the entry point, with both spellings in
     the message), or normalise at the command line and the compile
     database and refuse inside sources. Cost at 10^5 observers and
     10^4 directories on a case-sensitive volume, where the answer is
     always "the same": the check must cost one `read_dir` per
     directory per process, or nothing where the volume is found to be
     case-sensitive (say how that is found, per mount, and why it is
     safe: a tree can span mounts). Unicode normalisation folding
     (macOS) is the same defect by another fold: say whether the
     byte comparison against `read_dir` covers it (it should: the
     entry's bytes are the name).
   - **A directory that cannot be listed** (search permission without
     read permission: a shared `/home`). WP-075's check lists every
     directory from `/` down and fails the write with status 3 there,
     on any volume. A component needs no listing where the volume is
     seen not to fold it: the same name in another case (and, where
     the name is not ASCII, in the other normalisation forms) reaches
     nothing or another file (`lstat`, device and inode). Where it
     reaches the same file the listing is needed and its failure is
     the error. Say whether this is sound against hard links and
     against a volume that answers lookups inconsistently (WP-075's
     handback met one: this workspace's own mount), and build it into
     the one function.
   - Symbolic links and hard links are not this package: a symbolic
     link is resolved by `canonicalize` already; two hard links are
     two names by design (say so in `spec/edits.md` §2.1).
2. **Built after the ruling.** `spec/edits.md` §2.1's open question
   ("Case-insensitive volumes against `readonly` entries") becomes
   text; `spec/cdb.md` and `spec/model.md` gain the sentence where a
   path enters. Tests skip with a stated reason on a volume of the
   other kind, and one test says which kind the volume is, as WP-075's
   do.

## Tests

Per entry point of the inventory, the file reached by a second
spelling (a directory component, the file's own name, the main file
in the compile database, an ownership entry, an overlay entry, an
`#include`): one name downstream, or the refusal. End to end: the
review's case (`readonly` entry, include through another case) is
read-only in the digest walk (no rule maps its entities), in reduce
and in apply. Mutations: the function returning its argument; the
cache keyed by the spelling asked instead of the directory's identity;
the check skipped for the last component.

## Rules

`docs/AGENTS.md`. The gate is the full `cargo xtask ci`. Second review
(ownership is trusted base). The reviewer's question: a file that the
request makes read-only, written or mapped by rule under any spelling.

## Done when

The gate passes with `main` merged in; no test of the inventory
reaches a file under two names; the cost on `llvm` `lib/Support`
(process time with and without the check) is in the landed file.

## Out of scope

Windows paths (drive letters, `\\?\`, 8.3 names); a volume that
changes its case rule during a run.
