## Scope

A new crate, `crates/slip_refactor`: the transforms Slip implements in
Rust (Level A of `docs/design/01-transform-api.md` §6). Its first one is
`spec/edits.md` §9, and this package is the part of §9 that Demo 2
stands on: entities at namespace scope and members of classes that are
not templates, outside dependent contexts.

The rename reads the subject through four interfaces and nothing else of
the front end's tables (`spec/edits.md` §9.7): `slip_digest::query::Keys`
(`docs/wp/WP-087.md`), `slip_kiln::written` (`docs/wp/WP-067.md`),
`slip_kiln::ranges` (`docs/wp/WP-084.md`, which WP-068 needs) and
`slip_kiln::sites` (`docs/wp/WP-068.md`). They are the interfaces the
host of a programmable transform reads the subject through, so the
native rename and a rename written in C++ see the same references, the
same ranges and the same keys.

In:

- §9.1: the target, the seeds, `unsupported` for another kind.
- §9.2: a subject's `rule` from `Keys::rename_rule`, and its `id` from
  `Keys::key_id`.
- §9.3: every row except "An overriding function" and "A dependent
  name". Declarations and definitions, explicit specialisations and
  explicit instantiations (`slip_kiln::written::decl_names`): literal
  pieces. Id-expressions, member accesses, qualified names (the last
  component only), template names with arguments, non-dependent names in
  patterns (`written_refs`): spelled pieces, with the key of the
  referent's origin (`written::origin`, then `Keys::key_id`), and the
  rule on tokens whose derivations have different origins. Macro tiers
  through `slip_kiln::sites`.
- `keep` (§4.2) for every name token spelled like the old name that
  this observer resolved to something else, declarations included.
- §4.3: votes.
- §9.5: `read_only`, `name_taken`, `unsupported`, `unreachable`, and
  `refuse` claims.
- `spec/edits.md` §6.3: the `edits.*` counters of a map shard.
- `spec/harness.md` §3: the `kiln-boundary` lint lets `slip_refactor`
  link `slip_kiln` and name its module `kiln` (`xtask/src/lint/crates.rs`,
  the two lists and their messages, and the lint's tests).

Conservative, until the next two packages replace it (each in a file of
its own, so the three never share one):

| File | This package writes | Replaced by |
|---|---|---|
| `src/rename/families.rs` | a seed that is a virtual member function is flagged `unsupported` | `docs/wp/WP-072.md` |
| `src/rename/followers.rs` | a using-declaration that names a subject flags it `unreachable`; a subject that names an unnamed class or enumeration (`digest.md` §3.3) is `unsupported` | `docs/wp/WP-072.md` |
| `src/rename/dependent.rs` | a dependent name spelled like the old name is claimed `unresolved` | `docs/wp/WP-073.md` |
| `src/rename/spec_members.rs` | a seed that is a member of a class template is `unsupported` | `docs/wp/WP-073.md` |

Every one of these is safe to be wrong about: verification, not the
flag, is what stands between a wrong edit and the tree. They exist so
that the common failure is a refusal that names its cause instead of a
mismatch.

Files: the crate (`Cargo.toml`; `src/lib.rs`; `src/rename/{mod.rs,
target.rs, subjects.rs, decls.rs, refs.rs, claims.rs}` and the four
above; `tests/rename.rs` and `tests/rename/`), the root `Cargo.toml`
(the workspace dependency line; the crate links Kiln and is not a
default member), `crates/slip_cli/Cargo.toml` (the one line that makes
`slip_cli` depend on it, so that the worker's package need not touch a
manifest), the lint as said. The crate's own manifest lists
`slip_reduce` as a dev-dependency for `docs/wp/WP-072.md`'s tests.

## Interface

`spec/edits.md` §9.7:

```rust
pub fn run(transform: &Transform, unit: &slip_kiln::Unit<'_>, keys: &mut slip_digest::query::Keys<'_>,
           files: &dyn Fn(kiln::source::FileId) -> Option<FileRef>) -> Result<Edits, String>;
```

`Err` is a failure of Slip (a request of a kind this crate does not
have, a unit parsed without `ParseOptions::written`); everything about
the subject is in the `Edits`. The result has passed `Edits::normalise`
and satisfies §4.7; its `failure`, `groups`, `reports` and `renamed` are
empty (§9.6).

Fixed inside the crate, for the two packages that follow:

```rust

    pub unit: &'a slip_kiln::Unit<'r>,
    pub keys: &'a mut slip_digest::query::Keys<'k>,
    pub sites: slip_kiln::sites::Sites<'a, 'r>,

    pub claims: Claims,

}
pub(crate) struct Subjects { /* by KeyId; the DeclIds of each */ }
impl Subjects {
    /// Adds the entity of `decl` (any redeclaration) or joins it. Its id
    /// is `Keys::key_id` and its rule `Keys::rename_rule(entity, new)`.
    /// `None` if it has no key: the caller claims nothing for it.
    pub fn add(&mut self, keys: &mut Keys<'_>, decl: DeclId, role: Role, new: &[u8], of: &[KeyId]) -> Option<KeyId>;
    pub fn of_decl(&self, keys: &Keys<'_>, decl: DeclId) -> Option<KeyId>;   // is this entity a subject of the observer
    pub fn flag(&mut self, id: KeyId, flags: u64);
    pub fn link(&mut self, a: KeyId, b: KeyId);
}
/// How a replacement is written (§9.3 "The pieces").

pub(crate) struct Claims { /* derivations, before §4.3's join */ }
impl Claims {
    pub fn replace(&mut self, sites: &Sites<'_, '_>, name: Span, subjects: &[KeyId], written: Written);
    pub fn keep(&mut self, sites: &Sites<'_, '_>, name: Span);
    pub fn unresolved(&mut self, sites: &Sites<'_, '_>, name: Span);
    pub fn refuse(&mut self, sites: &Sites<'_, '_>, name: Span, subjects: &[KeyId], reason: Reason);
```

`Claims::replace` turns into a `refuse` by itself when `Sites` cannot
locate the token (the reason is `Sites`'s); a `keep` or `unresolved` at
a token that cannot be located is dropped (nothing would be edited
there). When the derivations of one token are joined (§4.3): all
`Spelled` with one key gives `spelled(K, new)`; anything else, all of
them subjects, gives `literal(new)`.

Rules this package fixes:

- **Matching the target.** §9.1 is stated over keys (the name, the
  parent chain, the kind) and is read literally, with `Keys::key`
  (`docs/wp/WP-087.md`). A declaration is looked at only if the AST
  names it like the old name (see "Cost"); then `Keys::key` of its
  entity must have the name `identifier(old)` and an allowed kind, and
  the chain is walked outwards: a key's `parent` is a key id, so at each
  step the enclosing entity is taken from the AST (the semantic parent,
  a linkage specification skipped), its key id must be the one in
  `parent`, and its key must be named like the next component and be a
  namespace, a class or a class template; after the outermost component
  the parent must be `root`. An entity whose key has parent `c_linkage`
  or `builtin`, or a parent the AST's enclosing entity does not have,
  does not match. The one use of the AST's scopes by themselves is the
  last sentence of §9.1: an entity whose key has parent `c_linkage`,
  named like the old name, whose enclosing scopes (their keys walked as
  above from the innermost) are the target's, is a seed with
  `unsupported`. An inline or unnamed namespace is a component
  like any other, so it matches only a request that names it. A
  candidate for which `Keys::key` refuses is not a seed. Otherwise
  there is no match over the AST alone: the AST only proposes
  candidates.
- **Cost.** One pass over `decl_names` and one over `written_refs`; no
  key is computed and no token located unless the entry's referent (or
  the declaration) is named like the old name. The pass adds the
  counter `edits.refs` (entries looked at).
- **Which entity a reference denotes.** The entry's `referent`, taken to
  its origin by `slip_kiln::written::origin` and to the digest's entity
  by `Keys::entity`. `via_using` is `followers`' business: the core
  treats the name as denoting the referent.
- **`name_taken`** as §9.5's row says, decided from the declarations
  this observer sees.
- **`read_only`**: any redeclaration's name token in a file that is not
  owned. Such a declaration is not claimed.
- **`unreachable`**: a subject named in an attribute argument or a
  designator, as far as the AST shows one (the list of
  `docs/wp/WP-067.md`'s handback says what neither table records).
- **A referent without a key** (`NoKey`): it is not a subject, and a
  token that denotes it is a `keep`. A declaration that matches the
  target and has no key is not a seed (§9.1 matches keys); if nothing
  else matches, the observer has no subject and reduce's `no_subject`
  says so.
- **Determinism**: `Edits` is a function of the unit. No map is
  iterated in hash order on the way to it.

rewritten under `SLIP_BLESS=1` and reviewed by hand. One directory per:

- row of §9.3 in scope with its piece, each in a source file and in a
  header included twice (votes); the same with the name qualified, with
  `::` in front, through a namespace alias and through a
  using-directive;
- an overload set (all renamed; each call's spelled piece carries the
  key of the overload it selected); a call that selects an overload of
  another scope spelled the same (`keep`); a local variable, a
  parameter, a field and a label spelled the same (`keep` or nothing,
  as §4.2 says, each stated);
- a token whose two derivations have different origins, both subjects
  (a macro argument substituted into two calls that select two
  overloads): a literal;
- each flag of §9.5, with the smallest source that sets it;
- the target's match (§9.1): a namespace opened twice; a member of a
  class in a namespace; a function of the same name in a sibling
  namespace and in the global namespace (not seeds: `keep`); an inline
  namespace named by the request and not named; an unnamed namespace
  (no seed); a function with C language linkage declared in the
  target's namespace (a seed with `unsupported`), and one of that name
  declared in another namespace (not a seed);
- each tier of §2.2 for a reference and for a declaration (a function
  declared through a macro argument; through a macro body);
- a function template with an explicit specialisation, an explicit
  instantiation, a use with explicit arguments (the spelled piece
  carries the template's key);
- a variable with a block-scope `extern` redeclaration; a static data
  member defined out of line; a member function called through `.`,
  `->` and a qualified id;
- the four conservative rows above;
- a source with errors (the unit is `diagnosed`; `run` is not called
  for it, and the runner checks the worker's rule by a test that does
  call it and expects no panic).

One test ties the subjects to the walk: for every directory, each

## Added after the review of WP-103 (2026-11-23)

A function that a class template befriends with a declaration that is
not a definition has two entities under rules: the function, and the
friend declaration inside the template, which is its own entity in each
instantiation and is **not** followed to the function's rule
(`spec/landed/digest/WP-103.md`, fix round 3; `docs/wp/WP-103.md`
"Supervisor's handback"). The rename of such a function must declare
the second rule as well, the one for the friend declaration's key, or
verification reports a mismatch (never a wrong equal). `followers`
finds these (a friend declaration of the subject in a class template's
pattern) and the core declares their rules; a test with the friend in
one template, in two templates, and with the friend also defined in
the template (which is followed and needs no rule of its own).

## Handback

**Round 1** (branch `wp/071-rename-core`). The crate
`crates/slip_refactor`: `Cargo.toml`, `src/lib.rs` (`run`, the §9.7

`edits.refs`), `src/rename/{mod, target, subjects, claims, decls, refs,

tests) and 61 directories under `tests/rename/`. The root `Cargo.toml`,
the one line in `crates/slip_cli/Cargo.toml`, and the kiln-boundary lint
(`xtask/src/lint/crates.rs`, `xtask/tests/lint.rs`, `xtask/tests/ci.rs`).
Decisions where the spec was silent, each §9.3 and §9.5 row with its
test, the mutation table (34 mutants: 30 caught, 4 survived with the
reason), For Kiln, and notes for WP-072, WP-073 and WP-074:
`spec/landed/edits/WP-071.md`.

**What the rename does with each kind of new name.** An identifier
(`[A-Za-z_][A-Za-z0-9_]*`, not a keyword, not the old name) is renamed
to; a reserved identifier (`_x`) is accepted as `Transform::validate`
accepts it. A keyword (`delete`) and a UCN (`café`) are rejected by
`validate`, so `run` returns `Err("the request is not valid: …")` and
`Keys::rename_rule` is never asked. Test: `requests_the_rename_does_not_run`.

**Interface drift.** `Ctx` has two more fields, `named` (the
`decl_names` entries named like the old and the new name) and `settled`
(declarations a hook dealt with). `Subjects` has `entities`, `seeds`
and `finish`; `Claims` has `finish`.

**Surprises.** A specialisation a macro body writes whole is given by
`decl_names` (refused `macro_body`); the absent one is a specialisation
whose *name* is a macro (`template <> void NAME<int>(int) {}`), absent
from Slip's `decl_names`, not from Kiln, and flagged `unreachable`. A
friend in a class template's pattern has a key of its own with another
discriminator, so it is matched by scope, kind and name.

**Fix round** (after the review). In `slip_kiln::written::origin`: a
partial specialisation (class or variable template) has its template as
origin (A1); a friend declaration that does not define the function is
not followed to the pattern's (A4). In the rename: every subject keeps
the rule `Keys::rename_rule` gives, and one whose key follows a pattern
member is `unsupported` (A5; §4.1 now says a rule is a function of key
and request); `name_taken` reads the scopes a name enters, through the
transparent scopes, block-scope `extern`, bases in both directions and a
macro of the new name, and never a template parameter (A3, B1, §9.5's
four additions); A2 (a dependent friend specialisation) is a named hole
in §9.5 with three `# pending` directories, and B2 (`n::v<T>`) a known
over-refusal with one, both under For Kiln. The post-image test skips a
run with a flagged subject (a11). Tests for the reviewer's R01, R02,
R06, R07, R08, R09, R11, R14; R03–R05 argued in the landed file. 90
directories (4 pending), two unit tests. Mutations redone: 60 (round
1's 34, R01–R14, 14 new): 51 caught, 9 survived, each argued in the
landed file (6 equivalent, 2 unreachable at this pin, 1 redundant
clause, removed).

**For the digest.** Proposed as the real fix of A5: a rule on an
instantiated member's key is accepted when it maps to the same name as
the followed pattern's rule, so that a function defined as a friend in

**After the re-check.** `run` refuses a unit parsed without the
