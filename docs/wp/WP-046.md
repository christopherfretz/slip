## What is decided

Read `spec/landed/digest-kinds/WP-026.md` ("Default arguments of
instantiated declarations", "Evaluation"), `WP-028.md` (constant
values), `WP-027.md`, and the Handback sections of `docs/wp/WP-026.md`,
`WP-027.md`, `WP-033.md`, `WP-035.md`. The decisions below settle what
they left open; each is shown by a `resolved` pair
(`crates/slip_digest/tests/resolved/`, WP-045's runner): a use on side B
makes the resolved or derived unit appear and changes no unit both sides
have. If a pair shows a rule is not independent of use, stop on it and
report.

1. **`exception_spec` (property 1, §11.2).** `demand::deferrable`
   returns `None` today for two cases; both get a rule that reads only
   facts resolution does not change:
   - it reads the entity's representative declaration
     (`Walk::representative`), not Kiln's first (WP-032 rule 1);
   - a function explicitly defaulted on its first declaration is of the
     class when that declaration was written without an exception
     specification. Find what in the AST says so after resolution
     (Kiln re-points the declaration's type). If nothing does, every
     function explicitly defaulted on its first declaration is of the
     class, as every destructor is (§11.2 rule 4), and its written
     specification, if it has one, is in `exception_spec`;
   - an implicit instantiation is of the class when its pattern's
     specification is one Kiln defers (rule 3: a value-dependent
     `noexcept` operand, a dynamic specification naming a dependent
     type, a pattern itself of the class). The predicate reads the
     pattern. If the pattern's own stored form cannot say (it was
     resolved or re-pointed), every implicit instantiation is of the
     class.

   Whichever way each falls, state the rule in §11.2 and show by a pair
   that a use that resolves the specification changes no unit both
   sides have. The members of an explicitly instantiated class follow
   the effective kind of `docs/wp/WP-045.md` decision 1 (read it; use
   its function when it exists, and until then write the rule so that
   switching is one call).
   A type digest that meets `Deferred(d)` is as §11.2 says and is not
   changed here.
2. **`value` (property 2, §11.3).** The unit exists when the state is
   `Value` or `NotConstant`. Its stream is `value?` and then one
   `value?` per temporary the variable extends, in `mangling_index`
   order. After this package a variable's own unit is not indeterminate
   for `eval` in any state but `Evaluating`. The own unit never says
   whether the variable was evaluated.
   One more decision: **a variable whose initialiser is in WP-045's
   `definition`** (an instantiated static data member, a variable
   template's specialisation) has its `value` unit under the variable
   as any other; nothing is under `definition`.
3. **`dtor_delete` (5), `inherited_constructor` (6)**: as the table of
   §11.1 writes them, present when Kiln holds the fact.
4. **`default_argument` (§11.4).** A derived unit, kind
   `default_argument`, parent the function or field, name `parameter(i)`
   (0 for a field), for:
   - each parameter of an instantiated function declaration whose
     default argument Kiln has instantiated (the parameter holds the
     expression and `DEFAULT_ARG_PENDING` is clear, or whatever Kiln's
     source shows is the mark: cite it). "Instantiated declaration" is
     what `spec/landed/digest-kinds/WP-026.md` defines, restated with
     WP-045's effective kind;
   - each field instantiated from a pattern whose default member
     initialiser Kiln has instantiated, under every form of
     instantiation (§11.4 third paragraph);
   - an inheriting constructor: `docs/wp/WP-035.md` Handback and
     `spec/landed/digest-kinds/WP-035.md` say what Kiln builds for its
     default arguments (they are the base constructor's). Decide from
     Kiln's source whether a unit is needed; if the base constructor's
     units already hold them, say so in §11.4 and write none.

   Its stream is the expression, walked as an initialiser is, numbered
   on its own (the parameters before it are referred to as the function's
   own stream numbers them: say how, and show by a test that a default
   argument naming an earlier parameter in an unevaluated operand,
   `sizeof(p)`, digests equal across two uses and differs when the
   earlier parameter's type does).
   The unit is queued when its function or field is written: it does
   not wait for a `Ref`.
5. **`default_immediates` (property 7).** Parent: the unit that holds
   the default argument or initialiser (the function or field for one
   written in source, the `default_argument` unit for an instantiated
   one). Discriminator: the parameter's index, absent for a field.
   Stream: the values of the argument's immediate invocations that have
   a `default_imm` entry, in walk order. Present when at least one has.
6. **`Pending(Area::Demand)` goes** from every site of this package's
   scope, and with WP-045's from the crate: when both are merged, the
   second to merge removes `Area::Demand` from `Area` if nothing writes
   it (the supervisor says which is second).

The spec changes with the code (§11.1 to §11.5, digest §2.3's table
where a row changes); decisions and Kiln's evidence go to
`spec/landed/digest-kinds/WP-046.md`. Kiln's account in digest §2.3 is
of an older revision: where the source at the pin disagrees with a row
(a state that is no longer demand-driven, or one that is and is not
listed), follow the source, record it, and list it in the handback as a
question for Kiln.

  content differs: only that unit differs.

  loses its `# pending` mark. Unit tests that assert
  `Pending(Area::Demand)` at this package's sites assert the new

  the `default_argument` unit queued only on a `Ref`: each caught by a
  named test.
