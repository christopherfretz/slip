# WP-136 — a specialisation whose substitution failed is no entity: the 13,405 `error` units of Demo 1

- Status: todo
- Milestone: M1
- Track: C
- Needs: WP-131
- Size: S
- Parallel with: WP-106, WP-122, WP-125, WP-126, WP-130 (one digest branch merges at a time; this one first: it is four fifths of the corpus's indeterminate units; launched when the pin holds Kiln's WP-3281)

## Scope

Demo 1's run of record (`spec/landed/harness/WP-059.md`; `main`
`10e8259a`, `llvm/lib/Support`, 151 observers) has 16,736 indeterminate
units. 13,405 of them, in 133 observers, are derived units of node
`specialisation` with the cause `error`: 2,491 distinct
specialisations, 12,306 of the units in libstdc++ and 1,103 in LLVM's
headers. Two thirds are two helpers
(`std::__detail::__and_fn`, `__or_fn`, `type_traits` lines 175 and
182); the rest are `std::get`, `std::__get_helper`,
`basic_string::insert`, `llvm::StringRef::operator=`,
`raw_ostream.h:426`, `function_ref`'s constructor and their kin.

None is an error. Each is a candidate of an overload resolution whose
substitution failed, as its author meant it to:

```cpp
template <class T> auto g(T t) -> decltype(t.size());
int g(...);
int u() { return g(1); }
```

Kiln keeps the failed `g<int>` as a declaration with
`DeclFlags::INVALID`; `Walk`'s declaration header (`decl.rs`: "flags")
makes every unit with an invalid declaration indeterminate
(`Cause::Error`, `spec/digest.md` §10 first item); `slip units` shows
`specialisation derived i g<int>`.

1. **The rule** (the supervisor's ruling; write it into
   `spec/digest.md` §2.1 and §8): a specialisation whose substitution
   failed is not an entity of the program ([temp.deduct]/8: deduction
   fails; no specialisation is formed). It is **no unit**, nothing lists
   it, and nothing of its partly built declaration is read. What a
   failed candidate decides is recorded where it is decided and is
   already digested there: the callee an overload resolution chose, the
   declaration the address of an overload set resolved to, the partial
   specialisation an instantiation was made from, the value of a
   requires-expression or a concept-id, the guide class template
   argument deduction chose. A candidate that fails before and after
   changes nothing; one that begins to succeed and wins changes the
   use's unit; one that begins to succeed and loses changes no meaning.
   So leaving it out loses no difference, and it removes a dependence of
   a translation unit's units on which candidates were tried.
2. **Telling it from an error, exactly: Kiln's mark** (its WP-3281;
   the design was reviewed by the supervisor 2026-11-23; this package
   is built when the pin holds it). `ast.decls.subst_failed(d)` is
   `Some(kind)` exactly when Kiln set `INVALID` on `d` inside a trap (a
   SFINAE context, or a diagnostic capture then discarded) that printed
   no error; in a translation unit with no error diagnostic every
   invalid declaration carries it. What the digest does per kind:

   | Kind | Is | The digest |
   |---|---|---|
   | 1 function signature (deduction, explicit arguments, a guide) | no entity | no unit (item 1) |
   | 2 explicit-specifier | no entity | no unit |
   | 3 variable, ambiguous partial specialisation | no entity | no unit |
   | 4 class, ambiguous partial specialisation | a type that can still be named (`X<int>*`), never complete | a unit, written exactly as a specialisation that was never instantiated: an attempt that failed and no attempt are one state (what the attempt decided is at the use) |
   | 5 local of a failed signature (a parameter, a statement-expression variable, a closure) | part of a declaration that is no entity | never reached; item 3's cause if it is |
   | 6 other, trapped | unknown | indeterminate, `Unaccounted("decl/trapped")`; the corpus count goes to Kiln |
   | any other value, or invalid with no mark | an error | as today (`Cause::Error`) |

   Assert the invariant where the observer's diagnostics are known: an
   observer with no error diagnostic and an invalid declaration without
   the mark is a defect of one of the two tools (a counter, and a line
   in the run's report; not a panic). Open at Kiln when this was
   written: whether "no pattern" for a variable is split from kind 3,
   and whether a closure of a failed signature keeps its owner or
   carries kind 5: read Kiln's landed note at the pin.
3. **A reference to one stays indeterminate.** If any stream reaches a
   failed specialisation as a `Ref` (none should: it was not chosen),
   the unit that holds the reference is indeterminate with a cause of
   its own (`Unaccounted("ref/failed-substitution")`), and the corpus
   count of that cause must be zero: the supervisor runs it.
4. **Its kin**: the same question for a failed specialisation of a
   member function template of an instantiation, of a constructor
   template (`function_ref`'s), of a conversion function template, of a
   deduction guide; for a class template partial specialisation that
   did not match (is anything kept?); for a variable template; for an
   alias template whose substitution fails inside another's signature
   (`__enable_if_t<false>`). For each: whether Kiln keeps a declaration,
   what the digest does with it today, and a pair.
5. **The using units are what must hold**: pairs under `tests/differ`
   where the only change makes a failing candidate succeed and win (the
   use's unit differs), and under `tests/equal` where it makes one
   succeed and lose (equal: the rule's claim), and where the failing
   candidate's template is itself relocated under a declared rule
   (equal). A pitfalls row "a candidate that substitution removes"
   (`crates/slip_verify/tests/pitfalls/`, the next free `N` number):
   `good` a relocation beside `enable_if` overloads and a `decltype`
   return; `bad` an edit that makes the other overload win.
