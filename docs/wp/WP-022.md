# WP-022 — slip_model: keys, names, rules and the `DECL` container

- Status: done
- Milestone: M1
- Track: A
- Needs: WP-006
- Size: M
- Parallel with: WP-021, WP-023

## Scope

The data of `spec/digest.md` §3 (keys, parents, names, discriminators,
`KeyId`, mapped keys under a rule table) and of `spec/verify.md` §2
(`Declared`, rules, exemptions, `rules_id`, the container kind `DECL`), in
`slip_model`: plain types, their byte encodings, their JSON rendering and
the functions that are pure arithmetic on them. No Kiln, no file system.
`slip_digest` builds keys with these types while it walks; `slip_verify`
and the verify job read `Declared`; a second implementation has to get
the same `KeyId` for the same entity, so every byte is specified.

New modules `slip_model::keys` and `slip_model::declared` (and the
container kind beside the existing ones). The numbers of `KeyKind` and
`Name` are the tables of `spec/digest-kinds.md` §3.1 and §3.2.

## Interface

```rust
// slip_model::keys
/// digest-kinds §3.1. `explicit_instantiation` (24) is in the table and
/// not used: it has a variant so that reading it is not an error.
#[repr(u8)] pub enum KeyKind { Namespace = 1, Class = 2, /* … */ UnresolvedIfExists = 33 }

/// digest §3: who an entity is a member of.
pub enum Parent { Root, CLinkage, Builtin, Unit(Digest) }

/// digest §3.1, digest-kinds §3.2.
pub enum Name {
    Identifier(Vec<u8>), Operator(u64), Constructor, Destructor, Conversion(Digest),
    LiteralOperator(Vec<u8>), DeductionGuide, Anonymous, Content, Local(u64),
    UnnamedBy(Box<Name>), UnnamedOrdinal(u64), Property(u64), Order, Parameter(u64),
}

pub struct Key { pub kind: KeyKind, pub parent: Parent, pub name: Name, pub disc: Option<Digest> }
impl Key {
    /// `H("slip.key.v1", encoding)`.
    pub fn id(&self) -> Digest;
}
pub const KEY_TAG: &str = "slip.key.v1";
pub const DISC_TAG: &str = "slip.disc.v1";

/// digest §3.4.
pub struct Rule {
    pub parent: Parent, pub kind: KeyKind, pub name: Name, pub disc: Option<Digest>,
    pub to_parent: Parent, pub to_name: Name,
}

/// A rule table ready to apply. Built from rules in any order.
pub struct RuleTable { /* … */ }
impl RuleTable {
    pub fn empty() -> RuleTable;
    /// Err: two rules with the same `(parent, kind, name, disc)`.
    pub fn new(rules: Vec<Rule>) -> Result<RuleTable, RuleError>;
    pub fn rules(&self) -> &[Rule];          // sorted as verify §2 says
    pub fn is_empty(&self) -> bool;
    /// digest §3.4: `key`, whose parent and discriminator are already
    /// mapped, with parent and name replaced if a rule matches; else
    /// `key` unchanged. One lookup, logarithmic or better.
    pub fn map(&self, key: Key) -> Key;
    /// `H("slip.rules.v1", list<Rule>)` over the sorted rules.
    pub fn id(&self) -> Digest;
}

// slip_model::declared
pub struct Declared { /* rules: RuleTable, changed, created, removed: Vec<Digest> */ }
impl Declared {
    pub fn none() -> Declared;
    /// Sorts nothing: Err names the list and the index that is not
    /// strictly ascending, or the rules' error.
    pub fn new(rules: Vec<Rule>, changed: Vec<Digest>, created: Vec<Digest>, removed: Vec<Digest>)
        -> Result<Declared, DeclaredError>;
    pub fn rules(&self) -> &RuleTable;       // and changed(), created(), removed()
}
```

and, as the existing formats give them (`spec/model.md` §5.5, §10): the
binary writer and reader of a `DECL` container (kind `DECL`, version 1,
one required section `declared`, id 1) and its JSON writer and reader,
with errors and offsets in the style of §2.1, §2.2 and §5.4.

**Encodings** (the primitives of `spec/model.md` §2; this is the reading
of digest §3 that this package fixes, to be recorded in the landed file):

- `KeyKind`: `uv`, its number. `Parent`: `uv` 0, 1, 2, or 3 followed by
  the `digest`. `Name`: `uv`, its number in digest-kinds §3.2, then the
  "Then" column: `bytes`, `uv`, `digest` or a nested `Name`.
- `Key`: `kind`, `parent`, `name`, `disc` (`opt<digest>`).
- `Rule`: `parent`, `kind`, `name`, `disc`, `to_parent`, `to_name`.
  Rules are ordered by the bytes of the encoding of their first four
  fields.
- `Declared`: `list<Rule>`, then three `list<digest>`.

A reader rejects: an unknown `KeyKind` or `Name` number, a `Parent` tag
above 3, an `UnnamedBy` nested more than 8 deep, an `Operator` number of
0, lists that are not strictly ascending, two rules with one match,
trailing bytes. `Operator`'s number is otherwise not interpreted here
(its table, digest-kinds §10.2, belongs to the walk).

**`map` is one step.** Mapping an entity bottom-up (its parent first,
everything in its discriminator first) is the walk's job; `map` does the
last step. A rule is applied at most once per entity and rules do not
chain: `map(map(k))` may differ from `map(k)`, and the walk never asks
for it.

## Tests

`crates/slip_model/tests/keys.rs` (digest §3, digest-kinds §3):

- every `KeyKind` and every `Name` form round-trips; golden bytes and
  golden `KeyId`s for a handful of keys written out by hand in the test
  (a namespace in the root; a class in it; a function with a
  discriminator; an unnamed class named by a typedef; a conversion
  function; a content-keyed unit), so that a change of encoding fails
  with the bytes shown;
- keys that differ in exactly one of kind, parent, name, discriminator
  have different ids; `Identifier("operator+")` and `Operator(n)` differ;
- every rejected encoding above, with the error's offset;
- `RuleTable`: no rule; a rule that matches (parent and name replaced,
  kind and discriminator kept); a rule that does not match because of
  kind, parent, name, or discriminator, one test each; two rules that
  swap two names (each key mapped once); two rules with one match
  refused; `id` independent of the order the rules were given in and
  different for different tables; `rules()` sorted.

`crates/slip_model/tests/declared.rs` (verify §2):

- the container round trip, binary and JSON, with a golden of each under
  `crates/slip_model/tests/golden/`;
- rejected: each list unsorted, a duplicate in each, two rules with one
  match, an unknown section, the section missing, a wrong kind, a wrong
  version;
- `Declared::none()` is four empty lists and its `rules().id()` is the id
  of the empty table.

`crates/slip_verify`: `Exemptions` can be built from a `Declared`
(`Exemptions::from_declared(&Declared)`), one test. No other change
there.
