# WP-038 — pair tests under flags and targets, and the rows only they reach

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-021, WP-024
- Size: M
- Parallel with: WP-032..037, WP-039

## Scope

The pair tests (`crates/slip_digest/tests/{differ,equal,demand,indeterminate}`)
parse every source as `kiln -std=<std> -fsyntax-only` for
`x86_64-unknown-linux-gnu` (`slip_kiln::snippet`). Rows of
`spec/digest-kinds.md` that Kiln builds only under a flag or for
another target have no test for that reason alone; the handbacks of
WP-026..033 list them. This package gives a test its own command line
and then writes those tests.

1. **`slip_kiln::snippet`** (`crates/slip_kiln/src/snippet.rs`): a
   snippet parsed under extra driver arguments and a target.
2. **The runner** (`crates/slip_digest/tests/common/mod.rs`): header
   lines of a test's main file select them.
3. **The rows**: every line of `tests/tables/untested.txt` that a flag
   or a target reaches gets its directory. Start from this list and
   check each against Kiln (a row another flag reaches is yours too):
   - AArch64: `BuiltinType` `Sv*` and `MFloat8`, `VectorKind` `Neon`,
     `NeonPoly`, `SveFixedData`, `SveFixedPredicate`, `CallConv`
     `AArch64VectorCall`, `AArch64SveCall`, `Aapcs`, `AapcsVfp`,
     `AttrKind` and `AttrNode` `ARM_NEW`, `ARM_LOCALLY_STREAMING`,
     `TARGET_VERSION`, `TARGET_CLONES.b`;
   - `-fms-extensions` or the Microsoft spellings Kiln accepts:
     `AttrSyntax` `Declspec`, `TagKeyword` `Interface`;
   - reflection (`-freflection`, or C++26 with whatever Kiln's
     `reflection_for` asks): `FieldData` `flags-no-unique-address`
     (`kiln_sema/src/meta/define.rs:614`), the `Reflectee` table,
     `BuiltinType` `MetaInfo`, `DeclKind` `ConstevalBlock`;
   - contracts: `ContractSite`, `ContractKind`, `ColdDeclData`
     `contracts`, `DeclKind` `ContractResultName`;
   - floating-point command lines (`-ffp-contract=`, `-frounding-math`,
     `-ffp-exception-behavior=`, `-ffp-eval-method=`): the rows of
     `FpOptions`, `FpContract`, `FpExcept`, `FpEval`, `FpRound` that a
     pragma cannot reach. `fp.rs` belongs to WP-034 and may still be
     pending: write the tests, mark them `# pending`, `# needs: stmt`.
   - others the handbacks name: `ParamAbi` `Swift*`, `BuiltinType`
     `Float32`…`StdFloat128`, `Half`, `CallConv` `C` and `SysV`,
     `VarStorage` `Register` (C++17 has no `register`: is there a
     mode?), `AttrKind` `NOCF_CHECK`, `CLEANUP`, `BUILTIN_ALIAS`.

Not in scope: a test that imports a module (`Owner/unit`, `UnitInfo`
`imports`, `UnitKind` other than the unit's own). Find out what it
would take (the snippet front end has `ModuleOptions::default()` and no
file system: can a module file be built in memory from one snippet and
handed to the next through Kiln's public interface, at which
`file:line`?) and report it in the handback: half a page, no code.

## Interface

```rust
// slip_kiln::snippet
/// What a test adds to `kiln -std=<std> -fsyntax-only`.
#[derive(Clone, Debug, Default)]
pub struct Extra<'a> {
    /// Driver arguments, each as one would write it (`-fms-extensions`,
    /// `-march=armv9-a+sve2`). Appended after `-std=` and before
    /// `-fsyntax-only`.
    pub args: &'a [&'a str],
    /// A target triple Kiln's driver knows; `None` is
    /// `x86_64-unknown-linux-gnu`.
    pub target: Option<&'a str>,
}
pub fn parse_with<R>(
    snippet: &Snippet<'_>,
    extra: &Extra<'_>,
    f: impl FnOnce(&Parsed<'_>) -> R,
) -> Result<R, String>;
```

`Snippet` and `parse` do not change (fifteen callers in files other
packages are editing); `parse` is `parse_with` with `Extra::default()`.

Rules of `parse_with`, each with a unit test in `snippet.rs`:

- The options still come from Kiln's own parse of the line
  (`Args::parse_as`) through the same public functions `Language`
  uses today. Read each function of `Language` and each field it sets
  by hand (`complex_promoted`, `target_features` / `x86_features`, the
  `x86()` switch, `sema_target`, the preprocessor's feature queries)
  and make it right for the arguments and the target given, or name in
  the module documentation ("Language options": "Where they differ")
  what still differs. A field that cannot be computed without a crate
  `slip_kiln` does not link is documented, not guessed.
- An argument Kiln's driver does not know, one it reports an error
  for, and one that changes what is read or written rather than the
  language (`-o`, `-I`, `-include`, `-D`, `-U`, `-x`, `-c`, `-E`,
  `-M*`, `-fmodule-*`, `-fprebuilt-*`, `--precompile`, `-verify`, a
  second `-std=`, an input file) is `Err` with the argument named,
  before anything is parsed. Decide the list by reading
  `kiln_driver::args`: the rule is that the snippet stays the only
  input and the unit's AST the only output. `-D` is excluded on
  purpose: a test writes `#define`.
- An unknown target is `Err`. Which triples the driver knows is read
  from `DriverTarget::parse`; list them in the documentation.
- Still no predefined macro, no header, no file system, the same
  thread and stack rules, and the same result for the same input on
  any host and thread (the determinism test of WP-021 runs under an
  `Extra` too).

The runner: a main file's leading comment lines gain

```
// args: -fms-extensions -fno-rtti
// target: aarch64-unknown-linux-gnu
```

beside `// std:` and `// errors: yes`, in any order, within the first
lines as today (raise the limit of four if needed; a header line after
the first line that is not one is not read, and a line that looks like
a header but is misspelt, `// arg:`, `//target:`, is an error of the
test, not a comment: say how you tell them apart). `// args:` splits
at spaces; no quoting. In a `t.cpp` test both sides share the lines; in
an `a.cpp`/`b.cpp` test each side has its own, and **a `differ` test
may differ in nothing but its `// args:` line** (that is how a
command-line fact is shown to be in the digest: `-frounding-math`
against none). `SLIP_DIGEST_DUMP` prints the line in effect.

`spec/landed/harness/WP-038.md` records the rules above as decided, and
`spec/harness.md` gains what a reader of a pair test must know (find
where WP-021's snippet is described there, or add the paragraph where
the pair tests are; `spec/digest-kinds.md` §1.5 names the test forms:
add one sentence there pointing at it, nothing else in that file).

## Tests

- `snippet.rs`: the rules above; one construct per flag family that is
  an error without the flag and parses with it (`__declspec`, an SVE
  type, a reflection, a contract); the same source under two targets
  gives different `sizeof(long double)` or `alignof`; determinism.
- The runner: a test of the header parser (each line form, the misspelt
  forms, both-sides and per-side).
- The rows: per row as the common rules of `docs/wp/WP-029.md` say
  (rule 5; rule 6: break one row in five and see its test fail; the
  second rule of `docs/wp/WP-034.md` "Rules" for enumerations, flags
  and optionals). The code of these rows is on `main` already, written
  by other packages without a test: **expect to find defects**. A row
  whose code is wrong is not fixed here: the test is written, marked
  `# pending` with `# needs: <area of the file>`, and the defect is
  reported in the handback with the source, the row and the
  `file:line`. A one-line fix in a file no open package owns
  (`types.rs`, `attrs.rs`, `decl_func.rs`, `decl_class.rs`, `consts.rs`)
  may be made, each listed.
- A row that no flag, target or source reaches stays in
  `untested.txt` and is listed with the Kiln site that shows it (for
  the table corrections: `unbuilt`).

## Rules

`docs/AGENTS.md`; the "Rules common to the digest's area packages" of
`docs/wp/WP-029.md` for the tests, and the three further rules of
`docs/wp/WP-034.md` "Rules". Files: `crates/slip_kiln/src/snippet.rs`,
`crates/slip_digest/tests/common/mod.rs` (and the runners beside it
only if a signature changes), the new test directories,
`tests/tables/untested.txt` by blessing, the two spec files named
above. `cargo xtask ci` is the gate; `slip_kiln`'s lints
(`kiln-boundary`) stay as they are.

## Done when

The gate passes with `origin/main` merged in; `parse_with` and the
header lines are documented and tested; every row a flag or target
reaches has its directory or is reported as defective code; the
handback has what `docs/AGENTS.md` rule 12 asks, the rows added by
family with the command line each needed, the rows that stay
unreachable with their Kiln sites, the defects found, the rows broken
on purpose, and the half page on module imports.

## Out of scope

Importing modules; the production parse (`parse_observer`), whose
command line is the compilation database's; predefined macros and
system headers in snippets; per-test rule tables (`tests/rules.rs`,
wave 3).
