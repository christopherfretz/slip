## Rules

The eight rules of `docs/wp/WP-057.md` "Rules" hold, and its "Done
when" table is the form of the landed file. Read
`spec/landed/pitfalls/WP-057.md` first: how each tree was checked with
clang and with `slip parse`, and the lessons. Beyond them:

- **Every row must discriminate.** For each row and each silent tree,
  the landed file answers in one line: which blind verifier would
  wrongly accept this tree (one that ignores argument-dependent lookup;
  one that compares declared units only; one that keys a C function by
  its namespace; one that leaves default arguments, friends or
  operators found at instantiation out of its digest). If the honest
  answer is "none: any check catches it", the tree is not the row yet.
- **Prove every silent change** on a copy outside the repository: the
  callee in `clang++-19 -Xclang -ast-dump`, a `static_assert` on
  `decltype` with distinguishable return types, a `constexpr` value
  under `static_assert`. Record the method per tree.
- **Names** in `expect.txt` and `declared.txt` are as `spec/verify.md`
  §6.1 gives them (template arguments qualified), whatever today's
  printer prints; list the lines where the two differ.
- **Rows whose finding the table gives two ways** (N25, N31, N35: a
  collision under the merged rule, or `removed` and `added`): write the
  one your reading of `spec/digest.md` §3.4 and `spec/verify.md` §2.1
  expects and say which sentence decides it. WP-056 corrects the line
  if the run shows the other.
- **N27 and the second subject of N38 are `good`-only rows**: they are
  against false findings. Each has two `good` trees where the table
  says so, and the landed file says which over-eager verifier would
  wrongly report them.
- **N34's wrong edit must not touch `dep/`**: the owned code redefines
  the dependency's macro; the dependency's headers are byte-identical
  in every tree.
- A hazard you know that N01 to N38 still do not cover is listed in the
  handback with a five-line sketch; do not build it.

**For the supervisor to decide.**

- **N34 under the merged rule is a hole in the spec, not in the walk.**
  The wrong edit renames the dependency's `legacy::Dep` to `acme::Dep` in
  this translation unit; the merged rule maps it back onto `legacy::Dep`,
  and `verify.md` §2.1 has no sentence that tells a dependency's entity
  from an owned one, so the tree verifies once the walk is complete. I
  kept the table's line (`mismatch removed legacy::Dep`): the finding is
  right (the dependency's binary still defines `legacy::Dep`). A sentence
  is needed, for instance: a rule does not apply to an entity every
  declaration of which is in a file the run treats as read-only (the
  dependency's), so that `acme::Dep` keeps an unmapped key. The second
  subject, one rule per moved entity, is caught as the spec stands.
- **Format.** `declared-<k>.txt` (N12, N34) and `good-<k>: none` (N18)
  are not in §1; the runner (WP-056) needs both, or the subjects become
  rows of their own. A row's declared file cannot be shared where a shape
  needs other rules.
- **Names.** `verify.md` §6.1 has no row for a `default_argument` unit
  (N23 bad-4; the walk writes `<function>::<default_argument N>`), and
  says nothing of inline namespaces in a qualified name (N31: the walk
  leaves them out, which breaks "different keys, different names").

**Today's walk** does not meet: the `good` trees left pending by the
