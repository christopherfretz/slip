# WP-107 — slip_digest: the tables Kiln computes for classes are not written, and the rows that show it

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-045, WP-046
- Size: M
- Parallel with: WP-040, WP-049, WP-103, WP-104, WP-106

**Starts after WP-045 is on main** (it and WP-046 wrote the `demand`
runner's rules for derived units, which these tests lean on).

## Scope

`spec/digest-kinds.md` §11.7: record layouts, the subobject graphs and
final overriders of polymorphic classes, vtable layouts and the
validated comparison category classes are computed by Kiln the first
time something needs them, and **none of it is written**: each is a
function of declarations whose units are compared (digest §6, last
rule). About seventy rows say `demand` and have no test
(`tests/tables/untested.txt`):

- §4.7: `RecordLayout` (13 rows), `LayoutCache` `map`;
- §10.6: `ClassCache` `map`, `SubobjectId`, `Subobject`,
  `ClassVirtuals`, `VTableComponent` (16), `Thunk`, `VTableLayout` (7),
  `VttComponent`, `CmpCategories`, `CmpCategoryInfo`, `CmpCategory`,
  `CmpResult`;
- §10.9: `Ast` `layouts`, `virtuals`, `vtables`, `cmp_categories`.

A `demand` row's test (§1.5) is a source, and the same source with an
added use that makes Kiln fill the field: every unit both sides have is
equal. For each table find, by reading Kiln at the pin, **every**
construct that makes Kiln compute it (`sizeof`, `alignof`, `offsetof`,
a constant expression that reads a member, a `static_assert` on a
layout, a base-to-derived cast, `dynamic_cast`, a virtual call, a
definition that needs the vtable, a pointer to a virtual member, a
defaulted `operator<=>`, a `<=>` on a class, a structured binding of a
class) and write the pair for it. The landed file has the table:
Kiln's table, the construct, the Kiln `file:line` that fills it.

But "not written" is only sound if the claim under it is true, and that
is the real work here:

1. **Is each table a function of units that are compared, and of
   nothing else?** For each row, name the units the value follows from
   (the class's own unit and its bases' for a layout; the virtual
   functions' units for a vtable; `std::strong_ordering`'s members for
   a comparison category) and the command-line facts it follows from
   (the target, `-fpack-struct`, `#pragma pack`, `-fms-bitfields`: a
   digest is relative to its command, digest §1 rule 8). Then try to
   break the claim: a layout that changes while every unit named stays
   equal. `#pragma pack` and `#pragma ms_struct` around a class (is the
   pragma's effect in the class's unit? `alignas`, `packed`,
   `no_unique_address`, bit-field widths, `[[trivial_abi]]`,
   `empty_bases`, the order of fields and bases, a base made virtual,
   a key function moved (the first non-inline virtual function: defined
   in class against out of line), a covariant return type (a thunk), a
   `final`, an overrider added in a derived class, a `using` that
   unhides. For each: the pair of sources, and which unit differs. One
   whose layout or vtable differs with all units equal is a wrong
   equal: report it with the row that must become `in` or the unit
   that must hold the fact, and make the affected unit indeterminate
   until it does.
2. **Values that were computed from a table are written where they are
   used** (digest §7: constants; §6): `sizeof(S)` as a constant in an
   expression, an `offsetof`, a member pointer's offset, a
   `dynamic_cast`'s path, a base-to-derived adjustment in a cast, the
   vtable index of a virtual call if Kiln stores one in the call. Read
   how the walk writes each today; show that a layout change reaches
   every user's unit (differ tests under the user), or that the user
   holds only what the class units decide. Whichever it is, it must be
   the same whether or not the table had been computed before the walk.
3. **The comparison categories**: `CmpCategoryInfo` is validated from
   the `<compare>` classes of the translation unit (a snippet declares
   its own). Two different definitions of `std::strong_ordering` (other
   values for `less`, another member order): which units differ?

## Interface

Files you may edit: test directories, `spec/landed/digest/WP-107.md`.
Code changes only for item 1's "indeterminate until it does" (one
cause, where the walk writes the class), and for a defect in how a
value of item 2 is written if it is in `value.rs` or `expr_misc.rs` on
lines no open package owns; everything else is reported with a pending
test. Do not change a row of `spec/digest-kinds.md`: propose it in the
handback.

## Tests

`tests/demand/<short name>/<row>/` per row, generated where rows share a
shape (`VTableComponent`'s sixteen, `RecordLayout`'s thirteen: one
source per construct, the directories written out or generated under
`tests/gen/`), and the `differ` tests of items 1 to 3 under the unit
that must change. A `demand` test must be able to fail: for one row in
five, show that writing the table into the unit that owns it makes the
test fail (a temporary change, listed in the handback, not left in).

## Handback

What landed is in `spec/landed/digest/WP-107.md`.

- **Tests.** 42 `demand` tests: 39 rows (the 15 layout rows, the 9
  virtuals rows, the 15 comparison rows) and 3 constructs under
  `demand/_/`. Each was checked by a probe: side A has no entry in the
  table, side B has one. Pair tests for the class tables and for rule 9
  (below) are generated by `tests/gen/class_tables.py`; none pending.
- **Wrong equal (item 1), fixed by a row change.** A typedef carrying
  an alignment changes Kiln's layout (`kiln_abi/src/layout/mod.rs:365`),
  but the type digest was canonical. As the coordinator asked, row
  `TypeView/Typedef` is now `in` under digest-kinds §4.2 rule 9: a type
  whose sugar, walked as Kiln's layout walks it, meets a typedef
  carrying an alignment is written as `Typedef`, those typedefs
  (`ref*`), then the canonical digest. Every other typedef stays
  transparent. The class cause `layout/typedef-alignment` is removed;
  the 10 indeterminate tests are now differ pairs, and the 2 pending
  tests run. New pairs cover parameters, return types, `new`,
  `alignof` of an array, `sizeof`, template arguments, deduced types,
  `decltype`, redeclarations, `using` with the attribute, atomic,
  dependent arrays, address spaces and references. I to K with the
  same alignment differs (the entity is written; a rule maps a rename).
  Review round: a typedef whose declarations do not all carry the same
  alignment (none against some, or other values) is indeterminate
  (`typedef/alignment-by-declaration`), with every unit whose type
  meets it, because Kiln's `alignof` reads only the declaration a use
  names and its layout every declaration present at first layout,
  cached; the walk's bound is reached by a test;
  a function template's first-use sugar is shown not to be read.
  No golden changed. Scheme: added under scheme 2 after WP-113, no bump.
- **Item 2.** Constants (`sizeof` in a constant, a constant object,
  `offsetof`) are written where they are used. Member pointers, casts,
  `dynamic_cast` and virtual calls write no offset or index, so only
  the class units decide them.
- **Item 3.** Another value for `less` changes that member, its
  `<value>`, and constants computed with `<=>`. Another data member type
  changes the member and every value. Member order changes nothing:
  Kiln finds the values by name.
- **Left in `untested.txt`.** The 30 vtable rows. `ensure_vtable` has
  no caller outside `kiln_abi`, and `-fdump-vtable-layouts` is refused
  by the snippet check, so `Ast::vtables` is never filled.
- **Mutations.** Writing each table into the class unit fails every
  demand test of that table (M1 to M3). The rule 9 mutations (A1 to
  A21, B1 to B3, C1 to C5) and their survivors are in the landed file.
- **Decisions where the package was silent.** The bound cause and the
  by-declaration cause are `Unsupported` strings. The vtable rows stay listed instead of getting
  pending tests, because no construct reaches them.
- **For Kiln.** Four defects against clang 19 (landed file): `alignof`
  of a reference to an aligned typedef drops the referee's sugar;
  Kiln's `alignof` (`layout_attributed_typedef`) reads only the named
  declaration's attributes while its layout reads every declaration;
  `.*` and `->*` drop the pointee's sugar; the layout reads
  redeclarations after the one a field names and caches by first use.
