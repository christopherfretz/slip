# WP-084 — slip_kiln: ranges, tiers 0 and 1, and unit order

- Status: todo
- Milestone: M3
- Track: B
- Needs: WP-025

## Scope

`spec/api.md` §1 (unit order) and §5.4; `spec/edits.md` §2.2 (the range
of a name token). Functions over a unit that everything with a range
depends on, and that must be right before anything edits text.

**The rules for the end of a token and for a range of file characters
are Kiln's, and this package calls them.** Kiln WP-2150 (Kiln `main` at
`913a490bb`; Kiln `spec/source.md` "Editable file ranges" and "Expansion
entries", `spec/lex.md` "End of a token") delivered what
[KF3](../requests/KF3-location-utilities.md) asked: `kiln_lex::token_end`,
`SourceManager::editable_file_range`, `file_loc_at_macro_start`,
`file_loc_at_macro_end`. This package writes no version of
`makeFileCharRange` and lexes nothing itself. What is Slip's is the
tier, the range of a *name*, and unit order.

**It needs the pin move after WP-044**: the package that moves Slip's
Kiln revision to `main` at or after `913a490bb` (Slip's pin is
`62d190007`, and `83566cc47` with `docs/wp/WP-044.md`; neither has these
functions). Item 3 and test 5 need nothing of it and can be written and
tested at the present pin (`include_loc`, `expansion_info`); so can the
marked-snippet harness of the tests and the machinery of test 4. Items
1 and 2 cannot be tested before it.

1. **The file range of a token span, or none** (`file_range_of_span`,
   `file_range`): Kiln's `editable_file_range` of the span, unchanged,
   for a span that is not empty. An empty span has no range here
   (version 0 of the API has no insertion point). `file_range(first,
   last)` ends the span at Kiln's `token_end(last)` and has no range
   when that has none. The **tier** is not in Kiln's answer and is
   derived from Kiln's own two rules: 0 when each end of the span that
   is a macro location passes `file_loc_at_macro_start` (the begin) or
   `file_loc_at_macro_end` (the end), which is Kiln's rules 1 to 3; 1
   when Kiln answered and that is not so, which is its rule 4 (both ends
   in macro-argument entries of one use of one parameter). A range that
   is a whole expansion is therefore the invocation, at tier 0, as in
   clang: the extent of `ID(a + b)` with `#define ID(x) x` is the
   whole invocation.
2. **The file range of a name token, or none** (`name_range`),
   `spec/edits.md` §2.2. A name's range must be the identifier's own
   bytes (`spec/api.md` §6.6 rule 1), and rule 1 does not give that for
   a name that is a whole expansion: `ID(foo)`, or `NAME` with `#define
   NAME foo`. So the question is put to Kiln at the place where the
   token is written. While the location of the token's first character
   is in a macro-argument entry (`expansion_info`), it is replaced by
   `immediate_spelling_loc` of it. If what is reached is a file
   location, the span is from there to `token_end` there, the range is
   `editable_file_range` of that span (a span of file locations:
   Kiln's rule 1 and its check that the result is one buffer range, in
   order), and the tier is 0 if no step was taken and 1 otherwise. If it
   is a macro location (a replacement list, a `#` or `##` result),
   there is no range. This function does not look at the buffer's
   origin, the load report or the bytes: `not_a_file`, `file_recoded`
   and `not_plain` are `slip_kiln::sites`' (`docs/wp/WP-068.md`), for
   the rename, and `docs/wp/WP-085.md`'s for a script. The walk is
   Slip's because the tier is Slip's: Kiln has no function for the
   origin of a token (KF3 §2, row U3). It uses no arithmetic on
   locations.
3. **Unit order.** A comparator of two locations by their position in the
   preprocessed token sequence: walk expansion and inclusion parents to a
   common ancestor (`include_loc`, `expansion_info`). Kiln has no such
   function.

`Unit` gains what `token_end` needs and the closure's `FrontEnd` has:
the interner (`FrontEnd.interner`, Kiln `kiln_driver/src/front_end.rs:103`
at `913a490bb`) and the lexer options of the unit (`FrontEnd.pp`, `:113`,
with `Preprocessor::lex_options`, `kiln_pp/src/preprocessor.rs:614`),
behind one method, so that no other module of Slip holds either.

## Interface

```rust
// crates/slip_kiln/src/parse.rs
impl<'r> Unit<'r> {
    /// Kiln's `kiln_lex::token_end` with this unit's interner and lexer
    /// options: the end of the token that starts at `at`, or `None`.
    pub fn token_end(&self, at: Loc) -> Option<Loc>;
}

// crates/slip_kiln/src/ranges.rs
#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum Tier { File = 0, MacroArgument = 1 }
pub struct FileRange { pub file: kiln::source::FileId, pub lo: u32, pub hi: u32, pub tier: Tier }

/// Rule 1, for a span that already ends at the end of its last token.
/// `lo` and `hi` are Kiln's: offsets in its text of the file.
pub fn file_range_of_span(sm: &SourceManager, span: Span) -> Option<FileRange>;
/// Rule 1. `first` and `last` are the locations of the first and the last token.
pub fn file_range(unit: &Unit<'_>, first: Loc, last: Loc) -> Option<FileRange>;
/// Rule 2. `name` is the span of one identifier token as Kiln's tables
/// give it (a written reference's name, a declaration extent's `name`).
pub fn name_range(unit: &Unit<'_>, name: Span) -> Option<FileRange>;
pub fn unit_order(sm: &SourceManager, a: Loc, b: Loc) -> std::cmp::Ordering;
```

## Tests

`crates/slip_kiln/tests/ranges.rs`, snippets with marked positions:

1. Tier 0: plain text; a span holding a whole object-like and a whole
   function-like invocation; a span that is exactly one invocation.
2. Tier 1: inside one argument; the same argument used twice gives the
   same range for both uses; nested invocations (an argument passed on to
   another macro).
3. None: first token in a replacement list; last token in one; a span
   that starts in file text and ends in an expansion; tokens from two
   different arguments; a pasted token; a stringised argument; a span
   across two files; an empty span.
4. **The property that defines correctness**: for every `Some(r)`,
   re-preprocessing a copy of the file in which the bytes of `r` are
   replaced by a unique marker token moves exactly the span's tokens and
   no other. Run it over every expression of every snippet of the digest
   pair tests. It tests Slip's use of Kiln's function and the derived
   tier (a tier 0 range is outside every argument, a tier 1 range inside
   one); a failure that is Kiln's rule is reported to Kiln, not repaired
   here.
5. `unit_order`: tokens in a header before and after a nested include;
   tokens of one expansion; an argument used twice (two positions); it is
   a total order on the locations of a unit (sort and check adjacent
   pairs).
6. `name_range`: plain text (tier 0); `ID(foo)` with `#define ID(x) x`
   (tier 1, the three bytes; `file_range_of_span` of the same span is
   the invocation at tier 0); an argument passed through two macros and
   an argument inside another argument (tier 1); `NAME` with `#define
   NAME foo`, `#define foo foo`, `A(B)` with `#define B foo`, a pasted
   and a stringised name (none). **Agreement with Kiln's rule**: for
   every name token of every snippet, `name_range` and
   `file_range_of_span` of the token's own span are equal, or the second
   is a whole invocation that properly contains the first, or the first
   is none and the second is a whole invocation; any other pair fails
   the test and is a question for Kiln.

## Done when

The tests pass. Over three LLVM units, the property of test 4 holds for
every call expression (run once by hand, numbers in the hand-back). The
hand-back lists every Kiln function called, with `file:line` at the
pin, and says that `slip_kiln::ranges` lexes nothing and has no rule
of its own for a range of file characters.

Which other uses an argument has (the preprocessing record, request KR4).
