## Scope

(`spec/landed/digest/WP-141.md`, option 5, §8.1 "Named whole", §8.2,
§8.4, §8.5). WP-141 writes a using-directive at namespace scope and a
namespace alias in an owned file with the reading of the namespace's
own key, so in the migration of a root namespace into one a dependency
opens the correctly redirected `using namespace legacy;` →
`using namespace acme;` is still `removed` and `added`, and the split
directive of WP-141's central case is `added`. This package makes them
verify:

## Findings of the design attack (2026-11-23), binding for this build

The independent review of the design (its report is kept by the
supervisor; F-numbers are its) found no changed lookup in parsed code
that step 1a lets through, and confirmed the arithmetic of D1, D2, C1,
C2, C3, C6, C7, C8, A1, the absence of an order dependence, and the
exactness argument of §8.2 (an equal alternate sum forces every
alternate into the pre-image's group; the alternate sum is over the
set, since C1's alternate is also a written unit). Three things change
what is built:

- **F6. An alternate belongs to declarations, step 1a is stated on
  units.** Two declarations can write one unit (one key, one digest,
  one group) while only one of them offers the alternate: the same
  directive entered once in an owned file and once where it has one
  reading, or written in `namespace acme {}` (whole) and in an owned
  `namespace legacy {}` (not whole). **A unit has the alternate only if
  every declaration that writes it offers it.** The alternate sum
  follows the same rule. A fixture for each of the two shapes, and the
  mutation "any declaration offers it".
- **F3. The second guard.** In an observer that includes both
  dependencies and no owned opening of `acme`, the split directive of
  the central case is `added <using_directive acme>`: `acme` has one
  view there, so no alternate. With an owned `namespace acme {}` in the
  same header the namespace has an owned view by its opening alone
  (WP-140), holds nothing under `legacy`, and the alternate is taken:
  no finding. So the edit that verifies in every observer has **both**
  guards, `namespace legacy {}` and `namespace acme {}`, before the two
  directives (the second is needed to compile wherever nothing has
  declared `acme` yet). A row for that observer with both guards (no
  finding) and without the second (the finding, with a note that says
  to add the owned opening); the sentence in `spec/verify.md` that an
  owned opening with nothing in it holds nothing and yet gives the
  namespace its owned view. `created <using_directive acme>` is not a
  remedy (one key for every such directive of the codebase).
- **F8. An alias that named both parts** needs `changed L` (WP-141's
  ruling), and so does every alias of it (`namespace M = L;`), and
  `changed` then admits any retarget of the alias. Item 6 below.

6. **A declaration narrower than `changed` for an alias that named both
   parts: propose and stop for the supervisor** (a new declared form is
   the operator's to see). The shape to weigh: `narrowed <alias>`, by
   key, which holds only if the post-image's alias has exactly the
   reading `Ref::part` of the pre-image's key in the owned view (the
   alias now names the owned part and nothing else changed), follows
   alias chains by itself, and can be emitted by the tool that split
   the alias. Say what it accepts that `changed` should not have to.
