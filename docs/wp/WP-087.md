## Scope

**This package is in the trusted base** and is reviewed as such: the
supervisor's read, an independent review, and the byte-identity check
of "Done when". It adds a read-only public interface to `slip_digest`;
it changes no digest.

`docs/wp/WP-040.md` adds `local::unit_of`, which this exposes.

**It is on milestone M2's path.** The native rename takes every key and
every rule from this interface (`spec/edits.md` §9.7,
`docs/wp/WP-071.md`), and the check of spelled entities reads
`with_rules` (`docs/wp/WP-096.md`). M2's exit runs through it: there is
no second, smaller `Keys` for M2 (`docs/demos/demo-2.md` §1).

`spec/api.md` §7.5 rules 1 to 3 and §7.6 rule 3; `spec/digest.md` §2.1,
§2.2, §3; `spec/verify.md` §2.1. A transform says "this call is meant to
change" or "this function is renamed". The untrusted host must turn that
into the keys verification uses, and it must get them from the code that
computes the digests, not from a second implementation that could
disagree.

Why this is safe to expose: a key is a name for a unit. Knowing it lets a
transform declare that unit `changed`, which the transform could not do
otherwise at all, and which is reported (§7.5 rule 6). It gives no way to
alter what the walk writes.

## Interface

```rust
// crates/slip_digest/src/query.rs
pub struct Keys<'a> { /* a Walk over the input; memoised */ }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum NoKey { NotAUnit, ContentKeyed, Indeterminate(Cause) }

impl<'a> Keys<'a> {
    pub fn new(input: &'a Input<'a>) -> Keys<'a>;
    /// The same over a post-image, with the Slip run's rules: the keys
    /// are then in the pre-image's key space (verify §2.1). WP-096 uses it.
    pub fn with_rules(input: &'a Input<'a>, rules: &'a slip_model::keys::RuleTable) -> Keys<'a>;
    /// The declaration the digest treats as the entity of `d`.
    pub fn entity(&self, d: DeclId) -> DeclId;
    /// The entity that is the digest unit holding the declaration `d`
    /// (digest §2.1): `d`'s entity when it is a unit, else the innermost
    /// enclosing entity that is. Local entities: `local::unit_of`.
    pub fn unit_of(&mut self, d: DeclId) -> Option<DeclId>;
    /// The key id of the unit `e`, in the pre-image's key space.
    pub fn key_id(&mut self, e: DeclId) -> Result<Digest, NoKey>;
    /// The key itself (digest §3): `key(e)?.id() == key_id(e)?`, and
    /// the two refuse alike. Under `with_rules` it is the mapped key.
    /// The native rename reads it twice: to match a target by the key's
    /// name, parent and kind (edits §9.1), and to make the rule of a
    /// follower whose key does not hold the identifier as its name (an
    /// unnamed class named by a renamed variable, edits §9.2).
    pub fn key(&mut self, e: DeclId) -> Result<slip_model::keys::Key, NoKey>;
    /// The key ids of the units of this translation unit that digest
    /// §2.2 derives from `e`, sorted: its resolved properties, the
    /// instantiations of it and of its members.
    pub fn derived(&mut self, e: DeclId) -> Vec<Digest>;
    /// verify §2.1: the rule under which a post-image where `e` is
    /// declared `new_name` in the same scope has `e`'s key.
    pub fn rename_rule(&mut self, e: DeclId, new_name: &[u8]) -> Result<slip_model::keys::Rule, NoKey>;
}
```

`Keys::new` does not run the walk. Each method computes what it is asked
and no more; `derived` may enumerate the specialisations of `e`.

`key` is as safe to expose as `key_id`, for the reason given above: a
`Key` is the value whose hash the id is (`slip_model::keys::Key::id`),
it is read-only, and it gives no way to alter what the walk writes. A
key's `parent` is a key id, not a key: a caller that walks the parent
chain asks `key` again for the enclosing entity it took from the AST,
and must find that entity's id in `parent`.

## Tests

`crates/slip_digest/tests/api_keys.rs`:

1. For every unit of every pair-test snippet: `key_id(unit)` equals the
   key the full walk gives it (`Output::names` joins them).
2. `unit_of`: an expression's holder that is a function; a variable's
   initialiser; a member function defined in class; a lambda's call
   operator inside a function (the function); a default member
   initialiser (the class or the field, as digest §2.1 says); a
   parameter; an enumerator.
3. `derived`: a function template with two instantiations in the unit; a
   class template whose member is instantiated; a function with a
   deduced return type.
4. `rename_rule`: digest the snippet; apply the rename by hand to its
   text; digest it under the rule; the digests are equal. Under a rule
   built for another name, they are not.
5. Each `NoKey`: a content-keyed unit (digest §3.3); a parameter; an
   entity whose key is indeterminate.
6. `entity` agrees with the walk on every declaration of the snippets.
7. `with_rules`: for the renamed snippet of test 4, `key_id` of the
   renamed entity under the rule equals its key in the original.
8. `key`: for every unit of every pair-test snippet, `key(unit)` is
   `Ok` exactly when `key_id(unit)` is, with the same `NoKey`
   otherwise, and its `id()` is that key id; the same under
   `with_rules` for the renamed snippet of test 4. For a function in
   `namespace a { namespace b { … } }`, the key's parent is the key id
   of `b` and `b`'s is that of `a`; for an unnamed class named by a
   variable, the name is `unnamed_by` the variable's identifier; for a
   function in a linkage specification, the parent is `c_linkage`.

- **Departure:** `NoKey` has two more variants, given only by
  `rename_rule`:
  - `NotRenamable` (`unsupported`): a specialisation, partial
    specialisation or decomposition, or a key whose name is not an
    identifier;
  - `BadName` (`invalid_argument`): a new name that is not
    `[A-Za-z_][A-Za-z0-9_]*`, judged first; or the entity's own name.
- **`derived`** lists what the walk writes as derived and reaches from
  `e`. It runs the walk once per `Keys`. On every pair-test side:
  - every key it gives is the key of a written unit;
  - every derived unit is listed from some declared unit. The
    exceptions are units of compiler-declared entities and template
    parameter objects.

  A class's implicit members are derived from the class.
- **A refused rule table** keys nothing, as in the walk:
  `Indeterminate(key/refused-rule)`, and `derived` is empty.
- **Outside `query.rs`:** `pub mod query;` in `lib.rs`, and
  `pub(crate)` on `local::param_template` and
  `local::param_templates`. No function body changed. The pair tests
  and goldens pass unchanged under `cargo xtask ci`. The corpus digests
  were not rerun (no release build); that is left to the supervisor.
- **WP-095:**
  - `NotRenamable` maps to `unsupported`, as `NotAUnit`,
    `ContentKeyed` and `Indeterminate` do;
  - `BadName` maps to `invalid_argument`.
