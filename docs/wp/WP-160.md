### Summary by item

1. **Label named like the old name (`stay-label`, `stay-label-address`, `stay-label-other-function`, all `xfail`):**
   - **Cause (from Kiln source and live probe `crates/slip_kiln/tests/written.rs` `wp160_label_recording`):**
     - Label declarations (`f:` in `kiln/crates/kiln_parse/src/stmt.rs` via `ext_label`; GNU `__label__ f;` in `kiln/crates/kiln_parse/src/extents.rs` via `ext_local_labels`) create a `DeclKind::Label` and record a row in `ast.decl_extents` (`kiln/spec/ast.md` §19) with `e.name = name_span`. `slip_kiln::written::decl_names` returns them, and `slip_refactor::rename::decls::claim` emits `keep` because a label is not a subject.
     - Label uses (`goto f;` in `kiln_parse/src/stmt.rs` -> `act_on_goto` in `kiln_sema/src/stmt.rs`; GNU address-of-label `&&f` in `kiln_parse/src/expr.rs` -> `act_on_addr_label` in `kiln_sema/src/stmt.rs`; and `asm goto` label operands) record **nothing** in `ast.written_refs` and **nothing** in `ast.decl_extents`. `GotoStmt` does not even store the label identifier's `name_loc` (only the `goto` keyword's `loc`). `kiln/spec/ast.md` §18.4 explicitly excludes labels ("Not in the table: ... labels ...") and §18.8 classifies them as documented non-names.
     - Because Kiln records no occurrence for label uses, `slip_refactor` cannot claim `keep` for `goto f` or `&&f`, so the residue scan (`spec/edits.md` §8.4) flags the label token as `residue not_compiled`, ending `verified_with_residue` and writing nothing without `--allow-residue`.
   - **No workaround in Slip:** per scope, Slip does not walk statements or scan raw tokens. `stay-label` remains `xfail` naming the Kiln request below, and two new `xfail` tests were added for the remaining label forms: `tests/transform/rename/stay-label-address/` (`&&f`, GNU extension) and `tests/transform/rename/stay-label-other-function/` (`goto f` in a function that does not mention `a::f`).

   #### Kiln request (for supervisor to send)

   - **Title:** Record label references (`goto`, `&&label`, `asm goto`) in `ast.written_refs`
   - **What Slip needs:** When `ParseOptions::written` (`ast.written_refs` recording) is enabled, record a written reference for every label use — `goto l;`, GNU address-of-label `&&l`, and `asm goto` label operands — with `range` equal to the label identifier token's span and `entity = Some(label_decl_id)` pointing to the `DeclKind::Label` declaration (consistent with `decl_extents`, which already records `l:` and `__label__ l;` as `DeclKind::Label`). A dedicated `RefRole::Label` (or an existing role documented in `kiln/spec/ast.md` §18) is fine; once landed, Slip will accept that role in `slip_refactor/src/rename/target.rs` (`rename_role`) and drop the three `xfail`s.
   - **Minimal reproduction** (pinned in `crates/slip_kiln/tests/written.rs` `wp160_label_recording`):
     ```cpp
     namespace a {
     int f(int x) { return x; }
     int u(int n) {
       int r = 0;
     f:
       r += f(1);
       if (r < n)
         goto f;
       return r;
     }
     int addr(int n) {
       void *p = &&f;
       int r = 0;
     f:
       r += f(1);
       if (r < n)
         goto *p;
       return r;
     }
     int other(int n) {
       __label__ f;
       int r = 0;
     f:
       if (r < n) {
         ++r;
         goto f;
       }
       return r;
     }
     }
     ```
     At this pin, `decl_extents` has rows for all four label declarations (`f:` x3 and `__label__ f;`), while `ast.written_refs` has **no** entry for `goto f` (in `u` or `other`) or `&&f` (in `addr`).

### Choices

1. **Carry `display` on `Refusal` (`EDTS` v3) rather than adding unselected followers to `EditSet.subjects`:** `spec/edits.md` §6 defines `EditSet.subjects` as the *selected* subjects and followers, and `declared::union_of`, `reduce.rules`, and `reduce.subjects.selected` rely on that invariant. Storing `display: opt<str>` directly on `Refusal` preserves that invariant, fixes both `mixed_follower` and any unselected `mixed_set` subject, and follows WP-139's precedent of bumping `EDTS` version without retaining pre-release old-version readers (`SINCE = 3`).
2. **`require: case-insensitive` stays inside `work_base` (`$SLIP_TEST_ROOT` when set):** Falling back from a case-sensitive `$SLIP_TEST_ROOT` onto a case-folding `<root>/target` violates `spec/harness.md` §11.5 (and in fact reproduces the §11.5 inode-renumbering burst on the workspace mount during `back`!). Keeping the test in `work_base` guarantees inode stability when `$SLIP_TEST_ROOT` is set on a local case-sensitive filesystem (`SKIP` there; `PASS` on a case-folding local volume such as macOS APFS; `ERROR` under `SLIP_REQUIRE_ALL=1` if no case-folding volume is used).
3. **`Refusal.display` is optional when `subject` is present, forbidden when `subject` is absent:** `slip_reduce` always populates `display` whenever `joined.subjects` knows the subject, while hand-built test edit sets without a display string stay valid; a refusal without a `subject` (`no_subject`, `no_observer`, `no_edit`, `rule_conflict`) cannot carry a dangling `display`.
