# WP-057 — pitfall rows N01 to N24: relocating a namespace

- Status: in-progress
- Milestone: M1
- Track: C
- Needs: WP-025
- Size: L
- Parallel with: WP-058, WP-050, WP-055 and the digest's open packages

**Can start now.** A row is C++ and three small text files; it needs no
code of Slip's that is not on main. What it cannot have yet is its
verdict: the runner (WP-056) comes after `slip verify`. Until then a row
is checked by the production compiler and by `slip parse`, as below.

## Scope

`spec/pitfalls.md` §1 (the form of a row) and §2 (the table): one
directory per row N01 to N24 under `crates/slip_verify/tests/pitfalls/`,
named `n01-<slug>` to `n24-<slug>`.

Files you own: those directories, and `spec/landed/pitfalls/WP-057.md`.
Nothing else: no runner, no script in the repository, no change to
`spec/pitfalls.md` (hand back what you would change).

## Interface

`spec/pitfalls.md` §1 is the format. `declared.txt` is the text of
`spec/verify.md` §2.3; entity names in `declared.txt` and `expect.txt`
are written as `spec/verify.md` §6.1 "Names" gives them
(`legacy::f(int)`, `legacy::Mine`, `legacy::store<legacy::Mine>`).

## Rules

1. **One hazard per row.** `good/` and `bad/` differ from `pre/`, and
   from each other, by the edit the table describes and nothing else: no
   reformatting, no renamed parameter, no moved line that the edit does
   not need. A reviewer reads `diff -r pre good` and `diff -r good bad`.
2. **Self-contained and small.** No system header, no `#include <…>`.
   `dep/` holds the code that stays (`namespace legacy` of the
   dependency) and is byte-identical in every tree of a subject. A file
   is rarely over forty lines.
3. **The setting of §2** unless the row says otherwise: `dep/` declares
   in `namespace legacy` and keeps it; owned code moves from
   `namespace legacy` to `namespace acme`; `declared.txt` is the one
   line `relocate legacy => :: acme` (the merged form: after the rule,
   `acme` in the post-image and `legacy` in the pre-image are one
   namespace). N21 and N22 say "one rule per moved entity": one
   `relocate <entity> => acme :: =` line each, and no line for the
   namespace. A row whose correct edit adds a declaration (N05, N16)
   has the `created` line for it.
4. **Both forms of the wrong edit where the table gives both.** "`not_parsed`;
   with a fallback: `mismatch …`" is two trees: `bad/` on `pre/` (the
   parse fails) and `bad-2/` on `pre-2/`, where `pre-2/` is `pre/` plus
   the worse-matching declaration that keeps the wrong edit compiling.
   `pre-2/` gets a `good-2/` as well: the correct edit must verify on
   the second subject too. The silent tree is the one that tests the
   digest; do not leave it out because the first already "catches" the
   edit.
5. **`expect.txt` names what must be found**: for a `mismatch`, the
   kind and the entity the table's last column names, and a place
   (` @ main.cpp:<line>`, or the header) wherever the hazard sits on one
   line: the call, the use, the declaration. A line without an entity
   (`mismatch` alone) only where the table says no more.
6. **A row the catalogue calls `good` only** (N11, N18) has `good/` and
   no `bad/`; write a second `good-2/` if the hazard has two shapes
   (N11: a friend function, and an elaborated type specifier).
7. **Checked before it is handed back**, each tree and each subject:
   - with `clang++-19` (`scripts/provision.sh --full` of the workspace
     installs it): `clang++-19 -std=c++20 -fsyntax-only -I. -Idep
     main.cpp` in the tree. Subjects and `good` trees are accepted; a
     `bad` tree is rejected exactly when its line is `not_parsed`;
   - with `slip parse` on a one-entry compilation database for the tree
     (`slip parse --db <file> --store <dir>` in a temporary directory):
     the shard is `ok` where clang accepted and `diagnosed` where it
     rejected. A disagreement is a report to Kiln: give the two
     diagnostics in the handback, and mark the tree
     `xfail <tree>: Kiln and clang disagree (<one line>)`.
   Use a loop in your shell for this; it is not committed.
8. **Do not bend a row to make it pass.** If the hazard cannot be built
   as the table describes (the wrong edit cannot be made silent, the
   correct edit needs more declared than the row says), build the
   nearest honest row and say in the landed file what differs. The table
   is the supervisor's to amend.

## Handback

Rows: `crates/slip_verify/tests/pitfalls/n01-unqualified-staying-type` to
`n24-unqualified-base`, 24 directories, 68 trees and 37 subjects (17
`not_parsed`, 35 `verified`, 16 `mismatch`; N22 has `good: none`). The per-tree table
(clang, `slip parse` shard, expected line, the fact) and the conventions
are `spec/landed/pitfalls/WP-057.md`. No `xfail` line: Kiln and clang
agree on every subject and tree (clang 19 rejects exactly the 17
`not_parsed` trees; `slip parse` gives `diagnosed` on those and `ok` on
the rest). Each silent wrong edit was checked under clang with its
fallback made `= delete` (or incomplete) in a scratch copy: the `bad`
tree is rejected, the subject and the `good` tree accepted.

**Deviations from `spec/pitfalls.md` §2** (rule 8), and what I would change:

- N06: the entity is `legacy::store<legacy::Mine>::put(legacy::Mine &)`,
  not `legacy::store<legacy::Mine>`: the call is in the member's
  instantiated body, a resolved unit `definition` (digest-kinds §11.9).
  Change the column to name the member, and say in `verify.md` §6.1 how a
  resolved unit is named (the line assumes its owner's name).
- N23: the finding is `changed legacy::take(int)`, not the caller: a
  default argument is written in its function's unit (digest-kinds §7
  "Shared nodes", §11.4). Change the column to "as N01; the silent tree
  shows `mismatch changed` the function whose default it is". E10's
  "and a caller that relies on the default" has the same problem.
- N15: the macro is `legacy::make<T>(0)`: with no argument a
  worse-matching `legacy::make` ties or needs the trailing-pack rule.
  Write the column with an argument.
- N05, N16, N17: a using-declaration is two units, the declaration and
  its shadow (`legacy::<using acme::Mine>`, `legacy::<shadow acme::Mine>`):
  two `created` lines each. Rule 3 and the column should say so. N05's
  shadow name holds the template's whole head and signature
  (`acme::<shadow template <class> bool legacy::operator==(const
  type-parameter-0-0 &, const type-parameter-0-0 &)>`), which is long to
  write by hand.
- N09: the correct edit adds the alias `A`, a unit: `created A`.
- N20: `legacy::f()` (the §6.1 function name), not `legacy::f`.
- N11, N18: the second and third shapes are subjects `pre-2/`, `pre-3/`;
  §1 describes `pre-2/` only as "`pre/` plus a fallback".

**What the walk gives today** (a scratch, uncommitted in-process
comparison through `slip_cli::declare`, `slip_digest::digest` and
`slip_verify::compare::compare_groups`; no `slip verify` yet). Lines met:
N01, N05 bad-2, N12, N13 bad-2, N14, N15 bad-2, N17 bad, N20, N21, N22
bad-2, N23 bad-2 (as amended), N24, and good trees of N01, N11 good-2,
N12, N14, N18 good-2, N21, N24. Most other trees have only
indeterminate findings from `Pending(Demand)` (the demand area). Two are
not pending, and are reports:

- N18 `good` gives `changed legacy::where()`: `__PRETTY_FUNCTION__`'s
  value is symbolic but its type `const char[N]` carries the name's
  length (`legacy` 6, `acme` 4). With a destination of six letters the
  tree verifies. `digest.md` §9 says a type a value determines is written
  by value; it should say that the builtin's own type is symbolic with
  it (a `sizeof` of it is then a constant and still caught).
- N18 `good-3` (`std::source_location`) gives `changed legacy::where()`
  also with a name of equal length, and `std::source_location::current`
  is indeterminate: the immediate invocation in the default argument
  (`default_immediates`) holds the function name's value.

**Names.** The walk prints template arguments unqualified:
`legacy::store<Mine>`, `legacy::touch<Mine>(legacy::Mine &)`,
`legacy::enroll<Mine>(const char *)`. The package's interface writes
`legacy::store<legacy::Mine>`; N06's line uses that form and does not
match the walk's name today (main's new §6.1 says "canonical arguments
as Kiln prints them", which leaves this open). The walk even writes
`legacy::operator==<Mine>(const acme::Mine &, const acme::Mine &)` for
one unit of the post-image.

**Kiln.** No disagreement of verdict. Diagnostic text only: for an
explicit or partial specialisation whose template is not found (N07,
N19 `bad`) Kiln says `explicit specialization of non-template struct
'traits'`, clang `no template named 'traits'`.
