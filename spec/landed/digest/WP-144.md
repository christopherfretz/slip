# WP-144 — owned code that is already in the target namespace before the edit

What was built in **PR 2a** (the trusted base and its verify-job wiring),
after the supervisor's design ruling on item 1 (`7a469bbd`,
`docs/wp/WP-144.md`). **PR 2b** (`slip declare`'s `existing` line,
`Record`'s files, unused-entry reporting in `slip_verify`, `spec/exec.md`
§8.8, and `declare.rs`'s loop test) follows on top of 2a. Case
directories are under `crates/slip_digest/tests/rules/` unless said.

## 1. The question

Under `relocate legacy => :: acme`, owned code that already lived in
`acme` before the edit (`acme::x` untouched beside a moved `legacy::g`)
was mapped back to `legacy::x`, giving `removed acme::x`, `added
legacy::x`, and a finding on every reference to `acme::x`
(`spec/verify.md` §2.1, `spec/landed/digest/WP-141.md` §9 Q6).

## 2. The ruling: Option A with five amendments, and Policy 1

- **Option A** (declared `existing` lists in `DECL`): keys stay a
  function of the post-image and the `DECL`, identical in every observer.
  Rejected: B (per-observer inference, vulnerable to cross-observer
  collision B1a and lacking pre-image keys at sums time), C (cannot tell
  two declarations of one file apart), D (loses the namespace's unit and
  `ns_rules`).
- **Five amendments:**
  1. *Program-wide vs local:* `own_lists::is_program_wide` (shared with
     WP-146's `candidate`, less its deduction-guide clause: not
     `units::repeatable`, not internal linkage, not in or under an
     unnamed namespace; typedefs and aliases program-wide). Program-wide
     entities are listed by key in `Declared.existing`; local entities by
     `(key, file)` in `Declared.existing_local`, matching iff **every**
     declaration's expansion-location file is listed. Neither list covers
     the other class.
  2. *Table-free probe key `U(e)` in two passes:* `U(e)` is `e`'s key
     formed as a dependency entity's in probe writing (namespaces keyed
     in their unmapped view, R1/R2 and `ns_table` never consulted,
     separate probe memos). `ns_table` builds in two non-re-entrant
     passes (namespaces, then members/directives). When either existing
     list is non-empty and a probe aborts (depth limit, cycle, or any
     cause), the candidate entity's own key (and any enclosing namespace
     in `ns_table`) receives that cause so its unit is indeterminate
     (never `Verified`; Fix round 1 W1).
  3. *A namespace's own view follows what it holds:* `stays` iff listed
     whole, holds an existing member, or holds a nested namespace that
     stays; `own_view = owned && !stays`. Moved members in a staying
     namespace get a view unit named `legacy (the moved part of acme)`.
  4. *Whole namespaces:* **any named namespace** (owned or not; Fix round
     1 M1) whose `U(n)` is in `Declared.existing` (or enclosed in a
     listed namespace) makes every owned entity keyed under it existing
     at any depth, sets `stays = true` (with no mapped view unit unless
     moved members exist), and holds in the unmapped view even when
     empty. Who may write still reads `owned`.
  5. *`mapped = owned && !existing`; who may write still reads `owned`:*
     rules 1 & 2, `ns_table`'s member view, and R1's `route` read
     `mapped` (`entity_view`); `decide_owned`, `only_by_inclusion`,
     `records::facts`, rebuilt accounting, and §9.2 counts still read
     `owned`. An existing entity's namespace chain is climbed in the
     unmapped view (never `via`, `direct` for a rule producing a level
     unless `kept`). In WP-146's ownership lists (`own_lists.rs`),
     program-wide existing entities appear as `fixed` `M` entries
     (`OwnedState::keyed` records `(false, key)` and `as_if_owned` maps
     them under the owned view).
- **Part II (Policy 1):** entity ownership stays per inclusion
  (`in_owned_file`), keeping `views/a4-owned-header-both-ways` failing
  closed. The two `ns_refs.rs` sites (`:563` read-only openings hold,
  `:580` `dirs`' directive view — along with `:580`'s `rebuilt_reference`
  guard moving from `!read_only_by_path(d)` to `in_owned_file(d)`) moved
  to per-inclusion in their own separate first commit (`5421e373`).

## 6. PR 2a Fix round 1

- **W1 (wrong `verified` on probe abort):** `probe_u` now returns
  `ProbeKey::{Key(Digest), Aborted(Cause)}`; `listed_res`, `existing_res`,
  `mapped_res`, `entity_view_res`, `ns_own_view_res`, and `NsInfo::probe_cause`
  propagate any probe-abort cause onto the candidate entity's own key in
  `keys.rs::key_in` (and record top-level/`ns_table` aborts in
  `ExistingState::probe_causes`), making its unit indeterminate (never
  `Verified`). Empty-list inertness is preserved (`has_existing() == false`
  skips all probes). Regression test `wp144_probe_abort_at_depth_limit_is_not_verified`
  pins the exact 70-deep typedef chain (`a.cpp` verified, `b.cpp` `Mismatch`
  with `FindingKind::Indeterminate`, run `NotVerified`).
- **M1 (whole-namespace entry when dependency also opens the namespace):**
  Removed `!self.owned(n)` from `owned.rs::listed_res` and `owned &&` from
  `ns_refs.rs` Pass 1. Any named namespace (owned or not) is listed when
  its `U(n)` is in `existing`, listing its owned part (`stays = true`, no
  mapped view unit unless moved members exist, write-ownership unchanged).
- **S1–S7 & dead code removed:**
  - Added tests killing R2, R4, R6, R7, R9, R10a–e, R11a–g, R14a–b, and
    v4 golden files (`crates/slip_model/tests/golden/declared-v4.{bin,json}`).
  - Removed 4 dead/redundant branches: unreachable `Specialization` /
    `PartialSpecialization` arms in `owned.rs::key_kind_of` (excluded by
    `key_namespace`), unreachable `chain.is_empty() || chain.len() > REDECL_LIMIT`
    in `owned.rs::existing_res` (excluded by `owned(e)`), duplicate
    `if self.probe > 0` in `owned.rs::entity_view_res` (replaced with
    `debug_assert_eq!(self.probe, 0)` since `keys.rs:258` already redirects
    namespaces in probes), and redundant `|| entry.dep_chain` in
    `rule_use.rs::made_by` (replaced with `debug_assert!(!entry.dep_chain)`
    since `own_lists.rs` calls `made_by` only on mapped entries).
