# WP-158 — every instantiation has a unit

A defect of `spec/digest.md` §2.2 and §4.3 found by the delta review of
WP-154's design: a name in an instantiated body bound otherwise after a
rename, and every unit both images had was equal, because no unit held
the instantiation. Four shapes (`crates/slip_digest/tests/rules/wp158/`):

```cpp
struct X { int mf(int) { return 1; } int mf(long) { return 2; } };
int w() {
  auto l = [](auto u) { return u.mf(1L); };
  int (*p)(X) = l;                 // 1: reached only through the conversion
  decltype(l(X())) x = 0;          // 2: reached only in an unevaluated operand
  return p(X());
}
template <class T> int c(T) {
  auto l = [](int k = T::f(1L)) { return k; };                 // 3
  struct L { int g(int k = T::f(1L)) { return k; } };          // 4
  return l() + L().g();
}
```

## 1. The cause: the digest's choice of units

Kiln at the pin holds every fact; nothing is asked of Kiln.

- **Shapes 1 and 2.** Kiln holds the call operator's specialisation
  `operator()<X>(X) const` (`SpecInfo` kind `ImplicitInstantiation`,
  with its body) whatever made it instantiate it. The digest classified
  it `OnDemand`, a unit only if some stream writes a `Ref` to it:
  `demand::effective_kind` is `None` for a local entity, so
  `units::class_of` fell to `in_builtin`, which reads a member of an
  `IMPLICIT` class as a builtin's part (meant for `__va_list_tag`), and
  a closure type is `IMPLICIT`. A call writes the `Ref`; a conversion to
  a function pointer (the invoker's body is empty, Kiln forwards in code
  generation) and an unevaluated operand (the type only) write none.
- **Shapes 3 and 4.** Kiln instantiates a local function's default
  arguments eagerly with the body that declares it
  (`kiln_sema/src/templ/subst/decls.rs` `defer_default_args_to`, in local
  scope), and the parameter holds the expression. The digest writes an
  instantiated declaration's default as absent (`decl_func::written_default`,
  `digest-kinds.md` §11.4) and writes `default_argument` units only from
  `demand::resolved_units`, for a function that is a unit. A local
  class's member or a non-generic closure's call operator is no unit
  (written in place, §4.3), so the expression was in no stream.

## 2. The rule and what changed

`spec/digest.md` §2.2 "Every instantiation has a unit": every function
body and every default argument or default member initialiser Kiln
instantiated is in the stream of a derived unit, whatever made the front
end instantiate it.

- `units::class_of`: a local entity with `SpecInfo` takes the class of
  its specialisation kind (`spec_class`) before `in_builtin`: a
  specialisation of a generic lambda's call operator, conversion
  function or invoker is a derived unit, keyed under the closure type,
  its body the resolved unit `definition` (§4.3).
- `demand::local_default_arguments`: once the queue is empty, for each
  local function that is no unit, made by instantiation, with an
  instantiated parameter holding a default, the `default_argument`
  units of `demand::default_arguments` under the function's key
  (`demand::local_owner`: the key, derived class, origin file; no unit
  is written for the function itself); then the queue is drained again
  for what they demand. `trace.rs` writes them again for localisation.
- `units::apply_taints`: a taint whose scope is such a local function
  goes where it went before (the owner's unit or the order unit), not to
  one of the new parts.

No existing unit's stream, key or table row changes.

## 3. The count: `digest.instantiated.unheld`

`demand::unheld`, always present (§12), required 0 on both sides of
every fixture by `tests/common` (§13 item 7), reported on the corpus.
What "Kiln instantiated" is read from:

- **bodies**: `DeclArena::fn_def_insts` (Sema appends a function each
  time it finishes instantiating its body), and every function
  declaration with a body that `templ::made_by_instantiation` says an
  instantiation made (its `SpecInfo` or `MemberSpecInfo` kind, else the
  kind governing its lexical context: a local class's member, a lambda's
  call operator in an instantiated body);
- **defaults**: the `ParamData` `default_arg` of those declarations'
  parameters, and the `FieldData` `init` of fields with
  `Ast::instantiated_from`;
- **variable initialisers** (fix round 1, F3): the `VarData` `init` of
  every variable (first declaration) that `made_by_instantiation` says
  an instantiation made and that is not local to a function
  (`Walk::is_local`): a variable template specialisation, a static data
  member of a class template specialisation or of a local class in an
  instantiated body. When the variable has a pattern whose declarations
  have no initialiser (`pattern_has_init`) nothing is counted. The line:
  a variable declared in a function body is a statement of that body,
  held with it; it is not counted on its own (`demand::unheld_var_init`).

A body, default or initialiser is **held** when the own stream of a
unit that is kept writes it. Exactly (fix round 1, F5):
`Walk::hold_body` (`decl_func::write_body`), `Walk::hold_expr`
(`param_data`, `field_data`, `var_data`, `var_definition`,
`demand::default_argument`) and `Walk::hold_type` record only

- between `Walk::hold_begin` and `Walk::hold_end(kept)` in the run's
  loop (a unit and its resolved units, or the local defaults), into a
  pending buffer that `hold_end` keeps only for a kept unit; and
- when `Walk::in_own_stream` is true: not numbering
  (`local::numbering_mode`), at the unit's level (`unit_level`: not
  inside a key or a type digest), not in a profile, not detached, and
  `Walk::dropped` 0. `dropped` is raised around the two walks whose
  stream is written and thrown away inside a kept unit's window: the
  second walk of a default argument's immediate invocations
  (`demand::immediates`) and the candidate streams `units::canonical_decl`
  digests to choose a friend's canonical candidate.

`emitted::in_place` (the emitted mark written in place) uses the same
predicate, so "held" and "written in place" are one condition. A stream
written and dropped outside the window (the mark's walks, a trace)
holds nothing. Left out of the count: a declaration with
`DEPENDENT_CTX` (a pattern), and one inside a local type a kept stream
met and could not number (`local::local_type`, `Walk::hold_type`): that
unit is indeterminate, the known limit of §4.3 "What these rules do not
yet show" (`tests/indeterminate/_/inst-default-argument-lambda`). Only
the members of that local type are left out: an unheld body elsewhere
in the same parse is still counted (test
`a_held_local_type_leaves_out_only_its_members`).

The run's loop drains the queue of local default arguments a second
time after the queue of units is empty. One pass is the fixpoint today:
`local_default_arguments` scans every declaration, not the queue, and an
implicit instantiation such a default demands is queued as a derived
unit anyway (the review's mutation MC survives every suite). The second
drain is kept as a defence, for a unit only such a default could
demand; its comment says so.

What the counter cannot see is what Kiln did not instantiate: a friend
definition reached through a later redeclaration (`spec/digest.md` §2.3
"a friend definition not instantiated", review finding F1).

## 4. `spec/verify.md` §4 and the new units

A unit WP-158 adds on one side only is not a new refusal:

- §4 step 3 reports a one-sided derived unit only when it is marked
  emitted unreferenced (WP-155); otherwise it is counted
  (`verify.derived.only_pre`/`only_post`).
- `emitted::mark` returns at once for a local representative (the
  specialisation's `rep` is local) and for a `default_argument` part,
  and `local_default_arguments` units never pass through it. Only the
  in-place rule can mark a new unit: its own stream writes a local
  function with `constructor`, `destructor` or `used`, which is emitted
  code, and a one-sided unit then is a true finding.
- Where both sides have a new unit, it is compared as any derived unit.
  Pitfall R25 subjects 9 to 12 rename the overload the call does not
  bind: the new units are on both sides, equal, and the trees verify.
