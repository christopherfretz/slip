# WP-107 — the tables Kiln computes for classes

`spec/digest-kinds.md` §11.7 says record layouts, the subobject graphs
and final overriders, vtable layouts and the comparison categories are
not written, because each is a function of units that are compared.
This file records:

- the constructs that make Kiln fill each table, and their tests;
- per row, the units and command-line facts the value follows from;
- item 1: every attempt to change a table while all units stay equal;
- item 2: where values computed from a table are written;
- item 3: two definitions of `std::strong_ordering`;
- the cause added for the one wrong equal found, and the mutations.

Kiln citations are at the pin of `slip/kiln`. The tests are generated by
`crates/slip_digest/tests/gen/class_tables.py`. The walk reads none of
the four tables: `layouts`, `virtuals`, `vtables` and `cmp_categories`
appear in `crates/slip_digest/src` only in `tables.rs`. So a unit's
digest is the same whether or not a table was computed before the walk.

## What fills each table

`demand` tests (§1.5) are under `tests/demand/<short>/<row>/` and
`tests/demand/_/<construct>/`. Each was checked with a probe: side A
holds no entry for the table, side B holds one, and only `added y()`
(plus implicit members of the used class) differs.

## What each value follows from

| Table | Units | Command-line facts |
|---|---|---|
| `RecordLayout` | the class (its fields, bases, attributes on every redeclaration, including `packed`, `ms_struct`, `aligned`, `alignas`, and `ColdDeclData` `record_pack`); its bases' units; its fields' types' units (and their layouts); the units of constants in bit-field widths and alignments; for an instantiation, the pattern's `record_pack` | the target (x86_64 or aarch64 Linux: the only ones Kiln accepts). `-fpack-struct` and `-mms-bitfields` are refused by Kiln's driver. |
| `ClassVirtuals`, `Subobject` | the class and its bases' units (base list, virtual-ness), the virtual function units (`virtual`, `override`, `final`, declarations) | none |
| `VTableLayout` and its parts | as `ClassVirtuals`, plus key function placement (`<key_function>` derived unit), covariant return types (the overriding function's unit) and the layout | the target |
| `CmpCategoryInfo` | `std::partial_ordering`, `std::weak_ordering`, `std::strong_ordering`: the class, its data member, its static value members and their `<value>` units | none |

Where the layout reads a typedef's own alignment, the class unit does
not hold the fact: the field's type digest does (digest-kinds §4.2
rule 9), and the typedef's unit holds the alignment.

### Typedefs carrying an alignment (digest-kinds §4.2 rule 9)

Kiln's layout reads a `Typedef` sugar node's alignment
(`Layouter::type_info`, `kiln_abi/src/layout/mod.rs:365`; `max_align_attr`,
`kiln_abi/src/layout/props.rs:78`; `decl_align`, `mod.rs:518`). The type
digest was canonical (§4.1, §4.2), so a typedef `I` declared
`aligned(8)` and `int` gave one digest: a wrong equal for fields,
variables, `alignof`, `new`, `sizeof` and `alignas(type-id)`.

The class-level cause `Unsupported("layout/typedef-alignment")` is
removed (`decl_class.rs` is as before this package). In its place, row
`TypeView/Typedef` is now `in` under rule 9:

- A typedef **carries an alignment** when any of its declarations has
  an `ALIGNED` node or a `cold.alignment` entry: Kiln's test
  (`max_align_attr` reads every redeclaration).
- The walk (`aligned_typedefs`, `crates/slip_digest/src/types.rs`)
  follows `type_info`: a typedef's underlying type; the base of a
  cv-qualified array and of an `ExtQual`; the element of any array and
  of a complex type; the value of an atomic type; the referee of a
  reference; otherwise one step of `Ast::layout_desugar_once`. It
  stops at a canonical type.
- If it meets any typedef carrying an alignment, the type digest is
  the tag `Typedef`, the list of those typedefs as `ref*` (walk order),
  then the canonical type's digest. Otherwise the digest is the
  canonical one, as before: every other typedef stays transparent.
- Past 4096 steps it writes an empty list and the cause
  `Unsupported("TypeView/Typedef-aligned-bound")`.
- The typedef's own unit holds its alignment attribute, so a change of
  the value changes only that unit (`differ/_/typedef-alignment-value`).
  A user holds a reference to the typedef, as a field of class type
  holds its class.

What is written, by the sugar the typedef is reached through:

| Reached through | Written | clang 19 `alignof` | Kiln | Test |
|---|---|---|---|---|
| a field `I i` / `int i` | `I` | 8 / 4 | 8 | `differ/_/typedef-alignment-field`, `sizeof-class` |
| a variable; `alignof(I)` | `I` | 8 | 8 | `differ/_/variable-typedef-alignment`, `alignof-typedef-alignment` |
| a parameter | `I` | | | `-parameter` (`changed f(int)`) |
| a return type | nothing: the function type is canonical | | | `equal/_/typedef-alignment-return-type` (see below) |
| `new I` | `I` | | | `-new` |
| `alignof(I[4])`, `L a[2]`, `L a[]`, `T<N>` with `L a[N]` | the element's typedef | `L[4]`: 4 | 4 | `-alignof-array`, `-array`, `-flexible-array`, `-dependent-array` |
| `const L` array typedef, `const LA` with `typedef L LA[2]` | both typedefs met | | | `-const-array`, `-qualified-array-typedef` |

Notes:

- Inside a template the argument is canonical: `alignof(T)` in `Z<I>`
  is 4 in clang 19, so writing nothing there is right.
- The alias template row is where clang 19 and Kiln part: Kiln keeps
  the argument's sugar (clang 22's behaviour). The digest follows Kiln,
  and writes more than clang 19 reads: a false difference at worst.
- `_Complex F` with a typedef `F` is a parse error, and `aligned(0)` is
  an error, so the complex step and a zero alignment have no test.
- The return type pair is equal: the function's type is not walked
  (Kiln reads no alignment from a function type), so it is written
  canonically. A parameter differs because the parameter's own
  declared type is written, and its key `f(int)` does not change.

**I to K with the same alignment.** Decision: **differ**. The written
fact is the typedef's entity, not its alignment value, so a rule can
map a rename (`differ/TypeView/Typedef.decl`). Writing only the value
would make a typedef that later changes alignment invisible to its
users. They hold `Ref(I)`, so the change shows in `I`'s unit.

**Aligned typedef to the plain type.** Differs (`differ/TypeView/Typedef`,
`-field`).

**False differences.** Writing more is never a wrong equal: the
canonical digest is still written, so two types equal under rule 9 are
equal canonically too, and list the same typedefs. The costs:

- a type naming an aligned typedef where layout does not read the
  alignment (a parameter, a template profile): its digest differs from
  the `int` spelling. Template profiles (dependent bounds, NTTP
  arguments, template bodies) write operand types with sugar, so a
  template whose signature names such a typedef in an expression gets
  a different key from the `int` spelling (seen as removed/added, a
  false difference);
- more than one typedef listed where the outermost decides.

**Where the walk has only the canonical type.** The substituted field
type of an instantiation, a deduced type and an expression's type.
Substituted class, function and variable template arguments are
canonical in Kiln and in clang, so neither reads a typedef there.
Deduced types and `decltype` keep the typedef in both, and the walk sees
it. Expressions are written through `write_type` with their sugar. The
other `canonical(` uses in `slip_digest` (`names.rs`, `local.rs`,
`keys.rs`, `query.rs`, the NTTP placeholder check) are analyses, not
type writes. No place was found where Kiln reads an alignment the walk
cannot see, so no fail-closed cause is kept.

**Goldens.** None changed: the full `slip_digest` suite after the
change moved only the 10 former indeterminate tests (now pairs). No
golden source (`tests/golden/`) or other pair names a typedef carrying
an alignment, and rule 9 changes only digests of types whose sugar
meets one. `tables.rs` changed only in the row's decision (blessed). The row
was `out`, so its test was `equal/TypeView/Typedef` (a plain typedef
is transparent); an `in` row's test is a differ pair, so that test
moved unchanged to `equal/_/typedef-without-alignment`.

**Scheme.** WP-113 moves the digest scheme from 1 to 2 and merges
first. This row is added under scheme 2 with no further bump: no
release is made between the two, so no stored digest of scheme 2
predates it.

## For Kiln

Two defects, both against clang 19, found while writing rule 9:

- `alignof(L&)` with `typedef long L __attribute__((aligned(4)))` is 8
  in Kiln, 4 in clang ([expr.alignof]/3: the referee's alignment).
  `decl_align` and `type_info` read the canonical referee, dropping its
  sugar. The digest writes the referee's typedef, one fact more than
  Kiln reads (`differ/_/typedef-alignment-reference`).
- `typedef int R __attribute__((aligned(8))); typedef int R;`:
  `alignof(R)` is 4 in Kiln and 8 in clang, while Kiln's class layout
  reads 8 (`max_align_attr` reads every redeclaration).
  `Ast::layout_attributed_typedef` (`kiln_ast/src/layout_sugar.rs:58`)
  checks `HAS_ATTRS` only on the declaration the sugar node names. The
  digest follows the layout (any redeclaration).

And two observations:

- `ensure_vtable` has no caller outside `kiln_abi`, so `Ast::vtables`
  stays empty under `-fsyntax-only`.
- An `ms_struct` on a redeclaration after the definition is in
  `attr_allowed_after_def`'s list (`kiln_sema/src/after_def.rs:153`)
  and `Ast::is_ms_struct` reads every redeclaration, yet the layout
  does not change. The digest is equal either way, so this is only a
  question of where Kiln drops it.
