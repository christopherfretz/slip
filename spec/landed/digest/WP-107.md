# WP-107 — the tables Kiln computes for classes

`spec/digest-kinds.md` §11.7 says record layouts, the subobject graphs
and final overriders, vtable layouts and the comparison categories are
not written, because each is a function of units that are compared.
This file records:

- the constructs that make Kiln fill each table, and their tests;
- per row, the units and command-line facts the value follows from;
- item 1: every attempt to change a table while all units stay equal;
- item 2: where values computed from a table are written;
- item 3: two definitions of `std::strong_ordering`;
- the cause added for the one wrong equal found, and the mutations.

Kiln citations are at the pin of `slip/kiln`. The tests are generated by
`crates/slip_digest/tests/gen/class_tables.py`. The walk reads none of
the four tables: `layouts`, `virtuals`, `vtables` and `cmp_categories`
appear in `crates/slip_digest/src` only in `tables.rs`. So a unit's
digest is the same whether or not a table was computed before the walk.

## What fills each table

`demand` tests (§1.5) are under `tests/demand/<short>/<row>/` and
`tests/demand/_/<construct>/`. Each was checked with a probe: side A
holds no entry for the table, side B holds one, and only `added y()`
(plus implicit members of the used class) differs.

Filled only by `kiln_abi::ensure_vtable` (`kiln_abi/src/vtable/mod.rs:151`).

## What each value follows from

| Table | Units | Command-line facts |
|---|---|---|
| `RecordLayout` | the class (its fields, bases, attributes on every redeclaration, including `packed`, `ms_struct`, `aligned`, `alignas`, and `ColdDeclData` `record_pack`); its bases' units; its fields' types' units (and their layouts); the units of constants in bit-field widths and alignments; for an instantiation, the pattern's `record_pack` | the target (x86_64 or aarch64 Linux: the only ones Kiln accepts). `-fpack-struct` and `-mms-bitfields` are refused by Kiln's driver. |
| `ClassVirtuals`, `Subobject` | the class and its bases' units (base list, virtual-ness), the virtual function units (`virtual`, `override`, `final`, declarations) | none |
| `VTableLayout` and its parts | as `ClassVirtuals`, plus key function placement (`<key_function>` derived unit), covariant return types (the overriding function's unit) and the layout | the target |
| `CmpCategoryInfo` | `std::partial_ordering`, `std::weak_ordering`, `std::strong_ordering`: the class, its data member, its static value members and their `<value>` units | none |

Where the layout reads a typedef's own alignment, the class unit does
not hold the fact. That is the wrong equal of item 1, and the class is
made indeterminate.

### The wrong equal and its cause

Kiln's layout reads a `Typedef` sugar node's alignment
(`kiln_abi/src/layout/mod.rs:443`, `max_align_attr` at
`kiln_abi/src/layout/props.rs:78`). It finds the node through
`layout_desugar_once` and array element types
(`Ast::layout_attributed_typedef`, `kiln_ast/src/layout_sugar.rs:58`).
The type digest is canonical (digest-kinds §4.1, §4.2), so the typedef
is lost.

Cause `Unsupported("layout/typedef-alignment")` (`TYPEDEF_ALIGNMENT`,
`crates/slip_digest/src/decl_class.rs`) is set in `members()`, where
the walk writes the class. It is set when the layout of the class reads
such a typedef:

- through the type of any field (all `Field` members, so an
  instantiation's derived fields count);
- or through an `alignas(type-id)` on any declaration of the class or
  of a field.

The walk follows Kiln's: cv-qualified array to its base, array to its
element, otherwise `layout_desugar_once`. It stops at a canonical type
and answers yes past 4096 steps. A typedef "carries alignment" when any
of its declarations has an `ALIGNED` node or a `cold.alignment` entry,
as Kiln's test does.

Outside classes, the wrong equal stays as two pending tests: `alignof`
of the typedef and a variable of it.

Proposed row change: digest-kinds §4.1/§4.2 should write a `Typedef`
sugar node whose declaration carries an alignment in the type digest
(`TypeView/Typedef`): its alignment, or the typedef's identity. Then
the cause can be removed and the two pending tests pass.

## Item 2: values computed from a table

The pairs change `#pragma pack` on `S` (or a class's fields), with
users around it.

| User | Units that differ | Test |
|---|---|---|
| `sizeof(S)` in a function | only `S`: the function holds `sizeof(S)`, and the class decides it | `differ/_/layout-sizeof-in-function` |
| `constexpr n = sizeof(S)`; `int arr[sizeof(S)]` | `S`, `arr`, `n::<value>` | `differ/_/layout-sizeof-in-constant` |
| `constexpr S s{1, 2}` | `S`, `s::<value>` | `differ/_/layout-constant-object` |
| `offsetof(S, i)` | `S`, `f()` (`OffsetOfExpr.b` is written) | `differ/_/layout-offsetof` |
| `&S::i` used through `.*` | only `S`: a member pointer is its member and path | `differ/_/layout-member-pointer` |
| base-to-derived and derived-to-base conversions | only the changed class: the base path is written, no offset | `differ/_/layout-base-conversion` |
| `dynamic_cast` | only the changed class | `differ/_/layout-dynamic-cast` |
| a virtual call, after swapping the order of virtuals | `A`, `A::<key_function>`: no vtable index is stored in the call | `differ/_/vtable-virtual-call` |

Each user either has the value written (constants, `offsetof`) or holds
only what the class units decide. None of it depends on whether the
table was computed before the walk.

## For Kiln

No defect found. Two observations only:

- `ensure_vtable` has no caller outside `kiln_abi`, so `Ast::vtables`
  stays empty under `-fsyntax-only`.
- An `ms_struct` on a redeclaration after the definition is in
  `attr_allowed_after_def`'s list (`kiln_sema/src/after_def.rs:153`)
  and `Ast::is_ms_struct` reads every redeclaration, yet the layout
  does not change. The digest is equal either way, so this is only a
  question of where Kiln drops it.
