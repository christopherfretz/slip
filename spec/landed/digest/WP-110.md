# WP-110 — rules rename owned entities only: ownership in the walk's keys

`spec/verify.md` §2.1 "Rules rename owned entities only" and
`spec/digest.md` §3.4 "Ownership", built: the container carries the
run's files (`Declared` version 2), the walk is given which files are
read-only (`Options::read_only`), decides once per entity whether it is
owned, and applies rule 1 and rule 2 at every site that maps a key.

## The container (item 1)

`DECL` version 2 (`spec/verify.md` §2): `Declared` gains `kept`
(ascending `KeyId`s, carried only; its meaning is WP-111) and `files`
(`Option<Ownership>`). `rules_id` is `rules.id()` without `files` (so a
version 1 file and a version 2 file with no rule have the id they had)
and `tagged_digest("slip.rules.v2", rules, owned, readonly)` with them.
The reader's checks are the rows "The reader's checks" of §2, each with
a test in `crates/slip_model/tests/declared.rs`:

| Row | Refused | Test |
|---|---|---|
| 1 | rules not ascending, two rules with one match, a bad name | `rejects_rules_unsorted`, `rejects_two_rules_with_one_match`, `rejects_bad_names_in_a_file` |
| 2 | `changed`, `created`, `removed` not strictly ascending | `rejects_each_list_unsorted_or_duplicated` |
| 3 | `kept` not strictly ascending | `rejects_kept_unsorted_or_duplicated` |
| 4 | an `Ownership` that is not canonical (owned empty; a path not canonical and absolute; a list not strictly ascending; an entry in both) | `rejects_each_bad_ownership` (8 rows) |
| 5 | a version 1 container with a rule | `rejects_version_1_with_a_rule` |
| 6 | rules and no `files`; `files` and no rule | `rejects_files_absent_with_rules_and_present_without` |

Versions 0 and 3: `rejects_wrong_version`. `rules_id` covers `files`:
`rules_id_covers_files`.
`dump` and `undump` keep the version of the file they read
(`version_1_without_a_rule_is_read`, `ignorable_section_kept_by_dump`).
The goldens `tests/golden/declared.{bin,json}` are version 2 with `kept`
and `files`.

**Decision (the spec was silent):** `files` is present exactly when
`rules` is not empty (row 6). With no rule ownership is never
read, so a `files` there is a container that says something nothing
checks; with rules and no `files` the walk would have to guess. An
in-memory `Declared` may hold rules and no files (a builder's state);
`validate` refuses it.

## Ownership of a file (item 2)

`slip_digest::ReadOnly<'a>`, the one new field of `Options`, beside
`rules`. A `Copy + Sync` value (a worker shares one `Options` across its
threads) with four forms: `EVERY_FILE` (the map phase, and any caller
without a run's files: every key is the key of the empty table),
`NO_FILE` (WP-103's behaviour, for tests), `files(&ReadOnlyFiles)` (the
verify job's), and `new(&dyn Fn(FileId) -> bool + Sync)` (a test's).
Why a value and not `&dyn Fn` alone: `Options` must stay `Sync`, and
the verify job's answer is a table it computes once per image.

`ReadOnlyFiles::new(files: Option<&Ownership>, sm, subject_path)`
decides every buffer of the source manager once: read-only unless
`files` is given, `subject_path(f)` (the job's `Input::subject_path`:
empty for a buffer that is no file) is not empty, and
`Ownership::is_owned(path)`. A buffer made after `new` is read-only.
Unit tests: `owned.rs` `read_only_files_maps_through_the_subject_path`
(seven buffers under a root map of the test's own, `/post/...` for
`/subject/...`: owned, read-only by the longest entry, `<built-in>`, a
path outside every entry, a relative path, a path that shares a prefix
but not a component) and `the_two_constants_and_a_predicate`.

## Ownership of an entity (item 3)

`Walk::owned(d)` (`crates/slip_digest/src/owned.rs`), memoised per
entity (`Walk::entity`), decided by `decide_owned`:

1. every declaration of the chain (`Walk::chain`, the one `units.rs`
   walks) is in an owned file; a chain longer than `REDECL_LIMIT` is a
   dependency entity (an unread declaration might be read-only);
2. a specialisation or partial specialisation (`templ_link` of the
   representative, as `compute_key` reads its template) of a dependency
   template is a dependency entity; so is an implicit deduction guide (a
   `CXXDeductionGuide` flagged `IMPLICIT`, or the function template whose
   pattern it is) of one;
3. an `IMPLICIT` declaration whose context is a record is a dependency
   entity if the record is.

`in_owned_file(d)`: `sm.expansion_loc(loc)` (Kiln's walk to the
outermost invocation; `crates/slip_kiln/src/ranges.rs` is not on this
branch's `main`, so the source manager is read directly); scratch space,
no file offset, or a buffer whose name begins with `<` is read-only;
else the cached `ReadOnly` answer per `FileId`. A cycle (an entity asked
while it is being decided) answers "dependency entity" and nothing
decided while one is met is memoised.

`Walk::owned` debug-asserts that the table is not empty; nothing calls
it otherwise (`rule_applies` and `namespace_parent` return first).

## The mapping (item 4): the sites

Every key the walk writes is computed by `Walk::key_in(d, view)`
(`keys.rs`): `compute_key_in` builds the key bottom-up, and
`map_key(d, view, key)` applies the table if and only if
`rule_applies(d, view)`. `view` is `None` for an entity's own key and
`Some(b)` for a namespace keyed in a member's view (rule 2). The sites:

| Site | What it maps | Path |
|---|---|---|
| `Walk::key` → `key_in(d, None)` | an entity's own key, memoised in `Walk::keys`; every reference in every stream (`refs.rs` `write_key`, `write_sym`, `local.rs`, `units.rs` 562, 637) goes through it | `map_key(e, None, …)` |
| `key_in(ns, Some(b))` | a namespace in the view of a member of the other ownership, memoised in `owned_state.views` | `map_key(ns, Some(b), …)` |
| `parent_in`, both namespace arms (`to_namespace` and the main match) | a member's namespace parent | `namespace_parent(ns, member, view)`: `key(ns)` when the view equals the namespace's own ownership, else `key_in(ns, Some(view))`; `unit_parent` under no rule |
| `parent_in`, every other arm | a class, function or specialisation parent | `key(x)`: its own key (rule 2) |
| `Walk::key_bytes` | the key bytes of a written unit | `map_key(e, None, …)` |
| `mapped_name` (WP-103) | a specialisation's template name | `map_key(e, None, …)`, so a dependency template's specialisation keeps its plain name |
| `follow_patterns` (`RULE_ON_INSTANTIATED_MEMBER`) | a rule on an instantiated member | checked only when `rule_applies(e, None)` |
| `spec_key` | a specialisation's arguments | `write_args` → `key` of each argument: by the argument's own ownership |
| `units.rs` `fallback_key` | a content-keyed unit | `map_key(e, None, …)` |
| `records.rs` `key_again` | the records' recomputation of each unit's key | `map_key(e, None, …)` |

Three `rules.map` calls remain, and none is an entity's: the order unit
(`units.rs` `order_unit`, `records.rs` 111: a constant key that no rule
can match) and the part keys of `demand.rs` (`write_part` 193,
`part_key` 250 and 259): a `resolved` or `default_argument` unit's key
has its entity's mapped key as its parent, and a rule of either kind is
refused (`Rule::refusal`), so `rules.map` there is the identity on
every table the walk keys under. `spec/verify.md` §2.1 now says so.

`records::key_agreement(input, rules, read_only)` is the property of
item 4: it digests, collects the memo `Walk::keys`, checks that every
`views` entry is of the view opposite the namespace's own (otherwise the
namespace has two keys under one view), then recomputes every key in a
fresh walk in reverse order and compares. Run on every case of
`tests/rules/` under each of its ownerships, and under `EVERY_FILE`.

## The tests

`crates/slip_digest/tests/rules.rs`: a case with `readonly.txt` (file
names of the case, read-only; the rest of `/case` owned, through
`ReadOnlyFiles` and an `Ownership` in subject paths) is judged twice:
by `expect.txt` with those files read-only, and by `expect-owned.txt`
with every file owned (WP-103's behaviour). A case without `readonly.txt`
is judged by `expect.txt` with every file owned. On every case: the
digest twice (determinism), `records`, `key_agreement`, the rule uses,
and the property: with every file read-only the digests and causes are
those under no rule.

With every file owned every case of WP-103 is what it was: **167 cases
compared** (10 more are pending, `needs-wp113/*` and one in
`attempts/`), all equal to their `expect.txt`, unchanged.

### Reported, not decided

**Two observers (`observer-includes-both` / `observer-includes-owned-only`).**
The same edit (move `Both`, which `dep.h` also declares, from `legacy`
to `acme`) is a collision in the observer that includes `dep.h` and
**verified** in the one that does not: there `Both` has no read-only
declaration and is owned. The edit is wrong (the dependency still
declares `legacy::Both`). A run that holds both observers does not
verify (the first is indeterminate). A run in which no observer
includes `dep.h` verifies it: the wrong `verified` that
`spec/verify.md` §2.1 already names ("if no observer includes both,
nothing shows it", §8). Ownership cannot be decided from what a
translation unit does not see; closing it needs the run to know which
entities read-only files declare, independent of the observers (an
index of the dependency's headers, WP-111's question).

No other case gives a wrong `verified` under ownership, and none refuses
a correct edit that cannot be declared: the two refusals of a correct
edit (`owned-definitions-kept`, `dependency-opens-destination`) are
under every file owned, and ownership removes them; `removed legacy` is
a namespace unit, which `removed` declares.

## Nothing moves with `rules` empty

`rule_applies` returns `false` before it asks for ownership, so
`map_key` is the key unchanged, which is what `rules.map` is under the
empty table; `namespace_parent` is `unit_parent`, the old `parent_of`;
`follow_patterns` and `mapped_name` return before reading ownership; the
`views` memo is never written. `Options::read_only` is therefore not
read. The map phase (`slip_cli/src/worker.rs`) passes `EVERY_FILE`. The
digest goldens and every `tests/` suite of `slip_digest` other than
`rules.rs` are unchanged and pass, and the property above checks, on
every case, that a non-empty table with every file read-only gives the
digests of the empty table.

## What the verify job and `slip declare` must do

- The verify job (WP-052 / WP-056): for each image under a non-empty
  table, `ReadOnlyFiles::new(declared.files(), input.sm,
  &input.subject_path)` and `Options { rules, read_only:
  ReadOnly::files(&f), .. }`; the post-image's files map back to subject
  paths through its roots (§5.1). Its header's `rules` is
  `declared.rules_id()`.
- `slip declare` (WP-111): give `files` (`Declared::with_files`, from the
  run's `Ownership`) whenever it writes a rule, and the `kept` line
  (`Declared::with_kept`); pass the same `ReadOnly` to `records` for the
  post-images, so that the `created`/`kept` lines resolve under the keys
  the job will compute; refuse a `relocate` line whose entity is a
  dependency entity and not a namespace (`DependencyEntity`).
- The pitfall runner (WP-056): give each `declared.txt` its files, `dep/`
  read-only; the row `n34-dependency-namespace-macro` then meets its
  `bad` and `bad-3` lines (its comments say so).
