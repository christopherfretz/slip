# WP-115 — name-derived values: a shared string per holder, `__impl` objects per holder

What `crates/slip_digest` does for digest §9 beyond
`spec/landed/digest/WP-104.md`, which this file's "Known costs" replace.
Kiln references are at the pinned Kiln (`kiln/` in the checkout).

## Item 1: a shared `__builtin_FUNCTION()` string (G2)

Kiln makes one source-location string per content
(`kiln_sema/src/builtins.rs` `srcloc_string`, `frozen_string`): the
`"get"` of `a::get()` and of `b::get()` is one object, and a pointer to
it says nothing of which use made it. `value.rs` `name_string` (fix
round: `sourced`) now writes such a string (the `uv 2` form of `PtrBase`
`StringLit`) as `(role, ref ctx)` and the names around `ctx`, as before,
only where **every use of the object in the translation unit** is of one
role (plain or pretty) and of one entity (`Walk::entity` of its
context), and that entity's name of the role is the bytes; otherwise
(the uses in several entities, a file name, no use at all) **the bytes**
are written. "One entity" is exactly `Walk::entity`: a function and its
redeclarations, a template's pattern with the template; a lambda's call
operator or a member of a local class of `X` is **not** `X` (it is
another function, and its name is not `X`'s). A default argument
evaluated at a call is the caller's use (Kiln records it with the
caller's context, `note_default_arg_use`). The result is memoised per
string (`NameValues.sourced`), the same in every stream.

**What equal means for a name string** (the coordinator's ruling, §9):
two are equal when their bytes are equal, or when their bytes differ
exactly as a rule says the name of one certain entity changed. The
symbolic form is the permission to follow a rename, written only where
the string is certainly that entity's. It is certain here because a
pointer to a source-location string object can only have been made by a
use Kiln recorded (`srcloc_string` is called from `record_source_loc` and
the deduced-return refresh) and every such use is in that entity; the
exception is the C++26 named hole below.

**The holder's own use is no longer a rule.** WP-115's first round wrote
the string as the holder's own use where it had one. That was a guess
when the object also had uses elsewhere, with a behavioural wrong equal:
`differ/_/name-value-shared-bytes-rename-holder` (rule renaming the
holder `f(long)` to `q(long)`; side A's `p` is `f(int)`'s `"f"`, side
B's `h::q()`'s `"q"`; the own rule wrote both as the holder, though a
right rename keeps `"f"`). It passes now: the bytes differ. No narrower
case where the guess is certain can be proved from what Kiln records
(a pointer does not carry its use); the use kept with the pointer
("For Kiln") closes the costs below.

**Why two holders that pass different functions' names differ.** A
string is written as `(role, X)` only where the bytes are Kiln's name of
that role for `X` and `X` is the only entity with a use, so two strings
written alike hold the names of one entity, mapped by the rules: their
bytes differ by what the rules change of that name, nothing else. Bytes
written as bytes are equal only when they are equal: the program passes
on what it did. Pairs: `differ/_/name-value-plain-not-holder` (`G`
passing `ga()`'s or `gb()`'s name), `differ/_/name-value-pretty-not-holder-same-plain`
(`x::n()` and `y::n()` share the plain `"n"` but not their pretty
names), `differ/_/name-value-holder-unique-several-entities` (several
entities: the bytes, not the first entity, so a rename that makes the
two sides pass different functions' names differs),
`equal/_/name-value-holder-unique-entity` (one entity, relocated),
`differ/_/name-value-shared-bytes-rename-holder` (above),
`equal/_/name-value-file-name-like-function` (a file named `get` shares
its name's object with `get()`'s plain name: a file-name use, so the
bytes, equal under a rename of `get()`). Under (a) the
two pairs that were named holes are right equals, both sides passing
the same bytes: `differ/_/name-value-bytes-equal-shared-origin` (was
`-holder-shared-origin`) and `-bytes-equal-shared-plain-rename` (was
`-shared-plain-bytes-rename`), each now seeing only the units whose
bodies changed.

**The costs.** A function of the same name gaining or losing a use of
the string moves every holder of it between the entity's form and the
bytes; a string used in two entities is written by bytes, which a
relocation or a rename of a pretty or plain name changes. Five pairs,
pending `# needs: kiln-srcloc-origin`: four that the first round's own
rule made pass (three equal pairs, one differ pair whose expectation is
that only the added units are seen) and the namespace-scope lambdas:

- `equal/_/name-value-cost-overload-plain-rename` (`"f"` in `f(int)` and
  `f(long)`, a rename of `f(int)`),
- `equal/_/name-value-plain-default-argument-holder` (`"h"` in `x::h()`
  and, through a default argument, `h()`; a rename of `h()`),
- `equal/_/name-value-holder-own-lambda` (two lambdas of `f()` print one
  pretty name; a relocation),
- `equal/_/name-value-cost-namespace-lambdas-shared-pretty` (the same at
  namespace scope),
- `differ/_/name-value-cost-plain-added-earlier` (side B adds `a::get()`,
  so `b::get()`'s `"get"` goes to its bytes: `b::get()` is seen).

## Item 2: `__impl` objects numbered per holder (G3)

An `__impl` object is identified (`value.rs` `write_location`) by where
its use is numbered and its ordinal there. A use whose context is a
function is numbered among that function's uses (as before). A use
whose context is no function is numbered among the uses held by **the
declaration that holds it**, found by walking, in declaration order,
the expressions of every variable's and field's initializer and every
parameter's default argument (`value.rs` `holders`): the variable, the
field, or the function whose parameter it is, as its first
declaration. Its encoding: `Ref::none`, `count 0` (the old prefix, so
no function's form is met), the holder (`ref?`) with the names of the
named local types around it, the ordinal, the file. A use no such
expression holds (an enumerator, an array bound, a template argument)
is `ref? none`, `count 0`, numbered among every such use of the
translation unit, the old cost, kept where Kiln gives no holder.

The holder of each kind of use, with its pairs (`-added`: a use added to
another holder, only that one changes; `-swapped`: `G` passing the
holder's first or second use, chosen by `__builtin_LINE()`, differs):

| Use | Holder | Pairs |
|---|---|---|
| `current()`'s default argument in a namespace-scope initializer | the variable | `differ/_/name-value-holder-default-argument-added`, `-swapped` |
| a default member initializer used by an aggregate initialization in a namespace-scope initializer | the variable (in a constructor or a function: that function) | `differ/_/name-value-holder-member-init-added`, `-swapped` |
| a default member initializer's own use (at the field) | the field | unit test `wp115_impl_objects_by_holder` |
| a variable template's initializer | the specialisation (its own instantiated initializer) | `differ/_/name-value-holder-variable-template-added`, `-swapped` |
| a lambda at namespace scope (an init capture) | the variable whose initializer holds the lambda (its body is a function) | `differ/_/name-value-holder-lambda-added`, `-swapped` |
| a default argument's own use | the function | unit test |

`differ/_/name-value-holder-which-holder`: the first uses of two holders
have one ordinal; `G` passing one or the other differs by the holder.
`differ/_/name-value-cost-global-loc-added-before` lost its pending
mark.

**Why no wrong equal.** Every use of a group that builds an `__impl`
object is counted, in `ExprId` order (fix round, F1: the first round
counted objects, and Kiln shares one object between uses of one file,
function, line and column, so two uses in one macro invocation shifted
every later use's ordinal; layout is dropped, so a selection by
`line()`/`column()` could return another use under the same ordinal:
`differ/_/name-value-impl-shared-object-shift-namespace`, `-function`,
control `-control`). An object is written as the (group, ordinal) of its
first use (`equal/_/name-value-impl-shared-object-first-use`: the shared
object of side A and side B's own object of that use are equal). Within a group ordinals are distinct; groups are told apart
by their entity, by the `Ref::none` prefix between a function's group
and a holder's, and by `ref? none` for the uses no declaration holds.
So an object is written alike on two sides only where its first use is
the same use (the same ordinal of the same, mapped, group); its line and
column are left out by §9 as before. Sharing changes only which object
a later use gets, never another object's ordinal: where it differs
between the sides (one layout puts two uses in one macro invocation),
the value differs, a cost, never an equal.

## Item 4: an `__impl` object's file

`write_location`'s `opt(false)` is never written for an object a use
built: `record_source_loc` (`kiln_sema/src/builtins.rs`) returns before
recording anything when `srcloc_string` of the file fails, the object's
`_M_file_name` is that pointer, and `finish_source_locs` keeps it.
Objects Kiln makes without a use (`meta_source_location`, reflection)
are not in the map and are written by content. Unit test
`wp115_every_impl_object_has_its_file` (namespace scope, a default
member initializer, a deduced return type, a default argument, a
variable template).

## Item 5: the re-check of WP-104's second fix round

- **H1 (repaired).** A pretty identity (`__PRETTY_FUNCTION__`, a
  source-location pretty name, a function's `__impl` object) also
  writes `local::write_signature_names`: the named local types and the
  block-scope aliases the function's signature mentions (the pattern's
  parameter types and return type walked with their sugar, an alias's
  underlying type and the canonical type too, the function's template
  arguments), `count` then names, met first first. It may name more than
  is printed, never less. Pairs: `differ/_/name-value-signature-local-enum`,
  `-local-alias`, `-local-enum-source-location`,
  `-local-enum-function-name` (each `changed G`,
  `derived-changed G::<value>`; `f()` itself is equal, a local type's
  name being no content of the function that declares it); controls
  `equal/_/name-value-signature-namespace-type` (a namespace-scope type,
  relocated) and `-local-enum-plain-control` (`__func__` prints no
  signature).
- **C1 (recorded, a cost).** Why: an immediate invocation in a default
  argument or default member initializer has no stored value (it is
  evaluated at each use); Kiln keeps the value of the uses without
  source-location values in `ColdExprData` `default_imm`, which only a
  `default_immediates` unit writes (§11.4). The operand of a
  `ConstantExpr` without a value is read by value (§9), so the decayed
  name string's bound is written and the enclosing function differs.
  Writing the operand symbolically when `default_imm` holds a value was
  tried and is **unsound** for exactly these owners: a lambda's call
  operator, a local class's member or field, a block-scope function
  declaration have no `default_immediates` unit, so the value would be
  in no stream (`differ/_/name-value-immediate-*-length` failed with it:
  a length read from the name equal under the relocation). The repair
  needs `default_imm` written in the stream that writes a local owner in
  place (a §11.4 question). Pairs pending `# needs: known-cost`:
  `equal/_/name-value-immediate-lambda-default-argument`,
  `-local-member-init`, `-block-function-default-argument`,
  `-local-member-default-argument`; their controls run:
  `differ/_/name-value-immediate-*-length`. clang-19 prints the
  enclosing function's name in all four (`void legacy::f()`), and Kiln
  agrees; at namespace scope the name is empty.
- **C2 (repaired).** A `PredefinedExpr`'s owner is searched at its
  location and then at the `#include` of each inclusion around it
  (`value.rs` `inclusion_chain`, Kiln's `SourceManager::include_loc`),
  innermost first: the functions whose extent holds the first location
  any extent holds are the innermost, and among them the shortest
  extent wins (extents of one inclusion nest; an inclusion's raw range
  lies outside its includer's). An extent whose ends are in two
  inclusions is not compared by raw location: where such a function has
  the string's name, the bytes are written. Pairs:
  `equal/_/name-value-body-from-include`, control
  `differ/_/name-value-body-from-include-length`;
  `equal/_/name-value-body-from-include-inner-first` (a local class's
  `f()` in the included file owns its `__func__`, not the `f()` around
  the `#include`), `equal/_/name-value-body-split-tie` (a body that ends
  in the included file: a tie, the bytes).
- **Two overloads of one macro invocation** share an extent: a
  `__func__` string either could hold is a tie and its bytes are
  written; a `__PRETTY_FUNCTION__` string only one holds is that one's.
  Unit test `wp115_overloads_of_one_macro_fall_back_to_the_bytes`.

## Named holes

- **Reflection and contract strings (C++26).** `frozen_string` is shared
  by the source-location strings and by reflection's and contracts'
  strings (`kiln_sema/src/meta/names.rs`, `meta/value.rs`,
  `meta/query/entity.rs`, `meta/recipe.rs`, `meta/ext.rs`, and
  `contracts.rs` through `srcloc_string`), one object per content, while
  `origins` lists only the source-location uses. A reflection string of
  the same bytes as a function's name, used only in that function, is
  written as that function's name, and a rule renaming it would make it
  equal to the renamed bytes: a wrong equal for the one-entity rule.
  Not reachable at C++20 and below (no reflection, no contracts).
  Whether the digest can see it and refuse: partly. A `CXXReflectExpr`
  is written as unsupported already, and `Ast::contract_sites` is
  visible, but a reflection can also be made by a metafunction
  (`std::meta::reflect_constant`) with no `^^` in the translation unit,
  and nothing Kiln records marks a string object as a reflection's. A refusal on "any `CXXReflectExpr` or contract site in
  the translation unit" is a few lines but not certain; not built.

## For Kiln

- A source-location string is one object per content (`srcloc_string`,
  `frozen_string`): a pointer to it does not say which use made it, so
  the digest writes the bytes wherever the object has uses in more than
  one entity (the five costs of item 1). Request: the use kept with the
  pointer (or one object per use). It also closes the C++26 hole if a
  reflection's and a contract's strings carry their maker the same way.
- `frozen_string` shares its objects between source-location strings
  and reflection/contract strings, and nothing marks which made an
  object: the named hole above.

The survivors:

- **M2i.** A pretty name also writes `write_signature_names`'s `count`
  (H1), so without the role a plain and a pretty name of one function
  still differ in length within the field; the role is kept so the form
  does not rest on what follows it.
- **The name test by length.** Every use of a source-location string
  holds Kiln's name of its own context (`record_source_loc` computes the
  bytes from `ctx`, `predefined_function_names`), so where every use is
  of one entity the test passes, and no test can hold another
  function's name. The exception is a pretty name not refreshed after a
  deduced return type (an immediate invocation in a default argument,
  `note_default_arg_use`): its bytes are the declared form of the same
  function's name, so the mutant writes that function where the code
  writes the bytes; a cost removed, never an equal of different names.
  The test stays as the guard against Kiln's names and the digest's
  parting.
- **A first file-name use not refused.** Each use records its context's
  plain name beside its file names (`record_source_loc`), so an object
  whose uses are all of one entity and whose bytes are that entity's
  name has a plain use too wherever it has a file-name use: the roles
  differ and the bytes are written either way.
- **No names around a holder.** A holder has local types around it only
  when it is inside a function (a local class's field, a local
  function's parameter), and the `__impl` objects of those holders' own
  uses are never a value: a default member initializer or default
  argument is evaluated at its use, which is a use of its own with the
  evaluating function's context. The names are written for when Kiln
  gives one.
- **No prefix before a holder.** A function's group writes
  `write_signature_names`' count after its names and a holder's does
  not, so the two do not meet in the tests; the prefix keeps the forms
  apart by their first item rather than by what follows.
