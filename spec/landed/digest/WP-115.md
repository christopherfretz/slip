# WP-115 — name-derived values: a shared string per holder, `__impl` objects per holder

What `crates/slip_digest` does for digest §9 beyond
`spec/landed/digest/WP-104.md`, which this file's "Known costs" replace.
Kiln references are at the pinned Kiln (`kiln/` in the checkout).

## Item 1: a shared `__builtin_FUNCTION()` string (G2)

Kiln makes one source-location string per content
(`kiln_sema/src/builtins.rs` `srcloc_string`, `frozen_string`): the
`"get"` of `a::get()` and of `b::get()` is one object, and a pointer to
it says nothing of which use made it. `value.rs` `name_string` now
writes such a string (the `uv 2` form of `PtrBase` `StringLit`) as:

1. **The holder's own use.** The holder is the unit whose stream is
   being written (`UnitLocals.holder`, as its entity). A use of the
   object is the holder's own when its context is the holder, or a local
   function written in the holder's stream (`local::unit_holding` is the
   holder: a lambda's call operator, a member of a local class, through
   the closure type or local class `local::unit_of` places). The
   first such use (`ExprId` order) whose context's name of the use's
   kind (plain or pretty) is the bytes is written, `(role, ref ctx)` and
   the names around it, as before.
2. **Not the holder's own name.** Where the holder has no such use (the
   string reached a unit that is not the function it names: a
   namespace-scope variable, through a call or a `constexpr` variable
   of another function), the string is written as the context of its
   uses only where **every** use of the object is of one role and one
   entity, and that entity's name is the bytes (it is then the only
   function the pointer can come from); where the uses are in several
   entities, **the bytes** are written. A template argument is a key
   and written by value anyway (`Walk::by_value`). A default argument
   evaluated at a call is the caller's use (Kiln records it with the
   caller's context, `note_default_arg_use`), so the caller holds it as
   its own (`equal/_/name-value-plain-default-argument-holder`).

The result is memoised per (string, holder) (`NameValues.sourced`); a
content digest has no holder and gets the second rule.

**Why two holders that pass different functions' names differ.** A
string is written as `(role, X)` only where the bytes are Kiln's name of
that role for `X`, so two strings written alike hold the names of one
entity, mapped by the rules: their bytes differ by what the rules
change of that name, nothing else. Where two functions' names have
different bytes, the strings differ by bytes or by entity (rule 2 writes
an entity only when it is the only one): `differ/_/name-value-plain-not-holder`
(`G` passing `ga()`'s or `gb()`'s name), `differ/_/name-value-pretty-not-holder-same-plain`
(`x::n()` and `y::n()` share the plain `"n"` but not their pretty
names). Where two functions share a plain name, one object holds it:
the program passes the same pointer either way and there is nothing to
tell apart; the bytes are written and a relocation, which changes no
plain name, keeps them. The residual cases, where a rule renames one of
two same-named functions and the value reaches the holder from the
other through another unit, are the named holes below.

A closure at namespace scope has no owner, so no unit holds its call
operator: two namespace-scope lambdas whose pretty names are one string
fall back to the bytes, a cost under a relocation
(`equal/_/name-value-cost-namespace-lambdas-shared-pretty`, pending
`# needs: known-cost`; the same in a function,
`equal/_/name-value-holder-own-lambda`, is equal).

Pairs: `equal/_/name-value-holder-unique-entity` (one entity, relocated),
`differ/_/name-value-holder-unique-several-entities` (several entities:
the bytes, not the first entity, so a rename that makes the two sides
pass different functions' names differs),
`differ/_/name-value-cost-plain-added-earlier` (was
`equal/_/…`, pending: side B adds a namespace and a function, which an
equal test does not allow; only those two are seen, `b::get()` is
equal), `equal/_/name-value-cost-overload-plain-rename`.

## Item 2: `__impl` objects numbered per holder (G3)

An `__impl` object is identified (`value.rs` `write_location`) by where
its use is numbered and its ordinal there. A use whose context is a
function is numbered among that function's uses (as before). A use
whose context is no function is numbered among the uses held by **the
declaration that holds it**, found by walking, in declaration order,
the expressions of every variable's and field's initializer and every
parameter's default argument (`value.rs` `holders`): the variable, the
field, or the function whose parameter it is, as its first
declaration. Its encoding: `Ref::none`, `count 0` (the old prefix, so
no function's form is met), the holder (`ref?`) with the names of the
named local types around it, the ordinal, the file. A use no such
expression holds (an enumerator, an array bound, a template argument)
is `ref? none`, `count 0`, numbered among every such use of the
translation unit, the old cost, kept where Kiln gives no holder.

The holder of each kind of use, with its pairs (`-added`: a use added to
another holder, only that one changes; `-swapped`: `G` passing the
holder's first or second use, chosen by `__builtin_LINE()`, differs):

| Use | Holder | Pairs |
|---|---|---|
| `current()`'s default argument in a namespace-scope initializer | the variable | `differ/_/name-value-holder-default-argument-added`, `-swapped` |
| a default member initializer used by an aggregate initialization in a namespace-scope initializer | the variable (in a constructor or a function: that function) | `differ/_/name-value-holder-member-init-added`, `-swapped` |
| a default member initializer's own use (at the field) | the field | unit test `wp115_impl_objects_by_holder` |
| a variable template's initializer | the specialisation (its own instantiated initializer) | `differ/_/name-value-holder-variable-template-added`, `-swapped` |
| a lambda at namespace scope (an init capture) | the variable whose initializer holds the lambda (its body is a function) | `differ/_/name-value-holder-lambda-added`, `-swapped` |
| a default argument's own use | the function | unit test |

`differ/_/name-value-holder-which-holder`: the first uses of two holders
have one ordinal; `G` passing one or the other differs by the holder.
`differ/_/name-value-cost-global-loc-added-before` lost its pending
mark.

**Why no wrong equal.** Each object is claimed by its first use and gets
one (group, ordinal); within a group ordinals are distinct, and groups
are told apart by their entity, by the `Ref::none` prefix between a
function's group and a holder's, and by `ref? none` for the uses no
declaration holds. So two objects of one program are never written
alike, and an object is written alike on two sides only as the same
ordinal of the same (mapped) holder; its line and column are left out
by §9 as before.

## Item 3: goldens and the scheme

No golden of the workspace holds a digest computed from source

a shared source-location string's entity (item 1), a non-function
`__impl` object's numbering (item 2), a pretty identity's signature

## Item 4: an `__impl` object's file

`write_location`'s `opt(false)` is never written for an object a use
built: `record_source_loc` (`kiln_sema/src/builtins.rs`) returns before
recording anything when `srcloc_string` of the file fails, the object's
`_M_file_name` is that pointer, and `finish_source_locs` keeps it.
Objects Kiln makes without a use (`meta_source_location`, reflection)
are not in the map and are written by content. Unit test
`wp115_every_impl_object_has_its_file` (namespace scope, a default
member initializer, a deduced return type, a default argument, a
variable template).

## Item 5: the re-check of WP-104's second fix round

- **H1 (repaired).** A pretty identity (`__PRETTY_FUNCTION__`, a
  source-location pretty name, a function's `__impl` object) also
  writes `local::write_signature_names`: the named local types and the
  block-scope aliases the function's signature mentions (the pattern's
  parameter types and return type walked with their sugar, an alias's
  underlying type and the canonical type too, the function's template
  arguments), `count` then names, met first first. It may name more than
  is printed, never less. Pairs: `differ/_/name-value-signature-local-enum`,
  `-local-alias`, `-local-enum-source-location`,
  `-local-enum-function-name` (each `changed G`,
  `derived-changed G::<value>`; `f()` itself is equal, a local type's
  name being no content of the function that declares it); controls
  `equal/_/name-value-signature-namespace-type` (a namespace-scope type,
  relocated) and `-local-enum-plain-control` (`__func__` prints no
  signature).
- **C1 (recorded, a cost).** Why: an immediate invocation in a default
  argument or default member initializer has no stored value (it is
  evaluated at each use); Kiln keeps the value of the uses without
  source-location values in `ColdExprData` `default_imm`, which only a
  `default_immediates` unit writes (§11.4). The operand of a
  `ConstantExpr` without a value is read by value (§9), so the decayed
  name string's bound is written and the enclosing function differs.
  Writing the operand symbolically when `default_imm` holds a value was
  tried and is **unsound** for exactly these owners: a lambda's call
  operator, a local class's member or field, a block-scope function
  declaration have no `default_immediates` unit, so the value would be
  in no stream (`differ/_/name-value-immediate-*-length` failed with it:
  a length read from the name equal under the relocation). The repair
  needs `default_imm` written in the stream that writes a local owner in
  place (a §11.4 question). Pairs pending `# needs: known-cost`:
  `equal/_/name-value-immediate-lambda-default-argument`,
  `-local-member-init`, `-block-function-default-argument`,
  `-local-member-default-argument`; their controls run:
  `differ/_/name-value-immediate-*-length`. clang-19 prints the
  enclosing function's name in all four (`void legacy::f()`), and Kiln
  agrees; at namespace scope the name is empty.
- **C2 (repaired).** A `PredefinedExpr`'s owner is searched at its
  location and then at the `#include` of each inclusion around it
  (`value.rs` `inclusion_chain`, Kiln's `SourceManager::include_loc`),
  innermost first: the functions whose extent holds the first location
  any extent holds are the innermost, and among them the shortest
  extent wins (extents of one inclusion nest; an inclusion's raw range
  lies outside its includer's). An extent whose ends are in two
  inclusions is not compared by raw location: where such a function has
  the string's name, the bytes are written. Pairs:
  `equal/_/name-value-body-from-include`, control
  `differ/_/name-value-body-from-include-length`;
  `equal/_/name-value-body-from-include-inner-first` (a local class's
  `f()` in the included file owns its `__func__`, not the `f()` around
  the `#include`), `equal/_/name-value-body-split-tie` (a body that ends
  in the included file: a tie, the bytes).
- **Two overloads of one macro invocation** share an extent: a
  `__func__` string either could hold is a tie and its bytes are
  written; a `__PRETTY_FUNCTION__` string only one holds is that one's.
  Unit test `wp115_overloads_of_one_macro_fall_back_to_the_bytes`.

## Named holes

Both need the value to reach the holder through another unit, which
differs: the same class as H1 was ("the owner differs"). Both close if
Kiln made one source-location string per use, or kept on a pointer the
use that made it ("For Kiln" below). Pending pairs, `# needs:
kiln-srcloc-origin`:

- `differ/_/name-value-holder-shared-origin`: `f(long)` has its own use
  of `"f"`, but `p` comes from `f(int)`; under `rename g(int) => f`
  side B's `p` is `h::f()`'s `"f"` and `f(long)` is written alike,
  though under the rule side A's `p` would be `"g"`.
- `differ/_/name-value-shared-plain-bytes-rename`: `G`'s `"get"` has uses
  in several functions on both sides, so its bytes are written; under a
  rename of `a::get()` side A's `G` would change, side B's does not.

Under a relocation no plain name changes, and a pretty name is shared
only by functions of one qualified name and signature, which one
relocation moves together: neither hole is reached by the motivating
use.

## For Kiln

- A source-location string is one object per content (`srcloc_string`):
  a pointer to it does not say which use made it. Smallest source:
  `differ/_/name-value-holder-shared-origin`. Request: one object per
  use (or per context), or the use recorded with the pointer.

The survivors:

- **M2i.** A pretty name now also writes `write_signature_names`'s
  `count` (H1), so without the role a plain and a pretty name of one
  function still differ in length within the field; the role is kept
  so the form does not rest on what follows it.
- **The same-length name.** Every use of a source-location string
  holds Kiln's name of its own context (`record_source_loc` computes
  the bytes from `ctx`, `predefined_function_names`), so the holder's
  own use always passes the name test, and a test cannot hold another
  function's name. The one exception is a pretty name not refreshed
  after a deduced return type (an immediate invocation in a default
  argument, `note_default_arg_use`): its bytes are the declared form
  of the same function's name, so the mutant writes that function
  where the code writes the bytes; a cost, never an equal of different
  names. The test stays as the guard against Kiln's names and the
  digest's parting.
- **`unit_holding` without its unit test.** A local function that is a
  unit itself (a generic lambda's specialisation, an implicit member of
  a local class) is written in its own stream, not its owner's; the
  mutant would count its use as the owner's own. Among the uses of one
  string, it can only choose between functions whose names are the
  bytes and that are local to one owner, which no rule maps apart; the
  code is the conservative reading of "written in the holder's stream".
- **The memo without the holder.** The entry it can find instead is the
  holder-less one (a content digest), which is the second rule's answer:
  the one entity or the bytes, the answer that is sound in every
  stream. So the mutant can only turn an own-rule answer into a cost.
- **No names around a holder.** A holder has local types around it only
  when it is inside a function (a local class's field, a local
  function's parameter), and the `__impl` objects of those holders' own
  uses are never a value: a default member initializer or default
  argument is evaluated at its use, which is a use of its own with the
  evaluating function's context. The names are written for when Kiln
  gives one.
- **No prefix before a holder.** A function's group writes
  `write_signature_names`' count after its names and a holder's does
  not, so the two do not meet in the tests; the prefix keeps the forms
  apart by their first item rather than by what follows.
