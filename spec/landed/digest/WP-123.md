# WP-123 — a written expression as a template argument; a numbering asked for late

What `crates/slip_digest` does for the two `unaccounted` causes the
LLVM corpus reached (`docs/wp/WP-123.md`): `ArgView/Expr` and
`local/late-numbering`. Kiln references are at the pinned Kiln (`kiln/`
in the checkout).

## How the cases were found

`crates/slip_digest/examples/digest_one.rs` (kept): digests one observer
of a plan (`SLIP_PLAN=<plan>`, `SLIP_ONLY=<substring of the main file>`)
at detail `all` with names, and prints the parse's status, the walk's
`digest.*` counters, and each indeterminate unit as `cause<TAB>name`
(`SLIP_CAUSE` narrows); with `SLIP_EXPR_ARGS=1`, also every canonical
type whose canonical arguments hold an expression without a profile. It
was run one observer at a time, `-j 1`, over the 132 observers of the
Demo 1 preview plan (2026-11-23, `llvm/lib/Support`) whose map shards
held either cause. A temporary trace, not committed, printed in the
`Expr` arm the expression's kind and dependence and where the walk was
(unit stream, type, key, profile), and in `local::numbering` the late
owner with a backtrace.

The 132 observers gave exactly the preview's counts: 2,792 units for
`ArgView/Expr` and 4 for `local/late-numbering`. No unit was
`ExcSpec/Deferred`.

## Item 1: `ArgView::Expr`

### What Kiln holds, and why it is `Expr` and not `Profile`

A canonical list holds `Expr { profile: None }` only where Kiln kept a
non-type argument as written and never converted it.
`canonical_arg` (`kiln_ast/src/types/args.rs:264`) turns an `Expr` with
a profile into `Profile`, so the walk, which reads only canonical lists,
never sees `Expr` with a profile. Kiln profiles an expression argument
in two cases:

- when the argument is value- or instantiation-dependent;
- when it is a non-dependent argument of a dependent specialisation
  (`profile_value_args`, `kiln_sema/src/templ/actions.rs:715`).

Every expression found was non-dependent (`IntegerLiteral`,
`CXXBoolLiteralExpr`, `DeclRefExpr`), and none is a constant Kiln also
holds as a value: nothing converted it, so there is no value.

### The forms

**A: the explicit template arguments of a dependent name in a
template's body.** Kiln keeps them in `TemplateTables` `expr_targs`. No
template is chosen until instantiation, so they are never converted.
The unit's stream writes them (`templ::expr_maps` → `Walk::write_args`),
outside any type, key or profile. In the preview: **2,496 units**.

```cpp
namespace n { constexpr int k = 0; }
template <int I, class T> int get(T);
template <class T> int f(T t) { return get<n::k>(t); }
```

Corpus cases:

- `std::__copy_move_a<true>(…)` in `std::move` and `std::move_backward`
  (`stl_algobase.h:683`, `:922`);
- `std::get<0>(t)` (`unique_ptr.h:191-197`, `functional`,
  `STLExtras.h`, `llvm::less_first`/`less_second`);
- `this->template resizeImpl<false>(N)` (`SmallVector.h:652`, `:655`);
- `std::atomic_is_lock_free<_Tp, __default_lock_policy>(__p)`
  (`shared_ptr_atomic.h:117`), a `DeclRefExpr` naming a namespace-scope
  constant;
- `__detail::__mod<…, __detail::_Shift<result_type, 32>::__value>(…)`
  (`random.tcc:3241`), a `DeclRefExpr` naming a static member through a
  qualifier.

Argument writes in the trace: `IntegerLiteral` 2,867,
`CXXBoolLiteralExpr` 518, `DeclRefExpr` 134. These count writes summed
over observers, not units.

**B: the arguments of a befriended specialisation in a class
template.** The canonical `TemplateSpecialization` keeps them unprofiled
(For Kiln 1). They are written inside the type's stream
(`type_nesting` 1). In the preview: **296 units**, the class unit and
its `::<friend …>` units:

- `std::__detail::_Hash_code_base`: `hashtable_policy.h:1314`,
  `friend struct _Local_iterator_base<…, false>;`;
- `llvm::DenseMapIterator`: `DenseMap.h:1238-1239`;
- `llvm::ilist_node_impl`: `ilist_node.h:86-93`.

All 199 argument writes were `CXXBoolLiteralExpr`.

```cpp
namespace n { constexpr int k = 0; }
template <class T, int I> struct It;
template <class T> struct M { friend struct It<T, n::k>; };
```

No argument was found in a key or inside a profile.

### What the row is now

`Expr` is `in`, `tag 6`, and is followed by the expression
(`digest-kinds.md` §4.6, the rule under the `ArgView` table).
`Expr.profile` is `bookkeeping`, `out`: it is always absent where the
walk reads. The expression names entities, so a transformation that
requalifies them is compared under the rules. The tag alone would have
made `get<n::k>` equal to `get<n::j>`.

**Form A: written in full.** It is the unit's own expression
(digest §7), walked by `expr::child`, as a declaration's own default
template argument already is (`templ::decl_maps`). The unit's reading of
the written list (`own_spelling::left_out_of_args`, which reads the
same expression with rule 1) is unchanged. The unit's stream is not
memoised across units, so nothing here depends on order. Numbering mode
walks it too, so a lambda in such an argument is numbered with its
owner.

**Form B: written by its canonical operand.** Inside a type, a key or
a profile the argument is written by its canonical operand
(`expr_dep::profile_expr`). These are the bytes `ArgView::Profile` would
have if Kiln had profiled the argument, and the form Kiln's own
profile gives such an argument (`args each`, `expr_profile.rs`). Inside
a profile it is walked in the profile's frame (`expr_profile::walk`),
so the frame's numbering of its own locals carries on.

Inside a type or a key, the unit's local state (`UnitLocals`: holder,
content, local types written, scopes, generic lambdas) is put aside
while the argument is written (`local::detached`). A type is memoised
per parse, so its stream must not read the unit that met it first:

- a rule-11 check answers as a stream with no holder does
  (`own_spelling::templated_at`: true, the conservative answer);
- a function name a program reads (`__func__`), which would print the
  names around the holder, is `Unsupported("ArgView/Expr-scope-names")`;
- a lambda-expression is `local/lambda-in-type`, as it is anywhere in a
  type;
- a local object of the unit still takes the unit's ordinal and raises
  `local_uses`, so the type is memoised for that unit only (digest
  §4.2).

The forms found read none of these. The detachment is a guard, not a
fix for any case found.

| `differ/ArgView/Expr.expr` | form A: `get<n::k>` against `get<n::j>`, the argument names another constant |

In the two `equal` pairs, rule 11 does not make the alias differ: it
reads a written qualifier into the unit's list only where the qualifier
can hold an instantiation-dependent operand, and a namespace's (or a
namespace alias's) cannot.

The lib test `a_written_argument_does_not_read_the_unit_that_met_it_first`
(`local.rs`) walks forms A and B and the item 2 source. It checks:

- every unit is written (no cause);
- the keys and digests are the same in unit order and in reverse;
- the befriended type's digest is the same when its first asker's
  holder is the class template and when it is a non-template function,
  each in a fresh walk.

`a_detached_stream_reads_no_holder` (`local.rs`) checks the guard
directly. With a non-template holder, inside `local::detached`:

- `templated_at` answers true;
- `write_scope_names` is cut under `ArgView/Expr-scope-names`;
- the holder is back afterwards.

### Verdicts that moved

Every unit of either form was indeterminate. It is now written, so each
such unit's verdict moves from indeterminate to equal or differ by its
content. No pair test's expectation changed: no earlier pair reached
the arm. `differ/_/spelling-args-dependent-member`
(`t.template m<sizeof(sizeof(f(t)))>()`) has a dependent argument, which
is `Profile`.

## Item 2: `local/late-numbering`

**One form, four units.** It is a range-`for` over a non-dependent
prvalue in a template's body. The instantiated body holds the pattern's
`MaterializeTemporaryExpr`, because it is not instantiation-dependent
(For Kiln 2). The temporary's `LifetimeExtendedTemporary` has
`LetData.extending` naming the pattern's `__range` variable. So the
specialisation's resolved unit `definition` writes `Ref::outer` to the
pattern's owner (`decl_func::let_data`). `number_all` had not numbered
that owner: it has no local type and no closure. The four units:

- `llvm::format_provider<llvm::iterator_range<const unsigned *>>::consumeOneOption(…)::<definition>`
  (`FormatProviders.h:376`, `for (const char *D : std::array<const char *, 3>{…})`);
- three `llvm::cl::sub::apply<Opt>(Opt &) const::<definition>`
  (`CommandLine.h:488`, `for (SubCommand *SC : Group->getSubCommands())`,
  an `ArrayRef` by value).

Reduced:

```cpp
struct R { int *b, *e; int *begin() const { return b; } int *end() const { return e; } };
R make();
template <class T> int g(T) { int s = 0; for (int x : make()) s += x; return s; }
template int g<int>(int);
```

**The collection.** `number_all` now also numbers the owner of the
variable each `LifetimeExtendedTemporary` extends, when that variable
is local and its owner is in a template (`local::in_template`: the
owner, or a declaration on its semantic context chain, is a template, a
pattern or a partial specialisation; a chain past the bound counts as
one). This is the WP-045 precedent (an expanded expansion statement's
variable) for another node Kiln shares. A temporary in a non-template,
or in a specialisation's own instantiated node, extends a variable of
its own unit, and no numbering is added for it, so
`the_common_case_numbers_nothing` holds as it was.

**Pairs.** `differ/_/inst-range-for-temporary`: the range's type
differs (`R` against `Q`, a `long` range). The pattern differs, and the
specialisation's `definition` moves with it (`exact derived`). Its
source joins `pair_sources()`, so `the_walk_declares_what_the_numbering_found`
(`late == 0`) walks it.

**Verdicts that moved.** The four units are no longer indeterminate.
No pair's expectation changed.

## Mutations

Each was applied, run against its narrowest tests, and undone.

| mutation | killed by |
|---|---|
| the arm writes the tag only (`expr` unused) | `differ/ArgView/Expr.expr`, `differ/_/argview-expr-friend`, `rules/kinds/argview-expr-renamed-no-rule`, `rules/kinds/argview-expr-friend-renamed-no-rule` |
| the expression written without its references (`written_arg` writes the expression's kind only) | the same four |
| the collection's new case removed (`number_all` skips the temporaries) | `local::tests::the_walk_declares_what_the_numbering_found` (`differ/_/inst-range-for-temporary`: `late` 1), `a_written_argument_does_not_read_the_unit_that_met_it_first` (a `local/late-numbering` unit) |
| `local::detached` does not put the state aside | `local::tests::a_detached_stream_reads_no_holder` only |

The last mutation survives every pair test and the order test: no
source found writes, inside a type, an unconverted argument whose walk
reads the holder. A befriended type in a class template always names the
template's parameters, so every holder that meets it is templated, and
`__func__` cannot be written at class scope. The guard is held by its
unit test.

## Scheme

`scheme` stays 2 (digest §11). Every unit this changes was
indeterminate, and an indeterminate unit is unequal to everything
(§10), so no unit that compared equal now differs: there is no baseline
to void.

## For Kiln

1. **A befriended specialisation's value arguments are not profiled.**
   `friend struct It<T, true>;` in a class template keeps
   `ArgView::Expr { profile: None }` in the canonical
   `TemplateSpecialization`. The same `It<T, true>` written as a
   member's type is profiled (`profile_value_args`,
   `kiln_sema/src/templ/actions.rs:715`, from the template-id path at
   `:1445` and `dependent_spec_canon` at `:1267`). The two spellings are
   then two canonical types (checked on the pinned Kiln with that pair
   in one class), where [temp.over.link]/5 makes them one.
   Corpus: `DenseMap.h:1238-1239`, `ilist_node.h:86-93`, libstdc++
   `hashtable_policy.h:1314`. Slip writes the argument by its profile
   either way, so the digest does not depend on this. The request is one
   canonical type.
2. **A lifetime-extended temporary of a pattern is shared with its
   instantiations.** In `for (int x : make())` in a template's body, the
   instantiated body holds the pattern's `MaterializeTemporaryExpr`,
   whose `LetData.extending` is the pattern's `__range`, not the
   instantiation's. Slip numbers the pattern's owner and writes
   `Ref::outer` to it. That is faithful to what Kiln holds, but it gives
   an instantiation's body a reference into another unit. With its own
   temporary, the instantiation would need none. Corpus:
   `FormatProviders.h:376`, `CommandLine.h:488`.
