# WP-040 — local types, closures and the numbering of owners

What `crates/slip_digest` reads into digest §4.1, §4.3 and digest-kinds
§2.4, §10.4 where the specs are silent or Kiln differs from them, with
Kiln's `file:line` at the pin `913a490bb`. The code is `local.rs`; the
tests are named after each decision.

## Owners

- **Read from `Ast::closure_owner`** (`kiln_ast/src/lambda.rs:257-279`),
  never the map `closure_owner`: the default (the closure's context past
  a requires-expression's parameter scope) is not stored. Kiln's answer
  is taken to the entity with a key (`local::owner`): a parameter to its
  function, a template parameter to its template, a pattern to its
  template, a call operator to its own entity; a `RequiresExprBody`
  still met on the way is `Unsupported("local/requires-scope")` (the
  entities a requires-expression declares are WP-036's).
- **A closure owned by a namespace, a class or the translation unit has
  no number** (`Unsupported("local/closure-owner")`), and every use of it
  is indeterminate. This covers an enumerator, a base-specifier, a
  namespace-scope `static_assert` and every namespace-scope
  `consteval {}` block, which Kiln builds as the call of a synthesized
  lambda (`kiln_sema/src/consteval_block.rs:1-36`). A content-keyed owner
  cannot number its closures: the closure's key would be under the
  owner's key, which is the digest of a stream that holds the closure.
  Tests: `local::tests::the_owner_of_each_closure`,
  `the_owner_of_each_closure_more`;
  `indeterminate/_/consteval-block-at-namespace-scope`.
- **The places, one by one** (`the_owner_of_each_closure` on Kiln's own
  source `kiln_parse/tests/closure_owner.rs`,
  `the_owner_of_each_closure_more` on the rest): default member
  initialiser — the field; variable initialiser, plain, `inline`,
  template, static member defined outside — the variable (template: the
  variable template); default argument of a member or namespace
  function — the function; function signature, requires-clause, alias —
  the function or template; bit-field width — the field; block-scope
  `static_assert` and an init-capture's initialiser — the function. Each
  of these the owner's stream walks, so the closure is numbered.
- **Listed, not numbered** (`UndeclaredLocal` on every use, no change to
  the specs' text needed beyond saying so):
  - the closure Kiln instantiates, lazily and per parameter, for the
    default argument of a function template's specialisation: its owner
    is the specialisation, whose stream does not walk the instantiated
    default argument;
  - a default template argument: Kiln makes one closure for the pattern
    and one per use (several entities for one lambda-expression). The
    pattern's is numbered (the template's stream walks its head's
    default in full, WP-036); the per-use closures are in no stream, so
    they have no number and the question of one key in two parses does
    not arise.
  - a closure a signature names by its type (`decltype([]{})` in a
    parameter type): the numbering reads no type or key, so the key of
    the template is `UndeclaredLocal` (WP-036's
    `lambdas_in_signatures_collide`, which expected a `collision`
    before; either way never one entity in silence).

## Numbering

- **A mode of the walk** (`local::numbering`): keys, types, references
  and values return at once; local types and objects whose owner is the
  one numbered are recorded in declaration order; the members of local
  types are not entered; depth counters are saved and restored; the
  result is memoised per owner.
- **Eager** (`local::number_all`, called by `walk::run_with` after
  `units::collect`): every owner of a local type and every closure's call
  operator is numbered before the first unit, then the memo is sealed. A
  numbering asked for afterwards is `Unaccounted("local/late-numbering")`
  (`the_walk_declares_what_the_numbering_found` asserts none over every
  pair-test source). So no numbering runs on top of a unit's walk and
  the stack bound of one walk holds (`lib.rs` "What bounds the stack").
- **Causes of a cut numbering**: `walk/depth` past a limit,
  `local/numbering-cycle` for a numbering asked for while it is computed;
  every number read from a cut numbering carries the cause.
- **A type the walk declares that the numbering lacks or has elsewhere**:
  `Unaccounted("local/numbering")` (never in the pair tests).
- **The order of units does not change a number**
  (`the_order_of_units_does_not_matter`), and a source without local
  types numbers nothing but its closures' owners
  (`the_common_case_numbers_nothing`).

## `Ref::outer`

`REF_OUTER = 5`, the owner's key digest, the index: init-capture
variables first, then parameters, then the other local objects, each in
declaration order (§4.3). Written when the unit holding the reference is
not the unit whose stream holds the declaration (`local::unit_of`): the
body of an instantiated generic call operator naming a variable of the
enclosing function, a parameter of an enclosing lambda, an init-capture.
`this` is not an object and stays `CXXThisExpr`. Test:
`outer_references_by_owner_and_index`; demand tests below.

A specialisation can name a parameter of its pattern (an expansion
statement's pattern, `differ/ExpansionData/expansions`) whose template
has no local types, so `number_all` did not number it. A parameter of
the owner's own prototype, the owner not a call operator, has its
position as its index (no init-capture variable precedes it and the
prototype is walked first): `local::direct_param` gives it without a
numbering (`a_pattern_parameter_named_by_a_specialisation`;
`the_walk_declares_what_the_numbering_found` checks it against every
numbering of the pair tests). Any other object of an owner not numbered
is `local/late-numbering`.

## Local types in the stream

- Written in place at the declaration: `n`, the stream, the members'
  streams in `members-other` order (sorted by key). Met again: `n`
  alone. Two member functions swapped is `equal`
  (`equal/_/local-member-functions-swapped`), two fields swapped
  `differ` (`differ/_/local-fields-swapped`).
- A local class in a member function of a local class is owned by that
  member function.
- An unnamed local class, a local enumeration and its enumerators, a
  class with declarators in its `DeclStmt`, two blocks each with a class
  of one name: all `local(n)` by declaration
  (`differ/_/local-enum`, `_/local-class-with-declarator`,
  `_/local-classes-two-blocks`).
- **A reference before the declaration** names the number the owner's
  numbering gave (`differ/_/local-reference-before-declaration`,
  `_/local-class-names-a-later-one`, `_/lambda-recursive-this-auto`).

## Derived units under a local type

Units of their own, of the class, group and file other derived units
have: the specialisations of a generic lambda's call operator, of the
conversion and invoker templates; the non-template conversion and
invoker once defined; the implicit special members once defined
(`local::derived_under_local`). The closure's stream does not change
when one appears (`demand/_/generic-lambda-second-call`,
`_/lambda-to-function-pointer`, `_/closure-copy`;
`derived_units_under_a_local_type`). An instantiation of a function
template holds its own local types, numbered in its own stream.

## `LambdaData`

Row by row as digest-kinds §10.4. What Kiln stores beyond the tables:
`DeclRefExpr` `NAMES_CLOSURE_COPY` and `REFERS_TO_ENCLOSING` are rows of
§7 `DeclRefExpr.bits` (now tested, `differ/ExprNode/DeclRefExpr.*`);
`ClosureThunk` (`kiln_ast/src/lambda.rs:217`, `closure_thunk` at `:343`)
is computed from the closure's members, not stored, so no table owes a
row.

## Rule 6

`Unsupported("local/lambda-in-key")` while `Walk::in_key > 0`,
`Unsupported("local/lambda-in-type")` while a type digest is computed
(`LocalState::in_type`), detected in `local::lambda_expr`
(`a_lambda_in_a_key_or_a_type`). At the pin the pair tests cannot reach
either: an expression in a type or a signature is `Pending(Expr)` before
the lambda is met (`indeterminate/_/lambda-in-key`,
`_/lambda-in-dependent-type` stay `# needs: expr`).

## Display names

A name under a local type prints the type as its key: the owner's name,
`::local(n)::`, then the inner scopes and the member
(`mk()::local(0)::operator()<long>(long) const`; `?` for a number not
known). Kiln prints a closure as `(lambda)` in a component but
`(anonymous class)` in a scope, so the scope Kiln prints
(`AstNames::write_scope_prefix`) is replaced, not edited.

## Requires-expression parameters (WP-036's open point)

Kiln gives a requires-expression's parameter in a body the
function-scope depth of the enclosing function's own parameters
(`kiln_sema/src/decl.rs:643`: `prototype_params.len() - 1 +
requires_param_scopes`, both 0 in a body; in a trailing requires-clause
the requires-parameter is at depth 1), and keeps it on substitution
(`kiln_sema/src/templ/concepts/requires.rs:74`). `expr_dep::param_ref`
writes `Ref::param` (depth, index) with no in-requires bit, where the
profile form (`expr_profile.rs` `D_PARM`) has one. No shape reaches the
collision at this merge: a requires-parameter named from inside its
body is the frame's or the unit's ordinal, and five shapes (a nested
requires, a type requirement, a compound requirement, `sizeof`, a
trailing requires-clause) give two digests
(`a_requires_parameter_is_not_a_function_parameter`). A form of
`Ref::param` with the bit is the spec owner's to add if one does.
