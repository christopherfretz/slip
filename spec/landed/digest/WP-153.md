## 1. First: "outcome equal, binding moved" can change behaviour

The package's Scope says: "No evaluated call changes while the outcome
is equal." That holds for calls of the substituted expression at run
time. It does not hold for the program. **What a name binds decides
what is instantiated, and an instantiation can emit code that runs.**

```cpp
extern "C" int puts(const char *);
inline int note() { puts("registered"); return 1; }
template <class T> struct Reg { static int r; };
template <class T> int Reg<T>::r = note();
struct Base { static int s(); };
namespace n {
struct S : Base {
  template <class U = int> static auto s() { return (void)&Reg<U>::r, 1; }
};
}
template <class T, int = sizeof(T::s())> int call() { return 0; }
int main() { return call<n::S>(); }
```

`T::s()` binds `n::S::s<int>`. Its return type is deduced, so its body
is instantiated. The body odr-uses `Reg<int>::r`, so that variable's
definition is instantiated, and its initialiser runs at start-up. The
program prints `registered`. Rename the member template `n::S::s` to
`h`: `T::s()` binds `Base::s`, nothing is instantiated, the program
prints nothing. `sizeof` gives 4 both times and `main` returns 0 both
times. Kiln emits such a definition where its semantic analysis
instantiated it (`kiln/crates/kiln_codegen/src/module.rs`
`instantiated_var_def`).

The same program with three other forms of the last two lines:

```cpp
// (b) the substitution fails later, in the same substitution
template <class T, int = sizeof(T::s(), T::nope())> int call(int) { return 1; }
template <class T> int call(long) { return 0; }
int main() { return call<n::S>(0); }
```

```cpp
// (c) a partial specialisation's match fails after a name bound
template <class...> using void_t = void;
template <class T, class = void> struct has { static constexpr int v = 0; };
template <class T>
struct has<T, void_t<decltype(T::s()), typename T::nope>> { static constexpr int v = 1; };
int main() { return has<n::S>::v; }
```

```cpp
// (d) no template at the use: an operand that only a type holds
decltype(n::S::s()) v = 0;
int main() { return v; }
```

**The design review ran all four** as pairs of the digest's test
runner with the rename mapped. In each, no unit that both images have
differs; six derived units are in the pre-image only (`n::S::s<int>`,
`Reg<int>`, `Reg<int>::r`, and their definitions); none is
indeterminate. By `spec/verify.md` §4 step 3 that is `verified`
(`slip_verify` itself was not run). clang 19 and GCC 14 print
`registered` before and nothing after, with equal exit codes, for all
four. The reason `spec/verify.md` gives for step 3 ("Why a derived unit
on one side only is not a difference": the demand "is written in the
stream of the unit that made it") is false for this class.

The review found two more forms.

**A function, not a variable.** Give the member template
`__attribute__((constructor))` and a body that prints, with no `Reg`:
the pre-image alone has `n::S::s<int>` and its definition, and the
program prints before the rename and not after. With `used` nothing is
printed, and the symbol is in the object file on one side only.

**A candidate that is no longer considered.** No name binds another
entity; a substitution simply does not happen in the post-image:

```cpp
extern "C" int puts(const char *);
inline int note() { puts("registered"); return 0; }
template <class T> struct Tr { static int r; };
template <class T> int Tr<T>::r = note();
namespace lib {
struct X {};
template <class T> auto probe() { return (void)&Tr<T>::r, 1; }
template <class T, int = sizeof(probe<T>())> void f(T, char);
}
void f(lib::X, long) {}
#ifdef B
void use() { ::f(lib::X(), 0); }
#else
void use() { f(lib::X(), 0); }
#endif
int main() { use(); }
```

The call is requalified and the callee is the same function.
Argument-dependent lookup no longer supplies `lib::f`, whose default
template argument had instantiated `probe<lib::X>` and through it
`Tr<lib::X>::r`. `use` is equal on both sides; seven derived units are
in the pre-image only; the program prints `registered` before and
nothing after (both compilers). This is the edit a namespace migration
makes.

What closes each:

| Case | Is | Closed by |
|---|---|---|
| the first program | a successful substitution, the package's class | this design (the default argument's unit differs, §4), and WP-155 |
| (b), (c) | **the counter-case to "successes only"**: a name bound, the substitution failed later, the binding reached the program | WP-155 only. The binding itself, in a failure, stays a limit of names (§3.10) |
| (d) | not a substitution: an operand that is not dependent and that only a type holds | this design (§3.8), and WP-155 |
| a `constructor` or `used` function | as the first program | this design, and WP-155 |
| a candidate no longer considered | no binding moved anywhere | **WP-155 only.** No record of what names bound can see it |

**WP-155** (ruled 2026-11-24; a package of its own, launched first, not
part of this one): a derived unit that is emitted whether or not it is
referenced, present in one image only, is a finding. Such a unit is the
definition of a variable of static or thread storage duration that is
not constant-initialised, or has a non-trivial destructor, or is
`used`; or of a function with `constructor`, `destructor` or `used`.
The walk marks them; a trait's `::value` is not one. The finding says
"no longer instantiated in this translation unit". The rule is only as
good as the match between Kiln's compatibility level and the
compilation database's compiler: which candidates a front end
substitutes at all differs between compilers and versions.

Without a forced instantiation, a moved binding in an operand that is
not evaluated at run time changes no behaviour, and the package's
sentence stands. The statement Slip makes, "every name resolves as it
did", is false in every case above except the last.

## 2. The design in one page

- **Behaviour** is WP-155's, first, and independent of everything
  below. This package is about names.
- **The unit**: one new **derived** unit per substitution. `KeyKind` 34
  `substitution`; its parent is the unit of the declaration Kiln's key
  names; its name is a new `Name` 16 `substitution(kind)`; its
  discriminator is the digest of the canonical arguments, written as a
  `specialisation`'s. It maps under a namespace rule and under a
  rename's declared changes exactly as a `specialisation` key does. No
  exemption applies to it and no rule may name it.
- **What the unit holds** depends on the form (§3.13 is the decision
  table, with Kiln's answer as input; the supervisor rules):
  - **Form R, the root.** Kiln keeps, per key, the root of what the
    substituter built. The unit is the digest's ordinary walk of it.
    Names, operators, constructors and conversions are all in it as
    they are in an instantiated body. No entry needs a name.
    Recommended for all four kinds. Kiln can give it for `Alias`,
    `DefaultArg` and `PartialMatch` as they are, and for
    `Satisfaction` after two pieces of work.
  - **Form T, the rows.** The unit is the sorted set of Kiln's rows,
    each entry named by (owner, region, ordinal within the region).
    Nothing of Form T is built before the pin has the owner (Kiln
    WP-3143, later than the pin) and the region (which does not exist
    yet).
- **Operands a type or a value holds**, in ordinary code and in
  instantiated declarations (`decltype(make(x)) y;`,
  `array<char, sizeof(to_wire(x))>`, `-> decltype(T::s())` in a
  specialisation, a resolved `noexcept(e)`): a sibling derived unit of
  the unit that wrote them, `KeyKind` 35 `operands`, holding the
  ordinary expression walk of each. It reads the AST as it is at the
  pin, needs no rows, and replaces the reading of `specs()` in Form R.
- **A key exists for every completed substitution** (ruled; Kiln's
  WP-3540 is amended so), also one that bound nothing and a check that
  ended unsatisfied, so that a unit both images have is compared and a
  key's presence says only "was asked for". The unit writes the key's
  outcome.
- **Nothing existing moves.** Units are only added. `scheme` moves
  at the first stage that writes a substitution unit, unconditionally
  (ruled; WP-155 has taken 3, so the numbers are those of §13.1); a
  digest of that scheme or a later one is always made with Kiln's key
  table on.
- **What cannot be read is never equal by silence**: an omission Kiln
  reports, an image without the table, a key of a kind the walk does
  not know, and (Form T) an unknown region or an unresolved row each
  make an indeterminate unit.
- **Stated limits** (named in `spec/digest.md` §2.3): the binding in a
  substitution that failed; a local constrained declaration; two
  elements of a pack expansion that swap (Form T only); the shapes
  Kiln has no key for until it adds them (KR9 §5.4).

## 3. Decisions

### 3.1 Two forms, designed to the same depth

Kiln can say what a substitution bound in two ways.

**Form R (root).** Per key, the root of what the substituter built: an
expression, a type, or an argument list. Kiln never truncates its
arenas (`kiln/crates/kiln_sema/src/templ/deduce_call.rs`
`in_sfinae_held` takes the expression arena's length only to flush
member references), so the nodes exist; the root is what is missing.
`decltype_ty` (`kiln/crates/kiln_sema/src/templ/subst/types.rs`)
substitutes the operand before the type is built, and the type carries
it (`TypeView::Decltype { expr }`).

**Form T (rows).** Per key, the rows of `subst_rows`: one per dependent
entry of the pattern, with what it bound. This is Kiln's WP-3540 as
frozen for its stages 0 and 1.

The first version of this proposal chose rows and gave four reasons
against the root. The review showed that they do not hold:

| Reason given | Why it does not hold |
|---|---|
| the form carries the sugar of the first use's arguments | the digest writes canonical types everywhere, as for any instantiated body; §3.4 says where the walk stops |
| a failed substitution has no form | it has no rows either |
| edit planning needs rows | it does, and it does not need the owner, the region, the pack element or the properties P1 to P4 in the strength the digest needs them |
| Kiln's design is frozen as rows | Kiln has costed a root per key (below) and proposes a parallel table `subst_roots` behind its own switch, later; the key stays 24 bytes |

What Form R removes: the naming of entries (§3.5, with the review's
findings 2 and 5), the second naming scheme operators would need
(KR9 §5.3), the pack-element limit, and the question whether a type
name is written by entity or by type.

**Kiln's cost study** (Kiln's answer of 2026-11-24), per kind:

| Kind | A root |
|---|---|
| `Alias` | complete, and already kept alive by the alias cache; built without type locations |
| `DefaultArg` | complete; the root would be the argument before conversion |
| `PartialMatch` | the substituted argument list is built and then dropped; interning it gives the root; the shortcut for a bare non-type parameter builds nothing |
| `Satisfaction` | **not complete**: a fully concrete requires-expression is rebuilt with an empty requirement list (the substituted requirements are orphaned); a failed atom has no root; a hit in the atomic-constraint cache builds nothing (the entry would have to store its expression) |

For every kind the operands are unevaluated: nothing in them is
odr-used and no body is instantiated because of them. Cost: about 0.1
to 0.3 MB on `<bits/stdc++.h>`; a module image writes only reachable
nodes, so roots add bytes there. §3.4 says what each line means for
the walk; §3.13 decides per kind.

**Common to both forms**: the unit and its key (§3.2, §3.3), presence
(§3.9), failures (§3.10), the gaps (§6), the operand units (§3.7,
§3.8). **Never both for one key**: one unit, one content.

### 3.2 The unit: a derived unit per substitution

**Decided.** One unit per key of Kiln's table.

*Lost: bytes in an existing unit* (the specialisation's `resolved`
unit for a default argument and a deduced signature; the using unit for
an alias template-id), as the facts list of `spec/digest-kinds.md` §4.4
is appended. Three reasons. An alias template-id and a satisfaction
have no unit of their own, and "the using unit" is whichever unit
wrote the use first: the content would be in a unit chosen by order.
A specialisation's unit exists for more reasons than this substitution
(a default argument's substitution is made once per (template,
parameter, prior arguments) and serves many specialisations). And an
existing unit would gain bytes, which moves every recorded digest of a
translation unit that includes a standard header.

*Lost: one unit per row* (Form T). A row that only one image has would
be a one-sided derived unit and no finding.

*Lost: one unit per template* (all its substitutions together). Its
content would depend on which uses the translation unit makes
(`spec/digest.md` §1 rule 5).

### 3.3 The key, and how it maps

```
key    := kind: 34 substitution
          parent: Unit(key of D)
          name:   16 substitution(k)
          disc
```

| `k` | Substitution | `D` | `disc` is the digest of |
|---|---|---|---|
| 1 | `PartialMatch` | the partial specialisation | the specialisation's arguments |
| 2 | `Satisfaction` | the concept, or the constrained declaration | the arguments shown; none for a declaration that is not a template |
| 3 | `DefaultArg` | the template | the parameter's index, then the prior arguments |
| 4 | `Alias` | the alias template | the arguments |
| 5 | the type of a non-type template parameter (a kind asked for, KR9 §5.4) | the template | the parameter's index, then the prior arguments |
| 6 | Form T only: the rows of `specs()` for one region of a specialisation (§3.7) | the specialisation or instantiated member | the region |
| 7 | a sentinel (§6) | the root | the cause's word, then the file's subject path, the module's name or the kind's number |

Arguments are written as `spec_key` writes a specialisation's
(`crates/slip_digest/src/keys.rs`): canonical, each reference by its
mapped key. `D` always has a key unless it is local (§6.4): `keys.rs`
`key` gives one to every declaration at namespace or class scope, and
to a member of a class template specialisation under the
specialisation's key (`spec_key`). That is the check the supervisor
asked for on answer 9; the review confirmed that the key joins under a
relocation and a rename.

**Mapping.** The key holds a parent key id and arguments made of
references and type digests, and no name of its own. Both are mapped
as they are for a `specialisation` key (`spec/digest.md` §3.4): rules
are applied to the post-image and undo it (`spec/verify.md` §2), so a
post-image key `<acme::X, void>` under `relocate legacy => :: acme` is
compared as `<legacy::X, void>`. Under a rename's declared change the
parent's key maps and the unit follows.

**Rules and causes.**

- A rule that names a `substitution` or an `operands` key is refused,
  as a rule on a part is (`RULE_ON_PART`, `spec/verify.md` §2.1). "No
  rule matches a specialisation" needs no change.
- The unit is derived: compared when both images have it, no exemption
  (`spec/verify.md` §4 step 3).
- The unit inherits what is wrong with its key: if `D`'s key, or a key
  named in the arguments, is indeterminate or collides, the unit is
  indeterminate with that cause, as a specialisation's unit is.

**Group.** The derived group of the file that holds the first
declaration of `D` (`spec/digest.md` §11).

**The unit's printed name** is `D`'s name, the arguments, and the kind:
`bindings in default argument 2 of call for <n::S>`,
`bindings in the match of swappable<T, void> for <legacy::X, void>`,
`bindings in alias R<n::S>`, `bindings in the satisfaction of HasS<n::S>`.

*Lost: the using unit as parent* (§3.2). *Lost: `PartialMatch` keyed
under the specialisation.* The specialisation exists whether or not the
partial specialisation matched, and several can match one
specialisation; the partial specialisation is the pattern, and Kiln
keys it so.

### 3.4 Form R: the unit is the walk of the root

```
stream := k: uv
          form: uv                   1 root, 2 rows (§3.6)
          outcome: uv                1 completed, 2 completed unsatisfied (§3.9)
          deduced: list<ArgView>     k = 1 only: the payload of the key
          slots: list<Slot>
Slot   := 0                          not reached
        | 1                          reached and failed (an atom that is false by a substitution failure)
        | 2 Root
Root   := 1 expression: child        the ordinary expression walk
        | 2 type: the type's digest, then its operands (§3.7's walk)
        | 3 template: ref
        | 4 value: the argument as `enum ArgView`   a place the substituter built nothing for
```

**Slots.** A substitution has a fixed number of places, given by its
pattern, and a slot per place:

| `k` | Slots |
|---|---|
| 1 | one per written argument of the partial specialisation, in order |
| 2 | one per atomic constraint of the normal form, in the normal form's order; for a concept-id's own check the same over the concept's normal form |
| 3, 5 | one |
| 4 | one: the alias's type |

A slot is `0` when the substitution did not reach its place (the
right operand of a satisfied disjunction, an atom after a failed one)
and `1` when it reached it and failed there inside a check that
completed. Keeping the place is what keeps two different atoms apart:
without it, "bound in the first" and "bound in the second" could be
one sequence (the disjunction of §3.5). What a failed atom's names
bound before the failing one is not in a root (Kiln: a failed atom has
no root). That is the limit of names of §3.10, inside a check; Kiln's
rows have those names, and the edit planning reads them.

**What Kiln's cost study means for the walk.**

- *"Without type locations"* (`Alias`). The digest reads no position,
  and it reads types from the type nodes, so nothing is lost for an
  operand a type node holds. One thing is: a parameter of a function
  type in the alias's type-id whose type is adjusted (an array or a
  function type) has its written type only in its parameter
  declaration (`ParamData::original_ty`, `spec/digest-kinds.md` §4.4
  rule 2), and a root built without type locations has no such
  declaration. An array bound's operand in such a parameter
  (`using F = void (*)(int p[sizeof(T::s())])`) is not in the root. A
  named gap, asked (KR9 §5.3).
- *"The argument before conversion"* (`DefaultArg`). The conversion
  the site applies can itself select a function: a converting
  constructor or a conversion function when the parameter has class
  type, a conversion function to the parameter's scalar type
  (`template <class T, int = T()>` with `T::operator int`). A root
  taken before conversion misses that selection. G5 below asks for the
  root after conversion and before evaluation; if Kiln cannot give
  that, the conversion's function is a row to ask for or a limit to
  state.
- *"The shortcut builds nothing"* (`PartialMatch`): a bare non-type
  parameter replaced by its value involves no name. Its slot is root
  form 4, the value.
- *"Unevaluated"*: the walk writes the entity a node refers to
  whatever its `USED` mark, which is not digested. Nothing changes.
- *`Satisfaction`*: of the three missing pieces Slip needs two: the
  substituted requirements kept (G6), and the atom cache's entry
  holding its expression (G4). A failed atom needs no root (slot `1`).

**What is written** is what the walk writes for the same nodes in an
instantiated body (`spec/digest.md` §6): the entity a name refers to,
the function an operator, a constructor or a conversion selected, the
implicit steps, types by their canonical digest, values by value. A
type root writes its canonical type and then the operands its sugar
holds, by §3.7's walk; an expression root's types written inside it
(`static_cast<decltype(e)>`, `sizeof(type)`) are read the same way.

**A name the substitution left dependent** (inside a generic lambda or
a nested template of the pattern) is written as the walk writes it in
any instantiated body that still holds a pattern: in profile mode, with
the unit's own spellings facts (the found set, the operator set;
`spec/digest-kinds.md` §4.4 rules 1 and 2). Nothing new is defined for
it. A substitution unit is a unit like any other for §4.4.

**Where the walk stops**, so that the first use's spelling is not in
the unit: at the replacement of a `SubstTemplateTypeParm` (an
argument's own sugar, with any operand it holds, belongs to the unit
that wrote the argument, §3.8); at the underlying type of a typedef or
an alias specialisation (the operand belongs to the alias's own unit
or key); at the deduced type of a placeholder.

**What Slip needs Kiln to guarantee about the nodes** (KR9 §5.3):

| | Guarantee |
|---|---|
| G1 complete | every node reachable from a root has every field the walk reads, filled as in an instantiated body: types, value categories, `satisfied`, stored values. No node kind exists that is built only under a substitution and nowhere else |
| G2 resolved | every name, operator, constructor, conversion and implicit step the substitution selected is in the nodes as it would be in an instantiated body. No unresolved lookup remains for a call whose arguments are not dependent after the substitution |
| G3 nothing dangles | every declaration a node refers to is still valid and reachable: none belongs to a frame that was dropped (a parameter of a function type built inside the substitution, a closure type, an instantiated local). A declaration made inside the substitution is either local to the root, so that the walk numbers it within the unit (`spec/digest.md` §4.3), or a real instantiation that the specialisation tables list |
| G4 one root per key | P1 of KR9 §4 for roots: the first completed run's root stands; a later use answered from a cache neither replaces it nor needs it; a key whose atoms are replayed from the atomic-constraint cache has, slot by slot, a root that walks to the same bytes as a fresh substitution's would (sharing the cached nodes is the simplest way) |
| G5 after conversion, before the value | where Kiln keeps only a value (a non-type default argument converted, a constraint's atom evaluated), the root is the expression after the site's implicit conversion and before evaluation |
| G6 requires-expressions | a requires-expression in a root keeps its substituted requirements. At the pin a substituted requires-expression whose result is not dependent is rebuilt with an empty requirement list (`kiln/crates/kiln_sema/src/templ/concepts/requires.rs`, the end of the function that rebuilds it) |
| G7 the marker | an argument's replacement in a root is under a `SubstTemplateTypeParm` (types) or its expression counterpart, so the walk can stop there; a root holds no other trace of how the first use spelled its arguments. Kiln's alias cache is keyed by the sugared arguments at compatibility level 22 and above (`kiln/crates/kiln_sema/src/templ/class.rs` `alias_template_type`), so this needs a statement |
| G8 the key's condition | Kiln's test for a key is static: the pattern has a dependent entry, filled by the parser. An operator has no entry. A pattern whose only dependent selection is an operator must still get a key (open question 2) |

A walk that meets a node it cannot account for makes the unit
indeterminate with the walk's usual cause; nothing special is added.

### 3.5 Form T: how a row names its entry

**Decided: (owner, region, ordinal).** Kiln gives owner and region per
entry (KR9 §5.1); Slip derives neither.

- The **owner** is the declaration at namespace or class scope in whose
  declaration the name is written: a template, a partial
  specialisation, an alias template, a concept, a member. Never a
  namespace, never the translation unit, and never the class for a name
  in the head of a member template.
- The **region** is the part of the owner's declaration the name is
  in: the default argument of template parameter *i*; the type or
  type-constraint of template parameter *i*; the requires-clause of the
  head; the signature (return type and parameters); the trailing
  requires-clause; the exception specification; the
  explicit-specifier; the default argument of parameter *i*; the body
  or initialiser; an alias's type-id; a concept's expression; a partial
  specialisation's arguments; a class's base list; an attribute. The
  list is Kiln's to close: every entry has exactly one. A region value
  the walk does not know makes the unit indeterminate,
  `Unaccounted("substitution/region")`.
- The **ordinal** is the entry's rank among the entries of the same
  (owner, region) that have `DEPENDENT`, in table order within one
  declaration. A signature and a requires-clause repeat across
  redeclarations; there the ordinal runs over the declaration the row's
  entry is in, and Kiln's rule for which redeclaration's entries a
  substitution reads decides whether two images join (a question of
  KR9 §5.1).

The row writes the owner as a reference, the region as two `uv`, and
the ordinal as `uv`.

**The property, as it is.** The set of `DEPENDENT` entries of an owner
is **not** a function of the owner's text. A call is a dependent entry
when lookup at the definition finds two overloads and a resolved one
when it finds one (the review's dump: `c.h(t)` and `q::k(t)` flip with
the number of overloads of `h` and `k`; `using legacy::swap; swap(a, b)`
is dependent and `legacy::swap(a, b)` is not). So:

- A rename of the identifier, a move of the declaration, and a change
  of what a name binds at instantiation leave the ordinals as they
  were.
- A change elsewhere that makes an entry stop or start being
  dependent (one of two overloads renamed, removed, or moved to
  another namespace; a call requalified) removes or adds that entry's
  row and renumbers the entries after it **in the same region**. Every
  substitution unit holding a row of that region differs:
  `derived_changed`, no exemption. The owner's own unit is expected to
  differ too (its found set changed), so this multiplies a finding; it
  was not run that it never makes one from nothing.
- The region bounds the damage: a change in a body does not renumber a
  default template argument.

That fragility is the main reason Form R is preferred.

**No interim rule** (ruled). The first version found the owner by
walking outward from `WrittenRef::enclosing`. The review's dump of
Kiln at the pin shows where that fails:

| Name in | `enclosing` at the pin |
|---|---|
| a default template argument of a namespace-scope template | the namespace, or the translation unit |
| a default template argument of a member template | the class |
| a requires-clause in the template head | the namespace |
| an alias template's type-id | the namespace |
| the type of a non-type template parameter | the namespace |
| a lambda in a default template argument | the closure's call operator |
| a partial specialisation's arguments; a concept's body; a trailing requires-clause | the declaration (right) |
| a member's default argument; a parameter of a function type in an alias | the parameter |

For a namespace-scope template the walk ends at a namespace and the
unit would be indeterminate: every `DefaultArg` and `Alias` unit, so no
observer that makes one would verify. For a member template it ends at
the class, which has a key: the ordinals would be class-wide and wrong
without a cause. Neither is acceptable.

**Kiln's answer of 2026-11-24**: its WP-3143, later than Slip's pin,
already fixes the first five rows: a default template argument, an
alias's type-id, a head requires-clause and a non-type parameter's
type are held by the templated declaration, and a member template's
head names by the member. What remains:

| Residual | Matters for Form T? |
|---|---|
| a generic lambda's head is held by the enclosing variable, not by its call operator | no: the call operator is local and its keys are left out (§6.4); it matters when local declarations are designed |
| a template template parameter's inner head is held by the outer template | no: the outer template is the owner by the definition above |
| a name in a function-type parameter, or in a lambda, inside an alias's type-id is held by that parameter or call operator | **yes**: the owner is the alias template, and a walk outward from such a nested declaration is not known to reach it. Asked (KR9 §5.1) |

**The region does not exist** in Kiln: `enclosing` gives the owner
only. It is new Kiln design. So **no stage that names an entry by
(owner, region, ordinal) is built before the pin has WP-3143, the
residual case for aliases, and the region.**

*Lost: the ordinal within the key's run of rows.* It loses the entries
that are absent. With

```cpp
namespace n {
struct S {
#ifndef B
  using a = int;
#endif
  using b = int;
};
}
template <class T> concept E = requires { typename T::a; } || requires { typename T::b; };
static_assert(E<n::S>);
```

the check binds `T::a` and never substitutes `T::b`. With `B`, `T::a`
names nothing, the first requirement fails, and the check binds
`T::b`, to the same type. Each side has one row, the first of its run,
with the same target.

*Lost: the entry's profile.* The identifier cannot be part of it (a
rename changes it); without it two entries of one pattern are alike.
*Lost: the position.* The digest holds none. *Lost: the owner found by
Slip from the declaration-extent table* (the review's alternative): it
reads positions in the walk, and whether an extent starts at
`template` was not checked; the ruling is that Kiln gives the owner.

### 3.6 Form T: the row and the stream

```
stream := k: uv
          form: uv                   2 rows
          outcome: uv                1 completed, 2 completed unsatisfied (§3.9)
          deduced: list<ArgView>     k = 1 only
          rows: list<Row>            sorted by their bytes, duplicates removed
Row    := owner: ref, region: uv uv, ordinal: uv, Target
Target := 1 entity:    ref
        | 2 type:      the digest of the type named
        | 3 dependent: adl: bool, found: list<ref>   sorted, duplicates removed
        | 4 builtin
```

- **A resolved entity that is not a type**: the reference. The callee
  is the fact (`spec/digest.md` §6). `how`, `found`, `udir` and the
  `adl` set are not written: they say how the entity was reached.
- **A resolved type name** (a class, an enumeration, a typedef, an
  alias): the digest of the type it names (ruled). Kept code is
  compared so: `n::S::t x;` against `Base::t x;` is equal when both
  name `int` (`spec/digest.md` §1 rule 2). In Form R the question does
  not arise: a type is written canonically.
- **An entry that stays dependent**: the tag, whether
  argument-dependent lookup will run, and the declarations found now
  as a sorted set. Which substitutions give such rows is a question to
  Kiln (KR9 §4, P2): a class instantiation leaves the head names of
  every member template dependent and gives none today.
- **A builtin candidate**: the tag.
- **A row with `REF_UNRESOLVED`** under a key: the unit is
  indeterminate, `Unaccounted("substitution/unresolved")`.

A key with no rows (§3.9) writes `k`, the form, the outcome, the
deduced list and an empty list. Kiln's row rule (its answer of
2026-11-24): a name that bound has a row; a name that did not bind or
was never reached has none; a failed atom's names that bound before
the failing one have rows, also when the atom is replayed from the
cache. Sorting makes the stream independent of Kiln's recording order
and of how many pack elements gave the same row; two elements that
swap what they bind are equal (a stated limit of Form T, KR9 §5.6).

### 3.7 Instantiated declarations: the operand unit, not `specs()`

A specialisation's signature, its exception specification, its body
and each of its default arguments are substituted at different times,
and Kiln keeps the results in the specialisation. What the digest
misses in them today is not the substitution but an **operand that
only a type or a value holds**: the digest writes the canonical type
or the value (`spec/digest.md` §1 rule 2) and not the expression.

What Kiln keeps of such an operand at the pin (read in
`kiln/crates/kiln_ast/src/types/`):

| Operand | Held by |
|---|---|
| `decltype(e)` | `TypeView::Decltype { expr, underlying }` (`context.rs`) |
| `typeof(e)` | `TypeView::TypeOf { operand }`, `TypeOfOperand::Expr` (`context.rs`) |
| an array bound | `ConstArray::size_expr`, "the bound as written, when it was an expression" (`node.rs`) |
| an expression as template argument | `ArgView::Expr { expr, profile }` in a written argument list (`args.rs`), under `TypeView::TemplateSpecialization { args }` |
| a pack index | `TypeView::PackIndexing { index }` |
| `noexcept(e)` | `ExcSpec::NoexceptExpr { expr, value }` (`func.rs`) |
| `explicit(e)` of a member of an instantiated class | `ColdDeclData::explicit_expr` (`kiln/crates/kiln_ast/src/decl.rs`) |

`spec/digest-kinds.md` marks each `written`, `out`.

**Decided: the operand unit.** A unit whose walk meets such an operand
that is not instantiation-dependent gets a sibling:

```
key    := kind: 35 operands, parent: Unit(the unit's key), name: 17 operands, disc: none
stream := count: uv, then per operand, in the order of the unit's own walk
          (the order of structure of spec/digest-kinds.md §4.4 rule 2):
          site: uv      1 decltype, 2 typeof, 3 array bound, 4 template argument,
                        5 pack index, 6 exception specification, 7 explicit-specifier
          child         the ordinary expression walk
```

- It is derived whatever its parent is, and in the derived group of
  the parent's file. A unit without such an operand has none.
- The parent may be any unit: a declared entity, a specialisation, a
  `resolved` unit (`definition`, the exception specification's), a
  default argument's unit. So an operand in a specialisation's
  signature is beside the specialisation, one in its body beside its
  `definition`, and each exists exactly when its parent does. That is
  what the "part" of a `specs()` row was asked for in the first
  version, and here it costs nothing.
- An operand that is instantiation-dependent is not this unit's: it is
  a pattern's, and §4.4's spellings write it.
- The walk stops as in §3.4 (a substituted parameter's replacement, an
  alias's underlying type, a deduced type).
- The sites are every field of `spec/digest-kinds.md` that is
  `written`, `out` and holds an expression. The build takes the list
  from the kinds table, and the completeness test of `spec/digest.md`
  §13 holds it to that.

**What this covers in an instantiated declaration**: the signature
substituted in deduction (`-> decltype(T::s())`, a parameter's array
bound), also of a candidate that lost; a resolved `noexcept` operand;
a local variable's `decltype` in an instantiated body; a member
`int a[sizeof(T::s())]` of an instantiated class; `explicit(e)` of a
member of an instantiated class.

**What it does not, and is asked of Kiln** (KR9 §5.4, §5.8):

- a requires-expression in an instantiated body: its substituted
  requirements are not kept (G6 of §3.4);
- `explicit(bool)` of a function template specialisation: only the bit
  is kept;
- an out-of-line redeclaration's signature (Kiln's stage 5);
- whether an instantiated declaration stores its type with these
  operands in every case. `decltype_ty` returns the node built from
  the substituted operand, and the constant-array arm of the type
  substitution hands the bound's expression on (both read in
  `kiln/crates/kiln_sema/src/templ/subst/types.rs`); that the
  declaration then stores that type and not its canonical form was
  **not probed**. `spec/digest-kinds.md` §4.4 rule 7 records one case
  where Kiln drops a bound's expression. The first task of the operand
  stage is the probe, per site.

**Form T's alternative: read `specs()`.** If Kiln answers that the
operands are not kept and offers rows only, the digest reads `specs()`
for these shapes, under these rules:

- A row is read only when its `spec` is a specialisation or a member
  of one. A row whose `spec` is an alias template, a concept or a
  constrained pattern (at the pin: `spec` is the alias template, the
  concept, the templated declaration) is not read: its substitution is
  one of the table's kinds, or the partly concrete case of §3.12. Read
  as one set per such `spec` it would change with every added use.
- Kiln marks a `specs()` row whose substitution is keyed in
  `subst_keys`, so that the digest does not read it twice.
- The unit is (`spec`, region): `k` 6, the region of the row's entry
  as discriminator. The region stands for the time of the substitution
  (the signature at deduction, the body at definition), so a unit
  exists exactly when its substitution was made
  (`spec/digest.md` §1 rule 5). The region must be total over every
  frame `written_spec_key` gives a key for
  (`kiln/crates/kiln_sema/src/written_specs.rs`;
  `kiln/crates/kiln_sema/src/templ/stack.rs` lists `MemberClass`,
  `StaticDataMember`, `VarTemplateInit`, `Enum`, `Annotation`,
  `ExplicitArgSubstitution` among them).
- An unknown region makes the unit indeterminate.

### 3.8 Operands in ordinary code

**Ruled: in the statement.** A name in an operand that is not dependent
and that only a type or a value holds is a written name in ordinary
code, and argument-dependent lookup moves it in a migration:

```cpp
namespace lib {
struct X {};
#ifndef B
int make(X);
#endif
}
template <class T> int make(T);
lib::X x;
decltype(make(x)) y;
char buf[sizeof(make(x))];
template <class T, unsigned long N> struct array {};
array<char, sizeof(make(x))> a;
```

`y`, `buf` and `a` have the same types on both sides; `make` is
`lib::make` on one and `make<lib::X>` on the other.

**Mechanism: §3.7's operand unit**, with a declared parent. It is the
review's finding 8. The first version proposed to write the operand's
bindings into the using unit's own stream; that would make
`equal/_/decltype-non-dependent` (`int x; decltype(x) v;` against
`int x; int v;`) differ, since the operand exists on one side only.
As a sibling derived unit it is one-sided there and no finding; where
both sides have the operand and a name moved it is `derived_changed`.

Accepted: a unit with two operands of which a transform removes one
(replaces `decltype(e)` by the type) has an operand unit on both sides
that differs. That is a finding without a moved name. It fails closed
and is rare; open question 4.

What must be asked of Kiln for ordinary code (KR9 §5.8): that a
template-id that is not dependent keeps its expression argument in the
written list and not only the converted value; and the list of other
places where an expression is written and only its value is kept (a
bit-field's width, an enumerator's value, `alignas(e)`, an attribute's
argument). Each is a site to add or a limit to state.

### 3.9 A key that only one image has

**Ruled** (the supervisor withdrew answer 1 to Kiln): a derived unit on
one side only is no finding, so "keys only where rows exist" is not
enough. A substitution that completes in both images, with something
bound before and nothing after, must have a unit in both:

```cpp
namespace n {
struct S {
#ifndef B
  using a = int;
#endif
};
}
template <class T> concept E = requires { typename T::a; } || true;
static_assert(E<n::S>);
```

**Kiln's answer of 2026-11-24**: WP-3540 is amended and frozen again
with a key for every completed substitution, also with no row.
"Completed", per kind: `PartialMatch`, the partial specialisation
matched, its constraints included (a non-match gets no key);
`DefaultArg` and `Alias`, substituted, and converted where the site
checks, with no captured failure; `Satisfaction`, the check produced
an answer (a substitution failure inside an atom makes the atom false
and the check completes; a hard error does not). A check that ended
unsatisfied is a key with `SubstOutcome::Unsatisfied`; the outcome is
not part of the key's identity. Whether a pattern can have a key at
all is a static test, filled by the parser, so keys do not come and go
with what was reached.

So presence means "was asked for", and a one-sided key means the
demand changed (which a migration does, and WP-155 judges).

**Decided: the outcome is written in the unit's stream** (§3.4, §3.6),
not in its key. "Satisfied before, unsatisfied after, the same names
bound" then differs in a unit both images have. It is partly redundant:
the result is stored in each expression that asked
(`spec/digest.md` §2.3, §6) and decides the candidate chosen. It is
not wholly so: a check made for a candidate that loses either way
leaves its result in no unit. One byte; kept.

*Lost: a one-sided substitution unit is a finding.* The review's pairs
show the false findings: a requalified call with the same callee stops
argument-dependent lookup from substituting a candidate.

### 3.10 Failed substitutions

**Ruled: successes only**, in both forms. A substitution that failed
has no key. What it decided is compared (its candidate is not viable,
its pattern is not matched). What its names bound before it failed is
a **limit of names**, stated. What that binding instantiated is
behaviour and is WP-155's (§1 (b), (c)).

The supervisor's answer 3 keeps what matters most: a default
argument's key is committed when it succeeds, also when a later one
fails.

### 3.11 Candidates that lost

- A function template candidate whose deduction succeeded has a
  specialisation, kept whether or not it wins
  (`kiln/crates/kiln_sema/src/templ/funcs.rs`
  `get_function_spec_signature`; only `USED` tells a winner). Slip
  already queues it as a derived unit
  (`crates/slip_digest/src/units.rs` `collect`). Its signature's
  operands are its operand unit (§3.7). **In the promise.**
- A partial specialisation that matched and lost partial ordering has a
  `PartialMatch` key (answer 2, ruled). **In the promise.** No
  `selected` mark: the chosen pattern is in the specialisation's unit
  (`SpecInfo` `from`, `spec/digest-kinds.md` §9.4).
- A candidate whose deduction failed, a conversion considered for a
  candidate that lost, and a candidate no longer considered: **not in
  the promise** (§3.10, §1).

### 3.12 An alias-id with partly concrete arguments (Kiln's question 6)

```cpp
template <class X, class Y> using A2 = typename X::t (*)(typename Y::t);
```

used as `A2<n::S, T>` in a template that is never instantiated: `X::t`
binds `n::S::t` when the pattern is parsed.

**Ruled: no partly dependent key, and the digest does not read the
`specs()` row.** The binding happened while a pattern was parsed. It is
held to the standard of the same name written directly in the pattern:
seen through the pattern's canonical type. Read as one set per alias
template it would change with every added use. Where the alias's
result absorbs the binding (`void_t<decltype(X::s()), Y>`), the
directly written form absorbs it the same way; if the operand is not
instantiation-dependent it is §3.8's, and if it is, §4.4's. If the
enclosing template is instantiated the alias runs again under an
`Alias` key. Default arguments and concept-ids with partly concrete
arguments follow the same rule.

### 3.13 The decision table

The inputs are Kiln's answer of 2026-11-24. The supervisor rules.

| Kind | What Kiln can give | What Slip should ask for | The unit if the kind has rows only |
|---|---|---|---|
| `Alias` | a root as it is (the alias cache keeps it) | the root; the written type of an adjusted parameter in it (§3.4) | Form T |
| `DefaultArg`; the type of a non-type parameter | a root, before conversion | the root after the site's conversion (G5); the kind for the parameter's type (KR9 §5.4) | Form T |
| `PartialMatch` | a root once the argument list is interned | the root | Form T |
| `Satisfaction` | no root without three pieces of work | two of the three: the substituted requirements kept; the atom cache's entry holding its expression. Not the third (a failed atom is slot `1`) | Form T, and operators in constraints stay unseen until Kiln gives rows for nodes (KR9 §5.3, second form) |
| an operator, constructor or conversion inside any of these | in a root; in no row | — | a stage of its own on rows for nodes, before `Alias` |
| instantiated declarations (§3.7) | the AST as it is, where the probe finds the operand kept | the requirements of a requires-expression; `explicit(bool)`; a redeclaration's signature | `specs()` by region, for those three only |
| operands in ordinary code (§3.8) | the AST as it is | KR9 §5.8's confirmations | — |

**Recommended: Form R for all four kinds**, and to ask Kiln for the
two pieces `Satisfaction` needs.

- Concepts are where operators are (`a == b`, `os << x`,
  `f(args...)` in a requires-expression). `Satisfaction` on rows would
  leave exactly the lookups a migration moves unseen, and would need
  the node rows of KR9 §5.3 as well.
- One of the two pieces, the kept requirements, is needed in any case
  for a requires-expression in an instantiated body (§3.7).
- With all four kinds on roots, nothing of §3.5 and §3.6 is built in
  the digest: no owner, no region, no ordinals, and the region need
  not be designed in Kiln for the digest's sake.

**Mixing forms across kinds.**

- *In the key*: nothing. The key is the same in both forms.
- *In the stream*: the `form` byte, so that two units of one key read
  in different forms can never be equal. Changing a kind's form later
  moves `scheme`.
- *In the report*: nothing in the finding (the unit's name is the
  same). The listing of a unit's content differs: a walked root, or
  rows.
- *In the build*: this is the cost. One kind on rows needs the whole
  of Form T (§3.5, §3.6, the owner, the region, its tests and
  mutations) for that kind alone, and waits for the pin with WP-3143
  and for a region that Kiln has not designed.

So if Kiln declines the two pieces for `Satisfaction`, the choice is
between Form T for that one kind and waiting. **Recommended then**:
build `Alias`, `DefaultArg` and `PartialMatch` on roots; state
`Satisfaction` as a limit by name with its count
(`digest.substitution.unread.satisfaction`); and put the question of
Form T for it to the supervisor with Kiln's cost for the region.

A kind is never read both ways. Rows remain what the rename and the
namespace rule's edit planning read (`spec/edits.md` §9.4) in every
outcome. If a root's guarantees (G1 to G8) fail for a kind in a
stage's probes, that kind falls back to its last column.

## 4. Which unit differs, and what the report says

**The package's example.** `call<n::S>` takes the default argument of
parameter 2. Unit: (`substitution(3)`, parent `call`, parameter 1,
arguments `<n::S>`). Form R: the slot is the expression
`sizeof(n::S::s())` after substitution, and the walk writes the callee,
`n::S::s` before and `Base::s` after. Form T: the row for `s` has
target `n::S::s` before and `Base::s` after. The rename's declared
change maps the renamed member; it is still not `Base::s`. Finding:
`derived_changed`, unit
`bindings in default argument 2 of call for <n::S>`.

**A trait whose `swap` moved.**

```cpp
template <class T> void swap(T &, T &);
namespace legacy { struct X {}; void swap(X &, X &); }
template <class...> using void_t = void;
template <class T> T &ref();
template <class T, class = void> struct swappable { static const int v = 0; };
template <class T>
struct swappable<T, void_t<decltype(swap(ref<T>(), ref<T>()))>> { static const int v = 1; };
int u = swappable<legacy::X>::v;
```

A migration under `relocate legacy => :: acme` that moves `X` and
leaves `swap` behind:

```cpp
template <class T> void swap(T &, T &);
namespace acme { struct X {}; }
namespace legacy { void swap(acme::X &, acme::X &); }
template <class...> using void_t = void;
template <class T> T &ref();
template <class T, class = void> struct swappable { static const int v = 0; };
template <class T>
struct swappable<T, void_t<decltype(swap(ref<T>(), ref<T>()))>> { static const int v = 1; };
int u = swappable<acme::X>::v;
```

The trait says 1 both times: before through `legacy::swap(X &, X &)`
found by argument-dependent lookup, after through `::swap<acme::X>`
found by ordinary lookup. The rule is applied to the post-image and
undoes it, so both images have the unit (`substitution(1)`, parent the
partial specialisation, arguments `<legacy::X, void>`). The callee in
it is `legacy::swap(legacy::X &, legacy::X &)` in the pre-image,
unmapped, and `swap<acme::X>`, mapped to `swap<legacy::X>`, in the
post-image. Finding: `derived_changed`, unit
`bindings in the match of swappable<T, void> for <legacy::X, void>`.

It is the **only** finding. The post-image's
`legacy::swap(acme::X &, acme::X &)` maps to the pre-image's key and
has its digest (`spec/verify.md` §2.1, "Namespaces merge"), so no
declared unit differs; only the report of stale and kept names
(`spec/verify.md` §9.2) can speak of the function left behind. Without
this design the observer is `verified`.

**An alias template whose argument's member moved.**

```cpp
struct Base { static int s(); };
namespace n { struct S : Base { static int s(); }; }
template <class T> using R = decltype(T::s());
R<n::S> v;
```

Unit: (`substitution(4)`, parent `R`, arguments `<n::S>`). Form R: the
slot is the type `decltype(n::S::s())`; its canonical type is `int`
both times, and its operand, read by §3.7's walk, has the callee
`n::S::s` before and `Base::s` after. Form T: the row for `s`. Finding:
`derived_changed`, unit `bindings in alias R<n::S>`. The unit is
`R<n::S>`'s, not `v`'s: every use of `R<n::S>` in the translation unit
is behind the one finding.

A finding names the unit. What differs inside it is detail the walk
can list for a unit when asked; printing it is part of the first
stage that writes such a unit.

## 5. Inertness and `scheme`

- No existing unit's key, stream, digest or cause changes. The walk
  adds units.
- With no substitution of these kinds and no operand of §3.7, no unit
  is added.
- The derived groups of the files that hold the keyed declarations
  gain units, so those group digests and `tu` change. That is the form
  WP-140 took (`spec/digest.md` §11).
- **`scheme` moves at the first stage that writes a substitution
  unit, unconditionally** (ruled; the first version argued it could
  share 2). Call that number the table scheme. **A digest of the table
  scheme or a later one is always made with Kiln's key table on.** The
  setting is thereby recorded where digests are matched: two digests
  of one scheme were made the same way. The walk has no option to
  leave the table out: an image without it gets a sentinel (§6.2).
- The numbers (ruled, §13.1): WP-155 moves `scheme` to 3. The operand
  stage needs no table and can land before Kiln's stage 0; it closes a
  wrong equal, so it moves `scheme` by the rule of `spec/digest.md`
  §11, sharing the number in force if no baseline of it is recorded
  yet. The table scheme is always a new number.
- `crates/slip_digest/tests/written_on_off.rs` asserts today that the
  digest is the same with the written-reference table on and off. From
  the first table stage that holds only for the declared groups and
  for the units that exist today, and "off" gives the sentinel. The
  test's statement changes in that stage.

## 6. Gaps

### 6.1 Omissions Kiln reports

Kiln cannot list the keys it did not record, so the digest writes a
unit that stands for them.

| Kiln says | The digest writes |
|---|---|
| `Unrecorded::PrefixKeys { files }` | per file, one unit (`substitution(7)`) in that file's derived group, indeterminate, `Unaccounted("substitution/prefix-keys")` |
| `Unrecorded::ModuleKeys { module, files }` | per file the same, `Unaccounted("substitution/module-keys")` |
| `Unrecorded::ModuleKeysLeftOut { module, keys, rows }` | one unit in the derived group with the empty path, indeterminate, `Unaccounted("substitution/module-keys-left-out")` |
| `subst_keys_complete()` false and none of the three | one unit, indeterminate, `Unaccounted("substitution/incomplete")`: a defect of the facade, made loud |

An indeterminate derived unit is a finding on either side
(`spec/verify.md` §4 step 3), so an observer whose image has an
omission is never `verified`. A precompiled header made elsewhere
without the switch makes every observer that uses it unverifiable.
Accepted (ruled): it is loud and correct, and Slip makes its own
images with the switch on.

### 6.2 An image without the table

One unit, indeterminate, `Unaccounted("substitution/off")`. A digest
of the table scheme (§5) without the table does not exist as an equal
partner.

### 6.3 A key of a kind the walk does not write

- While stages are still to come, a key of a kind a later stage will
  write is counted, `digest.substitution.unread.<kind>`, and is part of
  the stated limit. The count is the exact form of "n substitutions of
  this kind were made and not looked into".
- Once the last stage of §10 is in (ruled): one unit per such kind,
  indeterminate, `Unaccounted("substitution/kind")`. A kind Kiln adds
  later is then loud, not silent.

### 6.4 Keys of a local declaration

A constrained generic lambda's call operator and a member of a local
class have no key (`crates/slip_digest/src/keys.rs` `is_local`). A key
of Kiln's table that names one has no parent to name. The walk writes
no unit and counts it (`digest.substitution.local`). Ruled: counted,
left out, named in the limit. An operand unit does not have this gap:
its parent is the unit whose walk met the operand.

| Counter | Meaning |
|---|---|
| `digest.substitution.keys`, `.keys.<kind>` | keys read from Kiln's table |
| `digest.substitution.units`, `.units.<kind>` | units written |

## 9. Mutations

Each must fail a named test.

Both forms:

- the arguments left out of the discriminator (a pair with `R<n::S>`
  and `R<n::S2>`); the parameter index left out of a `DefaultArg` key;
- a sentinel of §6 not written, or written without the flag (a facade
  test with a synthetic `Unrecorded`; an image without the table);
- a unit added to a declared group; an existing unit's digest touched
  (the inert test: every existing pair gives today's declared groups
  and today's units);
- an operand site skipped (one `operands-*` pair per site); the walk
  not stopping at a substituted parameter
  (`subst-<shape>-sugar-operand`); an operand unit written for an
  instantiation-dependent operand (an existing pattern pair gains a
  unit);
- a rule on a substitution key accepted;
- the outcome not written (`subst-unsatisfied`); the form byte not
  written (a unit test of the stream).

Form R: a slot's place not kept (`subst-disjunction`,
`subst-two-entries`); an empty slot not written
(`subst-nothing-bound`); a type root written without its operands
(`subst-alias`).

Form T: a row's target, owner, region or ordinal not written (§8's
pairs; `subst-two-entries` and `subst-disjunction` for the ordinal;
`subst-region` for the region); rows not sorted
(`subst-<shape>-order`); the ordinal counted over all entries, not the
dependent ones; a typedef written by reference, not by type (an
`equal` pair: `Base::t` and `n::S::t` both `int`); an unresolved row
or an unknown region treated as absent.

## 13. Open questions

Sixteen questions of the first version are ruled (§14). These are new
with this revision:

1. **`scheme` at stage O.** The ruling moves `scheme` to 3 "at the
   first stage that writes a substitution unit" and ties scheme 3 to
   the key table being on. Stage O writes operand units, needs no
   table, and can land before Kiln's stage 0 exists in the pin. It
   closes a wrong equal. **Recommended**: stage O moves `scheme` to 3
   by the same unconditional rule; the first table stage moves it to
   4, and "always made with the table on" is true of 4. Two moves,
   each voiding baselines once. The alternative is to hold stage O
   until Kiln's stage 0 is in the pin and move once.
2. **The condition for a key.** Kiln's test is static: the pattern
   has a dependent entry, filled by the parser. An operator has no
   entry. If `val<T>() << val<T>()` has no `DEPENDENT` entry (whether
   a template name with dependent arguments is one was not probed), a
   pattern whose only dependent selection is an operator gets no key,
   and a root's advantage is lost for it. **Recommended**: the
   condition is "the pattern is instantiation-dependent" (G8), which
   is as static. It is in KR9 §5.5 as a question; it refines what Kiln
   froze.
3. **A written type argument of a transparent alias in a root**
   (`void_t<typename L::t, typename R::t>` after substitution; §8,
   `subst-two-entries`). The canonical type is `void`. Form T sees the
   two type names as rows. For Form R to see them, a type root must
   also write the written arguments of an alias specialisation, as
   canonical types. **Recommended: yes, in a substitution unit's
   roots**; not in ordinary code, where it would write the spelling
   rule 2 leaves out (`void_t<int>` against `void`). This is the one
   place where Form R needs a rule the ordinary walk does not have.
   It also bears on the hazard "Alias templates with dependent
   arguments".
4. **An operand unit with several operands**, one of which a transform
   removes (§3.8): a finding with no moved name. **Recommended:
   accept**; the alternative, a unit per operand, has no stable key.
5. **Redeclarations in Form T** (§3.5): which redeclaration's entries
   a substitution of a signature or requires-clause reads, and whether
   the ordinal joins when a transform reorders them. It goes to Kiln
   with the region; it matters only if Form T is built.
6. **The form, per kind** (§3.13). **Recommended**: roots for all
   four kinds; ask Kiln for the kept requirements and the atom cache's
   expression; if Kiln declines those, `Satisfaction` is a named limit
   and the question of rows for it alone comes back with Kiln's cost
   for the region.
7. **The conversion a default argument's site applies** (§3.4). Kiln's
   root is the argument before conversion. Is the conversion's
   function (a converting constructor, a conversion function) in the
   promise? **Recommended: yes**, as any selection; asked as G5.

### 13.2 The second design review and the supervisor's rulings (2026-11-24)

The review of the revision probed Kiln at the pin, site by site (what
the AST holds in ordinary code, in a specialisation's signature, in a
member of an instantiated class, in an instantiated body), and ran
pairs through today's digest. It found seven shapes where a binding
moves and every unit both images have is equal under this design (B1
to B7) and eleven corrections (S1 to S11). Its evidence is kept
outside the repository. **Where a ruling below differs from §3.4,
§3.7, §3.8, §3.11 or §13.1, the ruling holds**; the stage that builds
a part lands the ruled text in the specs.

**B1. An array bound is not a site at the pin.** Kiln keeps the bound
as a value only, for every declarator: in ordinary code, written in a
template and not dependent, and after substitution
(`kiln/crates/kiln_sema/src/decl.rs` builds the type with no
expression). Only a dependent bound in a pattern keeps its expression.
Stage O does not claim site 3. Of §3.8's example, `y` and `a` are
closed and `buf` is a limit that `spec/digest.md` §2.3 names. Kiln is
asked for the bound as written on every constant array type whose
bound was an expression (KR9 §5.11); the site is built at the pin that
has it (stage e).

**B2. Every declaration of the entity.** A unit's stream is read from
one declaration; an operand is written on each. The operand unit of an
entity reads the operands of every declaration of it the translation
unit has, in declaration order. A declaration with at least one
written operand gives a group (its count, then its operands); a
declaration with none gives nothing. A transform that adds or removes
a declaration with an operand changes the unit (ruling 4's class).

**B3. A member template of an instantiated class.** Its partly
substituted signature is in its unit's key, so a name that moved in it
gives one unit on each side only and no finding. Ruled: the
`definition` unit of a class made by instantiation writes the keys of
its member templates (every member that is a template and a derived
unit), sorted, as `members-other` does for declared members. This is
the one existing stream that changes (§5's first bullet has this
exception). The stage proves that such a key maps: a correct
relocation of a namespace the signature refers to must leave the
class's unit equal. If the key cannot be mapped, the stage stops and
reports. §3.7's "instantiation-dependent" has two populations: a
pattern nobody substituted (§4.4's spellings), and a partly
substituted member of a specialisation (this rule).

**B4. The sites are the holders of a written type.** §3.7's table
named seven fields; the walk is defined instead by every place that
holds a type as written or a written argument list:

- a declaration's written type: return, each parameter before
  adjustment, variable, field, typedef and alias, base specifier,
  friend;
- a default template argument;
- the argument list of an explicit or partial specialisation and of an
  explicit instantiation;
- in an expression: the template arguments and the qualifier of a
  reference to a declaration, of a member expression and of a
  concept-id; the written type of a cast, of `sizeof`, `alignof`,
  `typeid`, a type trait, `new`, a compound literal;
- a nested-name-specifier that names a type (probed by the stage).

Each holder is a row of the completeness test. An operand written in a
unit's body belongs to that unit's operand unit, in the walk's order.

**B5. Ruling 3 of §13.1 is revised: the written argument list of an
alias specialisation is a site wherever a written type is read**, in
ordinary code and in instantiated declarations (site 8): per argument
its canonical form, then the operands inside it. It is always written
(S5's test does not apply: the name that moved shows only in the
canonical type, `void_t<typename T::t>` with `T::t` now `long`). The
alias template's own name stays unwritten (a type name is compared by
its type). `void_t<int>` against `void` in ordinary code is a
one-sided operand unit and no finding. Stage O counts these operands
on the corpus; if they are the bulk of the new units the supervisor
rules again.

**B6. A `Satisfaction` slot is a leaf of the constraint-expression as
Kiln checks it** (split at `&&`, `||` and parentheses), not an atom of
the normal form. A leaf that is a concept-id holds the substituted
concept-id: its written arguments are read after substitution (with
the stop at a replacement), and it leads to the concept's own key.
`requires Big<decltype(make(T()))>` is then a slot that holds `make`.
This agrees with Kiln's design pass (KR9 §5.10) and corrects §3.4's
"`k` 2"; the arguments, the fold, the partly checked concept-id and
the nested requirement are asked in KR9 §5.11.

**B7. Three claims of §3.7 and §3.11 narrowed.**

1. "A candidate that lost has a specialisation" is true among
   templates. A template candidate that Kiln does not instantiate
   because a non-template is the better match has no declaration in
   Slip's parse; that is the limit of the compatibility level that
   `docs/wp/WP-155.md` states, and Kiln is asked whether it deduces at
   all there.
2. An adjusted parameter of an instantiated function has no written
   type at the pin (`decltype(T::s()) q[2]` is `int *`). A limit by
   name until Kiln keeps it (asked).
3. A pack index after substitution is absent at the pin. Site 5 has no
   population; its number is reserved. A limit by name (asked, low).

**S1.** Site 7 (`explicit(e)`) is dropped: the unit's own stream walks
it today. The operand sites are a class of their own in
`spec/digest-kinds.md`, listed by name; "`written`, `out` and holds an
expression" does not find them.

**S2.** The pair runner's `equal` stays strict. A pair whose only
difference is a one-sided operand unit (`equal/_/decltype-non-dependent`,
`equal/TypeView/Decltype`) moves to a class of its own whose
expectation is: every unit both sides have is equal, the one-sided
units are operand units, `verify` gives no finding. The stage lists
any other pair that changes class before changing it; each is a
ruling.

**S3. Operands are read only from what is written in the unit** (B4's
holders): never from the type of an expression, never from a deduced
type. For a variable declared with a placeholder the stage reads what
tells that at the pin (the type's location); if nothing does, the
stored type is read, the duplicates are a stated cost, and Kiln is
asked for a mark. The stops of §3.4 hold in instantiated declarations
as in roots (a substituted parameter's replacement; a specialisation's
own argument list).

**S4.** For a specialisation, the operand of its `noexcept` belongs
only to the operand unit of its resolved `exception_spec` unit, never
to the specialisation's own.

**S5. An operand is written only if its walk writes a reference to a
declared entity or a selection** (a callee, a constructor, a
conversion, an operator function); the count counts those. A unit with
none has no operand unit; `noexcept(true)` and `array<char, 4>` add
nothing. The replacement of a substituted non-type parameter is not
walked. A non-dependent operand of a pattern's member is written on
each instance's member too; the stage measures it.

**S6.** An operand is walked in its parent's state: the parent's
parameters and locals have the numbers the parent's walk gives them at
that place, `this` is the parent's. A parameter of a function type
that has no function declaration is numbered by the depth of its
function type in the holder and its index.

**S7.** B4's holders apply inside an operand: a nested operand is its
own entry, right after the operand that holds it, and is counted. Each
written operand is written once: where a function has parameter
declarations the operands are read from them and not again from the
function's type. A lambda in an operand is `spec/digest.md` §4.3's
case for the operand unit as for any unit.

**S8.** `spec/verify.md` §4 step 3 gains the argument for an operand
unit: one side only, with a parent both images have, means the operand
was removed with its names or no longer refers; nothing binds
otherwise.

**S9.** Form R's guarantees are completed in KR9 §5.11. One is a
limit and not a guarantee: a key's root is that of the first run
(Kiln caches); a compiler that substitutes an alias specialisation
again at a later use, after a declaration was added to an associated
namespace, can bind the second use otherwise. Named in
`spec/digest.md` §2.3 by the first table stage, beside the
compatibility level.

**S10.** The rule for `scheme` is `spec/digest.md` §11, not §8 (§5 and
§13.1 cite it wrongly).

**S11.** KR9 §5.8's third question is answered by the probes: a
bit-field's width, an enumerator's value, `alignas(e)` and an
attribute's argument are kept and walked today.

Notes taken: an operand unit of an indeterminate or colliding parent
inherits the cause (as §3.3 says for substitution units); the typedef
stop is implementable at the pin; every member of an instantiated
class has a derived unit of its own, so each operand has a parent.

Stage e's list grows by B1 and B7's items 2 and 3. Stage O's package
is `docs/wp/WP-156.md`.
