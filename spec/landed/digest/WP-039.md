# WP-039 — the declaration header, the names and the keys

What `crates/slip_digest` reads into digest §3, §4.3 and digest-kinds
§3.2, §5.3, §10.2 where the specs leave it open, found while testing the
header, the names and the keys.

## Unnamed classes and enumerations (§3.3)

- **The first declarator is the first in source order.** In
  `typedef struct {} *P, *T;` the class is named by `P` (the typedef name
  for linkage purposes is absent: neither declarator names the class
  itself). Writing `*T, *P` instead names it by `T`: the class's key
  changes, and `differ/_/key-typedef-unnamed-first-declarator-order` holds
  it. This is the conservative reading of "else its first declarator": the
  order of declarators is a fact of the source, and a tool that reorders
  them changes which name the class has, so the key says so.
- A typedef name for linkage wins over the first declarator
  (`typedef struct {} S, *P;` is named by `S`); a declarator that changes
  after the first does not move the class; pointer, reference, array and
  member-pointer declarators all name it (`declarator_of` looks through
  them). These are `differ/_/key-typedef-*` and `key-unnamed-*`.

## Name-independent members (§3.3)

Two non-static data members named `_` in one class (P2169,
[basic.scope.scope]/5; Kiln accepts them in every mode, with a warning
before C++26) are two entities with one name, and §3.3 gives a `field`
no discriminator, so they had one key: the walk marked the collision
and both were indeterminate (`differ/DeclMisc/0-name-independent`). A
name-independent field's discriminator is now `uv`, its ordinal among
the name-independent members of its kind and name in its class, in
member order (`keys.rs` `name_independent_ordinal`). The ordinal is
present for the first one too, so adding a second leaves the first's
key alone; removing the first moves the second, as removing an unnamed
type moves the ordinals after it. Its display name ends
` (name-independent n)`. A table correction for digest-kinds §3.3
(`field`: "the ordinal, for a name-independent member") is a follow-up.

The `0-name-independent` bit follows from the name and the scope (every
member named `_` has it, no other declaration that has a key does), so
no pair flips the bit alone: its test shows the member added, and the
bit written as a constant is a mutation no pair test can see.

## Display names (`names.rs`)

Display names are in no digest; they are what a verify report prints
and what an `expect.txt` line names, so two units of one output should
not share one. The forms:

- a function template: `template <class, int, template <class> class,
  class...>`, then its return type (not for a constructor, destructor or
  conversion function), then the qualified name and the pattern's
  signature: `template <class> void f(type-parameter-0-0)`;
- a member-like friend: its befriending class first,
  `A<int>::friend template <class> void m(type-parameter-0-0)`;
- a non-template deduction guide: its signature,
  `<deduction guide for S>(char)`;
- an unnamed class or enumeration: by what names it (§3.3),
  `(anonymous struct for P)`, else its ordinal, `(anonymous enum 1)`;
  its members are written below that name;
- an unnamed field or variable of an anonymous class:
  `(object of (anonymous union for a))`; an unnamed bit-field
  `(unnamed n)`;
- a holding variable of a structured binding: `x (holding variable)`;
  the decomposition itself `[a, b]`;
- the repeatable kinds: `<using n::f>` (an inheriting constructor
  `<using P::P>`), `<shadow n::f()>`, `<using_directive n>`,
  `<using_enum E>`, `<friend f()>`, and the content-keyed `<static_assert>`,
  `<asm>`, `<consteval_block>`, which have no printed content: two of
  them in one scope share a name, and the uniqueness test accepts it.

Names print no expressions. What differs in an expression alone (a
requires-clause, a null pointer's type in an argument, which Kiln's
argument printer writes as `nullptr`) gives two units one name; the
uniqueness test lists each such directory (`tests/determinism/keys.rs`
`SAME_NAME`).

## The uniqueness test

`tests/determinism.rs` `keys_and_names_are_unique` checks, on both sides
of every directory of `differ`, `equal`, `demand` and `indeterminate`
(pending ones included), that no key is counted a collision
(`digest.collisions`), that no key holds two digests unmarked, and that
no display name names two keys. It reuses the first parse of the
determinism test (one walk, shared through a `OnceLock`), so it costs no
parse of its own. What is known is listed per directory with its reason
(`SAME_KEY`, `SAME_NAME`); an entry that no longer matches fails, so the
lists only shrink.

## Collisions accepted

Two entities that differ only in an expression the key profiles (a
trailing requires-clause, a type-constraint, a partial specialisation's
requires-clause, a decltype operand, a dependent array bound) have one
key while the expression area is pending: both profile as
`Pending(Expr)`. The walk marks the key a collision, so both units are
indeterminate and nothing is called the same falsely. The probes are
`# pending`, `# needs: expr`.

## The forms of the row tests

The pair tests of this package are generated by
`crates/slip_digest/tests/gen/decls.py`; each test's comment says its
form.

- `DeclKind`: "kind changed" where C++ allows one key with two kinds
  (`Field` against `IndirectField`); "added" for most. A template
  parameter's kind is in the template head, which is in the key
  (§3.3), so `TemplateTypeParm` against `NonTypeTemplateParm` is a
  removed and an added template, not a changed one. `ParmVar`,
  `UsingShadow`, `ConstructorUsingShadow`, `LifetimeExtendedTemporary`
  and `Label` are shown through the unit that holds them; `Empty` and
  `AccessSpec` are `equal`. An "added" test fails when the kind is
  skipped only if the unit's stream is otherwise empty, and never when
  the tag is written as another kind's: that is the form the WP accepts
  for kinds that cannot share a key.
- `DeclNameKind`, `DeclName` `0-kind`: two names that differ in the kind
  alone, the payload equal (`_x` against `operator""_x`, `S()` against
  `~S()`), so a kind written as a constant makes the two keys meet.
- `DeclName` `Constructor.0-payload`, `Destructor.0-payload`,
  `DeductionGuide.0-payload`: a key has no payload for these (§3.2), and
  no stream writes a `name` at the pin (`Walk::write_name` has no
  caller), so the class or template is reached through the parent key
  or the discriminator: the tests rename the class.
- `OverloadedOperator`: each operator against the next of the same
  signature in its group; a tag written as a constant makes the two
  keys meet. The unit test `keys::tests::the_key_of_an_operator_holds_its_row`
  checks every row's key name, and that no two share one.

## Rows left in `untested.txt`

- `TagKeyword/None`: Kiln's canonical dependent name writes `None` as
  `Typename` (`kiln_ast/src/types/canon.rs:899` `canonical_keyword`), and
  `TagKeyword` is written only from a canonical dependent name
  (`types.rs` `DependentName`): the row is never met. Table correction:
  `written | out | as Typename`. `equal/TagKeyword/None` shows it.
- `TagKeyword/Interface`: never produced in C++ mode
  (`kiln_ast/src/types/kinds.rs:882`).
- `ModuleOwnership` (all five rows) and `DeclMisc/0-module-ownership`
  (pending, `needs: kiln`): Kiln sets no module ownership:
  `DeclMisc::with_module_ownership` (`kiln_ast/src/decl.rs:512`) has no
  caller, so every declaration is `Unowned` and no pair can differ.
- `ExcSpec/Dynamic`, `Dynamic.0`: a dynamic specification is kept only
  before C++17 (`TypeContext::proto` reads `exc_protos` then; from C++17
  the canonical form is `None`, `kiln_ast/src/types/canon.rs:657`), and
  the snippet runner has no mode before C++17
  (`crates/slip_kiln/src/snippet.rs:435`). `equal/_/exc-dynamic-is-none-in-cxx17`
  shows the C++17 fact.
- `DefinitionBits` `0-pod`, `0-trivially-relocatable`,
  `0-has-inherited-assign` and `FnSpec/0-immediate-escalating`: set only
  when a BMI is read (`kiln_sema/src/bmi_image.rs:890`, `:927`), which
  needs an import.
- `ParamData/flags-static-array`: C only (`int a[static 4]`,
  `kiln_sema/src/declspec.rs:668`); the runner has no C mode.
- `VarEvalState/Evaluating`: cannot outlive the translation unit; the
  unit is `Unaccounted("VarEvalState/Evaluating")`
  (`spec/landed/digest-kinds/WP-026.md`).
- `StringEncoding/Wide16`: a 16-bit `wchar_t`, which the x86-64 Linux
  target has not (`spec/landed/digest-kinds/WP-028.md`).
- `DeclNode/ConstevalBlock.data`: WP-038's, with `DeclKind/ConstevalBlock`.
