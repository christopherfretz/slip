# WP-024 — the framework of the walk, keys, units and types

What `crates/slip_digest` reads into `spec/digest.md` and
`spec/digest-kinds.md` where they are silent, and where the walk departs
from the letter of WP-024. Each choice is the conservative one: where a
fact could not be settled, the unit is indeterminate.

## Streams and causes

- **Cause priority.** A stream keeps the first cause it meets, except
  that any cause other than `Pending` replaces `Pending`
  (`Stream::indeterminate`, `units::merge`). So a unit's reported cause
  is `Pending` only if nothing else is wrong with it, and an
  `indeterminate` test can tell a real cause from an unwritten area.
- **The pending placeholder** is `uv 0` (no tag is 0, §1.4), written by
  `Stream::pending(area)`; WP-024's text calls it `w.pending`. Every
  pending function has its final signature.
- **Depth.** Types, keys, `Nns`, template names, argument lists, template
  heads and declaration streams each enter one level; past 200 levels
  the stream is indeterminate with `Unaccounted("walk/depth")` and a
  fixed placeholder is written. A result computed below such a hit is
  not memoised (its cause depends on where it was reached from).
- **Counters.** Besides §12 and `digest.indeterminate.<cause>`, the walk
  adds `digest.indeterminate.pending.<area>`, so that the split of
  `Pending` by area is visible while areas are missing. The per-cause
  counters count indeterminate keys (one cause per key, `Output::causes`);
  `digest.indeterminate` counts units after the merging of §11.

## Types

- **The view read.** §4.1 says `canonical_view(c)`. Kiln's
  `canonical_view` strips an `ExtQual` node (it returns the view of the
  base), which would lose the address space. The walk reads
  `view(canonical(q).ty())`, the canonical node itself, and writes
  `ExtQual` as its row says. Every other variant is the same either way.
- A canonical node that is sugar, or a field "sugar only" present in a
  canonical node, is `Unaccounted("<Table>/<row>")`.
- `FuncInfo` bits 25 and above (no row) are `Unaccounted("FuncInfo/0")`;
  `0-no-proto` is `Unsupported`. `0-regparm` is written as
  `uv` 0 when absent and `n + 1` for `regparm(n)`, so that `regparm(0)`
  and its absence differ.
- `ParamAbi` has no generated `row()` (`pin=none`): the walk matches it
  exhaustively onto the table's constants.
- A function declaration's `ty-type` is the type digest of its declared
  type with the outermost function type's exception specification
  written as `None` (memoised apart from the plain digest).
- `Deferred(d)` met in a declaration's own `ty-exception-spec` (a
  function outside the deferrable class) is
  `Unaccounted("ExcSpec/Deferred")`; in a type it is the tag and the
  `Ref` of `d` (§4.2 rule 4).

## Keys

- **Local entities.** A class, enumeration or closure type inside a
  function body, an initialiser, or a requires-expression has no key yet:
  its key is `Local(n)` in the unit that declares it, which is the local
  area. Until it lands, a `Ref` to one is `Ref::none` with
  `Pending(Local)`. A closure type is always local. Parameters, local
  variables and bindings get local ordinals (`local::ordinal`), first
  met first, per unit.
- **Block-scope externs** (`misc-local-extern`) take as parent the
  namespace around the function, skipping the function. *Kiln conflict:*
  Kiln never sets `DeclMisc` `0-local-extern` (`with_local_extern` has no
  caller), so the walk also takes as local-extern a `Function`, or a
  `Var` declared `extern`, whose semantic context is a function, as
  `kiln_abi::mangle::local_extern_ns` does; the bit it writes is that
  reading, merged over the declarations.
- **Parents** may be a namespace, class, enumeration, class template (the
  pattern's context is mapped to its template), specialisation or
  partial specialisation. Any other context is
  `Unaccounted("key/parent")` and the entity has no key.
- **Using-declarations.** The discriminator of all three kinds (`Using`,
  `UnresolvedUsingValue`, `UnresolvedUsingTypename`) is an optional
  `enum Nns` of the qualifier.
- **Function templates.** The discriminator is the template head, then
  the function discriminator of the pattern written inline (not hashed
  apart), then the return type (`type?`).
- **Unnamed entities.** Ordinals of §3.3 start at 0 and count only the
  entities named by ordinal, classes and enumerations apart from fields;
  a scope is numbered once over all its redeclarations, first first,
  looking through transparent scopes. "Named by the next declarator"
  requires that the next sibling names it through its type (pointer,
  reference, array and function types are looked through); otherwise the
  first named member names it.
- **Injected class names** are not declarations in Kiln (only a sugar
  type), so they need no rule.
- **Specialisation keys** use `SpecInfo::args` in canonical form; a
  partial specialisation's key adds its own head and uses
  `PartialSpecInfo::canonical`.
- A `TemplLink` of kind `DependentFriend` is
  `Unsupported("TemplLinkKind/DependentFriend")`.

## Units

- Content-keyed units whose payload is pending all have the same digest
  in a scope (the placeholder), so two of them in one scope merge under
  §3.4's repeatable rule; they are indeterminate with `Pending`, so
  nothing relies on the merge.
- `UsingPack`, `FriendTemplate`, `ImplicitParam` and
  `ImplicitConceptSpecialization` (`unbuilt` or unsupported in §5.2) are
  not units; a `Ref` to one is `Ref::none` with `Unsupported`.
- Members of a builtin (`__va_list_tag`'s fields) are on demand, as the
  builtin is.
- **Implicit declarations.** A declaration that is implicit in Kiln is
  derived (§2.2), except a `UsingShadow`, a `ConstructorUsingShadow` and
  an `IndirectField`: Kiln marks them implicit, but they are declared by a
  written using-declaration or anonymous member, so they are declared
  units. An implicit function or deduction guide is derived if it has a
  body and on demand otherwise; any other implicit declaration (the
  unnamed field of an anonymous member, a builtin's parts) is on demand.
- **An invalid member** makes its own unit indeterminate (`Error`), not
  its class's, while `RecordData` is pending: whether a class's digest
  holds its members' invalidity is the area's to say.
- `DeclMisc` `0-definition` is read as "the entity has a definition"
  (`Ast::definition`), not from the cache bit, which "clear means ask the
  group". `0-implicit` is set if every declaration is implicit; `0-injected`
  and `0-access` come from the declaration read; `0-friend`,
  `0-local-extern` and `0-module-ownership` are merged as their rows say.
  A friend field holding 3 or an ownership field holding 5 to 7 is
  `Unaccounted`.
- **The deferrable class** (§11.2) is decided where stored facts decide
  it: every destructor, and every function whose declarations are all
  implicit or that is implicitly defaulted, is of the class. An
  explicitly defaulted function (whether a specification was written is
  not stored once it is resolved) and an implicit instantiation (its
  pattern's operand is an expression) write `Pending(Demand)` in place of
  `ty-exception-spec`.
- A template parameter in a template head is written as its `DeclNode`
  rows (kind, flags, misc, `ty-type`) and its `TemplateParmInfo`; its
  default argument (a `ColdDeclData` row) is not part of the head, so a
  key does not change when a default is added.

## Names

`Output::names` prints canonical types, so a template parameter is
`type-parameter-D-I` as Kiln's printer has it; a content-keyed unit is
its scope and `<kind>`; the order unit is `<order>`.

## The pair tests

- `t.cpp` is parsed under the path `main.cpp` (so are `a.cpp` and
  `b.cpp`), so that both sides' main-file groups have the same subject
  path.
- A test whose `expect.txt` has the line `# pending` is skipped and
  listed by its runner.
- The `indeterminate` runner compares the `indeterminate` lines with the
  units flagged for a cause other than `Pending`; units flagged only
  `Pending` are ignored.
- `tests/tables.rs` ignores `tests/<root>/_/`.
- **`matches!`.** The rule "no `_` and no `..` over a Kiln enumeration"
  is read to cover `matches!`, which has an implied `_` arm: the crate
  compares with `==` or writes a full `match`. The pair-test helpers
  (outside the walk) use `matches!` over strings and over `Cause`, which
  is this crate's own.
- `DeclNode` `IndirectField.data` has no pair test yet: the chain is a
  `ref*` of fields whose digests are pending (`FieldData`), so no edit of
  the chain alone is visible; the row stays in `untested.txt`.
- **Determinism across processes.** `tests/determinism.rs` reruns its own
  binary with `SLIP_DIGEST_CHILD=<dir> --exact child`: the `child` test
  prints the `Debug` form of both sides' `Output` between marker lines,
  and the parent compares it with its own. One directory in three goes
  through a child, to stay within the time budget.
