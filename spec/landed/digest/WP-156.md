# WP-156 — operand units

`docs/wp/WP-156.md`; stage O of `docs/wp/WP-153.md`. The design is
`spec/landed/digest/WP-153.md` §3.7 and §3.8 as ruled in its §13.2.
The ruled text is `spec/digest.md` §2.3 ("What the operand units
close"), §2.4 and §12, `spec/digest-kinds.md` §3.1, §3.2, §5.5 and
§11.11, and `spec/verify.md` §4 (the argument for a one-sided operand
unit) and §6.1 (its name and trace). This file records how the walk
does it and what it chose where the design left a choice.

## 1. The walk

`crates/slip_digest/src/operands.rs`. A unit's operand state
(`UnitState::operands`) is begun where its stream is begun
(`units::write`, `Walk::content_hash`, `demand::write_part`,
`local::compute`) and finished after the stream, still in the unit's
state, so the entries are written with the parent's numbering, `this`
and locals (S6). Three hooks collect:

- `operands::decl` at every declaration the stream writes
  (`Walk::decl`): the declaration's signature (§2.4's holders) when it
  is not one of the entity's own declarations, which `begin` reads as
  one group per declaration (B2);
- `operands::expr_node` at every expression node the stream writes
  (`expr::write_node`): the holders in an expression (the template
  arguments and qualifier of a reference, a member expression, a
  concept-id; the written type of a cast, `sizeof`, `alignof`,
  `typeid`, a type trait, `new`, a compound literal);
- `operands::bases` and `operands::exception_spec`: a class's base
  specifiers where its `definition` unit holds them, and a
  specialisation's `noexcept` in its `exception_spec` unit only (S4).

`scan` walks a written type and stops where §2.4 says. `finish` writes
the groups: per entry `uv site`, then the expression (`expr::child`)
or, for site 8, the canonical arguments; an entry of sites 1, 2, 4 and
6 is kept only if `Walk::op_refs` moved while it was written or it is
indeterminate (S5). The nested holders met while an entry is written
become entries right after it (S7). The own-spelling list of what the
entries met is the operand unit's (`own_spelling::write_unit_list`
after the entries); the parent's was written with the parent.

## 2. Choices

1. **`TypeRef::refs`.** A type digest is memoised across units. A memo
   hit adds the references the type's stream wrote to `Walk::op_refs`,
   so whether an operand is written (S5) does not depend on which unit
   computed the type first.
2. **The name.** `Written::operands` holds the parent's key kind; the
   unit is named as its parent and `::<operands>`
   (`v::<operands>`, `S<N::A>::<definition>::<operands>`).
3. **A content-keyed parent.** Its operand unit is collected while its
   content digest is computed (`Walk::content_hash`, memoised) and kept
   in `Walk::content_operands` until the unit is written: the content
   digest is computed once.
4. **Numbering.** The numbering of an owner (`local::compute`) collects
   the same operands and walks them after the owner's own stream and
   before its parts (`operands::number`), so a local type or a lambda
   in an operand has the owner's numbers. A lambda in a closure's call
   operator's `noexcept` is reached through `operands::member` from
   `local::member` in numbering mode.
5. **A variable declared with a placeholder.** Kiln's `VarSpec`
   placeholder (`VarPlaceholder`, at the pin since WP-163's Kiln) tells
   it: such a variable has no written type, and is counted
   (`digest.operands.deduced`); no duplicate is written.
6. **A default template argument.** A default type argument is
   scanned; a default non-type argument is walked by the unit's own
   stream (`templ::head`) already.
7. **B3.** `decl_class::members` lists, in `members-other`, the members
   of a class made by instantiation (not local) that are member
   templates (a class, function, variable or alias template) and
   derived units, sorted with the rest.
8. **Causes.** An operand unit inherits its parent's cause
   (`operands::inherit_causes`, by key). A parameter of a function type
   with no `ParamData` is `Unaccounted("operands/param")`; an operand
   unit past its bounds is `Unaccounted("operands/limit")` (never met).
9. **Counters** (`digest.md` §12) are written only when not 0, so a
   translation unit with no operand writes none and no existing golden
   counter list changes.

## 3. The limits

Each is pinned by an equal pair whose comment names it,
`crates/slip_digest/tests/equal/_/limit-operands-*`: an array bound
(B1), a pack index (B7.3), `explicit(e)` of a function template
specialisation, and a template candidate that lost to a non-template
(B7.1). Out of scope and also a limit: the requirements of a
requires-expression in an instantiated body.

Two limits the work package named are closed at the pin, found while
writing their pairs: an adjusted parameter of an instantiated function
(B7.2; `ParamData::original_ty` keeps the type before adjustment after
substitution, `tests/differ/_/operands-adjusted-parameter`), and the
written type of a compound literal of array type (Kiln's
`compound_literal_written`, `tests/differ/_/operands-expr-holders`). A reflection operand (`decltype(^^int)`) is indeterminate
(`Unsupported("ExprKind/CXXReflectExpr")`), as any reflection is.
