# WP-044 — the Kiln pin moves to `main` (`83566cc47`)

What `spec/digest-kinds.md` and `crates/slip_digest/src/` took from the
move of the `kiln` submodule from `62d190007` (`slip/kf1`) to
`83566cc47172ea2e18c194b9611d291fc8994a34` (Kiln's `main`). Kiln sites
are at the new pin; paths are under `kiln/crates/`.

## `slip_kiln`

- `FrontEndError` is `#[non_exhaustive]`: `parse::run` maps every reason
  it does not classify as a failure of the worker, its message as the
  error (`Panicked`, `Thread`, and any later one).
- `Args` has seven new fields (`dump_written_refs`, `decl_extents`,
  `dump_decl_extents`, `host_call_test_handler`, `host_calls_visible`,
  `env`, `no_side_outputs`): `snippet::io_change` refuses a change to any
  of them, as it does every field it does not know to be safe.
- Behaviour-neutral: `FrontEndOptions` `pch_probe` and `environment`
  (defaults kept), `Consulted` `content`, `entry_args` setting
  `no_side_outputs`.
- `tests/parse.rs`: the reproducers of `docs/requests/KD1` §1, §2 and of
  KD2 parse `ok` with no diagnostics; the written-reference table and the
  declaration extents are off and empty.

## Rows removed

- `ColdDeclData` `instantiated_from` (removed by Kiln; it was never
  filled). Every declaration's stream loses its empty form, one `uv 0`,
  so every digest changes once with the scheme; no unit changes against
  another. The unit test `instantiated_from_is_never_filled` of
  `decl_scope.rs` went with the field it tested.
- `StmtNode` `flags` (`kiln_ast/src/stmt.rs:213`: "the per-kind flags
  byte was always zero and is gone", WP-2026).
- `TemplLink` `DependentFriend.0-index`. `TemplLinkKind` `DependentFriend`
  keeps its row as `unsupported | unbuilt | retired` (§1.4), so its tag 4
  is not reused; Kiln leaves tag 4 unused too
  (`kiln_ast/src/decl.rs:649`: "A raw link with tag 4 reads as none").
  The arms for it in `keys.rs`, `order.rs`, `units.rs` and `templ.rs`
  went.

## Rows added

- **`ColdDeclData` `using_shadows`, `shadow_using`: `out`** (confirmed).
  A shadow is a unit, keyed by its target (`keys.rs` `KeyKind::
  UsingShadow`, `ast.using_target`), and a using-declaration is a unit
  keyed by its qualifier. The access a class-scope using-declaration
  gives is the shadow's own `DeclMisc` `0-access`: Kiln sets it on each
  shadow (`kiln_sema/src/using.rs:955-957` for `UsingShadow`, `:740` for
  each `ConstructorUsingShadow` of an inheriting constructor). No
  finding.
- **`ColdDeclData` `closure_owner`: `in`, `keyed`** (`kiln_ast/src/
  decl.rs:1794`). The table row only: closures stay
  `Pending(Area::Local)` until `docs/wp/WP-040.md`; its test is
  `# pending`, `# needs: local`.
- **`ColdExprData` `member_overload`: `in`, `record OverloadedMember?`**,
  after `member_extra` (`kiln_ast/src/expr.rs:1463`), and the table of
  `OverloadedMember` (`expr.rs:1182`): `qualifier` `enum Nns?`,
  `template_args` `enum ArgView*?`, `naming_class` `ref`. An entry on an
  expression that is not a `MemberExpr` is `Unaccounted
  ("ColdExprData/member_overload")`; Kiln asserts the kind
  (`expr.rs:2075`). Template arguments are absent when none were
  written or they are dependent: the access is then a
  `CXXDependentScopeMemberExpr` (`expr.rs:1186-1189`).
- **`TemplateTables` `oper_lookups`: `in`, `record OperLookups`**
  (`kiln_ast/src/templates.rs:309`), written in `templ::expr_maps` after
  `expr_nns`, and the tables of `kiln_ast::oper_lookup`: `OperLookups`

  (interning; the last two `snap(skip)`), `OperSetId` `0` and `SetSpan`

## Pins

The twelve types Kiln's WP-2120 made public are pinned at compile time
in `src/tables.rs` and left `tests/tables/pins.txt`. The entries
`types::args` and `types::node` of `REEXPORTS` (`tests/tables/
generate.rs`) went, since those modules are public and not all their
types are re-exported (`ListEntry`, `ArgTable`, `Store`): the generated
file names `types::args::ArgKind`, `types::node::TypeNode` and the like
by their public module. The unit test `snake_case` checks the mapping
on `types::nns`, still private, and checks that `types::node::Store`
keeps its module.

## Tests

`differ/ColdExprData/member_overload`, `differ/OverloadedMember/
{qualifier, template_args, naming_class}`, `differ/TemplateTables/
oper_lookups`, `differ/OperLookups/by_expr`, `differ/OperCandidate/decl`;
`# pending`: `differ/AttrNode/CLEANUP.a` (stmt),
`differ/ColdDeclData/closure_owner` (local). In `attrs.rs`:
`s10_1_cleanup_is_the_function`, and `s10_1_unaccounted_words` for an
unchecked node and for a `CLEANUP.a` that is no declaration.

Each differ test was seen to fail with its row's code taken out, except
`OverloadedMember/naming_class`. The naming class is the qualifier's class
for a qualified name and the object's class otherwise
([class.access.base]/5, `expr.rs:1190-1191`), so a source cannot change
it without changing the qualifier or the object expression, which are
written. The row is kept `in` as decided; its test shows the pair
differs. The tests that need the access to stay overloaded use a
namespace-scope variable template with a dependent argument: a template
member's body is a statement (WP-034), and a default member initialiser
or `sizeof` reaches expression kinds still pending (WP-035, WP-037).

`indeterminate/AttrNode/CLEANUP.a` went with the decision it tested
(`unsupported`); `differ/AttrNode/CLEANUP.a` replaces it.
