# WP-026 — slip_digest: the payload records of functions and variables

What `crates/slip_digest/src/decl_func.rs` and `local::write_decl` read
into `spec/digest-kinds.md` §2.3, §2.4, §5.4, §5.6 (`ScopeData`) and §11.9
where they are silent. Each paragraph is one decision; the tests named
back it.

## Order of the rows

- `FunctionData` writes `params`, `body`, `spec`, `templ` in table order,
  then the language linkage of §5.6 (`enum LinkageLang?`, then
  `aux-braceless` as `bool` when present). `VarData` writes `init`,
  `spec`, `templ`, then the linkage. The linkage is last because the
  table's note puts it after the record's rows. The tests are
  `differ/ScopeData/*` and `differ/LinkageLang/*`, plus the unit test
  `decl_func::tests::linkage_is_an_optional_language_then_braceless`.
- The `bit` rows of `FnSpec` form one flag word, in table order, at the
  place of the first bit row (`0-inline`, after the `0-storage` tag). The
  `0-constexpr-kind` and `0-defaulted` tags follow the word, in table
  order. `VarSpec` likewise writes the `0-storage`, `0-tls` and
  `0-init-style` tags, then one word of its seven bit rows.
- `ParamData` writes `default_arg`, `original_ty`, one word
  [`flags-explicit-object`, `flags-pack`, `flags-static-array`], then
  `flags-scope-depth` as `uv`.

## Language linkage

- The linkage is that of the innermost `LinkageSpec` around the entity's
  first declaration. The walk goes through namespaces, classes and
  functions, so a local variable and a class member hold one too. It is
  written for every function and variable stream, `static` ones
  included: it says what the enclosing language is, not whether the
  entity has C language linkage. `extern "C++"` is written `Cxx`, which
  differs from no `LinkageSpec` at all (`differ/LinkageLang/Cxx`). The
  reading is `Walk::linkage_spec(d, true)`, shared with the key's
  `c_linkage` rule (`linkage_spec(d, false)`, §5.2).
- `ScopeData` `aux` bits other than the language byte and
  `LINKAGE_BRACELESS` make the unit `Unaccounted("ScopeData/aux")`.

## Merging over redeclarations (§2.3)

- `FnSpec` `0-inline` is set if any declaration has `inline`.
  `0-implicit-inline` is set if no declaration has `inline` and any has
  `implicit_inline`. Kiln marks a declaration that follows an `inline`
  one as `implicit_inline`, not `inline`, so without this rule the entity
  would carry both bits. Tests: `equal/_/merge-inline` and
  `equal/_/merge-implicit-inline`.
- `0-constexpr-kind` is `Consteval` if any declaration says `consteval`,
  else `Constexpr` if any says `constexpr`. Kiln rejects declarations that
  disagree. If both are seen anyway, the unit is
  `Unaccounted("FnSpec/0-constexpr-kind")`.
- `0-storage`: `Static` when the declaration read is `static`; Kiln
  copies `static` forward with `storage_inherited`. Otherwise it is
  `Extern` when some declaration says `extern` and the function is
  inline (`inline` or `implicit_inline` on any declaration), else `None`
  (`differ/FnStorage/Extern`, `equal/_/fn-extern-not-inline`).
- `0-defaulted` and every other `FnSpec` bit are read from the
  declaration the walk reads.
- `VarSpec` `0-constexpr`, `0-constinit` and `0-inline` are set if any
  declaration sets them. `0-inline-implied` is set when the variable is
  inline and every declaration that has `inline` also has the implied bit,
  that is, when `inline` is written on no declaration
  (`equal/_/merge-constinit`, `equal/_/merge-static-member-constexpr`,
  `differ/VarSpec/0-inline-implied`). The `0-storage`, `0-tls` and
  `0-init-style` tags and the other bits are read from the declaration
  read.
- `ParamData` `default_arg` is the parameter's own, else the default the
  first declaration of the function that gives one at the same index
  gives (`equal/_/merge-default-arg-later`, unit test
  `param_default_merge`). Kiln copies defaults forward, so this matters
  only for a declaration that precedes the one that gives the default.
- If `FnSpec` or `VarSpec` of any declaration is not equal to its rebuild
  from Kiln's accessors and `with_*` setters, the unit is
  `Unaccounted("FnSpec/0")` or `Unaccounted("VarSpec/0")`. Such a bit or
  value is one that no row accounts for. Unknown `ParamData` `flags` bits
  make the unit `Unaccounted("ParamData/flags")`.

## The definition class (§11.9)

- A function is of the definition class when it is an implicit
  instantiation (its own `SpecInfo` or `MemberSpecInfo` kind, else
  `units::in_implicit_instantiation`), when every declaration is
  implicit, or when its first declaration is explicitly defaulted
  (`Defaulted::Explicit`). Kiln defines a function defaulted on its first
  declaration only when it is odr-used, the same as an implicit member
  (`demand/_/defaulted-ctor-use`; unit test `definition_class`). A
  function defaulted on a later declaration is defined there and is not
  of the class. A variable is of the class when it is an implicit
  instantiation.
- For a function of the class, `body` is written absent and
  `0-return-deduced` clear in the own stream. The unit is
  `Pending(Demand)` until the resolved unit `definition` exists (unit
  test `definition_class_body_is_pending_demand`). §11.9 moves
  `0-return-deduced` only when the pattern's return type holds a
  placeholder. Without one the bit is never set, so writing it clear for
  the whole class is the same.
- For a variable of the class, `init` is written absent, `0-init-style`
  as `C` (the first tag, the empty form), and `0-inline` and
  `0-inline-implied` clear. The unit is `Pending(Demand)`.
- In an implicit instantiation `default_arg` is written absent (§11.4),
  whatever Kiln holds (`demand/ParamData/flags-default-arg-pending`,
  `demand/_/implicit-instantiation-default-arg`). Outside one, a
  parameter whose `DEFAULT_ARG_PENDING` bit is set and that has no default
  makes the unit `Unaccounted("ParamData/flags-default-arg-pending")`.
  Kiln leaves the bit set after the late parse, so the bit alone is not
  read.

## Evaluation state (§11.3)

- `VarData` `eval` is not written. The state `Evaluating`, which cannot
  outlive the translation unit, makes the unit
  `Unaccounted("VarEvalState/Evaluating")`.

## `decl` in a block (`local::write_decl`, §2.4)

- `Var` with `local_extern` and `Function` write `ref`. `Var`, `ParmVar`,
  `Binding`, `Label` and `ContractResultName` write their ordinal, then
  their stream. `StaticAssert`, the three template parameter kinds and
  `LifetimeExtendedTemporary` write their stream and no ordinal.
- These kinds write nothing: `Typedef`, `TypeAlias`, `NamespaceAlias`,
  `Using`, `UsingShadow`, `ConstructorUsingShadow`, the three
  `UnresolvedUsing*` kinds, `UsingEnum`, `UsingDirective` and `Empty`.
  Each one names an entity, and the uses that follow are written by what
  they resolve to.
- A local type and what only a local type holds (`CXXRecord`, `Enum`,
  `EnumConstant`, `Field`, `IndirectField`, the four method kinds,
  `Friend`, `AccessSpec`, `FunctionTemplate`) are `Pending(Local)`.
- The kinds Kiln does not build (`UsingPack`, `FriendTemplate`,
  `ImplicitParam`, `ImplicitConceptSpecialization`) are
  `Unsupported("DeclKind")`. Any other kind, including `ConstevalBlock`,
  is `Unaccounted("decl/kind")`. Each of these writes the placeholder
  `uv 0`. Unit tests are in `local::tests`.
