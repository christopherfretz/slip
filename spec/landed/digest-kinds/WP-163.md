# WP-163 — the Kiln pin moves to `60fb5ab9d`

What moving the `kiln` submodule from `4a83f6e3c` (WP-066) to
`60fb5ab9d0dac55023bb75182a1e77762d25dc0b` changed in Slip. That commit
is Kiln's `main` at its PR #943, with PCH format 187 and image format
101. The rules are those of `docs/wp/WP-163.md`. The coordinator ruled
**parity first**:

- Slip loses nothing it had at the old pin.
- Slip gains no capability except the un-pends the package marks "here".
- Where Kiln now yields something new, the `slip_kiln` boundary leaves
  it out, in one named place, with a test.

Kiln sites are given at the new pin, with paths under `kiln/crates/`.

## Recording tables off by default

There is no digest row for the tables below, and Slip turns none of them
on for any caller:

- **The substitution-key table** and its switch
  (`-fkiln-written-ref-keys`, WP-3540 stage 0), **the root table**, and
  the kind `PartialMatch` (WP-3541). They are off (KR9).
- **New written-reference roles** (WP-2820 F1).
  - Kiln now records `Operator` and `UdSuffix` rows whenever the
    written-reference table is on.
  - `slip_kiln::written::left_out` drops them in `instances_of`,
    `refs_of` and `dependents_of`.
  - Test: `wp163_operator_and_ud_suffix_are_left_out`. `tests/ranges.rs`
    filters them in the same way.
- **`SpecRef` rows for a function template's default template argument**
  (WP-3520).
  - `slip_kiln::written::in_template_head` drops a row whose range lies
    in the template's parameter list. The rename does not read these
    rows before WP-154's stages.
  - Test: `slip_kiln/tests/written.rs`
    `wp163_default_template_argument_rows_are_left_out`.
  - The `wp139_no_row_*` guard tests are unchanged.
- **`-imacros`, `-iprefix`, `-iwithprefix`, `-iwithprefixbefore`.**
  - Kiln's driver accepts these flags since WP-2822 (`c52c27ba8`).
  - Slip refuses them as before: `slip_kiln::check::not_modelled`, in
    `refused()` and in `parse_observer_with` (`spec/cdb.md` §6.2,
    rejection 3).
  - Tests: `tests/check.rs` `s6_unknown_flag_refused` and
    `tests/lookups.rs` `dash_imacros_kiln_accepts_slip_does_not_pass`.

## Where an old fact moved in Kiln (parity restored)

- **Friend targets** (WP-3164, `2af5deebd`).
  - A dependent constructor, destructor or conversion friend now has a
    type target.
  - `slip_kiln::written::friend_target` maps such a friend back to the
    member declaration, as the old pin gave it. All six callers go
    through it.
  - A class-key friend (`friend struct Bq<..>::Y;`) now keeps its
    written qualifier in its `Elaborated` type. `own_spelling.rs`
    `friend_name` reads through it as it read the unqualified type
    before. A `typename` friend kept its qualifier at both pins and is
    read as before.
  - Tests that are unchanged: the 4 `pattern-friend-*` and 2
    `spelling-friend-*` fixtures, and `spelling-decl-friend-typename`.
- **`#embed` found through `--embed-dir`** (WP-2829, `c52c27ba8`).
  - `Found::EmbedDir{index}` replaces `Found::Embed` for such a hit.
  - `slip_kiln::lookups::embed_read` rebuilds the path with
    `kiln_pp::join_path`. Without it, the hit counted as missed.
  - Tests that are unchanged: `found_embed`, `missed_embed` and the
    `verify_job` tests `n2_hard_linked_*` and `n2_one_class_*`.
- **Source-location strings** (WP-3000, `50ee80489`).
  - Kiln now makes one string object per (content, role, declaration).
  - `value.rs` `NameValues.origins` is keyed by the literal's bytes, so
    uses are taken by content as before (`spec/digest.md`, the uses of a source-location string).
  - Tests that are unchanged: the 3 `name-value-*` fixtures and
    `names.rs` `wp115_*` and `wp145_*`.
- **Instantiated parameter attributes** (WP-3407, `14b25bd70`).
  - An instantiation's attributes now come from the latest declaration,
    as `inherited` copies.
  - `attrs.rs` `param_nodes` reads the inherited copies for an
    instantiation only.
  - Test that is unchanged: `param-attr-template-first-declaration`.

- **`differ/_/param-attr-template-definition`** adds
  `changed f<int>(int *)` (WP-3407).
  - The instantiation now holds the attribute that the definition added.
  - This is right by digest §1: code generation for `f<int>` reads it.

  - The unit test `attrs.rs` now expects `definition == [0,1,1]`.

  `changed` of the shadow (WP-3145/3146, `690711450`).

- **`rules/stale/guide-of-owned-template-left`** is removed (WP-3272,
