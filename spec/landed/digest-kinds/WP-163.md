# WP-163 — the Kiln pin moves to `60fb5ab9d`

What moving the `kiln` submodule from `4a83f6e3c` (WP-066) to
`60fb5ab9d0dac55023bb75182a1e77762d25dc0b` changed in Slip. That commit
is Kiln's `main` at its PR #943, with PCH format 187 and image format
101. The rules are those of `docs/wp/WP-163.md`. The coordinator ruled
**parity first**:

- Slip loses nothing it had at the old pin.
- Slip gains no capability except the un-pends the package marks "here".
- Where Kiln now yields something new, the `slip_kiln` boundary leaves
  it out, in one named place, with a test.

Kiln sites are given at the new pin, with paths under `kiln/crates/`.

## Rulings of fix round 2 (the coordinator's)

- **(i)** A function template with no definition reads its first
  declaration (a later non-defining declaration naming `n::j` is equal):
  the design as it was, unchanged.
- **(ii)** Non-dependent template-ids (`It<int, n::k>` against
  `It<int, n::j>`) are equal at every site, per §4.6 (a converted value
  is the same type) and the old pin. Not changed in this package
  (parity); the coordinator opens a separate package.
- **(iii)** For Kiln's held batch, not acted on: Kiln does not convert
  the value arguments of a variadic template (`f(V<n::k, Ns...>*)`, and
  `f(W<T, n::k>*)` with `template<class, int...> struct W`, get keys
  holding `n::k`, where clang converts them), so two translation units
  spelling one such entity differently would give it two keys. Slip's
  comment "a pack, which Kiln does not convert" stands. The request text
  is in `docs/wp/WP-163.md`, "Fix round 2".
