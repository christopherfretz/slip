# WP-028 — slip_digest: constant values and strings

What `crates/slip_digest/src/value.rs` decides where `spec/digest-kinds.md`
§8, §8.1 and §10.3 and digest §7 are silent.

**Padding is written as stored.** Digest §7 asks for the image "with
padding zeroed". Kiln already guarantees it: `check_image`
(`kiln_ast/src/consts/mod.rs` 632–692) refuses to intern an aggregate
whose padding or relocated bytes are not zero, and a restored snapshot
goes through the same check (`kiln_ast/src/consts/snap.rs:102`). So
`ByteImage.bytes` is written as Kiln holds it, with no shadow run read
and no zeroing done in Slip. `ShadowKind` and `ShadowRun` stay `out`.

**What bounds the recursion.** A value names other values only through
`PtrBase::Const` and `Reloc.value`, and the store is append-only, so a
value names only values interned before it: there is no cycle. Each
nested value is one depth level of the walk (`Walk::enter`), so a chain
deeper than `DEPTH_LIMIT` writes the placeholder and `TOO_DEEP`. Depth
alone does not bound the work, since a shared sub-value reached many
times (a DAG) is written in place each time; a per-call budget
(`VALUE_BUDGET`, 2^26 units: one per value plus one per image byte)
caps it, and running out is `Cause::Unaccounted("value/size")`.

**The placeholder.** Where a value is cut (depth or budget), the stream
gets `uv 0` in its place and the cause, so the stream stays well
formed. An image over budget writes empty bytes.

**A reflection is its tag only.** `ValueKind/Reflection` is
`unsupported`: the tag is written, then `Cause::Unsupported
("ValueKind/Reflection")`; `ty` and `id` are not read.

**A temporary without its `LetData`.** A `PtrBase::Temporary` whose
declaration has no `lifetime_extended` record is a fact no row accounts
for: `REF_NONE`, `uv 0`, `Cause::Unaccounted("PtrBase/Temporary.0")`.

**A label difference operand that is not an `AddrLabelExpr`.**
`ExprArena::addr_label` panics on another kind, so the kind is checked
first; another kind writes `REF_NONE` and
`Cause::Unaccounted("PtrBase/LabelDiff.plus")` (or `.minus`).

**A label is its local ordinal.** `PtrBase::Label` writes
`Walk::write_ref` of the label declaration, which a body unit turns into
its local ordinal and a key into `Unaccounted("key/local-ref")`.

**Tag rows a pair cannot isolate.** The tag rows of `ValueKind`,
`FloatKind`, `NullKind` and `MemberKind` are functions of the value's
type, which the stream already writes before them: changing the kind in
source always changes the type too. Their `differ` tests change the
kind and see the unit change, but breaking only the tag is caught by
the unit tests in `value.rs`, not by those pairs.

**Rows C++ cannot reach.** `PtrBase/Absolute` and `PtrBase/LabelDiff`
come only from a C static initializer (`kiln_oven/src/value.rs`
`nowhere_of` and `label_diff_of`), and the snippet has no C mode
(`crates/slip_kiln/src/snippet.rs:308`); `StringEncoding/Wide16` is a
16-bit `wchar_t`, which the x86-64 Linux target does not have. Unit
tests in `value.rs` build them by hand; the rows stay in
`untested.txt`.

**A default template argument is not a constant.** The existing
`_/template-default-value` test stays `# pending`, `# needs: expr`: Kiln
holds a non-type template parameter's default as an expression
argument, not an interned constant, so this area does not reach it.
