# WP-028 — slip_digest: constant values and strings

What `crates/slip_digest/src/value.rs` decides where `spec/digest-kinds.md`
§8, §8.1 and §10.3 and digest §7 are silent.

**Padding is written as stored.** Digest §7 asks for the image "with
padding zeroed". Kiln already guarantees it: `check_image`
(`kiln_ast/src/consts/mod.rs` 632–692) refuses to intern an aggregate
whose padding or relocated bytes are not zero, and a restored snapshot
goes through the same check (`kiln_ast/src/consts/snap.rs:102`). So
`ByteImage.bytes` is written as Kiln holds it, with no shadow run read
and no zeroing done in Slip. `ShadowKind` and `ShadowRun` stay `out`.

**A pointer to a constant is written by that constant's content.** This
is how digest §7 ("a pointer to a constant is written by that constant's
content") is read. `PtrBase/Const.0` writes the 32-byte content digest
`H("slip.value.v1", s)`, where `s` is the stream that writing the named
constant in place would give, and its cause is merged into the stream
that uses it. The digest is computed as a key is
(`spec/landed/digest/WP-024.md`, "A key does not depend on the unit that
asks"): the unit's local state is put aside and `in_key` is raised, so a
local entity met below it is `Unaccounted("key/local-ref")`. That is
conservative and the established rule. The digest is memoised in the
walk by `ConstValueId`. It is not memoised when a depth hit or a cycle
happened below it, or when it used a digest that was not memoised,
because then its cause depends on the path. Two things stay written in
place: the value `value` is given, and each relocation of an image. A
relocation's value is a pointer scalar, and a pointer to a local static
must keep its local ordinal. The tag `slip.value.v1` is new and belongs
in `spec/model.md`'s table of tags.

**What bounds the work and the stack.** A value names other constants
only through `PtrBase::Const` (its own, or a relocation's). The store is
append-only, and Kiln rejects a `Const` id not yet interned, so the
constants a value reaches form a DAG whose edges go to smaller ids. When a
content digest is needed, every constant it reaches that has no digest
yet is collected with an explicit stack. They are then computed in
increasing id order, so children come first, under one depth level. While
one is written, every digest it names is already known, so a chain of
any length nests one level, not one level per link. Because of the memo,
a constant shared by many pointers is written once per walk, so the work
is linear in the constants reached. Before this rule, the review's
twenty-level chain of shared pairs took 34 s. The pair
`differ/_/value-shared-chain-leaf` and the unit test
`shared_constants_are_written_once` (thirty levels) now take well under a
second. The depth limit still applies where such a computation starts
(`nesting_is_bounded`). That deviates from the review's suggestion, which
was to recurse one level per link and assert that a 250-deep chain is
indeterminate from depth 0. Recursing that way would mean a shared DAG
deeper than the limit is never memoised, and its work grows exponentially.
One constant's stream (its image and its relocations in place) does at
most `VALUE_BUDGET` units of work (2^26: one per value and one per image
byte). Running out is `Cause::Unaccounted("value/size")`. Each constant
gets a fresh budget, so a budget trip does not depend on the path, and a
digest that tripped is still memoised. The cause
`Unaccounted("value/order")` covers a constant named before its digest
exists. Kiln's store order makes that unreachable.

**The placeholder.** Where a value is cut (depth or budget), the stream
gets `uv 0` in its place and the cause, so the stream stays well
formed. An image over budget writes empty bytes. A content digest that
cannot be computed is 32 zero bytes and the cause.

**A reflection is its tag only.** `ValueKind/Reflection` is
`unsupported`: the tag is written, then `Cause::Unsupported
("ValueKind/Reflection")`; `ty` and `id` are not read.

**A temporary without its `LetData`.** A `PtrBase::Temporary` whose
declaration has no `lifetime_extended` record is a fact no row accounts
for: `REF_NONE`, `uv 0`, `Cause::Unaccounted("PtrBase/Temporary.0")`.

**A label difference operand that is not an `AddrLabelExpr`.**
`ExprArena::addr_label` panics on another kind, so the kind is checked
first; another kind writes `REF_NONE` and
`Cause::Unaccounted("PtrBase/LabelDiff.plus")` (or `.minus`).

**A label is its local ordinal.** `PtrBase::Label` writes
`Walk::write_ref` of the label declaration, which a body unit turns into
its local ordinal and a key into `Unaccounted("key/local-ref")`.

**Cause names.** A variant row that is not `in` gives a cause named
`<short name>/<row>`, for example `FloatKind/Quad` or `PtrBase/Absolute`.
`tables::Row` carries no name, so `value.rs` maps each Kiln variant to its
name with an exhaustive `match`.

**`Entry` is read through a tuple.** `StringPool::get` returns
`(StringEncoding, &[u8])`, not the `Entry` record. If Kiln adds a field
to `Entry`, nothing here fails to compile. Such a field would have to be
found by the tables test against the pinned descriptor, not by this
file.

**Rows a pair cannot isolate.** Here, "not isolated" means a pair that
changes the row in source always changes an earlier row too, so breaking
only this row leaves the pair passing. A unit test in `value.rs`
isolates each one:

- **Type-determined rows.**
  - The `FloatKind`, `NullKind` and `MemberKind` tags depend only on the
    value's type: `every_float_kind_by_its_row` and
    `null_and_member_kinds_by_their_rows`.
  - `Int.signed`: `int_bits_are_the_normalised_words`.
- **The scalar's type equals the argument's type.** In a non-type template
  argument, `Int.ty` and `Pointer.ty` are the argument's type, so
  `ArgView/Value.ty` changes with them: `the_type_of_a_scalar_by_its_row`.
  `ByteImage.ty` likewise: `an_aggregate_by_its_rows`.
- **The `ValueKind` tag** is not a function of the type: a null and a
  non-null pointer of one type differ in it. But its pairs always change
  the variant's rows that follow, and breaking the tag alone is caught by
  every unit test that compares a whole stream.
- **Layout-determined rows.** These follow from the type and the active
  union members, so a pair that moves one changes the others:
  - `UnionMember.at`, `ByteRange.start` and `ByteRange.len`:
    `an_aggregate_by_its_rows`;
  - `Reloc.at` (Kiln records every pointer slot as a relocation, a null
    one too, so the offsets follow from the type; moving a pointer
    changes `Reloc.value`): `an_aggregate_by_its_rows`;
  - `MemberPtr.derived` changes with the member it names:
    `null_and_member_kinds_by_their_rows`.

Each such pair's `expect.txt` names what else changes and the unit test.

**Rows the snippet runner cannot reach.** `PtrBase/Absolute` and
`PtrBase/LabelDiff` come from the Oven's fold (`kiln_oven/src/value.rs`
`nowhere_of` and `label_diff_of`). The fold runs in C++ too
(`kiln_oven/src/lib.rs:1882`), so a full compile or a resolved `eval` may
reach them. They are reached from C static initializers, and the snippet
runner has no C mode (`crates/slip_kiln/src/snippet.rs:308`).
`StringEncoding/Wide16` is a 16-bit `wchar_t`, which the x86-64 Linux
target does not have. These rows stand on hand-built unit tests:
`an_absolute_address_is_its_offset`,
`a_label_difference_is_its_labels_and_size`, and `an_encoding_by_its_row`,
which builds the string pool by hand. They stay in `untested.txt`.

**A default template argument is not a constant.** The existing
`_/template-default-value` test stays `# pending`, `# needs: expr`: Kiln
holds a non-type template parameter's default as an expression
argument, not an interned constant, so this area does not reach it.

## Hazards

**Pointers to different union members are one constant.** Kiln stores a
pointer as its base, offset, designated type and `past`, with no member
path. So `&u.a` and `&u.b` of `union U { int a; int b; } u;` are one
constant: same base, offset 0, and designated type `int`. Kiln itself
treats `A<&u.a>` as `A<&u.b>`, and the same holds for
`(void*)&u.a` and `(void*)&u.b`. No row can see the difference, so a
digest cannot tell those two programs apart. This has been reported to
Kiln. The pair `differ/_/value-pointer-to-union-members` records it,
marked `# pending`, `# needs: kiln`.
