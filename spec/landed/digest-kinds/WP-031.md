# WP-031 — the expression walk and the core expression kinds

What `crates/slip_digest` (`expr.rs`, `expr_core.rs`) reads into
`spec/digest-kinds.md` §7 where it is silent, and where the walk departs
from the letter of WP-031. Where a fact could not be settled, the unit is
indeterminate.

## The walk

- **No recursion for core kinds.** `expr::child` runs one heap stack of
  `Item`s: a node is expanded into the primitives of its rows in table
  order, pushed in reverse, and a child is expanded when it is popped. The
  stream is byte for byte what a pre-order recursive walk writes. An
  operator chain, a call chain or a cast chain of any length takes one
  Rust frame; the left spine is on the heap.
- **Recursion that remains.** A kind written by another file is an
  `Item::Exec` of its `KindFn`, which reaches its children through
  `expr::child`; each such call enters one level of `walk::NODE_LIMIT`
  (`Walk::enter_node`). Past it the stream gets a placeholder and
  `Unaccounted("walk/depth")`, the same cause as `DEPTH_LIMIT`.
- **The limits.** `NODE_LIMIT` is 10 000 and `DEPTH_LIMIT` stays 200.
  `expr::tests::frames_fit_the_stack` measures, in the test profile,
  about 823 bytes per node level (the real path: `child`, `walk`,
  `walk_items`, the kind's function, `child`) and about 744 KB for the walk at
  `DEPTH_LIMIT`: 9.0 MB for both limits. These are test-profile frames;
  the worker package measures the release profile on the corpus before
  the scheme is fixed. `walk::STACK_SIZE` is 64 MiB,
  more than four times that, and the test checks the margin. A package
  whose kind function has a larger frame adds its path to that test.
- **Linear work.** `tests/expr_chains.rs` digests 2 000- and 20 000-long
  operator and member-call chains and right-nested `?:` chains, and 20-
  and 200-deep left-nested `?:` chains (`((a ?: a) ?: a)`, bounded by the
  depth limit): no hard cause, `digest.bytes` grows
  by ten (within 9 to 11), and walk time is within 25 times plus 20 ms.

## The rules at the head of §7

- **Parentheses.** `child` skips every `ParenExpr`. A skipped
  `ParenExpr` that has an entry in a `ColdExprData` map whose row is `in`
  is `Unaccounted("ExprNode/ParenExpr")` (the entry would be lost); one
  without an operand writes `uv 0` and `Unaccounted("ExprNode/ParenExpr.a")`.
  `child_keep_paren` keeps an outermost `ParenExpr` with its rows. It
  exists for the `DependentDecltype` profile (§4.2 rule 7) and skips the
  parentheses inside it.
- **Opaque values.** Sources are numbered per unit (`UnitState::opaques`)
  in the order the walk first reaches them through an `OpaqueValueExpr`.
  The first reach writes the number and the source (`child?`); later
  reaches write the number and an absent `child?`. An opaque value with no
  source takes the next number. Only an `OpaqueValueExpr` registers a
  source, with one exception below.
- **`BinaryConditionalOperator`: the common expression once.** The list
  `a` is (common, opaque condition, opaque true arm, false arm); Kiln's
  only builder (kiln_sema forms.rs:706) makes the opaque's source the
  common expression, element 0 (forms.rs:699). The walk registers element
  0 as an opaque source (`Item::OpaqueSource`) before it expands it, so
  the opaques that follow write only its number and an absent `child?`.
  Writing it under each opaque too made a left-nested `?:` chain
  exponential (74 KB to 7 MB from 20 to 200 levels). Other kinds whose
  child is reachable by two paths (`PseudoObjectExpr`, `ArrayInitLoopExpr`)
  belong to other packages; they need the same registration.
- **The type memo and the expression state.** A type's digest is memoised
  per unit, and a type can hold an expression (a `decltype`, an array
  bound), so the expression state (opaque numbering, the dependent depth,
  `walk::ExprState`) is put aside while a type is digested
  (`Walk::take_expr_state`) and put back after: the same type gives the
  same bytes whatever the opaque counter. Every place that puts the unit
  aside uses one helper, `Walk::take_unit`.
- **Shared nodes.** The default argument behind `CXXDefaultArgExpr` and
  the initialiser behind `CXXDefaultInitExpr` are never children. What
  the use writes is the kind's own function (pending in `expr_init`).

## Common rows and causes

- **`ExprDeps`.** The four `in` bits are one flag word. The `0-error` bit
  is `Cause::Error` (digest §10), and so is `RecoveryExpr`: both are
  "the expression holds an error", not a fact the walk failed to read. A
  bit outside the five is `Unaccounted("ExprDeps/0")`.
- **Bad words.** A value category or object kind with no row, a per-kind
  flag or `aux` bit no row accounts for (`check_bits`, `check_aux`), a
  zero word where a child or declaration is required: each is
  `Unaccounted("<Table>/<row>")` with a placeholder. None panics.
- **Cold rows** are written for every expression, after the kind's rows,
  each in its empty form when the map has no entry, then
  `templ::expr_maps` (pending).
  - `member_extra` on a node that is not a `MemberExpr` is
    `Unaccounted("ColdExprData/member_extra-record")`.
  - `cast_written` on a kind that is neither an explicit cast nor a
    `CXXUnresolvedConstructExpr` is `Unaccounted("ColdExprData/cast_written-cast")`.
  - `splice_args` is `Unsupported("ColdExprData/splice_args")`, as its row
    says.
  - `source_loc` (symbolic) and `default_imm` (demand) write nothing.

## Rows read narrowly

- **`DeclRefExtra.template_args`** is written only when the named entity
  is a template (`expr_core::names_template`). In Kiln a `DeclRefExpr`
  names the specialisation, and a dependent name is an
  `UnresolvedLookupExpr`, so the row is never observable today: its
  test, and `ExprNode/DeclRefExpr.b`'s, stay in `untested.txt`.
- **The base path** (`ImplicitCastExpr.b`, `type*` of each base class)
  is read for every cast kind with a base path. `const_cast`,
  `reinterpret_cast` and `__builtin_bit_cast` never carry one in Kiln, so
  their `.b` rows stay untested. The trace, over every call of
  `Builder::cast` (kiln_ast builder.rs:2414) and `functional_cast`
  (:3812):
  - a non-empty path is passed only by `conv::raw_cast` (kiln_sema
    conv/mod.rs:235, `ImplicitCastExpr` only) and by `typed_cast`
    (expr/ref_cast.rs:478);
  - `typed_cast` gets a path only from `class_ref_cast` (ref_cast.rs:236,
    by `class_relation` :301 and :328), `static_downcast` (:385) and
    `static_mp_upcast` (:454), all reached only under
    `CastStyle::allows_static` (ref_cast.rs:68, expr.rs:7804, 7811,
    7818), which is false for `Const` and `Reinterpret` (expr.rs:84);
  - the bit cast is built at builtins.rs:3328 and :3401 with `None`;
  - every other site passes `None`: expr.rs:7860, templ/actions.rs:2082,
    templ/nttp.rs:563, class/special/define.rs:878, splice.rs:537,
    class/member_expr.rs:2559 and :2583, kiln_ast builder.rs:2360;
  - an instantiation rebuilds a cast through the same checks
    (templ/subst/exprs.rs:1032 maps the kind back to its `CastStyle`).
  So their `b` is always empty.
- **`CastKind/ToUnion` and `NonOdrUse/Discarded`** are written by their
  tags but Kiln never builds them; they stay untested.

## Decisions by the table's owner

- **`ColdExprData/member_extra-qualified`** is true only for a qualified
  member that is a virtual function (through a using-shadow, its entity),
  `is_virtual` on any declaration of its chain (`expr::virtual_fn`). Kiln
  sets it on the written `virtual` (kiln_sema class/virtual/mod.rs:119),
  on a redeclaration (:127), on an overrider declared without `virtual`,
  destructors included (:160), and on an implicit destructor or
  assignment (class/special/implicit.rs:1525). The qualifier suppresses
  virtual dispatch only there, so `a.A::g()` against `a.g()` for a
  non-virtual `g` is equal, and differs for a virtual function, a virtual
  destructor and an overrider (`differ/ColdExprData/member_extra-qualified`,
  `equal/_/expr-qualifier`, `equal/DeclRefExtra/qualifier`).
- **`ExprNode/CXXThisExpr.aux-implicit`** is written only inside an
  instantiation-dependent expression, the `CXXThisExpr` itself included,
  else its empty form. A `this` is dependent by its type alone
  (kiln_ast builder.rs:3969), but Kiln reads the bit also on a `this`
  that is not dependent and is the base of a dependent member access:
  `member_base_deferred` (kiln_sema templ/subst/exprs.rs:2111), the
  mangling of a dependent expression (mangle/dep.rs:1533) and the
  expression profile (profile_expr.rs:509, 539). The predicate is
  therefore widened from "the node is instantiation-dependent" to "an
  enclosing expression is" (a depth count, `ExprState::dependent`). So
  `this->m` against `m` is equal in a non-template member
  (`equal/_/expr-qualifier`) and differs in a member of a class template
  (`differ/ExprNode/CXXThisExpr.aux-implicit`); Kiln builds the same node
  kinds in both (a `MemberExpr` over a `CXXThisExpr`).

## What the tests can fail for

- **Stream-level row tests** (`src/expr_rows.rs`, unit tests of `expr`).
  For every test directory of `CastKind`, `UnaryOp`, `BinaryOp`,
  `CharKind`, `StringKind`, `NonOdrUse`, `StorageDuration`,
  `ValueCategory`, `ObjectKind` and `ExprDeps`, some node of the
  directory's source writes that row (the tag, or the common rows with the
  row in place of Kiln's value). Every flag row is checked set on some
  node of its directory; the base paths, `MaterializeTemporaryExpr.b`,
  `CXXBindTemporaryExpr.b`, `CompoundAssignExtra.lhs_ty` (`b += p` for a
  `bool b`: `int` against `int *`), `CXXOperatorCallExpr.aux` and `.a`,
  `CXXBoolLiteralExpr.a`, `union_field` and `fp_round` by their rows;
  every `OverloadedOperator` an operator call can carry, and every
  directed `FpRound`, from generated sources; the opaque numbering by
  `opaque` itself.
- **Mutation sweep.** Writing one constant for each enumeration
  (`ExprKind`, `ValueCategory`, `ObjectKind`, the `ExprDeps` word,
  `CharKind`, `StringKind`, `NonOdrUse`, `UnaryOp`, `BinaryOp`,
  `OverloadedOperator`, `CastKind`, `StorageDuration`, `FpRound`, the
  bool literal, the opaque number), dropping each flag (the four
  `ExprDeps` bits, `IntegerLiteral.bits-wide`, the three `DeclRefExpr`
  bits, `bits-arrow`, `aux-implicit`, `bits-cannot-overflow`,
  `bits-assume-ignored`, `bits-part-of-explicit-cast`,
  `aux-lvalue-reference`, `aux-side-effects`, `aux-elided`,
  `aux-value-hidden`, `member_extra-qualified`), and emptying the base
  path, `MaterializeTemporaryExpr.b`, `CXXBindTemporaryExpr.b`,
  `union_field`, `CXXOperatorCallExpr.a`, `lhs_ty` and `IntegerLiteral.a`:
  every mutation fails a test. Writing the `out` bits `ADL` of an
  operator call fails `equal/_/expr-adl-bit`; writing
  `HAD_MULTIPLE_CANDIDATES` fails nothing (below).
- **Rows Kiln never reaches**, so no test can fail for them:
  - `CastKind/ToUnion`: never built (kiln_ast expr.rs:624; only matched at
    kiln_sema static_tls.rs:163 and class/temporary/lifetime.rs:717).
  - `NonOdrUse/Discarded`: never set (kiln_ast expr.rs:720; sema sets only
    `Constant` and `Unevaluated`).
  - `UnaryOp/Coawait`: a `co_await` is a `CoawaitExpr`; sema never builds
    a built-in unary operator of it (kiln_sema expr.rs:3667,
    `unreachable!`). Its directory stays pending for the statements.
  - `FpRound/Dynamic` and `FpRound/Nearest` in `fp_round`: only a
    directed mode enters the map (kiln_sema stmt.rs:400,
    `FpRound::is_directed` at kiln_ast fp.rs:50).
  - `OverloadedOperator` `New`, `Delete`, `ArrayNew`, `ArrayDelete` as a
    `CXXOperatorCallExpr.aux`: a new or delete expression is its own kind.
  - The base path of `const_cast`, `reinterpret_cast` and
    `__builtin_bit_cast` (above).
  - `DeclRefExtra.template_args` and `ExprNode/DeclRefExpr.b` (above).
  - `HAD_MULTIPLE_CANDIDATES` (`out`): defined at kiln_ast expr.rs:307 and
    set by nothing outside the builder's tests, so
    `equal/_/expr-several-candidates` cannot fail until Kiln sets it.

## Departures from WP-031's text

- **`this->m` against `m`** is must-equal outside a template and differs
  inside one, by the owner's decision above.
- **ADL.** Kiln sets a call's ADL bit only for an operator call
  (overload/oper.rs:1160) and a structured binding's `get`
  (struct_bind.rs:984), never for a call by name, so `equal/_/expr-adl-bit`
  is an operator found by ADL alone against the same operator found by
  ordinary lookup too (a using-directive after or before the use), and
  `differ/_/expr-adl-other-operator` the case where ordinary lookup selects
  another `operator+`.

## Tests of other packages changed by the merge

Expressions that were `Pending(Expr)` are now written, so tests that
spelled the placeholder or relied on a unit staying indeterminate moved:
- `attrs.rs` tests take an operand's bytes from the walk
  (`expr::capture::captured`, test-only) instead of the placeholder;
  `s10_5_annotations` now checks that `[[=1]]` and `[[=1 + 0]]` differ in
  the expression only.
- `decl_func::tests::the_initialiser_comes_from_its_holder`: the
  remaining cause is `Pending(Demand)` (the value), no longer the
  expression's.
- `differ/FnSpec/0-not-selected` adds `changed X::~X<T>()`: the pattern's
  requires-clause is now digested.
- `differ/_/value-shared-chain-leaf` adds `changed p0` to `p30`: their
  initialisers no longer make them indeterminate, and each value reaches
  the leaf.
