# WP-037 — traits, coroutines and the remaining expression kinds

What `crates/slip_digest` (`expr_misc.rs`) reads into
`spec/digest-kinds.md` §7 where it is silent, and where it departs from
the letter of the tables. Where a fact could not be settled, the unit is
indeterminate.

## Reading the words

**No panicking accessor.** Every kind reads its node's words through
`expr::node` and decodes them itself: Kiln's accessors (`trait_kind`,
`typeid_operand`, `va_arg`, `array_trait_type`, `generic_control`, …)
`expect` an invariant of the builder, and a word the builder never writes
must make the unit `Unaccounted`, not stop the walk. The one accessor
called is `choose_operands`, after the walk has checked the word it would
panic on (`ChooseExpr.a`, 0).

**Enumerations stored by position.** `PredefinedKind` and `SourceLocKind`
are stored as their index in `ALL` (`kiln_ast` expr.rs:1528, :1571, whose
`from_aux` is private and falls back to the first variant): the walk reads
`ALL` by position, and a value past the end is
`Unaccounted("ExprNode/PredefinedExpr.aux")` (resp. `SourceLocExpr.aux`)
instead of Kiln's fallback. `SuspendKind` is bits 1-2 of `aux` (0 `Void`,
1 `Bool`, 2 `Handle`, expr.rs:3542); 3, which Kiln reads as `Void`, is
`Unaccounted(".../aux-suspend")`.

**A `bool` stored in a word** (`CXXNoexceptExpr.b`, `OffsetOfExpr.aux`) is
written as `bool` of "non-zero"; a value other than 0 or 1 is also
`Unaccounted`.

## Kinds

**`CXXTypeidExpr.a` and `GenericSelectionExpr.a-control`** are written as
the enumeration the table names (`TypeidOperand`, `GenericControl`): its
tag from the generated table, then the variant's payload. The flag bit
that says which variant (`bits-arg-is-type`, `out`) is read only to
choose it. `GenericControl::Type.1`, the location, is not read.

**`TypeTraitExpr.a`** is `type*` of the list's words, each a `QualType`; a
word of 0 is left out with `Unaccounted("ExprNode/TypeTraitExpr.a")`.

**`OffsetOfExpr.aux`** is Kiln's `invalid_record` (`kiln_ast`
builder.rs:3530, `offsetof_invalid_record` expr.rs:3596; set by
`kiln_sema` gnu.rs:336-385 when the designator passes through an invalid
class), which always comes with an error diagnostic; the table's first
note ("the record is not standard-layout") was wrong about Kiln, and
the table owner took this reading. The walk writes the bool and, when
it is set, makes the unit indeterminate with `Cause::Error` (digest
§10). No pair test can show the row (both sides would have errors); the
unit test `offsetof_invalid_record_is_an_error` holds the rule. A
non-standard-layout class gives `aux` 0 and only a warning
(gnu.rs:356).

**`OffsetOfExpr.a` holds every index, constant or not** (builder.rs:3530):
`__builtin_offsetof(S, x[1].p)` writes the literal `1` as a child, and its
value is folded into `b`.

**`CoawaitExpr.a` / `CoyieldExpr.a`: the operand is not written.** A
resolved expression's list has six elements (`kiln_sema`
coroutine.rs:716): the walk writes `count 4` and elements two to five
(`common`, `ready`, `suspend`, `resume`). The first, the operand as
written, is a node of `common` in every builder: `common` is the
operand itself, its materialisation, or built from a call that takes it
(`await_transform`, `yield_value`, `operator co_await`, member or not:
`build_resolved_coawait` coroutine.rs:720, `build_unresolved_coawait`
:756, `build_coyield` :975, and the implicit initial and final suspend
points of `build_suspend` :815, whose operand is the call of
`initial_suspend` / `final_suspend`). Writing it again said nothing
more, and made `co_await co_await … x` grow as 2^depth. The unit test
`coawait_operand_is_in_common` pins the fact for each form (a plain
lvalue and a prvalue awaitable, `await_transform`, a member and a
non-member `operator co_await`, both together, `co_yield`, and the
implicit points): the operand's `ExprId` is among the nodes reachable
from `common` in Kiln's AST. It held for every form, so no form needs
the operand written by opaque number. `nested_coawait_is_linear` shows
2,000 nested `co_await` write ten times the bytes of 200;
`coawait_operand_change_differs` (and the pair test
`differ/_/coawait-operand-alone`, pending on the statements) shows a
change in the operand alone still differs, through `common`.

**`common` is written once.** `common` is the source of the sixth
element, an `OpaqueValueExpr` the three calls name, so it takes its
opaque number before it is written (as `BinaryConditionalOperator`'s
common expression, WP-031): the calls' opaque values then write the
number alone. A `CoyieldExpr` of a template pattern holds the operand
alone (builder.rs:3376) and is written as a list of one. Any other
length is `Unaccounted(".../a")`, and every element is written.

**`AtomicExpr.aux`** is the operation's number in Kiln's numbering (the
builtin ids of `kiln_ast` decl.rs:4879 `builtin::atomic`). The walk keeps
its own list of the 38 operations (`ATOMIC_OPS`) and writes `uv` of the
number; a number outside it is `Unaccounted("ExprNode/AtomicExpr.aux")`.
The unit test `atomic_numbering_is_kilns` holds each number against Kiln's
constant and the set against `atomic::is_op`, so a renumbering in Kiln
fails a test before it silently changes digests.

**`ShuffleVectorExpr.b`** is `uv*` of the list's words when the mask is
known (`aux` bit 0); a poison lane is `u32::MAX`, written as that number.

**`ExtVectorElementExpr.b`** is the accessor's spelling (`sym`), read as
`Symbol::from_index(b)`.

**`GenericSelectionExpr.b`.** Kiln stores the selected association's
expression, not its position (builder.rs:2098). The walk writes the
position of the association whose `expr` word is that expression; a
selected expression that is no association's is
`Unaccounted("ExprNode/GenericSelectionExpr.b")` and the optional is
absent. A list whose length is not 2 + 3k is `Unaccounted(".../a-associations")`.

**`ChooseExpr.aux`** is written as stored (1, 2, or 0 while dependent);
another value is `Unaccounted` and is still written.

**`PseudoObjectExpr`.** The only builder is the synthesized three-way
comparison of a defaulted `operator<=>` (`kiln_sema`
class/compare/three_way.rs:76, for a subobject pair with no usable
`<=>`): `[a <=> b, ovl, ovr, result]`, `b` 2. Before the list is written,
the source of every semantic `OpaqueValueExpr` that is a direct child of
the syntactic form takes its opaque number: the syntactic form writes `a`
and `b` once, and `ovl`, `ovr` and the result's references write the
number alone. The operands are subobject accesses of the class (`this->m`
and `other.m`), so pseudo-objects do not nest from source and the walk
cannot be exponential here; `pseudo_object_writes_operands_once` shows
that each operand is written exactly once. A source that is not a direct
child of the syntactic form (none today) is written at its first opaque
value, by the rule for opaque values.

**`StmtExpr.a`** goes through `stmt::child` (a `StmtId`); its pair tests
wait on the statements' area.

## Cold rows

**offsetof: a step names its index by position.**
`OffsetofStep::Index.index` and `OffsetofComponent::Index.index` are
`uv` of the position of that expression in `OffsetOfExpr.a`, found by
`ExprId`, where the expression itself is written; both builders put
every index of the designator in that list, in order (`offsetof`
builder.rs:3538, `dependent_offsetof` builder.rs:3587-3597), so the
pattern form keeps its index expressions there too. An index not in the
list is `Unaccounted("OffsetofStep/Index.index")` (resp.
`OffsetofComponent/Index.index`) and writes `uv` of the list's length
(`offsetof_index_not_in_the_list`). Writing the expression again made
an offsetof nested in a non-constant index grow as 2^depth;
`nested_offsetof_is_linear` shows 200 levels write ten times the bytes
of 20 (Kiln's bracket nesting keeps the depth small). Once the offset is
not a constant, a constant index is an `Index` step as well (`z[1][a]`
has two), so the positions of the steps are those of the list in order;
the unit tests `offsetof_index_positions` and `offsetof_layout_rows`
hold them (they fail when the position is skipped or written as a
constant). The pair tests swap two indices between two steps
(`z[a][b]` against `z[b][a]`); they differ through `OffsetOfExpr.a` as
well, since the positions follow from the list and the designator, so
no pair can show the position alone.

**`array_trait`**: `dim` (`child?`) then `value`; an entry without a
record (never built) writes `opt false, uv 0`.
**`offsetof_pattern-components`** and **`offsetof_layout`**: the
enumeration's tag from the generated table, then the variant's `in`
fields; the locations are not read.

## Symbolic rows

`PredefinedExpr.a` (the name's string), `SourceLocExpr.a` (the context)
and every `SourceLocValues` row write nothing. The type of a
`PredefinedExpr` (`const char[N]`) is a common row and still changes
with the length of the name: that follows from the position too, and is
written.

## Rows left untested

**`TraitKind::VecStep`** is OpenCL's `vec_step`, which Kiln does not
parse in C++; its row stays in `untested.txt`. So do `TypeTrait`
`IsSameAs` and `IsLiteralType` (aliases: a built expression names
`IsSame` / `IsLiteral`, `kiln_ast` expr.rs:770-777), `IsReferenceable`
(not a C++ keyword at Kiln's `compat`, `kiln_parse` keywords.rs:262) and
`TypesCompatible` (C only, keywords.rs:295), and `ExprNode`
`OffsetOfExpr.aux` (above).
