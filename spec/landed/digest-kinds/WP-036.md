# WP-036 — dependent expressions, profiles and requires-expressions

What `crates/slip_digest/src/expr_dep.rs` reads into
`spec/digest-kinds.md` §7 (the names and constructs of templates), §9.3
(`RequiresData`, `Requirement`) and digest §4.4 (canonical expression
operands) where they are silent, and where it departs from the letter of
WP-036. Where a fact could not be settled, the unit is indeterminate.

## Profiles (§4.4): profile mode

- **What is walked in profile mode.** Every `ProfileId` operand of a type
  (`expr_dep::profile`) and every expression written into a key: a
  function's trailing requires-clause (`keys.rs`) and, since this round, a
  template head's requires-clause in a key (`templ::head`, `Head::Key`).
  The walk is `expr_profile::walk`, called by `expr_dep::profile_expr`
  with the stream's expression state put aside (`Walk::take_expr_state`)
  and a fresh `expr_dep::Frame` installed, both restored after.
- **A row is written iff Kiln's profile distinguishes it.**
  `expr_profile.rs` follows `Ast::profile_node` (`kiln_ast`
  `types/profile_expr.rs:441-861`) kind by kind with an exhaustive match
  and an explicit stack, writing for each Kiln word the digest's form of
  the same fact: a canonical type word is the type digest, `D_DECL
  first(d)` is the `Ref` of the first declaration, a symbol or
  `DeclNameId` is its `Name`, a canonical qualifier, template name or
  argument list is `write_nns`/`write_template_name`/`write_args`, an
  `aux` detail is its table row. The bytes therefore never depend on
  which spelling of a profile Kiln met first (F1).
- **Rows left out in profile mode**, against §7's full walk (all kinds):
  `ExprNode.ty`, value category (except an explicit cast's,
  `profile_expr.rs:624-636`), object kind, `ExprDeps`, the per-kind flag
  bits Kiln does not read, `ColdExprData` and `templ::expr_maps` rows
  (`expr_nns`/`expr_targs` are read where Kiln reads them). Per kind:
  - `ImplicitCastExpr`, `ConstantExpr`, `MaterializeTemporaryExpr`,
    `CXXBindTemporaryExpr`, `ExprWithCleanups`: the node itself (walked
    through, `:450-454`), so its cast kind, base path, value and cleanup
    flags;
  - `SubstNonTypeTemplateParmExpr`: `a` (the parameter replaced) and the
    reference bit; it is its replacement `b` (`:455`);
  - `OpaqueValueExpr`: the opaque numbering; it is its source (`:456`);
  - `IntegerLiteral`, `FloatingLiteral`: the radix and spelling rows;
    value and canonical type (`:462-473`);
  - `DeclRefExpr`, `MemberExpr`: `DeclRefExtra` qualifier and
    `found_decl`, and non-dependent explicit template arguments of a
    reference to anything but a function or variable template
    (`ref_args`, `:393-413`);
  - `UnresolvedLookupExpr`: `b`, the declarations found (`:511-523`).
    Counted in `Walk::left_out` when non-empty, which marks the type
    (below);
  - `CXXDependentScopeMemberExpr`: the canonical qualifier when the
    spelled one is written (`:528-552`);
  - `SizeOfPackExpr`: the partial arguments
    (`size_of_pack_partial`) and `size_of_pack_origin` (`:553-561`);
  - `RequiresExpr`, `ConceptSpecializationExpr`: `aux`, the stored
    result (`:737-791`); a requires-expression's parameters' declaration
    streams (their types only);
  - `CXXConstructExpr`, `CXXTemporaryObjectExpr`: the construction flags
    (`:647-651`);
  - `CXXNewExpr`: the selected allocation and deallocation functions
    (`:671-684`).
- **Facts written in profile mode that §7 writes otherwise or not at
  all**:
  - every `ParenExpr` (`:562`), F3; the head requires-clause keeps them as
    the trailing one does;
  - a template parameter by depth, position and pack-ness, a non-type one
    with its type, a top-level placeholder's constraint ignored
    (`decl_words`/`nttp_type_words`, `:327-392`);
  - a function parameter (`D_PARM`, `:345-362`) by position, pack-ness,
    the in-requires bit (its context is a `RequiresExprBody`),
    function-scope depth and its canonical type. The type is written
    because net (2) needs it: without it net (2) found 160 collisions over
    the pair tests and 5 over the test's own sources (`f(T a)` and
    `g(U a)` naming `a`);
  - a requires-expression's parameters as a count and each one's type, a
    reference to one by position (no frame number);
  - the spelled qualifier of a member access on an object of dependent
    type, level by level (`spelled_nns_words`, `:190-224`);
  - explicit template arguments holding a non-dependent expression one by
    one, the expression by its profile (`push_args`, `:414-440`);
  - the deduced class template of a `CXXUnresolvedConstructExpr`
    (`ctad_word`, `:303-325`).
- **Kinds walked in full.** The kinds Kiln profiles as unique
  (`:838-861`) and `CXXReflectExpr`, `CXXSpliceExpr` (`:792-837`, whose
  profile form needs reflection facts the digest does not yet write) are
  walked by §7 (`expr::child`) with the frame installed. Their bytes are a
  function of their own spelling; the nets leave them out.
- **The nets** (`expr_profile_tests`). For every expression of both sides
  of every pair test (1346 directories, 8597 expressions compared, 362
  left out: a kind walked in full or a cause) and of seven sources of the
  test's own (several spellings of one profile; profiles differing in one
  fact: a parameter's depth, type or in-requires bit, a member access's
  base or spelled qualifier, a compound requirement's `noexcept`), Kiln's `Ast::expr_profile_words` is compared with the
  bytes: (1) equal words give equal bytes, (2) different words give
  different bytes. One exception to (2) is accepted by name:
  `demand/_/local-extern-in-instantiated-body`, two declarations of one
  entity (a block-scope `extern` and the instantiation's redeclaration)
  that Kiln's profile tells apart by `DeclId` and the digest writes as
  one `Ref`; the digest is right there.
- **The mark** (F1, item 1c). `TypeRef.spelling` is set when the type's
  stream raised `Walk::left_out`, and every memo hit (per parse, per unit,
  abort memo) raises it again, so an enclosing type is marked too.
  `Walk::absorb_type` (used by `write_type` and `DeclNode` `ty-type`)
  adds `Pending(Area::Spelling)` when the type is marked and no key and
  no type is being written. A key ignores the mark.
- **Locals.** A reference to a local entity other than a parameter takes
  the unit's ordinal (in a key, `Unaccounted("key/local-ref")`). Whether
  one did is read from `UnitState::local_uses` before and after, which a
  nested profile or type digest raises too, so it carries to every
  enclosing frame and to the unit (F7; the `outer` flag is gone). A frame
  that numbered entities (only in a kind walked in full, or a
  requires-expression walked in full in a key) and also wrote a unit
  ordinal is `Unaccounted("profile/local-mix")`.
- **Owned expressions (item 1d).** In the unit stream, the expressions a
  declaration owns outside its type are walked in full by §7: default
  template arguments written as an expression (`templ::decl_maps`, now
  `arg_view::EXPR` and `expr::child`; a canonical-only expression stays a
  profile), a dependent `noexcept` operand of the declaration's own type
  (`write_exc_spec` with `own`, outside a key), the head requires-clause
  (`Head::Unit`), the trailing requires-clause (`decl_maps`), default
  function arguments (`decl_func.rs`, already) and `explicit` operands
  (cold map, already). No row of `expr_dep.rs`, `templ.rs` or
  `decl_func.rs` is in a key only: the trailing and head requires-clauses
  are in both, as a profile in the key and in full in the unit.
- **`ProfileEntry.first_expr` absent.** Only the sentinel entry 0 lacks
  one (`kiln_ast` `types/profile.rs` `ProfileTable::new`;
  `types/context.rs:1422`). `uv 0` and
  `Unaccounted("ProfileEntry/first_expr")`; the row stays in
  `tests/tables/untested.txt`. Profile-table exhaustion
  (`context.rs:1426` returns id 1 and sets `exhausted`) is unreachable in
  practice: it needs 2^32 profile words (16 GiB) or 2^32 profiles in one
  parse (`profile.rs:67-70`, `node.rs:226`).

## Depth (F4)

`type_digest` keeps a type digest computed below a depth-limit hit or a
cycle in `Walk::abort_memo`, by canonical type and `no_exc`, for the
duration of the outermost `type_digest` call only (`Walk::type_nesting`
back to 0 clears it): a hit raises `aborts` again, and `local_uses` and
`left_out` as the first computation did. The chain
`f(T p0, decltype(p0+p0) p1, ...)` is linear at the limit
(`expr_profile_tests::a_chain_at_the_depth_limit_is_linear`, n = 190,
205, 400; the last two too deep). The same hole is in `keys.rs:252` (a
key computed below a hit is not memoised) and `decl.rs:67` (content
digests); `value.rs:356` keeps aborted results in a per-computation side
map already. The key and content holes are not closed here: they are
bounded by the cycle checks there and no source reached them.

## Parentheses (F2)

`expr::strip_parens` skips a `ParenExpr` only when no profile or key
frame is installed and its operand is not instantiation-dependent
(`ExprDeps::INSTANTIATION`); the cold-map check is made only for a
skipped one.

## Stored results (`RequiresExpr.aux`, `ConceptSpecializationExpr.aux`)

- **Decision: `in`, written as `uv` 0, 1, 2** (`ExprArena::satisfied`,
  `kiln_ast` `expr.rs:3134`). A value over 2 is `Unaccounted`.
- **Where it is set.** At the expression's own analysis
  (`kiln_sema` `sat.rs:1321`, `actions.rs:1737-1738`, `requires.rs:257`),
  write-once (`kiln_ast` `expr.rs:3130-3165`). The result can move with a
  use elsewhere only through the satisfaction cache, and only for a
  program that is ill-formed, no diagnostic required
  ([temp.constr.atomic]/3); a use elsewhere checked afterwards does not
  change it (`demand/_/requires-result-checked-elsewhere`,
  `demand/_/concept-result-checked-elsewhere`).
- **Tests.** The instantiated initialiser of a variable template lives in
  its `definition` unit, which is pending demand: the pair tests of the
  two `aux` rows and the two `demand/_/*-result-checked-elsewhere` tests
  are pending (`# needs: demand`), and `expr_dep_tests::stored_results`
  checks 0, 1 and 2 at the stream.

## Kinds

- **Names.** `expr_dep::decl_name` turns a raw `DeclName` into the
  `Name` of §3.2 exactly as `Walk::plain_name` names a declaration
  (checked over every kind of name by
  `expr_dep_tests::a_raw_name_is_the_declarations_name`). A destructor
  name carries no type (`Name::Destructor`), as a declaration's does.
- **`UnresolvedLookupExpr.b`** is written sorted (`write_refs_sorted`):
  the set found at the definition, not Kiln's order.
- **`CXXDependentScopeMemberExpr.aux`.** `arrow` is `in`;
  `template-keyword` is `out` by the table and untested: Kiln rejects
  `t->f<int>()` without `template` in a dependent context, so the bit
  cannot change alone (`differ/_/dependent-member-template-keyword`
  changes the parse instead).
- **`SubstNonTypeTemplateParmExpr`, `SubstNonTypeTemplateParmPackExpr`,
  `FunctionParmPackExpr`** are built in keep mode (`kiln_sema`
  `subst/exprs.rs:2616`, `:2748`); their pair tests reach them through a
  member template of an instantiation's `decltype` profile. The pack of
  `FunctionParmPackExpr.a` is `Ref::param`, as `size_of_pack_origin`.
- **`SizeOfPackExpr`.** The instantiated form is `TemplateTables`
  `size_of_pack_origin` and `size_of_pack_partial`, written by
  `templ::expr_maps` (`kiln_sema` `pack.rs:860-955`); `b` non-zero is
  `Unaccounted`.
- **`CXXExpansionSelectExpr`.** Kiln builds the node only with
  `ExpansionForm::Dependent` or `Enumerating` (`kiln_sema`
  `expansion.rs:248`, `:1142`); `Iterating` and `Destructuring` are the
  statement's, and their rows stay untested for the statements' package.
  The node is in function bodies only: its pair tests are pending stmt,
  `expr_dep_tests::expansion_select_form_and_depth` checks form and depth.
- **`LambdaExpr`** writes its closure whole through `local::write_decl`;
  pending local.

## Hooks outside the file

- `walk.rs`: `ExprState::profile: Option<expr_dep::Frame>`, and
  `is_fresh` requires it `None`.
- `refs.rs`: `Walk::write_ref`'s local-object branch defers to
  `expr_dep::profile_local` while a frame is installed.
- `walk.rs`: `Walk::{left_out, type_nesting, abort_memo}`.
- `types.rs`: `TypeRef.spelling`, `Walk::absorb_type`, the abort memo in
  `type_digest`, `write_exc_spec`'s owned operand. `decl.rs`: `ty-type`
  through `absorb_type`.
- `lib.rs`: `Area::Spelling` ("spelling"), `mod expr_profile`.
- `expr.rs`: `strip_parens` (F2). `templ.rs`: `head` and `decl_maps`
  (item 1d).
