# WP-034 — statements and the floating-point state

What `crates/slip_digest` (`stmt.rs`, `fp.rs`) reads into
`spec/digest-kinds.md` §6 and §6.1 where they are silent, and what Kiln
was found to do for the "things to settle" of WP-034. Kiln paths are
under `kiln/crates/`.

## The walk

- **Tails.** `stmt::child` enters one level of `walk::NODE_LIMIT` and
  writes the statement in a loop. A kind whose last row is one statement
  returns it as its tail and the loop writes it next: `IfData` `els`,
  `CaseData` `sub`, `DefaultStmt.a`, `LabelStmt.b`, `AttributedStmt.b`,
  `LoopData` `body`, `RangeForData` `body`, `CXXCatchStmt.b`. No row
  follows a tail in its node, so the bytes are those of a recursive
  walk, and an `else if` chain, a run of labels, a chain of attributed
  statements or of loops whose body is the next loop takes one level and
  one Rust frame. No statement has rows after a statement child that
  could form a spine, so no heap stack is needed.
- **Recursion that remains.** Every other statement child (a block's
  statements, `then`, a `switch` body, a `try` block, the handlers, the
  coroutine parts, the expansion parts) is a `child` call: one level
  each. `stmt::tests::frames_fit_the_stack` measures, in the test
  profile, the bytes per level through a block, `if`-`then`, `else`,
  `switch`, `try` and range-for nesting: at most 1 232 bytes, so
  `NODE_LIMIT` (10 000) levels take 12.3 MB and `STACK_SIZE` (64 MiB)
  holds four times that (49.3 MB). The test checks the margin.
  Constraint on later packages: when `StmtExpr` and `LambdaExpr` land,
  `frames_fit_the_stack` gains an expansion-statement shape, a
  coroutine body and a statement-expression shape (a statement inside
  an expression inside a statement), the recursion those make possible.
- **Depth limit.** A chain of nested statements that are not tails,
  `if (x) if (x) …`, takes one level each and reaches the specified
  `NODE_LIMIT`: past 10 000 levels the unit is indeterminate with
  `walk/depth`.
- **Linear work.** `tests/stmt_chains.rs` digests 2 000- and 20 000-long
  `else if` chains and runs of `case` labels, and blocks of 10 000 and
  100 000 statements: no hard cause, the same digests twice,
  `digest.bytes` grows by ten (9 to 11), and walk time within 25 times
  plus 20 ms. The review measured the stream bytes of nested shapes:
  nested `switch` at depth 4/8/12/16/256: 2 169 / 3 393 / 4 617 /
  5 841 / 79 409 (linear); every chain measured is linear in the walk.
  Expansion statements grow with the code they stand for (next section).
- **Ids that name nothing.** A required statement or expression word
  that is 0 writes `uv 0` and `Unaccounted("StmtNode/<Kind>.<row>")`; a
  list word or element that names nothing is left out with the same
  cause. Kiln never builds one (its accessors assert the kind), so these
  are guards, not rows.

## §6 StmtNode

- **`flags`** is gone. Kiln's WP-2026 removed the per-kind flags byte
  (it was always zero), and WP-044 retired its table row at the Kiln pin
  `83566cc47`; `stmt::node` no longer reads it (it used to make a
  non-zero value `Unsupported("StmtNode/flags")`). The node's rows are
  its tag, then `a`, `b` and `aux` as each kind reads them.
- **An `aux` value no row accounts for** is `Unaccounted`:
  `IfStmt.aux` above 3 (`StmtArena::if_kind` reads any other value as
  `Ordinary`, `kiln_ast/src/stmt.rs:728-735`), `CXXExpansionStmt.aux`
  outside `MASK | EXPANDED`, `CoreturnStmt.aux` above bit 0,
  `GCCAsmStmt.aux` outside the four `asm_bits`, and a
  `ContractAssertStmt.aux` with bits above the semantic slot or kind 3.
- **`CXXExpansionStmt` `aux-form` and `aux-expanded`** are read from
  `aux` as `StmtArena::expansion_form` and `expansion_expanded` read
  them (`kiln_ast/src/stmt.rs:764-772`), so a unit test can change them.
- **`GCCAsmStmt`'s four bits** are one `FlagWord` in row order
  (volatile, goto, inline, basic); the constants are Kiln's `asm_bits`
  (`kiln_ast/src/stmt.rs:501-509`), held equal by
  `stmt::tests::asm_bits_are_kilns`.
- **Braces.** `if (x) return;` and `if (x) { return; }` differ: the
  braces are a `CompoundStmt`, a node with its own rows (its FP
  override and its statement list); a block is also a scope. Digest §1
  promises equality for spelling that builds the same AST, which this
  does not (`differ/_/stmt-braces`).

## `CompoundStmt.aux`: the FP override of a block

- **No pragma.** The index is 0 and `compound_fp` gives
  `FpOverride::NONE`: `StmtArena::intern_fp` returns 0 for an empty
  override (`kiln_ast/src/stmt.rs:692-703`). The walk writes the record,
  not the index.
- **Inheritance.** A block records the pragma state in effect at its end,
  which starts as the enclosing state (`kiln_parse/src/stmt.rs:41-67`:
  `fp_outer` is taken at the `{`, the block's own pragmas are applied,
  the state is recorded and the outer one restored at the `}`). So a
  pragma at file scope reaches every later body
  (`differ/_/fp-file-scope-pragma`), and a block's pragma ends with it.
- **Popped and reset.** `#pragma STDC FP_CONTRACT DEFAULT` clears the
  bit and restores `NONE`'s value (`FpOverride::set_contract(None)`,
  `kiln_ast/src/fp.rs:304-312`); `float_control(pop)` restores the
  pushed state. A body after either is equal to one that never saw the
  pragma (`equal/_/fp-pragma-reset`, `equal/_/fp-pragma-popped`).
- **Instantiation** keeps the pattern's override
  (`kiln_sema/src/templ/subst/stmts.rs:167-192`).

## §6.1 FpOverride

- **`mask`.** The bits are Kiln's `fp_bit` constants, held equal by
  `fp::tests::mask_bits_are_kilns`; a bit outside the twelve is
  `Unaccounted("FpOverride/mask")`.
- **A `vals` field whose bit is clear.** Every setter of `FpOverride`
  sets the field's bit with its value (`set_flag`, `set_round`,
  `set_except`, `set_eval`, `set_contract`, `kiln_ast/src/fp.rs`), and
  the one that clears a bit, `set_contract(None)`, also puts back
  `NONE`'s value. So a field whose bit is clear holds `NONE`'s value in
  every override Kiln builds, and two parses that mean the same store
  the same `vals`: the record is written as stored, `mask` included.
  `differ/FpOverride/mask` shows that the mask alone is a difference
  (`FP_CONTRACT ON` sets the value `NONE` has): Kiln emits code from
  the command line for a field whose bit is clear, so a set bit is a
  fact even when its value is the default.
- **`strict_fn`** is set on a function body when a scope in it is
  FP-constrained (`kiln_parse/src/fp_pragma.rs:417-428`, `fn_body_fp`;
  `kiln_sema/src/class/special/define.rs:428-430`), and on every
  function body under `-frounding-math`
  (`kiln_parse/src/fp_pragma.rs:434`). `differ/FpOverride/strict_fn`
  (WP-038's `a.cpp`/`b.cpp` with `// args:`) changes the command line
  only, so it holds the row alone; `fp::tests::every_row_is_written`
  holds it too.
- **Rows no pragma reaches alone.** `float_control(precise, on|off)`
  sets `nnan`, `ninf`, `nsz`, `afn` and `math_errno` together; their pair
  tests are the same pair, and `fp::tests::every_row_is_written` holds
  each. `rounding_math` has no bit and no pragma sets it (it comes from
  the command line): it is written and held by that unit test, and
  `FpOptions/rounding_math` stays in `tests/tables/untested.txt`.

## Statements reached twice

- `SwitchData` `cases`: every case and default statement is in the body
  the walk writes (`kiln_sema/src/stmt.rs`, the switch's case list is
  filled as labels are parsed inside its body). `out`, as the table says.
- `CoroutineBodyData` `promise_stmt`: the `DeclStmt` of `promise`, which
  the `promise` row writes. `out`.
- Others found, all written twice deterministically (no fact is lost or
  depends on order): the coroutine's `return_value` expression is also
  the initialiser of `result_decl` when there is one, or the value of
  `return_stmt` (`kiln_sema/src/coroutine.rs:1281-1322`); an expanded
  expansion statement keeps its pattern parts beside the expansions and
  its `init` statement is the one the pattern has
  (`kiln_sema/src/expansion.rs:1204`), and its `range_init` is the
  same node as the initialiser of the range variable in `prelude`
  (`kiln_sema/src/expansion.rs:286`, `:975-988`); a `__label__` label
  is written by its `DeclStmt` and by its `LabelStmt.a`.
- **A shape for WP-049** (a node reached twice in one stream is written
  once; `docs/wp/WP-049.md`), not special-cased here: an expanded
  statement writes `range_init` twice, and each expansion carries its
  inner pattern, so nesting grows faster than the source. The review's
  measurements, stream bytes at nesting depth d:
  - `template for (int e : {1})` at d = 4/8/12/16: 4 638 / 11 654 /
    21 934 / 35 478 (quadratic: each expansion carries its inner
    pattern);
  - the destructuring form at d = 4/8/12/16: 6 783 / 15 513 / 27 523 /
    42 813;
  - `template for (int e : {1, 2})` at d = 4/8/12: 20 564 / 351 582 /
    5 665 094 (2^d expanded leaves, about 1 380 bytes each: the code
    Kiln builds is that size).
  Once `StmtExpr` lands, the twice-written `range_init` can hold a
  statement, and the doubling compounds per level: WP-049 owns that.

## IfData

- **`then` is never absent.** `act_on_if` stores `then: Some(then)`
  (`kiln_sema/src/stmt.rs:931`); in an instantiation the discarded
  branch of `if constexpr` is an empty `CompoundStmt`, not `None`
  (`kiln_sema/src/templ/subst/stmts.rs:711-725`), and `els` likewise;
  an `if consteval` without a `then` gets a `NullStmt` (`:666`). The
  table's note said "absent when discarded in an instantiation"; it now
  says "always present; a branch discarded in an instantiation is an
  empty block", and `child?` stays (the presence byte is always 1).
  With an explicit instantiation (an implicit one's body is `demand`,
  `decl_func.rs`), changing the discarded branch changes the pattern
  only and changing the taken branch changes both
  (`differ/_/if-constexpr-discarded`, `differ/_/if-constexpr-taken`).
- **`if consteval`** stores no condition; both branches are kept and
  written, in the pattern and the instantiation
  (`kiln_sema/src/templ/subst/stmts.rs:650-669`;
  `differ/_/if-consteval-else`).

## ReturnStmt.b

Set when the return is parsed, to the copy-elision candidate
(`kiln_sema/src/stmt.rs:299-345` `copy_elision_candidate`, used by the
return at `:1873-1883`), and cleared at the end of the function body for
a class-returning non-template function whose candidate is not the NRVO
variable (`kiln_sema/src/stmt.rs:2110-2116`, through
`AstBuilder::clear_return_nrvo`, `kiln_ast/src/builder.rs:1194`). An
instantiation rebuilds the return through the same path
(`kiln_sema/src/templ/subst/stmts.rs:327-339`). Both depend on the body
alone, so the row is `in` (`demand/_/stmt-return-implicit-copy`: a use
elsewhere that defines the copy constructor does not move it). No pair of
sources changes the row without the operand or another return;
`stmt::tests::the_return_candidate_is_written` holds it.

## Labels and local declarations

- A label is written by `local::write_decl` (its ordinal and stream); a
  `goto` before the label, a `__label__` label and a label nothing jumps
  to, renamed, are equal (`equal/_/label-*`); renaming locals,
  parameters and bindings is equal (`equal/_/stmt-locals-renamed`).
- A declaration statement of a typedef or alias writes its tag and its
  count only (§2.4 gives the typedef nothing): `typedef int I;` and
  `typedef long I;` unused are equal, the count differs
  (`equal/_/typedef-only-decl-stmt`, `differ/_/typedef-only-count`), and
  `using T = ns::S;` against `using T = ::ns::S;` is equal.

## Implicit parts

- Range-for: the `range`, `begin`, `end` and `loop_var` variables are
  written by `local::write_decl` with their initialisers, which hold the
  selected `begin`/`end`/`*` functions; `cond` and `inc` hold `!=` and
  `++`. Each is shown by a pair where only the selected function changes
  (`differ/RangeForData/*`). A pattern with a type-dependent range has
  none of `begin`, `end`, `cond`, `inc` (Kiln's dump of
  `template <class T> void f(T &t) { for (int e : t) ; }`).
  Its test is `differ/_/range-for-dependent`.
- Coroutines: every part Kiln builds names the promise's functions, so a
  pair changing one promise function changes the parts that call it.
  The pairs of `differ/CoroutineBodyData/*` keep one promise class on
  both sides and change one member each, so the coroutine changes only
  through the part that calls it. A call names its callee by key, so a
  member whose return type changes changes the coroutine through the
  call's type (`on_exception`, `on_fallthrough`, `return_value`), and a
  member the promise gains changes it through the selection (`allocate`,
  `deallocate`). `return_on_alloc_failure` keeps the function on both
  sides (its presence also selects the `nothrow` allocation) and changes
  its return type. `differ/_/coroutine-return-value-void` holds `return_value` alone: a
  coroutine returning `void` has no result variable and no return
  statement, and dropping a non-template `get_return_object` beside a
  template one selects the template. `differ/_/coroutine-return-stmt-conversion` holds
  `return_stmt`: the conversion of the result variable to the return
  type selects `operator tk() &&` on one side and `operator tk() const &`
  on the other (the result variable is converted as an xvalue: the
  review's `operator tk() &` alone does not compile). `init_suspend` and
  `final_suspend` are `CoawaitExpr`s and `promise` and `param_moves`
  differ in a `CXXConstructExpr`: their tests were `# needs: expr` until
  the expression area landed, and pass now.
  `result_decl` is not isolated: it exists exactly when
  `get_return_object`'s type is not the return type, and its
  initialiser is the `return_value` call, written there too, so
  anything that changes it changes `return_value` or `return_stmt`.
- Expansion statements (`kiln_sema/src/expansion.rs:264`
  `act_on_finish_expansion`: in a template the statement is not
  expanded; builder `kiln_ast/src/builder.rs:4302`): both the pattern
  parts and the expansions are written. Kiln expands a statement exactly
  where it is not in a template, and its depth follows the nesting, so
  no pair of sources changes `aux-expanded` or `b` alone;
  `stmt::tests::the_expansion_bit_and_depth_are_written` holds both.

## Language modes

`CXXExpansionStmt` (reflection) and `ContractAssertStmt` (contracts)
need `-std=c++26` (`kiln_driver/src/args.rs:426`, `:451`
`contracts_for`); the pair runner's `// std: c++26` builds both, so
their pair tests are in place.

## ContractAssertStmt

- **`aux-semantic`** is the evaluation-semantic slot. The builder writes
  `aux` as the kind alone (`kiln_ast/src/builder.rs:4402-4416`
  `contract_stmt`) and nothing else writes the slot
  (`StmtArena::contract_semantic_slot` has no caller), so it is always 0,
  "the translation unit's default", which is the command line's and not
  written (§10.9). The row is written as stored (a non-zero slot would
  be a fact of the statement) and held by
  `stmt::tests::the_contract_semantic_slot_is_written`; no source
  reaches it, so `StmtNode/ContractAssertStmt.aux-semantic` stays in
  `tests/tables/untested.txt`.
- **Preconditions and postconditions** are the function's
  `ColdDeclData` `contracts` (§11.4), written since WP-033, each
  through this walk: the pair tests of `ContractKind/Pre`, `/Post`,
  `/Assert` (against a precondition), `ContractAssertStmt.aux-kind` and
  `.b` (`post(true)` against `post(r: true)`) are no longer pending, nor
  are WP-033's `differ/ColdDeclData/contracts` and
  `differ/_/decomp-block-scope` (renaming a binding is equal, so its
  pair now makes the `return` name the other binding).
- **`ContractSite`** rows are symbolic and write nothing: the presumed
  file, the function's pretty name, the predicate's spelling, the line
  and the column change no unit (`equal/ContractSite/*` with `contract_assert`, `equal/_/contract-site-*-pre` with a precondition).

## GCCAsmStmt

`operands` is `num_outputs + num_inputs` long by construction
(`StmtArena::asm_operands`, `kiln_ast/src/stmt.rs:835-839`; `push_asm`
`:704`); a mismatch would be `Unaccounted("AsmData/num_inputs")`.
`num_outputs` is written after the operands as the table orders it; the
pair of `differ/AsmData/num_outputs` changes the second operand from an
input to an output, whose constraint differs too.

## Mutation sweep

Each row of `stmt.rs` and `fp.rs` was skipped (or written as a
constant) in turn and the pair and unit tests run; the review added 30
mutations of its own. The rows that were not caught by any test, and
their pairs now:
`AsmOperand` `name` (`differ/_/asm-operand-name-swapped`: the presence
bytes are the same, the names swap), `ExpansionData` `expansions`
(`differ/_/expansion-expansions-selection`: the second expansion
selects another `g`), `ExpansionData` `prelude`
(`differ/_/expansion-prelude-adl`: the iterating form's `begin`
call), `CoroutineBodyData` `return_value` and `return_stmt` (above).

The coroutine rows the expression area hid (`promise`, `init_suspend`,
`final_suspend`, `param_moves`) are caught since it landed. The rows
no pair can change alone stay uncaught (re-run after the review: these
three survive, every other mutation is caught):

- `CoroutineBodyData` `result_decl`: implied by `return_value` (its
  initialiser) and by the return type (whether it exists).
- `AsmData` `num_outputs`: implied by the operands, whose constraints
  say which are outputs (an output's starts with `=` or `+`).
- The handler count of a `try` (`CXXTryStmt.b` as a list): harmless,
  since every handler writes its own `CXXCatchStmt` tag, so the count
  is implied by the stream that follows.
