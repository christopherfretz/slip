# WP-049 — back-references: a node reached twice in one stream

What `crates/slip_digest` does to implement `spec/digest.md` §4.3
"Back-references" and `spec/digest-kinds.md` §1.7, the facts of Kiln it
rests on, and what was measured. Kiln sites are under
`kiln/crates/kiln_sema/src/` unless another crate is named; Slip sites
are under `crates/slip_digest/src/`.

## The rule as implemented

- `Walk::back_ref(s, node)` (walk.rs) is the one place the memo is read
  and written. The expression driver calls it once, in `write_node`
  after the parentheses are stripped (expr.rs, `written_before`), and the
  statement driver once, at the head of `stmt::node` (stmt.rs). No kind
  function knows whether its node is a first writing.
- A hit writes `uv 1537` (`walk_row::BACKREF`), `uv` the count, and
  nothing else: for an expression, none of the common rows, cold rows,
  maps or `LeaveDependent` items are pushed; for a statement, none of
  its tails. A miss inserts the node with the stream's next count and
  the node is written as before.
- The count is the stream's (`Stream::count_node`): one sequence for
  statements and expressions, from 0 at the head of each `Stream`.
- `BACKREF` is 1537: the walk's own rows take the range after the node
  enumerations' (`ValueKind` 1280, so 1536), §1.7. The generated
  `tables.rs` gains the module `walk_row`; the generator
  (`tests/tables/`) parses §1.7, checks its numbers (1537, 1538, … in
  order, names unique) and that no other table's range reaches 1536.

## Where the memo lives, and why it is kept per stream

The memo is `ExprState::nodes`, beside `opaques`. So it is put aside and
fresh, then restored, everywhere the expression state is: a type digest
(`take_expr_state`, types.rs), a canonical operand (`profile_expr`,
expr_dep.rs), and with the whole `UnitState` for a key, a content digest,
a unit, a value, and a partial specialisation's arguments
(`take_unit`). That is decision 4 with no new save or restore.

That alone is not enough: several streams are written alone under the
same `ExprState`, the encoded elements of a `*sorted` list
(decl_class.rs:359, decl_scope.rs:319 and :375), a discriminator
(keys.rs:402, :945) and a reference's own stream (refs.rs:114). A memo
keyed by the node only would let one of these name a node of another
(or of the stream around it) by a count that is not its own stream's:
two units that differ could write the same back-reference. So the memo
is kept per stream identity, a per-thread counter taken when the
`Stream` is made (stream.rs); a stream's identity never reaches its
bytes. `NodeMemo` holds the maps of the stream being written apart and
the others' in a map by identity (a stream returns to its own maps when
it writes again), and each stream's maps are one `u32 -> u32` map per
state (the node's id to its count), eight bytes an entry: decision 7
below says why.

The memo could live in the `Stream` instead, since every stream written
with the unit state put aside is a new `Stream` in this tree. It does
not: in `ExprState` it is also put aside by every `take_unit` and
`take_expr_state`, so a stream that one day continues across one (a new
numbering of locals, after which a node's first writing would read
differently) still cannot name a node written before it.

## The state

Decision 3: every piece of walk state that a row of any kind reads, and
what the memo does with it. Found by reading every use of `w.unit`,
`w.in_key`, the profile flag, `type_nesting` and the arguments the
drivers pass down.

| State | Rows that read it | In the memo |
|---|---|---|
| `unit.expr.dependent > 0` (inside an instantiation-dependent expression) | `CXXThisExpr.aux-implicit` (expr.rs:597, `core::this`); `CXXPseudoDestructorExpr.aux-qualified` (expr_init.rs:549) | its own map (`KEY_DEPENDENT`) |
| `in_key > 0` (a key is being computed) | a local reference is `ref none` (refs.rs:67, expr_dep.rs:486); a template template parameter's head is the key's form (templ.rs:199); a declaration's own `noexcept` operand (types.rs:494); a profile frame of its own (expr_dep.rs:284) | its own map (`KEY_IN_KEY`); it changes only with `take_unit` as well, so this is belt and braces |
| `unit.expr.profile` (profile mode, digest-kinds §4.4) | parentheses kept (expr.rs:462); a local reference is the frame's (refs.rs:62, expr_dep.rs:306, :477) | the memo is off: nothing counted, nothing named |
| statement or expression | which table the node is | its own map (`KEY_STMT`) |
| `type_nesting` | whether a left-out fact marks the unit (types.rs:50, expr_dep.rs:457): a cause, not a byte | not needed: constant over one `ExprState`'s life (raised only inside `type_digest`, whose state is fresh) |
| `keep_paren` (the driver's argument) | whether the outermost `ParenExpr` is written | not needed: the key is the node after stripping, so `(e)` kept is the `ParenExpr`'s own entry |
| locals and their ordinals, `next_local`, `opaques`, `next_opaque`, `local_uses`, `unit.types` | the ordinal a local reference writes (local.rs:17-22); an opaque value's number | not needed: a node's first writing numbers what it meets, so at a second reach in the same stream every number it would write is already the one it wrote; only `local_uses`, `aborts`, `left_out` and `bytes` would have grown, and each is read only as "changed since a mark" whose mark is at the head of a stream with a fresh memo or none (types.rs:105-107, expr_dep.rs:451-452, decl.rs:55, keys.rs:229, value.rs:352, templ.rs:351), so the first writing changed it inside the same window |
| `depth`, `node_depth` and the stack probe | limits: a node too deep is `TooDeep` | not needed: a back-reference costs no depth; a first writing that hit the limit made the stream indeterminate already |
| `unit.expr.imms` (WP-046, merged in: the `default_imm` values a `default_immediates` unit collects, demand.rs:499) | no row: `default_imm` writes nothing in a stream | not needed for the bytes; a back-reference does not enter its node, so a shared node's values are collected once, at its first writing, the same for every writing (digest-kinds §11.4 says so) |
| the test hook `tests::NEST` | recurses on the same node to test nesting | the memo is skipped under it (expr.rs `written_before`) |

The conservative form of decision 3 was not needed: the two pieces of
state that change inside one stream are bits of the key.

## Opaque values first

`written_before` (expr.rs) returns before the memo for an
`OpaqueValueExpr` and for a node numbered in `opaques` (the source of an
opaque value, numbered by `Item::OpaqueSource`, expr_misc.rs
`opaque_source`, or by the first `OpaqueValueExpr` that names it). Both
keep today's bytes: the opaque value writes its number, and the source
is written in full where the opaque rule writes it. A source's own
operands are ordinary nodes.

Still superlinear:

- **Nested designated lists in a template** (decision 6): quadratic
  before and after, about 5 % smaller. Kiln records a written form for
  every level of the nest, and builds each afresh:
  `dependent_init_list` (templ/actions.rs:2087) recurses into an inner
  list (:2092) and builds a new `InitListExpr` and `DesignatedInitExpr`
  for it, and `note_syntactic_list` (:2162) is called for each semantic
  level (init.rs:2114). `n` levels are `n + 1` semantic lists and
  `(n + 1)(n + 2) / 2` written ones; only the innermost initialiser is a
  node of two of them, so it alone becomes a back-reference. The test
  `expr_init::tests::nested_designated_lists` pins the count and fails
  when Kiln shares; the reproducer is in the Handback of
  `docs/wp/WP-049.md` ("For Kiln").
- **`template for` over `{1, 2}`**: 2^d expanded leaves, each a
  different instantiation of the body (its own expansion variable), so
  the code Kiln builds is that size (WP-034's finding); the rule takes
  out what was shared (the pattern parts each expansion carries), about
  2.7 times less at d = 12, and the rest is not sharing.
- **`return s;`**: no node is reached twice in this Kiln, in either form
  (`return_operand`, stmt.rs:1917, keeps one of its two trial
  conversions; the citation stmt.rs:1954 of WP-035 is now copy elision
  code). Linear before and after.

## Measured cost of the memo (decision 7)

How: a scratch binary (not in the tree) links `slip_digest` of `main`
at `317e9c3` or of this branch, builds the plan of the LLVM 19.1.7
compilation database under `$SLIP_CORPUS_DIR` (`cargo xtask corpus`),
keeps the 152 observers under `llvm/lib/Support/`, parses each with
`slip_kiln::parse_observer_with` (phase Map) and, on the front end's
thread, runs `slip_digest::digest` (all detail, no names) five times:
the time is the fastest of the five; the peak is `VmHWM` minus `VmRSS`
taken after resetting the high-water mark (`/proc/self/clear_refs` 5)
just before the first run. Release build, no debug info, one thread,
the runs one after another on a quiet machine: before, after, after,
before. The parse is not timed.

No unit of these 152 files reaches a node twice: every file's
`digest.bytes` and `tu` digest is the same before and after, so all of
them are "units with no shared node", and what is measured is the
memo's own cost.

| | Before | After | Change |
|---|---|---|---|
| digest time, sum of the 152 files (fastest of 5, best of 2 runs) | 24.761 s | 25.273 s | +2.07 % |
| the same, the median of 5 | 25.158 s | 25.706 s | +2.18 % |
| peak above the parse, sum over the files (lower of 2 runs) | 1 675 732 kB | 1 637 988 kB | -2.25 % |
| peak above the parse, the largest file (`UnicodeNameToCodepointGenerated.cpp`, higher of 2 runs) | 46 568 kB | 48 244 kB | +3.6 % |
| that file's time | 216.5 ms | 245.1 ms | +13 % |
| the two runs of before against each other (noise) | 25.310 s | 24.862 s | -1.77 % |

The sum is within 3 %, in time and in memory; one file is not.
`UnicodeNameToCodepointGenerated.cpp` is one array of 242 258 integer
literals, each under its conversion to `uint8_t`: about half a million
nodes in one unit's stream, so half a million inserts, and a map of
2^19 or 2^20 slots of 9 bytes (the old table and the new one both live
while it grows). The first form of the memo, one map from `(node and
state, stream)` to a `u64` count, 25 bytes a slot, cost that file up to
64 MB more peak (+138 %, the two runs 73 and 111 MB) and 25 % more
time; the
form that landed (`u32` to `u32`, one map per state, per stream) is the
one above. Less would need a memo that leaves nodes out (a node without
children, say), which decision 1 does not allow: every node is counted.
Decided at review: leaves stay in the memo. Leaving them out later
would change only streams that hold a back-reference (a node left out
is written in full where it is now named, and every count after it
moves down), so no unit in which no node is reached twice would move.

## Goldens and expectations that moved

Digest goldens: none moved. `tests/golden/profile_bytes.txt` (profile
mode, where the memo is off) is unchanged, as are every pair test,
`determinism.rs`, the chain tests and the 152 `tu` digests of
`llvm/lib/Support` above (no unit there has a shared node). What moved:

- `tests/golden/tables_small.txt`, the generator's golden: its header
  names §1.7 and it has an empty `walk_row` module. Not a digest; the
  generated `src/tables.rs` gains `walk_row::BACKREF`.
- `expr_misc::tests::coawait_writes_common_once` and
  `pseudo_object_writes_operands_once`: each compares the walk with a
  naive encoding that writes the opaque values' sources twice (the
  `CoawaitExpr` common expression; the two operands of the
  `PseudoObjectExpr`). With the rule, the naive encoding's second
  writing of the source is in full (a numbered source is not a
  back-reference) but the source's own operands are back-references, so
  the saving the test asserts (64 bytes where `common` is 275) no
  longer matched. The shared nodes are the sources' operands; the
  naive encoding is now measured without back-references
  (`walk::without_back_refs`, test only).
- `expr_init::tests::nested_designated_lists`: a measure, now a test
  (decision 6).

## Tests

- `walk::backref_tests` (backref_tests.rs): `the_shapes_are_linear`
  (each shape at N and 4N, at most 4.5 times, and whether it writes
  back-references); `a_node_written_again_is_a_back_reference`;
  `statements_and_expressions_are_counted_in_one_sequence`;
  `a_statement_and_an_expression_of_one_number_are_two_nodes`;
  `a_node_in_another_state_is_written_again`; `shared_node_in_two_states`
  (the pair of decision 3 as a unit test, the state-0 reach first);
  `a_node_shared_by_a_dependent_pattern_and_its_expansions` (sources do
  reach one node in both states: in
  `struct S { int m; void k() { template for (auto e : {1, 2}) { g(m + e); } } };`
  the implicit `this` and its member access, and in
  `template for (auto e : {1, 2}) { g(g(1) + e); }` the call `g(1)`,
  are written in the dependent pattern and reached again in the
  expansions, where they are written in full and counted again; there
  the dependent reach always comes first, so a pair cannot be made
  equal by leaving the bit out, and this test is what kills that
  mutation in a real source); `opaque_values_come_first`;
  `inner_streams_neither_see_nor_lose_the_memo`;
  `a_unit_written_inside_another_is_the_same` (a determinate
  `static_assert`, content-keyed, with a shared node, written inside an

  `a_back_reference_in_a_unit_stream_counts_from_its_first_node`;
  `a_skipped_paren_is_keyed_as_its_operand`;
  `shared_nodes_under_a_relocation_rule`; and the measure
  `measure_shapes`.
- `expr_init::tests::nested_designated_lists`, no longer ignored:
  decision 6 below.
- Pair tests: `differ/_/backref-{range,expansion,destructuring}-{inside,after}`,
  `differ/_/backref-nested-lists-inside`; `equal/_/backref-locals-renamed`
  and `equal/_/backref-content-unit` (a `static_assert` in a class,
  content-keyed, whose digest is computed inside the class's stream;
  every unit determinate, three slots sharing one clause, the clause in

  checks the back-references and the determinacy). `determinism.rs`
  digests every pair directory twice and in another process, so this
  pair is its case of a shared node in a unit written inside another's
  stream. The pairs show that sharing happens and that it does not move
  a digest; that it is encoded right (the count, the key) is checked
  only by the unit tests above.

## Owed later

- The bodies of implicit instantiations are still `Pending(Demand)`, so
  sharing that could depend on the order of instantiation cannot be
  observed yet. The package that walks instantiated bodies must re-run
  the review's probes, each with back-references on and off: the order
  of instantiation under `template for`, a range-for, a structured
  binding with a rewritten `!=`, a default member initialiser, folds
  over a pack, coroutines (an inserted `co_await`), a pseudo-object
  `?:`, and designated ranges and nested designated lists in a
  template.
