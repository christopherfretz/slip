# WP-041 — what a unit's own spellings hold beyond their profiles

What `crates/slip_digest/src/own_spelling.rs` and its sites read into
`spec/digest-kinds.md` §4.2 rules 1 and 3 and §4.4 ("The mark",
"Spellings"), and where the code departs from the letter of
`docs/wp/WP-041.md`. `Area::Spelling` is gone: no unit is
`Pending(Spelling)`. The rule throughout, since the fix round: where a
unit's meaning depends on something its digest does not hold, the unit
is indeterminate with a named cause. No hazard is accepted.

## Decisions as built

1. **A found set** is written as the full walk writes an
   `UnresolvedLookupExpr`'s: `Walk::write_refs_sorted` (a count, the
   `Ref`s sorted by their bytes, duplicates removed, a using-shadow as
   its target). Pinned: `own_spelling_tests::the_set_is_written_sorted_and_without_duplicates`.
2. **The list** is one per unit, written after the unit stream
   (`own_spelling::write_unit_list`, called by `units::write` and
   `Walk::content_hash` before the stream is finished): `count`, then per
   entry `uv` kind and payload (`1` `Found` `ref*sorted`, `2` `Oper`
   `ref*sorted`, `3` `Alias` `ref`, `4` `Chosen` `count` and `ref?` each,
   `5` `Profile` `bytes`, `6` `Round` `uv` reading, `count`, then `uv`
   node and `tag` `FpRound` each). The unit's entries are collected in
   walk order in `UnitState::facts`; a key and a content digest take a
   fresh `UnitState`, so nothing they read lands in the unit that asked.
   Unit streams are prefix-free, so the list appended after one is
   unambiguous. An empty set is an entry (its place keeps the entries of
   two spellings aligned) but does not make the list due; a unit with no
   due entry writes nothing more. Pinned on the whole pair-test corpus by
   `own_spelling_tests::a_list_changes_only_the_units_that_write_one`: with
   lists switched off, the units whose digest moves are exactly as many
   as the lists written and no key moves, except a content-keyed unit's
   (a `static_assert`'s key is its digest, `spec/digest.md` §3.3), whose
   holders change with it (`differ/_/spelling-static-assert`).
3. **Walk order** is the type's structure (rule 2) and, in an
   expression, profile mode's order (pre-order, children as
   `expr_profile::node` pushes them). Pinned by
   `own_spelling_tests::the_order_of_two_spellings_changes_no_digest` (eleven
   shapes, each with the two declarations in both orders),
   `the_order_of_two_partial_specialisations_changes_no_digest`,
   `equal/_/spelling-one-profile-two-spellings`,
   `equal/_/spelling-order-own-noexcept` and
   `equal/_/spelling-order-array-parameter`.
4. **Instantiated declarations** (decision 4). Kiln rebuilds every
   instantiation-dependent expression when it substitutes
   (`Substituter::needs_rebuild`, `kiln_sema/src/templ/subst/exprs.rs:30`),
   so a member template of `A<int>` has an expression of its own; the
   rebuilt unresolved name keeps the pattern's found set
   (`Substituter::callee`, `exprs.rs:2341`). Rule 2 applies as it stands.
   Pinned: `own_spelling_tests::an_instantiated_member_reads_the_patterns_found_set`.

## The rules as built

- **The mark** (`expr_profile.rs`) is a function of the profile, not of
  the spelling Kiln met first: it is raised at every
  `UnresolvedLookupExpr` (an empty set too), every `oper_lookups` entry
  (an empty set too), every `CXXNewExpr`/`CXXDeleteExpr`, a fold that
  `fold_left_out` (rule 9), and an operation that may round whose type is
  floating or dependent (rule 8), and a resolved `DeclRefExpr` or
  `MemberExpr` whose referent is a specialisation or a member of a class,
  of a class template specialisation or of an enumeration
  (`own_spelling::name_parts_left_out`, rule 10). It decides rule 5, `spelling/profile`
  and `spelling/conversion-name`; the list never depends on it.
- **Rule 1** (`own_spelling::expr`, `node`): an explicit stack mirroring
  `expr_profile::node`. Entries: `Found` per `UnresolvedLookupExpr`;
  `Oper` per expression with an `oper_lookups` set; `Chosen` per resolved
  `new`/`delete`. Types are read as written: a cast's `cast_written`
  type, else the node's. A kind profile mode walks in full is
  `spelling/full` when its own profile walk left a fact out (`full`: the
  mark of the node, not of the type around it).
- **Rule 2** (`own_spelling::ty`): the arms are exhaustive over `TypeView`. A
  canonical type that is not instantiation-dependent is skipped; a type
  with sugar is walked whatever its flags, because Kiln's flags do not
  carry the instantiation dependence of a resolved `noexcept` operand or
  of a constant bound as written. A function declaration's own type
  (`own_fn`) reads neither its exception specification (its unit walks
  it in full, from the written function node: `Walk::own_proto`, §4.2
  rule 3) nor its declared parameters (each `ParmVarDecl`'s unit writes
  its type as written, `ParamData::original_ty` for an adjusted one).
  `ConstantArray` reads `size_expr` (rule 7); a `TemplateSpecialization`
  that is not an alias reads its template name and written arguments,
  with or without `underlying`.
- **Rule 3, the sites**: `Walk::absorb_type` at unit level
  (`write_type`, `decl_node` `ty-type`); `expr_dep::profile_expr` at unit
  level; `expr_dep::profile` of a `ProfileId` (`spelling/profile` when
  its walk raised the mark); `Walk::write_args` at unit level; a default
  template argument (`templ::decl_maps`); `templ::partial_spec_info`
  (`PartialSpecInfo::args`).
- **Rule 4**: `Typedef`, a `Using` type naming a typedef-name, and an
  alias template specialisation (its pattern) are an `Alias` entry when
  the typedef-name's own aliased type as written makes a list due or
  carries a cause (`Walk::alias_due`). A block-scope typedef or alias has
  no unit: its declaration writes its aliased type, profile and list,
  into the enclosing unit (`local::write_decl`), and a use descends into
  the aliased type. Pinned: `differ/_/spelling-alias-template`,
  `spelling-member-alias`, `spelling-local-*`,
  `own_spelling_tests::an_alias_holds_its_set_and_its_user_the_ref`,
  `a_use_through_an_alias_lists_the_alias`,
  `an_alias_whose_spelling_is_indeterminate_is_listed`.
- **Rule 5**: see below.
- **Rule 6**: see the survey.
- **Rule 7** (`own_spelling::written_expr`): an expression the written type
  holds where the canonical type holds a value (a `size_expr`, an
  argument of a specialisation with `underlying`, a resolved `noexcept`
  operand) that is instantiation-dependent and neither type- nor
  value-dependent: its profile bytes are a `Profile` entry (taken with
  spelling reading off, its cause absorbed), then it is read by rule 1.
  Where Kiln keeps no such expression for a type that is
  instantiation-dependent and not dependent, the unit is
  `spelling/bit-int-width` (a `_BitInt` width) or `spelling/array-size`
  (a constant bound with no `size_expr`).
- **Rule 8** (`own_spelling::expr`): each reading has an ordinal in the unit
  (`UnitState::roots`); its nodes whose `fp_round` is not `Dynamic` are a
  `Round` entry by pre-order position. Complete: every node of an
  expression in a unit is either walked in full (`fp_round` is a row of
  the full walk, `expr.rs`) or read by rule 1, so every rounding mode
  under which a unit's spellings were written is in its digest.
  Indeterminacy was the alternative; it would have made every floating
  operation in a dependent type under `FENV_ROUND` indeterminate, while
  the mode is a fact Kiln holds and the unit can write.
- **Rule 9** (`expr_profile::fold_left_out`): a `CXXFoldExpr` over an
  operator other than `.*`, in profile mode or in the full walk, is
  `spelling/fold-operator` when some declaration that is not a member
  function is named for that operator (for a comparison, for any
  comparison: C++20 rewrites them). Kiln records no `oper_lookups` set
  for a fold ("For Kiln"). With no such declaration in the translation
  unit, the definition context finds nothing in every spelling.
  **Cost:** every `+` fold (and every fold over an operator some
  non-member function declares) is indeterminate in a translation unit
  that declares a non-member `operator+`, which every one including
  libc++'s `<string>` does, until Kiln keeps a fold's operator set (Kiln
  WP-2625, "For Kiln" 1).
- **Rule 10** (fix round 2; `own_spelling::name_parts`): what a resolved
  name's prefix and template arguments hold beyond the referent is
  written; their spelling is not. Rule 1 reads a resolved
  `DeclRefExpr`'s or `MemberExpr`'s `DeclRefExtra` `qualifier` (as
  rule 2 reads a nested name specifier) and, when the referent is not a
  template, its `template_args` (as written, `Ctx::Known(true)`). The full
  walk does the same through `Item::Exec(name_parts)`, from
  `expr_core::decl_ref` and the `MemberExpr` arm of `expr::cold`: at unit
  level it reads them into the list; off unit level (a key, a scratch
  walk) it raises the mark when the referent is of a kind whose prefix or
  arguments can hold a fact. The arguments are read whatever their flags.
  A prefix as such writes nothing, so a requalified name stays equal
  (`equal/_/spelling-requalified-name`, `-template-prefix`, `-signature`).
  Cost on the pair-test corpus: no bytes; with rule 10 the list test
  counts 190 lists over 192 changed units, without it 168 over 170, and
  all 22 more are the new probe tests: no unit written before the round
  gains a list entry or a cause.

## Departures

- **The trigger is the unit's own spelling, not the mark**: a unit writes
  its list whenever its own spelling holds a due entry
  (`differ/_/spelling-first-spelling-empty`).
- **Rule 4 reads an alias template specialisation's arguments**: they are
  the user's spelling.
- **Site 3 reads `PartialSpecInfo::args`**, not
  `TemplateTables::args_as_written` (Kiln fills it only for explicit
  specialisations).
- **Four more kinds of fact**: `Oper`, `Chosen`, `Profile`, `Round`.
- **`Walk::write_args` and default template arguments** are sites too.
- **A block-scope typedef writes its aliased type** (§2.4, which said it
  writes nothing): an unused alias's lookup is still the function's
  (`differ/_/spelling-local-alias-unused`). So `typedef int I;` against
  `typedef long I;`, unused, now differs:
  `equal/_/typedef-only-decl-stmt` (WP-034) moved to
  `differ/_/typedef-only-decl-stmt`.
- **A dynamic exception specification of a function declaration's own is
  written** (fix round 2, R3; the first round read it from the canonical
  type as `noexcept(false)`): Kiln keeps the list in C++17 and reads it in
  the override check (`check_override_exc_spec`), so `throw(int)` against
  `throw(long)` changes what the program means.
  `equal/_/exc-dynamic-is-none-in-cxx17` moved to
  `differ/_/exc-dynamic-is-kept-in-cxx17`; C++14 through the API:
  `tests/dynamic_exception_cxx14.rs`.
- **Rule 9 is narrowed** to translation units that declare the operator:
  the brief's letter (every fold over an overloadable operator) made 14
  pair tests over builtin `+` and `*` indeterminate where no candidate
  exists anywhere.
