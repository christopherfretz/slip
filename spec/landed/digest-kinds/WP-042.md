# WP-042 — `kiln_abi::odr_def` against the digest's tables

The audit asked by `docs/requests/KQ1-digest-fields.md` §E. Kiln's
`odr_def` hashes a definition for mortar's link-time ODR check; Slip's
digest hashes a unit to verify a transformation. Both read Kiln's AST.
This file lists every read `odr_def` makes, maps each to the row of
`spec/digest-kinds.md` that covers it, and gives a verdict (the verdicts
are those of `docs/wp/WP-042.md`). It then lists the rows `odr_def` never
reads.

- **Kiln read**: Slip's pin, `62d190007`, which is the submodule `kiln/`.
- **Paths**: in the tables `file:line` is under
  `kiln/crates/kiln_abi/src/odr_def/`, and `odr.rs` is
  `kiln/crates/kiln_abi/src/odr.rs`.
- **The contract**: `kiln/spec/abi.md` "Definition hash (`odr_def`)"
  (`abi.md:2202-2683`).
- **Slip's side**:
  - `spec/digest.md` and `spec/digest-kinds.md` at the base of branch
    `wp/042-odr-audit`;
  - the landed decisions in `spec/landed/digest-kinds/`;
  - `crates/slip_digest` where a decision had to be checked in code.

## Head

### What differs by purpose

These three reasons are fixed by the two specifications. They are not
findings. Table lines cite them as **P1**, **P2** and **P3**.

- **P1, definitions only.** `odr_def` hashes a definition the linker may
  merge:
  - an inline function, an instantiation, or a vague-linkage variable;
  - a template's own declaration is skipped as `partial`
    (`abi.md:2202-2240`; `decl.rs:52-56`; `mod.rs:491-494`).

  The digest has a unit for every entity, defined or not, and writes
  template patterns in the template's unit (digest §2.2,
  digest-kinds §9).
- **P2, names for the linker against keys.** `odr_def` names:
  - an entity by its mangled name without ABI tags (`refs.rs:157-200`);
  - a type by its canonical `<type>` encoding (`refs.rs:114-134`);
  - a local by its index in walk order (`mod.rs:683-695`);
  - a TU-local item by the per-TU placeholder `0xA4`, setting
    `USES_INTERNAL` (`abi.md` O-2, O-16).

  The digest names an entity by key (digest §3), a local by ordinal
  (digest §4.3), and a type by its canonical structure (digest-kinds
  §4.1). The two are compared by what distinguishes two entities.
- **P3, token-like against resolved meaning.** `odr_def` follows the
  standard's "same sequence of tokens", and also the must-equal rule
  across routes (`abi.md` "Not hashed", `abi.md:2579-2587`; the Misses
  table, `abi.md:2554-2573`):
  - it leaves out what follows from the operands: node types, value
    categories, implicit conversions, odr-use marks, lazily computed bits;
  - it replaces a value from a builtin macro with a placeholder.

  The digest writes resolved meaning. A written form `odr_def` keeps and
  the digest drops is expected. A resolved fact the digest drops is a
  finding.

Two more conventions:

- **Partial reads.** A read whose only effect is to mark the row
  `PARTIAL` (Kiln then compares nothing for the definition) has the
  verdict `same` when Slip's row is `in`. Kiln looked at the fact and
  declined to compare it, which is not a gap in Slip.
- **Hazards.** A fact under "Hazards accepted for now"
  (`spec/digest-kinds.md:5742`) is cited as a known gap.

### Areas pending when this was read

These areas have rows decided `in` whose code was still being written:

- expressions: WP-035, WP-036, WP-037;
- local entities: WP-040;

## The table

Columns:

- **Where**: `file:line` in Kiln at the pin.
- **Fact**: the descriptor and member as digest-kinds §1.2 writes a row,
  or the query's name.
- **`odr_def`**: what the hasher does with the fact. "w" means written;
  "r" means read to decide something.
- **Row**: the row, with its decision.
- **Verdict**: one of the five fixed verdicts.

## Findings

### Against Slip

**S1. Parameter attributes on a declaration other than the one read.**

The fact: Kiln reads `[[indeterminate]]` on parameter *i* of every
declaration in the function's chain (attrs.rs:104-112).

Slip:

- writes a parameter with `local::write_decl` from the declaration read
  only (`crates/slip_digest/src/decl_func.rs:62-66`);
- writes its attributes with `decl_attrs`, whose chain is the
  parameter's own (`crates/slip_digest/src/attrs.rs:565-578`);
- has a parameter with no redeclarations: parameter *i* of another
  declaration is another `DeclId`, which `alias_params` (decl_func.rs:88)
  maps only to an ordinal.

So when the function is defined, the attributes written on its
parameters in the earlier declarations are lost. The rule of digest-kinds
§10.1 ("every declaration of the entity's chain") does not say what a
parameter's chain is.

C++26 [dcl.attr.indet]/2 requires `[[indeterminate]]` on the first
declaration. That is exactly the declaration Slip does not read when
another one is the definition.

The other parameter attributes have the same gap:

- `nonnull`, `noescape`, `pass_object_size`, `annotate`;
- Swift ABI attributes, whose parameter-ABI list `FuncProto` `abis` does
  carry.

```cpp
// A: the attribute is on the first declaration
void f([[indeterminate]] int x);
void f(int x) { int y = x; }   // reading x is not erroneous

// B: no attribute anywhere
void f(int x);
void f(int x) { int y = x; }   // erroneous behaviour (C++26 [basic.indet])
```

The pair test, given here and **not run**. It is in the form of
`crates/slip_digest/tests/differ/`: source A and source B above, unit
`f`, expected `differ`. By reading the code, `slip_digest` at the base
gives `equal`, since `f`'s definition is the declaration read.

Proposed (digest-kinds §10.1, a sentence after the declaration rule):

> For a parameter, the chain is parameter *i* of every declaration of
> the function's chain that `ParamData` `default_arg` reads
> (block-scope declarations left out), in chain order.

This is the set WP-026 already uses for default arguments.

Closed while auditing:

- **A static member's in-class initialiser held by another declaration.**
  Closed with WP-026 "The declaration read"
  (`crates/slip_digest/src/decl_func.rs:277-292`).
- **`override`.** The note holds.

### Possible gaps of Kiln's

- **K1. Local classes.** `local_class` (lambda.rs:386-412) writes the
  kind, bases and members of a local class. It does not write:
  - `RecordData` `tag`: a local `union` and `struct` with the same
    members hash alike, although their layout differs;
  - the class's attributes, or its fields' (`packed`, `alignas`);
  - a local enumeration's underlying type.

  Miss #13 sends `alignas`/`packed` to kind 3, but a local class has no
  kind-3 row (`NotTuLocal::scopes` fails in a function, odr.rs:154).
  Example: a `sizeof(U)` that differs (8 against 16).
- **K2. Coroutine lambdas.** `closure_digest` hashes `LambdaData` `body`
  (lambda.rs:109). For a coroutine that is the unwrapped compound
  statement: kiln_sema `lambda/mod.rs` sets `lambdas.body` before
  `end_function_body` wraps it (coroutine.rs:1139). So the
  `CoroutineBodyStmt` (promise, initial and final suspend, implicit
  `co_return`, allocation) of a coroutine lambda is never hashed. An
  ordinary coroutine hashes it through `FunctionData` `body` (mod.rs:471).
- **K3. Structured bindings.** `ColdDeclData` `binding_expr` and
  `binding_var` are not read (decl.rs:240-246). The `get` that a
  tuple-like binding calls is not hashed, so two units that resolve
  `get<0>` to different overloads hash alike.
- **K4. `cleanup` on a local variable.** A local hashes only the listed
  attributes (decl.rs:238, attrs.rs:42-49). The function
  `__attribute__((cleanup(f)))` calls at scope exit is not hashed.
- **K5. `[[clang::musttail]]`** (low) is not hashed (stmt.rs:147-150,
  attrs.rs:178-195). A guaranteed tail call changes stack behaviour,
  not values.
- **K6. Concatenated string literals.** Any concatenated literal becomes
  the whole-literal placeholder (expr.rs:213), not only one with a
  builtin-macro piece. So `"ab" "c"` and `"ab" "d"` hash alike. Miss #9
  describes only the `__FILE__` case. This may be intended (the ruling
  says must-equal outranks detection), but the Misses table should say
  so.

Notes for the reply, not gaps:

- `type_trait_value` truncates to bool (init.rs:192). The traits' types
  are hashed, so nothing is lost.
- `#pragma clang attribute` copies its nodes without `IMPLICIT`
  (kiln_sema `pragma_attr.rs:503-518`), so they are hashed as written.

## Changes I would make to `spec/digest.md` and `spec/digest-kinds.md`

- **C1.** `LambdaCapture` `implicit` and `LambdaData` `default`
  (digest-kinds §10.4, lines 4879 and 4913). Keep `in`, and add a note:
  Kiln's ODR hash treats `[=]` with an implicit capture of `x` as equal
  to `[x]` (`kiln/spec/abi.md:2610`). The digest reports a transformation
  between the two as a difference. That is deliberate: in a template the
  default decides what an instantiation captures, and `[=]` captures
  `this` differently.
- **C2.** §10.1, the declaration rule: add the parameter sentence of S1.
  Then the same sentence in `ParamData`'s introduction (§5.4).
- **C3.** `AttrNode` `flags-implicit` (line 4510): the note says "added
  by sema or by a pragma". Kiln does not set the flag on attributes
  added by `#pragma clang attribute` (kiln_sema `pragma_attr.rs:503-518`
  copies the node). Change it to "added by sema; an attribute from
  `#pragma clang attribute` is stored as written, without this bit".
- **C4.** digest.md: none. Every digest-side `no-row` already has its
  stream.
