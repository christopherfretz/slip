## New Kiln variants Slip's matches meet

- `ExpansionKind::Embed` (WP-2544): the `#embed` bytes are an expansion
  entry whose expansion location is the directive's `#`. `sites` rule 1
  meets it, the spelling is in scratch space, so an edit is refused
  `pasted` (T3); `parse.rs` `expanded_before`/`after` treat it as a macro
  body, reached only for spans already refused; `ranges` refuses inside
  the bytes (`Scratch` or `Kiln`) and across them (`Directive` or `Kiln`).
  Right: no byte of the file is the token. Tests: `tests/parse.rs`
  `s1_embed_tokens_have_no_range_and_rank_where_the_directive_is`,
  `s1_an_edit_inside_or_across_embed_bytes_has_no_range`.
- `FileOrigin::Overlay` (WP-2390): read like `Disk` in `collect_inputs`,
  `session.rs` `read_files` and `lookups.rs`. Right: the bytes are the
  unit's.
- `RefRole::Redecl` (WP-1932): `takes_part` true (the name is the
  declaration's); `spelling.rs` counts it written. New roles `UsingDecl`,
  `UsingDirective`, `NamespaceAlias`, `Elaborated`, `SpecTarget`,
  `Designator`, `Concept`: `written.rs` gives them as references;
  `classify` explains a constructor under `UsingDecl` (an inheriting
  constructor).
- `Found::Absolute`, `Found::Embed` (WP-2620): `lookups.rs` lists the name
  where it is (it already did, whatever the form).
- `RunError::StackExhausted` (WP-2480/2500): `Session` keeps a `tripped`
  flag so `stack_exhausted()` still reads true after the run (Kiln now
  puts its own flag back after each run); mapped to `NotConstant` as
  before.
- `SessionRefused::Stopped` (WP-2322): a unit that stopped (a fatal
  error, or no tree) is `diagnosed` when its diagnostics hold an error,
  else `CommandLine`, as Kiln reported the two before.
  `SessionRefused::Panicked` (WP-2322): `CompileError::Panicked`, as the
  `catch_unwind` that caught it before gave. `KilnEntryError::NotConstexpr`:
  `EntryError::NotConsteval`. All in `session.rs`; right because each is
  what the same source gave at the old pin.
