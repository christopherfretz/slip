## `slip_kiln`: the interface the package adds

- `slip_kiln::kiln::{lex, pp}`: `kiln_lex` and `kiln_pp`, re-exported.
  `kiln_lex` is a new workspace dependency, named only by `slip_kiln`'s
  manifest.
- `ParseOptions` (`#[non_exhaustive]`, `Default`: everything off) with
  one field, `pp_record`, and `parse_observer_with(observer, phase,
  round, options, f)`: the option is passed to `FrontEndOptions::
  pp_record` and to nothing else. `parse_observer` passes
  `ParseOptions::default()`. This changes the signature
  `spec/model.md` §8.4 states: it gains the `options` parameter before
  the closure, and `Unit` the method below.
- `Unit::pp_record(&self) -> Option<&'r kiln::pp::PpRecord>`: Kiln's
  `Preprocessor::record()` (`kiln_pp/src/preprocessor.rs:639`) of the
  preprocessor the closure sees, `None` when the option was off.

**Why the accessor is sound as it is.** The record is owned by the
preprocessor (`Option<Box<PpRecord>>`, `preprocessor.rs:405`), which the
front end lends to the closure as `FrontEnd::pp: &'r Preprocessor<'sm,
'r>` and drops after it returns. `PpRecord` itself has no lifetime
parameter: it owns its tables (`kiln_pp/src/record.rs:342`), holding
locations of the unit's source manager, symbols of the unit's interner,
and its definitions as `Rc<MacroDef>`. So `record()` gives a borrow for
`'r`, the lifetime every other borrow of `Unit` has (`ast`, `sm`,
`oven`), and the accessor returns exactly that: nothing is copied, and
the borrow checker keeps the record from leaving the closure. Because of
the `Rc`s the record is neither `Send` nor `Sync`, so a `&PpRecord`
cannot cross to another thread either; `Unit` stays usable as before
(nothing in Slip sends a `&Unit` to another thread). Copying the record
out to outlive the parse is not possible without Kiln's help (a
`Send` form, or a record that is not the preprocessor's); no package
asks for that yet. The record's names read through the AST's interner
(`Ast::symbols`): the test reads each expansion's macro name that way
and compares it with the text at the invocation.

## Calling Kiln's functions (decision 1)

The editable ranges (`SourceManager::editable_range`,
`editable_file_range`, `kiln_source/src/editable.rs`), the expansion
entries (`SourceManager::expansion_count`, `expansion_entries`,
`kiln_source/src/manager.rs`) and the end of a token
(`kiln::lex::token_end`, `kiln_lex/src/token_end.rs`) are reached
through `Unit::sm()` and `slip_kiln::kiln::lex`; no function of Slip
computes them. `Preprocessor::add_callbacks` is not reachable through
`Unit` (the closure sees the preprocessor after the unit is read); no
package needs it in the parse task yet.

## Tests (`crates/slip_kiln/tests/parse.rs`)

- `s8_4_run_pp_record_on_request`: on a source with `ONE` (object-like)
  and `F(x)` (function-like), parsed with `pp_record`, the record's
  expansions in the main file are exactly `ONE` then `F`, each named by
  its definition and by the text at its invocation; parsed without it,
  `pp_record()` is `None`, and the two shards are equal.
- `s8_4_run_editable_ranges_and_token_end_through_slip_kiln`: on that
  source, a range wholly in the file is itself (`int bar`); a range from
  `F`'s argument inside its expansion to a file location after the
  invocation is refused; the range of the argument's token in the
  expansion is its bytes in the file (`bar`). These are the answers of
  Kiln's `kiln_pp/tests/editable_range.rs` (`file_tokens_and_bad_ranges`,
  `cpp_replace_whole_expansions_only`, `cpp_subst_argument_ranges`).
  `token_end` at an identifier is 3 bytes on, at `"ab"_x` 6 (the
  suffix is part of the token, as in `kiln_lex/tests/token_end.rs`).
