# WP-046 — the resolved properties and the `default_argument` unit

What `crates/slip_digest/src/demand.rs` writes for `spec/digest-kinds.md`
§11.1 properties 1, 2, 5, 6 and 7 and for the derived unit of §11.4,
where the spec left a choice. Kiln is cited at the pin `62d190007`.

## The deferrable class (§11.2)

- **Every rule reads the representative declaration** of the entity
  (`Walk::representative`), as the own unit does.
- **Explicitly defaulted on the representative declaration: always of the
  class.** Kiln defers such a function when no specification is written
  (`kiln_sema/src/class/special/deletion.rs:974-977`; comparisons
  `class/compare/default.rs:473-477`). On resolution it re-points every
  declaration's type to the computed specification
  (`class/special/excspec.rs:53-118`, through `with_exc_spec`,
  `class/special/declare.rs:1010-1015`), which replaces the prototype:
  nothing in `Ast` then says whether a specification was written. A
  written one (`S() noexcept = default;`) is therefore in the resolved
  unit too (`tests/resolved/exception_spec/defaulted-noexcept`).
- **Instantiated declarations: by the pattern, under every form of
  instantiation.** Kiln defers a dependent `noexcept(expr)` or a dynamic
  specification naming a dependent type when it instantiates a member
  declaration (`kiln_sema/src/templ/subst/decls.rs:766-770`,
  `except.rs:729-754`) or a function template's specialisation
  (`templ/subst/decls.rs:1170-1195`), whatever the specialisation kind,
  and resolves it when it defines the function
  (`kiln_sema/src/decl.rs:9670-9676`). Under an explicit instantiation
  definition the members it defines are resolved and the others are not
  (`tests/resolved/exception_spec/explicit-instantiation`), so the rule
  cannot follow the kind to decide resolution; it says only whether the
  declaration was made by instantiation (`demand::instantiated`, today
  `templ::instantiated_declaration`; WP-045's effective kind replaces
  that one call).
- The pattern of a function template's specialisation is the primary
  template's pattern (`SpecInfo` `template`): `SpecInfo` `from` names the
  template until the definition is instantiated, so it changes with use.
  Other declarations: `Ast::instantiated_from`. The pattern's specification
  is read from every declaration of its chain; a `Deferred` one there, or
  `DependentNoexcept`, counts as deferred, and a pattern that is itself of
  the class makes the instantiation so (a member template of a class
  template's instantiation). No pattern found: of the class.
- Over-inclusion is the safe direction and is accepted: Kiln substitutes a
  local-scope pattern's specification at once
  (`templ/subst/decls.rs:1174`) and a pre-C++11 dynamic one with the
  declaration; such functions are of the class and their resolved unit
  exists in every parse. A defaulted member of a class template's pattern
  is of the class too; its written or dependent specification is then in
  its resolved unit.
- An inheriting constructor is `IMPLICIT` on every declaration
  (`class/inhctor.rs:60-73`, `append_implicit_member`) and is also caught
  by its `inheriting_ctor` entry.

## `value` (property 2)

- The state read is the initialiser holder's (`decl_func::var_eval`), as
  `init` is read; with no holder or two, the declaration read.
- **At the pin `eval` is not demand-driven by a use.** It is written by
  `check_constexpr_init` (`kiln_sema/src/decl.rs:8870-8896`, called at
  `:8592`, `:9332`, `:9441`), `consteval_only.rs:526-527` and the module
  importer; the Oven only reads it (`kiln_oven/src/value.rs:89-98`). Every
  `value` pair shows the unit present on both sides or on neither. An
  in-class `static const int x = 1;` is never evaluated, used or not
  (`tests/resolved/value/in-class-static`); initialised out of line it is,
  at the declaration (`value/out-of-line-init`). That breaks
  `tests/equal/_/var-init-in-class-or-out-of-line`, now pending (§"Open
  questions" of digest-kinds).
- The temporaries are found by an index of every `LetData` by the first
  declaration of `extending`, built once per walk (`Walk::lets`), in
  `mangling_index` order. `LetData` `value` is written by `freeze_lets`
  (`kiln_oven/src/value.rs:579-604`) through
  `kiln_sema/src/oven_bridge.rs:72-76`.
- A temporary extended by a field (an initialiser in a class) is not in
  any `value` unit: §11.3 is about variables.

## `dtor_delete` (5) and `inherited_constructor` (6)

- `dtor_delete` is keyed by the destructor's first declaration and set by
  `check_destructor_delete` (`kiln_sema/src/new_delete.rs:2666-2721`)
  when Kiln defines a destructor outside a template
  (`kiln_sema/src/decl.rs:9836-9846`) or defines an implicit or defaulted
  one, on use (`class/special/define.rs:393-398`). A `dtor_delete_this`
  entry without `dtor_delete` is `Unaccounted("ColdDeclData/dtor_delete_this")`.
- `inheriting_ctor` and `inherited_ctor` are set together when Kiln
  declares the inheriting constructor (`class/inhctor.rs:78-79`), on its
  first use. One without the other writes a 0 with
  `Unaccounted("ColdDeclData/inherited_ctor")`.

## `default_argument` units (§11.4)

- **The mark is the expression, not the flag.** Kiln marks the parameter
  `DEFAULT_ARG_PENDING` when it defers the default
  (`templ/subst/decls.rs:1351-1420`) and sets `default_arg` when it
  instantiates it (`templ/default_args.rs:36-52`); the flag stays set
  (`kiln_ast/src/decl.rs:3141-3181`), and a failed instantiation resets
  the expression (`reset_failed_default_arg`, `:3152-3156`).
- The unit's expression is that of the first instantiated declaration of
  the chain (first declaration first) whose parameter i holds one.
- **Numbering:** parameter j of every declaration of the chain is local j,
  and later locals start at the parameter count. The function's own
  stream gives its parameters ordinals 0 to n-1 first
  (`decl_func::alias_params`), so both streams name a parameter alike
  (`tests/resolved/default_argument/earlier-parameter`: `sizeof(p)` is
  equal across uses; `demand::tests::default_argument_follows_parameter_type`
  shows it differs with p's type).
- A field's initialiser is instantiated by `act_on_field_init`
  (`templ/class.rs:2703-2783`, `class/mod.rs:620-668`), under every form
  of instantiation (`decl_class::instantiated_field`).
- **No unit for an inheriting constructor.** A call to one takes the base
  constructor's arguments and default arguments
  (`class/special/define.rs:1189-1192`, `:1239`); the base constructor's
  units hold them (`tests/resolved/default_argument/inheriting-constructor`).

## `default_immediates` (property 7)

- `default_imm` is set for an immediate invocation of a default argument
  or initialiser evaluated without impure effects
  (`kiln_sema/src/consteval.rs:827`, `:1093`), keyed by the `ConstantExpr`
  node `default_invocations` finds (`consteval.rs:596-628`).
- The values are gathered by the expression walk itself: `cold()` adds an
  `Item::Exec` for a node with an entry, which writes nothing and pushes
  the value when `ExprState::imms` is set. For a default argument written
  in source the expression is walked a second time into a dropped stream;
  for an instantiated one, while its `default_argument` unit is written.
- Entries inside a type (a `decltype` operand) are not listed: type
  digests take the expression state aside.

## Left for other packages

- Local classes (WP-040): a member of a local class can be of the
  deferrable class, or hold a `default_imm` value or an instantiated
  default argument; its own stream then omits the specification and no
  resolved unit holds it, because a local class is not a unit.
- A block-scope function declaration's default arguments are written in
  place (`local::block_defaults`); their `default_imm` values are in no
  unit.
