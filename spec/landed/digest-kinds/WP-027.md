# WP-027 — the payload records of classes, enumerations and typedefs

What `crates/slip_digest/src/decl_class.rs` reads into §5.5 (with digest
§5 and §2.3) where the tables are silent.

## Member lists

- `members-fields`, `members-virtual` and `members-other` hold exactly
  the members that are declared units (`units::unit_class` is
  `Declared`), whose semantic context is the class, each entity once (its
  first lexical declaration in the class). A `Friend` declaration is a
  member and is listed in `members-other`, as digest §5 asks; the entity
  it names, when declared in another scope (`friend struct H;`), is not.
  An implicit member and a derived unit are in no list. So the lists agree with the units, and a use that makes Kiln
  declare an implicit member changes no declared unit
  (`tests/demand/_/implicit-members-of-a-class`).
- A local class (§2.4) lists, written in place, the members that would be
  declared units were it not local: not an implicit member (one whose
  every declaration is `IMPLICIT`), not a closure type (§10.4), and a
  using-shadow or indirect field only as `units::unit_class` reads them.
- A field or an indirect field is in `members-fields`; a member function
  that is virtual on any of its declarations (`FnSpec` `0-virtual`, an
  overrider included) in `members-virtual`; everything else in
  `members-other`, sorted by encoded bytes. The bytes of a local member
  depend on its local ordinal (digest §4.3); see "Open points".
- **A member that is invalid (`0-invalid` on any declaration) makes its
  class indeterminate with `Error`.** The class's digest holds the
  member's key; a key read from an invalid declaration is not what
  digest §10 lets a unit depend on.
- More than 2^24 lexical members: `Unaccounted("members/limit")`.

## Bases

- `access` is the effective access: a base written without an access
  specifier is written as `private` for a class whose key is `class`,
  `public` otherwise ([class.access.base]/2), so `struct S : B` and
  `class S : public B` are equal (`tests/equal/TagKind/Class`).

## DefinitionBits

- One flag word of 61 bits, the `in` rows in table order (bit 0 is
  `0-complete`); `0-being-defined` and `0-complete-definition-required`
  are not written. Any other set bit is `Unaccounted("DefinitionBits/0")`.

## The definition class (§11.9) and §11.4

- The kind that governs a class or enumeration is its own `SpecInfo` or
  `MemberSpecInfo` kind, or, when it has neither, that of the class it is
  a member of, reached through classes only. The walk stops at a
  function: a local class or enumeration (anything declared in a function
  body, even of an instantiated function) has no governing kind and is
  written in full, default member initialisers included. A local class is
  not a unit, so no `definition` unit would ever hold its facts.
- A class or enumeration governed by `ImplicitInstantiation` is of the
  definition class. Its record writes the empty forms of §11.9 (for a
  class: three empty member lists, no base, a `DefinitionBits` word of
  0; for an enumeration: no enumerator, no `int_type`, no
  `promotion_type`, `flags-fixed` and `flags-complete` clear) and is
  indeterminate with `Pending(Demand)` without a placeholder byte: the
  resolved `definition` unit is the demand area's.
- **`FieldData` `init` is absent, with `Pending(Demand)`, for every field
  instantiated from a pattern**: a field of a class governed by
  `ImplicitInstantiation`, `ExplicitInstantiationDeclaration` or
  `ExplicitInstantiationDefinition`. Kiln instantiates a default member
  initialiser lazily, on use, whatever the kind of instantiation, so
  writing what it holds would make a use change the field's unit
  (`tests/demand/_/field-init-*`). It is present for a field written in
  source: a primary template, a partial or explicit specialisation, a
  class that is not a template, a local class.

## Mutations caught only by a unit test

- 18 single-bit drops of `DefinitionBits`, and the swap of
  `TRIVIAL_COPY_ASSIGN`/`TRIVIAL_MOVE_ASSIGN`, are caught by
  `definition_bit_pairs_flip_their_bit` alone: in their pair tests other
  bits move together with the row's.
- `BaseSpec` `access`, `is_virtual` and `pack_expansion` are caught by
  `base_spec_rows_in_and_out`; `EnumData` `flags-complete` and
  `TypedefData` `underlying` by `pair_tests_show_their_row_in_the_record`;
  `TypedefData` `templ` and `EnumData` `templ` by
  `templ_ends_the_typedef_and_enum_records` (their pair tests show
  `RecordData` `templ` of the enclosing specialisation).
- `LAMBDA` and `LAMBDA_CAPTURES` wait for the `local` area.

## Open points for the `local` package

- `members-other` of a local class is sorted by bytes that include
  first-met local ordinals (digest §4.3), so swapping two non-virtual
  members that declare parameters may read as a difference.

## Smaller choices

- `FieldData` `flags-init-style` is bits 2-3 of `flags`, masked by hand
  (Kiln names no constant); `FieldData::init_style` gives the tag.
- `CtorInit`: `kind`, then `init`, then the kind's `target` (a type
  digest for `Base`/`VirtualBase`, a `ref` for `Field`/`IndirectField`,
  nothing for `Delegating`). A target that names no type or no
  declaration of the right kind, or a delegating initialiser with a
  target, is `Unaccounted("CtorInit/<row>")` with a fixed filler.
- Missing payloads are `Unaccounted("<Record>/missing")`; unknown flag
  bits `Unaccounted("EnumData/flags")`, `Unaccounted("FieldData/flags")`;
  an enumeration member that is not an enumerator
  `Unaccounted("EnumData/members")`.

## Rows left untested

- `DefinitionBits` `0-pod`, `0-trivially-relocatable`,
  `0-has-inherited-assign`: no setter in `kiln_sema`.
- `FieldData` `flags-no-unique-address`: reachable only through
  reflection (`define_aggregate` with `.no_unique_address = true`,
  `kiln_sema/src/meta/define.rs:614`); the pair runner has no
  `-freflection`. The source attribute goes to the attributes, not here.
