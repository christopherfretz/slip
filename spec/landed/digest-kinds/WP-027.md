# WP-027 — the payload records of classes, enumerations and typedefs

What `crates/slip_digest/src/decl_class.rs` reads into §5.5 (with digest
§5 and §2.3) where the tables are silent.

## Member lists

- `members-fields`, `members-virtual` and `members-other` hold exactly
  the members that are declared units (`units::unit_class` is
  `Declared`), whose semantic context is the class, each entity once (its
  first lexical declaration in the class). A friend, a declaration the
  class holds lexically but that belongs to another scope
  (`friend struct H;`), an implicit member and a derived unit are in no
  list. So the lists agree with the units, and a use that makes Kiln
  declare an implicit member changes no declared unit
  (`tests/demand/_/implicit-members-of-a-class`).
- A local class (§2.4) lists, written in place, the members that would be
  declared units were it not local: not an implicit member (one whose
  every declaration is `IMPLICIT`), not a closure type (§10.4), and a
  using-shadow or indirect field only as `units::unit_class` reads them.
- A field or an indirect field is in `members-fields`; a member function
  that is virtual on any of its declarations (`FnSpec` `0-virtual`, an
  overrider included) in `members-virtual`; everything else in
  `members-other`, sorted by encoded bytes. The bytes of a local member
  depend on its local ordinal (digest §4.3), so the order of
  `members-other` in a local class follows first-met order.
- **A member that is invalid (`0-invalid` on any declaration) makes its
  class indeterminate with `Error`.** The class's digest holds the
  member's key; a key read from an invalid declaration is not what
  digest §10 lets a unit depend on.
- More than 2^24 lexical members: `Unaccounted("members/limit")`.

## Bases

- `access` is the effective access: a base written without an access
  specifier is written as `private` for a class whose key is `class`,
  `public` otherwise ([class.access.base]/2), so `struct S : B` and
  `class S : public B` are equal (`tests/equal/TagKind/Class`).

## DefinitionBits

- One flag word of 61 bits, the `in` rows in table order (bit 0 is
  `0-complete`); `0-being-defined` and `0-complete-definition-required`
  are not written. Any other set bit is `Unaccounted("DefinitionBits/0")`.

## The definition class (§11.9) and §11.4

- A class or enumeration whose own `SpecInfo`/`MemberSpecInfo` kind is
  `ImplicitInstantiation`, or that has neither and lies in an implicit
  instantiation (`units::in_implicit_instantiation`), is of the
  definition class. Its record writes the empty forms of §11.9 (for a
  class: three empty member lists, no base, a `DefinitionBits` word of
  0; for an enumeration: no enumerator, no `int_type`, no
  `promotion_type`, `flags-fixed` and `flags-complete` clear) and is
  indeterminate with `Pending(Demand)` without a placeholder byte: the
  resolved `definition` unit is the demand area's.
- `FieldData` `init` is written absent for a field of an implicit
  instantiation, by the same test, whatever Kiln holds.

## Smaller choices

- `FieldData` `flags-init-style` is bits 2-3 of `flags`, masked by hand
  (Kiln names no constant); `FieldData::init_style` gives the tag.
- `CtorInit`: `kind`, then `init`, then the kind's `target` (a type
  digest for `Base`/`VirtualBase`, a `ref` for `Field`/`IndirectField`,
  nothing for `Delegating`). A target that names no type or no
  declaration of the right kind, or a delegating initialiser with a
  target, is `Unaccounted("CtorInit/<row>")` with a fixed filler.
- Missing payloads are `Unaccounted("<Record>/missing")`; unknown flag
  bits `Unaccounted("EnumData/flags")`, `Unaccounted("FieldData/flags")`;
  an enumeration member that is not an enumerator
  `Unaccounted("EnumData/members")`.
