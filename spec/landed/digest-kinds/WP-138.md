# WP-138 — a fold's operator: `oper_lookups` in place of `spelling/fold-operator`

What `docs/wp/WP-138.md` changed in `crates/slip_digest` and
`spec/digest-kinds.md`. Since Kiln WP-2625 (`kiln` pin `4a83f6e3c`,
WP-066), `Sema::act_fold` (`kiln/crates/kiln_sema/src/templ/actions.rs:2110`)
calls `Sema::note_dependent_oper(e, binary_oper(op))`, recording the
fold's definition-context non-member operator lookup set in
`TemplateTables::oper_lookups` (`kiln/spec/ast.md` §8.5), matching a
dependent binary operator (`Sema::act_on_binary`,
`kiln/crates/kiln_sema/src/expr.rs:4140`) with one conservative
exception noted under Item 1 below. At instantiation,
`Substituter::fold` (`kiln/crates/kiln_sema/src/templ/pack.rs:673-787`)
combines each pair of elements — and any partially-substituted fold
rebuilt still as a fold — through `fold_combine`, setting
`oper_override = oper_rebuild_set(e)` so `oper_set` uses that recorded
set plus argument-dependent lookup and never performs a fresh unqualified
lookup.

WP-066 left `expr_dep::cxx_fold_expr` and `expr_profile::node` failing
closed with `Unaccounted("spelling/fold-operator")` via
`expr_profile::fold_left_out`. WP-138 removes that indeterminate and the
`fold_left_out` / `Walk::declared_operators` workaround, relying on
`oper_lookups` uniformly across the full walk, profile mode, and
`own_spelling`.

## Item 1 — Per-form Kiln record and digest encoding

| Fold form | Kiln `oper_lookups.of(e)` (`act_fold` → `note_dependent_oper`) | Digest (full walk via `templ::expr_maps`) | Digest (profile mode + `own_spelling`) |
|---|---|---|---|
| Unary left `(... op t)` | `Some(cands)` for every operator with non-member candidates (`has_nonmember_candidates(oo)`), lookup order; deduplicated by first decl | `opt(true)` + `write_refs_sorted` (by entity) | `oper_left_out` raises `left_out`; `own_spelling` pushes `Fact::Oper(ds)` (written sorted when due) |
| Unary right `(t op ...)` | Same (`act_fold(Some(e), op, None, ...)`) | Same | Same |
| Binary left `(init op ... op t)` / right `(t op ... op init)` | Same (`act_fold(Some(lhs), op, Some(rhs), ...)`); a partially-substituted fold rebuilt still as a fold inherits the pattern's `OperSetId` (`pack.rs:698,723,752,779`) | Same | Same |
| Overloadable operator with no candidate in definition context | `Some(&[])` (empty slice interned and stored, distinct from `None`; at instantiation ADL + member + built-in only) | `opt(true)` + count `0` | `oper_left_out` raises `left_out` (marks canonical type for rule 5); `own_spelling` pushes `Fact::Oper([])` (`due == false`) |
| `,`, `&&`, `||` (built-in evaluation rules / empty-pack identities) | `Some(cands)` (all three map to `OO::Comma`, `OO::AmpAmp`, `OO::PipePipe` with `has_nonmember_candidates == true`); empty unary pack expands to `void()` / `true` / `false` (`pack.rs:730-740`) without calling any operator; non-empty combinations use `oper_lookups` + ADL before built-in fallback | Same (`opt(true)` + `write_refs_sorted`) | Same (`oper_left_out` + `Fact::Oper`) |
| Comparisons `==`, `!=`, `<`, `>`, `<=`, `>=` | `note_dependent_oper` (`oper.rs:299-307`) loops over `[Some(op), rewritten_of(op)]`: `!=` records `operator!=` and `operator==`; `<`, `>`, `<=`, `>=` record the relational operator and `operator<=>`; `==` records `operator==` | Same (`opt(true)` + `write_refs_sorted`) | Same (`oper_left_out` + `Fact::Oper`) |
| Compound assignment (`+=`, etc.) and `->*` (`BinaryOp::PtrMemI`) | `Some(cands)` (`has_nonmember_candidates` is `true` for compound assignments and `OO::ArrowStar`) | Same (`opt(true)` + `write_refs_sorted`) | Same (`oper_left_out` + `Fact::Oper`) |
| Member-only `=` (`BinaryOp::Assign`) | `None` (`has_nonmember_candidates(OO::Equal) == false`; `[over.ass]/1`, `[over.match.oper]/3.2`: assignment has only member candidates, held via the operand class types) | `opt(false)` | `oper_left_out` does not raise; `own_spelling` pushes nothing |
| Non-overloadable `.*` (`BinaryOp::PtrMemD`) | `None` (`binary_oper(PtrMemD) == None`; `[over.oper.general]/3`) | `opt(false)` | `oper_left_out` does not raise; `own_spelling` pushes nothing |

Kiln's record matches dependent `BinaryOperator` on every fold form with
one exception: `Sema::act_fold` records a set even when no operand is
type-dependent (for example, a value-dependent pack over `int`, such as
`template<int... N> auto f() { return (N + ...); }`), whereas
`Sema::act_on_binary` records a set only when an operand is
type-dependent. That extra set can only add differences (conservative;
never causes a false equal). No form remains indeterminate and there are
no "For Kiln" items. Pinned by `expr_dep::tests::fold_oper_lookups_by_form`
(14 forms, including `+=` and `->*`) and the pair tests below.

## Item 2 — Instantiated folds

An instantiated fold expands to nested binary expressions (`BinaryOperator`
or `CXXOperatorCallExpr` / `CXXRewrittenBinaryOperator`), each walked by
the existing expression rows.

- An overload declared before the template moves the template pattern
  (its `oper_lookups` set changes) and any instantiation whose resolution
  switches to it (`differ/_/fold-operator-before-template-instantiated`).
- An overload declared after the template in an operand's associated
  namespace is found by ADL at that operand's instantiation, moving that
  instantiation while leaving the template pattern and unrelated
  instantiations unchanged (`differ/_/fold-operator-adl-instantiation`).
- A fold rebuilt still as a fold by partial substitution keeps its
  pattern's definition-point set (`fold_combine` / `oper_override` in
  Kiln): an overload declared after `S`'s definition and before `S<N::X>`
  is not picked up by `S<N::X>::f` (`differ/_/fold-operator-rebuilt-substitution`,
  `exact derived`).

## Item 3 — Removal of `fold_left_out` and `own_spelling` check

- `expr_profile::fold_left_out` and `Walk::declared_operators` had no
  other readers and are removed.
- `own_spelling::node` (`crates/slip_digest/src/own_spelling.rs:1321-1325`)
  already inspects `ast.templates.oper_lookups.of(e)` before dispatching
  on `ExprKind`, so `CXXFoldExpr` already receives the exact same
  `Fact::Oper` treatment as dependent unary, binary, and
  compound-assignment operators. Folds need this treatment for the same
  reason: Kiln's expression profiler (`kiln_ast/src/types/profile_expr.rs:581-584`)
  does not include `oper_lookups` in a `CXXFoldExpr`'s profile, so two
  declarations with identical fold syntax before and after an operator
  declaration share one `ProfileId` and must record their own spelling's
  `oper_lookups` in their unit list (`differ/_/spelling-fold-operator-trailing`,
  `differ/_/spelling-fold-operator-unary`, `differ/_/spelling-fold-operator-comparison`,
  `own_spelling::tests::the_order_of_two_spellings_changes_no_digest` `"fold"` shape).
- `expr_profile::node` keeps `oper_left_out(w, e)` for `CXXFoldExpr` so a
  unit holding a canonical fold type with no spelling of its own stays
  fail-closed under rule 5 (`indeterminate/_/spelling-fold-operator-enum-underlying`,
  `spelling/decltype`).

## Item 4 — `scheme` does not move

`scheme` stays `3` (`spec/digest.md` §11). No previously-determinate
unit changes its digest, key, or flags (confirmed by byte-identical dumps):

1. **Full walk**: `templ::expr_maps` already ran at the end of every
   `CXXFoldExpr` node since WP-066 (when Kiln WP-2625 entered the pin)
   and already wrote `oper_lookups.of(e)` (`opt(true)` + count `0` for a
   fold with no non-member operator declared; `opt(false)` for `.*` and
   `=`). Removing `if fold_left_out(w, op) { s.indeterminate(...); }`
   from `expr_dep::cxx_fold_expr` leaves every previously-determinate
   unit's bytes bit-for-bit identical; only units where `fold_left_out`
   returned `true` (previously indeterminate under `spelling/fold-operator`)
   change state (from indeterminate to determinate).
2. **Profile mode and `own_spelling`**: `expr_profile::node` already
   called `oper_left_out(w, e)` for `K::CXXFoldExpr`, and
   `own_spelling::node` already collected `Fact::Oper` from
   `oper_lookups.of(e)` (with empty `Fact::Oper([])` having `due == false`,
   writing no unit list when no other fact is due). Removing the
   `fold_left_out` check in `expr_profile::node` leaves every
   previously-determinate unit's profile bytes, marks, and unit list
   bit-for-bit identical.
3. **`alias_due`'s cause branch (`own_spelling.rs:338`)**: `alias_due`
   computes `let mine = w.unit.facts_due || scratch.cause().is_some();`.
   In `own_spelling::ty`, the only sites that call `expr_dep::profile_expr`
   and absorb its cause into `scratch` are `written_expr` (rule 7, line
   763) and `profiled_expr` (rule 12, line 740); both immediately push
   `Fact::Profile(...)`, whose `due()` is unconditionally `true`
   (`own_spelling.rs:90`), so `w.unit.facts_due` was already `true`
   before and after WP-138 even where `scratch.cause()` previously
   carried `spelling/fold-operator`. The only other `own_spelling` paths
   that invoke `expr_profile` (`no_spelling` / `marked` at line 139 and
   `full` at line 1585) inspect only `w.left_out`, which is unchanged
   because `oper_left_out(w, e)` already ran for every `CXXFoldExpr` with
   `oper_lookups.of(e).is_some()` and `fold_left_out` was already `false`
   for `.*` and for `=` (`[over.ass]/1` forbids non-member `operator=`).
   No other path in `own_spelling` called `fold_left_out` or
   `expr_profile`, so `alias_due` returns the exact same boolean for
   every typedef/alias and moves no existing determinate digest.
