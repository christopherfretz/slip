# WP-100 — a parameter's attributes over the function's chain

What `crates/slip_digest` (`attrs.rs` `decl_attrs`, `param_attrs`,
`entity_attrs`, `defining`, `own_attrs`; `decl_func.rs` `param_decls`;
`local.rs` `block_defaults`) decides for `spec/digest-kinds.md` §10.1,
§10.5, §5.4 `ParamData` and §2.4, and the evidence from Kiln's source. It
closes finding S1 of `spec/landed/digest-kinds/WP-042.md`. The first
round wrote one flat list over the chain; the review found that it makes
wrong equals (below, "Why not one list"), and the fix round replaced it.

## The chain and the lists

- The chain of an entity is `Walk::redecls`, first declaration first:
  Kiln's `redecls_of` (for a template, the templates its pattern's
  declarations describe, `Walk::chain`), without the declarations in a
  templated body and, unless all are, those instantiated outside their
  class (`spec/digest.md` §2.2).
- A parameter has no redeclarations: parameter *i* of another
  declaration of its function is another declaration with no link to it.
  A parameter's lists are those of parameter *i* (its `ParamData`
  `index`) of each declaration `decl_func::param_decls` gives: the
  function's chain without the block-scope declarations. Every
  declaration of a C++ function has the same number of parameters, so
  each has a parameter *i* (the code skips one that has none; C++ cannot
  reach it).
- A declaration's own list: its `decl_attrs` nodes in stored order,
  `inherited` copies left out.
- The defining declaration (`attrs::defining`): `Ast::definition` (for a
  template, the template its pattern's definition describes) if the
  chain holds it and the entity is not of the definition class (§11.9).
  A definition instantiated outside its class (a friend's) is the class
  specialisation's (WP-032); the first attempt marked it
  `Unaccounted`, which `demand/_/friend-definition-instantiated-on-use`
  rejected.

## The encodings

| Declaration | `attrs` | annotations |
|---|---|---|
| parameter of a function | `opt` + the definition's parameter *i* own list; count of the other non-empty lists, each, in chain order | one list over the parameters *i*, chain order |
| any other | count of the non-empty lists before the definition (all, without one), each; `opt` + the definition's own list; the lists after it as before | one list over the chain |
| parameter of a block-scope declaration (`own_attrs`) | its own list, one `attrs` list | its own |
| statement | its list | - |

The parameter rule is the coordinator's decision 1. The rule for any
other declaration departs from decision 2 (only `annotate` grouped, the
other nodes one list): see "Disagreements".

## Why not one list

What Kiln reads, cited at Kiln 913a490bb:

- The function prolog reads `nonnull` and `align_value` on the defined
  declaration's own parameter (kiln_codegen `class_b.rs:715`, `:718`)
  and the parameter's `annotate` on the definition's own
  (`emit_var_annotations`, `annotate.rs:327`, `ann_own`). So
  `void f(int *p [[clang::annotate("a")]]); void f(int *p
  [[clang::annotate("a")]]) {}` emits one `llvm.var.annotation` and
  `void f(int *p); void f(int *p [[clang::annotate("a")]]
  [[clang::annotate("a")]]) {}` two (clang 19 agrees); one list made
  them equal. `noescape` and the sanitiser's `nonnull` read every
  declaration (`redecl_params`, `class_b.rs:591`; `ubsan.rs:2150`), so a
  move between two declarations that are not the definition is equal.
- A function's `annotate`: `ann_attrs` (`annotate.rs:124`) walks the
  chain from the first declaration to the emitted one, inheriting by
  string, so once on each of two declarations is one annotation and twice
  on one is two. Kiln keeps no `annotate` node on a declaration after
  the definition, as clang 19 drops it ("attribute declaration must
  precede definition"), so `fn-attr-annotate-after-definition` differs
  under any rule; the split at the definition is for the readers that
  stop at the emitted declaration (`ann_attrs`, `target_version`), and
  is pinned by unit tests only.
- `fn_attr` (`new_delete.rs:169`) returns the first node of a kind on the
  latest declaration that has one. `patchable_function_entry(1)` and
  `(2)` on one declaration read `1`; split over two declarations, `2`.
  Clang 19 agrees (`"patchable-function-entry"="1"` against `"2"`). This
  is why every kind is kept per declaration, not `annotate` alone.
- `target_version` is read up to the emitted declaration
  (`target_version_so_far`, `module.rs:2122`).
- Readers that see the chain as a set or a sorted list (`has_fn_attr`,
  `module.rs:2132`; `fn_attrs_of`, `class_b.rs:321`) and `enable_if`,
  equal on every declaration (kiln_sema `enable_if.rs:75`), lose nothing
  either way; for them a move between declarations is now a reported
  difference that changes nothing (accepted: it errs towards a
  difference).
- C++26 annotations stay one list, for parameters too: reflection's
  `annotations_of` reads them flat over `redecls_of`, first first, for an
  entity and for parameter *i* alike (kiln_sema `meta/annot.rs:147`), and
  nothing else reads them. Grouping them would only add false
  differences.

No definition: a program in which the function has one differs from one
in which it has none in `DeclMisc` `0-definition`. A function of the
definition class is written as without one so its unit does not depend
on a use; a definition instantiated outside its class likewise
(hazard "A definition the chain leaves out").

## Block-scope declarations

- A block-scope declaration's parameter attributes are not the entity's,
  as its default arguments are not ([dcl.fct.default]/4; WP-026). Kiln
  attaches a parameter's attributes to that declaration's own parameter
  (kiln_sema decl.rs:6684). `local::write_decl` writes for a block-scope
  function its `ref`, a count, and per parameter its default (`child?`),
  then `attrs::own_attrs`: one `attrs` list of the parameter's own nodes
  and its annotation list (§2.4). Kiln rejects an annotation on such a
  parameter (kiln_sema annot.rs:200).
- Kiln's code generation does read them: hazard "Parameter attributes of
  block-scope declarations" (§10.1 hazards), and "For Kiln" 4.
- With statements merged (WP-034) bodies are walked: the pair test
  `differ/_/param-attr-block-scope` runs (`changed g()`, not `f`) and is
  seen to fail with `own_attrs` writing nothing; unit tests
  `attrs::tests::s10_1_param_chain_leaves_out_block_scope` and
  `local::tests::a_block_scope_parameter_writes_its_attributes`.

## What else is a parameter's alone (decision 3)

From `kiln_sema` `create_params` (decl.rs:6601-6700) and the function
redeclaration checks (decl.rs:6176-6203):

| Fact | Kiln | Verdict |
|---|---|---|
| attributes (`AttrArena` `of_decl`) | attached to the declaration's own parameter (decl.rs:6684); the only `inherited` copy is the function's asm label | the rule above |
| annotations (`AnnotArena` `of_decl`) | the declaration's own parameter (decl.rs:6673, annot.rs:138-165) | the rule above |
| `default_arg` | merged forward (decl.rs:6785) | read over the chain (WP-026) |
| `original_ty` | per declaration (decl.rs:6641); compared only for `-Warray-parameter` (vla.rs:137) | the declaration read's: instantiation, mangling a dependent bound and C's `static` (kiln_codegen class_b.rs:737) read the definition's |
| `flags-static-array` | per declaration (decl.rs:6643); codegen reads the defined declaration's (class_b.rs:734-750) | the declaration read's; C only |
| `flags-explicit-object` | the declarator's (decl.rs:6628); part of the function type | needs nothing |
| `flags-pack` | the parameter's type (decl.rs:6626); part of the function type | needs nothing |
| `flags-scope-depth` | the same for every declaration at one scope | needs nothing |
| `DeclNode` `ty` | per declaration (decl.rs:6635): top-level cv may differ | the declaration read's: they matter only in the definition ([dcl.fct]/5) |
| nullability on the parameter type | per declaration; checked against earlier ones (nullability.rs:435) | `out` (sugar) |
| the parameter's name | per declaration | spelling, out |
| `DeclFlags` `used`/`referenced` | where it is used | `demand` |

A parameter has no `VarData`; Kiln has no K&R mark on a parameter.

## Templates (decision 4)

- A function template's parameters' lists are those of the patterns of
  the template's declarations (`Walk::chain`), and its defining
  declaration is its pattern's definition, which does not depend on use.
  Test `differ/_/param-attr-template-first-declaration`.
- Kiln gives an instantiated function's parameters only their Swift ABI
  attributes (`param_infos`, kiln_sema templ/subst/decls.rs:513-626,
  :532). An explicit instantiation's unit therefore does not change in
  `differ/_/param-attr-template-{first-declaration,definition}`; clang
  19 instantiates the attribute. Tripwire unit test
  `attrs::tests::kiln_does_not_instantiate_parameter_attributes`.

## Disagreements with the fix round's decisions

- **Decision 2, "the function-level attribute list stays".** It is not
  sound: `fn-attr-same-kind-split-or-together` (above) is a false equal
  under it, against both Kiln and clang 19. Every kind is grouped per declaration, split at the
  defining declaration.
- **Decision 1, "the same shape for the annotation lists".** Kept as one
  list: Kiln's only reader reads them flat (above). Grouping is finer and
  would not be unsound; it would only add false differences.

## For Kiln

None is sent yet.

1. **Parameter attributes are not instantiated.** `template<class T>
   void f(T *p __attribute__((nonnull))) {} template void f<int>(int *);`:
   the instantiation's parameter has no `nonnull` node (kiln_sema
   templ/subst/decls.rs:513-626, only `param_abi_attrs`, :532); clang 19
   emits `ptr noundef nonnull`.
2. **The prolog reads the definition's own parameter only**, for
   `nonnull` (kiln_codegen class_b.rs:715), `align_value` (:718) and the
   parameter's `annotate` (annotate.rs:327, `ann_own`). `void f(int *p
   __attribute__((nonnull))); void f(int *p) { *p = 1; }`: Kiln's
   definition gets no `nonnull`; clang 19 emits `define void
   @_Z1fPi(ptr noundef nonnull)` (`mergeParamDeclAttributes`). Read from
   source, not run.
3. **`noescape` that differs between declarations is accepted**, where
   clang 19 rejects it ("conflicting types"); and **a nested
   declarator's parameter attributes are kept nowhere**: `void f(void
   (*cb)(int *q __attribute__((noescape)))) {}` digests as without it,
   clang 19 mangles `_Z1fPFvU8noescapePiE`
   (`differ/_/param-attr-nested-declarator`, `# needs: kiln`).
4. **Code generation reads block-scope redeclarations' parameter
   attributes**: `redecl_params` (kiln_codegen class_b.rs:591) and the
   sanitiser's `nonnull` (ubsan.rs:2150) walk `redecls_of`, which holds
   block-scope declarations, so `void g() { void f(int *p
   __attribute__((noescape))); }` changes the calls to `f` after it,
   while [dcl.fct.default]/4 keeps such a declaration's defaults its
   own. Whether clang 19 does the same is not checked.
