# WP-100 — a parameter's attributes over the function's chain

What `crates/slip_digest` (`attrs.rs` `decl_attrs`, `param_chain`,
`own_attrs`; `decl_func.rs` `param_decls`; `local.rs` `block_defaults`)
decides for `spec/digest-kinds.md` §10.1, §10.5, §5.4 `ParamData` and
§2.4, and the evidence from Kiln's source. It closes finding S1 of
`spec/landed/digest-kinds/WP-042.md`.

## The chain of a parameter

- A parameter has no redeclarations: parameter *i* of another
  declaration of its function is another declaration with no link to it.
  The chain of parameter *i* of a function is parameter *i* of each
  declaration `decl_func::param_decls` gives for the function: its
  chain (`Walk::redecls`), the first declaration first, block-scope
  declarations left out. *i* is the parameter's `ParamData` `index`.
  Attributes (`AttrArena` `decl_attrs`) and annotations (`AnnotArena`
  `of_decl`) are read over it with the rule for any declaration: chain
  order, stored order within one declaration, `inherited` copies left
  out. The encoding of the list is unchanged (one count, then the
  nodes; then one annotation list).
- `param_decls` is also what `ParamData` `default_arg` reads
  (`decl_func::merged_default`). Default arguments then leave out the
  instantiated declarations as well, because a default of an
  instantiated declaration is the `default_argument` derived unit's
  (§11.4, `spec/landed/digest-kinds/WP-026.md`). Attributes keep them:
  an instantiated declaration's attributes are written as found (§10.1).
- A declaration with no parameter *i* contributes nothing for *i*. In
  C++ every declaration of a function has the same number of parameters,
  so this is reached only by a C declaration without a prototype, which
  the pair tests (C++ only) do not exercise.
- A parameter whose position in its function's list is not its `index`
  makes the unit `Unaccounted("ParamData/index")`; its own attributes
  are then written alone. A parameter of a declaration that is not at
  block scope and is not in `param_decls` (no test reaches one: the
  declaration read is always in its chain) makes the unit
  `Unaccounted("ParamData/chain")`.
- The order is the first declaration first, wherever the declaration
  read is: the definition's parameter and the first declaration's give
  the same list (unit test `attrs::tests::s10_1_param_chain_order`).

## Block-scope declarations

- A block-scope declaration's parameter attributes are not the entity's,
  as its default arguments are not ([dcl.fct.default]/4; WP-026). Kiln
  does not merge them either: it attaches a parameter's attributes to
  that declaration's parameter only (kiln_sema decl.rs:6684). They are
  written with the declaration in its block: `local::write_decl` writes
  for a block-scope function its `ref`, a count, and per parameter its
  default (`child?`), then `attrs::own_attrs`: the parameter's own
  attribute list and annotation list, in the encoding of `decl_attrs` for
  a chain of that parameter alone. This is an addition to §2.4, like
  WP-026's. Kiln rejects an annotation on such a parameter
  (kiln_sema annot.rs:200), so the annotation list is empty in a valid
  program.
- So the change is in the stream of the function whose body holds the
  block-scope declaration, not in the entity's unit. Function bodies are
  pending at this base (`Cause::Pending(Area::Stmt)`): the pair test
  `differ/_/param-attr-block-scope` is `# pending` / `# needs: stmt`. The
  claims run now as unit tests: `attrs::tests::
  s10_1_param_chain_leaves_out_block_scope` (the entity's parameter
  does not see it, before or after the namespace-scope declaration) and
  `local::tests::a_block_scope_parameter_writes_its_attributes`.

## What else is a parameter's alone (decision 3)

What Kiln keeps per parameter declaration, read from `kiln_sema`
`create_params` (decl.rs:6601-6700), which makes the parameters of
every declaration, and from the function redeclaration checks
(decl.rs:6176-6203):

| Fact | Kiln | Verdict |
|---|---|---|
| attributes (`AttrArena` `of_decl`) | attached to the declaration's own parameter (decl.rs:6684); nothing copies them forward: the only `inherited` copy is the function's asm label | the chain rule above |
| annotations (`AnnotArena` `of_decl`) | taken from the same list into the declaration's own parameter (decl.rs:6673, annot.rs:138-165) | the chain rule above |
| `default_arg` | merged forward (decl.rs:6785, `merge_default_args_in`) | already read over the chain (WP-026) |
| `original_ty` | per declaration (decl.rs:6641); compared only for `-Warray-parameter` (vla.rs:137) | the declaration read's: it is used for instantiation, for mangling a dependent bound and for C's `static` (kiln_codegen class_b.rs:737), all of which read the definition's own parameter; a bound written on another declaration changes nothing ([dcl.fct]/5) |
| `flags-static-array` | per declaration (decl.rs:6643); codegen reads the defined declaration's parameter (class_b.rs:734-750) | the declaration read's; C only. Clang also reads the definition's own (`EmitFunctionProlog`) |
| `flags-explicit-object` | from the declaration's own declarator (decl.rs:6628); part of the function type, so every declaration agrees | needs nothing |
| `flags-pack` | from the parameter's own type (decl.rs:6626); part of the function type | needs nothing |
| `flags-scope-depth` | the declarator's nesting, the same for every declaration of a function at one scope | needs nothing |
| `DeclNode` `ty` | per declaration (decl.rs:6635): the top-level cv-qualifiers may differ | the declaration read's: they matter only in the definition ([dcl.fct]/5), which is the declaration read when there is one |
| nullability on the parameter type | per declaration; Kiln only checks it against earlier ones (nullability.rs:435) and does not copy it as clang does | already `out` everywhere (`TypeAttrKind`, sugar) |
| the parameter's name | per declaration | spelling only, stays out |
| `DeclFlags` `used`/`referenced` | set where the parameter is used, the definition's | `demand`, unchanged |

A parameter has no `VarData` (`ParmVar.data` is `ParamData`), so no
`VarSpec` word is merged or not merged for it. Kiln has no K&R mark on a
parameter (`ParamData` has none; a K&R definition is a function without
a prototype, decl.rs:1957), and the `this`-parameter mark is
`flags-explicit-object` above.

## Templates (decision 4)

- A function template's pattern is written from its defining
  declaration (WP-026); its parameters' chain is the patterns of the
  template's declarations, since Kiln chains the pattern functions
  (`Walk::chain`). Test `differ/_/param-attr-template-first-declaration`:
  the template's unit changes.
- Kiln gives an instantiated function's parameters only their Swift ABI
  attributes: `param_infos` (kiln_sema templ/subst/decls.rs:513-626)
  carries `param_abi_attrs` (decls.rs:532) and nothing else, and the
  parameters it makes are adopted as they are (decls.rs:1205-1220). So
  an explicit instantiation's parameter has no `nonnull`, `noescape`,
  `annotate` or `[[indeterminate]]`, whether the pattern's first
  declaration or its definition has it. The unit is written as found:
  in `differ/_/param-attr-template-first-declaration` and
  `differ/_/param-attr-template-definition` the explicit instantiation's
  unit does not change. Clang 19 instantiates the attribute from either
  declaration (`define weak_odr void @_Z1fIiEvPT_(ptr noundef nonnull)`).
  This is a finding for Kiln; the unit test
  `attrs::tests::kiln_does_not_instantiate_parameter_attributes` fails
  when Kiln changes, and then the two tests expect the instantiation to
  change too.

## Goldens

No golden moved: the encoding of a parameter's list is unchanged, and no
golden source has a parameter attribute on a declaration other than the
one read, or a block-scope function declaration in a body that is
walked (bodies are pending).

## Tests

- `differ/_/param-attr-on-first-declaration` (`[[indeterminate]]`,
  C++26), `param-attr-indeterminate-friend`,
  `param-attr-indeterminate-member`. `[[indeterminate]]` on the second of
  three declarations without the first is ill-formed
  ([dcl.attr.indet]/2; kiln_sema decl_attrs.rs:1772), so that position
  has no test for it.
- `differ/_/param-attr-{nonnull,noescape,annotate}-{first-of-two,
  second-of-three,friend,member}`. The `noescape` ones are ill-formed for
  clang 19, which puts `noescape` in the function type and rejects the
  redeclaration ("conflicting types"); Kiln keeps it as a declaration
  attribute and accepts them.
- `differ/_/param-annotation-on-first-declaration` (`[[=1]]`, C++26),
  unit test `attrs::tests::s10_5_param_annotations_over_the_chain`.
- `equal/_/param-attr-moved-to-definition`: one node, on either
  declaration, is the same list. `equal/_/param-attr-chain-order`: a
  second node moved to the next declaration keeps its place in chain
  order, so the lists agree.
- `differ/_/param-attr-block-scope` (`# pending`, stmt) and the unit
  tests named above.
