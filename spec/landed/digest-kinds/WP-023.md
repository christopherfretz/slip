# WP-023 — the tables test, the generated tables and the pins

What `crates/slip_digest/tests/tables.rs` reads into the grammar of §1
where §1 is silent, and the files beside it.

## Grammar

- A table of kind `enum`, `view` or `consts` is a table of variants: its
  rows are `variant` or `variant.field` (§1.2). A decoded form whose rows
  are fields is `kind=struct` with `pin=none`, as `AddrSpace` and
  `ByteImage` are.
- `selector` is for a record and `base` for a table of variants; anything
  else is an error. With a selector, a row's text before the first `.` is
  the kind prefix; without one, a member may hold a `.` (`intern.absent`,
  a field name as `TypeContext`'s descriptor writes it).
- A row of a variant decided `in` is `tag N`; any other `in` row is a form
  of §1.3. `tag N` is only for a variant row. `as V` is only for an `out`
  variant row and names another variant row of the same table that is not
  itself `as`. `unbuilt` is only for an `unsupported` row.
- Suffixes apply innermost first: `enum ArgView*?` is an optional list.
  `bit` and `keyed` take none.
- Note is required for an `unsupported` row and for an `out` row whose
  class is not `location` or `bookkeeping`.
- `enum T` names a table of variants; `record T` names a table that is
  not of kind `enum` or `consts` (a view of variants may be a record:
  `record Scalar` writes the rows of the value's variant).
- A member with a row of its own and a fact row (under the same kind
  prefix, or none) is an error: a packed field has only fact rows.
- After a type's table and before the next heading, a line that starts
  with `|` is an error.
- The tables of §3.1, §3.2 and §11.1 number their rows from 1 in order,
  each name once; §11.1 alone may write `retired` in place of a name.

## Kiln's side

- The descriptors are those `Schema::hashes()` gives for `Ast`, and for
  a second `Schema` into which the test registers every `pin=extra` type.
  The registrations are generated from the file into
  `tests/tables/extra.rs` and kept current like `src/tables.rs`; a type
  newly decided `extra` therefore takes two blessings (the first writes
  the registration, the second the pins it makes visible).
- A tabled type is `pin=schema` when a descriptor of `Ast` has its path
  (any instantiation), `extra` when only the registrations reach it, else
  `none`. The `kind` must be the descriptor's (`consts` is a `struct`).
- Slip names a type by its descriptor path through `slip_kiln::kiln`,
  `alloc` and `core` as `std` (prelude types bare), and Kiln's re-exports
  of the private modules `types::{args, context, func, kinds, layout,
  names, nns, node}`, `consts::value` and `source::loc` one level up
  (`REEXPORTS` in `tests/tables/generate.rs`; a wrong entry does not
  compile). A pinned type that is not nameable so is listed by hand in
  `tests/tables/pins.txt` as `<SCHEMA_HASH> <type>`, sorted; it gets no
  compile-time assertion and no `row` function, and the test compares its
  hash. `SLIP_BLESS=1` rewrites the hashes and never adds a type.

## The generated file

- One module per table, named by the short name in snake case (`r#` for
  a keyword); a variant constant is the variant's name in screaming snake
  case, and a `consts` row keeps its name. `key_kind`, `name` and
  `property` hold §3.1, §3.2 and §11.1, a retired number as a comment.
- A `row` function only for a `kind=enum` table with a descriptor that is
  not generic and not in `pins.txt`. Views and `consts` tables have none
  (a match over constants would need `_`).
- A table that is not of variants gets `ROWS`, every row in table order.
- The header allows `dead_code`, `clippy::too_many_lines` (a `row` over
  `ExprKind`) and `clippy::trivially_copy_pass_by_ref` (the interface takes
  `&T`), once.

## Tests

`crates/slip_digest/tests/tables.rs`: the checks on the real file
(`grammar`, `against_kiln`, `generated_file_is_current`,
`extra_registrations_are_current`, `recorded_pins_are_current`,
`rows_against_tests`) and, in `unit`, each check on small tables, with
the generator's output for them as the golden
`tests/golden/tables_small.txt`.

## When the Kiln pin moves (added 2026-11-22, with the move to `slip/kf1`)

A compile-time pin that no longer holds stops `slip_digest` from
compiling, and with it the test that would bless it. The crate has a
feature for that one command, `unpinned`, under which the generated
`pin!` lines compile to nothing:

```
SLIP_BLESS=1 cargo test -p slip_digest --test tables --features unpinned
```

Before blessing, read the compile errors: they name the types whose
schema changed. Diff those types between the two Kiln revisions, add
or change the rows in `spec/digest-kinds.md` (a new row's name goes
into `tests/tables/untested.txt` by hand unless its test comes with
it), and only then bless and review the diff of `src/tables.rs`. The
test `unpinned_only_when_blessing` fails any other run under the
feature. Nothing enables the feature in a manifest.
