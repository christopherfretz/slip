# WP-035 — the construction and initialisation expression kinds

What `crates/slip_digest/src/expr_init.rs` reads into `spec/digest-kinds.md`
§7, §7.2 and §7.3 where they are silent, and the facts of Kiln each
decision rests on. Kiln sites are under `kiln/crates/kiln_sema/src/` unless
another crate is named. Where a fact could not be settled, the unit is
indeterminate.

## Shape of the functions

- Each kind function is `run(w, s, e, rows)`: `rows` checks the node's
  words and pushes the primitives of its rows, in table order, to a
  `Vec`; `emit` writes them, a child through `expr::child`. The unit tests
  call the same `rows` functions and render the primitives, so a row's
  test reads what is written, not a copy of it.
- A word the table does not account for (a bit, `aux`, or `a`/`b` of a
  kind with no rows) is `Unaccounted("ExprNode/<Kind>.<row>")`. A child or
  entity word of 0 writes `uv 0` or `ref none` and is `Unaccounted` too.

## How a row is shown to be written

A pair test shows that a real change of source changes the unit, but a
real change usually moves more than one row (a class's own `operator
delete` is both another `b` and another `aux-sized`). So each `in`
enumeration, flag and optional row also has a line in the unit test
`expr_init::tests::enumerations_flags_and_optionals`, which renders the
rows of the pair test's node on each side and checks the row's value on
each: skipping the row or writing a constant fails there even where the
pair test still sees another row change.

Where an edit could, the pair test itself isolates the row: only that row
changes between the sides, so a mutation of the row fails the pair test.
- `InitListExpr.a` run length: `{[0 ... 1] = 7, [2 ... 3] = 8}` against
  `{[0 ... 2] = 7, [3] = 8}` (`_/init-list-range-length`).
- `InitListExtra.array_filler`, `InitListExpr.b`,
  `CXXParenListInitExpr.b`: `E v[2] = {e0}` (or `(e0)`), the filler's
  constructor `E()` against `E(int = 0)`.
- `ConstructInfo.std_init_list`: `L v{1, 2}` against `L v{{1, 2}}`.
- `ConstructInfo.zeroing`: `Z() = default;` in the class against
  `Z::Z() = default;` out of it (user-provided: no zeroing).
- `CXXNewExpr.aux`: `new S()` against `new S` with `S` having a declared
  `S()`.
- `NewExtra.placement`: `new (buf) int` against `new (buf2) int`.
- `CXXNewExpr.bits-array-form`: in a template, `new int[]{T()}` against
  `new int{T()}` (a dependent array form has no `array_size` and no
  function resolved).
- `CXXPseudoDestructorExpr.aux-qualified`: in a template (above).
- `CXXRewrittenBinaryOperator.b`: `_/rewritten-ne-reversed-same-semantic-form`.

Where no edit can, the fact is implied by another row that is written:
- `CXXDefaultArgExpr.a`: the parameter is the position in the call's
  argument list of the callee already written; another parameter is
  another position, which moves the arguments before it.
- `CXXNewExpr.bits-pass-align`, `CXXDeleteExpr.aux-aligned`,
  `CXXDeleteExpr.aux-sized`, `CXXDeleteExpr.bits-array-form`: each is a
  fact of the chosen function's signature, written as its `ref`
  (`operator new[]` against `operator new`, an `align_val_t` or `size_t`
  parameter); in a dependent pattern, where no function is chosen, Kiln
  sets none of them and the as-written flag and `array_size` carry the form.
- `NewExtra.allocated_ty`: the node's type is a pointer to it.
- `CXXRewrittenBinaryOperator.aux`: the shape of `a` (`!` around a call,
  `call @ 0`, `0 @ call`, or the call alone) with the callee implies the
  operator written.
- `CompoundLiteralExpr.aux`: its only effect is a cause (`Unsupported`);
  the indeterminate runner does not check the cause's name, and the unit
  test `check_a` does.
- `CXXDefaultInitExpr.a`: the field is implied by the initialiser's
  position in the aggregate's list, by `union_field`, or by the
  `CtorInit` of the constructor; writing `ref none` changes no unit,
  since no source makes the same position a different field.
- `ArrayInitLoopExpr.a`: equivalent, by the opaque-value rule: `b` reaches
  the same `OpaqueValueExpr`, whose source is written on first reach, so
  skipping `a` moves the same bytes later and no unit changes.

## Shared nodes (head of §7)

- `CXXDefaultArgExpr` writes `a`, the parameter, as its position
  (`ParamData.index`), and not the default argument: the argument is the
  function's, written with it. Its function is the callee of the enclosing
  call, already written there. `b` (the context of the use) is `out`.
- The default a call uses is the one of the declaration found at the call
  (expr.rs:6189), which may be a block-scope redeclaration
  (`void g() { void f(int = 2); f(); }`). That declaration is written by
  `local::write_decl` with its default: the unit test
  `block_scope_redeclaration_writes_its_default` calls it on both sides
  and sees the bytes differ with no cause. The pair
  `tests/differ/_/default-arg-block-scope-redeclaration` is pending
  `stmt` (the body is not walked yet).
- `CXXDefaultInitExpr` writes the field (`a`); the initialiser is the
  field's. `aux` is always 1 (any other value is `Unaccounted`); `b` is
  `out`. `ColdExprData` `default_imm` is `demand`: nothing is written, and
  `tests/demand` shows a use that instantiates leaves the unit equal.
- `ColdExprData` `default_arg_rewritten` is written by `expr::cold`.
  Kiln fills it when a temporary bound by a default argument or a default
  member initialiser is extended: for a default argument only in an
  automatic variable's initialiser (temporary.rs:434,
  `extend_init_temporaries` returns unless the storage is automatic), so
  that case waits for statements; for a default member initialiser in an
  aggregate, at namespace scope too (CWG1815: `temporaries_bound_by`,
  `temporaries_in_aggregate`, `rebuilt_default_init`, temporary.rs:565,
  :834, :878). The test is `struct Agg { const int &r = 1; }; Agg v{};`
  against `Agg v{1};`, and a unit test checks that side A has an entry.

## CXXConstructExpr, CXXTemporaryObjectExpr and ConstructInfo

Field by field against digest §6 (what a construction is):

- `ConstructInfo::from_aux(aux & 0x3F)` is destructured without a rest
  pattern; any bit of `aux` past 0x3F is `Unaccounted`. Written: the
  `ConstructionKind` tag, then one flag word `list`, `std_init_list`,
  `zeroing`, `immediate_escalating` (bits 0 to 3).
- `list` is in: `S(1)` and `S{1}` may choose the same constructor and
  still differ in narrowing and in the order of evaluation (§6:
  initialisation as written). `tests/differ/_/parens-against-braces`.
- `std_init_list` is in: an added `initializer_list` constructor that wins
  `T x{1}` changes the constructor and this flag
  (`tests/differ/_/init-list-constructor-added`).
- `zeroing` is in: value-initialisation zeroes before the constructor
  runs (`Z() = default;` in the class against a user-provided
  `Z::Z() = default;`, the same constructor otherwise).
- `immediate_escalating` is in, but set only for a call in a function
  body (consteval.rs:1507): its test is pending statements.
- `bits-had-multiple-candidates` is `out`: the constructor chosen is the
  fact; a candidate added that does not win changes nothing
  (`tests/differ/_/construct-overload-added` adds one that wins).
- `a` is the constructor as a `ref` (its key, not its spelling):
  `ns::S(1)`, `::ns::S(1)`, `S(1)` inside `ns` and an alias are equal
  (`tests/equal/_/construct-*`). `b` is the argument list.
- `ConstructionKind` other than `Complete` is made only for base and
  delegating initialisers (`ColdDeclData` `ctor_inits`, not walked yet):
  those tests are pending `decl_data`; the unit tests render the AST.
- A converting constructor against a conversion function: the
  construction against the call of the conversion function differ
  (`tests/differ/_/converting-constructor-against-conversion-function`).
- Instantiating the constructed class elsewhere (on side B) leaves the
  construction unchanged (`tests/demand/_/construct-*`).

## CXXInheritedCtorInitExpr

`aux` bits 0 to 1 are the `ConstructionKind`, bit 2 is the virtual-base
flag; any other bit is `Unaccounted`, as is a non-zero `b`. The node is
only in the body Kiln defines for an inheriting constructor
(class/special/define.rs:1189-1239): tests pending statements. The
default arguments of an inheriting constructor are the base
constructor's, reached through `a`.

## InitListExpr and InitListExtra

- `a` (the elements), then `InitListExtra` destructured: `array_filler`
  (`child?`), `union_field` (`ref?`); `rbrace` is `out`.
- `ColdExprData` `syntactic_list` is set only in a template, for a list
  with designators (init.rs:2114); `DesignatedInitExpr` exists only in
  such a written list. The test is a non-dependent `{.x = 1, .y = 2}`
  against `{1, 2}` in a template.
- `union_field` is the member a union's list initialises: `U::i` against
  `U::j`.

## Designators (§7.3) and DesignatedInitExpr

`DesignatedInitExpr` writes `a`, its initialiser; `expr::cold` writes
`designators`, which is a count then, for each designator outermost
first, its tag and: `Field` its name (`sym`), `Index` its index, `Range`
its first and last. `loc` and `ellipsis` are `out`. An entry on another
kind is `Unaccounted("ColdExprData/designators")`.

## ArrayInitLoopExpr

`a` is the common expression (an `OpaqueValueExpr`), `b` the element
initialiser, which reaches the same `OpaqueValueExpr` again
(class/special/define.rs:1059, struct_bind.rs:446). By the opaque-value
rule the source is written the first time only, so `a` is written once,
and nested loops (a multi-dimensional array copied by a structured
binding) add the same bytes per dimension (unit test
`nested_array_init_loops_are_linear`, 2 to 8 dimensions).

## CompoundLiteralExpr

A non-zero `aux` is a file-scope compound literal (gnu.rs:761): its
implicit variable (`b`) has no key, so the unit is
`Unsupported("ExprNode/CompoundLiteralExpr.aux")`. A non-zero `b` with
`aux` 0 is `Unaccounted`. A namespace-scope array literal
(`int *v = (int[]){1, 2};`) is file scope; a struct one is not.

## NoInitExpr, DesignatedInitUpdateExpr, ParenListExpr

`NoInitExpr` and `DesignatedInitUpdateExpr` come from a C99 nested
designator that overrides part of an earlier initialiser (init.rs:2932,
:3138, :3414). `ParenListExpr` is a template's `(a, b)` initialiser
(decl.rs:8413, new_delete.rs:842, lambda/capture.rs:1666).

## CXXNewExpr and NewExtra

- A flag word `bits-global`, `bits-array-form`, `bits-pass-align`, then
  the `NewInitStyle` tag, then `NewExtra` destructured: `allocated_ty`
  (type), `array_size` (`child?`), `init` (`child?`), `placement`
  (`child*?`), `operator_new`, `operator_delete` (`ref?`); `type_loc` is
  `out`. A non-zero `b` is `Unaccounted`.
- The allocation and deallocation functions are refs: a class's own
  `operator new` against the global one differs; `new ns::S` requalified
  is equal.

## CXXDeleteExpr

- One flag word: `bits-global`, `bits-array-form`,
  `bits-array-as-written`, `aux-sized`, `aux-aligned`; then `a`, then `b`
  as a `ref?`.
- `bits-array-form` and `bits-array-as-written` (new_delete.rs:2347,
  :2424): `delete pa` of a pointer to array sets the form only; a written
  `delete[]` sets both. In a pattern only the written form is known, and
  substitution reads `ARRAY_AS_WRITTEN` (subst/exprs.rs:1437); both are in.
- `aux-aligned` comes from the allocated type's over-alignment
  (new_delete.rs:2435: `aligned = aligned_allocation && align >
  default_new_align`), not from the function's parameters.
- `b` is the deallocation function Kiln looks up statically at the
  expression from the operand's type (new_delete.rs:2333 to :2543), stored
  as the latest declaration. For a class with a virtual destructor the
  function actually called is the one found from the dynamic type's
  destructor (`dtor_delete`); that is the class's fact, not this row. The
  global `delete` of an `int *` chooses the sized form (`aux-sized` set).

## CXXPseudoDestructorExpr, CXXThrowExpr

`aux` bit 0 arrow, bit 1 qualified, written as one flag word; `a` the
object; `b` the destroyed type. `CXXThrowExpr` `a` is `child?` (a rethrow
has none); a non-zero `b` is `Unaccounted`.

`aux-qualified` is written only for an instantiation-dependent node (the
predicate of `CXXThisExpr.aux-implicit`): the readers are Kiln's template
substitution (templ/subst/exprs.rs:834), its mangling of dependent expressions
and its profiles; `kiln_abi`'s definition hash of the node reads only the
arrow and the destroyed type, and codegen does not read it. Tests:
`tests/equal/_/pseudo-destructor-qualified-outside-template` and, in a
template, `tests/differ/ExprNode/CXXPseudoDestructorExpr.aux-qualified`.

`CXXNewExpr.bits-global` was to be made dependent-only too, but it is
kept for every node: `kiln_abi/src/odr_def/init.rs:146` hashes it for
every new-expression, and codegen emits that definition hash into the
Mason metadata (`kiln_codegen/src/mason_defs.rs:27`, kind 2 rows), so
`new int` against `::new int` changes what the toolchain emits.

## CXXRewrittenBinaryOperator: `b` is the written order

The first decision (`b` `out`) missed a difference; this replaces it.

- Written: `aux` (the operator as written, `BinaryOp` tag), `a` (the
  semantic form), and `b` as one `bool`: whether the two operands as
  written are in the reverse of their order in `a`. The operands are not
  written again.
- Why `b` cannot be `out`: `x != y` from a reversed `operator==(Y, X)`
  and `y != x` from a non-reversed one have the same semantic form
  `!(operator==(y, x))`, and in a template the instantiation forms the
  comparison again from the operator and `b`'s operands in their written
  order (templ/subst/exprs.rs:716, `act_on_binary(op, l, r)`), so the
  pattern means another thing (`tests/differ/_/rewritten-written-order-in-pattern`; its
  instantiation half, `rewritten-written-order-instantiation`, is pending
  `demand`).
- How: the operands of `b` are the very nodes the semantic form holds
  (overload/oper.rs:468, where `ops` is `args` copied; :1184, where
  `written` is `args`). `written_reversed` walks `a` in pre-order
  (`ExprArena::children_into` plus the opaque source of an
  `OpaqueValueExpr`), not entering either operand, and the flag is whether
  the second written operand is found first. It stops at the operands, so
  it is linear in the part of `a` outside them; past 256 visited nodes, or
  with an operand not found under `a`, or a `b` that is not two operands,
  the unit is `Unaccounted("ExprNode/CXXRewrittenBinaryOperator.b")`.
- Tests: `tests/differ/_/rewritten-ne-reversed-same-semantic-form` (only
  `b` changes: the unit test renders `bool true` against `bool false` with
  the same `a`), `rewritten-lt-reversed`, `rewritten-spaceship-reversed`,
  `rewritten-eq-reversed`; for `<` and `<=>`, `a` differs as well (`@ 0`
  against `0 @`). A non-reversed `==` is a plain call, no rewritten node.
- The unit test `rewritten_operands_are_in_the_semantic_form` pins that
  both operands are under `a`.
  For every rewrite Kiln makes, it finds both `ExprId`s of `b` among the
  nodes reachable from `a` (`ExprArena::children` and opaque sources).
  The rewrites covered:
  - `!=` from a member and from a non-member `==`, and from a defaulted
    `==`;
  - reversed `==` and `!=`;
  - `<`, `>`, `<=` and `>=`, from a member and from a non-member `<=>`,
    in both orders;
  - reversed `<=>`;
  - a defaulted `<`'s body, which Kiln builds as a rewritten `<=>`.

  Every form builds the node and every operand is found.
- Removed: the nesting limit, the thread-local depth counter, the
  `Unaccounted` cut and the bump of `Walk::aborts`.
- Tests:
  - `tests/differ/_/rewritten-operand-changed`, `rewritten-operand-order`
    and `rewritten-reversed-operands` still differ;
  - `ExprNode/CXXRewrittenBinaryOperator.aux` covers the operator as
    written;
  - `nested_rewritten_comparisons_are_linear`: `a < a < …` nested 200 and
    2 000 deep, each `<` from `<=>`, gives linear bytes and no cause.

## InitListExpr.a: runs

Table owner's decision on this package's proposal.

- `InitListExpr.a` is written as runs of one node: the count of runs,
  then for each its length (`uv`) and the node once. A run is a maximal
  sequence of consecutive elements with the same `ExprId`.
- The table's encoding stays `child*`, with the rule in the row's note:
  the grammar of §1.3 has no form for `(uv, child)*`, so this follows
  §1.3's "nearest form, the rule in prose".
- What Kiln builds for a range designator: `[a ... b] = x` initialises
  every slot of the range from the same clause (init.rs:3109). For an
  expression that needs no conversion, every slot holds the same node, so
  the range is one run.
  - `{[0 ... 2] = 7}` against `{7, 7, 7}` differs: one run of 3 against
    three runs of 1 (`tests/differ/_/init-list-range-against-written-out`).
  - `[0 ... 2]` against `[0 ... 3]` differs
    (`tests/differ/_/init-list-range-length`).
  - A range of 1 000 000 slots writes 2 bytes more than one of 1 000
    (unit test `a_range_is_one_run`).
- Nested ranges `[0 ... N][0 ... M] = x`: Kiln builds one sub-list per
  slot of the outer range (`descend` per slot, init.rs:3109, :3375). Each
  sub-list is one run of the shared node, so the bytes grow with the
  outer length only: 10×10 is 1 259 bytes, 10×1 000 is 1 269 and 20×10 is
  2 459 (unit test `nested_ranges_grow_with_the_outer_length_only`). That
  is linear in the AST Kiln builds, not constant.
- Cost, which runs do not bound (a separate package): a slot whose clause
  needs a conversion gets its own conversion node around the one shared
  clause (`long v[N] = {[0 ... N-1] = g() + …}`: N `ImplicitCastExpr`s,
  N runs). The clause is not a shared node to the walk, so it is written
  once per slot: 132 589 bytes for N = 10, 13 253 060 for N = 1 000.
  Nested ranges and ranges broken by overrides do the same: O(n·|E|) for
  n slots over a clause of size |E|, not linear in the source.
- A repeated `ExprId` that is not adjacent: the scan
  `expr_init::tests::shared_nodes` (ignored, a tool) over the sources of
  every pair test found none in an `InitListExpr`.

## Nesting

- An initialiser list of 100 000 elements is one level of recursion and
  linear bytes (unit test against 50 000).
- 2 000 nested braces (a dependent list keeps them as written) digest
  with no cause, linearly (against 1 000).
- A designated list in a template keeps its written form
  (`ColdExprData` `syntactic_list`, init.rs:2114, written by
  `expr::cold`). The written form's `DesignatedInitExpr`s hold the
  semantic form's own initialisers, so nested designated lists are
  written in time and bytes quadratic in their depth. The bytes for 1, 2,
  3, 4, 8 and 12 levels are 654, 1 130, 1 725, 2 439, 6 485 and 12 435
  (ignored measure `nested_designated_lists`). The cause is Kiln's: it
  builds a fresh written copy of the list at each level
  (templ/actions.rs:2162), and instantiation reads only the outermost
  (templ/subst/exprs.rs:2935). This is a follow-up (separate package), with the
  range cost above.
