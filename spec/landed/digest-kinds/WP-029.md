# WP-029 — templates and specialisations

What `crates/slip_digest/src/templ.rs` reads into `spec/digest-kinds.md`
§9 (§9.1, §9.2, §9.4, §9.5) and digest §8 where they are silent. Where a
fact could not be settled, the unit is indeterminate.

## Heads

- **Key form and unit form.** A key's template head writes each
  parameter as its `DeclNode` rows (WP-024). A unit's head
  (`TemplateInfo.params`, `PartialSpecInfo.params`) writes each
  parameter's whole stream, which closes with `TemplateTables.defaults`.
- **A template template parameter's own head** (`TemplateParmInfo
  params`) is written in key form inside a key and in unit form
  elsewhere, so a default in it changes the template's unit and not its
  key (`differ/_/ttp-inner-default`).
- **Defaults from the declaration that gives them** (§2.3). When a
  parameter of the declaration read has no default, own or inherited
  (`inherited_defaults`), the unit writes the stream of the parameter at
  the same position of the first other declaration of the template that
  has one of its own. The other declarations are those of the template's
  pattern (a template has no redeclaration group of its own:
  `Ast::redecls_of(pattern)` then `described_template`), latest first,
  the read one excluded. So `template <class T> struct X {};` followed by
  `template <class T = int> struct X;` digests as one declaration with
  the default (`equal/_/template-default-later-redecl`).
  A default inside a template template parameter's head given by another
  declaration is not merged that way (open: see the handback).

## Links and specialisation records

- **`TemplLink` `0-kind`** is `enum TemplLinkKind?`: absent for the word
  0; a word whose tag is no variant (`TemplLink::get` is `None` for a
  non-zero word) is absent and `Unaccounted("TemplLink/0-kind")`. An
  index with no record is `uv 0` and `Unaccounted("TemplLink/<Kind>.0-index")`.
  `DependentFriend` is `Unsupported` (WP-024).
- **`SpecKind` `Undeclared`**, which is `out`, is written with its tag and
  `Unaccounted("SpecKind/Undeclared")` if a stream ever meets it.
- **The §11.9 move applies to every implicit instantiation.** §9.4's
  prose moves `from` and `from_args` of an implicit instantiation to the
  resolved unit `definition`; §11.9's table lists them only for a class.
  The walk reads the prose: every `SpecInfo` of kind
  `ImplicitInstantiation` (class, function or variable) writes `from` as
  `Ref::none` and `from_args` absent, with `Pending(Demand)`. The demand
  package must write them in `definition` for functions and variables
  too, or the choice of a variable template's partial specialisation is
  in no unit. The `Pending(Demand)` cause is what keeps that from being
  lost silently: until the resolved unit exists, every such
  specialisation's unit is indeterminate.
- **References into a pattern.** `SpecInfo.from`,
  `MemberSpecInfo.instantiated_from`, `ttp_owner` and `instantiated_from`
  name declarations of a pattern. A pattern's declaration that has no
  key (a parameter, a local variable, a local class or one of its
  members, a label: `Role::Local`, or `is_local` and not a block-scope
  extern) is `Ref::none` with no cause: `write_ref` would give it a local
  ordinal of the unit being written (a parameter or variable) or
  `Pending(Local)` (a local class), neither of which names the pattern's
  declaration. A template parameter stays `Ref::template_param`.
- **`PartialSpecInfo`** has private fields (`shapes`, `shapes_len`), so
  it is read field by field, not destructured.

## `TemplateTables`

- **`size_of_pack_origin`** names the pack a substituted `sizeof...`
  named. A template parameter pack is `Ref::template_param`. A function
  parameter pack is `Ref::param(scope_depth, index)`, read from the
  parameter's `ParamData`: the function-scope depth and the position
  Kiln stores, which is what the mangling `sZ fL<depth>p<index>_` reads
  (`kiln_abi/src/mangle/dep.rs:703`). Both numbers are facts of the
  pattern's declaration, so the `Ref` is the same whichever unit (or
  key) is being written: it is not a local ordinal of the unit, which
  would depend on what that unit met first (WP-024 "A key does not
  depend on the unit that asks"). A `ParmVar` with no `ParamData`, or
  another pattern-local pack (a structured binding pack), is `Ref::none`
  with `Unaccounted("TemplateTables/size_of_pack_origin")`.
- **`member_like_friend`** is looked up by the declaration, then by its
  first declaration, as Kiln's mangler does
  (`kiln_abi/src/mangle.rs:1669`).
- **`pseudo_dtor_first`**: the type is written; the position (`-position`)
  is `out`.
- The rows keyed by `DeclId` (`decl_maps`) and by `ExprId` (`expr_maps`)
  are written in table order, each in its empty form when the map has no
  entry.
- **`param_object_values`** is written at the `data` position of a
  `TemplateParamObject` (where `decl.rs` calls `templ::param_object`),
  not as a closing row of every declaration's stream, although §9.5's
  first paragraph reads as if every `in` row keyed by `DeclId` were one:
  only a template parameter object can have an entry.

## Pair tests

- `TemplLink`, `SpecInfo`, `MemberSpecInfo` and the `SpecKind` rows are
  written by `templ_link`, which the payload records (`decl_func.rs`,
  `decl_class.rs`, WP-026/027) call. Until they do, the tests that see
  them only through `templ_link` are `# pending` with `# needs:
  decl_data`; they were checked passing with a local call added to the
  payload stubs (not committed).
- `expr_maps` is called by the expression area (WP-031): its seven rows,
  and `TemplateInfo.constraint`, are `# needs: expr`; `pack_index_origin`
  also `# needs: demand`. Their expect lines were not observed.
  `param_object_values` is `# needs: value`.
- **Rows no edit isolates.** These change only together with a key (or
  with another row of the same unit); their tests change the fewest facts
  possible, name every unit that changes, and say so in a `#` line of
  their `expect.txt`:
  - every `TemplLinkKind`: a pattern, a specialisation, a partial
    specialisation and a declaration with no link are different
    entities (`TemplLink` `0-kind`, absent against
    `MemberOfSpecialization`, is isolated);
  - `TemplateParamList.depth` and `TemplateParmInfo.depth`: the depth is
    the nesting of the list, which is the key's parent chain;
    `TemplateParmInfo.index` (the position in the key's head) and `pack`
    (also in the key's head) likewise;
  - `SpecKind` `ExplicitSpecialization` for a class: Kiln sets an
    explicit specialisation's `from` to itself
    (`kiln_sema/src/templ/spec.rs:931`), so the kind of a class
    specialisation never changes alone; its test uses a member, whose
    `MemberSpecInfo.instantiated_from` stays the same;
  - `SpecInfo.from_args`: the deduced arguments change only with the
    partial specialisation chosen (`from`) or with the specialisation's
    own arguments (its key);
  - `trailing_requires`: the clause is also in the function's
    discriminator;
  - `ttp_owner`: only a concept template parameter has an entry, always
    its own template, so it comes and goes only with `ttp_kind` (in the
    key);
  - `size_of_pack_origin` and `size_of_pack_partial`: the operand is in
    a function template's return type or parameter, in the key.
- `PartialSpecInfo.params` and `TemplLink` `PartialSpecialization.0-index`
  are isolated by a default inside a template template parameter's own
  head, which the key's head leaves out.
- **`member_like_friend`** rests on a unit that exists only because of an
  instantiation: a member-like friend is declared by each instantiation of
  its class, and today that declaration is a declared unit present only
  on the side that instantiates (`demand/_/member-like-friend-declared-by-instantiation`).
  Its `differ` test is `# needs: units`, as are that demand test and
  `demand/_/friend-defined-in-class-template` (instantiating the class
  sets `instantiated_from` on the friend's first declaration,
  `kiln_sema/src/templ/member.rs:316-329`). Both are unit-classification
  matters left to their own package; `templ.rs` writes the rows as
  stored.
