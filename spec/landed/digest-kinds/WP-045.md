# WP-045 — resolved units, the definition class, the effective kind

What `crates/slip_digest/src/demand.rs` and the sites of §11.9 decide
where `spec/digest-kinds.md` §11.1, §11.9, §11.10 and `spec/digest.md`
§2.2 are silent, with Kiln's evidence (Kiln at Slip's pin).

## Resolved units (§11.1)

- One function writes a resolved unit of any property
  (`demand::write_resolved`). Its key is kind `resolved`, parent the
  owner's mapped key, name `property(n)`, and an optional discriminator
  (a `uv` stream finished with the discriminator tag). Its stream has a
  fresh unit state (local ordinals from 0). It is derived; its file is
  the owner's origin file (`units::origin_file`), empty for an owner of
  the `tu` group. Its cause is the stream's merged with the cause the
  owner's key carries, as `units::write` merges a unit's.
- `demand::resolved_units` is called by `walk::run` after every unit it
  writes, with one arm per property; WP-046 adds arms. Resolved units are
  appended after their owner (the order of `written` is not behaviour).
- `Written.entity` of a resolved unit is the owner's entity, and
  `Written.resolved` names the property. `names.rs` writes the owner's
  name followed by `::<property>` (`::<property n>` with a
  discriminator); `units::apply_taints` marks the first unit of an
  entity, which is the owner.
- Property 4, `key_function`, the worked example: `ColdDeclData`
  `key_function` of the class's definition, `ref`. At the pin Kiln
  computes it when the class definition ends
  (`kiln_sema/src/class/virtual/complete.rs:366-373`, from
  `act_on_finish_class_contexts`, `class/mod.rs:689`), not on use; an
  instantiation has none (`may_have_key_function`). So the unit exists on
  both sides of every pair (`tests/resolved/key_function/*`).

## Decision 1: the effective kind (§11.10)

`demand::effective_kind`, as decided. Two choices beyond the list:

- The climb is through semantic contexts that are classes **or
  enumerations**, so an enumerator of a member enumeration takes its
  enumeration's kind.
- A declaration that is no member but has a `MemberSpecInfo` (a friend
  an instantiation declared) has none: Kiln's first declaration of a
  friend later written in source is the instantiation's, and its own
  kind would make the written entity derived
  (`units::tests::entity_declared_by_instantiation`). `units::outside_only`
  decides a friend. A local entity has none.

How it relates to the helpers it was asked to replace:

- `units::in_implicit_instantiation` stays, reduced to the effective
  kind: the nearest context that has an effective kind has
  `ImplicitInstantiation` (a local class has none, so the function that
  holds it answers). `units::instantiated_outside_class` reads the same
  climb for its lexical context. A member class used before an explicit
  instantiation, whose friends used to count as instantiated outside the
  class, now counts as the explicit instantiation's.
- `decl_func::instantiated_on_use`, `decl_func::implicit_instantiation`,
  `decl_func::{function,var}_definition_class` and
  `decl_class::{governing_kind, definition_class}` are removed:
  `demand::definition_class` and `demand::effective_kind` replace them.
  `decl_class::instantiated_field` reads the effective kind.
- `templ::governing_kind` and `templ::instantiated_declaration` stay:
  they answer of a **declaration**, by its lexical contexts (was this
  declaration made by an instantiation?), which the effective kind,
  a fact of the entity, does not answer. `instantiated_declaration` is
  used by the default-argument and `init_fp` rules and by
  `units::instantiated_out_of_line`.

## Decision 2: the unit class

`units::unit_class` reads the effective kind for every entity that is not
a pattern, outside-only, implicit or builtin: `ImplicitInstantiation` is
derived, the explicit kinds declared, `Undeclared` no unit, none declared.

Kiln's evidence that an explicit instantiation declaration instantiates
the class's definition and with it every member's declaration:
`kiln_sema/src/templ/spec.rs:1035` instantiates the definition
(`instantiate_explicit`) if the specialisation has none, for a
declaration as for a definition; `instantiate_members_of`
(`spec.rs:1306`) then instantiates, for a declaration, only member
classes (recursively, upgrading a fresh one to the declaration's kind,
`spec.rs:1366-1398`), and for a definition also member functions and
static data members. Member declarations come with the class definition
in either case.

## Decision 3: the definition class (§11.9)

`demand::definition_class`, as decided. Notes:

- The predicate climbs no lexical context: a member of an instantiated
  class is of the class by its effective kind, a friend by
  `units::outside_only`.
- A local entity has no effective kind, so a member function of a local
  class in an instantiated function is not of the class (it is written
  in full where the function's body is written, now in `definition`);
  an implicit special member of a local class still is (rule 3), and
  has no resolved unit since a local entity has no unit (see "Open
  points").

## Decision 4: rows moved, and the own unit

- The rows are written in the order of the table of §11.9; the flag
  words in `definition` hold only the moved bits, in the own word's
  order.
- **The own unit of an entity of the class is read from its first
  written declaration** (`units::read_decl` returns
  `Walk::representative`), not from the definition, and its chain leaves
  out the declarations an instantiation made out of line for a member
  (`units::instantiated_out_of_line`): Kiln instantiates a static data
  member's out-of-line definition, on use, as a **new** redeclaration
  whose lexical context is the namespace of the pattern's definition
  (`instantiate_static_member_def`, `kiln_sema/src/templ/class.rs:1943`),
  with the pattern definition's attributes and `VarSpec` bits; read by
  the own unit it would move the merges, the declaration read and
  `lexical_ctx`. The `definition` unit reads every declaration
  (`UnitState::definition`).
- The placeholder type: written in its empty form (absent `ty-type`) in
  the own stream, and in `definition`. The earlier text of §11.9 said the
  own stream writes the pattern's placeholder; the decision's "each
  written in its empty form" is what the code does.
- `DeclMisc` `0-definition` is clear for every entity of the class,
  fields, typedefs and enumerators of instantiations included (they have
  no `definition`: nothing of them is made on use).

## Decision 5 and 6: when `definition` exists, and what it reads

`demand::defining_declaration`; per kind in §11.9 with Kiln's
`file:line`:

- a function: `Ast::definition` (`kiln_ast/src/ast.rs:678`, set with
  the body by `AstBuilder::set_body`, `kiln_ast/src/builder.rs:907`), if
  it has a body. Kiln puts an instantiated definition on the same
  declaration (`instantiate_function_definition`,
  `kiln_sema/src/templ/class.rs:1526`), and an implicit member's
  (`define_implicit_special`, `kiln_sema/src/class/special/define.rs:355`;
  `define_defaulted_comparison`, `class/compare/synth.rs:90`);
- a variable: the first declaration of the whole chain that is a
  definition (`units::is_var_definition`), else the one holding an
  initialiser;
- a class or enumeration: `Ast::definition`
  (`kiln_ast/src/builder.rs:585`, `:665`);
- the fourth item of decision 3: the declaration `Ast::definition` names
  when it is instantiated outside its class.

## The members row of `definition`

`RecordData` `members` lists the members that are declared units
(§5.5). The members of an implicit instantiation are derived, so the
row in `definition` lists only the members an explicit specialisation
declares (`template <> void X<int>::f() {}`;
`tests/resolved/definition-differs/class-members`). A field added to the
pattern shows in the pattern and in the derived field's own unit.

## Tests and mutations

- `tests/resolved/definition/*`: one pair per kind of §11.9; a closure
  type is a local entity (pending, `Area::Local`), so its conversion
  function has no unit and no `definition` (WP-040).
- `tests/resolved/definition-differs/*`: a pair per row of decision 4,
  both sides defining the entity; the runner checks that no other unit
  both sides have differs, so the own unit is shown unchanged (the
  differ runner cannot say that a derived owner is unchanged). The body
  pair (`function-body`) is pending on statements: a body is
  `Pending(Stmt)` and not hashed until WP-034.
- Mutations, each caught by a named test: every row dropped from
  `definition` (`definition-differs/<row>`); the body, the variable's
  initialiser and `0-inline` written in the own unit too
  (`demand/_/instantiated-member-body`, `instantiated-static-member-init`,
  `decl_func::tests::definition_class_body_is_in_definition`); the
  effective kind replaced by the own kind
  (`demand/_/members-under-explicit-instantiation-use-before`,
  `differ/EnumData/templ`); the out-of-line instantiated declaration kept
  in the own chain (`demand/_/static-member-out-of-line-attribute`,
  `units::tests::instantiated_out_of_line_definition_is_left_out`).
  Two survive, both equivalent: dropping the body from `definition`
  (bodies are not hashed yet), and reading the own unit from the
  definition rather than the representative (with the chain filtered, a
  variable's definition is then not found and the representative is
  read; a function's instantiated definition is Kiln's same
  declaration).

## Open points

- **FnSpec `inline` of a function template specialisation** (reported,
  not decided here): `t<int>` takes the `FnSpec` of the definition it is
  instantiated from; when that definition is a friend's, defined in a
  class template, it exists only once the class is instantiated, so the
  own unit of `t<int>` differs with that instantiation
  (`tests/demand/_/friend-template-definition-instantiated-on-use`,
  pending; its side B also redefined `use`, fixed). The table of §11.9
  moves `is_coroutine` and `escalated` only.
- A static data member declared in its class with an incomplete array
  type and completed by its out-of-line definition: the own unit, which
  leaves out the instantiated definition, has the incomplete type; the
  completed type is not in `definition` (the table moves the type only
  for a placeholder). Not tested.
- `relocate_to_pattern_definition` (`kiln_ast/src/templates.rs:1984`)
  moves an instantiated member function's location to the pattern's
  definition: for a member of an explicit instantiation (declared) whose
  pattern is defined out of line in another file, the declared file may
  then follow the instantiation of the definition. Not tested.
- An implicit special member of a local class is of the definition
  class but has no unit, so no `definition` (WP-040).
