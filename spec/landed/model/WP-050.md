# WP-050 — the map task: the worker writes the `digests` section

`spec/model.md` §8.4 (`Unit::stack_remaining`, `-fkiln-reproducible-time`)
and §8.5 (the map task) say what the code does. This file records what
they left open, how the code decides it, the figures of the walk's stack,
and the first corpus run with digests.

## Rules

- **Where the checks live.** `with_input` makes the stack check of §8.5
  "The stack" before calling `f` (the spec's "the same checks" for every
  use of the walk), so `digest_unit`, which is `with_input(unit, subject,
  |input| digest(input, options))`, makes it through `with_input`. The
  stack is measured in `with_input`'s frame, on the front end's thread.
- **The walk's precondition is the worker's.** `digest_unit` does not look
  at `unit.errors()`: the map task's closure (`crates/slip_cli/src/
  worker.rs`, `map_observer`) calls it only when `unit.errors()` is 0, and
  otherwise returns `None`, so the shard is the parse task's.
- **Subject paths that are not an input.** The walk asks for the subject
  path of the file of every unit's first declaration. A buffer that is
  neither an input nor named `<…>` gives the empty path to the walk and
  records the error; the first such error is returned after the walk and
  the walk's result is dropped (`with_input`). Today only a `Lazy` buffer
  never read (a module file or a precompiled header, out of scope of M1)
  can be such a buffer: every buffer of an ordinary parse is an input or
  `<…>` (`tests/map.rs` `s8_5_subject_paths_of_inputs_and_predefines`
  asserts it of a unit with command-line macros and token pasting). No
  test reaches the `Err` (as WP-025's lazy buffers).
- **Cause counters.** `counters(output)` adds to `output.counters` one
  count of `digest.cause.<cause>.<word>` per element of `output.causes`
  whose cause is `Unsupported` or `Unaccounted` (one element per
  indeterminate key, its first cause). `cause_word` works on the text's
  bytes: a non-ASCII character is one `_` per byte (`Dé` is `d__`).
- **The map task and phases.** `MapTask` runs jobs of phase `map` only; a
  job of another phase is `Err` (`the map task runs phase map only; the job
  is of phase verify`) until the verify task (WP-052) exists.
- **Counters of the shard.** For an `ok` shard, the parse task's counters
  and `counters(output)` together, sorted by name (the names are
  disjoint). A shard that is not `ok`, or a unit with errors, carries the
  parse task's counters only.
