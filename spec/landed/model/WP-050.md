# WP-050 — the map task: the worker writes the `digests` section

`spec/model.md` §8.4 (`Unit::stack_remaining`, `-fkiln-reproducible-time`)
and §8.5 (the map task) say what the code does. This file records what
they left open, how the code decides it, the figures of the walk's stack,
and the first corpus run with digests.

## Rules

- **Where the checks live.** `with_input` makes the stack check of §8.5
  "The stack" before calling `f` (the spec's "the same checks" for every
  use of the walk), so `digest_unit`, which is `with_input(unit, subject,
  |input| digest(input, options))`, makes it through `with_input`. The
  stack is measured in `with_input`'s frame, on the front end's thread.
- **The walk's precondition is `map_unit`'s.** `digest_unit` does not
  look at `unit.errors()`; `slip_digest::map::map_unit` does, and returns
  `None` for a unit with errors (the shard is then the parse task's),
  else `digest_unit`. The worker (`crates/slip_cli/src/worker.rs`,
  `map_observer`) calls `map_unit` and no method of `Unit` (§8.4).
- **Subject paths that are not an input.** The walk asks for the subject
  path of the file of every unit's first declaration. A buffer that is
  neither an input nor named `<…>` gives the empty path to the walk and
  records the error; the first such error is returned after the walk and
  the walk's result is dropped (`with_input`). Such a buffer comes only
  from modules and precompiled headers, both out of scope of M1: a
  `Lazy` buffer never read, and the `Virtual` buffers Kiln names with a
  real path for the recorded text of a module or a precompiled header
  (`kiln_pp/src/modules.rs:1418`, `kiln_pp/src/state.rs:978`). Every
  buffer of an ordinary parse is an input or `<…>` (`tests/map.rs`
  `s8_5_subject_paths_of_inputs_and_predefines` asserts it of a unit
  with command-line macros and token pasting). No test reaches the `Err`
  (as WP-025's lazy buffers): it needs a module or a precompiled header
  the front end loads, and neither `slip_kiln` nor its snippet runner can
  make one; that is more than the hour the fix round allowed for it. The
  review's mutants of this path (M03, the `None` stack guard; M05 and M06,
  the cell that keeps the first such buffer) stay untestable until then.
- **Cause counters.** `counters(output)` adds to `output.counters` one
  count of `digest.cause.<cause>.<word>` per element of `output.causes`
  whose cause is `Unsupported` or `Unaccounted` (one element per
  indeterminate key, its first cause). `cause_word` works on the text's
  bytes: a non-ASCII character is one `_` per byte (`Dé` is `d__`).
- **The map task and phases.** `MapTask` runs jobs of phase `map` only; a
  job of another phase is `Err` (`the map task runs phase map only; the job
  is of phase verify`) until the verify task (WP-052) exists. A map job
  with a `post` (`a map job with a post`) or a `transform` (`a map job
  with a transform: the map task does not run transforms yet
  (spec/edits.md §8.1, M2)`) is `Err` too (`spec/exec.md` §5.5, §8.4).
  The three checks come before the store is opened, in that order.
- **Counters of the shard.** For an `ok` shard, the parse task's counters
  and `counters(output)` together, sorted by name (the names are
  disjoint). A shard that is not `ok`, or a unit with errors, carries the
  parse task's counters only.

## Declarations without a location (fix round)

`spec/digest.md` §11 left "a declared unit whose first declaration has no
location" to be decided. The decision, now §11 and a row of §2.2:

- **Origin file.** The file of a unit is that of its origin declaration
  (the representative for a declared unit, what it derives from for a
  derived one) if that has a location, else of the earliest declaration
  of its chain that has one (`Walk::located`, `Walk::unit_file` in
  `crates/slip_digest/src/units.rs`). Both readings of a unit's file,
  `write` for declared units and `origin_file` for derived ones, go
  through it; nothing else in the output carries a file. The declaration
  without a location stays in the chain and is read like any other: only
  the file moves.
- **No location at all.** An entity `unit_class` would make declared and
  no declaration of which has a location is on demand, as a builtin
  (`unit_class` over `class_of`); it does not look at `IMPLICIT`.
- **Friends of a class template's pattern.** Kiln chains a friend
  declared in a class template's pattern to a later namespace-scope
  global `operator new` or `operator delete`: its allocation path
  (`kiln_sema/src/new_delete.rs` `act_on_global_new_delete_decl`, and
  `find_global_op`, which then declares no implicit one) finds the
  friend by `lookup_local`, where ordinary redeclaration lookup does not
  (a pattern's `friend void g();` stays an entity of its own). Such a
  declaration (`pattern_friend` in `units.rs`) is left out, while the
  chain has another declaration, of what a unit is classified and read
  from (`representative`, `redecls`) and of what its file is taken from
  (`located`, which skips exactly what `representative` skips). The unit
  is then read from and in the group of the namespace-scope declaration,
  with one digest whether or not the template is instantiated after it
  (`tests/map.rs` `s8_5_pattern_friend_of_operator_new`). When the
  template is instantiated *before* the namespace-scope declaration,
  Kiln leaves the instantiated friend unchained (it chains the later
  declaration to the pattern's friend instead), so two entities have one
  key and both are flagged `collision`
  (`s8_5_pattern_friend_instantiated_before_the_declaration` pins it):
  Kiln's to fix, under "For Kiln" below.
- **Should one get through.** A declared unit whose chain has no located
  declaration (unreachable with the rule above) is written in the
  derived group with the empty path, indeterminate
  `Unaccounted("unit/file")` (counter
  `digest.cause.unaccounted.unit.file`), so that the job is not failed
  and the counter shows it; the validator's refusal of a declared group
  with the empty path is kept. The test is on the location, not on the
  empty path: a caller may give a file the empty path
  (`tests/expr_chains.rs` does for every file).
- **Kept although no input reaches them** (review M14, M17, M11): the
  location rule of `unit_class` (A2) is redundant with `all_implicit`
  today, since every declaration Kiln makes without a location is
  `IMPLICIT`; it is kept so that the rule holds by location, not by a
  flag Kiln could stop setting. The `Unaccounted("unit/file")` fallback
  and the worker's "the shard is not `ok` although the unit had no
  error" check are unreachable today and kept as defence. In
  `origin_file`, `unit_file` differs from `file_of` (review M19) only on
  a declaration without a location whose chain has one with; the climb
  of `origin_file` reaches such a declaration only through Kiln's
  implicit `namespace std` reopened in source, from an implicit entity
  declared directly in it, and no such derived unit is written today
  (an implicit deduction guide of a class template in `std` is no unit).
  Not tested, kept for the one reading of a unit's file.
- **Keys.** Unchanged: `parent_of` makes `Parent::Builtin` only for a
  builtin or a builtin template, so the implicit-only `operator new`
  (derived) and the one a source redeclares (declared) have one key, and
  a `Ref` to it from a shared header is the same with or without `<new>`
  (`tests/differ/_/operator-new-same-ref`: `f()` and `g()` do not
  change).

## For Kiln

- `kiln_sema/src/new_delete.rs`: `act_on_global_new_delete_decl` and
  `find_global_op` take candidates from `lookup_local(tu, …)`, which
  holds a friend declared in a class template's pattern; ordinary
  redeclaration lookup does not. A later global `operator new` is then
  chained to the pattern's friend, no implicit one is declared, and a
  friend instantiated before that declaration is left unchained (two
  entities, one key). Source: `template <class T> struct A { friend
  void *operator new(decltype(sizeof 0)); }; A<int> a; void *operator
  new(decltype(sizeof 0));`.
- `digest.indeterminate.error` in `ok` shards (2 870 430 units over the
  corpus; 2 in `llvm/lib/Support/MathExtras.cpp` alone in the first run):
  error nodes in a unit whose error count is 0.
