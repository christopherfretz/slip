# WP-022 — slip_model: keys, names, rules and the `DECL` container

Implemented by `slip_model::keys`, `slip_model::declared` and
`slip_model::formats` (the `DECL` codec). This file fixes the reading of
`digest.md` §3, `digest-kinds.md` §3.1–§3.2 and `verify.md` §2 that a
second implementation needs to get the same bytes and the same ids. Tests:
`crates/slip_model/tests/keys.rs`, `crates/slip_model/tests/declared.rs`.

## 1. Encodings

In the primitives of §2:

| Value | Encoding |
|---|---|
| `KeyKind` | `uv`, its number in digest-kinds §3.1 (1–33). 24 (`explicit_instantiation`) is listed: reading it is not an error. |
| `Parent` | `uv` 0 (`root`), 1 (`c_linkage`), 2 (`builtin`), or 3 (`unit`) followed by the parent's `KeyId` as a `digest`. |
| `Name` | `uv`, its number in digest-kinds §3.2 (1–15), then its "Then" column: `bytes` for `identifier` and `literal_operator`; `uv` for `operator`, `local`, `unnamed_ordinal`, `property`, `parameter`; `digest` for `conversion`; a nested `Name` for `unnamed_by`; nothing for the others. |
| `Key` | `kind`, `parent`, `name`, `disc` (`opt<digest>`). |
| `Rule` | `parent`, `kind`, `name`, `disc` (`opt<digest>`), `to_parent`, `to_name`. Its **match** is the encoding of its first four fields. |
| `Declared` | `list<Rule>`, then `changed`, `created`, `removed`, each a `list<digest>`. |

- `KeyId = H("slip.key.v1", encoding of the Key)`, the tagged digest of §3.
- `rules_id = H("slip.rules.v1", list<Rule>)` over the rules in table order:
  the count, then each rule's encoding. The empty table's id is
  `H("slip.rules.v1", 00)`.
- A rule table is ordered by the bytes of each rule's match, strictly
  ascending; two rules with one match are not a table. A key matches a rule
  when the encoding of its `(parent, kind, name, disc)` (in that order, not
  the key's own field order) equals the rule's match.
- `operator`'s number is not interpreted here, except that 0 is not one.

**Mapping is one step.** `RuleTable::map(key)` takes a key whose parent and
discriminator are already mapped and replaces its parent and name by the
`to_parent` and `to_name` of the rule whose match is the key's, if any;
kind and discriminator are kept. Rules do not chain: `map(map(k))` may
differ from `map(k)`. Mapping bottom-up is the walk's.

## 2. Rejections

A reader of any of these values rejects, with `Malformed` (§2.1) at the
offset given:

| Rule | Offset | Message (`what`) |
|---|---|---|
| a `KeyKind` number not in 1–33 | the value's first byte | `unlisted KeyKind value` |
| a `Parent` tag above 3 | the tag's first byte | `unlisted Parent value` |
| a `Name` number not in 1–15 | the number's first byte | `unlisted Name value` |
| an `operator` number of 0 | the operator number's first byte | `operator number is 0` |
| an `unnamed_by` nested in 8 others (at most 8 nest) | the ninth `unnamed_by`'s number | `unnamed_by nested more than 8 deep` |
| a `disc` tag other than 0 or 1 | the tag | `opt tag is not 0 or 1` |
| bytes after a lone `Key` (`Key::from_bytes`) | the first leftover byte | `bytes after the end` |

The reader of a name never recurses into more than 8 `unnamed_by`, whatever
the input.

`RuleTable::new` and `Declared::new` reject in memory what a reader would:
an invalid name (`RuleError::InvalidName`, with the message above), two
rules with one match (`RuleError::Duplicate`), and, for `Declared::new`,
which sorts nothing, a list that is not strictly ascending
(`DeclaredError::NotAscending`, naming `rules`, `changed`, `created` or
`removed` and the index of the later element). Checked in the order rules,
changed, created, removed.

## 3. The container `DECL`

The row §5.1 lacks:

| Kind | Format | Deterministic | Section |
|---|---|---|---|
| `DECL` | Declared changes (`verify.md` §2) | yes | this file |

Version 1. One section, `declared`, id 1, required, holding the `Declared`
record. `Declared` has `KIND`, `VERSION`, `to_bytes`, `from_bytes`,
`to_json`, `from_json` and `validate` as the formats of §5.5 do;
`validate` always succeeds, since `Declared` can only be built valid.
`formats::dump`, `undump` and `content_id` accept `DECL` as a fourth kind
(`undump`'s message for any other kind lists the four); a file of none of
the four kinds is still opened as a plan.

**Order of checks** (§5.4): the container; `UnknownSection` for any
critical id but 1; the section missing (`Malformed` at the `end` byte,
file length − 33, `declared changes have no declared section`); the
section's fields, with the rejections of §2 above, then `Malformed` at the
first leftover byte; then the invariants, in this order, each over the
whole list before the next:

| # | Rule | Offset | JSON path | Message |
|---|---|---|---|---|
| 1 | each rule's match above the previous one's | the later rule's first byte | `sections.declared.rules[i]` | `rules are not strictly ascending`, or, if equal, `two rules with one (parent, kind, name, disc)` |
| 2 | `changed` strictly ascending | the later element | `sections.declared.changed[i]` | `changed is not strictly ascending` |
| 3 | `created` strictly ascending | the later element | `sections.declared.created[i]` | `created is not strictly ascending` |
| 4 | `removed` strictly ascending | the later element | `sections.declared.removed[i]` | `removed is not strictly ascending` |

## 4. JSON rendering

By §10, with:

```json
"declared": {
  "rules": [
    { "parent": "root", "kind": "namespace", "name": { "identifier": "legacy" },
      "disc": null, "to_parent": "root", "to_name": { "identifier": "acme" } }
  ],
  "changed": [ "<digest>" ], "created": [], "removed": []
}
```

- `KeyKind`: its name in digest-kinds §3.1 (`class_template`).
- `Parent`: `"root"`, `"c_linkage"`, `"builtin"`, or `{ "unit": "<digest>" }`.
- `Name`: a form without a value is its name as a string (`"constructor"`,
  `"destructor"`, `"deduction_guide"`, `"anonymous"`, `"content"`,
  `"order"`); a form with one is an object with exactly one member, the
  form's name, whose value is the §10 rendering of the "Then" column
  (`bytes` as a string or `{ "hex": … }`, `uv` as a number or decimal
  string, `digest` as hex, a `Name` for `unnamed_by`):
  `{ "identifier": "f" }`, `{ "unnamed_by": { "identifier": "T" } }`.
- Reading accepts only that rendering: a form with a value written as a
  string, a form without one written as an object, an object with other
  than one member, and an unknown form are errors at the `Name`'s path (at
  `….<form>` for the member of an object). An `operator` of 0 is an error
  at `….name.operator`; a ninth nested `unnamed_by` at the path of that
  ninth `Name`. The messages of §2 are used.
- Invariants are errors at the paths of §3 with the same messages.

Goldens: `crates/slip_model/tests/golden/declared.bin` (the bytes) and
`declared.json` (its `dump`), holding every `Parent` and `Name` form.
