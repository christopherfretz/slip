# WP-064 — slip_exec: protocol 2, and the store's files of a transform

Implemented by `slip_exec::worker` (`Job.transform`, `Job.post`, `Post`,
`PostImage`, `PROTOCOL = 2`), `slip_exec::pool` (`JobExtra`, `run_with`)
and `slip_exec::store` (`Object`, blobs, rounds, transform run records,
the journal). This file fixes what `exec.md` §2, §2.2, §5.2, §5.5 and
§5.7 and `edits.md` §10.4 leave open, and corrects one word of §5.5.
Tests: `crates/slip_exec/tests/objects.rs`, `tests/worker.rs`
(`s5_2_protocol_2_*`, `s5_5_post_image_rejected`), `tests/pool.rs`
(`s5_2_job_extra_reaches_the_worker`,
`s5_2_run_with_refuses_what_the_task_refuses`,
`s5_2_ready_protocol_and_silent_exit_are_crashes`).

## 1. The messages (§5.2, §5.5)

- `Job`'s two fields follow `observer`, in the order of the table:
  `transform` as `opt<digest>`, `post` as `opt<Post>`. An `opt` tag other
  than 0 and 1 is `Malformed` at that byte.
- `PostImage`'s tag is a `uv`. Root maps that are not strictly ascending
  by `subject` (equal subjects included) are **`Malformed`** at the offset
  of the first map out of order, not `Invalid` as §5.5 says: the wire
  errors of `model.md` §2.1 have no `Invalid`, and a sorted list in
  another order is `Malformed` there. Neither path of a root map is
  checked to be absolute by the decoder.
- The encoder writes what it is given; a `Tree` out of order encodes and
  is refused by the decoder.

## 2. `run_with` (§5.7)

- The three combinations the task refuses (a map phase with `post`, a
  verify phase with `transform`, a verify phase without `post`) are
  returned as `PoolError::Store(StoreError::Invalid(<what>))` before
  anything else: no run record is read or published, no log, no worker.
  `run` is `run_with` with `JobExtra::default()`, so `run` with phase
  `verify` is refused the same way.
- Every job of the run carries the same `transform` and `post`, retries
  included.

## 3. The store (§2.2, edits.md §10.4)

- **Objects.** `publish_object` accepts a container of `object.kind()`
  whose frame passes `model.md` §5 rule 5 (magic, kind, version exactly 1,
  length, trailer, section framing); its sections are not decoded, since
  `slip_exec` does not know the types. Anything else is `Invalid` and
  nothing is written. The id returned is the trailer.
- **Publish once.** An object or a blob whose file already exists is not
  published again: the call returns its id and the file is left
  untouched (not replaced by rename, unlike the files of §2.1, which are
  not addressed by content). The directories `transforms/`, `edits/`,
  `overlays/`, `results/`, `blobs/` are made by the first publish into
  each; `open` does not make them, and a store without them is valid.
- **Blobs.** `blobs/<content digest>`, 64 lower-case hexadecimal digits
  and no extension. `read_blob` hashes the bytes it read; a mismatch is
  `Invalid` naming the file, its expected and its actual digest.
- **`find_object`** is `find_plan`'s rule over `<dir>/<64 hex>.<extension>`.
- **Rounds.** `next_round` reads the names of `shards/<plan>/` and
  `runs/<plan>/`. A round is taken by an entry `map.<r>` or `verify.<r>`
  of the first, or `transform.<r>.<ns>.run` of the second, `r` and `ns`
  canonical decimal; other names are ignored. A phase's run record does
  not take a round. The result is the least number not taken (so a plan
  with only `transform.2.*.run` gets 0).
- **Transform run records.** `publish_transform_run` accepts a `RUNT`
  container, version 1, whose section `run` (id 1) decodes, as
  `edits.md` §10.6 lays it out, as far as `started_unix_ns`; `plan`,
  `round` and `started_unix_ns` must be the ones given. The rest of the
  record is not read. Anything else is `Invalid`. Its path is
  `runs/<plan>/transform.<round>.<started_unix_ns>.run`, published as
  §2.1 publishes (a record of the same name is replaced).
- **`latest_run_of_round`**: among `runs/<plan>/<phase>.<round>.<ns>.run`
  with canonical decimal `round` and `ns` and the given round, the
  greatest `ns`; `None` if there is none; not validated. Neither it nor
  `latest_run` matches `transform.*` (the first component differs).
- **The journal.** `Store::open(_, Exclusive)` checks for `write.journal`
  (any kind of entry: `symlink_metadata`) after it has taken the lock and
  before it cleans stale `tmp/` entries; if it is there the store is
  dropped (releasing the lock) and the result is
  `UnfinishedWrite(<root>/write.journal)`. A shared open does not look.
  `open_for_recovery` is the exclusive open without that check (lock,
  stale cleaning, `Busy` as usual). No opener writes or removes the
  journal.
- **Display** of `UnfinishedWrite(p)`: `the store has an unfinished write
  of the working tree (<p>); run `slip apply --recover``.

## 4. The fake worker

`slip-fake-worker` echoes the protocol 2 fields into every shard it makes,
as counters present only with their field: `fake.transform` (first byte of
the id), `fake.post.declared` (first byte), `fake.post.image` (0 tree, 1
overlay), `fake.post.overlay` (first byte) or `fake.post.roots` (number of
root maps), `fake.post.pre`.
