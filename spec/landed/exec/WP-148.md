# WP-148 — slip_kiln at the new pin: working directory per run, written-refs option, split `>`, inputs read once, exact expression extents, thrown object

Implemented by `slip_kiln::parse`, `slip_kiln::lookups`,
`slip_kiln::ranges`, `slip_kiln::session`, `slip_script::driver`,
`slip_script::host`, and `slip_script::kiln_subject::calls` at Kiln pin
`60fb5ab9d`. This file records the rules and decisions of the seven items
of `docs/wp/WP-148.md` (items 1–5 and 7 implemented; item 6 proposal-only).
Spec updates were also folded into `spec/exec.md` §2/§5.2, `spec/model.md`
§8.4, `spec/api.md` §2.1/§2.5/§2.8/§5.4, `spec/edits.md` §2.2/§4.6, and
`spec/landed/api/WP-080.md`.

## 1. Working directory per run (Kiln WP-2121)

- `slip_kiln::parse::parse_observer_with` verifies that
  `observer.command.directory` exists and is a directory (`Err("cannot
  enter ...")` otherwise), resolves it via `kiln_source::WorkDir::at`,
  and passes `FrontEndOptions::working_directory = Some(work_dir_path)`
  with `FrontEndOptions::response_files = false` (Kiln WP-2411, fix round
  1). Turning `response_files` off ensures a parse never reads an `@file`
  response file that is absent from `shard.inputs` (`slip_cdb::normalise`
  already expands response files when building a plan). Both
  `not_modelled` and `slip_kiln::lookups`'s `driver` parse `line`
  verbatim (no `rsp::expand`), and `slip_kiln::lookups` resolves
  absent/duplicate search directories against `fe.sm.work_dir()` via
  `RealFs::in_dir`.
- `-working-directory` (`-working-directory=<dir>` and `-working-directory
  <dir>`) is refused by `slip_kiln::check::not_modelled` (fix round 1):
  otherwise a command line's `-working-directory` would shift Kiln's
  `fe.sm.work_dir()` away from `Command.directory`, breaking downstream
  lookup guards that resolve relative `Lookups` paths against
  `Command.directory`. Inside the front-end closure, `collect_inputs`
  resolves relative names against `fe.sm.work_dir().dir().unwrap_or(dir)`
  (which equals `Command.directory` since `-working-directory` is
  refused).
- No `std::env::set_current_dir` call remains anywhere in `crates/` (neither
  in library/binary code nor in tests, including `tests/support/oracle.rs`),
  and all process-wide parse serialization locks (`PARSE`, `LOCK`) were
  removed from tests.
- **Tests:** `crates/slip_kiln/tests/parse.rs`
  `s8_4_two_directories_concurrently` parses two observers in distinct
  directories concurrently across a barrier (with relative main files,
  relative `-I`, and relative `-include`), verifying both shards' inputs
  and that `std::env::current_dir()` does not change (passed 20 times in
  a row); `s6_2_working_directory_flag_is_refused` pins refusal of both
  `-working-directory=` and `-working-directory <dir>`;
  `parse::tests::s8_4_response_file_in_argv_is_not_expanded` pins
  `response_files = false`;
  `parse::tests::s8_4_directory_that_is_a_regular_file_is_refused` pins
  rejection of a regular file as `Command.directory`.
- **`--worker-jobs > 1` (`spec/exec.md` §5.2):** Per-run cwd removes the
  process-wide directory mutation that previously forced serial parses.
  `--worker-jobs 1` remains the default because the worker protocol is
  synchronous (one job in flight per worker), `peak_rss` attribution
  relies on `/proc/self/clear_refs` and allocator retention stays in RSS,
  stderr log splitting follows coordinator assignment, `slip_spelling`'s
  process-wide directory cache persists across jobs on case-folding
  volumes, `Loaded::run` is pinned to the compiling thread (`&mut self`),
  and per-observer process isolation limits crash/cap blast radius.

## 2. Inputs read once (WP-066 review F9)

- **Source-manager buffers (`FileOrigin::Disk`, `FileOrigin::Overlay`,
  loaded `FileOrigin::Lazy`):** `collect_inputs` computes size and BLAKE3
  directly from `SourceManager::original_bytes(file)` — never reading the
  file from disk again. Modifying a header on disk between the parse and
  `collect_inputs` still records the parsed bytes
  (`parse::tests::s8_4_inputs_buffer_mutated_before_collect_records_parsed_bytes`).
- **Consulted paths (`fe.consulted`):**
  - A `__has_include` hit is entered into `SourceManager` as a buffer when
    found, so it is already collected from `original_bytes`.
    `collect_inputs` (`parse.rs:878-883`) keeps a cross-check of
    `c.content` against `found[..buffers_end]`, but at Kiln `60fb5ab9d`
    that branch is **dead code**: `kiln_driver/src/front_end.rs:506-510,
    :519, :525` drops consulted events for any file the preprocessor
    entered and keeps only the first `Content` when a consulted path is
    read twice. The check is kept as defensive code that becomes live once
    Kiln reports every read.
  - For `#embed` (`ConsultedKind::Embed`) and `__has_embed`
    (`ConsultedKind::Probe`), Kiln retains only `Consulted::content`: size
    and a 128-bit FNV-1a digest (`kiln_driver/src/front_end.rs:234-261`),
    not raw bytes or BLAKE3.
  - When the path is overlaid, `collect_inputs` resolves the overlaid
    bytes from `overlaid_real` (canonical on-disk real paths resolved when
    building the overlay before the parse, falling back to
    `Overlay::resolve` for hard links), verifies them against `c.content`,
    and hashes those bytes. Replacing the underlying disk file in-place or
    by atomic rename (new inode) between parse and collect still records
    the overlaid bytes
    (`parse::tests::s8_4_inputs_overlaid_files_mutated_before_collect_record_overlaid_bytes`).
  - When the path is not overlaid, `read_consulted` reads the file once
    for BLAKE3 and checks `Content::of(&bytes) == seen`. Any mismatch fails
    closed (`Err("<path> changed during the parse: ...")`) rather than
    recording unparsed bytes
    (`parse::tests::s8_4_inputs_consulted_embed_mutated_before_collect_fails_closed`).
- **What lacks Kiln bytes or digest (corrected in fix round 1):**
  - A `__has_include` probe whose buffer was never loaded
    (`FileOrigin::Lazy` with no `original_bytes`, `Consulted::content ==
    None`): probes existence only, so a content edit between parse and
    collect can at most cause a conservative re-parse/mismatch, never mark
    an observer current for unparsed content; deletion fails closed
    (`cannot read`).
  - Response files (`@file`), which the original handback omitted: now
    closed by setting `FrontEndOptions::response_files = false` in
    `fe_options` (fix round 1), so `parse_observer_with` never reads any
    response file.
  - The second read of a path read twice in one parse (`#include` +
    `#embed`, or two `#embed`s of one file), which the original handback
    omitted: see §8.4 residuals below.
  - `#embed` / `__has_embed` itself carries only Kiln's 128-bit FNV-1a
    `Content`, not raw bytes or BLAKE3: see §8.4 residuals below.
  - (Additionally, a symlink retargeted between Kiln's open and
    `collect_inputs`'s `canonicalize` is unchanged from before WP-148
    because `SourceManager` stores names as opened, not canonical paths.)
- **§8.4 residuals (trusted base):**
  1. **Two reads of one file in a parse are not compared.** Kiln's
     `front_end::consulted` (`kiln_driver/src/front_end.rs:506-510, :519,
     :525`) drops consulted events for any file the preprocessor entered
     and keeps only the first `Content` when one consulted path is read
     twice. Thus `parse.rs:878-883` is dead code today, and a file modified
     between an `#include` and an `#embed` (or between two `#embed`s) of
     the same path in one parse is not detected until Kiln reports every
     read.
  2. **128-bit FNV-1a change detector on re-read `#embed` / `__has_embed`.**
     Until Kiln satisfies trusted-base requirement #3 below, the
     `verify_consulted_content` check on non-overlaid `#embed` /
     `__has_embed` files is a 128-bit FNV-1a change detector, not
     `spec/model.md` §3's cryptographic hash (BLAKE3). The collision risk
     is adversarial only; non-adversarial races are detected and fail
     closed.

## 3. The written-refs option (Kiln WP-2320)

- `fe_options` sets `FrontEndOptions::written_refs = options.written`,
  and `written_words` drops `-fkiln-dump-written-refs` (retaining only
  `-fkiln-decl-extents` because `FrontEndOptions` has no `decl_extents`
  switch at Kiln `60fb5ab9d`). No behaviour changes: shards are identical
  with and without `ParseOptions::written`.
- **Debug-build relative timings** (`crates/slip_kiln/tests/parse.rs`
  `measure_written_refs_cost`, 3 alternating pairs after warm-up, median
  ratio of `written: true` over `written: false`):
  - `resource/examples/swap_arguments.cpp` (166 files, 192,170 tokens):
    **1.108× (+10.8%)**
  - `kiln/tests/conformance/ext.gnu.builtins/overflow-constexpr.cpp`
    (1 file, 9,475 tokens): **1.115× (+11.5%)**
  - `crates/slip_digest/tests/equal/_/name-value-default-reach-large/a.cpp`
    (2 files, 20,234 tokens): **0.973× (-2.7%, within noise)**

## 4. Split `>` located (Kiln WP-2542)

- `slip_kiln::parse::Tokens` carries `&Ast::split_greaters`.
  `Tokens::token_end` calls `kiln_lex::token_end_split`, and
  `Tokens::is_token_start` accepts both a split `>` location and the
  immediately following remainder token in the same entry (`>` of `>>`,
  `=` of `>=`, `>=` or `=` of `>>=`).
- `slip_kiln::ranges::file_range_of_tokens` no longer refuses spans ending
  at a `>>`, `>=` or `>>=` token (`may_be_split` removed).
- **Tests (`crates/slip_kiln/tests/ranges.rs`):**
  - `s5_4_split_greater_all_three_forms` covers `>>`, `>=`, and `>>=`
    split by a template argument list close.
  - `s5_4_a_split_greater_ends_at_its_first_byte` (un-ignored) and
    `s5_4_test3_split_and_unsplit_greater_tokens` pin split vs unsplit
    behaviour.
  - `s5_4_test4_property_over_digest_pair_tests`: 3,212 pair-test
    directories, 86,255 expressions, 52,814 tier-0 + 18 tier-1 ranges
    checked, **0 failures**, **0 refused as possibly split `>`**.

## 5. Exact expression extents (Kiln WP-2327)

- `slip_script::kiln_subject::calls` replaces its hand-rolled extent
  table with `kiln_parse::ExprExtents` (re-exported via
  `slip_kiln::kiln::parse::ExprExtents`). Neither `slip_kiln::ranges` nor
  `slip_refactor` computes expression extents from AST nodes.
- **Cases where `ExprExtents` differs from the old table at this pin**
  (all previously `None`, now exact, each pinned in
  `crates/slip_script/tests/subject_calls.rs` and checked against clang 19
  by `item7_differential_against_clang` with 0 differences):
  1. `CXXNewExpr`: `new int(1)`, `new int(3) != nullptr`
     (`s6_6_rule3_the_extent_of_every_kind_of_the_table`,
     `s7_4_rule3_the_place_of_an_expression`)
  2. User-defined literal `CallExpr`: `1_km`
     (`s6_6_rule3_the_extent_of_every_kind_of_the_table`)
  3. `CXXNoexceptExpr`: `noexcept(v)`
     (`s6_6_rule3_the_extent_of_every_kind_of_the_table`)
  4. `DeclRefExpr` with explicit template arguments: `t<int>`
     (`s6_6_rule4_null_where_the_last_token_is_unknown`)
  5. Operator function named as a function: `&S::operator+`
     (`s6_6_rule4_null_where_the_last_token_is_unknown`)
  6. Member variable template with template arguments (Kiln WP-2724):
     `d.twice<7>`, `p->twice<2>`, `V::twice<3>`
     (`s6_6_rule4_a_member_variable_template`)
  7. `decltype` qualifier chains (both expressions and callees):
     `decltype(o)::x`, `decltype(o)::sx`, `decltype(o)::B::z`,
     `decltype(o)::B::sz(1)`, `decltype(o)::sz(2)`
     (`s6_6_rule4_null_where_the_last_token_is_unknown`,
     `s6_6_rule3_a_callee_after_decltype_and_a_conversion_in_parentheses`)
  8. Global-qualified and `decltype`-typed functional casts / temporary
     constructions: `::S(1)`, `decltype(x)(2)`, `::W<int>(2)`
     (`s6_6_rule4_null_where_the_last_token_is_unknown`,
     `s6_6_rule3_a_construction_named_by_a_template`)
  9. Single-element braced copy/converting `CXXConstructExpr` (Kiln
     WP-2723): `h({3})`, `g({x})`, `g({x,})`, `g2(1, {x}, 2)`
     (`s6_7_rule5_implicit_conversions_are_skipped`,
     `s6_6_rule4_an_argument_is_all_of_what_is_written`,
     `s6_6_rule4_an_argument_through_a_macro_is_all_of_the_expanded_argument`).
     Reference binding `f({x})` (`const O&`) still has no AST node for
     `{}` (`kiln_sema/src/init.rs:2236`) and stays `None` via the
     expanded-token argument guard.
  10. Rewritten comparisons `CXXRewrittenBinaryOperator` (reversed
      `1 == s` and synthesized `s != 1`)
      (`s6_6_rule3_a_rewritten_comparison_has_its_written_extent`,
      `wp084_point7_out_of_order_uses_written_extent`)
- **Explicit-object-parameter member call (`s.f(2)`):** Kiln's
  `WrittenExtents::written_first` (`kiln_ast/src/expr_extent.rs:238`)
  takes `CallExpr`'s `first_child` (the callee `f`) instead of
  `call_args[0]` (`s`). `calls::expr_tokens` adjusts `first` to the
  object's written first token when `explicit_object(e) == Some(Object::Before)`
  (`s6_7_rule1_explicit_object_parameter`).
- **Merged test edits:** no merged API, example, or rename test's edit
  moved (`tests/api.rs` 176 passed / 3 xfailed; `tests/examples.rs` 3/3
  passed; all `slip_refactor` and `slip_cli` tests unchanged).

## 6. Any-thread guard (Kiln WP-2410) — proposal only

- Kiln WP-2410 checks the *running* thread's `StackGuard` and restores
  Kiln's `stack_exhausted` flag on exit (`Sema::guard_enter_thread` /
  `guard_leave_thread`), eliminating the WP-080 cross-thread hazard
  (`spec/landed/api/WP-080.md` hazard 1 dropped; `kn1_…` in
  `crates/slip_kiln/tests/session.rs` passes).
- What `spec/api.md` §2.5 rule 5 still protects: ensuring the running
  thread actually has `STACK` (256 MiB) and a matching `StackGuard`
  installed (a subject front-end thread may have a different
  `-fkiln-stack-size=`). `Session::run(&mut self, ...)` already enforces
  exclusive single-run access.
- `slip_script::driver`'s threading was not changed (proposal in
  `docs/wp/WP-148.md` awaiting supervisor decision).

## 7. The thrown object (Kiln WP-2480)

- `slip_kiln::session` exposes `Class` (a class/struct entity identified
  by first `DeclId` and session id), `Session::class(namespaces, name,
  in_dir)`, and `ThrownRecord { class, bases, members }` on
  `RunFailure::Uncaught`, decoding both direct bases (`FieldKind::Base`)
  and virtual bases (`virtual_bases`) and integral/enum members from
  Kiln's frozen `RunValue`.
- `slip_script::driver` looks up `slip::v0::error` under `<resource>/include`
  once at load time, walks `ThrownRecord` in `slip_error_ordinal` to
  extract its `__n` ordinal when all matching `slip::v0::error` subobjects
  agree, and fetches the exact failure record via `Host::failure(ord)`.
- **Tests:** all four `m1_*` tests in `crates/slip_script/tests/budgets.rs`
  (`m1_rethrowing_an_older_slip_error_reports_its_refusal`,
  `m1_an_error_of_another_namespace_has_no_refusal`,
  `m1_a_type_derived_from_slip_error_carries_its_refusal`, and
  `m1_a_class_with_its_own_dunder_n_member_is_not_slip_error`) are enabled
  and passing; `tests/api/format/{failed,rethrow}` (renamed from `xfail`
  in fix round 1 because it no longer xfails) updated to the new message
  format `"an uncaught slip::error: <message> (<errc>)"`.

## For Kiln

1. **`FrontEndOptions::decl_extents`** (`kiln_driver/src/front_end.rs:81`):
   `FrontEndOptions` has `written_refs` (WP-2320) but no `decl_extents`
   switch, so Slip still injects `-fkiln-decl-extents` into the command
   line in `parse.rs::written_words`.
2. **Explicit-object-parameter member call extent**
   (`kiln_ast/src/expr_extent.rs:238`): `WrittenExtents::written_first`
   descends into `CallExpr`'s `first_child` (callee `f`) rather than
   `call_args[0]` (`s`) for `struct S { int f(this S, int); }; int g(S s)
   { return s.f(2); }`, returning `f(2)` instead of `s.f(2)`. Pinned by
   `crates/slip_script/tests/subject_calls.rs::kiln_hole_explicit_object_call_written_extent_starts_at_callee`
   so it fails as soon as Kiln fixes it.
3. **Trusted-base requirement — `Consulted` bytes or BLAKE3 (and every
   read reported)** (`kiln_pp/src/resolver.rs:457`,
   `kiln_driver/src/front_end.rs:234-261, :506-525`): `Consulted` must
   carry the bytes Kiln already holds (`kiln_pp/src/resolver.rs:457` passes
   `bytes: &all` to the observer), or their BLAKE3 digest (`spec/model.md`
   §3), and report every read rather than dropping `#embed` of entered
   files or keeping only the first `Content` of a path read twice. Until
   then Slip's non-overlaid `#embed` / `__has_embed` path re-reads the file
   for BLAKE3 behind a 128-bit FNV-1a change detector (§8.4 residuals
   above).
