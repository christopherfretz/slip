# WP-012 — slip_cli: plan, parse, dump

What `slip` (`crates/slip_cli`) does where `spec/exec.md` §8 leaves the
shape open. Normative until folded into `spec/exec.md`. Builds on
`spec/landed/exec/WP-004.md`, `WP-008.md` and `WP-009.md`, whose interfaces
are unchanged. Tests: `crates/slip_cli/tests/args.rs` (the command line,
pure) and `crates/slip_cli/tests/cli.rs` (the executable).

## Interface

```rust
// lib.rs
pub mod args; pub mod commands; pub mod worker;
pub mod status { pub const OK: u8 = 0; FINDINGS = 1; USAGE = 2; INPUT = 3; INTERNAL = 70; }
pub fn version_line() -> String;                 // "slip <v> (kiln <v>)"
pub fn run(args: &[OsString], out: &mut dyn Write, err: &mut dyn Write) -> ExitCode;

// args.rs
pub const USAGE: &str; pub const DEFAULT_STORE: &str /* ".slip" */;
pub const DEFAULT_WORKER_JOBS: u64 /* 1 */; pub const DEFAULT_WORKER_STACK: u64 /* 1 GiB */;
pub enum Invocation { Version, Plan(PlanArgs), Parse(ParseArgs), Dump { file: PathBuf }, Worker(WorkerArgs), Panic }
pub struct Db { pub name: Option<String>, pub path: PathBuf }
pub struct PlanArgs { pub dbs: Vec<Db>, pub store: PathBuf, pub jobs: Option<usize> }
pub enum PlanSource { Plan(OsString), Db(Vec<Db>) }
pub struct ParseArgs { pub source: PlanSource, pub store: PathBuf, pub jobs: Option<usize>,
                       pub only: Vec<Vec<u8>>, pub limit: Option<u64>, pub memory: Option<u64>,
                       pub observer_memory: Option<u64>, pub observer_timeout: Option<u64>,
                       pub estimate_base: Option<u64>, pub estimate_per_byte: Option<u64>,
                       pub worker_jobs: u64, pub worker_stack: u64 }

pub struct UsageError(pub String);
pub fn parse(args: &[OsString]) -> Result<Invocation, UsageError>;

// commands.rs

```

Additions to the brief's interface: `Invocation::Panic` (the hidden
`slip __panic`), the argument structs, `status`, `version_line`,
`commands::dispatch`, `worker::ParseTask` and `worker::main`.

## The command line

- **Options** are those of §8, each command accepting only its own;
  `__worker` accepts `--worker-jobs` and `--worker-stack`; `dump` accepts
  none (`dump -- <file>` reads a file whose name starts with `-`). An
  argument that starts with `-` (other than `-` and `--`) in option
  position is an option; an option's value is taken whatever it starts
  with. A positional argument is refused except `dump`'s one file. After
  `--` everything is positional. `-j=4` has the value `=4` (malformed).
- **Numbers** are decimal digits only (no sign, no white space, leading
  zeros allowed), at most `u64::MAX`. **Sizes** are a number and an
  optional upper-case suffix `K`, `M`, `G`, `T`; a product above
  `u64::MAX` is malformed. Lower-case suffixes are malformed.
- **Ranges.** `-j`, `--worker-jobs`, `--worker-stack` and
  `--observer-memory` must be at least 1; `--limit`, `--memory`,
  `--observer-timeout`, `--estimate-base` and `--estimate-per-byte` may be 0.
- **Database names.** With several `--db`, an unnamed one or a name given
  twice is a usage error, reported before anything is read. A single
  unnamed database is named `default`.
- **Usage error output**: `slip: <message>` and then the usage text, on
  standard error. No command, and `--help`, `-h` or `--version` with an
  argument, are usage errors.

## Output and status

- **`--version`** prints `slip <version> (kiln <version>)`. The same
  string is the `tool` of the worker's `Ready`.
- **Input errors** are one line, `slip: <what>: <why>`: a store error
  names the store (the `Unrecognised` and `Io` errors already start with a
  path and are printed as they are); a database error is
  `slip: <path as given>: <detail>` (`PlanError::Database`); a plan or
  container file that cannot be read or is invalid is
  `slip: <path>: <error>`; `--plan` prefixes are
  `slip: plan <prefix>: no plan in the store <root> has an id starting with it`
  and `slip: plan <prefix>: <n> plans have an id starting with it: <ids>`.
  `pool::run` returning `PoolError::Store` or `PoolError::Io` is also
  status 3 (`slip: parse: <error>` for the latter).
- **`--plan <x>`** is a prefix when it is 4 to 64 hexadecimal digits in
  either case (it is lower-cased); a plan file is published to the store
  with `Store::publish_plan`, which validates it again.
- **`wall`** is the run record's `wall_ns`, truncated to milliseconds.
- **`peak_rss`** is the largest `peak_rss` of the run record's jobs (the
  first such job on a tie) and its observer's main file; paths are written
  as their bytes. Omitted when every job's is 0, or there is no job.
- **The lines for shards that are not `ok`** (standard error, plan order)
  are written after the summary on standard output. Each reads the shard
  from the store; a missing shard is `slip: failed: <main>: no shard in the
  store` (it cannot happen after a run that completed), an unreadable one
  is status 3.
- **The empty selection's warning**:
  `slip: warning: the selection keeps none of the plan's <n> observer(s); the phase runs over nothing`.
  The unknown-memory warning:
  `slip: warning: the memory available is unknown; memory admission and caps are off (as with --memory 0)`.
- **Status 1 for `parse`** also when the number of `ok` shards counted by
  the pool differs from the number selected.

## Exit 70

`run` (every command but `__worker`) installs, once per process, a panic
hook that prints nothing and records the first panic's
`<message> (<file>:<line>)`. `run` wraps the command in `catch_unwind`; on
a panic it calls `process::kill_live_children_now` and
`jobserver::release_all`, then prints `slip: internal error: <that>` and
returns 70. A panic on a thread that does not reach `run` (none is known)
prints nothing. `signals::install`, which `parse` calls later, wraps this
hook. The worker keeps Rust's default hook: its report goes to the
attempt's log.

## `plan` and `parse`

- **Hashing threads.** `Pool::from_env()` (with `-j` if given), then
  `try_acquire` until it returns none or `jobs()` tokens are held; the
  plan is built on that many threads and the tokens are dropped when the
  build returns, before the plan is published.
- **`parse`** opens the store exclusively before reading any database or
  plan, then installs the signal handling (`signals::install`) at once, so
  an interruption while the plan is built also removes the lock. The
  callback removes the dead workers' `tmp/` entries (below) and then runs
  `pool::cleanup_on_signal`. `PoolError::Cancelled` returns through
  `signals::finish`, printing nothing more.
- **Dead workers' scratch directories.** After `pool::run` returns, and in
  the signal callback, while the lock is held, `parse` removes every
  `tmp/` entry named `<pid>.…` (a canonical decimal pid) whose process no
  longer exists, directories recursively, as an exclusive open does
  (§2 "Cleaning"); only where `/proc/self` exists. A worker killed by a
  cap, a time limit or a signal leaves its `tmp/<pid>.d` otherwise.
- **The pool.** `Options::new(pool.jobs(), config)`; `tool_slip`,
  `tool_kiln` the plan's; `worker_jobs` from `--worker-jobs`;
  `observer_timeout` `Some(DEFAULT_OBSERVER_TIMEOUT)` unless
  `--observer-timeout` is given (0: `None`). `admission::Config::with_budget(B)`
  with `observer_memory`, `worker_stack`, and the two estimate parameters
  when given. The worker command is `current_exe()` with
  `__worker --worker-jobs <n> --worker-stack <bytes>` (both always passed)
  and `env_remove` every coordinator variable whose name starts with
  `KILN_`. The sampler is `ProcSampler`.

## The worker

- `slip __worker` is `serve` with `tool` = `version_line()`,
  `stack_bytes` = `--worker-stack`, `max_jobs` = `--worker-jobs`, over
  unlocked standard input and output. A `serve` error is
  `slip __worker: <error>` on standard error and status 1.
- **The parse task** opens the job's store (`Job::store_path`, absolute)
  shared on its first job and keeps it, with its `Store::scratch_dir`,
  for its lifetime; a job naming another store replaces both. The scratch
  directory is `ParseOptions::scratch`. The store's `Drop` (at the end of
  `serve`) removes the scratch directory.

## Stack guard

`slip_kiln::parse_observer` installs Kiln's stack guard
(`kiln_sema::stack_guard::StackGuard::install`, with the thread's stack
size) first thing on the front end's thread, as the `kiln` executable's
compile thread does: nesting deeper than the stack ends in Kiln's fatal
diagnostic, a `diagnosed` shard, instead of aborting the worker.
`slip_kiln` now depends on `kiln_sema` (allowed by the `kiln-boundary`
lint). Test: `crates/slip_kiln/tests/parse.rs`
`landed_deep_nesting_is_diagnosed_not_a_crash`.

## Streams

`main` passes a locked standard output and an *unlocked* standard error:
the signal thread, the jobserver and the pool write warnings to standard
error from other threads, and a lock held by the main thread would block
them (the signal path for up to its 15 s bound).
