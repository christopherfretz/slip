# WP-047 — the pair runners: derived units named exactly, and a pool

Decided by work package WP-047. It adds to `spec/digest.md` §14 and
`spec/digest-kinds.md` §1.5 (what the pair tests show) and to
`spec/harness.md` §6.1 (the runner). The code is
`crates/slip_digest/tests/common/mod.rs` (`expect`, `exact_derived`,
`derived_differences`, `pool_size`, `pool_map`, `run_dirs`, `run_all`)
and `common/pairs.rs` (the judgments of `differ`, `demand`, `equal`).

## Lines of `expect.txt`

1. `changed`, `added`, `removed` `<name>`: as before, over declared and
   `tu` units.
2. `derived-added <name>` holds when side B has a derived unit under a
   key of the name and side A has none under it; `derived-removed
   <name>` the other way round. Either line fails the test when it does
   not hold, with or without `exact derived`.
3. `derived-changed <name>` holds, without `exact derived`, when the
   derived units under a key of the name differ in any way, presence
   included (its meaning before WP-047, kept so that no open branch's
   test changes meaning).
4. `exact derived`, a directive written alone on a line, at most once (a
   second is an error of the test): the derived keys that differ between
   the sides are exactly the keys the `derived-*` lines name, each in the
   way its line says, `derived-changed` meaning both sides have a derived
   unit under the key and they differ. Without the directive a derived
   unit no line names is free. `common::expect` does not return the
   directive; `common::exact_derived` says whether it is written.
5. A name is `common::Digested::name` of the key (the first of its units,
   from side A when A has the key), as in the other lines. Lines are
   compared by name only: two derived keys of one name that differ in the
   same way are one line, and a line names every key of its name. A test
   that needs to tell two such keys apart cannot; none does today.

## What each runner accepts

- `differ`: every line but `indeterminate`.
- `demand`: `added` and `derived-added` lines and the directive. Every
  `derived-added` line holds; under `exact derived` the derived
  differences are exactly the `derived-added` lines, so a derived unit
  only B has that no line names, or one only A has, fails. A derived unit
  both sides have that differs fails as every unit both have does.
- `equal` and `indeterminate`: no `derived-*` line and no directive (an
  error of the test, naming the line). In an `equal` test a unit only one
  side has, declared or derived, fails the test ("only in A: <name>",
  "only in B: <name>"): the derived groups are part of the `Digests`
  compared. That was so before WP-047 and no directory needed an
  `expect.txt` for it.

## The report of unnamed derived differences

With `SLIP_DIGEST_DERIVED=report` the `differ` runner prints, for each
passing directory, `<dir>: unnamed <line>` for each derived difference
(as `derived_differences` gives it) that no line of the directory names
exactly; one that only a `derived-changed` line covers (an appearance or
a disappearance) ends in ` (written derived-changed)`. It then prints the
count by kind and the twenty directories with the most. The report fails
nothing.

## The pool

1. `common::run_all` runs its directories on a pool of threads and
   reports what it reported before, in directory order: the
   `skipped (pending)` lines, the count line, and the failures joined in
   directory order in the panic. The report does not depend on the
   pool's size or the order the threads finish.
2. The pool's size is `SLIP_TEST_THREADS` when set — a positive decimal
   number, anything else an error naming the variable
   (`SLIP_TEST_THREADS=<value>: not a positive number`) — otherwise the
   smaller of 4 and `std::thread::available_parallelism()`. A test takes
   no token from the jobserver.
3. A panic in one directory's work is that directory's failure,
   `<dir>: panicked: <text>`; the other directories still run.
4. Nothing is shared between directories but the support files
   (`tests/support/`), read once. Each pool thread has an 8 MiB stack;
   the parse and the walk keep their own threads, so a pool of `n` has
   at most `n` parses and `n` walks at a time.
5. `SLIP_DIGEST_TIMES=1` prints, after the report, the twenty slowest
   directories of the runner with their milliseconds.
6. The determinism test walks its directories on the same pool, in both
   processes; the two walks of one directory run one after the other.
   The tables test parses nothing and is unchanged.
