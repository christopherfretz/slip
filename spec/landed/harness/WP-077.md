# WP-077 — the transform runner and its oracles

Decided by work package WP-077. `spec/harness.md` §6.2 to §6.4 say what a
transform test is, how it is run and what its oracles check; this file
holds the decisions behind the runner and its mechanics where §6 is
silent. The code is `xtask/src/transform.rs` (discovery, the options, the
outcomes, the summary) and `xtask/src/transform/{test_file.rs, tree.rs,
run.rs, oracles.rs, mutate.rs}`; the stand-in executable its tests use is
`xtask/src/bin/fake-slip.rs`; the tests are `xtask/tests/transform.rs`.
Where §6 was silent the stricter reading was taken: a test that cannot be
judged is an `ERROR`, never a pass.

## The command lines

Every `slip` command line is built in one module, `run::cmdline`, so that
the day a command's usage is fixed differently only it changes. Each
`slip` runs with the tree (below) as its current directory, standard
input closed, in a process group of its own, and the test's `timeout`
(below).

**Assumed, not yet landed.** `crates/slip_cli` does not yet run a
transform, so what follows is what the runner assumes of it, from
`spec/exec.md` §8 and `spec/edits.md` §10; the day it lands differently,
`run::cmdline` and `run::Lines` change and the fixture tests say where:

- `check` is invoked as in item 2 below and prints the lines of
  `spec/edits.md` §10.5 (`plan`, `round`, `edits`, `declared`, `overlay`,
  `result`, `state`), the result's `state` last, and writes its result
  record to `results/<id>.rslt` of the store it is given;
- `check --edits` takes a path as well as an id: a mutated set is
  published in the run's store (`Store::publish_object`) and given by its
  path there, `edits/<id>.edts`;
- a rename's inverse is the rename of item 3;
- a run's standard output holds only the plan lines of `spec/exec.md`
  §8.1 and the lines of §10.5, no `wall` or `peak_rss` line: `expect.txt`
  compares every line, and a timing line would differ on every run.

1. **The run** (§6.3 step 2, as written there):
   `<run words> --db <work>/cdb.json --owned <tree>/<p>… --readonly
   <tree>/<p>… --store <work>/store --relative-to <tree> --write -j 2
   --allow-<v>…`, `owned` and `readonly` in the order of `test.txt`,
   `allow` in the order `residue`, `unparsed`, `partial`, `errors`. The
   words of `run` are split at single spaces (no quoting: a name holds no
   space). `run` may not hold an option the runner gives (`--db`,
   `--plan`, `--owned`, `--readonly`, `--store`, `--relative-to`,
   `--write`, `--patch`, `-j…`, `--allow-…`), and its first word must be
   the test's area.
2. **Check** (`verify` and `mutation`; `spec/exec.md` §8,
   `spec/edits.md` §10.2): `check --plan <plan id> --round <n> --edits
   <edit set> [--declared <declared id>] --store <store> -j 2
   [--allow-unparsed]`. The plan, round, edit set and declared ids are
   those the run printed. `verify` gives the run's own edit set id and no
   `--declared` (check then compares against the run's own declared
   changes); `mutation` gives the mutated container's path in the store
   and `--declared` with the original's id, as §6.4 says. Check has no
   `--db` and no `--relative-to` in exec §8, so neither is given;
   `--allow-unparsed` is given when the test allows it, the only `allow`
   check takes.
3. **The inverse** (`back`): defined only for `rename` with exactly one
   `--from <name>` and one `--to <identifier>` (no `--opt=value` form, a
   `--to` without `::`): the last component of `--from` and the `--to`
   are swapped, `rename --from a::f --to g` becoming `rename --from a::g
   --to f`; every other word is kept. A written tree whose run has no
   inverse is an `ERROR` ("no inverse") unless the test says
   `oracle: no-back <reason>`.
4. **The build of `slip`**: `cargo build -p slip_cli`, only when at least
   one test is selected and `--slip` is not given; the executable is
   `<target>/debug/slip`.

## The work directory

1. A test's work directory is `<target>/transform/<area>/<name>`, where
   `<target>` is `$CARGO_TARGET_DIR` (relative to the workspace root if
   relative) or `target`. It holds `tree/` (where every `slip` runs),
   `store/`, `cdb.json` (the database the run is given, `@ROOT@` replaced
   by the tree's canonical path), `clang/` (the clang oracle's dependency
   files), and `determinism/store`, `back/store` — `run::WORK_ENTRIES`.
2. It is removed and made again by its explicit path, and only after a
   check: absolute, no `.` or `..` component, at least four components,
   the last three `transform`, `<area>`, `<name>`, and neither inside the
   test's directory nor holding it. Any other path is an `ERROR` and
   nothing is removed.
3. It is removed after `PASS` and `XFAIL`, and kept, with
   `  kept <path>` printed under the outcome's line, for every other
   outcome. A malformed `test.txt` is an `ERROR` before any directory is
   made.
4. The oracles that check the pre-image (`verify`, `mutation`) need the
   tree at the same path in its pre-image state, because ids include the
   tree's path and check reads the pre-image. So the oracles run in a
   fixed order: `clang` on the written tree, `back` on it, then the tree
   is copied again from `pre/` (removed by its path, copied), then
   `verify`, `mutation`, `determinism` (which writes the tree again; its
   exit status, ids, output and written tree are compared with the run's).
5. **Surroundings** (§6.3 step 2): after every invocation the work
   directory holds only `WORK_ENTRIES`, `back/` and `determinism/` only
   `store`, and the test's directory (read before the run, bytes and
   modes) is unchanged; otherwise a `FAIL` naming the stray path or the
   first difference. A store's own temporary files are inside `store/`
   and not looked at.
6. **The timeout**: `timeout: <s>` (default 600). The child runs in its
   own process group (`process_group(0)`); the invocation is done when
   the child has ended and both pipes are closed. At the deadline the
   group is killed with `kill -KILL -- -<pgid>`, the program being
   `/bin/kill` or `/usr/bin/kill` when present, else `kill` on `PATH`
   (`run::kill_program`: the run's `PATH` may lack it, and a shell's
   built-in may not take a group; `xtask` has no `unsafe`, so no direct
   `kill(2)`). The outcome is `KILLED`, "did not end within <s> s; its
   process group was killed". A child ended by a signal is `KILLED` too.

## Reading and comparing a run

1. The ids are read from the output lines of `spec/edits.md` §10.5: the
   first `plan`, `transform`, `round`, `edits`, `declared`, `overlay` and
   `result` line, and the state from the last `state` line. For
   `declared` and `overlay` the id ends at its `:`.
2. **Normalisation** (§6.3 step 5): the store's path is replaced by
   `@STORE@` (§6 is silent; the store is beside the tree, not in it, and
   its path is printed by the overlay lines), then the tree's path by
   `@ROOT@` — the longer of the two first — then every maximal run of
   exactly 64 `[0-9a-f]` by `<id>` (a run of 63 or 65 is kept).
3. **Structure** (`run::check_output`, §6.3 step 3): each id word at most
   once; `state` only right after `edits` (`accepted`/`refused`) or right
   after `result` (a state of edits §8.5), the result's the last `state`
   line; no `result` line from a `usage`/`input` run. A run expected to
   end in a state that prints no `result` line is not checked for
   structure: it is the state's difference below, with standard error.
4. **The store's records** (`run::read_record`, §6.3 step 4), when the
   run printed a `result` line: the result record is read and validated
   (`TransformResult::from_bytes`, edits §10.4); its state is the printed
   one; its `edits`, `declared` and `overlay` are the printed ids and its
   plan, round and transform the printed ones where printed; the edit set
   (`edits/<id>.edts`), the declared changes (`declared/<id>.decl`) and
   the overlay (`overlays/<id>.ovly`) are present, valid, and have the
   content id they are filed under; the overlay is the edit set's; the
   record's `allow_unparsed` is the test's; no `write.journal` is left.
   Each failure is a `FAIL` beginning `store:`.
5. **Permission** (`run::permitted`): `slip_verify::conclude::permits`
   over the result record, its edit set and the test's `allow residue`,
   `allow errors` and `allow partial` (the three of
   `conclude::Allow`; `allow unparsed` reaches only the command lines). No record, no permission. This
   is why `xtask` depends on `slip_verify` (`spec/harness.md` §1): the
   rule has one copy. `test.txt`'s static "may write" (the expected state
   and `allow`) decides only what the test must hold (`post/` or `post:
   none`) and whether the clang oracle checks the pre-image.
6. Differences, each printed as its first: `exit status <x>, expected
   <y>`; `state <x>, expected <y>` (a run that prints no `result` line
   where the state needs one: "the run printed no result line" with its
   standard error); ``output line <n>: expected `<x>`, got `<y>` `` (`the
   end` past the last line; a missing final newline is its own
   difference); `tree: file <p> differs (first at byte <k>)`, `file <p>
   mode <x>, expected <y>` (octal, the permission bits), `<kind> <p>
   added`, `<kind> <p> missing`, `<p> is a <kind>, expected a <kind>`
   (kinds: file, directory, symbolic link, other), in byte order of
   paths; a directory is an entry, so an empty directory added or lost
   is a difference. A tree written when the result does not permit it
   says so, with its state. All differences found are joined with `; `
   into one `FAIL`.
7. The written tree is read without following symbolic links: a link or
   another kind of file the run made is an entry that differs. `pre/`
   and `post/` are read as regular files and directories only (a link
   there, or a name that is not UTF-8, is an `ERROR` of the test).

## `test.txt`

Stricter than §6.2, each an error naming the line (`test.txt:<n>:`):
a line that is not `<name>: <value>`, an unknown directive, `run`,
`state`, `exit`, `std`, `args`, `tu` or `xfail` given twice, `exit`
outside 0 to 255, `spec` not of the form `<name> §n(.n)*`, a `tu`,
`owned` or `readonly` path that is absolute, has `.` or `..`, does not
exist in `pre/`, or is given twice, `oracle: no-<name>` without a
reason or naming no oracle, an entry of the directory other than
`test.txt`, `pre/`, `post/`, `expect.txt`, `cdb.json`, a directory not
named `<area>/<name>` in word characters, `post` with a value other
than `none` or given twice, `timeout` not an integer from 1 to 86400 or
given twice, a symbolic link anywhere in the test. A missing
`expect.txt` is an `ERROR` unless `--bless` is given. A test that may
write needs a non-empty `post/` or `post: none`, not both; one that may
not write has neither (§6.2). A `post/` file equal to its `pre/` file
compares the mode too, so a mode change alone is a `post/` file. The
default `tu` compares `.cpp` as bytes (`B.cpp` is a main file, `x.CPP`
is not). With `cdb.json`, `@ROOT@` is replaced by the tree's path made
JSON-safe; a tree path that is not UTF-8 or needs escaping is an
`ERROR`. "Sources are self-contained" is the test writer's rule; the
runner does not check it (the clang oracle runs without system headers
only if the test says so in `args`).

## Outcomes, the summary, the gate

1. `Outcome` adds `Killed(String)` to the interface of the WP: a `slip`
   ended by a signal or by its timeout is `KILLED`, which fails the gate
   and is never turned into `XFAIL` by `xfail`. The WP's `Skip` is
   removed: nothing produced it, and a transform test has no
   capability-dependent whole-test skip (`spec/harness.md` §6.2). What a
   host lacks shows as an oracle skipped. With `SLIP_REQUIRE_ALL=1` a
   test that passes with the clang oracle skipped for want of a compiler
   (not `--no-clang`) is an `ERROR`.
2. **Notes**: `Report` carries one `Note { oracle, off, reason }` per
   oracle that did not run: `off` for `oracle: no-<x>`, else skipped
   with its reason (`run_all`: "the tree was not written", "no compiler
   (none found, or --no-clang)", "the result is <state>", "the run has
   no result"). The determinism oracle always runs.
3. `xfail`: a test that fails is `XFAIL`; one that passes is `XPASS`
   (fails the gate); an `ERROR` or `KILLED` stays as it is.
4. One line per outcome that is not `PASS`: `<TAG> <area>/<name>:
   <message>` (`XFAIL`/`XPASS`: `xfail: <reason>`), then
   `transform: <n> passed, <n> failed` followed by `<n> xfail`,
   `<n> xpass`, `<n> error`, `<n> killed` for each that occurred, then
   `oracles: <n> off, <n> skipped (--verbose names them)` if any note was
   made, then, if any clang oracle was skipped, `clang oracle
   skipped: <n> (--no-clang)` or `clang oracle skipped: <n> (no compiler:
   $SLIP_CLANG, clang++-19 and clang++ not found)`. With `--verbose`, each
   note is printed before the summary, `  <area>/<name>: oracle <name>
   off|skipped: <reason>`, tests in order. Exit status 1 if the gate
   fails.
5. `--only` that selects no test prints `transform: --only <a> --only
   <b>… matches no test` and fails, before anything is built. Discovery
   fails on a symbolic link among the areas or tests ("a symbolic link,
   not a test or an area directory") and on a file there ("not a
   directory (tests are tests/transform/<area>/<name>/)"); an empty area
   is allowed.
6. Tests run on threads up to `-j` (default: the jobserver's size), each
   holding one token for the whole test; its `slip` runs with `-j 2`
   (`-j 1` for `determinism`) and takes its own.

## The clang oracle

`$SLIP_CLANG` if set and not empty, else `clang++-19`, else `clang++`,
each looked up on `PATH`. Each command of the database is run with its
first word replaced by the compiler and `-fsyntax-only` appended, in the
entry's directory. On the pre-image it runs before the run, when the
test may write — failure is the `ERROR` "the pre-image is not accepted
by clang"; on the written tree it runs when the tree was written —
failure is a `FAIL`. On the written tree each command also gets `-MD -MF
<work>/clang/<n>.d -MT dep`; the dependency files are read
(`oracles::parse_depfile`: `\`-continued lines, `\ ` an escaped space,
paths resolved against the command's directory), and a file the run
changed that no command read is a `FAIL`, "post-image not compiled:
<p>" (a header no main file includes would otherwise pass unchecked).
`--no-clang` turns it off; a skip, for either reason, is counted.

## Bless

`--bless` runs the test; the output's structure is checked first (a
`FAIL` before anything is written). It then refuses (a `FAIL`, "cannot
bless: …") when the exit status or the state differ, when the store's
records do not agree with the output, when the written tree adds or
loses an entry or changes one's kind (`post/` cannot hold it, §6.2),
when the tree was written and the result does not permit it, when the
test says `post: none` and the run wrote, and when the test may write,
the run wrote nothing and the test does not say `post: none`.
Otherwise it writes `expect.txt` (the normalised output) and the `post/`
files that differ from `pre/` in bytes or mode (with their mode),
removes stale `post/` files and empty directories, and prints `bless:
<path>` for each.

**A consequence**: since a test that may write must hold `post/` or
`post: none` before it parses, a new such test is written with a
placeholder (`post: none`, or a guessed `post/` file) and then blessed;
a bless that finds the other is refused and says which to write. The oracles still run after a bless. An
`ERROR` is never blessed; an `xfail` test is blessed like any other.
`test.txt` is never written.

## Mutation

1. The oracle runs only when the result record's state is `verified` or
   `verified_with_residue` (§6.4), with the edit set read with the record
   (`run::read_record`); otherwise it is skipped and noted. A valid
   result of those states names its declared changes and an accepted set
   (edits §10.4), so the oracle's two checks of that are unreachable from
   a sound store and kept as `FAIL`s of the runner. A mutated set is validated
   as `EDTS` (an invalid one is an `ERROR` of the runner) and published
   with the store's rule (temporary name, then rename).
2. **Drop** `i`: groups are repaired (the index removed, later ones
   shifted, a group left with fewer than two members dropped), `in_force`
   recomputed, and files that no record names any longer pruned, every
   file index renumbered. Dropping the only edit leaves a set that cannot
   be accepted: it is made `refused` (with a `no_edit` refusal if it had
   none), and its check must end `refused`.
3. **Add**: the `kept` ranges are taken in order, passing over one where
   an edit cannot stand (empty, equal to or crossing an edit, crossing a
   copied range), up to four. The new edit has the first edit's pieces,
   subjects, tiers, notes, observers and votes, and no macro site; it is
   inserted in order, group indices shifted, `in_force` recomputed.
4. **Key**: all 32 bytes complemented, for the first four spelled pieces
   in edit and piece order; nothing else changes.
5. **Judged**: the check's output's structure is checked, its `result`
   line is required, its record is read from the store and its state
   must equal the printed one. `verified` fails ("an edit was lost or
   invented and nothing noticed"). Drop and add pass with
   `not_verified`; a key passes with `not_verified` only if a failed
   spelling obligation of the record is one whose key, in the check's
   overlay, is the mutated piece's key. `refused` passes only for the drop
   that left a refused set, and that drop passes only with it. A drop passes with
   `verified_with_residue` only if a residue entry that is not a mention,
   in the dropped edit's file, lies within the dropped range. Any other
   state fails, naming the mutation's label (`drop edit <i>`, `add edit
   at kept <k>`, `change key of edit <i> piece <j>`).

## Open

1. `cargo xtask ci` has no `--no-clang`; the gate's step fails on a skip.
   A host without clang 19 runs `cargo xtask transform --no-clang`
   itself.
2. A mutation check that exits 3 (input) without a result line is a
   `FAIL`, not an `ERROR`.
3. A `cdb.json` entry with `command` instead of `arguments` is split with
   POSIX shell quoting (single, double quotes, backslash), no expansion.
