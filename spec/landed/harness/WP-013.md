# WP-013 — xtask: jobserver and perf

What `cargo xtask jobserver` (`spec/harness.md` §5) and `cargo xtask perf`
(§7) do where the spec leaves it open. Normative until folded into
`spec/harness.md`. Code: `xtask/src/jobserver.rs`, `xtask/src/perf.rs`,
`xtask/src/perf/render.rs`. Tests: `xtask/tests/jobserver.rs`,
`xtask/tests/perf.rs`, goldens in `xtask/tests/golden/perf/`.

`xtask` now depends on the workspace crates `slip_model` and `slip_exec`
(path dependencies through `[workspace.dependencies]`), and through
`slip_exec` on `signal-hook`, which §3.1 already allows. The `dependencies`
lint is unchanged: it checks third-party packages of `Cargo.lock` only, and
a workspace member has no `source`. Commands are still started with
`std::process::Command` (WP-005); nothing here starts a process.

Changes from the brief (`docs/wp/WP-013.md`): `measured` and
`render_summary` return `Result`, since a sum can overflow; `check` takes a
parsed `Baseline`, so that an error in the baseline names the baseline file
(the caller prefixes it) and an error in the run names the run's file;
`run`, `parse`, `inspect`, `read_baseline`, the name tables and the
`Measured` accessors are additions, so the tests need no process.

## Jobserver (§5)

- **Options.** `--fifo <path>` and `--jobs <n>`, each at most once, in any
  order, value as the next argument. A missing value, an empty `--fifo`, a
  repeated option, any other argument, and a missing or unknown command are
  usage errors: `xtask jobserver: <message>` and the usage text on stderr,
  exit 2.
- **`<n>`** is ASCII digits only (no sign, no spaces), not 0, fitting
  `usize`. A bad `--jobs` is a usage error (exit 2) `--jobs: `<v>` is not a
  positive integer`; a bad `$SLIP_JOBS` (including empty or not UTF-8) is
  an error (exit 1) `SLIP_JOBS: `<v>` is not a positive integer`. Stricter
  than `slip_exec::jobserver::resolve_pool_size`, which trims and accepts
  0; xtask applies its own check and uses `DEFAULT_POOL_SIZE` for the
  default.
- **The fifo** without `--fifo` is `slip_exec::jobserver::resolve_fifo`:
  the last `--jobserver-auth=` word of `MAKEFLAGS` if it is `fifo:<path>`
  (a descriptor form names no fifo and falls through), else a non-empty
  `$SLIP_JOBSERVER_FIFO`, else `/run/slip/jobserver.fifo`. A `MAKEFLAGS`
  that is not UTF-8 is ignored, as `default_fifo` ignores it.
- **Checks before opening** (exit 1, `xtask jobserver: <path>: <what>`):
  `does not exist`; `is not a fifo` (symbolic links followed; a directory
  or regular file is never opened); `cannot stat: <error>`. A failure of
  `status` or `refill` itself is `cannot read the pool: <error>` or
  `cannot refill: <error>`.
- Output on stdout is the one line of §5, the path as given or resolved
  (`Path::display`). The usage text states that `refill` is only correct
  while no client holds a token.

## Perf (§7)

### Run paths and loading

- **Path shape.** The last three components must be plain names: `runs`,
  a plan id (64 lower-case hexadecimal digits), and
  `<phase>.<round>.<started>.run` with phase `map` or `verify` and the two
  numbers canonical decimal `u64` (`0`, or digits without a leading zero).
  The store is the path without those three components, `.` when nothing
  is left. Components are taken as written (`Path::components`): a `..`
  among the last three is an error, not resolved.
- **Order of reading**: the record (read and validated as a `RUNR`
  container), then its `plan`, `phase` **and `started_unix_ns`** against
  the path (the store names the file by all three, `spec/landed/exec/WP-008.md`),
  then the store opened `Shared`, then the plan, then the shards. The
  record is read before the store is opened, so an absent or empty
  directory is never initialised as a store.
- **The plan** must be in the store, validate, and have the content id its
  name says.
- **Observers of the record** are the distinct `Job.observer` values. One
  that is not an observer of the plan is an error (its main file, which
  the summary prints, would be unknown).
- **Shards.** For each observer of the record, the shard of the run's
  phase and round is read; one that does not validate, or names another
  observer, phase or round, is an error naming the shard file. A missing
  shard is kept as `None`: `summarize` reports it, `counters` (and so
  `record` and `check`) refuse it. A shard's content id is not compared
  with any `Job.shard`.
- Errors are `<file>: <message>` with the file as the path given, or the
  store's path for the plan and shards (`Store::plan_path`, `shard_path`).

### Numbers

- Every sum is a checked `u64` addition; an overflow is an error
  (`<what> overflows a 64-bit unsigned integer`) and exit 1.
- **Seconds** are `(ns + 500 000) / 1 000 000` milliseconds in `u128`,
  printed `<ms / 1000>.<ms % 1000, three digits>` (half up; `u64::MAX` ns is
  `18446744073.710`).
- **Nearest rank** is `ceil(p × n / 100)` clamped to `1..=n` (so `p` 0 is
  the smallest value and `p` above 100 the largest); 0 for an empty list.
- **Efficiency** is computed from nanoseconds, not from the printed
  seconds: `cpu_ns × 100 / (wall_ns × workers_max)` rounded half up to two
  decimals in integers; `-` when `wall_ns × workers_max` is 0.
- **Ratios** of `check` are `run / baseline` in `f64` printed with two
  decimals (`{:.2}`); `-` when the baseline value is 0.

### Counters (§7.1)

- `run.observers` is the number of distinct observers of the record;
  `shard.<status>` counts the shards present by status (so with no
  missing shard they add up to `run.observers`).
- The shard counters are summed over the shards of the record's observers
  only. A shard counter whose name is one of the names §7.1 computes
  (`plan.observers`, `plan.excluded.*`, `run.observers`, `shard.*`) is an
  error, not an overwrite.
- An observer's "last job" (§7.1) is used by nothing in §7.2 or §7.3 and is
  not computed.

### `summarize` (§7.2)

- Every record is loaded before anything is printed; an error in any of
  them prints nothing on stdout and exits 1.
- Lines are exactly the §7.2 template with single spaces. `shard` lines in
  the order `ok`, `diagnosed`, `rejected`, `failed`; `missing shards <n>`
  only when `n` > 0, right after them; `job` lines in the order
  `completed`, `crashed`, `killed_memory`, `killed_time`, `cancelled`,
  every job (attempt) counted. `counter` lines are the shard counters
  summed over the shards present, by name (byte order). The `top` entries
  are indented two spaces. Records are separated by one empty line; the
  output ends with a newline.
- `top cpu` ranks every observer of the record, zeros included, by its
  summed `cpu_ns` (every attempt); `top peak_rss` by the greatest
  `peak_rss` of any of its jobs, whatever their end. At most ten each,
  ties by observer id ascending.
- `tool` is the record's `tool_slip` and `tool_kiln`.
- **Text.** The given path, the tool versions and the main file paths are
  printed as one line: valid UTF-8 as itself, `\` as `\\`, control
  characters below U+0100 and bytes that are not UTF-8 as `\xNN`.

### Baselines (§7.3)

- **Written** with `slip_model::json::write_pretty`: members in the §7.3
  order, `counters` sorted by name, `measured` in the §7.3 order. Counters
  and the whole-number measured values are JSON integers (also above 2^53:
  the §10 string rule is for container renderings, not baselines).
  `wall_s` and `cpu_s` are JSON numbers with a fraction: the `f64` nearest
  the three-decimal seconds, written shortest round-trip (`7.5`, `4.124`,
  `0.0`).
- **`perf record`** looks the corpus up (`xtask::corpus::rows`) before
  reading the record; refuses a record with `run.observers` ≠
  `plan.observers` (`the record covers <a> of the plan's <b> observers`)
  before computing counters; writes `bench/baselines/<corpus>.json` under
  the repository root through `.<name>.<pid>.tmp` in the same directory and
  one rename (creating the directory, replacing a file that exists,
  removing the temporary file on failure); prints the full path.
- **Read** (`check`) with `slip_model::json::parse`. Every member is
  required and none other is allowed, in any order. Messages:
  `not JSON: <reader error>`, `at the top level: expected an object`,
  `no member `<key>``, `at <key>: unknown member`, `at <key>: expected a
  string`, `at counters.<name>: expected an integer in 0..2^64`,
  `at measured: no member `<name>``, `at measured.<name>: unknown member`,
  `at measured.<name>: expected an integer in 0..2^64`, and for `wall_s`
  and `cpu_s` `at measured.<name>: expected a non-negative number of
  seconds with a fraction` (a JSON integer such as `4` is refused). The
  command prefixes `bench/baselines/<corpus>.json: `. A baseline whose
  `corpus` is not the corpus named on the command line is an error.
- **`perf check` output**, on stdout, in this order: `pin: baseline <a>,
  run <b>` if the pin differs (the run's pin is the corpus row's tag);
  `slip: baseline <a>, run <b>` and `kiln: …` if a tool version differs;
  one line `<name>: baseline <a>, run <b>` per differing counter, by name,
  `-` standing for a counter absent on that side; then all ten measured
  values `<name> <run value> (×<ratio>)` (the run's seconds with three
  decimals, whole numbers in decimal); and last `perf check: <corpus>: ok`
  (exit 0) or `perf check: <corpus>: FAILED (<n> difference(s))` (exit 1),
  `n` counting the pin and the counters.
- Errors (unknown corpus, unreadable or invalid files, a cancelled run)
  are `xtask perf: <message>` on stderr, exit 1; a wrong argument count or
  unknown command is a usage error with the usage text, exit 2.

## Tests

- `xtask/tests/jobserver.rs`: §5 over fifos the test makes and holds open:
  `status` (tokens left in place), `refill` short, full and above `<n>`,
  `<n>` from `$SLIP_JOBS` and the default, fifo precedence `--fifo` >
  `MAKEFLAGS` > `$SLIP_JOBSERVER_FIFO` (and the descriptor form falling

  bad `<n>` from either source, a missing path, a regular file and a

  a shard of another observer, phase or round, an invalid shard, overflow,

  goldens of a full and a cancelled run with ties, efficiency `-`, the ten

  the baseline golden, partial coverage refused, `record` then `check`,
  every kind of check difference, malformed baselines, and the executable's
  usage, unknown-corpus and unreadable-record errors.
