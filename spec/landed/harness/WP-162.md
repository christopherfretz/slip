## The probe (item 4)

The seed was the supervisor's (Python loops, no Slip code) during the
merge check of WP-159: of 4,800 files freshly created on the workspace
mount (each written as a temporary and renamed), about 795 had another
inode number 2 s later; in other runs none changed (0 of 20,000 at once,
0 of 600 sampled over 30 s, 0 over 80 s and over 780 s of 2,000 files of
which half were held open). The change comes in bursts, with the host's

## The helper (item 3)

One file, `crates/slip_kiln/tests/common/work_root.rs`, included by the
`tests/common` module of each crate below (`#[path]`, as
`crates/slip_cli/tests/declare.rs` includes `slip_digest`'s rules
reader), so that the rule is one text. Each crate's `common::work_root()`
is `work_root_or(env!("CARGO_TARGET_TMPDIR"))`. Its test,
`s11_5_work_root`, is in one file of each crate.

The directory of a process is never removed by that process (a test
binary has no end hook); a lock held on its `.lock` tells a later
process that it is still running. Every first call of a process removes
the siblings whose lock it can take and that are older than 10 s: an
ended process's directory, never a running one's. On the workspace's
mount `flock` does not exclude (a second lock of a held file succeeds,
measured), so there the sweep removes nothing; the root is meant to be
on a local file system, where it does.

## The transform runner (item 2)

`xtask::transform::work_base`: `$SLIP_TEST_ROOT/transform/<checkout>`
or `<target>/transform`. `tree::check_work_dir`, which guards the
directory the runner removes, accepts `transform` as the third or the
fourth component from the end. `slip` is still built and taken from the
target directory.
