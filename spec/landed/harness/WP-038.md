# WP-038 — pair tests under flags and targets

Decided by work package WP-038. `spec/harness.md` §6.1 is the reader's
summary; `crates/slip_kiln/src/snippet.rs` ("Language options", "Extra
arguments and targets") documents the implementation.

## `slip_kiln::snippet::parse_with`

```rust
#[derive(Clone, Debug, Default)]
pub struct Extra<'a> {
    pub args: &'a [&'a str],
    pub target: Option<&'a str>,
}
pub fn parse_with<R>(
    snippet: &Snippet<'_>,
    extra: &Extra<'_>,
    f: impl FnOnce(&Parsed<'_>) -> R,
) -> Result<R, String>;
```

`parse(s, f)` is `parse_with(s, &Extra::default(), f)`.

1. **The line.** `-std=<Snippet::std>`, then `--target=<Extra::target>`
   when one is given (as written), then `Extra::args` in order, then
   `-fsyntax-only`. Kiln's driver parses it (`Args::parse_as` with the
   argv0 `kiln`); every language option comes from that parse through
   the public functions the private `SyntaxJob` / `Job` methods of
   `kiln_driver` use, for the target the line names
   (`x86_64-unknown-linux-gnu` without one). Each field the snippet sets
   by hand follows the line: `complex_promoted` from
   `Args::complex_range` (its name, the type being `kiln_codegen`'s),
   the resolved target features (`target_features` on `AArch64`,
   `x86_features` on x86-64), Sema's target, the feature queries (the
   arguments without the `-fsanitize=` ones, the resolved sanitizers,
   `-ffp-eval-method=`, the target's builtins).
2. **The target** is `Err` unless `kiln_driver::toolchain::Target::parse`
   knows it: `aarch64`, `arm64`, `x86_64` or `amd64`, alone or followed by
   at most three `-`-separated parts of which the first or second begins
   `linux`.
3. **Each argument**, checked alone on the head of the line, in order, is
   `Err` naming it when:
   1. its spelling is refused: an input (`-` or no leading `-`), `-x…`,
      `-std` / `--std` in any form, `-target` / `--target` / `--target=`,
      a `native` `-march=` / `-mcpu=` / `-mtune=`, `-fsyntax-only`,
      `-fkiln-stack-size=`, `-Xpreprocessor` (it takes the next argument,
      `kiln_driver::codegen_flags::splice_preprocessor_args`, and last on
      a line the driver keeps it without a report);
   2. it takes the next argument as its value (the driver reports its
      value missing when it is last on the line);
   3. `kiln` would stop before the job for it: `Args::errors`, then the
      checks `kiln_driver::run_as` makes before the job runs
      (`features::resolve`, `Args::sanitize` and the coverage and
      hardware sanitizer checks, the large-data threshold on `AArch64` at
      clang 19, the XRay and code-generation invocation checks); an error
      among the diagnostic options' own (`DiagOptions::pending`:
      `-fdiagnostics-format=sarif`, `-ferror-limit=x`), which the
      driver's engine reports first; a driver warning (`driver_warnings`:
      the floating-point overrides, `-m[no-]outline-atomics` and
      `-moutline` off `AArch64`, `-mlarge-data-threshold=` without a
      medium or large code model, the unused XRay, return-address,
      `-ftrapv-handler`, time-trace and coverage-list arguments, the x86
      feature flags on `AArch64` and `-m3dnow`) that the `-W` options
      make an error, computed through `kiln_driver`'s public functions
      and rendered under `codegen_cmd::driver_diag_options`'s rule; the
      per-input errors of `input_std` for a C++ input (an invalid
      `-fvisibility=` value, `-fgnu89-inline`). Not asked:
      `hod::selected` (it reads `KILN_BACKEND`), the default sanitizer
      ignorelists (read from the resource directory), and the checks of
      what step 4 refuses anyway (inputs, `-M*`, PCH, modules, the
      time-trace granularity, framework directories);
   4. it changes a field of `Args` that says what is read or written
      rather than the language, or the form of the diagnostics
      (`-fdiagnostics-format=json`: `Parsed::diagnostics` is text). The
      check destructures `Args` with no rest pattern, so a field Kiln
      adds does not compile until it is classified.
4. **The whole line** is then `Err` by checks 3 and 4 for the arguments
   together (`-Werror -ffp-model=fast -ffp-contract=on`).
5. **Unchanged:** no predefined macro, no header search, no file system,
   the thread and stack rules of WP-021, and the same result for the same
   input on any host and thread.

## The runner's header lines

1. The header block of a main file is its leading lines that are header
   lines or `#include "side.h"`; the first other line ends it. There is no
   line limit. A later line of the main file that is exactly a header
   line (after a byte-order mark, if any) is an error of the test,
   "header line outside the header block".
2. A header line is exactly `// <key>: <value>` with one of the keys
   `std` (one of `c++17`, `c++20`, `c++23`, `c++26`), `errors` (value
   `yes`), `target` (one word) and `args` (split at spaces; no quoting).
3. A line of the block that looks like a header line — `//`, blanks, a
   word of ASCII letters and `-`, blanks, `:` — and is not one is an
   error of the test, as is a key given twice. A comment that does not
   look like one (`// §4.3 …`) ends the block.
4. A `t.cpp` test's sides share the lines; each side of an `a.cpp` /
   `b.cpp` test reads its own main file's.
5. `SLIP_DIGEST_DUMP` prints each side's line (`kiln <line>`); errors of
   a side name it too. `SLIP_DIGEST_ONLY=<text>` makes `run_all` (the
   four pair runners) keep the directories whose path contains `<text>`
   and print `SLIP_DIGEST_ONLY=<text>: <n> of <m> directories`;
   `common::dirs`, which the determinism test uses, is never narrowed,
   and `cargo xtask ci` removes the variable from what it runs.
6. Each file of `crates/slip_digest/tests/support/` is a file of every
   snippet whose directory has no file of that name. `meta.h` there is a
   subset of Kiln's `kiln/tests/support/kiln_meta.h`: that header
   includes standard headers (`<vector>`, `<optional>`, `<span>`, …) and
   a snippet has no header search path. (A template of deduced return
   type no longer stops it: `TypeView/Auto.deduced` is written when the
   deduced type is the builtin dependent type.)
