# WP-088 — slip_script: the effects

`crates/slip_script/src/effects.rs` implements operations 64 to 84 of
§3.2 (§7.1 to §7.5, §7.7) inside `Host::call`, and
`RunOutput::render` (`output.rs`) the rendering of §7.6. This file
records where the specification left a choice and how the code makes it.
Tests are in `crates/slip_script/tests/effects.rs`. Decision 15 of
`WP-081.md` (effects are `unsupported`) no longer holds.

## Decisions

1. **The staging of `Host::call` is kept.** An effect is validated in the
   immutable stage (`Host::effect`, called from `answer`): every refusal,
   every question to the subject and every check of its answer, every
   limit, and the whole record to make (the pieces, the text chosen for a
   spelled piece, the places). `deliver` hands it to `Host::record`, which
   only stores it and cannot fail. So a refused request, and a request the
   subject answered inconsistently, record nothing (§4 rule 3, §3.5 rule
   2), and the counter `api.op.<name>` counts it only if it succeeded.
2. **The null handles** (§3.2, as amended). Code handle 0 is the empty
   code and group handle 0 is no group, wherever either is taken: they are
   the header's default `code` and `group`. An operation whose result has
   no piece (`text("")`, a `cat` of empty codes) returns 0 and holds no
   code value, so it counts against no limit. Code and group handles are
   issued from index 0 in the order made; any other value of tag 5 or 6,
   or a handle of another tag where a code or a group is taken, is
   `invalid_handle`.
3. **Order of checks**, after the shape (`WP-081.md` decision 1): the
   arguments in order (handles and ranges, then the length of the text),
   then the refusals of the operation in the order its section lists them,
   then the subject's answers, then the limits on what the run holds.
   - `replace`: range, code, group, note length; empty range
     (`invalid_argument`); `not_editable`; unknown tier (`unsupported`);
     edits requested; the spelling (decision 5); pieces and bytes in
     pieces; text held.
   - `report`: where-kind and its integers, the value or range; severity;
     message length; reports; text held.
   - `expect_changed`: value; reason length; an entity or a declaration
     (`unsupported`); a null extent (`unsupported`); `Subject::unit_keys`;
     declared changes; text held.
   - `expect_renamed`: entity (`invalid_handle`, `wrong_kind`); name
     length (`limit_exceeded`); identifier (`invalid_argument` or
     `unsupported`, `WP-081.md` decision 6); a different name declared
     before (`invalid_argument`); `Subject::rename_rule`; text held.
   - `spell`: entity; `Subject::qualified`; `Subject::entity_key`; code
     values, pieces, bytes in pieces.
4. **A spelled piece holds its fully qualified text from `spell` on.**
   §7.2 says the text is chosen when the edit is recorded; of the two
   spellings only the sibling rule depends on the place, so the qualified
   text (rule 2, which depends on the entity alone) is computed once at
   `spell`, with the key (decision 8 of the package), and `replace`
   decides between it and the identifier. The qualified text counts in
   the bytes held by the code value (decision 7).
5. **The sibling rule** (§7.2 rule 1) applies when the code is exactly one
   piece, a spelled one (after normalisation: `cat(text(""), spell(e))` is
   one piece), and `Subject::references_at(r)` is not empty. For each
   reference there, the host checks the subject's answers (live, listed
   once, extent exactly `r`, a name range that is not empty and lies in
   `r`) and evaluates the conditions; they must hold for every reference
   and the name ranges must be one range (§7.2 rule 1, as amended: two
   name ranges for one extent leave no single range to narrow to). The
   narrowed edit's tier is `Subject::tier` of the name range. Condition 1
   ("E has an identifier") is evaluated but cannot fail for an entity
   `spell` accepted (§7.1 rule 4).
6. **The tier of an edit** is `Subject::tier` of its range. A range for
   which the subject has none (it lies in no name range and no extent:
   `WP-081.md` decision 3 lets a transform forge such a range in a file it
   was given) is refused by `replace` with `unsupported` (§7.3 rule 2, as
   amended). A tier other than 0 or 1 is a host failure.
7. **Limits** (§7.7, as amended). Each is inclusive (`WP-081.md` decision
   7). The table's counts of code values, pieces per code, edits, groups
   and reports did not bound what a run holds: `cat` copies piece lists
   and `replace` copies a code's pieces into the edit, so 2^22 code values
   of 2^16 pieces, or 2^20 edits of 2^16 pieces or with 2^12-byte notes,
   are far beyond any memory; and `expect_changed` had no bound at all.
   Three totals were added and one restated, all counting what is held,
   once per code value, edit or declared change that holds it: pieces
   (2^22), bytes of text in pieces (literal bytes and spelled text, 2^28,
   the row that was "bytes in literal pieces"), distinct declared changes
   (2^20), and bytes of text arguments (notes, messages, reasons, new
   identifiers, 2^26). With them the host holds at most a few hundred
   megabytes for effects whatever the transform sends. Where each is
   enforced is in the handback of `docs/wp/WP-088.md`.
8. **Declared changes are a set** (`Record::changed`). `expect_changed`
   records the entries `(key, place, reason)` not already recorded; a
   request whose entries are all there succeeds and records nothing
   (§7.5 rule 4), so repeating a declaration counts against no limit.
   `Subject::unit_keys` must give at least one key and no key twice.
9. **`expect_renamed`.** The host keeps the name declared for each entity.
   The same name again succeeds and records nothing (§7.5 rule 4); another
   name is `invalid_argument`; a declaration that was refused
   (`unsupported`, or a limit) does not claim the entity. The rule
   recorded is the subject's; the host checks that its `name` is the new
   identifier, since the rule undoes the rename (`spec/verify.md` §2.1).
   The fake built the rule the wrong way round (matching the old name);
   it now builds the undoing rule.
10. **Reports.** The place of an `info` is `Subject::place`; `attached`
    is `true` when the subject says the place is not the value's own
    (`WP-081.md` decision 14). A value with no place at all gives a report
    with no place and `attached` `false` (§7.4 rule 3, as amended). A
    where-kind other than 0, 1 or 2, or a nonzero integer the where-kind
    does not take, is `invalid_argument` (§3.2, as amended): these are
    values of the operation's arguments, not a wrong shape (255).
11. **An empty note is no note** (§7.3 rule 5, as amended): the edit's
    `notes` are empty, so a request with the default note and one without
    are the same record.
12. **`copy` of an empty range** is a piece. §7.1 rule 2 refuses only the
    null range, and the length of a copy is decided by apply.
13. **Statuses a subject may choose** (`WP-081.md` decision 17, for the
    methods the effects call). `unit_keys` and `rename_rule` may return
    `Err(unsupported)`; any other `Err` is a host failure naming the
    method and the status. `entity_key` and `qualified` have no status
    but `None`, which is `unsupported`; what the host checks of their
    `Some` is decision 5 for `qualified` (one or more identifiers, none
    empty, the last the entity's own), and nothing for `entity_key`,
    whose key the host cannot check. `extent` and `name_range`, asked by
    the effects, may return no `Err`, as for the queries. The trait's
    documentation says each of these.
14. **`RunOutput::render`.** One line per item in the output's order:
    `transform`, then `edit <i> <place> tier <t> = <pieces> [note "…"]…`,
    `group <i>…`, `report <place|-> <severity> "<message>" [attached]`,
    `changed <key> <place> "<reason>"`, `renamed <kind> <parent> <name>
    [disc <digest>] -> <parent> <name>`, `counter <name> <value>`. A place
    is `path:lo-hi`; text is quoted with `\\`, `\"`, `\n`, `\t` and `\xNN`
    for every other byte outside printable ASCII; a path is escaped the
    same way without quotes. The form is the documentation of the
    function; WP-090 may extend it.
