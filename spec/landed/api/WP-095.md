# WP-095 — slip_script: the subject over Kiln: keys for declarations and spelled entities

`crates/slip_script/src/kiln_subject/keys.rs` brings `spec/api.md` §7.5
rules 1 to 3 to `KilnSubject`: `unit_keys`, `rename_rule` and
`entity_key`, all answered by `slip_digest::query::Keys` (WP-087). The
subject computes no key: it finds the declaration that holds a value
and asks. Tests are in `crates/slip_script/tests/subject_keys.rs`.

## What was built

- **`entity_key(e)`**: `Keys::key_id` of the entity, or none.
- **`rename_rule(e, n)`**: `Keys::rename_rule`; every refusal
  (`NotAUnit`, `ContentKeyed`, `Indeterminate`, `NotRenamable`,
  `BadName`) is `unsupported`. A value that is not an entity is
  `unsupported`.
- **`unit_keys(v)`** for a live reference or a live expression: the
  holder (below), the unit `Keys::unit_of` gives it, that unit's key
  (`Keys::key_id`), then `Keys::derived` of the unit, the unit's own key
  left out. The unit's key comes first. Any other value, and every
  refusal, is `unsupported`. `KilnSubject::reference_unit_keys` and
  `expression_unit_keys` return the reason (`Why`) for the tests.
- **The key server.** `Keys` borrows a `slip_digest::Input`, whose path
  function is not `Sync`, and needs a thread of
  `slip_digest::STACK_SIZE` (64 MiB). The subject is `Sync` (WP-089). So
  `Keys` lives on a thread of its own, started by
  `KilnSubject::with_keys(f)`. That thread holds the `Input` and the
  `Keys` and answers one question at a time over a channel, until `f`
  returns or unwinds. `Keys` is built on the first question, so its
  memos (keys, units, and the one walk of `Keys::derived`) are paid
  once per `with_keys`. A question asked outside `with_keys` starts a
  server for that one question: the same answer, with nothing kept.
  Nested `with_keys` calls share the server. `script_test::run_one`
  runs each transform inside `with_keys`.
- **Recorded holders in the WP-086 calls index.** The walk records,
  for each `DeclRefExpr` and `MemberExpr` whose name is a written-reference
  entry, the holder it entered (`ref_holder`, keyed by the entry). When
  it reaches one entry from two holders, it records none.
- **One reference, several entries.** A `Reference` is one written
  name. A header entered twice, or a macro argument used twice, joins
  several of Kiln's entries into it. `Names` now keeps every entry of a
  reference (`reference_entries`).

## The holder of a reference

Each entry of the reference has a holder from two sources:

1. **The walk** (WP-086's index): the namespace- or class-scope
   declaration, as written, that the walk entered to reach the
   expression whose name the entry is. This covers names of expressions
   in bodies, initialisers, default arguments, default member
   initialisers, template heads, enumerator values and types as written.
2. **Kiln's table** (`enclosing`, Kiln `spec/ast.md` §18.3): the
   innermost declaration that claims the name. The table is an answer
   only in these cases:
   - A namespace, the translation unit, a linkage specification, an
     `export` block, an enumeration or a requires-expression body is no
     answer. Kiln gives that lexical context for the names of
     declarations that claim none (an alias, an enumerator, a
     `static_assert`, a template head), so the true holder is unknown.
   - A class is the answer only for a name in its head, before its body
     (a base specifier, the arguments of a specialisation). For the same
     reason, a name elsewhere in a class gives no answer.
   - A name in the decl-specifiers shared by a declarator group of two
     or more declarators (`S a, b;`) is held by each declarator, so it
     is refused. The group is the set of declarations, as written,
     whose extent rows share one `full` span.
   - An instantiated or implicit enclosing declaration is refused.

An entry with no holder from either source, or refused by either
source, has no holder: `unsupported`. The holders of every entry go
through `Keys::unit_of`. The answer is `unsupported` if they give two
units, or if one gives none. A local declaration (a lambda's call
operator, a local class, a local variable, a parameter) is no unit;
`Keys::unit_of` gives its containing unit (`spec/digest.md` §2.1).

How the holder is found for each place a reference can stand:

| Place | Source | Answer |
|---|---|---|
| Function body | walk (expressions); table (the function, or a local declaration that `unit_of` maps to it) | the function |
| Variable initialiser | walk; table | the variable |
| Declarator of one declaration (`S r();`, `S w;`) | table | the declaration |
| Decl-specifiers shared by two declarators (`S a, b;`) | table, refused | `unsupported` |
| Parameter type | table (the parameter or the function) | the function |
| Base specifier | table (the class head) | the class (a template: its instantiations derived) |
| Default argument | walk; table | the function |
| Default member initialiser | walk; table | the field (`D::k`) |
| Template argument at namespace scope | table: in a class head, the class; in a declaration, that declaration | the class or the declaration |
| Template argument in a template head (`template <class T = S>`) | table gives the context; the walk records only expressions | type name: `unsupported`; expression (`template <int N = f(2)>`): the template |
| Lambda in a function | walk (the enclosing holder); table (the call operator or a lambda parameter) | the enclosing function |
| Lambda at namespace scope (`auto l = [] {…};`) | walk; table | the variable |
| Alias or typedef target (namespace or class) | table gives the context | `unsupported` |
| Enumerator value | walk for expressions; table gives the enumeration | expression: the enumerator; type name (`sizeof(S)`): `unsupported` |
| `static_assert` | walk | the digest keys it by content: `unsupported` |
| A file entered in two holders; a macro argument expanded into two holders | each entry's holder | two units: `unsupported` |

An expression's holder is `KilnSubject::holder` (WP-086). Its argument
expressions and the callee's reference share its holder.

## Decided where the spec was silent

1. **Which unit holds a name the front end does not attribute.** Kiln
   gives the lexical context for the names of non-claiming declarations,
   and the declarator group, not one declarator, for shared
   decl-specifiers. The subject answers `unsupported` and never picks
   one. `spec/api.md` §7.5 rule 2 now says so.
2. **`Keys` lives as long as `with_keys`, not as long as the subject**
   (the package's item 4). A `Keys` inside the subject would make the
   subject neither `Sync` nor buildable without the digest's stack. A
   run of a transform is one `with_keys`, so `Keys` and its memos are
   built once per run. A caller that asks outside it gets correct but
   unmemoised answers. **WP-092's run must call `Loaded::run` inside
   `subject.with_keys`**, as `script_test::run_one` does.
3. **A type name in an enumerator value or a template head default** is
   `unsupported`, though the walk passes through those types. The walk
   records holders only for the names of expressions, so recording
   type names would be an extension of WP-086's walk. Not done.
4. **The answer for an expression** is the holder of the expression
   itself. A call in a header entered twice is two expressions, each
   with its own unit, while the callee's one reference has two units
   and is `unsupported`.

## Test 5: `KilnSubject`'s entity and `Keys::entity`

Every snippet of `subject_keys.rs` checks every declaration of the arena
(`entity_disagreements`). No declaration disagrees.

## Measurement: recording holders in the calls index

The test is a snippet of 2,000 functions, each with 4 calls of `f` and 5
written names of expressions, so 20,000 recorded entries. It is a debug
build, three rounds each, with the recording switched off by a
temporary edit and then switched on:

| | index build (4,000 calls) | recorded entries | map capacity |
|---|---|---|---|
| without recording | 0.97 to 1.01 s | 0 | 0 |
| with recording | 0.99 to 1.00 s | 20,000 | 28,672 |

There is no measurable time difference. The memory is one
`HashMap<u32, Option<DeclId>>`: 28,672 slots of 8 bytes plus one
control byte each, about 250 KiB for 20,000 entries (about 13 bytes per
entry).
Building the subject itself (`KilnSubject::from_snippet`, before the
index) took about 5.1 s on the same snippet. Rounds of 20,000 functions
did not finish in 7 minutes, so construction grows faster than
linearly. That predates this package (WP-085) and is reported in the
hand-back.

## Mutation testing

Each mutant is one textual replacement in `keys.rs` or `calls.rs`,
applied by a script that runs `cargo test -p slip_script --test
subject_keys` and restores the file. M1 was also run against the calls
index's library test `holder_of_each_call`. There are 12 mutants: 9
killed, 3 survive.

| Mutant | Killed by |
|---|---|
| M1 a lambda's body held by its call operator, not the enclosing holder | `kiln_subject::calls::tests::holder_of_each_call`; survives `subject_keys` (below) |
| M1b `unit_of` skipped: the holder (a lambda's call operator, a local) is taken as the unit | 8 tests, among them `s7_5_rule1_test1_the_keys_of_each_holder`, `s7_5_rule1_references_in_local_declarations` |
| M2 a `ContentKeyed` unit answered with a key | `s7_5_rule2_test3_content_keyed_and_indeterminate` |
| M3 only one of two instantiations among the derived keys | `s7_5_rule1_test1_instantiations_are_derived_units`, `s7_5_rule1_test1_the_keys_of_each_holder`, `s7_5_rule1_test2_…`, `s7_5_test4_…` |
| M4 the walk's holder ignored | `s7_5_rule1_the_walk_holds_what_the_table_does_not` |
| M5 any name in a class held by the class | `s7_5_rule2_test3_no_holder` |
| M6 a declarator group of two not refused | `s7_5_rule2_test3_no_holder` |
| M7 a namespace taken as a holder | `s7_5_rule2_test3_no_holder` |
| M8 only the first entry of a reference | `s7_5_rule2_a_header_entered_in_two_holders_has_no_unit` |
| M9 one entry reached from two holders: the last kept, not refused | survives (below) |
| M10 the table ignored where the walk answers | survives (below) |
| M11 an instantiated or implicit enclosing accepted | survives (below) |

Survivors:

- **M1**, against `subject_keys`: `Keys::unit_of` maps a lambda's call
  operator to the unit that holds the lambda (`spec/digest.md` §2.1),
  so the keys are equal. The holder itself differs, and WP-086's test
  of holders kills it. M1b, where the holder becomes the unit, is
  killed.
- **M9**: Kiln gives each expansion of a macro argument, and each
  entry of a header, an entry of its own. No entry was found that the
  walk reaches from two holders. `s7_5_rule2_a_macro_argument_in_two_holders_has_no_unit`
  (one name, two declarations, two entries) shows the case is refused
  one level up, by the two units of the reference's entries. The
  refusal stays as a guard against a Kiln that shares an entry.
- **M10**: on every snippet the walk and the table agree on the unit.
  `with` checks that no live reference has two units on every snippet,
  which would show a disagreement. The table is a cross-check where
  both answer.
- **M11**: Kiln's written-reference table records names as written,
  and their enclosing declarations are written declarations, so no
  instantiated or implicit enclosing was found. The check guards
  against attributing a written name to a declaration Kiln made.

## For Kiln

1. **Names of declarations that claim no extent are attributed to the
   lexical context.** In

   ```cpp
   struct S {};
   using A = S;
   enum E { e = sizeof(S) };
   template <class T = S> void t() {}
   struct C { using I = S; };
   ```

   the `enclosing` of each `S` is the translation unit, the enumeration
   `E`, the translation unit, and the class `C`. The alias, the
   enumerator and the template should each be the holder of the name.
   Asked: an alias, a typedef, an enumerator and a template (for its
   head) claim their names, as other declarations do.
2. **A shared decl-specifier is enclosed by the first declarator
   only.** In `struct S {}; S a, b;` Kiln records one entry for `S`,
   enclosed by `a`. Asked: an `enclosing` that says the name is shared
   (for example, the group's first declaration plus a mark), so that a
   consumer does not take `a` as its only holder.
