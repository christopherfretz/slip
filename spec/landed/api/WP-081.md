# WP-081 — slip_script: the operation table, the wire encoding and the run output

`crates/slip_script` (`wire.rs`, `subject.rs`, `host.rs`, `output.rs`,
`fake.rs`) implements §3, the statuses of §4, §5.2, the queries of §3.2
and the content of §7.6. This file records where the specification left a
choice and how the code makes it. Tests are in
`crates/slip_script/tests/wire.rs`.

## Decisions

1. **Order of checks.** A call is checked in this order: the operation
   number (254), the shape (255: the integer count, and text given to an
   operation that takes none), the arguments in order, the operation's own
   refusals, then the subject's answer. The first that fails is the status.
   Absent text is empty text, so an operation that requires text (`lookup`)
   refuses empty text as `invalid_argument`, not 255.
2. **254 and 255 are failures like the others.** They take the next
   ordinal, have a message, and are in the failure list; `error_message`
   serves them (§3.5 rule 3 numbers "the failures of a run").
3. **File handles are the host's.** The host issues a file handle (from 1)
   the first time it gives out a range in that file, and a range argument
   whose file handle it did not issue in this run is `invalid_handle`
   (§3.4 "the file handle is live", read as "issued in this run", like
   every other handle). Within an issued file any `lo <= hi <=` length is
   accepted, the empty range included (§3.4 asks no more).
4. **Info handles.** Indices are issued per sort, from 0, in the order the
   host first returns a value; the same value always has the same handle in
   one host, which is what makes `==` the identity of §5.1 rule 2.
5. **`is_editable` of the null range at L0** is `invalid_handle`, like every
   other range argument. The header never sends it (it answers `false`
   itself, §6.6 rule 6).
6. **Identifiers** (§6.1 rule 1; `lookup`, and `host::check_identifier`
   for WP-088). Text that is not UTF-8 is `invalid_argument`. Each
   component is then classed: empty, a digit first, or any ASCII byte
   other than a letter, a digit, `_` or `$` is *malformed*; otherwise a
   component with `$` or a code point outside ASCII is *undecided*;
   otherwise it is a keyword or alternative token of C++26
   (`host::KEYWORDS`, a sorted table) and malformed, or plain.
   `invalid_argument` if any component of the whole text is malformed,
   else `unsupported` if any is undecided. `final`, `override`, `import`,
   `module` are not in the table. See decision 22 for where this reads
   the amended text rather than its letter.
7. **Limits are inclusive.** A qualified name of exactly 2^12 bytes is
   accepted; one more byte is `limit_exceeded` (§7.7 "exceeding").
8. **An answer too large for the result word** (2^28 integers or bytes, or
   more) is `limit_exceeded` (§3.3, §7.7), checked before any handle is
   issued.
9. **Sorts are checked by the host before the subject is asked**, with the
   statuses §6 names: `identifier_of` of an expression, `parent_of`,
   `declarations_of`, `references_to`, `calls_to` of a non-entity,
   `entity_of` of a non-declaration, `referent_of` of a non-reference,
   `name_range_of` of an entity or an expression, `extent_of` of an entity
   and the `callee`/`arguments` operations of a non-expression are
   `wrong_kind`; `extent_of` of a declaration is `unsupported`. What the
   subject may still refuse, for a sort it is asked about, is decision 17.
10. **An inconsistent subject is a host failure** (`Err`, §2.8
    `host-failure`), never a status: a value it returns that is not live, a
    range outside its file, the same value twice in one sequence (§5.3
    rule 2), text whose length is not the range's, or kind bits that
    contradict the value's sort (a kind bit of 8 to 13 on a non-entity,
    bit 16 on a non-declaration, bit 17 on a non-expression, or a sort bit
    other than the value's).
11. **The place of a failure** (§2.8 rule 3) is `Subject::place` of the
    live value the refusal concerns, own or nearest. Refusals of a handle,
    a range or text, and statuses 254 and 255, have none.
12. **Counters the host keeps** (§7.6 rule 6). `api.op.<name>` counts
    the calls of each operation that succeeded, as rule 6 says; a failed
    call is not counted. `api.edits` and `api.reports` count the canonical
    output (identical requests are one edit, §7.6 rule 1).
    `api.unresolved_spelling_matches` is decision 19. `api.host_calls`,
    `api.steps` and `api.peak_bytes` are, by rule 6, added by whoever runs
    the evaluation (the driver, WP-089), not by `Host::finish`. The
    writer is decision 20.
13. **The canonical form** (`RunOutput::canonical`): pieces are normalised
    first (§7.1 rule 6), so identity by content does not depend on how a
    code value was built. Edits are ordered by place (the file's `FileRef`
    as derived: path, size, content digest; then `lo`, `hi`), then by
    pieces in the derived order (literal before copy before spelled, then
    by content). Joining two identical requests unions their notes and
    keeps the higher tier. A group's members are rewritten to the joined
    edits, groups sharing a member are merged, and a group left with fewer
    than two members (an empty group, or one whose members were joined
    into one edit) is dropped. Reports are ordered by (place, severity,
    message) with `attached` last as a tie-break; a report without a place
    sorts first. Rules are ordered by their encoding, whose prefix is the
    self-delimiting encoding of the match, so the order is the rule
    table's; identical rules are one. Counters are sorted by name.
14. **`Report::attached`** (§7.6, §7.4 rule 3) is `true` when the report is
    attached to the nearest place the host can name instead of the place of
    the value it was given; `false` for the value's own place, a range, or
    no place.
15. **Effects (operations 64 to 84)** are shape-checked and then
    `unsupported` until WP-088 implements them.
16. **Failure records are bounded** (§3.5 rule 3, §7.7). `Limits::
    kept_failures` (default 2^16) bounds the kept records: `failures()`
    holds the first `kept_failures` and no more, `last_failure()` the most
    recent, `failure_count()` how many there were. `error_message` of an
    ordinal in `1..=failure_count()` succeeds: with the kept text, or with
    the fixed text of §3.5 rule 3, in which `65536` is the limit's value
    (the specification's text with the default). Any other number is
    `invalid_argument`, and is a failure itself. `failure_bytes()` is what
    is held, so that a test can see it stop growing.
17. **Statuses a subject may choose** (§6, documented on the trait). Only
    the statuses the specification allows are passed on:
    `declarations` `Err(unsupported)`, `calls_to` `Err(wrong_kind)`, and
    `None` from `parameters`, `callee`, `callee_reference`, `arguments`
    as `wrong_kind`. Any other `Err` from those, any `Err` from
    `name_range` or `extent`, and `None` from `identifier` for a
    non-expression is a host failure naming the method and the status.
    `entity_key`, `qualified`, `unit_keys` and `rename_rule` are documented
    the same way; WP-088 enforces them, since no operation here calls them.
18. **Numbering** (head of `subject.rs`): a subject gives one number per
    value per sort, stable for the life of the `Host`; the handle identity
    of §5.1 rule 2 rests on it, and the host cannot see a violation.
19. **`api.unresolved_spelling_matches`** (§6.5 rule 6). `call` asks
    `Subject::identifier` of the entity given to `references_to` and
    `calls_to` before delivering, and keeps the non-empty ones of the
    calls that succeed in a set; `finish` asks
    `Subject::unresolved_named` for each, in sorted order, and sums
    (saturating). The counter is present exactly when every answer is
    `Some`; with no identifier asked it is present and 0.
20. **The counter writer.** The effects (WP-088) write a `Record` (edits,
    groups, reports, declared changes) that has no counters; `finish`
    makes every counter itself, once each, and sorts them. No path can push
    a host-owned name, nor any name twice.
21. **No panic from the public interface.** `RunOutput::canonical` is
    total (a group index out of range names no edit and is ignored);
    handle and file-handle issue are checked conversions whose overflow
    is a host failure.
22. **Where the identifier rule is read, not followed to the letter.**
    §6.1 rule 1's first check is written as "not plain and has no byte
    other than ASCII letters, digits, `_` and `$` and no code point
    outside ASCII", which would make `a$` `invalid_argument` and `a b`
    not; its parenthetical ("any other ASCII byte anywhere") and the
    second check say otherwise. The code follows the parenthetical: a
    disallowed ASCII byte, an empty component or a digit first is
    `invalid_argument` even in a component that also has `$` or a code
    point outside ASCII (`é b`, `1é`), since no reading of the open
    question could make those identifiers.
