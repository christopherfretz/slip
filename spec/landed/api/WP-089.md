# WP-089 — the run driver: compile, check the entry, run, classify

Decided by work package WP-089 where `spec/api.md` §2, §12 and the
package leave a choice. `crates/slip_script/src/driver.rs` is the
implementation; its tests are `crates/slip_script/tests/entry.rs`,
`contexts.rs`, `budgets.rs`, `identity.rs`, `demo.rs`, `stack.rs` and the
unit tests of `driver.rs`. Kiln file:line citations are at Kiln
`913a490bb`.

## Interface beyond the package's

- `LoadError::name()` gives the name of §12. `LoadError::Host` is
  `host-failure` (§12's new row): Kiln panicked compiling, Kiln's stack
  guard tripped compiling, or the thread was given less than `STACK`.
  `LoadError` is `Display`.
- `Outcome::Failed(Failure)`: `Failure` is `spec/edits.md` §4.6's record,
  `{ kind: FailureKind, message, place: Option<SourcePlace>, rendered,
  refusal: Option<host::Failure> }`. `FailureKind::name()` is §2.8's name,
  `code()` §4.6's number. `place` is in the transform's source;
  `refusal.place` is the subject's. WP-092's `encode_failure` takes this
  type (its text is corrected).
- `STACK` (256 MiB), `with_transform` (refuses less), and
  `with_transform_on_stack` (any stack: for tests and measurements of
  the host's limit).
- `Loaded::retired() -> Option<&str>`: why the use of the transform
  ended (rule 4 below). `Loaded::triple()` and `Loaded::predefines()`:
  the target terms of the id. `OTHER_THREAD`: the refusal of a run on
  another thread.
- `host_version()` and `transform_id(api_level, host, command_line,
  triple, predefines, files)`: the formula of §2.2, public for the tests.
- Constants: `TRANSFORM_ID_TAG`, `ENTRY`, `RESERVED`, `ERROR_TYPE`.
- `Host::new` takes `&(dyn Subject + Sync)` and `Loaded::run` takes
  `subject: &(dyn Subject + Sync)`. `Host`, the driver's handler and
  `Loaded` are `Send` (`decided_1_host_and_loaded_are_send`); a `Loaded`
  moved to another thread is still run only on the loading one.
- `slip_kiln::session`: `Session::triple()`, `predefines()` (the virtual
  buffer `<built-in>`, `kiln_pp/src/preprocessor.rs:661`),
  `stack_exhausted()` (Kiln's sticky flag,
  `kiln_sema/src/stack_guard.rs:184`); `RunReport::diagnostics`, Kiln's
  structured diagnostics with their places resolved (`RunDiagnostic`,
  `Severity`, `SourcePlace`); `RunFailure::Unknown` (a kind of Kiln's
  `#[non_exhaustive]` `RunError` it does not know);
  `CompileError::StackExhausted`; `TEMPLATE_DEPTH`; `panic_message`.

## Loading (§2.1 to §2.3, §12)

1. The order of the package's rule 1: options, compile, headers,
   reserved names, entry (`rule1_the_first_error_wins`).
2. The refusals of `slip_kiln::session` are passed on: `OptionRefused`
   is `transform-option` with its text; `CompileError::Diagnosed` is
   `transform-compile` with Kiln's rendering; `CompileError::Embed` is
   `transform-compile` rendered `<path>:<line>: error: `#embed` is not
   supported in a transform`.
3. `CompileError::CommandLine` (Kiln stopped before compiling the unit:
   a transform file that cannot be read, `docs/requests/KS2-amendment-1.md`
   §1) is `transform-compile` with Kiln's text, or "kiln stopped before
   compiling the transform unit, and said nothing" if it wrote none: the
   common cause is the author's. `CompileError::Panicked` and
   `CompileError::StackExhausted` are `host-failure`
   (`s12_what_load_makes_of_kilns_refusals`, `s12_a_trip_at_load_is_the_hosts_limit`).
4. `CompileError::StackExhausted` is recognised in the rendering, by a
   whole line `<place>: fatal error: kiln: stack exhausted during
   <phase>; reduce nesting or raise -fkiln-stack-size`: a unit that does
   not compile gives no structured diagnostics and no flag (KN4). A
   transform's text reaches a fatal error's message only quoted.
5. The resource directory is checked as `<resource>/include`, the word
   given to Kiln.
6. §2.3 rule 2 is "the name designates exactly one function":
   `consteval void transform(); consteval void transform() {}` loads
   (`s12_entry_errors`).

## The transform id (§2.2)

1. The target term: the triple Kiln writes and the content digest of the
   predefines buffer.
2. **The host term** (L6): `slip --version`'s line, `slip <version>
   (kiln <version>)`. Without it nothing in the id changed when the
   host's behaviour did (its classification, its operations behind the
   same headers' digests, Kiln's evaluator), and a cache keyed by the id
   (`spec/exec.md`'s M5 cache, future work) could outlive it. The line
   does not tell two development builds of one version apart (both are
   `slip 0.0.0`): a cache that persists across builds must key on the
   build as well. That is for the cache's package to decide; recorded as
   a supervisor decision.
3. The encoding is fixed in §2.2 and pinned by value
   (`s2_2_the_encoding_is_pinned`; the pinned digest changed with the
   host term).

## Runs (§2.4 to §2.8)

1. A run makes a new `Host` with `Limits::default()` and the transform id
   as its `transform`.
2. A completed run's output gets the evaluator's counters
   `api.host_calls`, `api.steps`, `api.peak_bytes` (§7.6 rule 6).
3. **The message and the place** (M2, M3; `spec/edits.md` §4.6), from
   Kiln's structured diagnostics, never from the rendered text. The
   primary is the run's first error. When it is
   `sema_immediate_call_non_constant` ("call to consteval function
   'transform' is not a constant expression",
   `kiln_diag/src/ids/sema_e_m.rs:214`), the cause is its first note with
   no diagnostic id: the Oven's account, which precedes the "in call to"
   notes of the call stack. Otherwise (a Kiln limit reached in an
   instantiation made at run time, `sema_template_recursion_depth`) the
   primary is its own cause. The place is the cause's; when that is in
   `<resource>/include`, the first later note's place outside it, then the
   primary's own. An uncaught `slip::error` is thrown in `<slip/meta.h>`
   and Kiln gives no call stack for an uncaught exception (KN5), so its
   place is the entry's (the primary's); the line of the refused call is
   pending (`s2_8_pending_the_place_of_a_refusal_is_the_call`). Paths are
   as Kiln names them, never made absolute by Slip. Each kind's message
   and place is asserted
   (`s2_8_each_failure_kind_its_cause_and_place_then_a_normal_run`).
4. **Retirement.** These end the use of the transform: every later `run`
   is `Err` without reaching Kiln, and `retired()` says why: a host
   error, a panic during a run, Kiln's stack guard (after or before a
   run), an unknown Kiln failure, and the internal errors `Poisoned` and
   `ForeignEntry`. All but the last two give the unit its outcome
   (`host-failure`), so its failure is recorded with its diagnostics; the
   outcome is for the unit, `retired()` and the next run for the worker.
5. **Classification order** (L1): the host's own error first, whatever
   the result (a run that completed or failed otherwise after a host
   error is not trusted); then Kiln's stack flag; then the result
   (`l1_a_host_error_comes_first`).
6. **An uncaught `slip::error`.** Kiln names the type of an uncaught
   exception as written, unqualified (`kiln_oven/src/notes.rs:237`):
   `slip::v0::error` is `error`. The driver reports the run's most recent
   refusal when the type is `error` and the run has one; the message is
   "an uncaught slip::error; the most recent refusal was: <message>
   (<errc>)". **This is wrong in three cases** (M1), until Kiln WP-2480:
   rethrowing an older `slip::error` after a newer refusal reports the
   newer; a class named `error` in any scope (`own::error`), thrown after
   a refusal, is reported as a `slip::error`; a class derived from
   `slip::error` carries no refusal. §2.8 rule 3 says so; each is a
   pending test asserting the right result (`m1_*`). Two refusals then an
   uncaught one report the second (`s2_8_rule3_of_two_refusals_the_most_recent`);
   a caught refusal then `throw 42` reports no refusal
   (`s2_8_rule3_another_type_after_a_caught_refusal`).
7. **The host's errors** (L2): `Err` from `Host::call`, and the host
   writing more than Kiln gave it room for (counted by the driver's
   `KilnOut`; Kiln would report "host call handler wrote n … into a
   capacity of …", `kiln_oven/src/vm/host.rs:146`), are `host-failure`
   and retire. `RunFailure::Host` with no host error is Kiln's own check
   of the primitive's buffers or a call with no handler: `not-constant`.
   `RunFailure::Unknown` is `host-failure` and retires: the host cannot
   say whose fault it is (`l2_*`).
8. **A panic during a run** (M4): `Loaded::run` contains it with
   `catch_unwind`. The run is `host-failure` "the run panicked: <the
   panic's message>", the transform is retired at once, and the session
   is not used again (`m4_a_panic_during_a_run_is_a_host_failure_and_retires`).
9. **Cancelled** is `Err` and does not retire.
10. **The flag of package rule 6**, as before
    (`rule6_the_handler_refuses_a_call_outside_a_run`,
    `rule6_a_call_from_a_nested_evaluation_does_not_reach_the_host`).
11. **Budgets** are the limits themselves: a run given exactly the steps,
    bytes or depth it used completes; one less fails with the budget's
    kind (`s2_5_rule1_each_budget_exactly`). A step budget smaller than
    an array's bound is Kiln's array-bound limit, `not-constant`, as
    clang's `-fconstexpr-steps` (not a defect). The default step budget
    is minutes of evaluation in a debug build: a plain loop runs about
    7.3 million steps a second (`measure_step_rate`: 1,008,576 steps in
    139 ms), so 2^32 steps take about 590 s; the review measured about
    100 s on its workload. §2.5's table says so.

## The thread and the stack (§2.5 rule 5; H1)

1. **The thread** (H1 a). An instantiation made at run time (reflection's
   `substitute`, then `size_of` or `extract`) on another thread than the
   compiling one is checked against the compiling thread's guard and
   trips it at any depth, by the history of the threads; the flag is
   sticky (KN1). So a `Loaded` is run only on the thread that loaded it:
   it records the loading thread's id, and a `run` from another thread is
   `Err(OTHER_THREAD)`, which names the rule, never reaches Kiln and
   retires nothing (`s2_5_rule5_a_run_away_from_the_loading_thread_is_refused`).
   The behaviour wanted is pending in `slip_kiln`
   (`kn1_pending_a_run_away_from_the_compiling_thread_completes`, Kiln
   WP-2410). Meanwhile WP-092 loads the transform on each thread that
   runs it (its rule 2 is amended).
2. **The stack** (H1 b). The recursions a run can drive at run time, and
   what bounds each:

   | Recursion | Bounded by | Native stack |
   |---|---|---|
   | constexpr calls | the depth budget (4096) | none: the Oven keeps an explicit frame stack (`down(600)` completes under a 32 MiB guard) |
   | class template instantiation (a static member's initialiser; a member's type) | `-ftemplate-depth` | about 36 and 23 KiB a level |
   | alias templates over member types | `-ftemplate-depth` | about 25 KiB |
   | variable templates, nested constant evaluation | `-ftemplate-depth` | about 35 KiB |
   | function templates (explicit arguments) | `-ftemplate-depth` | under 61 KiB |
   | substitution into constraints | `-ftemplate-depth` | under 61 KiB |
   | deduction, substitution into a return type | `-ftemplate-depth` | about 64 KiB (the worst) |
   | lambdas in a template | `-ftemplate-depth` | under 61 KiB |
   | expression nesting within one declaration | nothing of Kiln's (KN3) | about 0.45 KiB a parenthesis in substitution |
   | nested parsing | none at run time: the unit is parsed before any run | — |

   Measured in a debug build, on the compiling thread, from where a
   16 MiB guard trips (`stack.rs` `measure`). The session's template
   depth is 512 (`-ftemplate-depth=512`, §2.1 rule 1), half Kiln's
   default, and the loading thread has `STACK` = 256 MiB (255 MiB under
   Kiln's 1 MiB red zone). At depth 511 every shape completes under a
   64 MiB guard, and deduction (the worst) trips a 32 MiB one; so the
   worst at the limit is between 31 and 63 MiB, and 255 MiB is a margin
   of at least four (about eight by the per-level figure), and holds
   Kiln's own worst estimate of 300 KiB a level (150 MiB at 512). Kiln's
   default depth of 1024 would have needed about 64 MiB for deduction
   alone with no margin; halving it is the change that buys the margin
   at an acceptable stack. The proof is a test at the limit for each
   shape: 511 levels complete, 600 fail with "recursive template
   instantiation exceeded maximum depth of 512" (`not-constant`), never
   "stack exhausted", and nothing is retired
   (`s2_5_rule5_each_recursion_reaches_kilns_limit_before_the_guard`;
   `s2_5_rule5_constexpr_calls_reach_the_depth_budget`).
3. **A trip in a run** (H1 c) is then a host defect: `host-failure` and
   retirement, never a transform failure with the session kept (Kiln's
   flag is sticky). The path is tested with a real trip under a guard
   deliberately too small (4 MiB, 300 levels of a class template:
   `s2_5_rule5_a_trip_in_a_run_is_a_host_failure_and_retires`), and the
   check before a run with a trip made by running the session directly
   (`a_tripped_guard_is_seen_before_a_run_and_retires`); with the flag
   injected (`decided_3_*`) for the classification.
4. **A trip at load** (`<slip/meta.h>` under a 2 MiB guard) is the host's
   limit, `host-failure`, not `transform-compile`.

## §2.6 at this pin

Every context of §2.6 rules 2 and 3 written in the entry or in a template
it names is refused when the transform loads (`transform-compile`,
Kiln's diagnostic at the context's line), the same each time
(`s2_6_each_forbidden_context_is_refused`): such templates are
instantiated when the unit is compiled. A template instantiated at run
time through reflection is the case §2.6 rule 3 describes: a host call in
its template argument fails the run, `not-constant`, the same in each of
three runs, and nothing is retired
(`s2_6_rule3_a_template_instantiated_at_run_time`).

| Context (§2.6 rule 3) | At this pin |
|---|---|
| template argument, array bound, `constexpr` initialiser, `if constexpr`, `case`, `static_assert`, `noexcept`, `explicit` | diagnosed: `transform-compile` in the entry, `not-constant` in a template instantiated at run time |
| a constraint: a requires-expression | **not diagnosed**: the requirement is silently false (KN2, `kn2_a_host_call_in_a_requires_expression_is_silently_false`); the right outcome, a diagnosed failure, is pending (`kn2_pending_…`) |

## Findings for Kiln

Reproducers are in the package's Handback.

- **KN1** (confirmed): a run-time instantiation through reflection away
  from the compiling thread trips the guard at any depth, and the flag
  is sticky (`kiln_sema/src/templ/mod.rs:617`). Kiln WP-2410.
- **KN2**: a host call in a requires-expression is silently false.
- **KN3**: no limit bounds expression nesting (no `-fbracket-depth`); the
  stack guard is the only bound.
- **KN4**: a unit that fails to compile gives no structured diagnostics
  and no stack flag (`SessionRefused::TuHasErrors` carries a count).
- **KN5**: an uncaught exception's diagnostic has no call stack.
- **K5** (WP-2480): the type of an uncaught exception is unqualified
  (`kiln_oven/src/session.rs:356`, `notes.rs:237`).
- **K6**: `RunError::Host` joins the handler's error and Kiln's argument
  check (`kiln_oven/src/session.rs:352-354`).
