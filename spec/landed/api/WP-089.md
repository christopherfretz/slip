# WP-089 — the run driver: compile, check the entry, run, classify

Decided by work package WP-089 where `spec/api.md` §2, §12 and the
package leave a choice. `crates/slip_script/src/driver.rs` is the
implementation; its tests are `crates/slip_script/tests/entry.rs`,
`contexts.rs`, `budgets.rs`, `identity.rs`, `demo.rs` and the unit tests
of `driver.rs`. Kiln file:line citations are at Kiln `913a490bb`.

## Interface beyond the package's

- `LoadError::name()` gives the name of §12 (`internal` for
  `LoadError::Internal`, which §12 does not list: a Kiln panic while
  compiling). `LoadError` is `Display`.
- `Outcome::Failed` has a fifth field, `refusal: Option<host::Failure>`:
  for an uncaught `slip::error`, the refusal reported (its operation,
  status, message and subject place), which `spec/edits.md` §4.6 records
  as "the refusal". `place` is kept as the package wrote it and equals
  `refusal.place`.
- `Loaded::retired() -> Option<&str>`: why the use of the transform
  ended (rule 4 below). `Loaded::triple()` and `Loaded::predefines()`:
  the target terms of the id.
- `transform_id(api_level, command_line, triple, predefines, files)` is
  public: the formula of §2.2, used by the driver and by the tests.
- Constants: `TRANSFORM_ID_TAG`, `ENTRY`, `RESERVED`, `ERROR_TYPE`.
- `Host::new` takes `&(dyn Subject + Sync)` and `Loaded::run` takes
  `subject: &(dyn Subject + Sync)` (the package's "Decided since" item
  1). `Host`, the driver's handler and `Loaded` are `Send`
  (`driver::tests::decided_1_host_and_loaded_are_send`).
- `slip_kiln::session::Session` gains three accessors: `triple()`,
  `predefines()` (the bytes of the virtual buffer `<built-in>`,
  `kiln_pp/src/preprocessor.rs:661`) and `stack_exhausted()` (Kiln's
  sticky flag, `kiln_sema/src/stack_guard.rs:184`).

## Loading (§2.1 to §2.3, §12)

1. The order of the package's rule 1: options, compile, headers,
   reserved names, entry (`rule1_the_first_error_wins`).
2. The refusals of `slip_kiln::session` are passed on: an
   `OptionRefused` is `transform-option` with its text (an option
   outside §2.1 rule 2, a value, file or resource directory beginning
   with `@` or holding a NUL, a relative path, a `-D` whose replacement
   holds `embed`); `CompileError::Diagnosed` is `transform-compile` with
   Kiln's rendering; `CompileError::Embed` is `transform-compile`
   rendered `<path>:<line>: error: `#embed` is not supported in a
   transform`. §12's rows now list these causes.
3. `CompileError::CommandLine` (Kiln stopped before compiling the unit:
   a transform file that cannot be read, or a stop for a reason Kiln
   reports the same way, `docs/requests/KS2-amendment-1.md` §1) is
   `transform-compile` with Kiln's text. Chosen over `internal` because
   the common cause is the author's (a missing file), and the text Kiln
   wrote names it. `CompileError::Panicked` is `LoadError::Internal`.
4. The resource directory is checked as `<resource>/include`, the word
   given to Kiln; a refusal names that word.

## The transform id (§2.2)

1. The target term: the triple Kiln writes (`kiln_abi::Triple`'s
   `Display`) and the content digest of the predefines buffer. The
   predefines carry what the target shows the preprocessor
   (`__x86_64__`, `__SIZEOF_POINTER__`, ...), the triple what it shows
   constant evaluation (layout). The buffer also holds the `-D`/`-U`
   lines, which the command line already has; that is harmless.
2. The encoding is fixed in §2.2 and pinned by value
   (`s2_2_the_encoding_is_pinned`). The tag `slip.transform.v0` is
   registered in `spec/model.md` §3.
3. Only the machine's default target can be made at this pin (an author
   may not give `-target`), so "two targets give two ids" is tested on
   the term's bytes (`s2_2_the_target`); that the loaded id hashes this
   unit's triple and predefines is `s2_2_the_id_is_the_formulas_and_equal_for_equal_inputs`.

## Runs (§2.4 to §2.8)

1. A run makes a new `Host` with `Limits::default()` and the transform id
   as its `transform` (so `RunOutput.transform` is `Script.id`,
   `spec/edits.md` §4.8).
2. A completed run's output gets the evaluator's counters
   `api.host_calls`, `api.steps`, `api.peak_bytes` (§7.6 rule 6), sorted
   in with the host's.
3. `message` is the first non-blank line of Kiln's rendering, except for
   an uncaught `slip::error` (rule 5).
4. **Retirement.** Three things end the use of the transform: every later
   `run` is `Err` without reaching Kiln, and `retired()` says why. They
   are a host error, Kiln's stack guard, and a poisoned session. The
   first two also give the unit its outcome (`host-failure`, with Kiln's
   rendering), so that its failure is recorded with its diagnostics; the
   third has no outcome (the run that panicked unwound to the caller).
   This is how "the driver also returns it as an error of the worker"
   (package rule 5) is met with one return type: the outcome is for the
   unit, `retired()` and the next run are for the worker.
5. **An uncaught `slip::error`.** Kiln names the type of an uncaught
   exception as written, unqualified (`kiln_oven/src/notes.rs:237`):
   `slip::v0::error` is `error`. A class of the transform's own named
   `error` has the same name. So the driver reports the refusal only
   when the type is `error` *and* the run has a refusal; the message is
   "an uncaught slip::error; the most recent refusal was: <message>
   (<errc>)", the place that refusal's. It is the right refusal unless
   the transform stored an error and threw it later, or threw a class of
   its own named `error` after a refusal (finding K5).
6. **A host error** (`Err` from `Host::call`) is `host-failure` and
   retires. `RunFailure::Host` without a host error is not a host
   failure: it is Kiln's own check of the primitive's buffers
   (`kiln_oven/src/vm/host.rs:32`) or a call with no handler, caused by
   the transform calling the primitive, so `not-constant` (§3.5 rules 4
   and 5; `s2_8_each_failure_kind_then_a_normal_run`, mode `primitive`).
7. **Cancelled** is `Err` (§2.5 rule 4: no result at all) and does not
   retire: after `Cancel::reset` the transform runs again.
8. **Poisoned** is `Err` ("internal error: ...") and retires.
   **`ForeignEntry` cannot be reached**: `Loaded` takes its entry from
   its own session in `with_transform`, its fields are private, and
   `run` takes no entry; were it reached, it is an internal error that
   retires (`a_foreign_entry_is_an_internal_error`).
9. **Stack exhausted.** Detected by Kiln's flag (`Session::stack_exhausted`),
   read after every run and before every run, not by the rendered text,
   which a transform could imitate in a comment that a caret line
   quotes. When it is set the run is `host-failure` with Kiln's
   rendering whatever the run's own result (a run that completed while
   it tripped is not trusted either), and the transform retires. This
   holds on the compiling thread too: the flag is sticky there as well,
   and a stack's size is not a budget (§2.5 rule 2). Kiln reports the
   diagnostic once per unit (`kiln_sema/src/stack_guard.rs:191-193`),
   so a later run could fail without it; the driver never makes one.
10. **The flag of package rule 6.** The handler refuses a call while the
    driver's flag is clear, and the driver sets it for exactly the
    duration of `Session::run` (`rule6_the_handler_refuses_a_call_outside_a_run`).
    Since the handler is borrowed by `Session::run` alone, no such call
    can arrive today. The flag cannot tell a nested evaluation *inside*
    a run from the run itself: if Kiln's WP-2073 ever routes a nested
    evaluation to the run's handler, the flag is set. The defence is
    Kiln's ruling (`docs/requests/KS2-amendment-1.md` §4); today a nested
    evaluation has no handler and gets the unit's placeholder
    (`kiln_driver/src/session.rs:62`):
    `rule6_a_call_from_a_nested_evaluation_does_not_reach_the_host`.

## §2.6 at this pin

Every context of §2.6 rules 2 and 3, in the entry and in a template it
instantiates, is refused when the transform loads (`transform-compile`,
Kiln's diagnostic at the context's line), the same each time
(`s2_6_each_forbidden_context_is_refused`). §2.6 rule 3 says a template
case "fails the run that first instantiates it"; at this pin every
template an entry uses is instantiated when the unit is compiled
(`spec/landed/api/WP-080.md`, s1), so it is found earlier, which is the
safe direction. No run-time instantiation could be made, so "the same
failure in each of three runs" is tested on the load (three loads, one
error) and on runs that call the host legitimately
(`s2_6_rule1_the_run_may_call_the_host`).

## Findings for Kiln

- **K5. The type of an uncaught exception is unqualified.**
  `RunError::Uncaught.type_name` comes from `Oven::tname`
  (`kiln_oven/src/session.rs:356`, `notes.rs:237`), which writes the
  type as spelled: `slip::v0::error` is `error`. A client cannot tell its
  own exception type from a transform's class of the same name. Wanted:
  the qualified name, or the class's `DeclId`. Until then rule 5.
- **K6. `RunError::Host` joins two causes.** The handler's error and
  Kiln's own check of the primitive's arguments are one kind
  (`kiln_oven/src/session.rs:352-354`, `vm/host.rs:32`, `:137`). Slip
  tells them apart by recording its handler's errors (rule 6). A
  distinct kind for the argument check would make that unnecessary.
  Small; not on the critical path.
