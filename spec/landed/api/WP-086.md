# WP-086 — slip_script: the subject over Kiln: calls and expression extents

`crates/slip_script/src/kiln_subject/calls.rs` brings `spec/api.md` §6.7,
§6.6 rules 3 and 4 and §7.4 rule 3 (for expressions) to `KilnSubject`.
Tests are in `crates/slip_script/tests/subject_calls.rs`. This file
records what was built, the table of extents, what the spec left open
and how the code decides it, and what the tests measured.

## What was built

- **The index** (`call_index`, built once on the first question about
  a call or a live expression). One iterative walk (an explicit stack;
  no recursion) from the translation unit over every written
  declaration: a template's requires-clause and pattern, a concept's
  constraint, a friend's target, a function's default arguments,
  trailing requires-clause, contracts, member initialisers as written
  and body (not a defaulted function's), a variable's initialiser, a
  field's bit width and default member initialiser, an enumerator's
  value, a `static_assert`'s condition and message, and the members of
  every namespace, class, enumeration and linkage specification; and
  the expressions written in types and heads (review F4): a
  declaration's type as written (an alias's or typedef's target; a
  function's return and parameter types and `noexcept`), a template's
  parameters' types and default arguments, a class's bases, a fixed
  enumeration's base, `explicit(…)`, the attributes `alignas`/`aligned`
  (expression or type), `assume`, `enable_if` and `diagnose_if`, a type
  requirement, and the types an expression writes (a cast's, `sizeof`'s,
  `new`'s, `T()`'s, a name's qualifier and template arguments, a
  lambda's call operator's). A type is walked through what is written
  in it (pointers, arrays, function types, `decltype`, specialisations'
  arguments, qualifiers, pack expansions and indexing, `typeof`,
  splices), never through what a name stands for (a typedef's
  underlying type at its use, a deduced or substituted type).
  Statements and expressions are walked by their written parts only: a
  range-for's init-statement, range initialiser and body; an expansion
  statement's pattern (never its expansions); a `co_return`'s and a
  `co_await`'s or `co_yield`'s operand (not the calls Kiln makes for
  them); a coroutine's body as written; a lambda's captures'
  initialisers, its call operator's default arguments and contracts and
  its body; a statement expression's statements; a requires-
  expression's requirements. Instantiated and implicit declarations are
  skipped, so a call in a template is found once, in its pattern
  (§6.7 rule 2). Calls are sorted into unit order (`spec/api.md` §1) by
  their first token, then their callee's name, then the arena.
- **`calls_to(f)`**: the calls whose callee's origin is `f`'s origin, in
  unit order; `wrong_kind` as before for what is not a function or a
  function template.
- **`callee(x)`**: the function called, as resolved (its entity).
- **`callee_reference(x)`**: the written-reference table's entry whose
  name starts at the callee's location, in the role of an expression or
  member name (or of a template name: a member named after `template`,
  `d.template t<int>()`), whose referent is the callee's declaration.
  Never null: an expression of rule 1's shape without such an entry is
  not a call (`calls_without_reference()` counts them).
- **Every expression of rule 1's shape is returned or counted** (review
  F2; `spec/api.md` §6.7 rule 8): `call_of` sorts each call expression
  the walk visits whose callee is a name of a function into a call,
  `NoReference` (counted by `calls_without_reference()`) or
  `NotWritten` (its stored closing token is not a `)` after the callee:
  a conversion function's implicit call, a user-defined literal;
  counted in `extent_census().not_written`). `extent_census().visited`
  is the sum. Whether a call is written `callee ( … )` is decided by
  the token Kiln stores (`Tokens::kind_of`), never by the order of
  locations: inside a macro expansion Kiln numbers an argument's tokens
  after the body's, so `#define CALL1(fn) fn(1)` once put `)` "before"
  `f`.
- **`arguments(x)`**: the call's arguments without a default argument,
  each without what Kiln wraps around it (below), and without the
  object of a call to a function with an explicit object parameter:
  written before the callee (the callee's entry has the member-name
  role), or implicit (review F3: `f(2)` in a member, where Kiln's first
  argument is made from the implicit `this`, through a dereference and
  a copy that has no closing token).
- **`extent(x)`** of an expression: the range of its first and last
  token (the table below), through `slip_kiln::ranges::file_range_of_tokens`;
  null when the table has no row, or a row's condition fails.
- **`tiers(r)`**: for a range that is the extent of a live expression,
  the tiers it is reached at.
- **`place(x)`** of an expression: its extent; else the outermost macro
  invocation its first token came from (`Nearest`); else `Unnamed`.
- **`holder(x)`** (`pub(crate)`, for WP-095): the namespace- or
  class-scope declaration, as written, that the walk entered to reach
  `x`.
- **`slip_kiln`**: `Tokens` (`Unit::tokens()`) and
  `ranges::file_range_of_tokens`: the range from one token to another,
  by Kiln's `token_end`. The subject computes no range and no end of a
  token of its own.
- For tests: `extent_census()`, `no_extent(x)`, `call_sites()`,
  `file_path(f)`.

Live expressions are exactly the calls and their arguments (§5.1): any
other expression number is not live.

### What Kiln wraps around a written expression

Skipped (the "transparent" nodes), on an argument and wherever the
table descends: an implicit conversion; a temporary's materialisation,
binding or cleanup; a constant's wrapper; an initializer list's backing
array; the implicit call of a conversion function (Kiln stores no `)`
for it, or one at the callee), which is its object; an implicit
construction with no `)` of its own from one written argument that
begins where the construction is (`h({1})`, a construction at `{` from
`1`, is not transparent: the braces are in no node).

## The table of extents

An extent is the first token of an expression to its last. Kiln's
`begin_loc` and `end_loc` are not exact for every kind (KE1), so each
row says where the two tokens come from and why they are exact. A row
that cannot establish its token gives null (§6.6 rule 4: a wrong
extent is worse than none). "Stored end" is the closing token Kiln
records on the node (`ExprArena::end_loc`), "loc" the node's location.

| Kind | First token | Last token | Why exact |
|---|---|---|---|
| Integer, floating, character, `bool`, `nullptr`, `__null` literal | loc | loc | one token |
| String literal | loc | stored end, else loc | Kiln stores the last piece of a concatenation; one piece has none |
| `this` (written) | loc | loc | one token; an implicit `this` is null |
| `( e )` | loc | stored end | the parentheses are the node's |
| Lambda | loc (`[`) | stored end (`}`) | Kiln's |
| `{ … }` | loc | stored end | the braces |
| `static_cast` and the three others | loc (the keyword) | stored end (`)`) | Kiln's |
| `sizeof`, `alignof` | loc | stored end, else the operand's last | `sizeof x` has no `)` |
| C-style cast | loc (`(`) | the operand's last | the operand ends it |
| Prefix unary operator | loc (the operator) | the operand's last | |
| Postfix `++`/`--` | the operand's first | loc (the operator) | |
| Name (`DeclRefExpr`) | the table entry's first, `::` included | the name | the entry and Kiln's begin agree, the qualifier is linked, the name is one token, no template arguments |
| Member access `a.m`, `p->m` | the base's first | the member name | as for a name |
| Member named without `this` | the entry's first | the member name | as for a name, not `::`-led |
| `T(x)`, `T{x}` | loc, when the type is named there by an entry not led by `::`, or is a keyword type (`int(2)`) | stored end | the type's name is the first token |
| Call, member call | the callee's first (the object's, for an explicit object) | stored end (`)`) | written `callee ( args )`: the `)` after the callee |
| Subscript | the base's first | stored end (`]`) | |
| Binary, compound assignment | the left operand's first | the right operand's last | |
| Conditional | the condition's first | the else arm's last | |
| Overloaded operator written as one | prefix: loc; else the first operand's first | prefix: the operand's last; binary: the right's last; postfix: loc; `()` and `[]`: stored end; `->`: none | the operands are written where Kiln's arguments are; `p->m`'s last token is the member access's, so `p->f(1)` and `p->x` have extents and the bare `operator->` call has none |

Two conditions hold over every row:

- **A name of a specialisation has no last token** (`d.twice<7>`, a
  member variable template): Kiln records no template arguments on a
  member access, so the name may be followed by arguments the node
  does not cover.
- **An argument's range is all of the argument**: the token before it
  is `(` or `,` and the token after it is `,` or `)`, in the token
  stream the parser read after macro expansion
  (`Tokens::expanded_kinds_around`; review F1). From a first token at the
  start of a macro entry the walk moves to where the entry stands (the
  parameter an argument replaced, the invocation a body replaced), as
  Kiln's `file_loc_at_macro_start` does; inside an entry the neighbour
  is the token spelled beside it, which must be in the entry; an
  argument split over several entries has no known neighbour (null).
  Never the tokens beside the file range: at tier 1 they are the
  invocation's, so `#define M(a) f({a})` once gave `M(x)` the argument
  «x», though the written argument is `{x}`. Otherwise the argument is
  null with the reason "not all of the argument". Kiln leaves no node for written
  tokens of some arguments: the braces of `f({x})` when `x` alone
  initialises the parameter ([dcl.init.list]/3.2), so the argument's
  node is `x` and a range of it is too short.

Null for every other kind, among them: `new` and `delete`, `noexcept`,
a user-defined literal (a `CallExpr` whose stored end, the literal, is
before its callee, the suffix), a rewritten comparison, a pack
expansion, a fold expression, `typeid`, `throw`, a requires-
expression, a construction that is not transparent, an implicit `this`.

A name whose qualifier has a component the written-reference table
does not link (`decltype(x)::f`, a pack index, a splice) is null: the
table's first token would be after the qualifier's start.

## Decided where the spec was silent

1. **A pack expansion argument is not reachable in version 0.** A call
   whose arguments hold `args...` has a dependent callee (an unresolved
   lookup), so it is no call (§6.7 rule 2). Rule 5's last sentence holds
   vacuously; the extent table has no row for a pack expansion.
2. **The holder** is the declaration at namespace or class scope, as
   written (a template for its pattern), whose body or initialiser
   holds the call: a local class's and a lambda's calls are their
   enclosing declaration's (`spec/digest.md` §2.1: units are namespace-
   and class-scope entities).
3. **Reference numbers** are the index of the entry in Kiln's
   written-reference table, plus one. Whether a reference is live is an
   interim rule here (a role of §6.5 rule 3 and a live referent) until
   WP-085 gives its own; the numbering is the one WP-085 must keep.
4. **A template's head is walked** (reversed in the review, F4): the
   parameters' types and default arguments, and its requires-clause,
   are expressions of the unit (§6.7 rule 3: every call of the unit).
5. **`place` of an expression with no extent** is `Nearest` with the
   range of the outermost invocation its first token came from, when
   that is a range of the subject; otherwise `Unnamed`.
6. **`display` of an expression** says what it is and where
   (`a call at path:line:column`): never text of the code.
7. **`api.calls_without_reference`** is the method
   `KilnSubject::calls_without_reference()`: the `Subject` trait has no
   counters. Proposed in the hand-back of `docs/wp/WP-086.md`.
8. **`slip_kiln` gained `Tokens` and `file_range_of_tokens`**: the range
   from a first to a last token by Kiln's `token_end`, so that no range
   is computed in `slip_script`. Then `Tokens::kinds_around(file, lo,
   hi)` (the kinds of the tokens beside a file range, by Kiln's lexer),
   `Tokens::kind_of(loc)` and `Tokens::expanded_kinds_around(first,
   end)` (the neighbours after macro expansion), for the argument
   condition and the postfix test.
9. **An argument whose range is not all of what is written between
   its `(`/`,` and `,`/`)` is null.** §6.6 rule 4 says a wrong extent is
   worse than none; the argument's written tokens are known from the
   call's punctuation even where Kiln's node is short of them.
10. **A call through an overloaded `->` (`p->f(1)`)** has an extent: its
    first token is the object's and its last the call's `)`. The bare
    `operator->` call Kiln makes has none (no last token is written for
    it).
11. **A destructor called by name (`p->~D()`) is not a call of version
    0** and is counted without a reference: Kiln's table entry for it
    names `D` after `~`, not the callee's location, so there is no
    reference of rule 1 to return. A pseudo-destructor call (`ip->~I()`
    for a scalar `I`) calls no function and is neither a call nor
    counted.
12. **A member named after `template`** (`d.template t<int>()`,
    `p->D::template t<long>()`) is a call: the table gives its name the
    template-name role, which `callee_reference` accepts.
13. **Holes of version 0** (§6.7 rule 8): a call in an array bound
    written in a declarator (`int a[f(2)]`, `sizeof(int[f(13)])`, a
    parameter `int (&x)[f(19)]`): Kiln folds the bound and keeps no
    expression (For Kiln 4); the pending test
    `s6_7_rule3_pending_in_an_array_bound` holds the reviewer's lines.
    And a call in the arguments of an attribute other than `alignas`,
    `aligned`, `assume`, `enable_if`, `diagnose_if`.

## What a consumer must not assume (WP-084's seven points)

1. Implicit nodes: no call is one Kiln makes (a conversion function's, a
   range-for's `begin`/`end`), and an implicit `this` is not where a
   member call begins (`wp084_point1_…`).
2. A header entered twice: each entry's call is a call of its own, and
   both have the one range (`wp084_point2_a_header_entered_twice`).
3. A tier 1 extent changes every use of the macro argument
   (`wp084_point3_an_argument_used_twice`).
4. No extent ends at a token led by `>`: an extent ends at `)`, `]`,
   `}`, a name, a literal, `this` or `++`/`--` (the table), so the
   interim refusal of a split `>` never applies.
5. `#embed` misordering affects unit order only, and no call is made of
   an embed's tokens.
6. A recoded file gives no extent (`wp084_point6_a_recoded_file_gives_no_extent`).
7. Begin and end out of order: the extent comes from the table, not from
   `begin_loc`/`end_loc`; a rewritten comparison is null
   (`wp084_point7_out_of_order_has_no_extent`).

## The differential against clang 19 (test 7)

`item7_differential_against_clang` parses each unit with Kiln, through
the subject, and with `clang++-19 -fsyntax-only -Xclang -ast-dump=json
-nostdinc -nostdinc++ --target=x86_64-unknown-linux-gnu` (the side's
`-std`, arguments and target). The units are both sides of every
digest pair test and every test of Kiln's `tests/codegen` (C++26).
Calls are matched by the file and offset of their `)`. For each call
of the subject whose `)` was written in a file, the call's extent and
each argument's extent, when not null, must be the range clang gives
the same node (`[begin.offset, end.offset + end.tokLen)`). A unit either front end
rejects is skipped. With no `clang++-19` on `PATH` the test prints
`SKIP` and passes, and it fails under `SLIP_REQUIRE_ALL=1`.

Clang 19 begins a call to a function with an explicit object parameter
(`b.xobj()`) at the callee, not at the object (its
`CallExpr::getBeginLoc`; clang 20 begins it at the object). The test
moves clang's begin to the object's, at every depth (such a call can be
an argument); our extent begins there (§6.6 rule 3: the first token).
Through `p->`, clang's object is an implicit `*p` with no begin: its
first child's is taken. Kiln's tests marked `//@ skip(clang)` are left
out (one of them, `temp.expl.spec/member-class-template-spec-nsdmi.cpp`,
makes clang 19 hang).

With `SLIP_WP086_CONFORMANCE=1` the test also takes every test of
Kiln's `tests/conformance` (C++26). That run
takes about three minutes in a debug build, so it is not in the gate.

The review round (F7) added the reverse direction and calls through
macros. A call whose `)` comes from a macro is keyed by where clang
spelled that `)` and where its outermost invocation begins; a subject
extent of tier 1 is compared with clang's spelled range, one of tier 0
must begin where clang's outermost invocation begins and cover its last
token. The reverse direction takes each clang call (`CallExpr`,
`CXXMemberCallExpr`, `CXXOperatorCallExpr` of a named function) whose
`)` byte is a `)` in a file, and reports those the subject has no call
for, by kind and by context (in an instantiation, in an implicit or
defaulted declaration); written ones are listed. Clang's JSON holds no
types, so on clang's side a call in a type is seen only in a template
parameter's default, an `alignas` and an alias target.
`review086_differential_on_the_review_programs` (in the gate where
`clang++-19` is present) runs both directions on the reviewer's
programs (`M`, `N`, `P`, `R`, `CALL1`, `CALL`, `X`, `MEM`, and the three
type forms clang shows) and requires no difference, no clang call
missing and at least four comparisons through a macro; it kills the
mutants that undo F1 (N4), F2 (N1) and F4 (N12, N13, N14, N21).

review round:

  compared). 53 have no clang call: clang 22 builtins under
  `__has_builtin`, calls in initializer lists with an array filler, and
  calls in types clang's JSON does not show (`noexcept(…)`, template
  arguments in types). Extents: 6,958 equal, 2 equal through a macro,
  2,932 null (2,794 of them in calls closed by a macro: tier 0 is given

- **Reverse, default set**: 4,909 clang calls with a written `)`; 71

test correction: explicit-object calls nested in arguments (the test),

Survivors, each a guard that answers the same as the condition before it
on the Kiln Slip builds against:

- M1 (`postfix` without `close != callee loc`): the stored closing token
  must also be a `)`, and a callee's location is a name, never a `)`.
- M13 and R-unq-first (an unqualified name without the check that
  Kiln's begin is the table's first), R-global-le (a `::`-led name's
  begin allowed at the table's first, `is_le` for `is_lt`),
  M17 (`type_first` allowing a `::`-led entry): on this Kiln the begin of
  an unqualified name is its name, and the location of `::S(1)` is the
  `::`, where no entry starts. The checks guard against a Kiln that
  disagrees with its table; the differential would show it too.
- M14 (a `decltype` qualifier taken as linked) and R-qual-decltype
  (`PackIndexing` in that check): the table places no first token
  before a name after `decltype(…)::` (its first is the name), so the
  qualified arm is refused by `r.first != r.name.lo` first
  (`s6_6_rule3_a_callee_after_decltype_and_a_conversion_in_parentheses`
  pins the null). A pack index is written only in a template, where the
  qualified name is dependent and never a `DeclRefExpr`.
- M15, M16 (`name_last` allowing template arguments, or a name of
  several tokens): a name's last token matters only as an argument's
  last token, and there the argument condition refuses a short end (the
  token after it is `<` or `::`, not `,` or `)`). The checks keep a
  wrong last token from reaching any other use.
- R-closes-brace (`}` accepted after an argument): an argument that is
  followed by `}` lost its braces in Kiln (only a single-element list
  does: `f({x})`, For Kiln 2), and then the token before it is `{`, so
  the condition on the token before refuses it first. A list of several
  elements is a node with its braces.
- M23 (a `co_await`'s children walked), M24 (a range-for's `__begin`
  initialiser walked), M25 (a defaulted function's body walked): Kiln's
  calls there have no `)` after their callee, or no table entry, so
  `call_of` refuses them (`s6_7_calls_in_a_coroutine`, `wp084_point1_…`,
  `s6_7_rule2_a_call_in_a_template_is_returned_once` check that no call
  and no counted reference comes from them).
- M26, M27 and R-type-anyrole (`reference_index` or `type_first` with
  any role, or any referent): Kiln's table has one entry per name
  location in these roles.
- N7, N8 (inside a macro entry, the spelled neighbour taken even outside
  the entry): an entry's tokens are one run of its spelling, so the
  token beside a token that is not at the entry's edge is in the entry.
- N10 (any first argument of an explicit-object function called by an
  unqualified name taken for the implicit object): such a call names
  the function without an object only inside a member, where Kiln's
  first argument is the implicit `this`; `S::f(s, 2)` is ill-formed
  (clang: "call to non-static member function without an object
  argument").

What this says for KE1's priority:

- **Macros dominate** ("no range of tier 0 or 1": 96 to 99% of null
  calls). These are calls written in a macro's body (`__glibcxx_assert`,
  `APFLOAT_DISPATCH_ON_SEMANTICS`, `.def` X-macros), whose tokens are
  not all spelled in one file range. Exact `begin_loc`/`end_loc` from
  Kiln would not change them; the macro work of the design would.
- **Dependent kinds** (the arguments in templates: unresolved lookups,
  dependent member accesses, unresolved constructions) are the next
  group, 180 to 370 per unit. Their tokens are in no row because Kiln's
  begin and end for them are not checked here; KE1 for these kinds
  would turn most of them into extents.
- Kiln's gaps proper are small: 28 + 17 anonymous-union members with no
  table entry, 2 qualified names whose begin is not the qualifier.
- None is null by the two conditions over every row (an argument that
  is not all of what is written, a specialisation) in these units.

## For Kiln

1. **A qualified name's begin is its name** when a member calls a
   static overload through its class: `begin_loc` of the `DeclRefExpr`
   `Q::f` in

   ```cpp
   struct Q { static int f(const Q&, int); int f(int) const;
              int g() const { return Q::f(*this, 1); } };
   ```

   is `f`, though the qualifier is recorded. There is no `expr_begin`
   entry for it and the fallback at `kiln_ast/src/ast.rs:289` returns the
   location. Slip refuses (the "qualifier" reason); 2 in SemaExpr.cpp.
2. **No node for the braces of a single-element list**
   ([dcl.init.list]/3.2): in

   ```cpp
   struct O { bool a = false; long b = 0; };
   int f(const O&); int g(O);
   int use(O x) { return f({x}) + g({x}); }
   ```

   each argument is the node of `x` (through a reference binding or a
   copy construction), and no node covers `{` `}`
   (`kiln_sema/src/init.rs:306-325`; the reference path near
   `init.rs:2236`). Clang's range of the argument includes the
   braces. Slip refuses (the argument condition).
3. **A member variable template's template arguments are not
   recorded**: `d.twice<7>` and `p->twice<2>` in

   ```cpp
   struct V { template <int N> static constexpr int twice = 2 * N; };
   int k(int); int use(V d, V* p) { return k(d.twice<7>) + k(p->twice<2>); }
   ```

   have no `member_extra` (`kiln_ast/src/expr.rs:1834`), so the node's
   end is the name and the `<7>` belongs to no node. Slip refuses (the
   specialisation condition).
4. **No expression for a constant array bound**: in

   ```cpp
   constexpr int f(int x) { return x; }
   int arr[f(2)];
   ```

   the array type has `size_expr: None` once the bound folds to a
   constant (`kiln_sema/src/decl.rs:1828`, also `2304`, `2321`, `2325`,
   and `kiln_sema/src/templ/subst/types.rs:451`), so the call `f(2)` is
   in no node a walk can reach from the declaration. The same for
   `sizeof(int[f(13)])` and a parameter `int (&x)[f(19)]`. Slip names it
   a hole of version 0 (§6.7 rule 8) with the pending test
   `s6_7_rule3_pending_in_an_array_bound`. Asked: keep the written
   bound's expression on the constant array type (as the dependent and
   variable-length forms do).
