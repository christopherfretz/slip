# WP-082 — the resource headers: where they live, how they are checked

Decided by work package WP-082 where `spec/api.md` §2.1 and §2.2 and the
package leave a choice. `crates/slip_script/src/resource.rs` is the
implementation; `crates/slip_script/tests/header.rs` the tests.

## Interface beyond the package's

`slip_script::resource` also has `RESOURCE_DIR_VAR`
(`"SLIP_RESOURCE_DIR"`), `HEADERS: [Header; 2]` (each with its path under
the resource directory, the name errors use, its bytes, `digest()` and
`path_in(resource)`; `meta.h` first), `meta_h_digest()`,
`intrinsics_h_digest()`, `HeaderError::NAME` (`"transform-header"`) and a
`Display` for `HeaderError` that starts with `transform-header: `. The
names `HeaderError` carries are `slip/meta.h` and `slip/__intrinsics.h`.

## The resource directory

1. **An empty `$SLIP_RESOURCE_DIR` is not set.** An empty path would name
   the current directory by accident; it falls through to the next rule.
2. **"Else" means "else if it is a directory".** The installed directory
   `<directory of the executable>/../share/slip/resource` is used if it is
   a directory; else the repository's `resource/` this crate was compiled
   from (a path fixed at build time) if that is a directory; else the
   installed path, so that the error a missing header later raises names
   where an installed Slip looks. Whether a directory holds the right
   headers is not looked at here: the header check decides that.
3. **No path is canonicalised.** The variable's value is used as given and
   the executable's directory as `exe` gives it; `..` is not resolved. The
   resource directory enters `TransformId` "as given" (§2.2), so resolving
   it here would change identities for no rule's sake.

## `write_to` and `slip resource --write`

4. **Only the two headers are written**, at `include/slip/` under the
   directory: they are the embedded files. The examples are not embedded.
5. **A file already there is replaced**, through a temporary file beside it
   (`.<name>.<pid>.tmp`) renamed over it, so a transform compiled at the
   same moment reads whole bytes. Other files are left alone; a failure
   leaves the files written before it. The command prints nothing; its
   errors are status 3 (`spec/exec.md` §8.7).

## The header check

6. **Paths are compared as paths, not as bytes and not resolved.** A read
   path matches `<resource>/include/slip/<file>` when the two have the same
   components (`std::path::Path` equality): a doubled or trailing `/` and an
   interior `.` do not matter; `..`, symbolic links and relative against
   absolute do. This never accepts a file outside `<resource>`, and refuses
   a path that reaches it by another spelling, which is the conservative
   side of "the two under `<resource>/include/slip/`".
7. **Order and repeats.** `meta.h` is checked before `__intrinsics.h`, so a
   unit that read neither is `NotRead("slip/meta.h")`. If the same path
   appears more than once, every entry must have the embedded digest
   (`Differs` otherwise).
8. **The digest is the content digest** (`spec/model.md` §3,
   `BLAKE3(bytes)`), the same as the "digest of its content" in
   `TransformId`.

## The second compiler (test 3)

9. **Which compilers.** Every distinct compiler (by the file it resolves to)
   among `g++`, `g++-14` to `g++-16`, `clang++`, `clang++-19` to
   `clang++-22` found on `PATH` that accepts `-std=c++26 -fsyntax-only` on
   an empty `main` is used; each is named, with its `--version` line, on the
   test's standard error, written so the harness does not capture it. With
   none, the test prints `SKIP …` and passes, unless `SLIP_REQUIRE_ALL=1`
   (`spec/harness.md` §1 rule 3), where it fails.
10. **The one allowed warning** is a line containing `__call` and either
    GCC's "used but never defined" or Clang's "is not defined"
    (`-Wundefined-inline`). Any other warning, or any `error:`, fails. The
    warning is not required to appear.
