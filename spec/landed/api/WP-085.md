# WP-085 — slip_script's subject over Kiln: references, ranges and text

`crates/slip_script/src/kiln_subject/references.rs` brings `spec/api.md`
§6.5 (references), §6.6 (ranges of references and declarations), §7.2
rule 1 (`references_at`, `found_directly`), §7.4 rule 3 (places), §5.4 and
§7.3 rule 2 (`tiers`) and §6.5 rule 6 (the unresolved-name counter) to
`KilnSubject`, and makes "written" (§6.4 rule 3) Kiln's
declaration-extent table's answer. Tests are in
`crates/slip_script/tests/subject_references.rs`; WP-083's in
`tests/subject_entities.rs` still pass, two of them with the answers this
package was to flip. This file records what the spec and
`docs/wp/WP-085.md` left open and how the code decides it.

## Everything is read when the subject is made

`Unit` is not `Sync` (it holds the Oven), and `Unit::token_end` and
`Unit::is_token_start` are the only end of a token and the only token
starts (WP-084). So `KilnSubject::new` and `from_snippet` read both of
Kiln's tables once, through `slip_kiln::written` (`written_refs`,
`decl_names`, `row`, `dependent_names`), and keep what they derive: one
record per reference (referent, first token, name range, extent, nearest
place, found directly), the name range or nearest place of each
declaration `decl_names` gives, the tiers of every range given out, the
unresolved names by spelling, and one bit per written declaration. Only
what needs no unit is built on first use: the references by origin (and
each `references_to` answer, sorted once), and the references by extent.

Making a subject **fails** over a unit parsed without the tables
(`slip_kiln::written::recorded` false): `Result<KilnSubject, String>`.

## Decisions

1. **A reference** is one `written_refs` entry in a role of §6.5 rule 3
   (Kiln's `Expr`, `Member`, `Nns`, `Type`, `Template`, `Base`,
   `MemInit`) whose referent, as the subject numbers entities, is a live
   entity (a label, a contract's result name are not:
   `s6_5_rule3_referents_that_are_not_entities`). Kiln's stage 3 roles
   (using-declaration and -directive, namespace alias, elaborated,
   specialisation target, concept, designator) are §6.5 rule 4's and are
   skipped. So are the entries Kiln records in a rule 3 role as
   **components of a declarative chain**: the qualifier of a
   declarator-id, of a class head, of an explicit specialisation's name,
   of a using-declaration, of a using-enum-declaration's enumeration and
   that enumeration's name, of a friend's elaborated specifier. Every
   component of a qualifier chain has the chain's first token as its
   `first` (`slip_kiln::written`), so a context is a set of first tokens:
   each declaration-extent row's `qual` (a using-enum-declaration's
   `name` when it has no qualifier). The `first` of an entry in a role of
   rule 4 would be one too, but Kiln records no such entry yet (stage 3
   of its table: no `UsingDecl`, `UsingDirective`, `NamespaceAlias`,
   `Elaborated` or `SpecTarget` entry is made), so that code was removed
   (mutant N6). A name written inside the chain that is not one of its
   components (a template argument: `n::W<n::A>::k`'s `n::A`) has a
   `first` of its own and is returned (fix round, B3, decided:
   `s6_5_rule4_a_template_argument_inside_a_declarator_qualifier`). A
   namespace alias's target has no row `qual` and no entry (Kiln records
   only its qualifiers), so a using-directive and a namespace alias are
   taken whole: every name inside them (`s6_5_rule4_using_directive_and_alias_whole`).
   A row that is another declaration's (Kiln K3, decision 14) gives its
   `qual` only when the declaration that overwrote it is a friend: in
   `struct n::S *p;` both `n` and `S` are type names of rule 3 and are
   returned (`kiln_hole_k3_a_qualified_elaborated_specifier_overwrites_the_row`),
   in `friend struct a::b::S2;` neither is (`s6_5_rule4_friend_reference`).
   A using-enum-declaration is declarative (fix round, B2:
   `s6_5_rule4_using_enum_declaration`). This replaces the earlier
   interval test ("between `qual` and the name"), which also dropped
   template arguments and cost 15 to 25 s per LLVM unit before its
   indexing.
2. **"An elaborated or friend reference"** (rule 4) is Kiln's
   `Elaborated` role: an elaborated type specifier that declares (`class
   X;`, `friend struct S;`). One inside a type (`struct S *p;`) is a type
   name, as Kiln records it (Kiln `spec/ast.md` §19, the role table) and
   as `spec/landed/edits/WP-067.md` lists it, and is returned
   (`s6_5_rule4_elaborated_type_specifier_is_a_type_name`). §6.5 rule 4
   now says so.
3. **One written name is one reference.** Entries equal in the origin of
   their referent (decision 9), where the name's first character is
   spelled (file and offset), the outermost macro invocation it came
   through, name range, extent and found-directly are one reference,
   whose referent and first token are the first entry's: Kiln records the
   entries of one written name in the order they were preprocessed, which
   is unit order (keeping the earliest by unit order instead never changed
   an answer; mutant M24). The role and the referent are not part of the
   key: a name Kiln records twice (a template's name as a template and as
   the type its arguments make) is one reference, so no two references
   one `references_to` returns have one name range (fix round, 8a:
   checked by test 9's property over the pair corpus and the LLVM units).
   So an argument a macro uses twice, a header without a guard entered
   twice, an X-macro file read under two definitions of its macro, a
   default member initialiser used by two constructors give one reference
   per written name, while one written name that resolves to two
   entities of different origins in two entries gives one reference to
   each (`s6_5_rule1_a_header_resolving_differently_in_two_entries`), and
   two names written in one macro body are two
   (`s6_5_rule1_two_names_in_one_macro_body`).
4. **`name_range`** of a reference or a declaration is
   `kiln_subject::name_token`, **the one rule for a name token**
   (`spec/edits.md` §9.7: the native rename and a transform see the same
   ranges). It is `slip_kiln::ranges::token_range_or_why` of Kiln's name
   span (the range of the one token at its start, the rule
   `slip_kiln::sites::Sites::name_token` uses), kept when that token is
   the one spelled where the name's first character is (not an invocation
   holding it: `ID(foo)`, `#define foo2 foo`, `#define c c`) and its bytes
   are the referent's (or declaration's) identifier (not written with a
   line splice or a universal-character-name). An operator, constructor,
   destructor or conversion function has the empty identifier (§6.3), so
   it has no name range. The subject cannot call `Sites::name_token`
   itself (see "For the coordinator" below), so
   `wp085_one_name_rule_with_sites_over_digest_pair_tests` asks both for
   every name of every pair-test side written to disk (4 940 units,
   42 138 names: no disagreement), and the measurement asks both for every
   name of the three LLVM units. Both tests stay in the suite.
5. **`extent`** of a reference is the range of the span from its first
   token to the end of its name (WP-084's `file_range_of_span`). The first
   token is the table's `first` (the outermost qualifier component the
   table links), with three rules:
   - a **leading `::`** (the entry's `global`): the token just before
     `first`, on the line where `first` is spelled and in `first`'s own
     entry, lexed by Kiln (`is_token_start`, `token_end`), must be `::`
     (comments and blanks between are allowed, `:: /* x */ a::b`). When
     `first` comes from a macro whose invocation starts the name's range
     at tier 0 (`::NS::c` with `#define NS a`), the token before the
     invocation is looked at instead. Not found: no extent
     (`s7_4_rule3_global_not_found_then_the_written_rest`; `G a::c` with
     `#define G ::`, `::` ending a line, `GQ(a)::c` with `#define GQ(x)
     :: x`: `s6_6_rule4_extents_that_are_not_found`);
   - **an unlinked qualifier** (fix round, A1): when the entry has no
     `global` and the token just before `first` is `::`, a qualifier the
     table does not link (`decltype(s)::m`, a pack-index-specifier) ended
     the chain, and where the written name starts is not known: no extent,
     never one too short
     (`s6_6_rule2_an_unlinked_decltype_qualifier_gives_no_extent`). A
     pack-index-specifier needs a pack, so a template, where the name is
     dependent and not returned
     (`s6_6_rule2_a_pack_index_qualifier_is_dependent`);
   - an **unqualified destructor name** (`p->~T()`), whose entry starts
     at `T`: the token just before must be `~` or `compl`, and starts the
     extent (`p->TL S()` with `#define TL ~`: none). A qualified one
     (`p->T::~T()`) starts at its qualifier.
   A name range outside its extent would make §7.2 rule 1 fail; it was
   never seen (a `debug_assert!`), and both would then be null.
6. **Ranges are `slip_kiln::ranges`'** and nothing else: this module
   decides which span to ask about and refuses answers (decision 4; a
   range in a buffer that has no subject path; a range in a file Kiln
   recoded on loading, whose offsets are not the file's bytes,
   `s5_4_a_recoded_file_gives_no_range`). Extents use `file_range_of_span`:
   every span comes from a table with its end, so WP-084's interim
   refusal of a span whose last token begins with `>` (which is
   `file_range`'s, finding the end of a last token) never applies, and an
   operator name ending at `>>` or `>=` has its extent
   (`s5_4_interim_span_ending_at_a_split_greater_does_not_reach_a_reference`).
   The other interim refusals reach references as WP-084 says: a range
   over a line beginning with `#` inside a comment, a span out of order
   (both: the reference is returned with no extent), `#embed` tokens (no
   name is one; the names around them keep their ranges).
7. **`tiers(r)`** is `Some` exactly for a range that a name range or an
   extent of a reference, or the name range of a **live** declaration
   (§6.4 rule 3), is; the tiers of every such value with that range are
   joined (`s5_4_one_range_at_two_tiers`). Any other range is `None`, one
   inside such a range included, and a parameter's name (fix round, A3:
   `s5_4_no_tiers_for_parameter_names`).
8. **Places** (§7.4 rule 3). A reference: its extent; else the range of
   its written tokens `[first, end of name)` when that has one (a leading
   `::` not found, an unlinked qualifier), else its name range, else the
   outermost macro invocation that produced its name; else unnamed. A
   declaration: its name range; else the range of its name's tokens (an
   operator, a conversion function: `operator int`), else the invocation
   that produced its name or location; else unnamed; and for a row that
   is another declaration's (decision 14) the token at its own location,
   else that location's invocation. An entity: the place of its first
   written declaration in unit order; nowhere when it has none. A place
   other than the value's own is `Nearest`, which the report marks as not
   the value's own. The extent of a reference that is a whole expansion
   is the invocation, and is its own place (§7.4 rule 3 now says so).
9. **The origin** (§5.5) is `slip_kiln::written::origin`, nothing else
   (fix round, B1): read for every entity when the subject is made, and
   used by `Subject::origin`, `references_to` and the key of decision 3.
   So a use that resolves to an explicit specialisation (`n::tf(1)` with
   `template <> void tf<int>(int)`, `S<int>().f()` with `template <> void
   S<int>::f()`, `vt<int>` with `template <> int vt<int>`) is a reference
   to the template or the member
   (`s5_5_uses_of_explicit_specialisations_are_references_to_the_template`),
   and a member only an explicit specialisation declares is its own
   origin (`s5_5_a_member_only_an_explicit_specialisation_has`). WP-083's
   `s5_5_explicit_specialisation_is_written` and
   `review_f3_member_template_explicit_specialisation` now expect the
   template. `origin` reached the template in every case tried. Unit order
   is by first token, then the longer reference first (at one first
   token, the one whose name ends later: `T::T` before `T`), then the
   table's order.
10. **Unit order** is `slip_kiln::ranges::unit_order` (WP-084), except
    that an invalid location sorts after every valid one, as WP-083's
    comparator did (its mutant M17, `review_unit_order_invalid_last`);
    `ranges` puts it first. `kiln_subject::unit_order` is the wrapper.
    `references_at` gives the references with one extent in unit order
    too (§7.2 rule 1 now says so).
11. **`identifier` of a reference** (§6.3 "the identifier written there")
    is its referent's identifier: decision 4's check makes the name
    range's text equal to it whenever there is a name range, and an
    operator, constructor, destructor or conversion function name gives
    the empty identifier.
12. **The counter** (§6.5 rule 6) counts `dependent_names` records, each
    written name once (by where its first character is spelled), keyed by
    **the identifier** Kiln's lexer reads from the token there (line
    splices removed, universal-character-names decoded), not its bytes:
    `café`, `caf\u00e9` and a spliced `café` are one identifier (fix
    round, 8b: `s6_5_rule6_the_counter_compares_identifiers`).
    `unresolved_named` is always `Some`: the subject can tell, since the
    tables are recorded.
13. **`written(d)`** is: `d` has a row (`slip_kiln::written::row`) whose
    kind is not `ExplicitInstantiation`. Block-scope declarations, local
    classes and their members, template parameters, structured bindings
    and the declarations of a lambda's body have rows and are written
    (`s6_4_rule3_block_scope_and_template_parameters_are_written`,
    `review2_lambda_declares`, `review_f9_closure_call_operator`).

## Implicit declarations (WP-084 "What a consumer must not assume" 1)

Every node-to-range path, for an implicit declaration:

- **A reference**: every reference is a written name of Kiln's table;
  an implicit node (an implicit `this`, a range-for's hidden variables, an
  implicit conversion) records no entry and is no reference. A written
  name whose referent is implicit (`a.operator=(b)` naming the implicit
  copy assignment) is a reference with its written ranges: no name range
  (an operator), its extent `operator=`.
- **A declaration**: an implicit declaration has no row, so it is not
  written and no query yields it as a declaration; `name_range` and
  `place` are never asked of one.
- **An entity**: one with no written declaration (implicit, or made by
  instantiation) is `nowhere`; one with written declarations takes the
  first one's place, which is written.
(`s7_4_rule3_implicit_declarations`).

## Kiln holes

- **K1** (`spec/landed/edits/WP-067.md`): an explicit instantiation of a
  function template has no row, so `template void a::tf<long>(long);`'s
  qualifier `a` is not known to be a declarator's and is returned
  (`kiln_hole_k1_explicit_instantiation_qualifiers_are_returned`, today's
  answer). `written` is right there: no row, no declaration.
- **K3, refused** (fix round, A2): a row Kiln overwrote with another
  declaration's name is told by its declaration's own location
  (`ast.decls.get(d).loc()`) not being the row's name start. That test
  was checked over the pair corpus before it was used: the location is
  the name start for every other row of every kind (162 destructor rows,
  36 conversion-function rows, constructors, deduction guides, operators,
  `s6_6_rule1_a_declaration_named_through_a_macro_argument` for a name
  from a macro argument); the only rows where it is not are the 7 K3
  rows. Such a declaration has a null name range and its place is
  `Nearest`, the token at its own location (`kiln_hole_k3_a_friend_overwrites_the_row`,
  `kiln_hole_k3_a_qualified_elaborated_specifier_overwrites_the_row`: both
  now expect null). A name range is never another declaration's.
- **An init-capture has no row**: not written, its entity is nowhere; its
  references are returned (`kiln_hole_an_init_capture_has_no_row`).

## What a reference without a range looks like to a transform

It is returned by `references_to` and `references_at` never gives it
(that needs an extent). `name_range_of` and `extent_of` are null;
`referent_of`, `identifier_of` and `found_directly` answer as for any
reference. `is_editable` of the null range is false and `replace` cannot
be given one, so a transform that edits every reference it can sees it,
cannot edit it, and should say so; `place` gives the nearest place (the
invocation, or the written tokens), marked as not the reference's own, so
a report about it points at the macro use. Verification (§6.5 rule 5)
catches a rename that leaves it: the post-image resolves differently.

## For the coordinator: what `slip_kiln` lacks for one call

The fix round asked that `name_range_of` be the `At` range of
`slip_kiln::sites::Sites::name_token`, or, if that needs `slip_kiln`
changed, a differential test. It needs `slip_kiln` changed:

- `Sites` takes a file to be one only with a real path and a non-virtual
  origin, so every buffer of a snippet (the subject's test inputs, and a
  script given source text) is refused `not_a_file`;
- `Sites` decides `NotOwned` before it checks the bytes and the tier, so
  a name in a file that is not owned (a dependency's header, which the
  subject still answers about) has no checked range;
- the identifier at a token (`written::token_at`, `identifier_span`) is
  private, so the counter (decision 12) lexes the token itself.

A `Sites::name_token` that answers `At` for any loaded buffer, with
ownership a separate question, would let the subject call it. Until
then the two are compared by the two tests of decision 4.
