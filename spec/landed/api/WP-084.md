# WP-084 — slip_kiln: ranges, tiers 0 and 1, and unit order

`crates/slip_kiln/src/ranges.rs` and `Unit::token_end`
(`crates/slip_kiln/src/parse.rs`) bring `spec/api.md` §1 (unit order) and
§5.4 (tiers 0 and 1) and `spec/edits.md` §2.2 to code. Tests are in
`crates/slip_kiln/tests/ranges.rs`. This file records what the spec and
`docs/wp/WP-084.md` left open, how the code decides it, and where the
spec was corrected.

## The range is Kiln's

`slip_kiln::ranges` has no rule of its own for a range of file
characters, nor for what a token is. The end of a token is
`kiln_lex::token_end` (Kiln `spec/lex.md` "End of a token"), called only
through `Unit::token_end`; whether a location starts a token is Kiln's
lexer over the buffer (`Unit::is_token_start`, decision 6); both use the
unit's interner and lexer options, which only `Unit` holds in Slip. The
range of a span is `SourceManager::editable_file_range` (Kiln
`spec/source.md` "Editable file ranges"), unchanged when it is given.
`ranges` only refuses: four refusals (decisions 2, 6, 10 and the
`<scratch space>` rule of decision 11) take away a range Kiln gives, and
two of them are interim, until Kiln records what they guess at ("Until
Kiln answers").

## Decisions

1. **The tier** is derived from Kiln's own rules, not from the answer:
   tier 0 when `file_loc_at_macro_start(span.lo)` and
   `file_loc_at_macro_end(span.hi)` are both `Some` (both are the
   identity on a file location), which is when Kiln answered by its rules
   1 to 3 on the span as given; tier 1 when Kiln answered and that is
   not so, which is only through its rule 4. A span with one file end and
   one macro end that fails its rule gets no answer from Kiln (rule 4
   needs two macro ends), so it never reaches tier 1.
2. **An empty span** (`lo == hi`) has no range, whatever Kiln would say:
   version 0 of the API has no insertion point. Nor has a span Kiln maps
   to an empty or reversed run of bytes (`lo >= hi` after Kiln: a
   structured binding's member reference begins at its name and ends at
   the `[` before it). So a `FileRange` always has `lo < hi`. The empty
   check is on the span as given (`span.lo == span.hi`), not on raw
   order: the tokens of an expansion have raw locations above every file
   location, so `P 2` (`#define P 1 +`) has `lo > hi` raw and is tier 0
   (`s5_4_test1_tier0_from_an_expansion_into_file_text`).
3. **A whole expansion is the invocation, at tier 0, when Kiln's rules
   see the whole expansion**, also when its tokens came from one
   argument: for `ID(foo)` with `#define ID(x) x`, the range of `foo` is
   the seven bytes `ID(foo)`, not `foo`. Both rows of §5.4's table hold
   for it; the range is tier 0's (§5.4 rule 6). Kiln's rules see the
   whole expansion when the span's first token is the expansion's first
   and its last token the expansion's last; they do not when the
   expansion's first or last token is not one the span can name. So
   these shapes, which §5.4's table would give a range, get a narrower
   answer or none (review of WP-084, F7; none is wrong, each is less):

   | Source | Span | Table says | Given |
   |---|---|---|---|
   | `#define F(x, y) x y` and `F(, b)` | `b` | tier 0 `F(, b)` | tier 1 `b` |
   | the same and `F(b, )` | `b` | tier 0 `F(b, )` | tier 1 `b` |
   | `#define E(...) 2 __VA_OPT__(+ __VA_ARGS__)` and `E()` | `2` | tier 0 `E()` | none |
   | `#define PR _Pragma("x") a` and `PR` | `a` | tier 0 `PR` | none |

   What a caller does with a name whose range is more than the name is
   the caller's (`spec/edits.md` §2.2).
4. **"Starts in file text and ends in an expansion"** (WP test 3) has no
   range only when the end is not the end of the expansion; a span that
   starts in file text and ends at the last token of an invocation holds
   the whole invocation and is tier 0 (Kiln's rule 3,
   `s5_4_test1_tier0_whole_invocations`).
5. **`FileRange`** derives `Clone, Copy, PartialEq, Eq, Debug` (the WP
   gave `Tier` its derives and `FileRange` none). Its fields are public;
   `lo` and `hi` are offsets in Kiln's text of the file
   (`SourceManager::text`), which are the file's bytes exactly when Kiln
   changed nothing on loading it (`spec/edits.md` §2.3, `file_recoded`,
   which `ranges` does not look at).
6. **`file_range(unit, first, last)`** has no range unless `first` and
   `last` are each the start of a token as the preprocessor lexed it,
   and then ends the span at `unit.token_end(last)` (no range when that
   is `None`). An AST node can begin inside a token: the call of a
   user-defined literal `12_k`, its callee and an operator expression it
   begins all begin at the suffix `_k` (review F2), and without the
   check they got the ranges `_k` and `_k + 1`.
   - *How it is checked:* `Unit::is_token_start(loc)` takes a macro
     location to its spelling (`spelling_loc`), and looks the offset up
     in the starts of the tokens Kiln's lexer gives for the whole buffer
     (`Lexer::new_in_range`, `LexMode::Normal`, the unit's
     `Preprocessor::lex_options` with comments off), lexed once per
     buffer per unit and kept. The lexer lexes a skipped group as text
     it does not tokenise in the preprocessor, but by the lexer's own
     rule (`skip_plain_line_rest`, `kiln_lex/src/lexer.rs`) a normal lex
     of the same bytes gives the same tokens after it, so the starts of
     every token the preprocessor delivered are among those found. That
     is Kiln's lexer deciding, not a rule of Slip's: no table of the
     unit's tokens exists to ask instead ("Until Kiln answers").
   - *Interim:* a span whose last token, as `token_end` lexes it, begins
     with `>` and is longer than one byte (`>>`, `>=`, `>>=`) has no
     range. The parser may have split it: in `B<vt<1>> y;` the
     expression `vt<1>` ends at the first byte of `>>`, and the range
     was `vt<1>>`, one byte into `B`'s argument list (review F1). Which
     `>` the parser split is not visible ("Until Kiln answers"). The
     loss: every span ending at a `>>`, `>=` or `>>=` token, whether
     split or not, so a name such as `operator>>` or `operator>=` as
     written, and every expression or name ending at a split `>`
     (`std::enable_if_t<std::is_same_v<T, U>>`'s inner argument).
     Pinned by `s5_4_test3_none_a_possibly_split_greater`; the right
     answer (`vt<1>`) is the ignored
     `s5_4_pending_a_split_greater_ends_at_its_first_byte`.
   - It does not check that `first` comes before `last`: Kiln's rules
     give no range for a span out of order, and decision 2 refuses one
     Kiln maps backwards.
7. **Unit order** is over locations, not only tokens. Each location has a
   chain to a root: a macro location's parent is
   `expansion_info(loc).expansion.lo` (the invocation for a macro entry,
   the parameter's place in the replacement list for an argument entry),
   a file location's parent is `include_loc` (the `#include` that
   entered its inclusion), and a location with neither is a root. Chains
   are compared from the root, element by element, by raw location; a
   chain that is a prefix of the other comes first (an invocation before
   the tokens it expands to, an `#include` before the included tokens).
   Two locations of one inclusion or one entry (`same_entry_distance`
   either way) are in raw order without walking. It is a total order on
   every location of the unit, equal exactly when the locations are
   equal; for two tokens of the sequence it is their order there. A
   location that is no token (an invocation's parentheses, an argument
   as written, a byte inside a token) is placed by the same rule.
   A header's tokens are in the range of its inclusion
   (`add_inclusion`); the header's own range, which
   `SourceManager::loc` gives, has no include location and is a root.
   Roots: `Loc::INVALID` first, then the predefines buffer, then the
   other roots (the main file, a buffer never included, a `<scratch
   space>` buffer of `#embed`: decision 11) in raw order. The walk is
   bounded at 2^16 steps, which only a malformed table reaches; reaching
   it panics with the location (a comparator has no error to return),
   which is the report. Eight nested includes and six nested
   invocations (`s1_test5_unit_order_deep_nesting`) order correctly.
   - *Cost:* each comparison of two locations that are not in one entry
     builds both chains, two small allocations per comparison. A sort of
     n locations pays that n log n times. A caller that sorts many
     locations should compute each chain once (a sort key) when the cost
     shows; `unit_order` stays the definition.
8. **Snippet additions** the tests need, in `slip_kiln::snippet`:
   `Parsed::unit()` (the `Unit` of a snippet parse, so that a snippet
   test calls `token_end` the way a worker does); `parse_with_tables`
   (`parse` with Kiln's written references and declaration extents
   kept, for test 6); and `preprocess` with `Preprocessed` (the token
   sequence after phase 4 of a snippet, built on the same source
   manager setup, resolver and feature queries as the parse, for test 4;
   `Preprocessed::errors`, the errors it reported, which the property
   compares).
9. **Forced includes.** Kiln writes each `-include x.h` as an
   `#include "x.h"` line in the predefines buffer `<built-in>`
   (`kiln_pp/src/predef.rs:493`), and creates that buffer after the main
   file but reads it first (`Preprocessor::enter_main_file`,
   `kiln_pp/src/preprocessor.rs:645-667`). So `<built-in>` ranks before
   every other root, and a location in a forced header (or in a header
   it includes) comes before every location of the main file, as
   translation reads them (`s1_unit_order_forced_include_comes_before_the_main_file`
   in `crates/slip_kiln/tests/parse.rs`, through a real `-include`; found
   in the review of WP-083, whose `order.rs` this replaces). The buffer
   is recognised from the source manager alone, by its name `<built-in>`
   (`file_name`), the test Kiln's own `-E` printer uses
   (`kiln_pp/src/print.rs:290`); `unit_order` takes no preprocessor. The
   code also asks that the buffer be in memory (`file_origin` is
   `Virtual`), which no test can tell from the name alone: a file on disk
   cannot be named `<built-in>` by Kiln's loader, so the mutant that drops
   that half survives, and is argued, not killed. Another buffer whose
   name begins with `<` (`<scratch space>`) is not the predefines
   (decision 11). Should Kiln rename the buffer or keep its id in the
   source manager, this rule moves with it.
10. **A range holding a directive** (review F3, F4b). A range that holds
    a preprocessing directive, or any part of a skipped group, is no
    range, at both tiers. `f(1,\n#ifdef X\n b\n#else\n c\n#endif\n)`
    was the tier 0 range of the call, and replacing it deletes the other
    configuration's `b`; `1\n#if 1\n+ 2` holds `#if` without its
    `#endif`. A range inside one group, and one over many lines with no
    directive, are ranges.
    - *Interim:* Kiln records neither directive lines nor skipped groups
      where Slip can read them ("Until Kiln answers"), so the check is on
      the file's bytes: no range when the line holding the range's first
      byte, or any line that starts inside it, begins (after blanks,
      line splices and `/* */` comments) with `#` or `%:`. A skipped
      group lies between two directive lines, so a range that holds any
      of it holds one of them or lies inside it, and then its first line
      is in the group; a line of a skipped group that does not begin
      with `#` is not caught when the range is wholly inside the group,
      which the preprocessor never gives a token for. The check is
      marked INTERIM in `file_range_of_span`. Its loss: a line of a raw
      string literal or of a block comment that begins with `#` refuses
      a range that holds it
      (`s5_4_test3_none_a_range_holding_a_directive`, with the two
      review sources, `#include`, `#pragma`, `#define`, `%:` and a
      directive after a comment, an `#if` inside a macro argument
      (tier 1), and the two that keep their ranges).
11. **`#embed`.** Kiln makes the tokens of `#embed` file locations in a
    fresh `<scratch space>` buffer that the unit never entered
    (`kiln_pp/src/directive.rs:1932`). Such a location gets no range
    (`is_written_in_scratch_space`; the bytes are not the unit's text),
    and unit order ranks the buffer as any root that is neither invalid
    nor `<built-in>`: by raw order, so after every location of the main
    file. That is wrong (the literals come before what follows the
    directive) and documented: `s1_embed_tokens_have_no_range_and_rank_after_the_main_file`
    in `crates/slip_kiln/tests/parse.rs` pins it, and the ignored
    `s1_pending_embed_tokens_order_before_what_follows_the_directive`
    states the right order. A consumer must not order `#embed` tokens
    by `unit_order`.
12. **The kiln-boundary lint** (`spec/landed/harness/WP-021.md`'s third
    rule) covers `slip_kiln::ranges` beside `kiln` and `snippet`
    (`xtask/src/lint/crates.rs`, `kiln_module_paths`; test
    `s3_kiln_boundary_kiln_modules` in `xtask/tests/lint.rs`): its
    functions take Kiln's types, which a crate can pass on without
    naming `slip_kiln::kiln` (type inference), so only `slip_digest` and
    `slip_script` may name it, as `kiln`.
## Until Kiln answers

What Kiln lacks at the pin, by name, and what Slip does meanwhile. Each
interim rule takes ranges away; none adds one.

1. **The tokens of the unit.** `kiln_driver::front_end::FrontEnd` keeps
   only their count (`tokens: u64`); there is no table of the tokens the
   preprocessor delivered, nor a query "does a token start here". Slip
   lexes each buffer once with Kiln's lexer (decision 6). Wanted: the
   start of every token per buffer, or `is_token_start(loc)`, from the
   front end.
2. **Split `>`.** `kiln_parse` splits `>>` in `split_greater`
   (`kiln_parse/src/parser.rs:1750`) and records the location in
   `Sema::split_greaters` (`kiln_sema/src/lib.rs:716`, `pub(crate)`),
   which only Sema's private `token_end` (`kiln_sema/src/impcast.rs:552`)
   reads. The set is not on `Ast`, and the public `kiln_lex::token_end`
   (`kiln_lex/src/token_end.rs:32`) cannot see it. Wanted: the set (or a
   split-aware end of a token) on `Ast`. Then decision 6's interim
   refusal goes, and `s5_4_pending_a_split_greater_ends_at_its_first_byte`
   is un-ignored.
3. **Directive lines and skipped groups.** `kiln_pp::PpRecord`
   (`kiln_pp/src/record.rs`) records macro definitions and expansions
   only. `kiln_pp::PpCallbacks` (`kiln_pp/src/callbacks.rs`) has
   `source_range_skipped`, `inclusion_directive`, `macro_defined`,
   `macro_undefined` and `pragma`, but no callback for a taken `#if`,
   `#ifdef`, `#ifndef`, `#elif`, `#else` or `#endif`, nor for `#line`,
   `#error`, `#warning` or a null directive; and
   `kiln_driver::front_end::FrontEndOptions`
   (`kiln_driver/src/front_end.rs:43`) has no way to install callbacks,
   so Slip's worker cannot use even those. Wanted: the span of every
   directive line and every skipped range of the unit, kept on request
   like the macro record. Then decision 10's byte check becomes a lookup
   and its raw-string loss goes.
4. **`#embed`'s buffers** have no parent location: a `<scratch space>`
   buffer of `#embed` is a root (decision 11). Wanted: the `#embed`
   directive as its include location (or its expansion location).

## What a consumer must not assume

For WP-085, WP-086 and WP-068, and any caller of `file_range`:

1. **Implicit nodes have ranges.** An implicit node's `begin_loc` and
   `end_loc` are those of what it stands for, so `file_range` gives an
   implicit `this` the range of the member name (`m`), and the implicit
   variables and calls of a range-for `:` and `: arr`
   (`s5_4_implicit_nodes_have_the_range_of_what_they_stand_for`). No
   range for an implicit node is the consumer's rule: `ranges` sees
   locations, not nodes.
2. **A range in a file entered twice is one range for every entry.** A
   header without a guard, or an X-macro `.def` included under two
   definitions, gives the same `FileRange` for the span in each entry,
   and an edit of it changes every entry. The property of test 4 holds
   per entry; what the edit does to the other entries is for the votes
   (`spec/edits.md` §4.3) (`s5_4_test4_property_a_header_entered_twice`,
   `s5_4_test4_property_an_x_macro_file`).
3. **A tier 1 range changes every use of the argument** (§5.4 rule 4),
   and a whole-expansion span's range is the whole invocation (decision
   3): a range may be more than the node.
4. **No range is not an error**, and the interim refusals (decisions 6
   and 10) give none where a range exists: a span ending at `>>`, `>=`
   or `>>=`, and a range over a line that begins with `#` inside a raw
   string or comment.
5. **`unit_order` misorders `#embed` tokens** (decision 11), and costs
   two allocations per comparison across entries (decision 7).
6. **`lo` and `hi` are offsets in Kiln's text of the file**, the file's
   bytes only when Kiln changed nothing on loading it (decision 5).
7. **Begin and end may be out of order** in the AST (a reversed
   rewritten comparison, a structured binding's member reference): such
   spans get no range; the range of the written form is the caller's.

## What the tests found

- **Spans with no range in the digest pair tests** (2354 directories,
  both sides, 29523 expressions): "invalid location" 144 (an implicit
  expression); "file to file, out of order" 18 (the semantic
  `CXXOperatorCallExpr` of a reversed rewritten C++20 comparison, `a ==
  b` found as `operator==(b, a)`, whose `begin_loc` and `end_loc` follow
  the semantic operands); "empty or reversed" 7 (the member reference of
  a structured binding, from its name back to the `[`); "an end inside a
  token" 1 (an implicit `this`); the interim directive check 19 (the
  literals of `#pragma clang loop`, inside a directive line, and a
  `requires` clause holding an `#ifdef`). None is a disagreement with
  Kiln: the range of the written form is the caller's (`spec/api.md`
  §6).
- **The property's oracle** (`check_range`): the marked source must
  report the same preprocessing errors (a range holding half a
  conditional used to pass), the tokens of every other file must be
  unchanged, and in the entry that holds the span exactly the span (tier
  0) or each use of the argument (tier 1) becomes the marker. A range
  given for a span whose ends are not tokens of the sequence is a
  failure, and each macro snippet's counts of ranges by tier, of spans
  with none and of declaration names are pinned, so a lost range fails
  too.
- Review findings for Kiln: the split `>` and the missing directive
  record ("Until Kiln answers").
