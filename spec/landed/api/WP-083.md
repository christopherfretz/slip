# WP-083 — slip_script: the subject over Kiln: entities, lookup, structure

`crates/slip_script/src/kiln_subject/` (`mod.rs`, `entities.rs`,
`lookup.rs`, `order.rs`) implements `Subject` over one parsed Kiln unit
for §1 (unit order), §5.1, §5.5, §6.1 to §6.4 and the identifiers of
§7.2 rule 2. This file records where the specification left a choice, or
could not be read against Kiln's AST as written, and how the code makes
it. Tests are in `crates/slip_script/tests/subject_entities.rs`.

## Decisions

1. **Written declaration.** One function decides it,
   `KilnSubject::written` (`entities.rs`). **WP-085 replaces its body by a
   read of Kiln's declaration-extent table** (Kiln `spec/ast.md` §19.1:
   one row per declaration the parser parsed; none for implicit
   declarations, instantiations and their members; one for an explicit
   specialisation), switched on by `ParseOptions.written` (WP-067),
   keeping the tests; decision 2 stays (an explicit instantiation has a
   row and is still no declaration of the entity). Until then the rule is
   structural, and a declaration is written exactly when:
   1. it is not implicit, not the translation unit, and not made by
      instantiation (an implicit or explicit instantiation, a member of
      one, the declaration deduction makes of a specialisation before its
      explicit specialisation is read: `instantiated`); and
   2. it is reached from the translation unit through member lists, with
      template patterns and friend targets, never descending into an
      implicit declaration (a builtin record such as `__va_list_tag`) or
      an instantiation (Kiln lists an explicit instantiation in its
      context's member list); or
   3. it is a template parameter whose context (Kiln gives the template's
      scope, `TemplateParamList`) is the translation unit or so reached;
      or
   4. it is in no member list and declared in a block (its lexical
      context is a function, a deduction guide, a requires-expression, or
      a variable or data member whose initialiser holds it) or in a local
      class or enumeration (one in no member list itself), and that
      context is written by these rules.

   Kiln links every declaration it parsed outside a block into its
   lexical context's member list and none it made
   (`kiln_ast/src/decl.rs:2161`), so a class that is listed lists every
   member the parser parsed: an unlisted declaration whose lexical
   context is a listed class (the declaration deduction makes for
   `template <> void A::mt<int>(int)`, lexical context `A`) is not
   written. A flag test cannot replace the structure: that declaration
   is neither implicit nor an instantiation (its spec kind is already
   `ExplicitSpecialization`).
2. **Explicit instantiations** (`template struct C<long>;`, `extern
   template struct C<short>;`, `template void f<int>(int);`) and their
   members are not written declarations: they are instantiations (§5.5
   has them come from the template and its members).
3. **An entity** is `Walk::entity` of `slip_digest` (the first
   declaration; for a pattern, its template's). Its declarations
   (§6.4 rule 3) are its written redeclarations; for a template, the
   written redeclarations of its pattern, each mapped to the template
   declaration that describes it.
4. **Using-declarations, namespace aliases, type aliases** are entities
   lookup finds under their own name (§6.1 rule 5 as amended). A
   using-declaration and a namespace alias satisfy no kind predicate of
   §6.2; a type alias is a type.
5. **Transparent scopes** (§6.1 rule 3 as amended): inline namespaces,
   unnamed namespaces, unscoped enumerations, anonymous unions and
   anonymous structs (Kiln gives the enclosing class `IndirectField`s for
   both), at any depth. A typedef name for linkage purposes names its
   unnamed class as a scope (§6.1 rule 4 as amended; Kiln records it,
   `Decls::typedef_for_anon`); no other typedef or alias does. Linkage
   specifications and `export` are not scopes at all, so their members are
   members of the enclosing scope.
6. **Friends.** A function or class first declared in a friend declaration
   is a member of the innermost enclosing namespace ([namespace.memdef]/3):
   lookup finds it there, its parent is the namespace, and the friend
   declaration is one of its declarations. Kiln lists only the `Friend`
   wrapper in the class; the target has `ctx` the namespace
   (`FriendTarget`, `kiln_ast/src/decl.rs`). The index of a namespace
   walks the definitions of the classes that are its semantic members,
   and of the classes nested in them, wherever those definitions are
   written (`struct n::Out { friend void outf(Out); };` at global scope
   declares `n::outf`).
7. **Out-of-line definitions** (`void ns::f(int) {}`) are members of the
   scope their name names, not of the one they are written in.
8. **Kind bits.** `is_type` is a class, a class template specialisation,
   an enumeration, a typedef or alias-declaration; `is_template` includes
   partial specialisations (Kiln makes them `CXXRecord`s or `Var`s with a
   partial specialisation link, never a `…PartialSpecialization` kind) and
   alias templates; `is_variable` includes variable template
   specialisations and indirect fields; a concept, an enumerator, a
   using-declaration and a namespace alias satisfy none.
9. **`is_definition`** ([basic.def]): a namespace body, an enumerator, a
   data member, a concept, a namespace alias are definitions; a typedef and
   an alias-declaration are not; a template follows its pattern; a
   variable follows [basic.def]/2 (as `slip_digest` reads it); a class, a
   function and an enumeration are a definition when they are Kiln's
   definition of the entity.
10. **The global namespace** has no declaration (`declarations_of(^^::)`
    is empty): it has no body in the source.
11. **Parents of template parameters** are their templates. Kiln gives a
    template parameter the template's context as `ctx`
    (`kiln_ast/src/templates.rs`, `TemplateParamList`), so the owner is
    found from the template parameter lists, once, on first use.
12. **A parameter** is an entity per declaration: `parameters_of` an
    entity gives those of its first declaration in unit order, of a
    declaration its own. A parameter's parent is its function entity
    (for a function template, the template). Parameter declarations are
    not live values (`declarations_of` a parameter is `unsupported`).
13. **`qualified`** (§7.2 rule 2) is `None` for an entity with no
    identifier, a parameter, a template parameter, a using-declaration, a
    deduction guide, a binding, a specialisation, an entity with no written
    declaration, an entity whose written declarations are all friend
    declarations (a hidden friend, a class only a friend declares:
    qualified lookup cannot find it until a namespace-scope declaration
    exists), and an entity with an enclosing function, template,
    specialisation or unnamed class. Unnamed namespaces and unnamed
    enumerations are left out of the spelling (`enum { A };` in `e` is
    `e::A`); inline namespaces are in it. §7.1 rule 4 and §7.2 rule 2 are
    amended to say so.
14. **Unit order** is computed slowly, by one function
    (`kiln_subject::unit_order`, WP-084's signature, which replaces it):
    the include chain of the expansion location, outermost first, then
    the raw location. The predefines root (`<built-in>`, created after
    the main file but read before it; a forced include `-include x.h` is
    an `#include` of it) ranks before every other root, the others by
    `FileId`. A declaration is placed at its extent's start when Kiln
    records extents, at its name otherwise (snippets and production parses
    at this pin have no extents).
15. **File bytes** are the buffer's original bytes (`original_bytes`).
    Kiln's offsets are into the decoded text; the two differ only for a
    file that is not UTF-8 or has a BOM, which WP-085 must reconcile when
    it gives ranges.
16. **The lookup index** is per scope, built on first use and cached for
    the subject's life; the set of written declarations and the template
    parameter owners are one pass each over the arena, also on first use.
17. **The subject is `Sync`** (a run's handler holds it by reference and
    must be `Send` at Kiln `913a490bb`). It holds `&Ast`,
    `&SourceManager`, the subject path of each buffer (copied out when it
    is made: borrowed from the unit's inputs for a `Unit`, owned for a
    snippet) and `owned: &(dyn Fn(&[u8]) -> bool + Sync)`; never the
    `Unit` or the Oven. Its memos are `OnceLock`s (the written set, the
    template parameter owners, each file's bytes) and one `Mutex` over the
    scope indexes, held only to read or insert an index and never while
    one is built: two threads may build the same index twice, to the same
    value. The cost is one uncontended lock per `lookup` component and
    scope.
18. **No limit cuts an answer short** (the coordinator's S1). `lookup`'s
    walks (transparent scopes, nested classes) are worklists with a set of
    what they have seen, bounded by the arena, with no depth or step
    limit and no recursion; a chain walk (contexts, origins, the include
    chain) stops after more steps than the arena has declarations (or
    2^20 include levels), which only a cycle can reach and Kiln's AST
    has none. So no query fails for a limit, and there is no limit to
    reach in a test. (`Subject::lookup` returns `Vec<Entity>`: it has no
    status to fail with. If a limit is wanted, it needs that signature
    changed in `slip_script`, and `limit_exceeded`, §4, would be its
    status.)
19. **A closure's call operator** has no written declaration
    (`declarations_of` is empty): Kiln makes the closure type and its
    members implicitly; the lambda-expression is the written thing. **Known
    gap:** a declaration in a lambda's body (`[] { int z; }`) climbs to
    that implicit operator, so the structural rule finds no declaration
    of it, though the parser parsed one; the extent table (decision 1)
    closes it in WP-085, and `review_f9_closure_call_operator` pins the
    present answer with that note.
20. **`from_snippet`** is the constructor for a snippet's unit (tests);
    the constructor from parts is private, so no caller can build a
    subject over the AST of one unit and the source manager of another.
