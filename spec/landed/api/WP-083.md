# WP-083 — slip_script: the subject over Kiln: entities, lookup, structure

`crates/slip_script/src/kiln_subject/` (`mod.rs`, `entities.rs`,
`lookup.rs`, `order.rs`) implements `Subject` over one parsed Kiln unit
for §1 (unit order), §5.1, §5.5, §6.1 to §6.4 and the identifiers of
§7.2 rule 2. This file records where the specification left a choice, or
could not be read against Kiln's AST as written, and how the code makes
it. Tests are in `crates/slip_script/tests/subject_entities.rs`.

## Decisions

1. **Written declaration.** A declaration is *written* when the parse put
   it in a member list reachable from the translation unit (through
   linkage specifications, `export`, class bodies and template patterns,
   with friend targets), or when it is a template parameter of a written
   template, or is declared inside a written function, class, enumeration,
   variable or deduction guide. Implicit declarations, instantiations and
   member instantiations are not written. A flag test cannot replace the
   structure: before reading an explicit specialisation
   `template <> void tf<char>(char)` Kiln makes a declaration of `tf<char>`
   by deduction, which is neither implicit nor an instantiation (its spec
   kind is already `ExplicitSpecialization`, `kiln_ast/src/decl.rs:2161`),
   and is in no member list. That declaration is no declaration of the
   subject.
2. **Explicit instantiations** (`template void f<int>(int);`) are not
   written declarations of the specialisation: they are instantiations
   (§5.5 has the specialisation come from its template).
3. **An entity** is `Walk::entity` of `slip_digest` (the first
   declaration; for a pattern, its template's). Its declarations
   (§6.4 rule 3) are its written redeclarations; for a template, the
   written redeclarations of its pattern, each mapped to the template
   declaration that describes it.
4. **Using-declarations, namespace aliases, type aliases** are entities
   lookup finds under their own name (§6.1 rule 5 says only that they are
   not *followed*). A using-declaration and a namespace alias satisfy no
   kind predicate of §6.2; a type alias is a type.
5. **Transparent scopes** are exactly those §6.1 rule 3 lists: inline
   namespaces, unnamed namespaces, unscoped enumerations, anonymous
   unions. An anonymous `struct` (an extension) is not transparent.
   Linkage specifications and `export` are not scopes at all, so their
   members are members of the enclosing scope.
6. **Friends.** A function or class first declared in a friend declaration
   is a member of the innermost enclosing namespace ([namespace.memdef]/3):
   lookup finds it there, its parent is the namespace, and the friend
   declaration is one of its declarations. Kiln lists only the `Friend`
   wrapper in the class; the target has `ctx` the namespace
   (`FriendTarget`, `kiln_ast/src/decl.rs`).
7. **Out-of-line definitions** (`void ns::f(int) {}`) are members of the
   scope their name names, not of the one they are written in.
8. **Kind bits.** `is_type` is a class, a class template specialisation,
   an enumeration, a typedef or alias-declaration; `is_template` includes
   partial specialisations and alias templates; `is_variable` includes
   variable template specialisations and indirect fields; a concept, an
   enumerator, a using-declaration and a namespace alias satisfy none.
9. **`is_definition`** ([basic.def]): a namespace body, an enumerator, a
   data member, a concept, a namespace alias are definitions; a typedef and
   an alias-declaration are not; a template follows its pattern; a
   variable follows [basic.def]/2 (as `slip_digest` reads it); a class, a
   function and an enumeration are a definition when they are Kiln's
   definition of the entity.
10. **The global namespace** has no declaration (`declarations_of(^^::)`
    is empty): it has no body in the source.
11. **Parents of template parameters** are their templates. Kiln gives a
    template parameter the template's context as `ctx`
    (`kiln_ast/src/templates.rs`, `TemplateParamList`), so the owner is
    found from the template parameter lists, once, on first use.
12. **A parameter** is an entity per declaration: `parameters_of` an
    entity gives those of its first declaration in unit order, of a
    declaration its own. A parameter's parent is its function entity
    (for a function template, the template). Parameter declarations are
    not live values (`declarations_of` a parameter is `unsupported`).
13. **`qualified`** (§7.2 rule 2) is `None` for an entity with no
    identifier, a parameter, a template parameter, a using-declaration, a
    deduction guide, a binding, a specialisation, an entity with no written
    declaration, and an entity with an enclosing function, template,
    specialisation or unnamed class. Unnamed namespaces are left out of the
    spelling; inline namespaces are in it.
14. **Unit order** is computed slowly, by one function
    (`kiln_subject::unit_order`, WP-084's signature): the include chain of
    the expansion location, outermost first, then the raw location. Two
    root buffers are ranked by `FileId`. A declaration is placed at its
    extent's start when Kiln records extents, at its name otherwise
    (snippets have no extents).
15. **File bytes** are the buffer's original bytes (`original_bytes`).
    Kiln's offsets are into the decoded text; the two differ only for a
    file that is not UTF-8 or has a BOM, which WP-085 must reconcile when
    it gives ranges.
16. **The lookup index** is per scope, built on first use and cached for
    the subject's life; the set of written declarations and the template
    parameter owners are one pass each over the arena, also on first use.
