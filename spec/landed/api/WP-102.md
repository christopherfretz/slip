# WP-102 — slip_script: an edit's tiers are a set; a copy of an empty range

`crates/slip_script` (`output.rs`, `effects.rs`, `subject.rs`, `fake.rs`)
brings the run output to `spec/api.md` §7.6 as the M2 design left it, and
`code_copy` to `spec/edits.md` §4.2. Tests are in
`crates/slip_script/tests/effects.rs` and `tests/wire.rs`. This file
amends `WP-081.md` decision 13 and `WP-088.md` decisions 5, 6, 12, 13
and 14, each of which points here.

## Decisions

1. **`output::Tiers`** is the `tiers` of §7.6 `Edit`: a set of 0 and 1,
   never empty, held as a private byte with bit `t` for tier `t` (the
   bits of a claim's `tiers`, `spec/edits.md` §4.2). It has the constants
   `ZERO`, `ONE` and `BOTH`, `from_reached([bool; 2]) -> Option<Tiers>`
   (`None` for the empty set), `bits`, `contains`, `union` and `iter` (in
   ascending order). Its `Display` is `0`, `1` or `0,1`; `Edit.tier` is
   gone.
2. **Joining.** Requests that are one edit (same place, same normalised
   pieces, §7.6 rule 1) join their notes and their tiers by union.
   `tiers` is no part of an edit's identity or of the order of edits.
3. **`Subject::tiers(r) -> Option<[bool; 2]>`** replaces
   `Subject::tier(r) -> Option<u8>`. `None` is as before: `r` is not
   exactly a range `name_range` or `extent` gives, and `replace` refuses
   it with `invalid_handle`. `Some(reached)` says at which tiers the unit
   reaches `r`, `reached[t]` for tier `t`; both may be true (one range
   reached at tier 0 by one value and at tier 1 by another). The answer
   is an array and not a `Tiers` so that the empty set can be said, and
   it is a host failure, as a number above 1 was. An edit narrowed by the
   sibling rule takes the tiers of the name range (`WP-088.md`
   decision 5). The fake subject says "both" for a range given out that
   lies in one of `FakeSubject::both`.
4. **`code_copy` of an empty range is the empty code** (§7.1 rule 2, as
   amended): the null code handle, as `text("")` gives, holding no code
   value and counting against no limit. The range is checked as before
   (null, a file not given out, outside its file: `invalid_handle`)
   before it is found empty, and the call counts as one successful
   `code_copy` in `api.op.code_copy`. So no output holds a copy piece
   whose place is empty. `replace` of an empty range stays refused
   (§7.3 rule 2) and `report` at one is unchanged.
5. **`RunOutput::render`** writes `edit <i> <place> tiers <t> = …`, with
   `<t>` the `Display` of decision 1.
