# WP-137 — `spell` is made where it lands: an entity with no qualified name at a name range

`docs/wp/WP-137.md`. The supervisor's ruling on the "Open" point of
`spec/landed/api/WP-132.md` (its first resolution), written into
`spec/api.md` §7.1 rule 4 and §7.2 rule 1 and built in
`crates/slip_script`.

## What was built

- **Item 1: `spell(e)` of an entity with an identifier and no qualified
  name is made.** `Subject::unqualified` (new; `subject.rs`, the enum
  `Unqualified`: a specialisation, a member of a specialisation, a member
  of a class template, declared in an unnamed class, declared only by
  friend declarations) is asked when `Subject::qualified` is `None`.
  `KilnSubject` answers both from one walk (`entities.rs`,
  `spelling_of`), so the two cannot disagree; the fake answers from its
  own tree. The held piece (`HeldPiece::Spelled`) carries the reason and,
  for such an entity, its identifier as its text.
  At `replace`: the sibling form at an extent and at a name range is
  unchanged and writes the identifier with the entity's key; at a place
  that takes the fully qualified spelling (§7.2 rule 2), alone or as one
  piece of a `cat`, `Host::fully_qualified` refuses.
- **Item 2: what is still refused when the code is made**: `wrong_kind`
  for what is no entity (unchanged); `unsupported` for an entity the
  subject says is never spelled (`unqualified` is `None`: a parameter of a
  function or a template, no identifier, an implicit member, a
  using-declaration, a deduction guide, a structured binding, an entity in
  a function body), and for an entity with no key (unchanged). A reason
  given for an entity with no identifier is a host failure naming
  `Subject::unqualified`.
- **Item 3: the refusal at `replace`** is `unsupported`, its message names
  the entity (`display_string_of`) and why it has no qualified name, and
  the refusal's subject place (§2.8 rule 3) is the range replaced
  (`tests/effects.rs`
  `s7_2_rule_2_no_qualified_name_is_refused_where_it_lands`).
- **Item 4**: `lookup/r8-the-idiom-in-an-instantiation` has no `xfail`.
  Its edits are at the lines of the three calls (20 to 22; the guess said
  18 to 20, the lines of the class template's members) with the keys
  `W::g()`, `O::I::g()`, `X::g()`, the pattern members' (checked against
  `slip units`, below).

## Decisions

1. **The sibling condition compares the pattern's parent.** §7.2 rule 1
   already says "the parent of the origin of `referent_of(R)`"; it is kept
   and made explicit. `W::g` (the template's member, what
   `lookup(parent_of(referent_of(r)), "g")` gives) is a sibling at a
   reference to `W<int>::f` and to `W<long>::f` (origin `W::f`), not at
   one to `W<char>::f` declared by an explicit specialisation (its own
   origin); `W<char>::g` is a sibling there. The instantiation's own member
   `W<int>::g` (parent `W<int>`) is a sibling of nothing written, its own
   reference included. Comparing the instantiation's parent instead would
   have recorded `W<int>::g`'s key at `w.f()`, and verification takes the
   origin's key of what the written name denotes (`spec/verify.md` §10.2
   rule 4), which is `W::g`'s: an obligation that always fails.
2. **An entity that is not its own origin is refused at a reference
   (`unsupported`).** A specialisation (`tf<int>`) passes the sibling
   conditions at a reference to itself (its parent is its template's),
   and its key could never hold for the same reason: no origin is a
   specialisation. `Host::own_origin` refuses it where the sibling form
   would record a key (at the extent and at a name range named by
   references); at a name range that names declarations only the record
   is an identifier with no key, as before, and it is allowed. The key
   rule is not changed (no key is moved to the origin): the transform
   spells the origin, and the message says so (reached today by `lookup`
   in the parent). Supervisor's ruling (option 1): a name without
   template arguments can assert only an origin. Recording the origin's
   key under a piece that holds a specialisation would give, silently, a
   spelling whose check is weaker than what the transform holds; §7.2
   rule 5's principle (a spelling that could not be checked is not given)
   decides it, and the key rule is untouched (no second review).
3. **`cat` refuses nothing.** The code is made by `cat` as by `spell`;
   `replace` refuses it at a place that takes rule 2. At a name range a
   `cat` with a spelled piece and others was already `invalid_argument`
   (WP-132), and stays so.
4. **What is "never spelled".** The ruling names a parameter, no
   identifier and no key. The other cases `qualified_decl` refused before
   and the ruling does not list (template parameters, using-declarations,
   deduction guides, structured bindings, an implicit member with no
   written declaration and no origin, an entity whose parent has no
   written declaration) stay refused at `spell`: the conservative choice.
   §7.1 rule 4 now lists them. An entity made by instantiation with no
   written declaration (a member of an instantiation) is not "implicit":
   it has its origin.
5. **Precedence of reasons**: a reason that refuses outright (a function
   anywhere up the chain of parents) wins over one that only takes the
   qualified name away; among the others the one nearest the entity names
   it in the message.

## Open

- **(a) No `origin_of` query.** The refusal says to spell the origin;
  the API reaches it only by `lookup(parent_of(e), identifier_of(e))`,
  which for an overloaded function template returns every function and
  function template of that name in the parent (§6.1 rule 6), so the
  transform cannot tell from it which one `e` was made from. The
  supervisor is adding `origin_of` as an item of `docs/wp/WP-129.md`.

Nothing.

## The reviewer's question answered

WP-132 asked whether a key can be attached where a right rename fails or
cannot be seen. This package attaches no new key to an identifier piece
(`Host::finish` is unchanged). The new spelled pieces are those of an
entity with no qualified name, recorded only by the sibling form with the
entity's own key, and only when the entity is its own origin; so the
obligation is the one any sibling spelling makes, checked against the
origin of what the written name denotes.
