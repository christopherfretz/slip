# WP-058 — pitfall rows R01 to R11 and E01 to E16

What the rows of `spec/pitfalls.md` §3 and §4 are, as
`crates/slip_verify/tests/pitfalls/r01-…` to `r11-…` and `e01-…` to
`e16-…` build them, and where they read the table differently from how
it is written. The conventions of `spec/landed/pitfalls/WP-057.md` hold
where nothing below differs.

## Conventions of the rows

- Rows R rename in place in the global namespace (R04 in `app`, beside
  a dependency `lib` in `dep/dep.h`). `declared.txt` is one `relocate`
  line per renamed entity, its `<entity>` written as `spec/verify.md`
  §6.1 names it in the pre-image (`D::x()`, `Box::count() const`,
  `app::prepare(app::Mine &)`, the enumerator `green` with parent
  `Color`). R05 has no `declared.txt`: a local is not a unit.
- Rows E have no `declared.txt`, except E11 (`removed` lines) and E12
  (one `created` line); see "Where the rows differ".
- No system header: E02 declares the two lines of `std::swap` it needs.
  Owned headers sit beside `main.cpp` (E04, E11) and are included with
  `"…"` through `-I.`.
- Several shapes of one row are `good-<k>` trees on `pre/` (R05, E03,
  E06, E07), and independent subjects `pre-2/`, `pre-3/` where the
  shape needs its own subject (R11; the supervisor's ruling 5 on
  WP-057).
- A `bad` tree is an edit of its subject that differs from it by the
  wrong edit alone (`diff -r pre bad`). Where the correct edit is part
  of the wrong one (E02: bad qualifies both calls, good only the safe
  one) `diff -r good bad` is the wrong edit alone too.
- Places follow `spec/verify.md` §6.1: the line of the call or use for
  `changed` (in the post-image), the line of the declaration whose own
  row differs (R03: the override; E10: the default argument). R11 `bad`
  (a collision) and E09 (the order unit) have none.
- Entity names are written as the spec gives them, with template
  arguments qualified (the supervisor's ruling 1 on WP-057).

## How each tree was checked

- clang: `clang++-19 -std=c++20 -fsyntax-only -I. -Idep main.cpp` in the
  tree.
- Kiln: `slip parse --db cdb.json --store <dir> -j 1` on a one-entry
  compilation database of the tree, the shard's status as `slip parse`
  prints it.
- The change of meaning of every silent `bad` tree, on a scratch copy:
  a `constexpr` value under `static_assert` (functions made `constexpr`,
  the assertion appended: it holds on the subject and every `good` tree
  and fails on `bad`), or the callee in `clang++-19 -Xclang -ast-dump`,
  or a candidate made `= delete`, or the program linked and run. The
  method of each row is in the table.
- Not committed: an in-process comparison through `slip_cli::declare`,
  `slip_digest::digest` and `slip_verify::compare::compare_groups`, as
  WP-057 did ("What the walk gives today", below).

and `spec/digest-kinds.md` decide:

- **R03**: `changed D2::f()`, because `overrides` is a row of the

  `changed D2` (the class's list of virtual members); the expected line

- **R07**: `changed caller()`, because the call writes the

  template's discriminator holds the requires-clause), so the declared

  `measure<Box>` of the constrained template exists only in `bad`

- **E11**: two trees, one per hazard of the table: `derived_changed` for

## Where the rows differ from `spec/pitfalls.md` §3 and §4

- **R05** has no `declared.txt`: a local is not a unit and its name is
  not digested, so there is no `relocate` to write.
- **R11** has two more subjects (the supervisor's ruling 3): `pre-2/`
  with `__func__` as a value (`good-2`, `verified`) and `pre-3/` with
  `sizeof(__func__)` as an array bound (`bad-3`, `mismatch changed`). The
  rename is `f` to `start` so that the lengths differ.
- **E02**: the correct edit "left unqualified" is no edit; `good`
  qualifies the other call, `swap(i, j)` on `int`, where no
  argument-dependent lookup applies, and `bad` qualifies both.
- **E03**: two `bad` trees, one per wrong edit of the table
  (`decltype((x))`; `(show)(v)`), and two `good` trees of redundant
  parentheses.
- **E04** builds the non-dependent call only; the dependent operator
  expression of the table (`oper_lookups`) is not built.
- **E05**: the table's "moved, call qualified by a cast that keeps
  `h(long)`" does not verify: `h(static_cast<long>(1))` and `h(1L)` are
  other expressions than the implicit conversion of `h(1)` (today's walk
  gives `changed caller()` for both). `good` moves the caller past
  another function only, still before `h(int)`.
- **E10**: the finding is `changed take(int)`, not the caller (the
  supervisor's ruling 2 on WP-057, as N23).
- **E11**: `declared.txt` also has the `removed` lines for what `spec.h`
  and `better.h` declare, as a tool that removes those headers would
  declare them, so that `bad` and `bad-2` are caught by the change to the
  program and not by an undeclared removal (ruling 7). In `good` those
  lines are unused; `spec/verify.md` §2.2 makes an unused exemption no
  error.
- **E12**: the inner scope is a namespace, not a block, and `good`
  declares `created inner::spare()`. Any declaration statement inserted
  into a block, even an alias, which writes nothing, adds a `DeclStmt`
  node to its function's stream (digest-kinds §6, `DeclStmt`), so no
  correct edit inside a block verifies with nothing declared.
- **E14**: the line names `changed later()`, the lookup that changed in
  a unit the edit did not touch; `added <using_directive lib>` and
  `changed f()` are there too.
- **E15**: `good: none`. `T x = T(y)` is direct-initialisation and here
  selects the explicit constructor as `bad` does; where it is
  equivalent it is a written `CXXFunctionalCastExpr`, another expression
  than the implicit `ConstructorConversion` of `T x = y`.
- **E16**: `good: none`. `[&n]` for `[&]` changes `LambdaData` `default`
  and `LambdaCapture` `implicit`, which digest-kinds writes on purpose.
