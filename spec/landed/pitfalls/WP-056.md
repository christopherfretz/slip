# WP-056 — the pitfalls runner, and the catalogue's first run

What `crates/slip_cli/tests/pitfalls.rs` does where `spec/pitfalls.md` §1
leaves a choice, and the outcome of every tree at the package's gate.

## The runner

- `PLACES` is `Places::Mandatory`: localisation (WP-054) is on main.
- Four threads; every `slip` gets `-j 1`. Each subject has its own work
  directory under the test's temporary directory (database, store,
  declared text and container, reports, one `<tree>.found.txt` per tree
  with every group, its key and its two unit digests). It is removed when
  the run passes and kept, and named in the summary, when it does not
  or under `SLIP_PITFALLS_KEEP=1`. `SLIP_PITFALLS_ONLY=<a>,<b>` runs the
  rows whose directory name contains one of them, and the summary says
  the run was partial.
- The summary is written to the process's standard error directly, past
  the test harness's capture, so it is printed whether or not the test
  passes. After it, one `pitfalls: note <row>/<tree>: …` line per
  declared line left out.
- **The database** of a subject is one entry: `directory` the subject's
  real path, `command` `clang++ -std=<std> -I. -Idep -c main.cpp`.
- **`slip declare`** gets `--owned <subject>` and, when the subject has
  one, `--readonly <subject>/dep` (the longest entry decides,
  `spec/edits.md` §2.1), and `--root <subject> --post <tree>`. In a
  `bad` tree, every line that fails with `no unit` is left out (blanked,
  so the line numbers stay) and `declare` is run again; that includes a
  `relocate` whose parent does not resolve in a tree that does not parse
  (N22 `bad`, N38 `bad-2`, R06 `bad`, R14 `bad`, all `not_parsed`). Any
  other refusal is `ERROR`.
- **An `xfail` covers an `ERROR` from `slip declare`** refusing the
  declared file (status 1) only when its reason quotes, in backquotes,
  the error's class or a word the error quotes (`spec/pitfalls.md` §1,
  amended here at the coordinator's ruling); the tree is then `XFAIL`.
- **Places.** A site's file is made relative to the tree or to the
  subject, whichever it is under (a mark's file is a subject path,
  `spec/verify.md` §6.1). `removed` is read from `where.pre`. A `changed`
  is read from `where.pre` when the subject declares the entity and the
  tree derives it (§4 step 4); the runner asks `slip units` (pre-image,
  and `--post-image`) only when the two sides disagree on the line's
  place, so the answer cannot change otherwise.
- **`verified`** is met when the run's verdict and the observer's state
  are both `verified`: an observer that verifies in a run that is not
  verified (a stale observer, `spec/verify.md` §9.2) does not meet it.
- **Malformed**, beyond §1's list: an entry of the row's directory that
  is none of `pre`, `pre-<k>`, a tree, `expect.txt`, `declared.txt`,
  `declared-<k>.txt`; `<tree>: verified` for a `bad` tree; `none` for a
  `bad` tree; `good-<k>: none` without `pre-<k>/`; an `xfail` for a tree
  with no directory; two lines for one tree unless both are named
  `mismatch` lines.
- **Tier T2.** A subject that clang rejects is `ERROR` for each of its
  trees. A disagreement on a tree that has an `xfail` is a note, not an
  `ERROR`, and the tree's outcome follows its line.

## Cost

The catalogue takes 21 to 25 s of wall time in a test run (four threads),
the runner's own cases about 1 s; the peak resident memory of the test
and its `slip` processes is about 126 MiB, the largest `slip` about
29 MiB.

## Rows corrected at the first run

- **E06 subject 5**: the respelling of a parameter in a function that
  only returns `__PRETTY_FUNCTION__` verified, as `spec/digest.md` §9
  says it must (the string is only passed on; the names report, WP-112,
  is what tells the user). It is now part of `good-5`; `bad-5` respells
  the parameter of `width(Integer)`, which returns
  `sizeof(__PRETTY_FUNCTION__)` (19, then 15 with clang 19), and gives
  `mismatch changed width(int) @ main.cpp:5`. The table's E06 row says so.
- **Resolved units' names**: the instantiated body is the unit
  `<owner>::<definition>` (§6.1): N06 `bad-2`, `bad-3`, N28 `bad-2`, N40
  `bad-2`, R04 `bad`, R07 `bad-2`, E04 `bad-2` (`Tr<int *>`), E11 `bad`,
  E16 `bad-3`.
- **E22 `bad-7`**: the place is line 9, `M m(0)`: with the cast `m` is no
  longer the returned object, and that is written after `m`'s
  initialiser, whose literal is the last mark before the difference.
- **N22**: `good-2: none`, as `good` (the row's subject 2 had no line).
- **N44**: `pre-2/`, a copy of `pre/`, so that `declared-2.txt` has its
  subject; `good-2: none` (the hoist changes the linkage).
- **N39**: `declared.txt` relocates `Mine` only. The correct edit leaves
  `f` in `legacy`, so a rule for it left `good` stale (§9.2); `bad` moves
  `f` undeclared and still gives `changed acme::g()`.
- **E11 `good`, `good-5`**: their `xfail` lines (WP-045) removed; they
  verify.
