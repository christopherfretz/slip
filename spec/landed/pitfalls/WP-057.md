# WP-057 — pitfall rows N01 to N24: relocating a namespace

What the rows of `spec/pitfalls.md` §2 are, as
`crates/slip_verify/tests/pitfalls/n01-…` to `n24-…` build them, and
where they read the table differently from how it is written.

## Conventions of the rows

- Every subject has `dep/dep.h`, included as `"dep.h"` through `-Idep`,
  which declares in `namespace legacy` (so that `legacy` stays after the
  move) and, where a row needs it, the dependency's templates, macros or
  a library facility (`std::type_info`, `std::source_location` in N18).
  It is byte-identical in every tree of a subject; it differs between
  subjects only in N06 and N15, where the table puts the fallback in the
  dependency.
- Owned code is `main.cpp` and, where a row needs a second header, an
  owned header beside it (`box.h`, `box_ptr.h` in N19; `acme.h`, the
  pre-existing destination, in N21 and N22).
- A `pre-2/` is `pre/` with one line changed: the blank line 2 of `pre/`
  holds the fallback in `pre-2/`, so a line number means the same in
  both subjects. Where the correct edit inserts a line (N05, N08, N09,
  N16, N17, N20), `pre/` has a blank line there for the same reason.
- A block split is written on the line of the boundary
  (`} namespace legacy {`), so that the split adds no line.
- A row whose every `bad` tree is `not_parsed` says so in a comment of
  its `expect.txt`: `Caught only by a failed parse (spec/pitfalls.md §5)`
  (N02, N07, N09, N10, N16, N19).
- A using-declaration is two units, the using-declaration and its
  using-shadow, so a correct edit that adds one has two `created` lines,
  named as `spec/verify.md` §6.1 names them in the post-image:
  `legacy::<using acme::Mine>` and `legacy::<shadow acme::Mine>`; for
  N05, `acme::<using legacy::operator==>` and `acme::<shadow template
  <class> bool legacy::operator==(const type-parameter-0-0 &, const
  type-parameter-0-0 &)>`.
- Places (`@ file:line`) follow `spec/verify.md` §6.1: the call or use
  for `changed`; the unit's first mark (its first declaration) for
  `removed` (in the subject) and for a declaration row such as a base or a
  namespace's flag. N20 has none: the post-image has two units of the key
  and the site is the one with the smaller digest.

## Where the rows differ from `spec/pitfalls.md` §2

- **N06.** The table names `legacy::store<legacy::Mine>`. The call is in
  the instantiated member `put`, whose body is in its own resolved unit
  `definition` (digest-kinds §11.9); the class specialisation's stream
  holds no member's body. The row names
  `legacy::store<legacy::Mine>::put(legacy::Mine &)`. `spec/verify.md`
  §6.1 does not say how a resolved unit is named; the line assumes the
  name of the unit it belongs to.
- **N15.** The macro body is `legacy::make<T>(0)`, not
  `legacy::make<T>()`: a worse-matching `legacy::make` that keeps the
  call compiling needs an argument to be worse on. With no argument the
  candidates tie (or are ordered by the trailing-pack rule of
  [temp.func.order], a second hazard).
- **N20.** `legacy::f` is written `legacy::f()`, the §6.1 name of a
  function. Moving `f` in `bad` also respells its call (`acme::f()`), so
  that the tree compiles.
- **N23.** The table asks for `changed` at a caller that uses the
  default. The default argument is written in the function's unit, not
  at the use (digest-kinds §7 "Shared nodes", §11.4), so the caller is
  the same in both images and the finding is on `legacy::take(int)`.
  The row uses a default argument; a default member initialiser behaves
  the same way (`FieldData` `init`).
- **N05, N16, N17.** Each `created` is two lines (above).
- **N09.** The new alias is a unit: `declared.txt` has `created A`,
  which rule 3 of the package lists only for N05 and N16.
- **N11, N18.** The second (and third) shape is a second subject
  `pre-2/` (`pre-3/`), not a fallback added to `pre/`.
