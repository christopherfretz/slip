# WP-003 — slip_cdb: splitting, response files, normalisation, ByExtension

Behaviour landed by WP-003 that `spec/cdb.md` §3–§6 does not state. Each
choice is the conservative reading of a gap; the supervisor folds or revises
them at the end of M0.

## §3 Split errors

`SplitError.offset` is a byte offset into the input: of the opening quote for
a quote never closed (a backslash immediately before the end of a quoted part
leaves it unclosed), of the backslash for a trailing backslash, and 0 for a
string with no words. Only space, tab, newline and carriage return separate
words; other whitespace is an ordinary character.

## §4 Response files

- An empty response file (no words) is not an error: it contributes no
  words. §4's list of errors does not include it; §3's "no words" error
  applies to a `command` string only. (`split_response("")` is `Ok([])`.)
- `@` alone names no file and is kept as an ordinary argument.
- Depth: a response file named on the command line is at depth 1; one named
  inside it at depth 2. Depth 16 is accepted, 17 is `malformed_entry`. A
  cycle therefore ends as "nested deeper than 16".
- Relative paths at every depth are relative to the entry's `directory`, not
  to the response file naming them (as §4 says; restated because clang's
  default differs).

## §5 Normalisation

- An empty argument list (after §4) is `malformed_entry`.
- `--output=<x>` and `-fdiagnostics-color=<x>` are removed for any `<x>`,
  including empty; only the first five joined forms require a non-empty
  `<x>`.
- Classification precedence for one argument: exact "removed, separate
  value"; exact "kept, separate value"; "removed" alone or joined; input;
  otherwise a kept option. Step 4 inspects only kept options (never values).
- Any failure to resolve the input's real path is `missing_file` (detail
  "does not exist" for not-found, the OS error otherwise). A `file` whose
  real path cannot be resolved does not match (`malformed_entry`).
- Step 5's non-source extension is taken from the input as spelled.
  (As landed, that check ran last; review moved it before the existence
  check and `spec/cdb.md` §5 now states the order.)

## §6 ByExtension

- `main` (the real path of the main file) is not read; the extension is that
  of the input as spelled in `argv`. The input is found with the §5 step 3
  scan.
- The language values are `-x <v>`, `-x<v>`, `--language <v>` and
  `--language=<v>`; one that is the value of another option is not a
  language.
- A command with no input or with several inputs is
  `UnsupportedLanguage` (detail says which); one whose scan fails (a
  separate-value option with no value) is `UnsupportedFlag(<option>)`.
- `-x none` is `UnsupportedLanguage` (it is not in the value list).
  Review corrected preprocessed C to the driver's spelling, `cpp-output`
  (the spec's first wording implied `c-cpp-output`, which no driver accepts).
