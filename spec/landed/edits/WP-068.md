# WP-068 — slip_kiln: sites, the residue scan, and trees for tests

`crates/slip_kiln/src/sites.rs` (`spec/edits.md` §2.2, §2.3, §4.2),
`crates/slip_kiln/src/scan.rs` (the lexical half of §8.4) and
`crates/slip_kiln/src/tree.rs` (a front end over files on disk, for
tests), with two additions to `crates/slip_kiln/src/ranges.rs`. Tests:
`crates/slip_kiln/tests/sites.rs` (sites and tree) and
`crates/slip_kiln/tests/scan.rs`. Kiln sites are at Slip's pin
`913a490bb`, under `kiln/crates/`.

## What was built

- **`sites`**: `Sites::new(unit, ownership)`, `name_token(span,
  spelling) -> Located`, `file_ref(file)`, `is_owned(file)`, and
  `sites::Reason`, the rows of §2.3's table in its order, with
  `Reason::wire()` (decision 1). `sites` computes no range and no end
  of a token: each range it gives is an answer of `ranges` for a span
  Kiln gave.
- **`scan`**: `scan(bytes, name) -> Vec<Hit>`: Kiln's lexer in raw mode
  over the bytes, with a fresh source manager and interner per call.
- **`tree`**: `Tree::new(base, name, files)`, `root`, `observer(main,
  std, args)`, `parse(observer, options, f)`; removed on drop by the
  paths it wrote.
- **`ranges`** (WP-084's module), two functions so that `sites` carries
  `ranges`' answers instead of finding them again:
  `file_range_or_why(sm, span) -> Result<FileRange, NoRange>`
  (`file_range_of_span` is now its `.ok()`, unchanged), whose
  `NoRange::Directive` is the directive refusal; and
  `spelled_range(sm, span)`, Kiln's `editable_file_range` of the span's
  ends taken to their spelling, for a `macro_body` refusal's place
  (decision 6). Neither adds a rule for a range of file characters.
- **The kiln-boundary lint** lists `sites` beside `kiln`, `snippet` and
  `ranges` (`xtask/src/lint/crates.rs`, `kiln_module_paths`; test
  `s3_kiln_boundary_kiln_modules`): `name_token` takes Kiln's `Span`
  and `Located` holds Kiln's `FileId`, which a crate can reach without
  naming `slip_kiln::kiln`, as WP-084 decision 12 argues for `ranges`.
  `scan` and `tree` name no Kiln type and are not listed.

## Decided where the spec was silent

1. **`directive` has no wire value.** §2.3's table has a `directive`
   row; §4.2's `Reason` (`slip_model::edits::Reason`, WP-060) has no
   value for it. `sites` does not invent one: its `Reason` is its own
   enum, the table's rows in order, and `Reason::wire()` is `None` for
   `Directive`. A producer that must write a claim has to choose until
   §4.2 has the value (proposed in the Handback: `directive = 10`).
2. **`not_a_file` of a file location** (a token written directly in a
   buffer that is not a file: a snippet's file, the predefines) is tier
   X, the first row of the table, after `crossing` and before
   `directive`: rule 1 notes that the buffer is not a file, and rule 2
   gives `crossing` first if Kiln has no range and `not_a_file` if
   `ranges` says `Directive` (tests `s2_3_order_crossing_before_not_a_file`,
   `s2_3_order_not_a_file_before_directive`). The package's rule 3 names
   only the range's buffer; for a name written in a file, the range is
   in the same buffer (the argument's or the enclosing invocation's), so
   its check never fires alone (mutation M9, argued).
3. **The tier of a refusal**: `macro_body` 2, `pasted` 3, `crossing` and
   `not_a_file` X, and for `directive`, `not_owned`, `file_recoded` and
   `not_plain` the tier of rule 1 (0 or 1): they are properties of the
   range or the file, not of where the token is written. `not_plain` of
   `ID(foo)` is tier 1, as the package says.
4. **No `at` in a buffer that is not a file or whose load report is not
   clean.** Such offsets are not offsets of a file's bytes. So
   `not_owned` in a recoded read-only file has `at: None`
   (`s2_3_order_not_owned_before_file_recoded`), and so has a refusal
   whose invocation is in a recoded file. Offsets before a file's first
   replacement would be right; the rule does not use that.
5. **`macro_site` only in the claim's file.** `MacroSite::name_start`
   is "an offset in the claim's file" (§4.2). A `macro_body` refusal's
   range is in the definition; when the invocation is in another file
   there is no `MacroSite` (`s2_2_tier2_a_body_in_a_read_only_header`).
   For an `At` and every other refusal the invocation encloses the
   bytes, so it is in the same file.
6. **`macro_body`'s place is not `file_range_of_span`'s.** A body lies on
   a `#define` line, which `ranges`' interim directive check refuses
   (WP-084 decision 10): every body token would have no `at`. The place
   a person must look is not an edit, so it is `ranges::spelled_range`,
   Kiln's `editable_file_range` of the spelled span without that
   refusal. When there is none, the invocation's name is given.
7. **A file location in `<scratch space>`** reached by the walk
   (`#embed`'s tokens, a `_Pragma` buffer) is `pasted`: its bytes are
   not the unit's text. No name token is known to be there.
8. **`Located`** derives `Clone, Debug, PartialEq, Eq`; `Sites` keeps no
   cache of `FileRef`s (a binary search of the shard's sorted `inputs`
   by real path is the lookup; the interface's comment allowed one).
9. **`Tree::parse` takes `&ParseOptions`**: the package wrote
   `ParseOptions<'_>`, and the type has no lifetime (WP-067). It parses
   for `Phase::Map`, round 1. `Tree::observer`'s `main` is the file's
   real path, size and digest as written (zero and the empty digest when
   `main` is not one of the files), its `id` the command's `ObserverId`,
   its origin `(0, 0)`.

## WP-084's interim refusals, as `sites` sees them

- **A range over a line beginning with `#`** (decision 10): `ranges`
  says `NoRange::Directive`, and `sites` says `directive`, the row of
  §2.3 that names `ranges`' refusal. It cannot tell a real directive
  from a raw string's or a comment's line (Slip's limit until Kiln
  records directive lines, KB3), and the doc of `Reason::Directive`
  says so. Test `s2_3_directive_interim_raw_string_line` pins the
  false positive.
- **A span ending at `>>`, `>=`, `>>=`** (decision 6): only
  `ranges::file_range` refuses it; `name_token` maps the name's span as
  the written table gives it (`file_range_or_why`), and the invocation's
  name is one identifier. So the refusal never reaches `sites`.
- **`#embed`'s tokens** are no names; a scratch-space file location is
  `pasted` (decision 7).

## Where the tier could not be told from the source manager alone

Each is a candidate for KF3 §3 (`docs/requests/KF3-location-utilities.md`):

1. **Scratch space is known by a name.** `is_written_in_scratch_space`
   reads the *presumed* file name (`manager.rs:1170`): a real file with
   `#line 1 "<scratch space>"` makes its tokens `pasted`, and nothing
   tells a scratch buffer from a file except that name.
2. **"Not a file" is `file_origin` plus the shard's inputs.** A buffer
   Kiln creates in memory is `Virtual` whatever it stands for: an
   overlay given to Kiln as a virtual buffer would be `not_a_file`
   (the overlay parse, `spec/edits.md` §7.1, must give its files as
   files). The predefines and the command line's macros are told apart
   from a file only so.
3. **A builtin macro and a paste** are the same fact (a macro entry
   spelled in scratch space); both are `pasted`, as §2.2 wants, but a
   report cannot say which.

## `scan`

**Kiln's lexer decides what a token is.** `kiln_lex::Lexer::new`
(`kiln_lex/src/lexer.rs:114`) over one virtual buffer, options
`LexOptions::new(Std::Cxx26)` with `keep_comments` (`options.rs:67`).
Identifiers are compared by their interned symbol (`TokKind::Identifier`,
`token.rs:86`: universal-character-names resolved, splices removed); the
hit's range is the token's span as written. Mentions are searched in the
token's spelling with splices removed (`kiln_lex::clean`,
`spelling.rs:33`) and mapped back with `kiln_lex::source_offset`
(`spelling.rs:48`); a word character is what `kiln_lex::is_identifier`
(`unicode.rs:550`) takes after `_`, and `$`. Lines and columns are
`SourceManager::line_col` (`manager.rs:1344`): lines end at `\n`,
`\r\n`, a lone `\r`; columns in bytes.

Decisions:

1. **Header names** are lexed where Kiln's preprocessor asks for one
   (`Preprocessor::lex_header_name`, `kiln_pp/src/directive.rs:1265`,
   `LexMode::HeaderName`): after `#include`, `#include_next`, `#import`,
   `#embed` with `#` (or `%:`) first on its line (comments before it or
   between do not count), after `__has_include(`, `__has_include_next(`,
   `__has_embed(`, and after `import` or `export import` first on a
   line. No hit inside a header name (the package's rule): a file name
   is not a mention of an entity. `#include FOO` has the identifier.
2. **Mentions** are words in a comment, a string literal, a raw string
   literal (its delimiter included: it is part of the literal's
   spelling, and the scan errs to reporting), a character literal, and
   an error-recovery token (an unterminated literal: `#warning can't
   use foo` mentions `foo`). A literal's ud-suffix is part of it
   (`""_foo` mentions `_foo`).
3. **Escapes.** In a literal, an ASCII letter or digit right after an
   odd run of `\` is an escape, not part of a word: `"\nfoo"` mentions
   `foo`.
4. **Invalid UTF-8.** Each byte of an invalid sequence is lexed as
   U+0001, so offsets are the file's. Kiln's own load makes one U+FFFD
   that its lexer knows for a replacement (`lexer.rs:574`, `:1060`): it
   ends an identifier, is dropped between tokens, is no whitespace (a
   `\` before it splices nothing). U+0001 behaves the same for every
   hit; a U+FFFD spelled in the virtual buffer would not (Kiln's lexer
   keeps a real U+FFFD inside an identifier for recovery).
5. **A byte-order mark** is skipped by the lexer and counts in the
   column (`int foo;` after a BOM: column 8).
6. `#error`, `#warning`, a skipped `#if 0` group, `#ifdef foo`, a
   stringized argument `S(foo)`: raw lexing sees identifiers, which are
   hits (`mention` false); classifying them is WP-076's.
7. An empty name, or one that is not UTF-8, spells nothing; a file
   beyond Kiln's location space (about 2 GiB) gives no hit.

Known limits (each a residue the scan does not report):

- **`a##b` forms no mention of `ab`**, nor does any macro that builds
  the name.
- **A name spelled by escapes in a literal** (`"\x66oo"`,
  `"foo"`) is not found: literals are not decoded.
- **A ud-suffix of a number** (`12_foo`) is inside a pp-number and is
  not found; one of a string or character literal is a mention.
- **Trigraphs**: the scan lexes as C++26, where `??/` is no splice; an
  identifier split by a `??/` newline in a C++14 file is two
  identifiers.
- **A universal-character-name in a comment** (`// café`) is not
  `café`: comments are not decoded.
- **A header name** is never a hit, by decision.

## Found in Slip

- `crates/slip_kiln/src/written.rs:403` (`identifier_span`, WP-067): a
  declaration whose name is written with a universal-character-name or
  a line splice (`int café;`) has no `DeclName`: the span's text is
  compared with the identifier's characters. A rename then never sees
  that declaration. Found writing `s2_3_not_plain_a_universal_character_name`
  (which uses a reference instead).
