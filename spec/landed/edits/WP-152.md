# WP-152 — rename: what the new name finds at each instance a dependent name was edited on

Resolves finding 1 of `spec/landed/edits/WP-139.md`. Code:
`crates/slip_model/src/edits.rs` and `crates/slip_model/src/formats/edits.rs`
(`Reason::CapturedAtInstance = 14`, `"captured_at_instance"`, no format
version bump), `crates/slip_reduce/src/records.rs` (`reason_of`),
`crates/slip_kiln/src/written.rs` (`AdlSetId` and `Instance::adl`),
`crates/slip_refactor/src/rename/{dependent.rs,claims.rs,mod.rs}` and
`crates/slip_refactor/src/lib.rs`. Spec: `spec/edits.md` §4.2, §9.4,
§9.5 and §9.6.

## What Kiln exposes at pin `60fb5ab9d`

Kiln's per-specialisation table (`WrittenRefs::specs()`, `SpecRef`,
`kiln/spec/ast.md` §18.9) records `(entry, spec, entity, found, adl,
udir, flags, how)`. It records the **entity found**, not the lookup's
context class, except for argument-dependent lookup (`SpecRef::adl`).
On the AST itself, Kiln exposes `Ast::lookup_local(ctx, name)` (with
`LookupFlags::ADL_ONLY` and `LookupFlags::VIA_INLINE`),
`Ast::shadow_hider` / `Ast::using_named` (WP-3403), `BaseSpec::is_virtual`,
and `ExprArena::children_into`.

| Lookup shape | `RefLookup` | Context source at pin `60fb5ab9d` | Status |
|---|---|---|---|
| Argument-dependent lookup (`f(t)`) | `Adl`, `Both` | `SpecRef::adl` (`AdlSet`: `namespaces()`, `classes()`, `enums()`) + `Ast::lookup_local` + `LookupFlags::ADL_ONLY` / `lexical_ctx` | Checked (`captured_at_instance`; deliberately refuses non-viable overloads pending Kiln's overload facts; missing `adl` fails closed) |
| Member access in walked body / init (`t.f`, `p->f`, `this->f`, `t.B::f`, `t->f` via `operator->`) | `Member` | Rebuilt `MemberExpr` inside `spec`'s walked AST (`decl_ref_extra.qualifier` else base type with implicit `DerivedToBase` / `UncheckedDerivedToBase` / `NoOp` / `LValueToRValue` peeled; never explicit casts) + post-image `[class.member.lookup]` (incl. injected-class-name; no virtual-base dominance) | Checked (`captured_at_instance`) |
| Qualified name in walked body / init (`T::f`, `&T::f`, `D::f`, ctor mem-init, default member init) | `Qualified` | Rebuilt `DeclRefExpr` / qualified `MemberExpr` inside `spec`'s walked AST (`decl_ref_extra.qualifier`) + post-image `[class.member.lookup]` | Checked (`captured_at_instance`) |
| `Member` / `Qualified` where lookup context is not recovered or a walk/depth limit is hit (alias templates, requires-clauses, substituted signatures, default arguments, `decltype` in a local type alias, `WALK_LIMIT`, `BASE_DEPTH_LIMIT`) | `Member`, `Qualified` | `SpecRef` has no lookup-context class and the walked roots of `spec` do not recover it (or hit a limit) | **Fail-closed**: refused `captured_at_instance` with note, unless no class in the TU declares a member named `new_name` and no class is itself named `new_name` (For Kiln #1) |
| Ordinary unqualified lookup at the pattern's definition (`Unqualified`, and the ordinary-lookup half of `Adl` / `Both` outside the associated set) | `Unqualified`, `Adl`, `Both` | Enclosing-scope walk from `DependentName::enclosing` (`lookup_local`, `using_directives`, `ctx.named.new` for function locals/params/template params, `member_lookup_post` for enclosing classes) | **Fail-closed**: refused `captured_at_instance` when any non-subject `new_name` is found in an enclosing scope not hidden by a subject (For Kiln #2) |

## What was built

1. **`Reason::CapturedAtInstance = 14` (`captured_at_instance`).**
   Added to `slip_model::edits::Reason`, `formats::edits::Enumeration`,
   and `slip_reduce::records::reason_of` without changing container
   format versions (12 stays unlisted, 13 is `rebuilt`, 14 is
   `captured_at_instance`; `spec/model.md` §2).
2. **Per-instance capture check (`dependent.rs`).**
   When every evidence row of a dependent name binds a subject under
   `dependent: offer`, `captures` checks each row before emitting
   `replace`. Fast path: if `new_name` is not interned in
   `ast.symbols()`, no declaration in the unit is named `new_name` and
   nothing is scanned.
   - `Lookup::Adl | Lookup::Both`: reads `SpecRef::adl` via
     `written::Instance::adl` and scans each associated namespace's
     `Ast::lookup_local(ns, new_name)` for `Function | FunctionTemplate`
     declarations (admitting `LookupFlags::ADL_ONLY` hidden friends only
     when lexically declared in an associated class, mirroring
     `kiln_sema::overload::adl`). Any non-subject is a capture
     (deliberately including non-viable overloads, since Slip does not
     perform overload resolution pending Kiln's overload facts). Missing
     `SpecRef::adl` fails closed. Also runs enclosing-scope ordinary
     unqualified lookup (below).
   - `Lookup::Unqualified` (and the ordinary half of `Adl` / `Both`):
     walks enclosing scopes from `DependentName::enclosing` outwards
     (classes via `member_lookup_post`, functions via `lookup_local` and
     `ctx.named.new` for locals, parameters and template parameters,
     namespaces and the translation unit via `lookup_local` and
     `using_directives`), stopping at a scope that declares/introduces a
     subject named `old_name` and no non-subject `new_name`. Any
     non-subject found refuses `captured_at_instance`.
   - `Lookup::Member | Lookup::Qualified`: walks `spec`'s instantiated
     AST (`body`, `ctor_inits`, `var.init`, `field.init`, `field.bit_width`,
     class `StaticAssert`s, lambdas, statement expressions; bounded by
     `WALK_LIMIT = 100_000`) to find the rebuilt `MemberExpr` or
     `DeclRefExpr` at `name.name.lo` resolving to `entity`, recovers the
     qualifier or unpeeled object class, and runs `member_lookup_post`.
     Whenever no class is recovered or `WALK_LIMIT` / `BASE_DEPTH_LIMIT`
     is hit, the check **fails closed** (`captured_at_instance` with a
     note saying context was not recovered or the limit was hit), with
     the one exception that if no class in the TU declares a member
     named `new_name` and no class is itself named `new_name`, it
     accepts.
3. **Hiding vs capture (Item 2).**
   - In class hierarchies (`member_lookup_post`), lookup for `new_name`
     is simulated in the **post-image**:
     - If class `c`'s own name is `new_name` (injected-class-name,
       `[class.pre]/2`), or `c` directly declares or introduces (via a
       non-hidden `UsingShadow`, `ast.shadow_hider(d).is_none()`) any
       non-subject named `new_name`, lookup in `c`'s subobject stops and
       records a capture (naming the class or declaration found).
     - Else if `c` directly declares or introduces any subject named
       `old_name` (which will be named `new_name` in the post-image),
       lookup in `c`'s subobject **stops without recursing into `c`'s
       bases** (`[class.member.lookup]/2`). Any `new_name` in a proper
       base of `c` is therefore hidden by the renamed entity and is not
       a capture.
     - Otherwise, lookup recurses into every base of `c` (virtual and
       non-virtual alike; **no virtual-base dominance rule**). Every
       non-subject provider reached through any base (derived class,
       same class, sibling base, virtual base, or diamond) is a capture.
   - In ADL, non-functions and `ADL_ONLY` hidden friends of
     non-associated classes are ignored before and after and are not
     captures.
4. **Naming the specialisation and the declaration found.**
   When any capture (or fail-closed condition) is found, `dependent.rs`
   emits `refuse(captured_at_instance)` at `name.name`, records the
   site's `Instance`s (carried to `EditSet.instances` as for every site
   refusal), and attaches one `Severity::Note` `Report` per unique
   capture at `name.name`:
   `in <spec display>: new name '<new>' finds <found display>`,
   `in <spec display>: new name '<new>' finds injected-class-name <class display>`,
   or a note saying that lookup context was not recovered or a walk /
   base-depth limit was reached.
   `EditSet` and `Refusal` require no format version change; `slip
   reduce` joins and counts these reports across observers and prints
   them beside the refusal and `instance refused` lines.
5. **Unified capture-check list (Item 3).**
   `spec/edits.md` §9.4 lists in one place the two checks inherited
   from §9 (`name_taken` and derived-unit verification), the four
   per-instance checks added by WP-152 (`Member`, `Qualified`, `Adl` /
   `Both`, and enclosing-scope ordinary unqualified lookup), and the two
   fail-closed shapes waiting on Kiln.

## Decisions

1. **Naming the declaration found via `Severity::Note` `Report` + `EditSet.instances`, not a new `Refusal` field.**
   Adding a field to `Refusal` or `Instance` would bump `EDTS` version 3
   to 4 (changing every edit set id) and widen the WP's interface
   (`docs/wp/WP-152.md` "Interface" specifies `slip_model`: `Reason`,
   one value). `Edits.reports` already exists, is joined by reduce,
   survives refusal, and is printed by `slip reduce` / `slip rename`.
   `Severity::Note` has no effect on verdict state.
2. **Peeling implicit `DerivedToBase` / `UncheckedDerivedToBase` / `NoOp` / `LValueToRValue` on `MemberExpr::base`, never explicit casts.**
   Kiln inserts `ImplicitCastExpr(UncheckedDerivedToBase)` on `base`
   when a member is found in a base class (`this->f()` in `D : T` casts
   `D*` to `S*`). Peeling only implicit adjustments recovers `D`, while
   an explicit `static_cast<S*>(this)->f()` stays `S` (no false refusal).
3. **Walking `spec`'s AST for `Member` / `Qualified` context, failing closed when unrecovered.**
   `SpecRef` does not store the lookup context class, so `this->f()` in
   `wp139_new_name_captured_in_an_instantiation_is_not_verified`,
   `t.f()`, `(&t)->f()`, `t->f()`, `T::s()`, `&T::f`, `D::f()`,
   mem-initializers, and default member initializers cannot be checked
   from `SpecRef` alone. Walking `spec`'s owned statement/expression
   roots covers those common shapes; any shape whose rebuilt expression
   is not walked or not kept (default arguments `int x = T::s()`,
   `using R = decltype(T::s());` in a body, alias templates,
   requires-clauses, substituted signatures) or that hits `WALK_LIMIT` /
   `BASE_DEPTH_LIMIT` now **fails closed** (`refuse(captured_at_instance)`
   with a note), with the sole exception that when no class in the TU
   declares a member named `new_name` and no class is itself named
   `new_name`, no member/qualified lookup can capture it and the check
   accepts.
4. **No virtual-base dominance rule (fix round 1).**
   The initial round implemented `is_virtual_base_of`, which conflated
   distinct subobjects of the same base class (probe `d1`:
   `D : virtual X<U>, L<U>` with `X : V`, `L : virtual V` accepted and
   became ambiguous in the post-image). Fix round 1 removed virtual-base
   dominance altogether: any non-subject provider reached through any
   base (virtual or non-virtual) counts as a capture and refuses.
5. **Non-virtual base hiding vs virtual base overriding.**
   A non-virtual base `Base<int>::g()` directly hidden by `S<int>::f -> g`
   is not a lookup capture at `t.f() -> t.g()`. If `Base<int>::g()` were
   `virtual` with a matching signature, renaming `S::f` to `g` would
   introduce a new override (not a lookup capture of `t.g()`); digest
   verification catches that via the `overrides` row of `S<int>::g()`.
6. **Non-viable ADL candidates refused (fix round 1).**
   Probe `b1` (`o::g(int)` cannot take `(m::A, o::X)`) stays refused:
   Slip performs no overload resolution, pending Kiln's overload facts.
   The note names the candidate found (`o::g(int)`).

## For Kiln

1. **Lookup context class on `SpecRef` for `Member` and `Qualified` rows.**
   - **Slip need**: When `SpecRef::how` is `RefLookup::Member` or
     `RefLookup::Qualified`, record the class the instantiation's lookup
     searched (the object's class before derived-to-base conversion for
     an unqualified member access, or the qualifier's class for a
     qualified access / qualified name). This removes Slip's AST walk
     of `spec` and replaces the fail-closed refusal for unwalked/unkept
     shapes (alias templates, requires-clauses, substituted signatures,
     default arguments, `decltype` in a local type alias) when `new_name`
     happens to exist in an unrelated class.
   - **Source**:
     ```cpp
     namespace n {
     template <class T> struct S { static int s() { return 1; } };
     }
     template <class T> struct Der : T { static long sg() { return 0; } };
     template <class T> using A = decltype(T::s());
     template <class T> auto call() -> decltype(T::s()) { return 0; }
     int u() { A<Der<n::S<int>>> x = 0; return (int)sizeof(x) + (int)sizeof(call<Der<n::S<int>>>()); }
     ```
     Renaming `n::S::s` to `sg`: empirically observed
     (`rename::dependent::tests::wp152_alias_template_spec_ref_observed`),
     `SpecRef` records `entity = n::S<int>::s()` and `spec = A`
     (`DeclKind::TypeAliasTemplate`, display `"A"`) /
     `call<Der<n::S<int>>>()`, without recording that the nominated
     class was `Der<n::S<int>>`. Tested by `wp152_kiln_gaps_fail_closed`.
2. **Post-parse ordinary unqualified lookup at a `WrittenRef` entry's lexical position.**
   - **Slip need**: For a dependent unqualified call (`RefLookup::Adl`,
     `RefLookup::Both`, `RefLookup::Unqualified`), check what ordinary
     unqualified lookup at the pattern entry's definition point finds
     for `new_name` (enclosing scopes, block-scope locals, template
     parameters, visible using-directives, respecting point of
     declaration). `Ast::lookup_local` searches one `DeclContext` and
     cannot answer block-scope / point-of-declaration precision, so Slip
     walks enclosing scopes and fails closed conservatively.
   - **Source**:
     ```cpp
     namespace m { struct A {}; int f(A) { return 1; } }
     int g(m::A) { return 2; }
     template <class T> int call(T t) { return f(t); }
     int u() { return call(m::A()); }
     ```
     Renaming `m::f` to `g`: `SpecRef::adl` contains only namespace `m`,
     so `::g(m::A)` in the global namespace (found by ordinary lookup at
     `call`'s definition, causing ambiguity in the post-image) is caught
     by Slip's enclosing-scope walk and refused (`wp152_kiln_gaps_fail_closed`).
