# WP-066 — parsing through Kiln's overlay (KF2 stage 1)

What `crates/slip_kiln/src/parse.rs` gained to parse a unit with some
files' bytes replaced (`spec/edits.md` §7.1), against Kiln's overlay
(Kiln WP-2390, at the pin `4a83f6e3c`; `kiln_source/src/overlay.rs`).
The pin move itself is `spec/landed/digest-kinds/WP-066.md`.

## Interface

- `ParseOptions` gains `pub overlay: &'a [(&'a [u8], Arc<[u8]>)]` (so
  `ParseOptions<'a>`; the default is empty): replacement bytes by real
  path, absolute paths only, sorted by path, no two equal. The package text calls the entry
  `parse_observer_opts`; it is `parse_observer_with` (WP-067's name).
- An empty overlay gives no Kiln overlay at all
  (`FrontEndOptions::overlay` stays `None`): the shard is byte for byte
  `parse_observer`'s (`tests/overlay.rs` `empty_overlay_is_parse_observer`).
- `Err` before the parse: a relative entry (second review F7: it would
  resolve against the process's directory, not the command's, and could
  overlay a decoy); an entry not after the one before it; a path
  Kiln's `Overlay::replace` refuses (missing, not a regular file;
  `overlay.rs:329`); two entries of one file identity (below).
- `inputs`: an overlaid buffer's size and digest come from
  `SourceManager::original_bytes` (`kiln_source/src/manager.rs:1503`),
  which is the overlay's bytes. A consulted path that is no buffer (an
  `#embed` resource: Kiln keeps none of its bytes) is digested from the
  overlay's bytes when the overlay replaces it (`overlaid_bytes`), else
  from the disk as before.
- The check that no file changed during the parse (`merge_inputs`)
  compares the candidates `collect_inputs` made, so an overlaid file is
  compared with the overlay's bytes, never with the disk.
- `Unit::overlaid(&self, file: FileId) -> bool`: `FileOrigin::Overlay`.
  Kiln matches an entry to a file by identity, and the shard records an
  input under the spelling the unit reached it by, not the entry's (an
  entry `…/H.h` reached by `#include "h.h"` on a case-insensitive
  volume). So the rule (second review F8; `spec/edits.md` §7.1, the
  doc of `Unit::overlaid`): a consumer never matches an input to an
  entry by path text; it asks `Unit::overlaid`.
- `FrontEndReport::overlay_failures` non-empty: the run is void, and
  `parse_observer_with` returns `Err` naming the first entry.

## Tests (`crates/slip_kiln/tests/overlay.rs`)

Each case is checked against the reference: the same command without an
overlay over a copy of the tree in which the overlaid files hold the
overlay's bytes, the shard's paths rerooted to one string. Cases: the
main file; a header by two spellings and by a symbolic link (one input
entry); an overlay that adds an `#include` and one that removes one; an
empty overlay; an overlaid header and `#embed` resource that differ on
disk (the overlay's digests, no change reported); a missing path; two
entries of one file by a symbolic link and by a hard link; a relative
entry (`relative_entry_is_err`); an input reached by another case than
its entry, which `Unit::overlaid` says is the overlay's
(`an_input_reached_by_another_case_is_overlaid`, skipped with its reason
on a case-sensitive volume); the overlay
with `written` on (the table's offsets are the overlay's bytes). In
`parse.rs`: `s8_4_inputs_a_file_changed_during_the_parse_is_err` (another
file changed is `Err`).

## Where Kiln's form departs from the request (KF2 §1), and what Slip does

1. **Two entries of one file.** Kiln keys an entry by the file's
   identity and lets a second entry replace the first silently
   (`overlay.rs:323`). The request wants it refused. Slip checks
   `Overlay::len` after each `replace` (`overlay.rs:525`): when it did
   not grow, the entry named a file already in the overlay, and the parse
   is `Err`. Test: `two_entries_of_one_file_are_err`.
2. **`overlay_failures` cannot happen with Slip's bytes.** Only a loader
   (`replace_with`) fails; Slip gives bytes (`replace`, `Content::of`),
   so the `Err` path is not provokable through `ParseOptions`. It is
   kept (the run would be void) and has no test.
3. **`#embed` resources.** Kiln reads them through the overlay but keeps
   no bytes of them in the source manager, so Slip's record of them reads
   the overlay itself (`Overlay::resolve`, `overlay.rs:608`). Test:
   `overlaid_file_differing_on_disk_is_not_a_change`.
4. **Another file changed during the parse** is not provokable in a test
   without a race; it is a unit test of `merge_inputs`.
5. Points 1 (every route), 2 (nothing else changes) and 4 (per call) of
   §1 are Kiln's acceptance (the request's §4, in Kiln). Slip's reference
   check covers the routes above; it does not repeat `#include_next`,
   `-include` or module maps.
