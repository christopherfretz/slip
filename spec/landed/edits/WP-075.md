# WP-075 — `reduce`, `apply`, and the store behind them

`crates/slip_cli` (`spec/exec.md` §8.12, §8.14; `spec/edits.md` §7,
§10.2, §10.5; `docs/wp/WP-075.md`): `src/transform/{mod,store,lines,
reduce,apply}.rs`, the parsing of `reduce` and `apply` and of the
options a transform's commands share (`TransformOptions`, for WP-076)
in `src/args.rs`, two dispatch arms in `src/commands.rs`, and
`tests/stages.rs` (30 tests, through the executable over a store the
test fills with `slip_model`). Outside `slip_cli`:

- `name()` on `slip_model::formats::edits::{Reason, Severity,
  FailureKind}`, with the test `s10_5_enumeration_names` in
  `crates/slip_model/tests/edits.rs` (the lines print the names of
  §10.5, and only `State` and `Cause` had them).
- From the review's fix round, in `crates/slip_apply`: the one-spelling
  check of `spec/edits.md` §2.1 (`Tree::names`, `Refused::NotCanonical`,
  `check_owned`, run by `write` and `recover` before any ownership
  decision), and `Journal::of_write` (the journal a write of an overlay
  publishes, which `write` now builds with and `--recover` compares
  with). Tests in `crates/slip_apply/tests/write.rs`: a tree that finds
  names in any case (`Folding`), and one on disk.

## Differences from the WP's interface

- `edit_set_summary` takes `indivisible: bool` (the request's): the
  `groups` line is omitted for an indivisible request (§10.5), and the
  edit set does not say which it is.
- `edit_set_details` takes `record: &Path`, the edit set's file in the
  store: the cut line is `<kind>: <n> more (slip dump <file>)`.
- `reduce_round` returns `Reduced`, an alias of the WP's tuple (Clippy's
  `type_complexity`).
- `apply_result` writes only `written <n> file(s)` or `patch <path>` to
  `out`; `result <id>` and `state <State>` are printed by the command
  before it, so they are printed also when `permits` says no.
- `ReduceArgs::plan` is the WP's `PlanSource`; `reduce` accepts only its
  `Plan` form (`--plan <id or file>`).

## Decisions where the spec is silent

1. **The selected observers only.** `StoreShards` covers the observers
   of the round's latest map run record (`selected_of_round`), not
   every observer of the plan: an observer the phase did not select is
   not one of the run's, and is neither read nor counted as unparsed.
2. **The request is the first `edits` shard's**, in plan order of the
   selected observers; every other shard is checked against it by
   `slip_reduce` (§5.7), not by the command. A first shard naming a
   request the store lacks is an input error naming the `TRFM` file.
3. **`reduce` opens the store exclusively** (it publishes, and its runs
   use the scratch directory), so a store with a journal is refused
   with `StoreError::UnfinishedWrite` (status 3). It prints no `plan`
   line; its output starts with `edits <id>`.
4. **Threads.** `-j` bounds the CPU tokens `reduce` takes without
   waiting (at least one thread), as `plan` does; `fan_in` is 64. The
   output does not depend on either (§5.3; tested with `-j 1`/`-j 4`).
5. **Counts and groups.** The counts of the summary come from the
   edit set's records; the `groups` line from its group counters.
   `nested` is counted by a sweep over the edits of each file.
6. **Detail lines without a place.** A refusal with a site and no
   subject omits the display; one with neither prints
   `refusal <cause> (<observers part>)`. Places are `line:column` from
   the file on disk when its size and digest still match the
   `FileRef`, otherwise `:@<lo>`.
7. **`apply`'s status says what apply did** (coordinator's ruling, fix
   round; `spec/edits.md` §10.5 now says so): 0 when everything asked
   was done, whatever state the options given permitted
   (`verified_with_residue`, a partial result); 1 when it was refused
   and nothing was written; 3 for an error. The verdict is the `state`
   line. (The first round exited 1 for a written result with residue.)
8. **A stale file is a refusal under both actions**, status 1 (ruling,
   fix round): `--write` refuses it at §7.3 step 1 or 4, `--patch` while
   making the patch, which is then not written. (The first round made
   it status 3 under `--patch`.)
9. **`permits` first.** Nothing beyond the result and its edit set is
   read before `permits` answers. A no is
   ``slip: result <id>: its state `<s>` does not permit `--write` with
   the options given; nothing was written``, status 1. The overlay must
   be the result's and of its edit set, or it is an input error.
10. **The patch is written to a temporary beside it and renamed**; a
    file outside `--relative-to` is a usage error (status 2, §7.2)
    found before anything is written. The temporary,
    `.<name>.slip-tmp.<pid>`, is removed on SIGINT or SIGTERM by the
    same signal path that cleans the store's `tmp/` (a static slot
    names it while it exists). SIGKILL cannot be followed: the next
    `--patch` to the same file **reports** each such temporary of
    another pid beside it on standard error and leaves it (whether its
    process is alive cannot be told portably in safe std; removing a
    live run's temporary would break that run). Built: report, not
    remove.
11. **`--recover`.** Its output is
    `recovered: restored <n>, left <n>, reported <n>`, or
    `recovered: no unfinished write`; each reported path gets one
    standard-error line and the journal is kept (status 3). The
    ownership it checks is that of the write's request, found from the
    journal's overlay → its edit set → `set.transform` → `TRFM`; when
    that chain cannot be followed it is an input error and the journal
    is kept. `journal_not_owned` is an input error, nothing changed.
    Fix round: the journal must equal `Journal::of_write` of its overlay
    (the same files, `pre`, `post`, staged names), checked before the
    ownership, or it is an input error (status 3), nothing touched, the
    journal kept; and `slip_apply::recover` checks the spelling of every
    path first (`not_canonical`, status 3, the journal kept).
12. **Durability of the store's side.** `StoreBlobs::put` syncs the
    blob and `blobs/`; `StoreJournal::publish` writes a temporary in
    the process's scratch directory, syncs it, hard-links it to
    `write.journal` (failing if one exists) and syncs the store's root;
    `remove` syncs the root after removing.
13. **`--result`** is 4 to 64 hexadecimal digits, lower-cased, and
    must name exactly one result of the store.
14. **One spelling (fix round, ruling F1).** Apply writes a file only
    under the one spelling its directories have. In `slip_apply`, the
    last line before the tree is touched: every component of the path,
    **from `/` down** (stricter than the ruling's "from the owned root
    down": an owned root given in another case, say `--owned SRC` for
    `src`, would otherwise let `SRC/vendor/x.h` pass a `readonly` entry
    `src/vendor`), must equal byte for byte a name `Tree::names`
    (`read_dir`) lists for its parent, each directory listed once per
    call. A component that does not is refused `not_canonical` (naming
    the path and, when a listed name differs from it only in case, the
    spelling on disk) if a listed name differs from it only in case, or
    if `stat` (`lstat`) finds something at it; otherwise the path is
    missing and the checks after find it (`stale_file`). The listed
    name in another case is refused even when the lookup finds nothing,
    because this workspace's host mount (a FUSE volume) answers a
    lookup of a directory in another case one time and not the next
    (observed: `listdir` of `src/Vendor` failing and then succeeding,
    and `src/vendor` then failing), so the first version, which asked
    the volume whether the other spelling exists, let the reviewer's
    case through. A directory above the owned root that cannot be
    listed is an error (status 3), not a pass. Status 1 under `--write`
    and `--patch`, the tree untouched; status 3 under `--recover`.
15. **What reduce accepts today for such a path.** `Ownership::is_owned`
    and reduce's check are unchanged (ruling): an edit set naming
    `src/Vendor/x.h` under a request owning `src` with `src/vendor`
    read-only is accepted by reduce (bytes compare as owned), and apply
    then refuses it, `not_canonical`. Giving a file one spelling from
    the front end's inputs on is WP-147.
16. **`--patch` checks ownership as `--write` does** (fix round, F3a):
    `slip_apply::check_owned` before the patch is made (`not_canonical`,
    `not_owned`), the same refusals, status 1, no patch. It does not
    ask the in-place checks of §7.3 step 1 (hard links, permission
    bits, staged names): a patch replaces nothing.

## Open questions

- Decision 14 checks from `/` down, not from the owned root: a
  directory above the owned root that the user cannot list fails the
  write (status 3). Is that acceptable, or should the check start at
  the longest owned entry and leave the entry's own spelling to
  WP-147?
- The reviewer's Unicode case (another normalisation, no listed name
  differing only in case) is refused only when `lstat` finds the path;
  on a volume whose lookups are as unreliable for normalisation as this
  mount's are for case, such a path could pass. Not tested: no volume
  here normalises.
- Decision 1: whether an observer the map phase did not select should
  count as unparsed is §5's to say.
- The output lines of `apply --recover` (decision 11) are not in
  §10.5.
