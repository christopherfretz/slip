# WP-147 — one spelling per file

Status: item 1 (the proposal, §1–§7) **ruled**, below; item 2 built as
the ruling says, but for what waits on WP-074 and WP-114 (§6 step 5).
Read at `main` `b57d2b2b`, Kiln at the pin `4a83f6e3c`. Where the
proposal's text differed from the ruling it is changed to the ruling,
so §3–§6 describe what is built.

## The ruling

- **Q1. Normalise everywhere through one function; apply checks.**
  Accepted: `slip_spelling` (std only, `#![forbid(unsafe_code)]`, a
  default member). Three corrections, made in §3–§5:
  (a) a component with no ASCII letter is **not** exempt: a casefolding
  directory (ext4, f2fs, tmpfs) compares names under NFD with
  default-ignorable code points dropped and singleton decompositions
  applied, so a stored non-ASCII name is reached by a letterless ASCII
  spelling (`1\u{200B}3` as `13`; U+037E as `;`). A component passes
  without a listing only in a directory whose state is `NotFolding`; in an
  undecided directory a component that cannot probe lists it.
  (b) Only a component whose every byte is ASCII and which has a letter
  probes and sets `NotFolding`; the probe swaps the case of **every**
  ASCII letter. A component with a non-ASCII byte lists and never decides
  the state (ext4's casefold compares a name that is not UTF-8 by bytes:
  `fo\xFFo` probed as `FO\xFFO` misses in a directory that folds every
  valid name).
  (c) The process-wide lock is not held across `canonicalize`; it is held
  over one directory's step (its probe or listing) at a time.
- **Q2.** The counter `inputs.respelled`, no diagnostic, among the
  parse's counters; it must not change a shard's format, `scheme` or any
  content id on a volume that does not fold: it is present only when not 0.
- **Q3.** The allowlist is `ext2 ext3 ext4 xfs btrfs tmpfs f2fs`;
  **`overlay` is out** (its answers are its layers'; leaving it out costs
  one `read_dir` per directory per process; adding a type later is safe,
  removing one is not). A device on several mountinfo lines is trusted
  only if every line's type is in the list. Disk tests: `/dev/shm`
  (tmpfs: case-sensitive, nothing listed), `/tmp` (overlay: listed, does
  not fold), the workspace (FUSE: folds); one test says what `Disk` finds
  for each.
- **Q4. T1: refuse, status 3 (`Input`), and stricter:** where a `TRFM`'s
  ownership or a `DECL`'s files are read for a run, every entry must exist
  and be its own spelling; `Missing` is a refusal too.
- **Q5.** `--only` and `--match` stay byte filters over the on-disk
  spelling (`spec/exec.md` §8.2).
- **Q6.** Without mountinfo every directory is listed; an unlistable one
  there is status 3; a limit stated in `spec/edits.md` §2.1.
- **S1** through the same function, with a test (below, "As built").
- **Sequencing.** Steps 1–4, 6 and step 5's `commands.rs` and
  `transform/apply.rs` now; step 5's `image.rs` hunks and the T1 check in
  the worker and the verify job wait for WP-074 and WP-114 on `main`. The
  cost on `llvm` `lib/Support` is the supervisor's run (the command is in
  §6).
- **Mutations:** the six of §6, plus a letterless component exempt in an
  undecided directory, a non-ASCII component allowed to set
  `NotFolding`, `overlay` trusted, and `Missing` passed at T1.

The defect class: on a volume that finds a name in any case (or in any
Unicode normalisation) and keeps the spelling it was asked with,
`std::fs::canonicalize` returns the spelling it was **asked**, so one
file has as many "real paths" as the inputs have spellings of it, and
everything that compares path bytes (ownership, reduce's files, the
overlay, the verify job's maps) can be wrong. This workspace's volume
is one: a bind mount of a macOS volume (`fakeowner`, a FUSE mount),
case-insensitive, case-preserving, and it folds normalisation too
(`café.h` written NFC is found by its NFD spelling, same inode; the
listing has the NFC bytes). Every test below ran here; each skips,
saying so, on a volume of the other kind.

## 2. What Kiln does

Shown by `crates/slip_kiln/tests/one_spelling.rs` (passing tests, on
this volume):

- **Identity.** Kiln's source manager identifies a file by device and
  inode (`kiln_source` `FileKey::Unique`, from one `fstat` of the open
  file; clang's `UniqueID`). `#include "inc/Foo.h"` for `inc/foo.h`
  is one buffer, and the same header included as `foo.h` and as
  `FOO.H` in one unit is **one buffer** (`kiln_one_header_under_two_spellings`).
- **`#pragma once` and include guards** key on the buffer (`FileId`:
  `kiln_pp` `state.rs` `once: HashSet<FileId>`, `guarded:
  FxHashMap<FileId, …>`), so either keeps the second spelling out: the
  unit is `ok`. With neither, the header is entered twice, exactly as
  one spelling twice is (both diagnosed, the redefinition of `S`). The
  parse is right.
- **The spelling it reports** is the first: a buffer's `file_name` is
  the path as first loaded (header search joins the directory as given
  and the name as written), so `inc/FOO.H` when that came first.
  `slip_kiln` then makes it the input's path through `canonicalize`,
  which keeps that spelling (row K3).
- **No diagnostic.** Kiln has the group `nonportable-include-path` in
  its table of clang's groups and no warning in it; the unit has as many
  warnings as the same unit with the include spelled as on disk, where
  clang warns `-Wnonportable-include-path`.
- **Header search on a folding volume.** Kiln's resolver keeps a
  directory's listing, ASCII-lower-cased, to answer misses without an
  `open` (`kiln_pp` `resolver.rs` `Listing`), and compares a name with it
  ignoring ASCII case, so a folding volume still finds `Foo.h` as
  `foo.h`; a directory with a non-ASCII name is never used that way
  (`open` decides). Nothing there names a file: the spelling stays the
  one asked.

So Kiln has one file, and **no request to Kiln is needed** for the
parse: `docs/requests/KR7-…` is not written. The only Kiln-side
limit is its identity: a volume that gives one file two inode numbers
under two spellings (a CIFS mount with `noserverino`, some FUSE file
systems) would make two buffers and break `#pragma once`, as it
breaks clang. Slip cannot repair that from outside; it is stated in
`spec/edits.md` §2.1 as a volume Slip does not support (item 2), and
the function of §5 refuses where it sees it (two names, one path,
different identities).

## 3. The choice

**Normalise, everywhere a path enters, with one function; apply keeps
refusing** (it calls the same function and refuses unless the answer
is the path it was given). Argued against the inventory:

| | Normalise everywhere | Refuse everywhere | Normalise at the command line and the database, refuse in sources |
|---|---|---|---|
| The user sees | nothing; reports, patches and records name files as `ls` does | `--owned SRC` refused with both spellings (fine); a database whose `directory` is the shell's `$PWD` typed in another case refused or excluded (CMake records what was typed); an observer that includes a header in another case refused | the first two silent; the third refused |
| What breaks | nothing semantic; a volume that numbers one file twice (§2) is an error, not a wrong answer | a real tree on macOS with one nonportable include in a dependency (clang warns, the code builds): every observer that includes it is unparsed and the run is partial, and the user cannot fix a dependency | the same as refusing, for the same trees |
| Rows fixed | all | all, by refusal | all, the source rows by refusal |

The source rows decide it: an `#include` in a dependency is not the
user's to change, and Kiln parses it right (§2). Refusing there buys
nothing that normalising does not give, and costs the tree. At the
command line, a refusal would be acceptable, but one function and one
rule ("a file has the spelling of its directory entries, from the first
place a path enters") is simpler to state, review and test than two.
Apply is different: it is the last line of the trusted base and is
handed records, not user input, so it **checks** (the function's
answer must equal the path), as WP-075 built.

**Cost** at 10^5 observers and 10^4 directories on a case-sensitive
volume. The function walks a real path component by component and
caches per directory, keyed by the directory's identity:

- Per directory, once per process: one `lstat` of the directory (its
  device and inode: the cache key, and the mount it is on), and, the
  first time a component with an ASCII letter is looked up in it, one
  `lstat` of that component in another case (§4). On a volume Slip
  knows answers lookups consistently (below), "nothing, or another
  file" there means the directory does not fold: no `read_dir`, ever.
  That is two `lstat`s per directory per process, 2·10^4 for the
  package's tree, against the ten or so that `canonicalize` already
  makes per path. A component with no ASCII letter cannot probe: in an
  undecided directory it lists it; once the directory is `NotFolding` it
  passes.
- A component with a non-ASCII byte always lists its directory and never
  decides its state: Slip has no Unicode normalisation tables (no
  dependency), casefolding compares a name that is not UTF-8 by its
  bytes, and ZFS can normalise without folding case. Rare in source
  trees; none in `llvm`.
- Where a directory folds, or the mount is not known to be consistent
  (macOS, this workspace's mount, NFS, any FUSE), it is listed: one
  `read_dir` per directory per process, as the package bounds it.
- Per path after the first: a hash lookup per component.

**How the volume is known, per mount.** Linux only:
`/proc/self/mountinfo`, read once per process, gives each mount's
`major:minor` (the `st_dev` of its files) and its file system type. A
directory's device is looked up there; a type in the allowlist
`ext2 ext3 ext4 xfs btrfs tmpfs f2fs` is **consistent** (a local kernel
file system: a lookup's answer is the directory's, every time), and only
there does a probe decide anything; a device on several lines is
consistent only if every line's type is. Every other type (`overlay`
too: its answers are its layers'), a device mountinfo does not name (a
btrfs subvolume's anonymous device; this workspace's FUSE mount), and
every platform without mountinfo, is "list". Folding itself is never
decided per mount: ext4, f2fs and tmpfs (Linux 6.13) fold **per
directory** (`chattr +F`, inherited), and a non-folding parent can hold
a folding child, so the probe is per directory, on its own device.
**A tree that spans mounts** is safe for the same reason: each
directory is decided on its own device (a mount point's lookup is in
its parent's directory, on the parent's device; the names in it are on
its own), and the cache is keyed by `(device, inode)`, never by a
path.

**Unicode normalisation** is the same defect by another fold, and the
byte comparison against `read_dir` covers it: a listed name is the
bytes the volume stores, so a component not byte-equal to one is not
the volume's spelling (A1, K4: the NFD spelling of an NFC file is not
in the listing). What a byte comparison cannot do is find **which**
listed name it is without folding tables; the function finds it by
identity instead (§5): the listed names that could be it (ASCII
case-insensitive first; then the non-ASCII ones) are `lstat`ed and the
one with the asked path's device and inode is the spelling.

## 4. A directory that cannot be listed

The rule (the package's sixth bullet): a component needs no listing
where the volume is seen not to fold it, that is where its name in
another case reaches nothing or another file (`lstat`, device and
inode).

- **Hard links: sound.** A hard link is another directory entry. If
  `FOO.h` is a hard link of `foo.h` in a case-sensitive directory, the
  probe sees the same file and concludes "folds": the directory is
  listed (one `read_dir` more) and both names are in the listing. The
  error goes one way only, to more listing, never to a wrong pass; and
  where that listing fails it is a false error, not a wrong answer
  (directories cannot be hard-linked on the platforms in scope).
- **A volume that answers lookups inconsistently: not sound**, and so
  not used there. The probe's useful answer is a negative ("nothing in
  another case"), and that is exactly the answer this workspace's mount
  gave wrongly (WP-075 decision 14: `src/Vendor` found one time and
  not the next). A positive answer is evidence; a negative from such a
  volume is not. Hence the allowlist of §3: the probe runs only on a
  mount whose type is a local kernel file system; everywhere else the
  directory is listed, and a directory there that cannot be listed is
  an error (status 3) when, and only when, a component in it needs the
  listing. A3's `/home` on ext4 passes with one probe and no listing.
- **Built into the one function** as the directory's state, decided on
  the first component that needs it: `Unknown` → (consistent device,
  every byte ASCII and a letter) probe, every ASCII letter's case
  swapped → `NotFolding` | `Listed`; (otherwise, a letterless component
  too) `Listed`; a failed listing is `Unlistable(error)`, reported only by
  a component that needs it. In `NotFolding` an all-ASCII component
  passes with one `lstat` (for its identity); a non-ASCII one lists the
  directory whatever the state, and never changes it.
- **And the hole of A2 closes on any volume**: in a listed directory, a
  component that is not byte-equal to a listed name never passes on a
  lookup's word. The function then finds the listed name by identity
  (`lstat` of the asked path, compared with each candidate's), and if
  the asked path finds nothing it is `Missing`. Apply refuses both
  (`not_canonical` naming the spelling on disk; `stale_file`): apply
  only ever replaces existing files, so "missing, let the later checks
  decide" (WP-075) is not needed and was the hole.

## 5. The one function

A new crate, **`slip_spelling`** (std only; a default member;
`#![forbid(unsafe_code)]`). Not `slip_model`, which reads no file
system; not `slip_apply`, which the compile database and Kiln's
adapter must not depend on. Depended on by `slip_cdb`, `slip_kiln`,
`slip_apply` and `slip_cli`.

```rust
/// What the function asks of a file system: the disk, or a test's tree.
pub trait Lookup {
    /// `lstat`: `None` when nothing is there (`NotFound`, `NotADirectory`).
    fn lstat(&self, path: &[u8]) -> io::Result<Option<Id>>;
    /// `read_dir`'s names, as bytes; `None` when `dir` is missing or not a directory.
    fn names(&self, dir: &[u8]) -> io::Result<Option<Vec<Vec<u8>>>>;
    /// Whether lookups on device `dev` are answered consistently (§3's allowlist).
    fn consistent(&self, dev: u64) -> bool;
}
pub struct Id { pub dev: u64, pub ino: u64 }

/// `std::fs`, and `/proc/self/mountinfo` read once (`Mounts`; absent:
/// nothing is consistent).
pub struct Disk { /* … */ }

/// The walk and its cache: per directory, keyed by `Id`; the walked
/// prefixes keyed by their on-disk bytes, never by the spelling asked. A
/// `Mutex` inside, held over one directory's step at a time.
pub struct Spelling<L> { /* … */ }

impl<L: Lookup> Spelling<L> {
    pub fn new(lookup: L) -> Spelling<L>;
    /// The spelling on disk of `path`, a canonical absolute path whose
    /// links are resolved (`canonicalize`'s output). Idempotent; the
    /// identity on a volume that does not fold.
    pub fn on_disk(&self, path: &[u8]) -> Result<Vec<u8>, SpellingError>;
}

/// The process-wide `Spelling<Disk>` (in a `OnceLock`).
pub fn disk() -> &'static Spelling<Disk>;
/// `canonicalize` (the lock not held), then `disk().on_disk`: what every
/// entry point calls instead of `std::fs::canonicalize`.
pub fn real_path(path: &Path) -> Result<PathBuf, SpellingError>;
/// The path as given, respelled when `canonicalize` gives it back (a
/// transform unit's files, `spec/api.md` §2.2).
pub fn respelled(path: &[u8]) -> Vec<u8>;

```

**The cache** holds, per directory identity, its state (§4) and, when
listed, its names (a set, and an index by ASCII-lower-cased name). The
process-wide one serves the parse workers, the planner and the command
line: a worker parses many observers and lists each directory once. A
name missing from a cached listing, and not the same file as a name of
the first two tiers (equal but for ASCII case; non-ASCII), re-lists that
directory once per walk (a file made since) before the third tier is
tried, over the fresh listing: a temporary file in a listed directory
costs one listing, never one `lstat` per name of its directory
(`walk.rs` `a_new_file_in_a_big_listed_directory`, 1,000 names). Apply makes a `Spelling` of its own per call (it must see
the disk now, as WP-075's check does). Bounded by the tree: at 10^4
directories of 100 names, a few MB per process.

**Error cases and exit statuses** (`spec/edits.md` §10.5, `spec/exec.md`
§8.5):

| Error | Entry point (C1–C4, L1–L3) | Parse (K3) | Apply (A0–A3) |
|---|---|---|---|
| `Ok(q)`, `q ≠ p` | `q` used | `q` used | refused `not_canonical` naming `q`, status 1 (`--recover`: 3, journal kept) |
| `Missing` | as a missing file now: `missing_file` exclusion (cdb), `Input` status 3 (command line) | `Err` (the file went during the parse; the job fails, retried once) | refused `stale_file`, status 1 |
| `NoName` | `Input`, status 3, naming both | `Err` | refused `not_canonical`, no spelling named, status 1 |
| `Unlistable`, `Io` | `Input`, status 3 | `Err` | `Io`, status 3 (as now) |
| `NotAPath` | cannot happen after `canonicalize` (reported as the others) | the same | refused `not_canonical`, no spelling named (an overlay's paths are canonical, `spec/edits.md` §2.1) |

`--recover` passes a `Missing` path on: `restore` reports it and creates
nothing there.

## 7. Open questions (as proposed; ruled in "The ruling")

1. **Normalise, refuse, or the hybrid.** Recommended: normalise
   everywhere, apply checks (§3). The alternative worth naming is the
   hybrid; it fails the same trees as refusing does.
2. **Report a respelled include?** Options: nothing; a counter
   `inputs.respelled` in the shard (the inputs whose spelling the
   function changed); a Slip diagnostic like clang's
   `-Wnonportable-include-path`. Recommended: the counter (deterministic,
   free, and it tells a user why a patch names `vendor/` where the
   source says `Vendor/`); no diagnostic (Kiln has none to give, and
   it is not Slip's to lint).
3. **The allowlist of consistent file systems** (§3). Recommended:
   `ext2 ext3 ext4 xfs btrfs tmpfs f2fs overlay`; NFS, CIFS, every FUSE
   and 9p/virtiofs listed. ZFS left out until someone runs it (it is
   consistent, but normalises without folding case; non-ASCII names are
   listed anyway, so adding it later is safe).
4. **A request or `DECL` with an entry not spelled on disk** (T1).
   Options: refuse where it is read for a run (status 3); normalise it
   there. Recommended: refuse. A record is Slip's own output or a
   hand-written file; the command line normalises, so a mis-spelled
   record is a defect to show, and normalising a record silently would
   change what its content id names.
5. **`--only` and `--match`** stay byte filters over the on-disk
   spelling (F1). Recommended: yes, stated; an ASCII-case-insensitive
   filter is a convenience nobody asked for.
6. **macOS itself.** On a host without mountinfo every directory is
   listed (one `read_dir` per directory per process). Recommended:
   accept; `statfs`'s `f_fstypename` would need `unsafe` or a
   dependency, and APFS folds by default anyway.
