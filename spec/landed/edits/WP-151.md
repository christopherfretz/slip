# WP-151 — ownership entries spelled on disk; roots by the one function; one name per file

`crates/slip_cli` (`src/commands.rs`, `src/worker.rs`,
`src/worker/transform.rs`, `src/transform/{mod,store,map,reduce,check,apply}.rs`,
`src/verify_cmd.rs`, `src/image.rs`), `crates/slip_apply` (`src/build.rs`,
`src/lib.rs`: `Files::identity`, `one_name_per_file`), and the tests'
`crates/slip_kiln/tests/common/work_root.rs` (`folding_root`). The WP-147
follow-up (`spec/landed/edits/WP-147.md`, rows T1 and L3, `docs/wp/WP-151.md`).
`spec/edits.md` §2.1 and §7.1, `spec/exec.md` §8.4 and §8.6,
`spec/verify.md` §5.1 say what is built.

## What moved

- **T1, one function.** `slip_cli::commands::entries_on_disk(&Ownership)`:
  for every entry, owned then read-only, `slip_spelling::real_path(entry)`
  must equal the entry byte for byte. Otherwise `Err` naming the entry and
  its spelling on disk (`is not spelled as on disk (<spelling>)`), or
  saying it `does not exist`, or the walk's error. `Missing` is refused.
  Callers:
  - the worker: `worker/transform.rs` `read_transform` (the map job with a
    `transform`, before any parse) and `worker.rs` `make_params` (the
    verify job's `DECL`, the job fails);
  - `transform::read_request` (`transform/mod.rs`), the one reader of a
    request from the store for a command: `reduce` and `check`
    (`store::request_of_round`), apply's `--write`, `--patch` and
    `--recover` (`apply::ownership_of`);
  - `map` and `rename`: the request they build (`map::request_of`), before
    the store is opened;
  - `check`'s declaration (`check::load_declared`) and
    `verify --declared` (`verify_cmd::publish_declared`), before it is
    published.
  Each is status 3 (`Input`) for a command, before its first job.
- **L3.** `image.rs` `real_dir` (`--root`, `--post`, and the job's image
  in `Image::from_post`, which compares `real_dir(root)` with the root)
  and `Image::canonical` go through `slip_spelling::real_path`. A job's
  root in another case is refused
  (`image: <root> is not the real path of a directory`).
- **One name per file.** `slip_apply::one_name_per_file(set, files)`:
  two files of an edit set that are one file (device and inode, through
  the new `Files::identity`) are `Invalid`, naming both paths, with the
  device and inode. Called first by `build_into` (before the sink) and by
  `reduce_round` over the whole set before the edit set is published
  (status 3, `plan <id> round <r>: the edit set: ...`).

## Decisions

1. **`real_path(entry) == entry`, not `on_disk(entry) == entry`.** The
   walk alone does not follow links (`lstat`), so an entry through a
   symbolic link passes it; the request builder makes entries real paths
   (`spec/edits.md` §2.1), so the stricter check refuses only what was
   not made so. Apply's own check (WP-147 B1) stays `on_disk`; the CLI's
   runs before it.
2. **`Image::canonical`** keeps `canonicalize`'s answer when the walk
   fails for a reason other than "not found" (a directory that cannot be
   listed): regions are decided by identity, and a refusal there would
   turn an image that verified into an error.
3. **Where the verify job checks.** In `make_params`, where the `DECL` is
   read from the store, so a declaration kept from one job to the next is
   checked once. A caller of `verify()` with its own parameters (tests)
   is not checked.
4. **`--recover`.** A T1 error there keeps the journal; the message says
   so (`; the ownership of the unfinished write cannot be found, the
   journal is kept`).
5. **Apply.** T1 runs after `permits`; nothing is read from the tree
   before either.
6. **Reduce's order.** The check runs after `slip_reduce::reduce` (whose
   scratch spill under the store's `tmp` is its own and removed) and
   before the edit set is published; nothing is published for a refused
   set. In `check`, a declaration is published before the builder runs,
   so a builder refusal there leaves the `DECL` (content addressed,
   harmless).
7. **`Files::identity`** is a required method: a `Files` that cannot
   answer says `None` (the in-memory fakes), and the check skips such a
   path. A path that finds nothing is skipped too (apply refuses it,
   `stale_file`).
8. **Write's hard-link refusal stays reachable.** It refuses a file with
   more than one link even when the other name is outside the overlay,
   and a link made after the overlay; the builder's check covers only two
   names inside one overlay. Both kept (`slip_apply` `s7_3_disk_refusals`).

## Where the tests run

The workspace mount folds case and normalisation; the tests' work root
(`$SLIP_TEST_ROOT`, the container's overlay) does not. Tests about a
volume that folds use `folding_root()`
(`crates/slip_kiln/tests/common/work_root.rs`): a directory per process
under `CARGO_TARGET_TMPDIR/folding/<package>/`, named as the work root's,
swept when its twin's lock is free. It holds no hard link (the mount's
hard links can read another name's content, and fresh files can change
inode number). A guard per crate with such tests, `s11_5_folding_root`
(`slip_cli` `stages.rs`, `slip_apply` `write.rs`, `slip_refactor`
`rename.rs`), fails when the source tree's volume folds and the folding
root does not, and prints each root's kind. The WP-147 tests that
skipped under the work root moved to it, only their root changed.
`slip_kiln`, `slip_digest` and `slip_cdb` `one_spelling.rs` and
`slip_spelling` `disk.rs` already use `CARGO_TARGET_TMPDIR` and stay.

Tests (`slip_cli` unless named): `tasks.rs`
`s8_1_the_map_job_refuses_an_entry_that_does_not_exist`,
`s8_1_the_map_job_refuses_an_entry_not_spelled_on_disk`,
`s5_1_the_verify_job_checks_the_declared_files`,
`s7_1_two_hard_links_edited_under_their_names_refused_by_reduce`,
`s7_1_two_hard_links_refused_by_the_overlay_builder`; `stages.rs`
`s2_1_a_request_entry_that_does_not_exist` (reduce, check, apply),
`s2_1_a_request_entry_not_spelled_on_disk`; `verify.rs`
`s2_1_declared_files_spelled_on_disk` (`verify --declared`),
`s5_1_report_names_the_roots_as_on_disk`,
`s5_1_a_job_whose_roots_are_in_another_case_is_refused`. The hard-link
tests run under the work root; the rest that need a volume that folds
under the folding root, each with a control spelled on disk.
