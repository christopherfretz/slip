# WP-060 — slip_model: the transform request and the sections of M2

Implemented by `slip_model::transform`, `slip_model::edits`,
`slip_model::agreement`, `slip_model::spellings` and their codecs under
`slip_model::formats`. This file fixes what `edits.md` §2.1, §3, §4 and
`model.md` §8 leave open, so that a second implementation reports the
same error at the same place. Tests: `crates/slip_model/tests/edits.rs`
(TRFM, `edits`) and `crates/slip_model/tests/sections.rs` (`binding`,
`rule_use`, `spellings`).

## 1. Readings of the spec

- **covers** (§2.1). An entry covers a path it equals, or of which it is a
  proper prefix where either the next byte of the path is `/` or the
  entry's own last byte is `/`. So `/s/lib` and `/s/lib/` both cover
  `/s/lib/x.h`, `/s/lib` does not cover `/s/library`, and `/` covers every
  absolute path. A path is owned iff the longest covering entry of `owned`
  is longer than the longest covering entry of `readonly` (or `readonly`
  has none); a path no `owned` entry covers is read-only. Paths are not
  checked to be absolute.
- **Keywords** (§3): the 93 keywords of `[lex.key]` of C++98 to C++26 (63
  of C++98, `alignas alignof char16_t char32_t constexpr decltype noexcept
  nullptr static_assert thread_local`, `char8_t concept consteval
  constinit co_await co_return co_yield requires`, `contract_assert`) and
  the 11 alternative representations (`and and_eq bitand bitor compl not
  not_eq or or_eq xor xor_eq`). Keywords removed by a later standard
  (`export`, `register`) stay keywords. Identifiers with special meaning
  (`final`, `override`, `import`, `module`, `pre`, `post`) and GNU
  keywords are not keywords.
- An identifier is `[A-Za-z_][A-Za-z0-9_]*` over bytes: UTF-8 outside
  ASCII is not one.
- A replace claim with no piece is a deletion and is valid.
- An empty place is valid for a report (only `changed` and copy pieces
  require a non-empty one).
- `severity at most 2` (§4.7) is the decoder's rule for an unlisted
  enumeration value (`Malformed` at its first byte); a value in memory
  cannot break it.
- Not checked, as the §4.7 table does not list them: a `refusal.subject`
  within its file, a refuse claim having subjects, a keep claim having
  none.

## 2. JSON forms (`model.md` §10)

Members are named and ordered as the fields of the spec; enumerations by
their names in the spec (`rename`, `function`, `follower`, `replace`,
`macro_body`, `review`, `step_budget`, …); `bool` is a JSON boolean.

- `Transform`: `{kind, ownership: {owned, readonly}, indivisible, rename,
  script}`; `rename` is `null` or `{target, kind, new_name}`, `script`
  `null` or `{id, file, options, steps, bytes, depth}`.
- `Edits`: `{scheme, transform, failure, files, subjects, links, claims,
  groups, reports, changed, renamed}`.
  - `failure`: `null` or `{kind, message, place, rendered, refusal}`;
    `place` is `null` or `{file, line, column}`; `refusal` is `null` or
    `{function, errc, message, subject}`, `subject` a place or `null`.
  - A place (`Place`) is `{file, lo, hi}`.
  - A subject is `{id, rule, role, of, flags, display}`, `rule` a rule in
    the form of WP-022 or `null`.
  - A link is `{a, b}`.
  - A claim is `{file, lo, hi, stance, pieces, subjects, reason, tiers,
    macro, votes, notes}`; the field `macro_site` of the Rust type is the
    member `macro`, `null` or `{name_start, name}`.
  - A piece is an object of exactly one member: `{"literal": bytes}`,
    `{"copy": {file, lo, hi}}` or `{"spelled": {key, text}}`. Any other
    member is an error at its path (`….pieces[j].<member>`); an object of
    no or of two members, or a value that is not an object, is an error
    at the piece's path.
  - A group is an array of numbers.
  - A report is `{place, severity, message, attached}`.
  - A `changed` entry is `{key, place, reason}`.
- `Binding`: `{overlay, declared, pre}`. `RuleUse`: `{rules, uses}`, a use
  `{rule, via, direct}`. `Spellings`: `{seen, held, failed}`, a span
  `{first, count}`, a failed entry `{index, found, name}`.
- The shard renders the new sections after `verdict`, in id order:
  `edits` (17) between `counters` and `digests`, then `binding`,
  `rule_use`, `spellings`.

## 3. TRFM: order of checks, offsets and paths

After the decoder (unlisted `kind`, target kind, `bool` other than 0 or 1,
opt tag other than 0 or 1: `Malformed` at its first byte), the first
violation of, in this order:

| Rule | Offset | Path | Message |
|---|---|---|---|
| `owned` not empty | the `owned` count | `sections.transform.ownership.owned` | `owned is empty` |
| `owned` strictly ascending | that entry | `….ownership.owned[i]` | `owned is not strictly ascending` |
| `readonly` strictly ascending | that entry | `….ownership.readonly[i]` | `readonly is not strictly ascending` |
| no entry in both lists | the `readonly` entry | `….ownership.readonly[i]` | `a readonly entry is also in owned` |
| a rename is indivisible | the `indivisible` byte | `….indivisible` | `a rename is not indivisible` |
| `rename` present iff kind is rename | its opt tag | `….rename` | `a rename request has no rename` / `a script request has a rename` |
| the target has a component | the target count | `….rename.target` | `the target has no component` |
| each component an identifier, then not a keyword | that component | `….rename.target[i]` | `not an identifier [A-Za-z_][A-Za-z0-9_]*` / `a keyword of C++` |
| the new name likewise, then not the last component | the `new_name` field | `….rename.new_name` | as above / `the new name is the target's last component` |
| `script` present iff kind is script | its opt tag | `….script` | `a script request has no script` / `a rename request has a script` |

`….` is `sections.transform`.

## 4. `edits`: order of checks and messages

`validate` first refuses, in memory, a rule name no reader accepts (in a
subject's `rule`, path `sections.edits.subjects[i].rule`, then in
`renamed[i]`, with WP-022's message); the decoder refuses these when it
reads the rule. Then the phase (`an edits section in a shard whose phase
is not map`) and the status (`… whose status is not ok`) at the payload's
first byte, path `sections.edits`. Then the rows of §4.7 in order:

- the failure row: more than one file first (`a failed run names more than
  one file`, path `sections.edits.files`), then the first non-empty list
  of `subjects`, `links`, `claims`, `groups`, `reports`, `changed`,
  `renamed` (`a failed run has a list that is not empty`), at its count;
- subjects: each rule over the whole list (ascending, then `of` for every
  subject, then flags for every subject);
- links: for each link, ascending then `a < b`;
- claims: every claim rule for claim 0, then for claim 1, …; within a
  claim: range (within the file, then non-empty for replace, both at the
  claim's first byte), pieces only for replace (the `pieces` count), each
  piece in turn (empty literal, adjacent literal, empty spelled text, a
  copy's place), reason, subjects, notes (path `….claims[i].notes`), tiers
  (0, a bit above 4, a bit of 2–4 for a claim that is not a refuse, a
  macro with tier 0 alone), votes, then ascending;
- groups: for each group, fewer than two members, not ascending, a member
  that is not a replace claim, a member already in an earlier group, not
  ascending after the previous group;
- reports, then `changed`: for each entry, ascending then its place;
- `renamed`: by the match bytes (WP-022), an equal match being
  `two rules with one (parent, kind, name, disc)`.

`Edits::normalise` puts a section built in any order into the one valid
order: files sorted and deduplicated with every file index remapped
(claims, copy pieces, reports, `changed`, the refusal's subject), `of`
and subjects sorted and deduplicated, each link's ends ordered, claims
sorted with equal keys joined as §4.3 says (votes summed, saturating),
groups carried through the sort, joined where they share a member and
dropped below two members, then reports, `changed` and `renamed` sorted
and deduplicated.

## 5. `binding`, `rule_use`, `spellings`

Each is checked after `edits`, in id order, phase before status, both at
the payload's first byte and path `sections.<name>`
(`a <name> section in a shard whose phase is not verify`, `… whose status
is not ok`, for the binding `… whose status is failed`). Then:

- `rule_use`: uses strictly ascending by rule over the whole list
  (`uses are not strictly ascending by rule`), then no use with both
  counts 0 (`a use has via and direct both 0`), at that use, path
  `sections.rule_use.uses[i]`.
- `spellings`, in this order, each over the whole list:
  1. a span of count 0, at its `count` (`….held[i].count`, `a span has a
     count of 0`);
  2. a span past index 2^64 − 1, at its `count` (`a span runs past the
     largest index`);
  3. spans ascending and not touching or overlapping, at the later span
     (`….held[i]`, `spans are not ascending or touch`);
  4. `failed` strictly ascending by index (`….failed[i]`);
  5. a failed index inside a span (`….failed[i]`, `an index is both held
     and failed`);
  6. more indices in the spans and `failed` together than `seen`,
     counted without overflow, at `seen` (`sections.spellings.seen`).
