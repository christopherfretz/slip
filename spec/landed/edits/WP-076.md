## Differences from the WP's interface

- `MapInput` takes the round (`round`), the worker command and the token
  pool; `start` (TRFM published, then `next_round`) is the caller's, so
  that `rename` and `map` share it and the round is in the record when
  the map phase fails.
- `CheckInput` also takes the worker, the tokens, `--report`,
  `--findings` and `--locate`, and `selected`/`partial`.
- `check` returns `Checked { result_id, result, declared, overlay,
  report, scanned }`, not `(Digest, TransformResult)`: `rename` prints
  the details from them without reading the store again. It takes
  `&mut Record` (steps and the ids of the record), not `Vec<Step>`.
- `result_summary` takes `scanned` (whether the `residue:` line is
  printed); the detail lines are `report::details` with a struct
  `Details` (eleven fields).
- `rename_request` takes the names as bytes (`OsString` arguments).

## Decisions where the spec is silent

1. **The record is published whatever happens.** From the map phase on,
   `map`, `rename` and `check` publish their `RUNT` on success, on an
   error and on an interruption (the signal handler waits up to 5 s for
   it, then cleans up; `run_record::install_signals`). A run that fails
   before its round exists (a usage or input error, the plan) has none.
2. **`unchanged` is decided by the report, not told to it.** §8.2 says
   an observer with an `ok` map shard that read no overlay file, in a
   run without rules, gets no verify job and is `unchanged`. The
   coordinator does not pass that state: it calls
   `Report::add_unchanged_at` with the observer's map shard of the pre
   round, and the report checks it again (an overlay, no rule, the
   observer's own `ok` map shard of the round, with `inputs`, none an
   overlay file); anything else is `failed` with the reason. A defect of
   the coordinator's selection can then make a run fail, never pass.
3. **Who gets a job** is `check::gets_job(ok, has_rules, read_overlay)
   = ok && (has_rules || read_overlay)`. The verify phase runs (and has
   its run record) also when no observer gets a job.
4. **The map shard given to the report** for an observer with a job is
   read again after the verify phase (`verify_cmd::map_status`), as
   `slip verify` reads it at report time: a verdict is believed only
   against the map shard the store has then (`spec/verify.md` §9.3).
   An observer with no job whose map shard is gone by then is added
   with no shard (`failed`).
5. **Unparsed observers are not added to the report**: conclude counts
   them from the edit set's `unparsed` (§8.5's sum is over
   `selected − unparsed`).
6. **An interruption** (SIGINT, SIGTERM): no file of the tree is ever
   written (`rename::may_write`). If the map phase was cut short there
   is no edit set and no result. If the verify phase was, the overlay
   exists (it is built before the phase) and an `incomplete` result is
   concluded and published, then the record; the process ends by the
   signal (`spec/exec.md` §7). Scan does not run.
7. **A refused set given to `check`** concludes `refused`; no overlay is
   built, no verify phase runs, and `--declared` is not read.
8. **`check`'s own lines.** `check` prints `transform`, `round` and the
   edit set summary before its own lines, as `rename` does, so the
   output of `check` alone reads the same.
9. **`check`'s selection is the map round's** (`selected_of_round`).
   `--only` and `--limit` are accepted, and must give exactly that
   selection; otherwise an input error says so. The edit set's plan,
   round and transform must be the round's, an input error naming the
   field.
10. **`--declared` absent**: `check` derives the declared changes from
    the set (`slip_reduce::declared`) and publishes them, as `rename`
    does; given, a refused rule in it is an input error, as for `slip
    verify --declared`.
11. **Residue** (§8.4):
    - A hit covered by an edit is no residue (the edit rewrote it); a
      mention inside an edit is skipped likewise.
    - A hit covered by a `kept` place or by a refusal's range is no
      residue: it was already reported or judged.
    - Covered by an `unresolved` place: `dependent`. In a file some `ok`
      map shard read: `not_compiled`. Else `not_planned`.
    - The files scanned: the owned files any `ok` map shard read; the
      owned main files of unparsed observers only with
      `--allow-unparsed` (otherwise they make the result `incomplete`
      anyway); and the walk of every owned entry (byte order, no link
      followed; an owned entry that is itself a file with a matching
      extension is scanned).
    - `--residue-ext` entries without a leading `.` get one.
    - A file of the edit set whose size or digest is not the set's is an
      input error (it changed after the map phase).
    - The scan runs only for a rename request whose verify phase
      finished. The `residue:` line is printed only when it ran.
12. **The `finding` line's place** is the pre-image site, else the
    post-image site, when the group has one with a line; at most 64
    groups, the cut line naming `--report`'s file when given.
13. **The order of the detail lines** is §10.5's: `refusal`, `report`,
    `failed run`, `finding`, `stale`, `spelling`, `exempt`, `residue`
    (WP-075's edit-set details are split in two to keep it).
14. **`--db`**: the `plan` step is recorded only when the plan was built
    by this command; with `--plan` no `plan` line is printed.
15. **Statuses.** `map`: 0 if every selected observer is `ok` and no run
    failed, else 1, raised to the plan's own status. `rename` and
    `check`: 4 for `incomplete`; 0 for `verified` when what was asked
    was written (or nothing was asked); 1 otherwise. `rename` does not
    raise to the plan's exclusions (they are `plan`'s lines).
16. **Standard error** gets the report's error lines (one per observer
    not verified) and the map phase's not-ok lines, as `verify` and
    `parse` print them.
17. **`--to`/`--from` errors** are usage errors (status 2) when the name
    itself is invalid (`--to`: `int`: a keyword of C++); a name valid in
    itself that the ownership makes invalid is an input error.
