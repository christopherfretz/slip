# WP-150 — ownership agreed between observers: Stage 2 (the record)

Stage 2 of `docs/wp/WP-150.md`: the record of each observer's ownership
lists in the store and in section 35 of its verify shard, inert for every
verdict. Stage 3 (the cross-observer fold, `combine`, and the `ownership`
report section) is not built here; every existing test's verdict is
unchanged, and all `*_stage3` tests remain ignored.

## 1. Carrier and format (`spec/model.md` §8.9)

- **Section 35 (`ownership`) of `SHRD` (version 2 unchanged):** critical
  section id 35 (32 is `edits`, 33 `rebuilt_use`, 34 reserved for WP-144
  `existing_use`). Payload is `list<digest>`, strictly ascending, holding
  the content ids of the observer's `OwnershipList` blobs.
  - Phase must be `verify`, status must be `ok`, list ids strictly
    ascending. Empty `[]` is valid.
  - Because id 35 is critical, older readers refuse shards that carry it
    with `UnknownSection`.
- **`OwnershipList` blobs (`Store::publish_blob`, `blobs/<BLAKE3(bytes)>`):**
  raw wire-encoded (no `SLIP` container wrapper, because the blob address
  is `BLAKE3(bytes)` and `Store::read_blob` checks that digest over every
  byte).
  - Starts with `version: uv` (currently `OwnershipList::VERSION = 1`).
    Version `0` or `> 1` is `UnsupportedVersion` at offset 0 (JSON path
    `version`). This gives Stage 3 (e.g. item 9's unkeyable `fixed`
    entries) and WP-116 a clean upgrade boundary without silently misreading
    an older or newer blob.
  - Fields: `file: bytes`, `through: bytes`, `made: list<Made>`,
    `fixed: list<Fixed>`.
  - `Made := key: digest, post: opt<digest>, rule: uv, line: uv, column: uv`,
    strictly ascending by `(key, post)` (`None < Some`).
  - `Fixed := key: digest, as: FixedAs (t = 0 | m = 1), line: uv, column: uv, name: str`,
    strictly ascending by `(key, as)` (`t < m`), `name` at most 4096 bytes
    (`clip_message` on write).
  - Invariants (checked in binary, JSON, and `validate` in this order):
    non-empty (`made` or `fixed` non-empty); `through` empty if `file` is
    empty; `made` empty if `through` is non-empty; `made` strictly
    ascending by `(key, post)`; `made` `line == 0` iff `column == 0`;
    `fixed` strictly ascending by `(key, as)`; `fixed` `line == 0` iff
    `column == 0`; `fixed` `name` at most 4096 bytes.
- **Goldens and fuzz/property coverage:** `crates/slip_model/tests/ownership.rs`
  pins `ownership-list.bin`, `ownership-list.json`, and
  `shard-ownership.json`, checks every reader row with exact byte offsets
  and JSON paths, runs a 2000-case property round-trip test
  `decode(encode(x)) == x` across binary and JSON, and sweeps truncations,
  byte overwrites, and 2000 random inputs asserting no panics and canonical
  re-encoding of every accepted byte stream.

## 2. Presence agreement (fail closed)

`slip_verify::run::Report::ours` (`spec/verify.md` §9.3) requires section
35 on **every `ok` verify shard of a run with a non-empty rule table**
(including `unverifiable` `ok` shards, matching `rule_use`), and forbids
it on any `ok` verify shard of a run with an empty rule table:

- Missing section 35 under rules -> `Failed` (`"the shard has no ownership"`).
- Present section 35 without rules -> `Failed`
  (`"the shard has an ownership section and the run has no rule"`).

**Why always present (even empty `[]`) rather than present only when
non-empty:** a verify shard produced before WP-150 has `rule_use: Some(_)`
and `ownership: None`. If absence meant "no entries", an older shard that
actually had `made` or `fixed` entries would silently pass as empty and let
a cross-observer conflict verify. Making section 35 mandatory on every `ok`
verify shard under non-empty rules guarantees that an absent section is
never misread as empty.

## 3. Additive `slip_digest` field, writer, worker cache, and counters

- **Additive field in `slip_digest`:** `slip_digest::own_lists::Fixed`
  gained `pub through: Vec<u8>` (after `name`, preserving Stage 1's `Ord`).
  When a fixed entry's earliest read-only declaration lies in a file that is
  not read-only by its own path, `through_file` walks `SourceManager::include_loc`
  to record the subject path of the first read-only includer (e.g.
  `dep/ro_inc.h` for S9); otherwise `through` is empty. Nothing in digests,
  rule use, or existing verdicts reads it.
- **Writer (`crates/slip_cli/src/verify_job.rs`):** on every `ok` verify
  shard under non-empty rules, `publish_ownership_lists` groups `output.made`
  by `(file, b"")` and `output.fixed` by `(file, through)`, sorts and
  deduplicates `made` by `(key, post)` and `fixed` by `(key, as)` (so even
  an observer with an in-observer collision produces a strictly ascending
  canonical list), encodes each group as an `OwnershipList`, publishes it via
  `Store::publish_blob`, and attaches the sorted blob ids as section 35.
- **Worker deduplication (`crates/slip_cli/src/worker.rs`):** `VerifyTask`
  keeps `published: HashSet<Digest>` across jobs for the currently open
  store (cleared if the store changes) and calls `verify_job::verify_caching`.
  If a blob id is already in `published`, `Store::publish_blob` is skipped.
- **Counters (per `ok` verify shard under non-empty rules; absent without
  rules):**
  - `verify.ownership.made` — count of `MadeEntry` records across the shard's lists;
  - `verify.ownership.fixed` — count of `FixedEntry` records across the shard's lists;
  - `verify.ownership.lists` — number of blob ids in section 35;
  - `verify.ownership.bytes` — sum of encoded byte lengths of the shard's
    `OwnershipList` blobs (deterministic per observer, independent of the
    worker's `published` cache).

## 4. Note for Stage 3 (WP-150 item 9)

- `Made.post` is already `Option<Digest>` in `OwnershipList` version 1, so a
  made entity whose dependency-view key cannot be formed (`post: None`) is
  preserved verbatim in the blob without dropping it.
- For item 9's unkeyable `fixed` entry (a dependency entity whose
  as-if-owned key cannot be formed), Stage 3 can either bump
  `OwnershipList::VERSION` to 2 to add an unkeyable marker/variant, or add
  a `FixedAs` variant under version 2. Version 1's strict version check at
  byte 0 ensures no reader can confuse the two layouts.

## 5. Corpus run command (for the supervisor, before Stage 3)

Build release `slip` at `origin/main` (`36a2658f`, before Stage 2's
lists/blobs) and at this branch's head (`wp/150-ownership-record-stage2`).
Using the pinned `llvm` corpus (`$SLIP_CORPUS_DIR/llvm`) and its
`lib/Support` selection (151 observers) with Demo 1's `01-relocate`
(`relocate llvm::hashing::detail => llvm::hashing :: impl`) — and optionally
a broad namespace rule (`relocate llvm => :: fresh` on a scratch post tree
or dry declared file) to stress the high-entry regime of §3.5:

```bash
# 1. Run Demo 1 case 01-relocate (llvm/lib/Support, 151 observers) with both binaries
#    to compare worker time with and without the lists, and inspect counters:
cargo xtask demo 1 --slip <slip-main> --case 01-relocate
cargo xtask demo 1 --slip <slip-wp150> --case 01-relocate

# 2. Or directly into two fresh scratch stores for exact per-phase timing and blob stats:
DB="$SLIP_CORPUS_DIR/llvm/build/compile_commands.json"
SRC="$SLIP_CORPUS_DIR/llvm/src"

# Populate pre-image map shards once:
<slip-wp150> parse --db "$DB" --only /llvm/lib/Support/ --store /tmp/wp150-store -j 8

# Declare a namespace relocation (e.g. Demo 1 01-relocate, or a broad namespace rule):
# Using Demo 1's 01-relocate declared file and post tree, or a dry-run verify against SRC
# with a declared file built by `slip declare`:
/usr/bin/time -v <slip-main> verify --store /tmp/wp150-store-main --plan <plan-id> \
    --declared <decl> --root "$SRC=<post>" --only /llvm/lib/Support/ --round 1 -j 8
/usr/bin/time -v <slip-wp150> verify --store /tmp/wp150-store --plan <plan-id> \
    --declared <decl> --root "$SRC=<post>" --only /llvm/lib/Support/ --round 1 -j 8

# 3. Summed counters (`verify.ownership.made`, `.fixed`, `.lists`, `.bytes`) and worker time:
cargo xtask perf summarize /tmp/wp150-store-main/runs/<plan-id>/verify.1.*.run
cargo xtask perf summarize /tmp/wp150-store/runs/<plan-id>/verify.1.*.run

# 4. Distinct ownership list blobs and distinct bytes in the store (on a tree-image verify,
#    every file under blobs/ is an OwnershipList blob):
ls -1 /tmp/wp150-store/blobs | wc -l
du -sb /tmp/wp150-store/blobs
```

Figures to record here before Stage 3 is built:
- `verify.ownership.made`, `verify.ownership.fixed`, `verify.ownership.lists`,
  `verify.ownership.bytes` (summed across the 151 observers);
- distinct blob count and distinct bytes under `blobs/` (ratio of distinct
  to summed bytes vs §3.5's estimate);
- worker CPU / wall time with (`<slip-wp150>`) vs without (`<slip-main>`)
  ownership list encoding & publishing.
