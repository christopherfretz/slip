# WP-054 — traces of a unit's stream, and the place of a finding

What §6.1 ("Traces", "The site of a difference", "Other findings",
"Interface") left open, as `crates/slip_digest/src/trace.rs`, the
recorder of `crates/slip_digest/src/stream.rs`, the two hooks and
`crates/slip_cli/src/locate.rs` now implement it. Written for the second
reviewer of the trusted base, whose question is whether any path lets
tracing change a digest.

## Why tracing changes no digest

1. **`Traced.output` is made before any trace.** `trace` is
   `walk::run_with(input, options, |w, written, output| …)`: the ordinary
   pipeline (collect, the queue, `order_unit`, taints, collisions, names,
   the output) has run and returned its `Output` before the closure writes
   a single stream a second time. Nothing the second writing does to the
   walk's state (memos, caches, the queue) can reach an `Output` that
   already exists.
2. **The ordinary walk records nothing.** A stream has
   `rec: Option<Box<Recorder>>`, `None` unless it was made by
   `Stream::traced()` or while an `Armed` lives; both are in `trace.rs`
   only, after the walk. On a stream whose `rec` is `None`:
   - `mark` is an inlined test of that `Option` and returns;
   - `digest` tests it and writes the field exactly as before;
   - `finish` tests it (`is_some_and`) and hashes exactly as before;
   - `Default` reads one thread-local `Cell<u8>` (`ARMING`), which is
     `OFF` outside `Armed`, and makes no recorder.
   No byte of any stream is written by the recorder or depends on it:
   `rec` is never read by anything that writes bytes.
3. **Zero allocations for tracing on the ordinary walk, and how it is
   known.** A recorder is the only allocation tracing makes, and every one
   goes through `stream::recorder()`, which under `cfg(test)` counts into
   `RECORDERS`. `trace::tests::s6_1_traces_of_every_unit` asserts the
   count is unchanged across a full `digest` of a source with statements,
   expressions, a call, a default argument, a resolved unit, an
   instantiation, a content-keyed unit and the order unit. The cost per
   stream is one TLS read at creation, per node one branch, per digest
   field one branch; the stream grows by one pointer (8 bytes).
4. **No golden moves.** `tests/golden/` is untouched by this package and
   the gate runs `records.rs` and `tables.rs`, which compare against it.

## Property (2): units with no trace

**None.** `tests/trace.rs` `pairs_trace_every_unit` runs over every
directory of `tests/{differ,equal,demand,indeterminate,resolved}` that is
not pending (2746 directories), both sides: (1) `trace(…, all keys).output
== digest(…)` and (2) every unit that is not indeterminate has a trace
hashing to its digest, with its marks ascending and inside the stream and
its `refs` the bytes of keys of units at their offsets. The allow list
`ALLOWED` is held by the test and is empty.

## How the second writing repeats the first

The second writing of a unit runs the same code the first ran, from the
same declaration, with the same per-unit state; anything it cannot
reproduce is caught, not assumed away: the bytes must hash to the unit's
digest or there is no trace (§6.1), and the unit is counted in
`verify.traces.unstable`.

- **Entity units** (`trace::entity_unit`), as `units::write`: `from` is
  `Written.read` when `units::outside_only` holds (the declaration the
  first writing read), else `units::read_decl(w, e)`; the unit state is
  put aside (`take_unit`), `unit.local.holder = Some(e)`, then
  `decl_stream` and `enclosing::write`, and the state restored.
- **Content-keyed units** (`trace::content_unit`), as
  `Walk::content_hash`: the first writing found no memo entry of `e` and
  `e` in progress inside its own writing; the second removes the memo
  entry, marks `e` in progress if it is not, takes the unit's state, the
  type memo (`take_types`), `in_key` and `keys_in_progress`, writes, and
  restores every one of them (the memo entry put back). First mark only.
- **The order unit**: `order::write` again. First mark only.
- **Demand-driven units** (a constant's `value`, a default argument: the
  units `demand::resolved_units` writes after their owner, with
  `Written.owner` set) are written from inside another unit's walk, in a
  private `write_part` that makes its own `Stream`. They are written again
  by running the owner's `resolved_units` again under `stream::Armed`:
  while armed, a stream made while no recording stream is open records,
  and each such stream hashed with the unit tag is kept. The second run's
  `Written`s are matched to the kept recordings by digest, and to the
  first run's parts by key, `resolved` and `default_argument`; then the
  §6.1 check against the first walk's digest applies as for any unit.
  Once per owner.
- **Caches and memos** (type digests, keys, the content memo) are those
  the first walk left: a cached digest is written as the same 32 bytes
  whether the cache was warm or not, unless the walk is wrong, which is
  exactly what property (2) tests over every pair source.
- **Units written from another unit's walk** other than the parts above
  (an instantiation demanded during a walk) are queued and written by
  `units::write` like any entity, so they are entity units here.
- Of one key and one digest, the first written gives the trace (their
  streams are the same bytes).

## A panic in the second writing (review F1)

Before the fix a panic anywhere in the second writing reached the front
end's catch, and `verify` returned `Err("the front end panicked: …")`:
no shard, a computed `mismatch` lost (the reviewer's reproduction). Now
`trace` runs the second writing under `catch_unwind` inside `run_with`'s
closure, after `output` exists: a panic keeps the output and the traces
made before it (each already checked against its digest), traces nothing
more with that walk, and sets `Traced.panicked`. `locate::Side` carries
it (`panicked()`; its untraced units are then not counted as unstable),
and `verify_job` emits `verify.traces.panicked` (the images, 0 to 2,
whose second writing panicked) only when not 0. §6.1 and §7.2 say so.

The unwind leaves the stream module at rest: `Armed` is a local of
`parts_again` and its `Drop` sets `ARMING` off and clears `KEPT`; each
recorder is dropped with its stream (`LIVE` back to 0); nothing else is
thread-local (`NEXT_ID` only numbers streams; the kind-name table
tolerates poisoning). Tested by `trace::tests::s6_1_panic_in_the_second_writing`
through a test-only hook (`#[cfg(test)]`, no production flag) at the
three places a second writing can be: between units, inside an open
traced stream with the unit's state put aside, and while armed for a
unit's parts. At each: `panicked`, the output equal to `digest`'s, fewer
traces than without the panic and each equal to the one made without it,
the module at rest, and an ordinary `digest` on the same thread after it
making no recorder. The end-to-end reproduction through `verify` cannot
be injected from `slip_cli`'s tests without a production flag
(`cfg(test)` of `slip_digest` is off there); the counter's arithmetic is
`locate::tests::s7_2_unplaced_counts_both_sides`, and the catch is in
`trace`, which `locate::take` calls directly.

## The differ site test

`tests/trace.rs` `differ_sites`, over the pairs of `tests/differ` whose
`expect.txt` has a `changed` line and whose two sides have a unit of that
key with different digests: **2012 pairs** (55 are pairs with no branch
to check: `a.cpp` / `b.cpp`, or no `#ifdef B`; the 19 pairs main added
since the first count, WP-115's among them, are all of that kind). A
branch's lines include its directives other than the conditionals (a
site on a `#pragma` of the branch is inside it; review F3). Every site is
in a file of the pair or has no location. **4022 sites inside the right
branch, 350 not.** The pairs with sites outside, by class (a pair can
have several):

| Class | Pairs | Why |
|---|---|---|
| `First` | 48 | the site is the unit's first mark: the difference is in the declaration's `DeclNode` rows (its type, its specifiers), which have no mark (§6.1), or before the first node, and the declaration (a class head, a function) is outside the branch |
| `Unplaced` | 43 | the mark has no location: the order unit's first mark (no place), or a node the front end makes with none (`CXXDefaultArgExpr`, `ImplicitValueInitExpr`); §6.1: "empty, 0, 0 if it has none" |
| `EmptyBranch` | 32 | side A's branch has no line (`#ifdef B` without `#else`) |
| `DeclarationRows` | 28 | the site is a declarations mark (review F2, below): the difference is in the rows merged over the entity's declarations, placed at the entity's place, and the branch changes another declaration of the chain (a friend, a redeclaration, an attribute on a member's definition) |
| `Elsewhere` | 24 | the branch changes a declaration and a use outside it is where the bytes differ (`v = bf.b` when the branch makes `b` a bit-field) |

The declarations mark moved 27 pairs' sites (counted with the hook left
out and in, over the same pairs): 24 from `First` to `DeclarationRows`
(same line: the place of the first mark and of the declarations mark is
the same entity's); `asm_label` from `Elsewhere` (the initializer of line
8) to inside its branch (lines 4 and 6); `init_fp` and
`weak-static-member-of-instantiation` from `Elsewhere` (an initializer)
to `DeclarationRows` (the entity's place); `layout-offsetof` and
`layout-sizeof-in-constant` gain the class beside their others. One pair
lost sites inside: `differ/_/lexical-ctx-member-other-namespace`, whose
difference (the definition's lexical context, a cold row) was placed at
the definition's body, inside the branch by chance of being the last node
before the row, and is now placed at the entity (the in-class
declaration, line 3): coarse and true, where the old place was right only
by accident. The totals stay 4022 / 350 for this reason (2 sites in, 2
out).

For the pairs under the expression and statement tables the test asserts
every site in its branch, except the 13 it lists in `SITES_OUTSIDE` with
their classes and the reason per entry; a listed pair whose classes
change fails too. For the two pairs of `DECLARATION_ROWS`
(`differ/ColdDeclData/asm_label`,
`differ/_/weak-static-member-of-instantiation`) it asserts that each
side's site is the declarations mark.

## Declarations' own rows (review F2)

The ruling took the one-line form: `decl_stream` marks
`s.mark_decls(e)` after `decl_node`, before `decl_scope::cold`,
`attrs::decl_attrs`, `templ::decl_maps` and `other::module_rows`. The
mark is a `stream::Hook::Decls(e)` (the recorder's mark type is now
`Hook`: a node or an entity's declarations), resolved at the entity's
place (`trace::entity_place`, the same rule as a unit's place) with the
node name `declarations` (`trace::DECLARATIONS`), which is no
`ExprKind`, `StmtKind` or key kind name. It is a traced-only hook like
the others: `mark_decls` does nothing unless the stream records, and
`pairs_trace_every_unit` (tracing changes no digest; every unit with a
trace; **2784 directories** after main `aa9adcd9`) passes. Every
declaration stream gets one, a local's or a parameter's too, at its own
entity's place.

What it does not do: place a difference at the redeclaration that
differs. `decl_stream` writes the entity's rows once, merged over its
chain: `decl_node` (kind, flags, `decl_misc` over every redeclaration,
the type, the exception specification, `decl_data` with the initializer
or body), then `decl_scope::cold` (each cold field read from the
declaration of the chain that has it: `from_chain`, so the asm label
comes from line 4 but is written in the entity's row), `decl_attrs`
(merged over the chain), `decl_maps`, `module_rows`. A mark per
redeclaration means a mark at each merge site that picks a value from a
particular declaration: the `from_chain` reads of `decl_scope.rs`, the
per-declaration loops of `decl_misc`, `decl_attrs` / `entity_attrs`,
`decl_func.rs:87`, `decl_scope.rs:67`, `demand.rs:950` and
`types.rs:894`: about a dozen hooks in five files. That is a follow-up
for the closing package (below).

## Decisions

- **A place is physical** (review F5): `located` uses `line_col`, the
  line of the physical file, which is the file its subject path names; a
  `#line` directive moves neither (§6.1 corrected from "presumed").
  `tests/trace.rs` `s6_1_site_under_a_line_directive`.

- **The expression hook is in `expr::write_node`**, right after
  `strip_parens`, not in the `Item::Node` arm of `walk_items`: it covers
  both the `Node` and the `Decayed` items and marks the node after its
  parentheses are stripped (the node whose bytes follow). One line.
- **`take` walks with `Detail::All`** (step 6 asked for `None`): `fill`
  needs, per wanted key, the units' digests, classes and indeterminacy
  (smallest digest; §4 step 4; indeterminate), and the unstable count
  needs the units without a trace. `tu` does not depend on detail, so G3
  is unchanged. Cost: the unit lists of one TU held for the length of step
  6 (one `Unit` of 72 bytes per unit).
- **`Side::unstable()`** is public (the units of wanted keys with no
  trace); `verify_job` adds pre and post and emits
  `verify.traces.unstable` only when it is not 0 (`verify_job.rs`: one
  field of `Post`, one line in step 6, one counter in `finish`).
- **Kind names** are `Debug` of Kiln's `ExprKind` / `StmtKind`, interned
  once per variant for the process.
- `PLACES` (`tests/pitfalls.rs`) is left to WP-056, which is not on main.

- **Marks per redeclaration** (review F2, for the closing package): the
  dozen hooks above, so a difference in a merged row is at the

- **F4** (review): a reference copied with `Stream::raw` (the elements of

  `UnresolvedLookupExpr` is placed at the right node with an empty `what`
  (`differ/_/dependent-call-found-signature`).

## What §6.1 says that the code does as written but a reader may not expect

- A site at a node with no location (`CXXDefaultArgExpr`,
  `ImplicitValueInitExpr`) is the empty file, line 0: §6.1 says so. A
  default argument's site is better given at the call; Kiln gives these
  nodes no location (see the handback, "For Kiln").
