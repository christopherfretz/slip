# WP-096 — spelled entities in one observer

What `crates/slip_digest/src/spelling.rs`
(`slip_digest::spelling::check_spellings`) reads into `spec/verify.md`
§10.2 and §10.6 where they are silent, and the stricter reading taken
each time. The tests are `crates/slip_digest/tests/spelling.rs` (the
package's six groups, `s10_*`, the attacks, `attack_*`, and fix round
1's, `f1_*` to `f4_*`, `s3_4_*`, `s10_2_rule1_role_*`, `s10_7_*`) and the
unit tests `spelling::tests::s10_2_rule1_every_role` and
`spelling::tests::s3_4_part_keys_are_no_origins_keys`.

**Fix round 1** (independent review, finding F1 a wrong `Holds`): every
recorded name takes part whatever its role, names Kiln records without a
referent answer and fail, and what Kiln does not record is a named hole
of §10.7. `spec/verify.md` §10.2 rules 1, 3 and 5, §10.4 and §10.7 are
amended. The first handback's claim that Kiln records no role outside
the seven of `spec/api.md` §6.5 was false: Kiln re-roles any name whose
target is a concept to `Concept` (`kiln_sema/src/written_refs.rs:54-55`;
`slip_kiln/tests/written.rs` `s9_3_role_concept_name`), and the role
filter dropped it, so a concept name in one use of a macro argument, or
of a header entered twice, could not veto.

## The interface, and its departure

`Obligation` and `Spelling` are §10.6's (`Obligation` derives `Debug`,
`Clone`, `PartialEq`, `Eq`). The function takes the unit as well:

```rust
pub fn check_spellings(unit: &slip_kiln::Unit<'_>, input: &Input<'_>,
                       rules: &RuleTable, read_only: ReadOnly<'_>,
                       obligations: &[Obligation]) -> Vec<Spelling>;
```

`read_only` (fix round 2, after WP-110) is the run's ownership, of the
type the walk takes (`Options::read_only`): the verify job passes the
`ReadOnly` it gives the walk of the same parse, made by `ReadOnlyFiles`
from `Declared.files`. No second type.

**Why.** Rule 2 of the package says the written references are
`slip_kiln::written::written_refs` and the origin
`slip_kiln::written::origin`, and both take a `slip_kiln::Unit`, which
`Input` (an `Ast`, a `SourceManager` and the subject paths) does not
hold and cannot make. The two ways round it were a second reading of
Kiln's table here (rule 2 forbids it) or new functions in `written.rs`
taking an `Ast` (another package's file, under a fix round). The verify
job has the `Unit` (`parse_observer_with` hands it to its closure) and
builds the `Input` from it, so it passes both. `input` must be the
digest's view of `unit`: its `ast` and `sm` are `unit`'s. If they are
not (a caller's error), a debug build asserts and every answer is
`NotSeen` (`s10_6_unit_and_input_of_two_parses`).

**Where it runs.** `Unit` is not `Sync` (Kiln's `Oven` holds `Cell`s),
so the check runs on the thread that holds the unit: the front end's,
whose stack (Kiln's default, 1 GiB) is more than `STACK_SIZE`. The tests
call it in the snippet parse's closure.

## How an obligation is decided

1. **Names** (§10.2 rule 1): `written_refs(unit)`, every role, and
   `dependent_names(unit)`, the entries without a referent (each with
   its role, span and whether resolution failed: nothing was missing
   from `slip_kiln::written` for this). `takes_part` returns true for
   every role but lists each, with no `_` arm, so a role Kiln adds does
   not compile until someone has looked at it. At this pin Kiln records
   eight roles: the seven of `spec/api.md` §6.5 rule 3 and `Concept`;
   each has a test that it answers and vetoes
   (`s10_2_rule1_role_{expr,member,nns,type,template,base,mem_init,concept}`).
2. **Name range** (rule 2): `ranges::file_range_of_span(sm, name)` of
   the entry's name span, which is Kiln's `editable_file_range`
   unchanged (a written reference's span ends at the end of its last
   token, so `file_range`, which re-lexes the end, is not the function).
   A reference takes no part when it has none, and also when:
   - the range's file has a load report that is not clean (Kiln
     replaced invalid UTF-8, `spec/edits.md` §2.3 `file_recoded`): its
     offsets are not the post-image's bytes, and an obligation's are;
   - the range's buffer has an empty subject path (no file).
3. **Answers** (rule 3): the range's subject path is the obligation's
   `file`, `hi` equal, `lo` at or after the obligation's `lo`. The file
   is matched by subject path, not by buffer: a file entered twice, or
   under two spellings of its path, is one file, and every entry's
   references answer (`attack_a_file_entered_twice`).
4. **Origin and key** (rule 4): `written::origin(unit, referent)`, then
   `Keys::with_rules(input, rules, read_only).key_id(origin)`, one `Keys`
   per call, memoised per origin. Under WP-110 a rule maps an owned
   entity only: a dependency entity (one declaration in a read-only
   file, `spec/verify.md` §2.1) keeps its own key, and the check compares
   it as such. The collision walk is run with the same `read_only`
   (`Options::read_only`), so the keys it marks are in the same key space
   as the keys compared, and the re-marking of mapped collisions on the
   copy reads the same walk's keys.
5. **The answer** (rule 5): `Holds` if some name answers and every
   answering one is a reference with `Some(key)` equal to the
   obligation's; `NotSeen` if none answers; else `Fails` with the first
   answering name in unit order that is not such a reference: its key
   and name, or, for a name without a referent, `found` absent and
   `found_name` `<unresolved name: dependent>` (`UNRESOLVED_DEPENDENT`)
   or `<unresolved name: resolution failed>` (`UNRESOLVED_FAILED`).

**Unit order** (rule 6 of the package). `written_refs` is in the table's
order at this pin (`slip_kiln::written::ORDER` is still `table_order`,
`crates/slip_kiln/src/written.rs:166`, though WP-084 has landed), so the
check sorts the names by `ranges::unit_order` of their starts, stably
(references before names without a referent among equal ones). Two substitutions of one macro argument are two entries
of two expansion entries and are ordered by them
(`s10_4_found_is_the_first_other_reference`).

## Decisions where the spec is silent

1. **A key that is not one entity's is no key.** An answering
   reference whose origin `Keys::key_id` refuses (`NotAUnit`,
   `ContentKeyed`, `Indeterminate` for any cause) has no key: `Fails`,
   `found` absent. So does one whose key **collides** in the unit
   (digest §3.4), which `Keys` does not see (`query.rs` "What it does
   not see"): `Ok(k)` there may be the key of two entities, and the one
   the name denotes need not be the one the transform meant.
   `attack_a_colliding_key` is that case: a rename of `o::f` to `g` that
   leaves a compatibility `o::f` behind; the post-image's `o::f` has the
   obligation's key unmapped and `o::g` has it mapped, and the sibling
   spelling `f` resolves to the old declaration. Without the collision
   check it holds. The obligation's key and the reference's are never
   both indeterminate and "equal": an indeterminate reference has no key
   to compare.

   *Which keys collide* is the walk's own marking, not a second rule:
   the check runs the walk once (`walk::run_with`, the rules, no
   detail). Since WP-045 a unit's `collided` says it is in a collision
   whatever cause it keeps first, set by `units::mark_collisions`,
   `keys::mark_mapped_collisions` and `units::mark_part_collisions`;
   the check **uses `collided`** for units, and no longer re-marks them.
   Parts (`owner` set: resolved and `default_argument` units) are left
   out: a part's key is of kind `Resolved` or `DefaultArgument`, an
   origin's never is, so no obligation has one
   (`spelling::tests::s3_4_part_keys_are_no_origins_keys` keys every
   declaration of a unit with default arguments, a default member
   initialiser and resolved units, under no rule and under a rename,
   and finds no part's key among them). A collision of a key **no unit
   has** marks only the order unit's cause (`collided` is not set
   there), and the order unit keeps the first cause met; so on a copy of
   the units the check **resets** the order unit's cause and runs
   `keys::mark_mapped_collisions` again, and such a key collides when
   the order unit then shows `Collision` and no unit has the key
   (`s3_4_a_colliding_key_no_unit_has`, also with the order unit
   already indeterminate for `order/depth`). This reads `pub(crate)`
   items of `walk.rs`, `units.rs` and `keys.rs` and changes none of
   them.

   An indeterminate **unit** whose key is sound (an unsupported
   expression in a body, a taint) is not a failure: the name denotes the
   entity, and the comparison of digests reports the unit.
2. **A refused rule table** (`RuleTable::refused`): every key is
   `Indeterminate(key/refused-rule)` (`Keys::with_rules`), so an
   obligation that some reference answers fails with `found` absent, and
   one that none answers is `NotSeen`. Never `Holds`
   (`attack_a_refused_table`). The walk under such a table keys nothing
   either, so the observer is not `verified` on that account too.
3. **The name of what was found** (§10.4 `name`, §6.1): the walk's name
   of the found key's unit (`Output::names` of the same walk, which
   names an inline namespace: `attack_an_inline_namespace`); for a
   reference with no key, or a key no unit has, the host's
   `display_name` of the origin's entity, cut at 4096 bytes at a
   character boundary. Not in the trusted base.
4. **Malformed obligations**: `lo >= hi` or an empty `file` is
   `NotSeen` (the overlay's decoder refuses them; §10.1). An obligation
   whose `file` the unit did not read is `NotSeen`: no reference is in
   it (test 6).
5. **Unit parsed without the tables**: `NotSeen` for every obligation
   (rule 3 of the package; `s10_2_not_seen_without_the_tables`).
6. **A reference found through a using-declaration** (the open
   question of `spec/verify.md`): Kiln's table gives the target as the
   entity, with the shadow as `found`; `WrittenRef::referent` is the
   target. Step 4 of §10.2 need not look through it
   (`attack_through_a_using_declaration`). The open question can be
   closed.

## The explicit-instantiation question (handback of WP-087)

It is not §10's. An obligation's key is never a specialisation's nor an
instantiated member's:

- `spell(e)` refuses a specialisation, a member of one and a member of a
  class template (`spec/api.md` §7.1 rule 4);
- the native rename's `K` is the key, with no rules, of the **origin**
  of the entry's referent (`spec/edits.md` §9.3): the template, or the
  member of the template;
- an explicit instantiation's own name (`template struct S<long>;`,
  `template int f<int>(int);`) is a declaration's name
  (`written::decl_names`, `ExplicitInstantiation`), written with a
  literal piece: no obligation; and Kiln records no reference for it
  (role `SpecTarget`, stage 3, not at this pin:
  `s10_7_unrecorded_names_are_not_seen`).

What the check compares is the origin's key under the rules: for
`S<long>().n()` with `template struct S<long>;` in the unit, the
referent is the member of the explicit instantiation, its origin the
pattern's `S::n`, whose mapped key is the pre-image's `S::m`
(`s10_2_rename_a_member_of_a_class_template`). WP-103's rule (a member
of an instantiation follows its pattern's mapped name) does not enter:
the check never keys an instantiated member. The question, whether
`expect_changed` on a template member covers the explicit instantiation
definition that is a declared unit, is §2.2's: `Keys::derived`
(WP-087) and whoever expands `expect_changed` (the host, WP-095).

## Names without a referent

A name Kiln records without a referent — dependent (`REF_DEPENDENT`) or
whose resolution failed (`REF_UNRESOLVED`) — that answers makes the
obligation `Fails`, `found` absent. Before fix round 1 it was `NotSeen`.
Both stop the run (§10.3: `failed`, `denotes_other` or `unseen`), so
the run's verdict does not change; the report now says *which* name and
why, and a dependent use of one macro argument now vetoes a resolved
use of it that has the key (`f2_a_dependent_use_of_a_macro_argument_fails`,
the reviewer's P4: `g<a::A>` calls `a::f` by ADL). Tests:
`s10_2_fails_at_a_dependent_name`,
`attack_a_dependent_call_two_instantiations`,
`attack_a_requires_expression`.

## Ranges `ranges` refuses, and other names that are not seen

Each is `NotSeen` unless another name answers, never `Holds`:

| Case | Test |
|---|---|
| a name in a macro body (tier 2: Kiln gives no range) | `attack_a_name_in_a_macro_body` |
| a name in a skipped group, an unused macro argument | `s10_2_not_seen_in_a_skipped_group`, `…_unused_macro_argument` |
| an operator used as an operator (no entry); a template-id's arguments (the range is the name) | `attack_conversion_and_operators`, `attack_a_template_id` |
| names Kiln does not record (the named hole above) | `s10_7_unrecorded_names_are_not_seen` |

| a file Kiln recoded (invalid UTF-8): its offsets are not the file's | `f3_a_recoded_file_on_disk_is_not_seen` |

`ranges`' interim directive refusal applies to a name only when the
line it starts on (or a line starting inside it) begins with `#`: such a
reference takes no part, so an obligation there is `NotSeen`, never
`Holds`. The split-`>` refusal is `file_range`'s, which the check does
not call: a name span from Kiln's table already ends where the parser
ended it (`attack_operator_shift`, an explicitly named `operator>>`).
A recoded file cannot be written by a snippet (`&str`):
`f3_a_recoded_file_on_disk_is_not_seen` parses a real file
(`parse_observer_with`, the reviewer's P12) whose comment holds `0xff`;
Kiln's reference to `g` sits, in Kiln's offsets, on the bytes of `f`.

A name written with a line splice or a universal-character-name inside
it is recorded with a range over its bytes at this pin, and the check
answers it as any other (`attack_a_splice_in_the_name`,
`attack_a_ucn_in_the_name`): WP-068's `decl_names` defect has no
counterpart in `written_refs`.
