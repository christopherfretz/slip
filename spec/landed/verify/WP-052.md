# WP-052 — the verify task, tree images, the worker's `PhaseTask`

What §5 (and `spec/exec.md` §2, §8.4, §8.6) left open, as
`crates/slip_cli/src/{image,verify_job,locate,worker}.rs` and
`crates/slip_exec/src/store.rs` now implement it. Written for the second
reviewer of the trusted base: every place a `verified` is made, every
early return of `verify`, every guard with its test.

## Where a `verified` is made

Two places, both in `verify_job::verify`, both through `slip_verify`:

1. **Step 3**, `AtSums::Equal => … verified(pre.id, rules_id)`: reached
   only after P1 to P3, G1 and C have held. Test:
   `s5_2_verified_at_the_sums` (`verify.reparsed` 0).
2. **Step 5**, `verdict(comparison, pre.id, rules_id, params.limit)`,
   which is `verified` only for a comparison without findings: reached
   only after R1, G2 and R2 have held and `compare_groups` returned `Ok`.
   Test: `s7_2_exemptions_used` (a finding exempted by a declared
   `changed` key). Step 6 can only withdraw it (G3), and runs only when
   `total > 0`, so it never sees one.

Nothing else in `slip_cli` names `VerdictKind::Verified`.

## Guards

| Row | Test | `reason` | Made by |
|---|---|---|---|
| P1 | `p1_no_map_shard` | `pre-image: no map shard` | no map run |
| P2 | `p2_map_shard_not_ok` | `pre-image: the map shard is diagnosed` / `rejected` / `failed` | a real parse (diagnosed); an edited store (rejected, failed) |
| P3 | `p3_map_shard_without_digests` | `pre-image: the map shard has no digests` | an edited store |
| G1 | `g1_absolute_include`, `g1_absolute_include_directory`, `g1_relative_include_directory`, `g1_symlink` (`g1_identity_image`: holds) | `post-image: read <path>, a file of the subject` | real parses |
| C | `c_digests_not_comparable` (unit test of `not_comparable`) | `digests: <message>` | constructed digests: see below |
| R1 | `r1_pre_image_no_longer_parses` | `pre-image: no longer parses (diagnosed): <message>` | real parses (the subject broken after the map) |
| G2 | `g2_header_edited` (`g2_not_reached_at_the_sums`: verified) | `pre-image: <path> changed since the map phase` | real parses (a header edited after the map) |
| R2 | `r2_digests_not_those_of_the_map_shard` | `pre-image: its digests are not those of the map shard` | an edited store: see below |
| G3 | `g3_post_image_changed_during_the_job` | `post-image: changed during the job` | real parses, a writer racing the job |
| O1, O2 | — | — | the overlay form, WP-074 |

- **C is unreachable without a defect.** Its three checks (scheme, groups
  strictly ascending, `tu == tu_digest(groups)`) are rules 1, 3 and 7 of
  the shard's digests validation (`slip_model::formats::digests`), so a
  stored pre shard that fails one is refused by the decoder in step 0
  (the job's `Err`, tested in `s5_2_pre_shard_altered_fails_the_job`),
  and the post digests come from the walk of this job. The check is kept,
  factored as `not_comparable`, and tested at unit level.
- **R2 is unreachable from real parses of one build.** The digests of a
  parse are a function of its inputs, which G2 has just found equal, and
  of the command, which is the observer's. Time does not enter (tried:
  an array sized by `__TIME__[7]` verifies at the sums 1.1 s after its
  map). R2 is what catches a map shard written by
  another build of the walk; the test edits one group's digest (and `tu`)
  in the stored shard.
- **G3 is reached by a race**: a thread replaces a header of the post
  tree by rename, alternating two contents, while the job runs; each
  attempt is a mismatch or G3, never `verified`, and G3 must be seen in
  200 attempts. Its second case alternates
  two contents that differ in a space only.
- **A `CompareError` is unreachable without a defect**: both lists come
  from walks of this job with detail for every group of `G`. Tested at
  unit level (`compared`).

## Decisions

- **`Params.pre`.** `spec/exec.md` §8.6 gave `Params` no `pre`, and also
  said `verify` reads neither the job's `post` nor the worker's arguments;
  step 0 needs `Job.post.pre`. The field is added (the more refusing
  reading: `verify` reads nothing but `Params`), and §8.6 corrected.
- **`ImageError::NotNormal`.** A root with a trailing `/`, or an empty,
  `.` or `..` component, is refused: G1 compares roots with real paths as
  bytes, so a root in another form would let a read of the subject
  through. Added to §8.6.
- **`from_post` checks the file system**: every root of a job's image must
  be, now, the real path of a directory (`canonicalize` gives it back),
  or the job fails. The coordinator made them so; one that changed since
  would make G1 compare with the wrong bytes.
- **`from_post` and `to_post` are M1** (the tree form); §8.6 listed them
  under M2. Moved.
- **The textual rule's example.** §5.1 said `-DROOT="/s"` is rewritten;
  by the bullet that defines the rule it is not (the root is followed by
  `"`). The bullet is kept and the example corrected (`-DROOT="/s/"` is
  rewritten). Either reading is safe: G1 refuses a post-image parse that
  reads the subject.
- **`Image::parse` gives `f`'s value only with an `ok` shard**, as the map
  task drops the walk's.
- **A pre shard that is there but invalid, or of another observer, phase
  or round, is the job's `Err`**, not `unverifiable`: the store was
  altered, and an `Err` is reported as a failure of the run.
- **`pre` of an `unverifiable` verdict** is the content id of the pre
  shard whenever one was read (P2, P3 and every later guard), zero only
  for P1.
- **G3 compares the `inputs` as well as `tu`** (and needs the second parse
  `ok`): a post-image that changed in a way the digest does not see is
  still another image, and the names would come from it. The §5.3 row is
  corrected to say so.
- **Step 6 runs when `total > 0`** and `locate > 0`, also when `limit` is
  0 and no finding is kept: G3 is then still checked.
- **An empty `G` with sums that differ, an `ok` post shard without
  `inputs`, and an `ok` parse whose walk did not run are `Err`** (defects;
  no verdict is made from them).
- **G2 with an absent `inputs`** (not possible for an `ok` shard) treats it
  as an empty list, so it differs from any parse that read a file.
- **`--findings 0` and `--locate 0`** are accepted.
- **`Image` keeps the tree form only**: WP-074 adds the overlay variant
  behind the same functions.
- **`slip_cli` calls `unit.errors()`** inside the parse callback to skip
  the walk on a unit with errors, as the map task does.
- **The worker keeps `Params`** while `post.declared` and `post.image` are
  equal, updating `pre`; a job with another image or `Declared` makes new
  ones (`worker_phase_task`).

## What `locate` fills until WP-054

`name` only, of the first `locate` findings (those `limit` kept): the
first name, in byte order, of a unit of the key in the pre-image, else in
the post-image, cut to 4096 bytes at a character boundary. The pre side is
taken inside step 4's parse; the post side is a third parse (step 6).
`location` stays absent.

## What verifies at the sums today

With the walk at this base: variables, declarations, structs, namespaces,
function bodies, function template definitions, calls, enums, aliases,
member functions, `constexpr`, constructors with default member
initialisers, local variables, overloads, default arguments, string
literals, `virtual`/`override`, `static_assert`, a dependent call in a
template. Not: a class template specialisation used (`B<int>`) and a call
of a function template (`id(1)`): indeterminate, `pending.demand`, lifted
by WP-045; a local class and a lambda: `pending.local`, lifted by WP-040.
