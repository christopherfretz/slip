# WP-121 — the verify job under rules: `binding` and `rule_use` with a tree image

`crates/slip_cli/src/verify_job.rs` (items 1 to 3),
`crates/slip_verify/src/run.rs` (item 4). Tests:
`crates/slip_cli/tests/verify_job.rs` (`s9_1_*`, `s9_2_*`, `s9_3_*`,
`s2_1_*`), `crates/slip_verify/tests/agreement.rs`
(`s9_3_refused_shard_says_why`, `s10_4_fold_refusal_says_why`),
`crates/slip_verify/tests/run.rs` (`s7_1_a_foreign_shard_says_why`).

## 1. `binding` (`spec/verify.md` §9.1)

A verify job whose `Declared.rules` is not empty puts
`Binding { overlay: None, declared, pre }` in the shard right after
step 1's parse, so every shard it returns has it: `ok` (each verdict),
`diagnosed`, `rejected`. `declared` is `Params::declared_id`, a new
field of `Params`: the content id of the `DECL` container, which the
worker's `make_params` (the one place params are made, `spec/exec.md`
§8.6) reads from `Job.post.declared` and has already checked against
the bytes. `pre` is `Params::pre` (`Job.post.pre`). `overlay` is absent:
the job has a tree image only (`Image::from_post` refuses the overlay
form until WP-074). The parse task never returns status `failed`; the
job still adds no binding to such a shard (the model refuses one). A job
that fails returns `Err` and writes nothing; the coordinator's `failed`
shard has no binding, unchanged.

## 2. `rule_use` (§9.1; `Options.rule_use`)

Step 1's walk runs with `rule_use: !rules.is_empty()`. Every `ok` shard
(each verdict, `unverifiable` included) gets
`RuleUse { rules: Declared::rules_id(), uses: <the walk's counts> }`
through `Post::finish`, the one place an `ok` shard is assembled. The id
is `rules_id` (rules and files), the id the verdict carries and the
report's header compares (`Report::ours`, A4). A `diagnosed` or
`rejected` shard has none.

**Which parse.** The job parses the post-image at step 1 and, when it
localises, again at step 6. Only step 1's walk counts: step 6 walks
through `locate::take`, with `rule_use: false`. The counts cannot
differ from those step 6's parse would give: G3 keeps step 6's result
only if the second parse is `ok` with the same `inputs` (every file
read, by path, size and content digest) and the same `tu` digest, and
the walk's counts are a function of the unit, which is a function of
the command and those inputs. If the post-image changed between the
parses, G3 makes the verdict `unverifiable` ("changed during the job");
the shard's `digests` and `rule_use` are then both step 1's, one image.
The walk counts the same with the option on as off for every other
output (`slip_digest` `pair_tests_on_and_off`), so turning it on moves
no digest and no counter of the shard.

## 3. An empty rule table is M1's, byte for byte

With an empty table (no `--declared`, or a `DECL` with no rule) the job
writes neither section, and the walk runs with `rule_use: false` as
before. `s9_1_no_rules_shard_unchanged` pins it with a golden,
`crates/slip_cli/tests/golden/verify-no-rules.txt`, blessed on `main`'s
code before this package changed anything (commit "pin the verify shard
of a run without rules before the package") and unchanged by it: the
shard's JSON for a `verified`, a `mismatch`, a `diagnosed` and an
`unverifiable` (P1) job, with every section by name, the tree's
directory, the observer id and the map shard's id written as
placeholders, and only the counters of §7.2 (the parse's and the walk's
are Kiln's and `slip_digest`'s, and `digests` is omitted for the same
reason). The test also requires no `binding` and no `rule_use` with
`Declared::none()` and with a `Declared` of one exemption and no rule.
The goldens of the report (`crates/slip_verify/tests/golden/`) did not
move.

## 4. The message of a refused shard (§7.1)

**Where it was lost.** `Report::add_at` asked `ours(shard, observer)`, a
`bool`; a refused shard became `Failed` with no shard to take a message
from (WP-055 chose the empty message so that a foreign shard's own
message is never shown as this observer's). A shard the fold refused
(A6) became `Failed` with its own message, empty for an `ok` shard. So
`slip: failed: <main>: ` with nothing after it.

**Now.** `ours` returns `Result<(), String>` and `read_sections` the
fold's refusal; the reason is the observer's `message` in
`not_verified` and the text after the main file on standard error. The
foreign shard's own message is still never shown. Per cause, in the
order checked:

| Cause (WP-070 §2.1) | Message |
|---|---|
| A1, observer | `the shard is another observer's` |
| A1, round | `the shard is of round <n>, not the run's <m>` |
| A1, verdict's rules | `the shard's verdict was made under other rules than the run's` |
| A2, binding (first field that differs: overlay, declared, pre) | `the shard's binding is not this run's: its overlay` / `…: its declared changes` / `…: its pre round <n>, not <m>` |
| A3 | `the shard has no binding` |
| A4 | `the shard has no rule_use`; `the shard has a rule_use and the run has no rule`; `the shard's rule_use is under other rules than the run's`; `the shard's rule_use names rule <i>; the run has <n>` |
| A5 | `the shard has no spellings`; `the shard has spellings and the run has no obligation` |
| A6 | `the shard's spellings are refused: <the fold's reason>`, the fold's own `spellings: ` prefix dropped (`… refused: obligation 2 is of /s/b.h, which the shard did not read`) |

A2 names the first field that differs, in the order overlay, declared,
pre (pinned with two fields differing). A3 is checked with A2 in one `match`: a missing binding where one is
required is A3, a present one that differs is A2. Not changed: an
observer with no shard (the caller decided it is not this run's from the
run record) has the empty message, and a shard the state table refuses
(`judge`: not phase `verify`, invalid, `ok` without a verdict, counters
that disagree, a `verified` or `mismatch` verdict whose map shard is not
`ok`) keeps its own message, empty for an `ok` one (follow-up in the
handback). No golden moved: none has a `failed` observer. The test that
pinned the empty message, `s7_a_foreign_shard_has_no_message`, is now
`s7_1_a_foreign_shard_says_why`.

## 5. End to end, at the level `main` has

`main` has the job and `slip_verify::run`, not the `slip verify` and
`slip declare` commands (WP-053). The cases are in
`crates/slip_cli/tests/verify_job.rs`: the jobs' shards, added to a
`Report` as `spec/exec.md` §8.7 adds them, and the exit status that
section gives the verdict (0 verified, 1 not verified, 4 incomplete).

- **A namespace relocation over two observers**
  (`s9_3_relocation_verified_over_two_observers`): each `verified`; the
  run verified, **status 0**; `agreement rules 1 stale 0 unused 0` and
  `not checked: agreement between observers for namespace rule 0`
  (§9.2: listed `unchecked` until WP-111, verdict unchanged). Before
  this package: both `failed`, the run incomplete, status 4. The wrong
  edit beside it: `mismatch`, not verified, status 1.
- **A rename (kind `class`)** with one observer that still declares the
  old name and was not edited (`s9_2_rename_with_a_stale_observer`):
  each observer `verified`, the second stale (`direct` 1), the run not
  verified, **status 1**. A correct rename with no stale observer is
  verified, status 0 (the relocation's path, without `unchecked`). The
  wrong edit beside it: `mismatch`, status 1.
- **WP-053's `s2_1_rule_naming_a_dependency_entity_matches_nothing`**
  pins status 4 (both observers `failed` for want of `rule_use`). With
  this package it gives **status 1**: both observers `mismatch`, the
  rule `unused`. That is right: the namespace is declared in a read-only
  file, no rule reaches a dependency entity (§2.1), so moving it is a
  real change in each observer, which the missing sections were hiding.
  The job-level counterpart is `s2_1_rule_on_a_dependency_entity_not_verified`.
  The executable-level cases are owed after WP-053 merges.
